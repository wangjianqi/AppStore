# 08-Cursor / Trae 等 AI IDE

> 🎯 **本章目标**：理解 AI IDE 的概念和核心能力，掌握 Cursor 和 Trae 的安装配置与核心功能使用，能够根据场景在 AI IDE 和终端 AI 工具之间做出选择，并学会组合使用多种 AI 工具。

## AI IDE 是什么？

### 传统 IDE vs AI IDE 的区别

IDE（Integrated Development Environment，集成开发环境）是程序员写代码的"工作台"。你可能听说过 VS Code、Xcode、Android Studio，这些都是传统 IDE。而 AI IDE 是在传统 IDE 的基础上，**把 AI 能力深度融入编辑器的每一个操作中**。

| 对比维度 | 传统 IDE | AI IDE |
|---------|---------|--------|
| 写代码 | 手动逐行输入 | 描述需求，AI 自动生成 |
| 改代码 | 手动查找、逐行修改 | 选中代码，用自然语言描述修改 |
| 查文档 | 打开浏览器搜索 | 直接在编辑器里问 AI |
| 调试 | 手动读日志、加断点 | 把错误贴给 AI，秒级定位 |
| 跨文件修改 | 逐个文件打开修改 | AI 同时修改多个文件 |
| 学习成本 | 需要记忆大量快捷键和 API | 用自然语言就能操作 |

💡 **一句话理解**：传统 IDE 是"工具箱"，你需要自己找工具、自己动手；AI IDE 是"带助手的工具箱"，你说一声，助手帮你干。

### 为什么 AI IDE 是未来趋势

AI IDE 不是简单的"编辑器 + 聊天窗口"，而是从底层重新设计了人机交互方式：

```
传统开发流程：
  想需求 → 搜索 API → 手写代码 → 运行 → 报错 → 搜索解决方案 → 修改 → 再运行 → ...

AI IDE 开发流程：
  想需求 → 描述给 AI → AI 生成代码 → AI 自动运行 → AI 自动修复 → 交付
```

AI IDE 的三大趋势：

1. **从"手动操作"到"自然语言驱动"**：不需要记住复杂的快捷键和命令，用日常语言就能完成操作
2. **从"单文件编辑"到"项目级理解"**：AI 能理解整个项目的结构，跨文件修改时不会"顾此失彼"
3. **从"被动工具"到"主动助手"**：AI 不只是等你提问，还能主动发现问题、建议优化

### AI IDE 的核心能力

所有 AI IDE 都具备以下核心能力（只是实现方式和体验有差异）：

| 核心能力 | 说明 | 类比 |
|---------|------|------|
| **智能对话** | 在编辑器里和 AI 对话，AI 能看到你的代码 | 身边坐了一个资深程序员 |
| **代码生成** | 描述需求，AI 自动生成代码 | 口述需求，助手帮你写 |
| **代码补全** | 你写几个字符，AI 猜你想写什么并补全 | 手机的输入法联想，但更智能 |
| **行内编辑** | 选中一段代码，用自然语言描述修改 | 圈出一段文字，告诉编辑怎么改 |
| **多文件编辑** | AI 同时修改多个相关文件 | 助手同时帮你改多个文档 |
| **错误修复** | 把错误信息给 AI，它帮你定位和修复 | 有人帮你查错并改正 |

## Cursor 安装与配置

### 下载与安装（官网 cursor.com）

Cursor 是目前最受欢迎的 AI IDE，由 Anysphere 公司开发，基于 VS Code 打造。

**下载步骤**：

1. 访问 [cursor.com](https://cursor.com)
2. 点击 "Download" 按钮
3. 选择你的操作系统（macOS / Windows / Linux）
4. 下载完成后，按提示安装

💡 **提示**：Cursor 的安装和普通软件一样简单，macOS 用户下载 `.dmg` 文件，拖到"应用程序"文件夹即可。

### 首次启动配置

第一次打开 Cursor 时，它会引导你完成以下配置：

| 配置项 | 说明 | 建议 |
|--------|------|------|
| 登录账号 | 使用 Google 或 GitHub 账号登录 | 推荐用 GitHub，方便后续集成 |
| 选择主题 | 深色 / 浅色主题 | 按个人喜好选择 |
| AI 模型选择 | 选择默认使用的 AI 模型 | 推荐选 Claude Sonnet，编程能力最强 |
| 隐私模式 | 是否允许 Cursor 用你的代码训练模型 | 建议开启 Privacy Mode |

⚠️ **注意**：如果你处理的是公司项目或敏感代码，务必开启 Privacy Mode（隐私模式），防止代码被用于模型训练。

### 导入 VS Code 设置和扩展

如果你之前使用 VS Code，Cursor 支持一键导入所有设置：

1. 首次启动时，Cursor 会自动检测已安装的 VS Code
2. 点击 "Import from VS Code" 即可导入：
   - 所有扩展（插件）
   - 快捷键设置
   - 主题和配色
   - 用户设置

💡 **提示**：Cursor 基于 VS Code，所以你之前在 VS Code 上安装的插件（如 Prettier、ESLint、GitLens 等）都能在 Cursor 里正常使用，无需重新配置。

如果你错过了首次导入，也可以随时在 Cursor 中操作：

```
菜单栏 → File → Import... → 从 VS Code 导入
```

### Cursor 核心功能

#### Chat 模式：与 AI 对话

Chat 模式是 Cursor 最基础也最常用的功能。你可以像和同事聊天一样，向 AI 提问、讨论方案、请求帮助。

**如何打开 Chat**：

- 快捷键：`⌃⌘ L`（macOS）/ `Ctrl+Alt+L`（Windows/Linux）
- 或点击右侧边栏的 Chat 图标

**Chat 模式的特色**：

| 特色 | 说明 |
|------|------|
| **上下文感知** | AI 能看到你当前打开的文件、选中的代码 |
| **@引用** | 用 `@文件名` 引用特定文件，`@文档` 引用官方文档，`@网页` 引用网页内容 |
| **代码应用** | AI 生成的代码可以一键应用到文件中 |
| **历史记录** | 对话历史会被保存，下次打开还能继续 |

**常用对话示例**：

```
你：@src/utils/auth.ts 这个文件的登录逻辑有什么问题？

你：帮我写一个 React 的 Modal 组件，支持自定义标题、内容和底部按钮

你：@package.json 这个项目用了什么技术栈？适合用什么状态管理方案？
```

💡 **提示**：善用 `@` 引用功能！当你想让 AI 分析特定文件时，用 `@文件名` 引用比口头描述文件路径更准确。

#### Composer 模式：AI 自动编写多文件代码

Composer 是 Cursor 的"杀手级功能"。它能让 AI 同时修改多个文件，自动完成跨文件的代码编写。

**如何打开 Composer**：

- 快捷键：`⌘ I`（macOS）/ `Ctrl+I`（Windows/Linux）
- 或使用快捷键 `⌘⇧ I` 打开 Composer 面板

**Composer vs Chat 的区别**：

| 对比维度 | Chat 模式 | Composer 模式 |
|---------|----------|--------------|
| 修改文件 | 一次通常修改一个文件 | 可以同时修改多个文件 |
| 交互方式 | 对话式，一问一答 | 描述需求，AI 自动规划并执行 |
| 适合场景 | 问答、小修改、代码解释 | 新功能开发、重构、批量修改 |
| 代码应用 | 需要手动点击"Apply" | 自动应用到所有相关文件 |

**Composer 使用示例**：

```
你：给项目添加一个"用户个人设置"页面，包含修改昵称、头像和密码的功能。需要：
1. 创建 SettingsPage 组件
2. 添加路由配置
3. 创建 API 请求函数
4. 添加表单验证

Composer 会：
1. 分析项目结构，了解路由和组件的组织方式
2. 创建 SettingsPage.tsx
3. 修改路由文件添加新路由
4. 创建 settings API 文件
5. 添加表单验证逻辑
6. 展示所有修改，等待你确认
```

⚠️ **注意**：Composer 修改多个文件时，务必仔细审查每一处修改。虽然 Cursor 会展示 diff 视图方便你检查，但不要无脑接受所有修改。

#### Inline Edit：行内编辑

Inline Edit 让你选中一段代码，直接用自然语言描述修改，AI 会就地修改代码。

**如何使用 Inline Edit**：

1. 选中要修改的代码
2. 按 `⌘ K`（macOS）/ `Ctrl+K`（Windows/Linux）
3. 在弹出的输入框中描述修改需求
4. AI 生成修改，你可以接受或拒绝

**使用示例**：

```
选中一段排序代码 → 按 ⌘K → 输入"改成按日期降序排列" → AI 修改代码 → 点击 Accept
```

💡 **提示**：Inline Edit 适合小范围修改，比如改个变量名、调整逻辑、添加错误处理等。大范围修改建议用 Composer。

#### 代码补全（Tab 接受）

Cursor 的代码补全比传统 IDE 的补全智能得多。它不只是根据语法补全，而是根据你的项目上下文和当前代码逻辑来预测你接下来要写什么。

**使用方式**：

- 正常写代码时，Cursor 会自动显示灰色补全建议
- 按 `Tab` 接受补全
- 按 `Esc` 拒绝补全
- 继续输入可以忽略补全

**补全类型**：

| 补全类型 | 说明 | 示例 |
|---------|------|------|
| 行级补全 | 补全当前行 | 你写 `const name =` → AI 补全 `user.name` |
| 块级补全 | 补全多行代码 | 你写函数签名 → AI 补全整个函数体 |
| 多处补全 | 同时补全多个位置 | 你改了一个变量名 → AI 建议其他位置也改 |

⚠️ **注意**：不要养成无脑按 Tab 的习惯！补全建议不一定正确，至少扫一眼再接受。

## Trae 使用入门

### Trae 是什么（字节跳动出品，国内友好）

Trae 是字节跳动推出的 AI IDE，同样基于 VS Code 打造。它最大的优势是**国内直接可用**——不需要科学上网，不需要海外账号，下载安装就能用。

| 特点 | 说明 |
|------|------|
| 国内直连 | 无需科学上网，国内网络直接访问 |
| 中文优化 | 界面和 AI 对中文支持优秀 |
| 免费使用 | 目前完全免费，不限次数 |
| 多模型支持 | 支持 Claude、GPT 等多种 AI 模型 |
| VS Code 兼容 | 支持导入 VS Code 设置和插件 |

💡 **一句话理解**：如果你觉得 Cursor 的网络和付费门槛太高，Trae 是目前最好的替代选择。

### 安装与配置

**下载步骤**：

1. 访问 [trae.ai](https://trae.ai) 或搜索"Trae AI IDE"
2. 点击 "下载" 按钮
3. 选择你的操作系统（目前支持 macOS 和 Windows）
4. 下载完成后，按提示安装

**首次配置**：

| 配置项 | 说明 | 建议 |
|--------|------|------|
| 登录账号 | 使用手机号或邮箱注册 | 国内手机号即可，非常方便 |
| 选择 AI 模型 | 选择默认使用的 AI 模型 | 推荐选 Claude Sonnet |
| 导入 VS Code 设置 | 一键导入 VS Code 配置 | 如果你之前用 VS Code，建议导入 |

⚠️ **注意**：Trae 目前仅支持 macOS 和 Windows，Linux 版本尚未发布。

### 核心功能（Builder 模式、Chat 模式）

#### Builder 模式

Builder 模式是 Trae 的核心功能，类似于 Cursor 的 Composer 模式。你描述需求，AI 自动创建和修改多个文件。

**如何使用 Builder 模式**：

1. 打开 Trae，点击左侧边栏的 Builder 图标
2. 在输入框中描述你的需求
3. AI 会分析项目、规划方案、自动修改文件
4. 审查修改内容，确认或调整

**Builder 模式示例**：

```
你：创建一个待办事项应用，支持添加、完成、删除任务，数据保存在 localStorage

Builder 会：
1. 创建项目结构
2. 生成 HTML、CSS、JavaScript 文件
3. 实现所有功能逻辑
4. 展示修改，等待你确认
```

#### Chat 模式

Chat 模式和 Cursor 的 Chat 类似，用于和 AI 对话、提问、讨论方案。

**如何使用 Chat 模式**：

1. 点击左侧边栏的 Chat 图标
2. 在输入框中输入问题或需求
3. AI 会结合当前项目上下文回答

**Chat 模式特色**：

| 特色 | 说明 |
|------|------|
| 中文优化 | 对中文问题的理解和回答更准确 |
| 上下文感知 | 能看到当前打开的文件和项目结构 |
| 代码应用 | 生成的代码可以一键应用到文件 |
| 文件引用 | 可以引用特定文件让 AI 分析 |

💡 **选择建议**：

## AI IDE vs 终端 AI 工具对比

### Cursor/Trae vs Claude Code/Codex 对比表

| 对比维度 | AI IDE（Cursor/Trae） | 终端 AI 工具（Claude Code/Codex） |
|---------|----------------------|-------------------------------|
| **运行环境** | 图形界面编辑器 | 终端（命令行） |
| **交互方式** | 可视化界面 + 对话框 | 纯文本对话 |
| **代码编辑** | 可视化 diff，一键应用 | 文本 diff，需确认 |
| **代码补全** | ✅ 实时补全，Tab 接受 | ❌ 不支持 |
| **多文件编辑** | ✅ Composer/Builder | ✅ 支持 |
| **运行命令** | ⚠️ 有限支持 | ✅ 完全支持 |
| **项目理解** | 基于打开的文件和引用 | 自动扫描整个项目 |
| **学习曲线** | 低，可视化操作 | 中，需要熟悉终端 |
| **适合人群** | 所有人，特别是新手 | 终端用户、高级开发者 |
| **适合场景** | 日常编码、UI 开发、学习 | 项目重构、批量操作、自动化 |

### 各自优缺点

**AI IDE 的优缺点**：

| 优点 ✅ | 缺点 ❌ |
|---------|---------|
| 可视化界面，上手简单 | 运行终端命令能力有限 |
| 实时代码补全，编码流畅 | 对项目整体理解不如终端工具深 |
| diff 视图直观，审查方便 | 资源占用较大 |
| 适合 UI 开发和前端调试 | 处理大型项目时可能卡顿 |

**终端 AI 工具的优缺点**：

| 优点 ✅ | 缺点 ❌ |
|---------|---------|
| 完全控制终端，能执行任何命令 | 纯文本界面，新手不友好 |
| 项目上下文理解更深 | 没有代码补全 |
| 适合自动化和批量操作 | 需要熟悉命令行操作 |
| 资源占用小 | 审查代码不如可视化直观 |

### 适用场景

| 场景 | 推荐类型 | 原因 |
|------|---------|------|
| 日常编码开发 | AI IDE | 补全 + 对话 + 编辑一体化 |
| UI 界面开发 | AI IDE | 可视化预览，所见即所得 |
| 项目重构 | 终端 AI | 理解项目更深，批量操作更强 |
| 自动化脚本 | 终端 AI | 能直接执行命令 |
| 学习编程 | AI IDE | 上手简单，反馈直观 |
| CI/CD 集成 | 终端 AI | 命令行原生支持 |
| 代码审查 | 两者皆可 | IDE 审查更直观，终端审查更全面 |

## 如何配合使用多种 AI 工具

### 推荐工作流：AI IDE + 终端 AI + 对话 AI

最有效的 AI 编程方式不是只用一个工具，而是**组合使用**，让每个工具发挥它最擅长的部分：

```
┌─────────────────────────────────────────────────┐
│              AI 编程工具组合工作流                  │
│                                                   │
│  📋 对话 AI（ChatGPT / Claude）                   │
│  → 方案讨论、架构设计、概念学习                     │
│                                                   │
│  🖥️ AI IDE（Cursor / Trae）                      │
│  → 日常编码、代码补全、小范围修改                   │
│                                                   │
│  ⌨️ 终端 AI（Claude Code / Codex）               │
│  → 项目重构、批量操作、自动化任务                   │
│                                                   │
└─────────────────────────────────────────────────┘
```

| 工具类型 | 代表 | 负责什么 | 什么时候用 |
|---------|------|---------|-----------|
| 对话 AI | ChatGPT、Claude | 方案讨论、学习概念 | 开始新功能前，讨论方案 |
| AI IDE | Cursor、Trae | 日常编码、代码补全 | 写代码时全程使用 |
| 终端 AI | Claude Code、Codex | 项目级操作、自动化 | 需要批量修改或自动化时 |

### 实际场景示例

**场景 1：开发新功能**

```
步骤 1 — 用对话 AI 讨论方案
  你：我需要给 App 添加推送通知功能，有哪些方案？
  ChatGPT：有 APNs、FCM、OneSignal 等方案，各自优缺点是...

步骤 2 — 用 AI IDE 编写代码
  你在 Cursor 中：用 Composer 创建推送通知模块，按照刚才讨论的方案实现

步骤 3 — 用终端 AI 批量处理
  你在 Claude Code 中：给所有现有页面添加推送权限请求逻辑，运行测试确保没有破坏
```

**场景 2：修复线上 Bug**

```
步骤 1 — 用对话 AI 分析问题
  你：用户反馈 App 闪退，日志显示...，可能是什么原因？
  Claude：根据日志分析，可能是...

步骤 2 — 用 AI IDE 定位和修复
  你在 Cursor 中：用 Chat 打开相关文件，让 AI 分析具体代码行

步骤 3 — 用终端 AI 验证
  你在 Claude Code 中：运行完整测试套件，确保修复没有引入新问题
```

**场景 3：项目重构**

```
步骤 1 — 用对话 AI 制定方案
  你：我想把项目的状态管理从 Redux 迁移到 Zustand，有什么建议？
  Claude：建议分步迁移，先从...

步骤 2 — 用终端 AI 执行迁移
  你在 Claude Code 中：按照迁移方案，把用户模块从 Redux 迁移到 Zustand

步骤 3 — 用 AI IDE 微调
  你在 Cursor 中：用 Inline Edit 微调迁移后的代码细节
```

💡 **核心原则**：**对话 AI 负责思考，AI IDE 负责编码，终端 AI 负责执行**。三者配合，效率最高。

⚠️ **注意**：同时使用多个 AI 工具时，务必用 Git 管理所有变更。每次切换工具前先提交当前状态，这样无论哪个工具改坏了，都能轻松回退。
