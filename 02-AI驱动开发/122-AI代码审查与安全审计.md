## 1. AI 代码审查概述

### 1.1 传统 Code Review 的痛点

传统 Code Review 就像**手工质检流水线**——每个零件都要人工检查，效率低、易疲劳、标准不统一。具体痛点如下：

| 痛点 | 描述 | 影响 |
|------|------|------|
| **效率瓶颈** | 大型 PR 动辄几百行变更，人工逐行审查耗时巨大 | 审查周期长，阻塞发布 |
| **标准不一** | 不同审查者关注点不同，有人看逻辑、有人看格式 | 审查质量参差不齐 |
| **疲劳遗漏** | 连续审查超过 30 分钟后，注意力显著下降 | 容易漏掉关键问题 |
| **安全盲区** | 多数开发者缺乏安全审计专业训练 | 安全漏洞被忽略 |
| **知识壁垒** | 新人不熟悉项目规范，审查意见缺乏建设性 | 审查流于形式 |

> 💡 就像医院体检，如果只靠一位全科医生从头查到脚，难免遗漏。AI 审查相当于增加了一位"AI 专科医生"，先做初筛，再由人类专家复核。

### 1.2 AI 审查的定位：辅助而非替代

AI 审查的定位是**辅助工具**，而非替代人类审查者。类比自动驾驶的 L2 级别——AI 辅助驾驶，人类始终握着方向盘：

| 维度 | AI 擅长 | 人类擅长 |
|------|---------|---------|
| 速度 | 秒级扫描数千行代码 | 每小时约 200-400 行 |
| 一致性 | 每次都检查相同维度 | 受状态和情绪影响 |
| 模式识别 | 擅长发现已知模式（安全漏洞、代码异味） | 擅长理解业务意图 |
| 上下文理解 | 有限，依赖 Prompt 提供的上下文 | 深刻理解项目背景和业务逻辑 |
| 创造性建议 | 基于训练数据的常见方案 | 能提出创新性解决方案 |
| 误判处理 | 可能产生误报或漏报 | 能结合经验判断真伪 |

> ⚠️ **关键原则**：AI 审查 ≠ 自动通过。AI 的审查结果必须经过人类确认后才能作为决策依据。把 AI 当作"第一道防线"，而不是"唯一防线"。

### 1.3 人机协作审查流程

推荐的人机协作审查流程分为四个阶段：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  1. AI 初筛  │───▶│  2. 人工复核  │───▶│  3. 协作讨论  │───▶│  4. 确认合入  │
│  自动扫描    │    │  重点审查    │    │  解决分歧    │    │  合并代码    │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

1. **AI 初筛**：提交 PR 后自动触发 AI 审查，输出结构化审查报告
2. **人工复核**：审查者根据 AI 报告，重点检查高优先级问题和 AI 标记的盲区
3. **协作讨论**：对 AI 和人工意见不一致的地方进行讨论
4. **确认合入**：所有问题解决后，由人工最终确认合并

## 2. AI 审查工具对比

### 2.1 主流 AI 审查工具一览

当前市场上有多款 AI 代码审查工具，各有侧重：

| 工具 | 核心功能 | 集成方式 | 语言支持 | 定价模型 | 适合场景 |
|------|---------|---------|---------|---------|---------|
| **GitHub Copilot Review** | PR 自动审查、代码建议 | GitHub 原生集成 | 多语言 | GitHub Enterprise 订阅 | 已用 GitHub 生态的团队 |
| **CodeRabbit** | PR 逐行审查、摘要生成、对话式反馈 | GitHub/GitLab App | 多语言 | 免费开源项目 / 付费 | 需要详细审查报告的团队 |
| **Sourcery** | Swift/Python 代码质量审查、自动重构 | IDE 插件 + CLI | Swift, Python | 免费基础版 / 付费 | Swift/iOS 项目首选 |
| **Claude Code Review** | 深度上下文审查、自定义 Prompt | CLI + API | 多语言 | API 按量计费 | 需要高度自定义审查逻辑 |
| **Cursor Review** | IDE 内审查、上下文感知 | Cursor IDE 内 | 多语言 | Cursor 订阅 | Cursor 用户日常审查 |

### 2.2 选型建议

选择 AI 审查工具时，就像选车——没有最好的，只有最适合的：

| 团队情况 | 推荐工具 | 理由 |
|---------|---------|------|
| iOS 纯 Swift 项目 | Sourcery + Claude Code | Sourcery 深度理解 Swift 语法，Claude Code 补充安全审查 |
| GitHub 生态团队 | Copilot Review + CodeRabbit | 双重审查覆盖，Copilot 轻量快速，CodeRabbit 详细深入 |
| 需要高度自定义 | Claude Code | Prompt 完全可控，可针对项目定制审查维度 |
| 预算有限 | CodeRabbit（开源免费）+ SwiftLint | 基础审查免费，SwiftLint 补充静态规则 |
| 企业合规要求高 | CodeRabbit + Semgrep + Claude Code | 多层扫描，合规审计全覆盖 |

> 💡 **实用建议**：不要只用一个工具。不同工具的审查角度不同，组合使用效果最佳。推荐"轻量工具做日常 + 深度工具做关键 PR"的策略。

## 3. AI 审查实践

### 3.1 PR 描述 + Diff 喂给 AI

AI 审查的第一步是**提供足够的上下文**。就像让医生看病，你得把症状和病史都说清楚：

```bash
git diff main...feature/login-module > diff.patch
```

将 PR 的描述和 Diff 一起喂给 AI：

```swift
// PR 描述模板示例
/*
## PR 标题
feat: 实现用户登录模块

## 变更说明
- 新增 LoginViewController，支持邮箱/密码登录
- 集成 Keychain 存储用户凭证
- 添加网络请求错误处理

## 影响范围
- 新增文件：LoginViewController.swift, LoginViewModel.swift
- 修改文件：NetworkManager.swift（新增登录 API）
- 依赖变更：新增 KeychainAccess 库

## 测试情况
- ✅ 单元测试通过
- ✅ UI 测试通过
- ⚠️ 未测试弱网环境
*/
```

### 3.2 审查维度

AI 审查应覆盖四个核心维度：

| 维度 | 检查内容 | 严重程度示例 |
|------|---------|-------------|
| **代码质量** | 命名规范、代码重复、复杂度、可读性 | 中 |
| **安全** | 注入攻击、密钥泄露、权限越权 | 高 |
| **性能** | 内存泄漏、主线程阻塞、N+1 查询 | 中-高 |
| **可维护性** | 耦合度、测试覆盖、文档完整性 | 低-中 |

### 3.3 审查 Prompt 模板

以下是一个经过验证的审查 Prompt 模板：

```
你是一位资深的 iOS 安全与代码质量审查专家。

【审查上下文】
项目技术栈：Swift 5.9 + UIKit + SnapKit + MVVM + SPM
项目规范：遵循 Swift API Design Guidelines，使用 [weak self] 避免循环引用

【审查任务】
请对以下代码变更进行审查，按四个维度输出结果：

1. 代码质量：命名、结构、重复代码、Swift 惯用写法
2. 安全：Keychain 使用、API 密钥暴露、输入验证、权限控制
3. 性能：主线程阻塞、内存泄漏、不必要的对象创建
4. 可维护性：耦合度、可测试性、文档

【输出格式】
对每个问题按以下格式输出：
- [严重程度: 🔴高/🟡中/🟢低] 问题标题
  - 位置：文件名:行号
  - 说明：问题描述
  - 建议：修复建议或代码示例

【代码变更】
{在此粘贴 diff}
```

> 💡 **提示**：Prompt 越具体，审查结果越精准。务必包含项目技术栈和编码规范，这样 AI 才能给出符合项目风格的建议。

### 3.4 审查结果分级

审查结果应按严重程度分级处理，就像医院分诊——急症先治，轻症后看：

| 级别 | 标识 | 含义 | 处理要求 |
|------|------|------|---------|
| 🔴 **Critical** | 必须修复 | 安全漏洞、崩溃风险、数据丢失 | 阻塞合并，必须修复 |
| 🟡 **Warning** | 建议修复 | 性能隐患、代码异味、可维护性问题 | 建议修复，可协商 |
| 🟢 **Info** | 参考信息 | 代码风格、命名建议、优化空间 | 自行判断，不阻塞 |
| 🔵 **Positive** | 良好实践 | 值得肯定的写法 | 无需处理，鼓励保持 |

## 4. iOS 安全审计

### 4.1 OWASP Mobile Top 10 与 AI 扫描

OWASP Mobile Top 10 是移动安全的"十大天敌清单"。AI 可以帮助逐项扫描：

| OWASP 编号 | 风险 | AI 扫描 Prompt 关键词 | iOS 典型场景 |
|-----------|------|---------------------|-------------|
| M1 | 凭证管理不当 | Keychain、UserDefaults、硬编码密码 | Token 存 UserDefaults 而非 Keychain |
| M2 | 供应链不足 | 第三方库版本、SPM 依赖 | 使用已知漏洞的旧版 Alamofire |
| M3 | 不安全的认证/授权 | 生物识别绕过、本地认证 | FaceID 验证仅前端校验 |
| M4 | 输入/输出操作不当 | 深度链接、URL Scheme | 未验证的 Universal Link 跳转 |
| M5 | 不安全的通信 | HTTP、证书校验、SSL Pinning | 允许 HTTP 明文传输 |
| M6 | 不安全的隐私控制 | 权限滥用、数据收集 | 申请了不必要的定位权限 |
| M7 | 二进制文件不安全 | 越狱检测、代码混淆 | 缺少越狱检测机制 |
| M8 | 安全配置错误 | Debug 模式、日志泄露 | Release 包仍输出 NSLog |
| M9 | 不安全的数据存储 | 文件加密、SQLCipher | 敏感数据明文存 SQLite |
| M10 | 加密不足 | 硬编码密钥、弱算法 | 使用 MD5 做哈希 |

AI 扫描 Prompt 示例：

```
请根据 OWASP Mobile Top 10 (2024)，逐项检查以下 iOS 代码变更中是否存在安全风险。
对每项风险给出：OWASP 编号、风险等级、具体位置、修复建议。
重点关注：Keychain 使用方式、网络请求安全、敏感数据存储、权限声明。
```

### 4.2 Keychain 泄露检测

Keychain 是 iOS 最安全的本地存储方式，但使用不当仍会泄露：

```swift
// ❌ 错误：将密码存入 UserDefaults
UserDefaults.standard.set(password, forKey: "userPassword")

// ✅ 正确：使用 Keychain 存储敏感信息
import KeychainAccess

let keychain = Keychain(service: "com.example.app")
  .accessibility(.whenUnlockedThisDeviceOnly)

try keychain.set(token, key: "authToken")
```

AI 审查 Keychain 的 Prompt 片段：

```
检查以下代码中 Keychain 的使用是否安全：
1. 是否有敏感数据（密码、Token、密钥）存入了 UserDefaults 而非 Keychain？
2. Keychain 的 accessibility 级别是否合适？
3. 是否使用了 whenUnlockedThisDeviceOnly 而非 afterFirstUnlock？
4. Keychain 的 service 和 group 标识是否正确？
```

### 4.3 API 密钥硬编码扫描

API 密钥硬编码是 iOS 开发中最常见的安全问题之一，就像**把家门钥匙贴在大门上**：

```swift
// ❌ 危险：API 密钥硬编码在源码中
let apiKey = "sk-abc123def456ghi789"
let openAIKey = "sk-proj-xxxxxxxxxxxx"

// ✅ 正确：从环境变量或 xcconfig 读取
// 在 .xcconfig 文件中（已加入 .gitignore）：
// API_KEY = sk-abc123def456ghi789
let apiKey = Bundle.main.infoDictionary?["API_KEY"] as? String ?? ""
```

AI 扫描硬编码密钥的正则模式：

```bash
# 用 grep 快速扫描常见密钥模式
grep -rn --include="*.swift" \
  -E '(sk-[a-zA-Z0-9]{20,}|AKIA[A-Z0-9]{16}|AIza[A-Za-z0-9_\-]{35})' \
  /path/to/project
```

> ⚠️ **警告**：即使密钥已经从代码中删除，Git 历史中仍然保留。一旦密钥泄露，必须立即轮换（rotate），仅删除代码是不够的。

### 4.4 网络传输安全检查

```swift
// ❌ 危险：允许 HTTP 明文传输
let url = URL(string: "http://api.example.com/login")!

// ❌ 危险：禁用 ATS（App Transport Security）
// Info.plist 中 NSAllowsArbitraryLoads = true

// ❌ 危险：信任所有证书
let session = URLSession(configuration: .default,
    delegate: TrustAllCertificatesDelegate(),  // 绝对不要这样做
    delegateQueue: nil)

// ✅ 正确：使用 HTTPS + Certificate Pinning
let pinnedURL = URL(string: "https://api.example.com/login")!

// 使用 Alamofire 的 ServerTrustManager
let serverTrustManager = ServerTrustManager(
    evaluators: [
        "api.example.com": PublicKeysTrustEvaluator(
            performDefaultValidation: true,
            validateHost: true
        )
    ]
)
```

### 4.5 Info.plist 敏感信息泄露

Info.plist 是 iOS App 的"身份证"，但经常泄露不该暴露的信息：

| 检查项 | 风险 | 修复方式 |
|-------|------|---------|
| `NSAllowsArbitraryLoads` | 允许 HTTP 请求 | 仅对必要域名设置例外 |
| 自定义键值含 API Key | 密钥暴露 | 移至 Keychain 或 xcconfig |
| `NSAppTransportSecurity` 过于宽松 | 中间人攻击 | 逐域名配置例外 |
| 调试描述字符串 | 泄露内部信息 | Release 包移除 |
| `ITSAppUsesNonExemptEncryption` | 出口合规问题 | 正确声明加密使用情况 |

AI 扫描 Info.plist 的 Prompt：

```
请检查以下 Info.plist 内容，识别可能的安全风险：
1. 是否存在 NSAllowsArbitraryLoads = YES？
2. 是否有自定义键包含 API 密钥、Token 等敏感信息？
3. ATS 例外域名是否合理？
4. 隐私权限声明是否与实际使用匹配？
```

## 5. CI/CD 中集成 AI 审查

### 5.1 GitHub Actions + CodeRabbit

CodeRabbit 可以零配置集成到 GitHub Actions：

```yaml
name: AI Code Review

on:
  pull_request:
    types: [opened, synchronize]

permissions:
  pull-requests: write
  contents: read

jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: CodeRabbit Review
        uses: coderabbitai/ai-pr-reviewer@latest
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        with:
          language: zh-CN
          review_simple_changes: false
          review_comment_lgtm: true
```

### 5.2 pre-commit hook + AI 检查

在提交前就拦截问题，就像**出门前照镜子**——先自查，再出门：

```bash
#!/bin/bash
# .git/hooks/pre-commit

STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM | grep "\.swift$")

if [ -z "$STAGED_FILES" ]; then
    exit 0
fi

echo "🔍 Running AI pre-commit checks..."

# 1. SwiftLint 快速检查
swiftlint lint --path $STAGED_FILES --strict
if [ $? -ne 0 ]; then
    echo "❌ SwiftLint check failed"
    exit 1
fi

# 2. 硬编码密钥扫描
for FILE in $STAGED_FILES; do
    if grep -qE '(sk-[a-zA-Z0-9]{20,}|AKIA[A-Z0-9]{16})' "$FILE"; then
        echo "❌ Possible hardcoded API key in $FILE"
        exit 1
    fi
done

# 3. AI 快速审查（可选，耗时较长）
if [ "$AI_PRE_COMMIT" = "1" ]; then
    DIFF=$(git diff --cached)
    claude --prompt "快速审查以下 Swift 代码变更，只报告 🔴Critical 级别问题：\n$DIFF" \
        --max-tokens 500
fi

echo "✅ Pre-commit checks passed"
```

> 💡 **提示**：pre-commit 中的 AI 审查建议设为可选（通过环境变量控制），因为 AI 调用有延迟，日常提交可能不需要每次都跑。

### 5.3 PR 自动审查工作流

完整的 PR 自动审查工作流：

```yaml
name: PR Auto Review

on:
  pull_request:
    types: [opened, synchronize, ready_for_review]

jobs:
  security-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Semgrep Security Scan
        uses: semgrep/semgrep-action@v1
        with:
          config: >-
            p/swift
            p/owasp-mobile
          publishToken: ${{ secrets.SEMGREP_TOKEN }}

  ai-review:
    runs-on: ubuntu-latest
    needs: security-scan
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get PR Diff
        id: diff
        run: |
          DIFF=$(git diff origin/main...HEAD)
          echo "diff<<EOF" >> $GITHUB_OUTPUT
          echo "$DIFF" >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT

      - name: AI Security Review
        uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            作为 iOS 安全审查专家，检查以下代码变更中的安全问题：
            - API 密钥硬编码
            - Keychain 使用不当
            - 网络传输安全
            - 敏感信息泄露
            只报告 🔴Critical 和 🟡Warning 级别问题。
          diff: ${{ steps.diff.outputs.diff }}
```

### 5.4 审查结果自动评论

AI 审查结果应自动发布为 PR 评论，方便团队查看和讨论：

```yaml
- name: Post Review Comment
  uses: actions/github-script@v7
  with:
    script: |
      const review = `${{ steps.ai-review.outputs.result }}`;
      const body = `## 🤖 AI 代码审查报告\n\n${review}\n\n---\n*由 AI 自动生成，请结合人工审查确认*`;
      github.rest.issues.createComment({
        owner: context.repo.owner,
        repo: context.repo.repo,
        issue_number: context.issue.number,
        body: body
      });
```

## 6. 静态分析 + AI

### 6.1 SwiftLint 规则定制 + AI 建议

SwiftLint 是 Swift 项目的"语法警察"，但默认规则可能不完全适合你的项目。AI 可以帮助定制规则：

```yaml
# .swiftlint.yml
opt_in_rules:
  - force_unwrapping
  - implicitly_unwrapped_optional
  - empty_count
  - closure_spacing
  - overridden_super_call
  - private_outlet
  - vertical_whitespace_closing_braces

disabled_rules:
  - trailing_whitespace
  - type_name

custom_rules:
  no_hardcoded_api_key:
    name: "No Hardcoded API Key"
    regex: '(sk-[a-zA-Z0-9]{20,}|AKIA[A-Z0-9]{16})'
    message: "请勿硬编码 API 密钥，使用 xcconfig 或 Keychain"
    severity: error

  no_userdefaults_for_sensitive:
    name: "No UserDefaults for Sensitive Data"
    regex: 'UserDefaults\.standard\.set\(.+,\s*forKey:\s*"(password|token|secret|key|credential)"'
    message: "敏感数据应存入 Keychain，而非 UserDefaults"
    severity: error

  weak_self_in_closure:
    name: "Weak Self in Closures"
    regex: '\{\s*\(\)\s*in(?![^}]*\[weak self\])'
    message: "闭包中应使用 [weak self] 避免循环引用"
    severity: warning
```

让 AI 帮你生成自定义规则：

```
请为 SwiftLint 编写自定义规则，检测以下 iOS 常见问题：
1. 在非主线程更新 UI
2. 使用 DispatchQueue.main.async 嵌套
3. UIViewController 中直接持有网络请求
4. 未使用 [weak self] 的闭包
输出格式：YAML custom_rules 配置
```

## 7. 审查质量保障

### 7.1 AI 审查的误报处理

AI 审查的误报就像**烟雾报警器误响**——响了不一定是着火，但每次都要确认。处理策略如下：

| 误报类型 | 原因 | 处理方式 |
|---------|------|---------|
| 上下文不足 | AI 不了解项目特定设计 | 在 Prompt 中补充项目上下文 |
| 规则过严 | 自定义规则匹配范围太广 | 调整规则的正则或条件 |
| 模式误判 | AI 将合理代码误判为问题 | 标记为已知误报，加入白名单 |
| 版本差异 | AI 基于旧版本 API 给建议 | 更新 Prompt 中的 API 版本信息 |

误报白名单示例：

```yaml
# .ai-review-whitelist.yml
whitelist:
  - rule: no_userdefaults_for_sensitive
    file: "OnboardingManager.swift"
    reason: "首次引导标记不是敏感数据"
  - rule: ios-nslog-in-release
    file: "CrashReporter.swift"
    reason: "崩溃上报模块需要日志输出"
```

### 7.2 人工复核策略

人工复核应聚焦于 AI 无法覆盖的区域：

| 复核重点 | 说明 | 时间占比 |
|---------|------|---------|
| **业务逻辑正确性** | AI 难以理解复杂业务规则 | 40% |
| **架构一致性** | 新代码是否符合项目架构 | 20% |
| **AI 标记的盲区** | AI 明确表示不确定的地方 | 20% |
| **AI 高优先级问题** | 确认 AI 报告的 Critical 是否属实 | 15% |
| **AI 未覆盖的维度** | 如国际化、无障碍等 | 5% |

### 7.3 审查指标追踪

用数据驱动审查质量改进：

| 指标 | 计算方式 | 目标值 |
|------|---------|-------|
| **AI 误报率** | 误报数 / AI 报告总数 | < 20% |
| **AI 漏报率** | 人工发现但 AI 遗漏的问题数 / 人工发现总数 | < 30% |
| **审查覆盖率** | 经过 AI 审查的 PR 数 / 总 PR 数 | > 90% |
| **平均审查时间** | PR 从提交到审查完成的平均时间 | < 4 小时 |
| **Critical 发现率** | AI 发现的 Critical 问题数 / 总 Critical 问题数 | > 70% |

### 7.4 持续改进审查规则

审查规则不是一成不变的，需要根据实际效果持续调优：

```
审查规则改进循环：

  发现误报/漏报 → 分析原因 → 修改规则/Prompt → 验证效果 → 上线
       ↑                                                    │
       └────────────────────────────────────────────────────┘
```

改进记录模板：

```markdown
| 日期 | 问题类型 | 描述 | 原因分析 | 改进措施 | 效果 |
|------|---------|------|---------|---------|------|
| 2025-03-15 | 误报 | AI 将测试中的硬编码标记为密钥 | 未排除测试文件 | 规则添加测试目录排除 | 误报减少 30% |
| 2025-03-20 | 漏报 | 未发现 Keychain accessibility 问题 | Prompt 未提及 | 补充 Keychain 审查维度 | 新增 5 个有效发现 |
```

### 8.2 完整 GitHub Actions 工作流

```yaml
name: AI Review Pipeline

on:
  pull_request:
    types: [opened, synchronize]

concurrency:
  group: ai-review-${{ github.event.pull_request.number }}
  cancel-in-progress: true

permissions:
  pull-requests: write
  contents: read
  checks: write

jobs:
  swiftlint:
    name: SwiftLint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: norio-nomura/action-swiftlint@3.2.1
        with:
          args: --strict --reporter github-actions-logging

  semgrep:
    name: Semgrep Security
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: semgrep/semgrep-action@v1
        with:
          config: >-
            p/swift
            p/owasp-mobile
            .semgrep/ios-security.yaml

  ai-security-review:
    name: AI Security Review
    runs-on: ubuntu-latest
    needs: [swiftlint, semgrep]
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get Diff
        id: diff
        run: |
          DIFF=$(git diff origin/main...HEAD -- '*.swift')
          echo "diff<<EOF" >> $GITHUB_OUTPUT
          echo "$DIFF" >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT

      - name: Run AI Security Review
        id: review
        uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt_file: .ai-review/prompt-templates/security-review.md
          diff: ${{ steps.diff.outputs.diff }}

      - name: Post Review Comment
        uses: actions/github-script@v7
        with:
          script: |
            const review = `${{ steps.review.outputs.result }}`;
            const body = `## 🔒 AI 安全审查报告\n\n${review}\n\n---\n*🤖 AI 审查结果仅供参考，请结合人工审查确认*`;
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: body
            });

  ai-quality-review:
    name: AI Quality Review
    runs-on: ubuntu-latest
    needs: [swiftlint, semgrep]
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get Diff
        id: diff
        run: |
          DIFF=$(git diff origin/main...HEAD -- '*.swift')
          echo "diff<<EOF" >> $GITHUB_OUTPUT
          echo "$DIFF" >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT

      - name: Run AI Quality Review
        id: review
        uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt_file: .ai-review/prompt-templates/quality-review.md
          diff: ${{ steps.diff.outputs.diff }}

      - name: Post Quality Comment
        uses: actions/github-script@v7
        with:
          script: |
            const review = `${{ steps.review.outputs.result }}`;
            const body = `## 📊 AI 代码质量审查报告\n\n${review}\n\n---\n*🤖 AI 审查结果仅供参考，请结合人工审查确认*`;
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: body
            });
```

## 本章小结

| 主题 | 核心要点 |
|------|---------|
| AI 审查概述 | AI 是辅助而非替代，人机协作流程：AI 初筛 → 人工复核 → 协作讨论 → 确认合入 |
| 工具对比 | 无单一最优工具，推荐组合策略：轻量工具日常 + 深度工具关键 PR |
| 审查实践 | Prompt 模板是关键，审查维度覆盖质量/安全/性能/可维护性，结果分级处理 |
| iOS 安全审计 | 对齐 OWASP Mobile Top 10，重点检查 Keychain、API 密钥、网络传输、Info.plist |
| CI/CD 集成 | GitHub Actions + CodeRabbit 自动化，pre-commit hook 前置拦截，PR 自动评论 |
| 静态分析 + AI | SwiftLint 定制规则 + AI 建议，Semgrep 语义扫描，CodeQL/AI 解读 Xcode Analyzer |
| 质量保障 | 追踪误报率/漏报率，人工复核聚焦业务逻辑，持续改进审查规则 |
| 实战流水线 | 多层扫描（SwiftLint → Semgrep → AI Security → AI Quality），Prompt 模板化，结果自动评论 |

> 💡 **最后提醒**：AI 代码审查是"安全带"而非"自动驾驶"。它能显著提高审查效率和覆盖面，但最终的代码质量责任始终在人类开发者身上。建立"AI 初筛 + 人工复核"的习惯，让 AI 成为你的得力助手，而不是甩手掌柜的借口。
