## 1. AI 生成测试概述

### 1.1 为什么测试是 AI 最擅长的领域

写测试这件事，开发者普遍不爱做——它重复、枯燥、没有"创造感"。但恰恰是这些特点，让 AI 在生成测试方面如鱼得水。

> 💡 **类比**：写业务代码像做菜——需要创意、经验和判断力；写测试像洗碗——机械、重复，但必须做。AI 就是你的洗碗机，把最枯燥的活交给它。

AI 擅长生成测试的原因：

| 特点 | 说明 |
|------|------|
| **规则明确** | 测试有固定模式：Arrange-Act-Assert，AI 最擅长遵循模式 |
| **上下文有限** | 单个测试通常只关注一个函数/方法，上下文范围小，AI 不容易"幻觉" |
| **边界值可枚举** | 空值、零值、极大值、负数——AI 可以系统性地覆盖所有边界情况 |
| **重复性高** | 测试代码结构高度相似，AI 的模式匹配能力可以批量生成 |
| **反馈闭环快** | 跑一遍测试就知道对不对，AI 可以快速自我修正 |

### 1.2 AI 生成测试 vs 手写测试

| 对比维度 | 手写测试 | AI 生成测试 |
|---------|---------|-----------|
| **速度** | 慢，一个函数的测试可能要 15-30 分钟 | 快，几秒到几分钟即可生成 |
| **覆盖率** | 依赖开发者经验，容易遗漏边界情况 | 系统性覆盖，边界值、异常路径更全面 |
| **一致性** | 不同开发者风格不同 | 风格统一，命名规范一致 |
| **维护性** | 开发者理解自己的测试，容易维护 | 需要审查 AI 生成的测试，确保可维护 |
| **创造性** | 可以设计精巧的测试场景 | 擅长常规场景，复杂场景可能需要人工补充 |
| **成本** | 人力成本高 | AI 成本低，但需要审查时间 |

> ⚠️ **注意**：AI 生成测试 ≠ 不审查测试。AI 生成的测试可能存在"看起来覆盖了但实际没测到关键逻辑"的问题，审查是必不可少的环节。

### 1.3 测试金字塔与 AI 的切入点

```
        /  E2E 测试  \          ← AI 辅助生成，但维护成本高
       /  集成测试    \         ← AI 擅长生成 Mock 和 Stub
      /  单元测试      \        ← AI 最擅长，效率最高
     /__________________\
```

| 测试层级 | AI 介入程度 | 说明 |
|---------|-----------|------|
| **单元测试** | ⭐⭐⭐⭐⭐ | AI 的绝对主场，输入输出明确，可批量生成 |
| **集成测试** | ⭐⭐⭐⭐ | AI 可生成 Mock/Stub 和接口测试，需要人工设计集成场景 |
| **UI 测试** | ⭐⭐⭐ | AI 可生成基础交互测试，复杂交互需人工补充 |
| **E2E 测试** | ⭐⭐ | AI 辅助编写脚本，但环境搭建和场景设计仍需人工 |

> 💡 **策略**：让 AI 从金字塔底部开始——先生成大量单元测试，再逐步向上覆盖集成测试和 UI 测试。底部投入最多，回报也最大。

## 2. AI 生成单元测试

### 2.1 XCTest 与 Swift Testing 代码生成

Swift 5.9 引入了全新的 Swift Testing 框架，相比传统 XCTest 更简洁。AI 可以同时生成两种风格的测试。

**传统 XCTest 风格**：

```swift
import XCTest
@testable import MyApp

final class CalculatorTests: XCTestCase {
    var calculator: Calculator!

    override func setUp() {
        calculator = Calculator()
    }

    override func tearDown() {
        calculator = nil
    }

    func testAddTwoNumbers() {
        let result = calculator.add(3, 5)
        XCTAssertEqual(result, 8)
    }

    func testAddNegativeNumbers() {
        let result = calculator.add(-3, -5)
        XCTAssertEqual(result, -8)
    }

    func testAddZero() {
        let result = calculator.add(0, 5)
        XCTAssertEqual(result, 5)
    }
}
```

**Swift Testing 风格**：

```swift
import Testing
@testable import MyApp

@Suite("Calculator 测试")
struct CalculatorTests {
    @Test("两个正数相加")
    func addTwoNumbers() {
        let calculator = Calculator()
        #expect(calculator.add(3, 5) == 8)
    }

    @Test("两个负数相加")
    func addNegativeNumbers() {
        let calculator = Calculator()
        #expect(calculator.add(-3, -5) == -8)
    }

    @Test("加零不影响结果")
    func addZero() {
        let calculator = Calculator()
        #expect(calculator.add(0, 5) == 5)
    }
}
```

> 💡 **提示**：告诉 AI 你使用哪种测试框架，它就会生成对应风格的代码。Swift Testing 更简洁，推荐新项目使用。

### 2.2 Mock / Stub 自动生成

Mock 和 Stub 是单元测试的核心工具，但手写它们非常繁琐。AI 可以根据协议或类定义自动生成。

**协议定义**：

```swift
protocol UserRepository {
    func find(by id: String) async throws -> User?
    func save(_ user: User) async throws -> User
    func delete(id: String) async throws -> Bool
}
```

**AI 生成的 Mock**：

```swift
final class MockUserRepository: UserRepository {
    var findResult: Result<User?, Error> = .success(nil)
    var saveResult: Result<User, Error> = .success(User(id: "1", name: "Test"))
    var deleteResult: Result<Bool, Error> = .success(true)

    private(set) var findCallCount = 0
    private(set) var saveCallCount = 0
    private(set) var deleteCallCount = 0
    private(set) var lastSavedUser: User?

    func find(by id: String) async throws -> User? {
        findCallCount += 1
        return try findResult.get()
    }

    func save(_ user: User) async throws -> User {
        saveCallCount += 1
        lastSavedUser = user
        return try saveResult.get()
    }

    func delete(id: String) async throws -> Bool {
        deleteCallCount += 1
        return try deleteResult.get()
    }
}
```

> 💡 **类比**：Mock 就像电影里的替身演员——长得像（实现同样的协议），但行为由导演（测试）控制。AI 可以根据"剧本"（协议定义）自动生成替身。

### 2.3 边界值与异常路径覆盖

AI 的一个巨大优势是能系统性地枚举边界值和异常路径，这是手写测试最容易遗漏的部分。

**被测函数**：

```swift
struct DiscountCalculator {
    enum DiscountError: Error {
        case invalidAge
        case negativePrice
    }

    func calculate(price: Double, age: Int) throws -> Double {
        guard price >= 0 else { throw DiscountError.negativePrice }
        guard age >= 0 && age <= 150 else { throw DiscountError.invalidAge }

        if age < 6 { return 0 }
        if age < 18 { return price * 0.5 }
        if age >= 65 { return price * 0.7 }
        return price
    }
}
```

**AI 生成的完整测试**：

```swift
@Suite("DiscountCalculator 测试")
struct DiscountCalculatorTests {
    let calculator = DiscountCalculator()

    @Test("6岁以下免费")
    func freeForChildren() {
        #expect(try! calculator.calculate(price: 100, age: 5) == 0)
        #expect(try! calculator.calculate(price: 100, age: 0) == 0)
    }

    @Test("6-17岁半价")
    func halfPriceForTeenagers() {
        #expect(try! calculator.calculate(price: 100, age: 6) == 50)
        #expect(try! calculator.calculate(price: 100, age: 17) == 50)
    }

    @Test("18-64岁全价")
    func fullPriceForAdults() {
        #expect(try! calculator.calculate(price: 100, age: 18) == 100)
        #expect(try! calculator.calculate(price: 100, age: 64) == 100)
    }

    @Test("65岁以上七折")
    func discountForSeniors() {
        #expect(try! calculator.calculate(price: 100, age: 65) == 70)
        #expect(try! calculator.calculate(price: 100, age: 150) == 70)
    }

    @Test("负价格抛出异常", .tags(.error))
    func negativePrice() {
        #expect(throws: DiscountCalculator.DiscountError.negativePrice) {
            try calculator.calculate(price: -1, age: 30)
        }
    }

    @Test("无效年龄抛出异常", .tags(.error))
    func invalidAge() {
        #expect(throws: DiscountCalculator.DiscountError.invalidAge) {
            try calculator.calculate(price: 100, age: -1)
        }
        #expect(throws: DiscountCalculator.DiscountError.invalidAge) {
            try calculator.calculate(price: 100, age: 151)
        }
    }

    @Test("价格为0时所有年龄段都是0")
    func zeroPrice() {
        #expect(try! calculator.calculate(price: 0, age: 30) == 0)
        #expect(try! calculator.calculate(price: 0, age: 5) == 0)
    }
}
```

### 2.4 Prompt 模板

以下是一个经过验证的 Prompt 模板，可以让 AI 高质量地生成单元测试：

```
你是一个 iOS 高级测试工程师。请为以下代码生成完整的单元测试。

【测试框架】Swift Testing（使用 @Suite、@Test、#expect）

【被测代码】
（粘贴代码）

【测试要求】
1. 覆盖所有正常路径
2. 覆盖所有边界值（零值、空值、极大值、极小值）
3. 覆盖所有异常/错误路径
4. 使用 Mock 替代外部依赖
5. 每个测试方法只测一个场景
6. 测试方法命名清晰，能看出测试意图

【Mock 要求】
- 使用 class 实现协议
- 记录方法调用次数
- 支持设置返回值和抛出错误
- 使用 private(set) 保护调用记录

【输出格式】
1. 先列出测试场景清单
2. 再输出完整测试代码
3. 最后说明覆盖率情况
```

> ⚠️ **注意**：不要只给 AI 代码就让它生成测试。明确指定测试框架、Mock 策略、命名规范等约束，输出质量会显著提升。

## 3. AI 生成 UI 测试

### 3.1 XCUITest 自动生成

XCUITest 是 Apple 官方的 UI 测试框架。AI 可以根据视图描述生成对应的 UI 测试代码。

```swift
final class LoginUITests: XCTestCase {
    let app = XCUIApplication()

    override func setUp() {
        continueAfterFailure = false
        app.launch()
    }

    func testSuccessfulLogin() {
        let emailField = app.textFields["email_field"]
        let passwordField = app.secureTextFields["password_field"]
        let loginButton = app.buttons["login_button"]

        emailField.tap()
        emailField.typeText("test@example.com")

        passwordField.tap()
        passwordField.typeText("password123")

        loginButton.tap()

        let homeTitle = app.staticTexts["home_title"]
        XCTAssertTrue(homeTitle.waitForExistence(timeout: 3))
    }

    func testLoginWithEmptyFields() {
        let loginButton = app.buttons["login_button"]
        loginButton.tap()

        let errorMessage = app.staticTexts["error_message"]
        XCTAssertTrue(errorMessage.exists)
        XCTAssertEqual(errorMessage.label, "请输入邮箱和密码")
    }
}
```

### 3.2 Accessibility Identifier 策略

UI 测试的稳定性高度依赖 Accessibility Identifier。AI 可以帮你制定标识符策略并批量添加。

**命名规范**：

| 元素类型 | 命名格式 | 示例 |
|---------|---------|------|
| 按钮 | `{动作}_{功能}` | `login_button`, `submit_order_button` |
| 输入框 | `{内容}_{field}` | `email_field`, `password_field` |
| 文本 | `{描述}_{label}` | `error_message`, `welcome_label` |
| 列表 | `{内容}_list` | `product_list`, `order_list` |
| 导航 | `{目标}_tab` | `home_tab`, `profile_tab` |

**SwiftUI 中添加标识符**：

```swift
TextField("邮箱", text: $email)
    .accessibilityIdentifier("email_field")

SecureField("密码", text: $password)
    .accessibilityIdentifier("password_field")

Button("登录") { login() }
    .accessibilityIdentifier("login_button")
```

> 💡 **提示**：让 AI 在生成视图代码的同时生成 Accessibility Identifier，而不是事后补加。这比写完 UI 再回头加要高效得多。

### 3.4 快照测试 Snapshot Testing

快照测试可以捕获视图的渲染结果，与基准图对比，确保 UI 不会意外变化。

```swift
import SnapshotTesting

@Suite("LoginView 快照测试")
struct LoginViewSnapshotTests {
```

> ⚠️ **警告**：快照测试在不同 Xcode 版本或系统版本间可能产生差异。CI 环境和本地环境的渲染结果可能不同，建议在 CI 中统一基准快照。

## 4. AI 生成异步测试

### 4.1 async/await 测试

Swift 的 async/await 让异步代码更清晰，AI 生成异步测试也变得更简单：

```swift
@Suite("UserService 异步测试")
struct UserServiceTests {
    var service: UserService!
    var mockRepository: MockUserRepository!

    init() {
        mockRepository = MockUserRepository()
        service = UserService(repository: mockRepository)
    }

    @Test("获取用户 - 成功")
    func fetchUserSuccess() async throws {
        let expectedUser = User(id: "1", name: "张三")
        mockRepository.findResult = .success(expectedUser)

        let user = try await service.fetchUser(id: "1")

        #expect(user?.name == "张三")
        #expect(mockRepository.findCallCount == 1)
    }

    @Test("获取用户 - 网络错误")
    func fetchUserNetworkError() async {
        mockRepository.findResult = .failure(URLError(.notConnectedToInternet))

        do {
            _ = try await service.fetchUser(id: "1")
            Issue.record("应该抛出错误但没有")
        } catch {
            #expect(error is URLError)
        }
    }
}
```

### 4.2 网络请求 Mock

AI 可以根据 API 定义自动生成网络请求的 Mock 层：

```swift
final class MockURLProtocol: URLProtocol {
    static var requestHandler: ((URLRequest) throws -> (HTTPURLResponse, Data))?

    override class func canInit(with request: URLRequest) -> Bool {
        return true
    }

    override class func canonicalRequest(for request: URLRequest) -> URLRequest {
        return request
    }

    override func startLoading() {
        guard let handler = MockURLProtocol.requestHandler else {
            fatalError("未设置 requestHandler")
        }
        do {
            let (response, data) = try handler(request)
            client?.urlProtocol(self, didReceive: response, cacheStoragePolicy: .notAllowed)
            client?.urlProtocol(self, didLoad: data)
            client?.urlProtocolDidFinishLoading(self)
        } catch {
            client?.urlProtocol(self, didFailWithError: error)
        }
    }

    override func stopLoading() {}
}
```

**在测试中使用**：

```swift
@Test("登录 API 成功返回 Token")
func loginAPISuccess() async throws {
    let session = URLSession(configuration: {
        let config = URLSessionConfiguration.ephemeral
        config.protocolClasses = [MockURLProtocol.self]
        return config
    }())

    MockURLProtocol.requestHandler = { request in
        let response = HTTPURLResponse(
            url: request.url!,
            statusCode: 200,
            httpVersion: nil,
            headerFields: ["Content-Type": "application/json"]
        )!
        let data = """
        {"token": "abc123", "user": {"id": "1", "name": "张三"}}
        """.data(using: .utf8)!
        return (response, data)
    }

    let client = APIClient(session: session)
    let result = try await client.login(email: "test@example.com", password: "123456")
    #expect(result.token == "abc123")
}
```

### 4.3 定时器与延迟测试

测试涉及定时器的逻辑时，AI 可以帮你注入时间控制，避免测试等待：

```swift
@Suite("倒计时测试")
struct CountdownTimerTests {
    @Test("倒计时正常递减")
    func countdownDecrements() async {
        let timer = CountdownTimer(duration: 5)
        let sequence = timer.start()

        var remaining: [Int] = []
        for await value in sequence.prefix(3) {
            remaining.append(value)
        }

        #expect(remaining == [5, 4, 3])
    }

    @Test("倒计时到0停止")
    func countdownStopsAtZero() async {
        let timer = CountdownTimer(duration: 2)
        let sequence = timer.start()

        var finalValue: Int?
        for await value in sequence {
            finalValue = value
        }

        #expect(finalValue == 0)
    }
}
```

### 4.4 并发安全测试

AI 可以生成检测数据竞争的测试，使用 Swift 的 Actor 和 Sendable 检查：

```swift
@Suite("并发安全测试")
struct ConcurrentAccessTests {
    @Test("多线程并发写入不会崩溃")
    func concurrentWriteSafety() async {
        let counter = ThreadSafeCounter()

        await withTaskGroup(of: Void.self) { group in
            for _ in 0..<100 {
                group.addTask {
                    await counter.increment()
                }
            }
        }

        #expect(await counter.value == 100)
    }
}

actor ThreadSafeCounter {
    private var _value = 0

    var value: Int { _value }

    func increment() {
        _value += 1
    }
}
```

> ⚠️ **警告**：并发 bug 难以通过测试稳定复现。AI 生成的并发测试是"烟雾测试"——能发现明显问题，但不能保证线程安全。开启 Thread Sanitizer（`-sanitize=thread`）可以大幅提高检测概率。

## 5. 测试质量保障

### 5.1 变异测试 Mutation Testing

变异测试是验证测试质量的金标准——通过故意修改代码（变异），检查测试能否检测到变化。

> 💡 **类比**：变异测试就像消防演习——故意制造"火情"（代码变异），看"消防系统"（测试套件）能否及时发现。如果改了代码测试还能通过，说明测试是无效的。

**常见变异操作**：

| 变异类型 | 原代码 | 变异代码 | 测试应该检测到 |
|---------|--------|---------|-------------|
| 算术运算 | `a + b` | `a - b` | ✅ |
| 比较运算 | `age >= 18` | `age > 18` | ✅ |
| 逻辑运算 | `&&` | `||` | ✅ |
| 返回值 | `return price * 0.5` | `return price * 0.8` | ✅ |
| 删除语句 | `discount = 0.7` | （删除该行） | ✅ |

**让 AI 执行变异测试的 Prompt**：

```
请对以下代码执行变异测试分析：

1. 列出所有可能的变异点
2. 对每个变异点，说明现有测试能否检测到
3. 如果有变异点无法被检测到，补充对应的测试

【被测代码】
（粘贴代码）

【现有测试】
（粘贴测试代码）
```

### 5.2 覆盖率分析

AI 可以分析覆盖率报告，找出未覆盖的代码路径：

```bash
# 生成覆盖率报告
xcodebuild test \
  -scheme MyApp \
  -destination 'platform=iOS Simulator,name=iPhone 15' \
  -enableCodeCoverage YES

# 导出覆盖率数据
xcrun xccov view --report MyApp.xcresult > coverage.txt
```

**让 AI 分析覆盖率的 Prompt**：

```
以下是项目的代码覆盖率报告。请分析：
1. 哪些模块覆盖率低于 80%？
2. 哪些关键路径没有被覆盖？
3. 为未覆盖的路径生成测试代码

【覆盖率报告】
（粘贴报告内容）

【相关源代码】
（粘贴低覆盖率模块的代码）
```

### 5.3 AI 测试中的反模式：测试实现而非行为

这是 AI 生成测试最常见的质量问题——测试代码的内部实现细节，而不是外部可观察的行为。

**❌ 反模式：测试实现细节**：

```swift
@Test("ViewModel 内部状态正确")
func viewModelInternalState() {
    let vm = LoginViewModel()
    vm.email = "test@example.com"
    vm.password = "123456"
    #expect(vm._isLoading == false)
    #expect(vm._errorMessage == nil)
}
```

**✅ 正确做法：测试可观察的行为**：

```swift
@Test("登录成功后导航到首页")
func loginSuccessNavigatesToHome() async {
    let vm = LoginViewModel(repository: mockRepository)
    mockRepository.loginResult = .success(User(token: "abc"))

    await vm.login(email: "test@example.com", password: "123456")

    #expect(vm.navigationDestination == .home)
    #expect(vm.errorMessage == nil)
}
```

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 测试私有属性 | 私有属性随时可能重构，测试会频繁失效 | 测试公开方法和可观察状态 |
| 测试方法调用次数 | 实现方式变化会导致测试失败 | 测试方法调用的效果 |
| 测试 Mock 的内部状态 | Mock 是测试工具，不是被测对象 | 验证 Mock 的返回值对被测对象的影响 |
| 硬编码 UI 文案 | 文案修改导致测试失败 | 使用 Accessibility Identifier 定位元素 |

> ⚠️ **关键原则**：测试应该验证**"做了什么"**（行为/结果），而不是**"怎么做的"**（实现细节）。好的测试在重构代码时不需要修改。

```yaml
  pull_request:

      - 'Sources/**'

    runs-on: macos-14
```

## 7. TDD + AI 实践

### 7.1 AI 辅助的红-绿-重构循环

TDD（测试驱动开发）的经典循环是"红-绿-重构"。AI 可以在每个阶段提供帮助：

```
🔴 红：写一个失败的测试
   → AI 可以根据需求描述生成测试骨架

🟢 绿：写最少的代码让测试通过
   → AI 可以根据测试生成最小实现

🔵 重构：优化代码结构，保持测试通过
   → AI 可以建议重构方案并验证测试仍然通过
```

| TDD 阶段 | AI 角色 | 效率提升 |
|---------|--------|---------|
| 🔴 红 | 根据需求生成测试 | 测试编写速度提升 5-10 倍 |
| 🟢 绿 | 根据测试生成实现 | 实现速度提升 3-5 倍 |
| 🔵 重构 | 建议重构方案 | 重构信心提升，有测试保护 |

### 7.2 先写测试再让 AI 实现

这是 AI 时代最高效的开发模式之一：

```
Step 1: 你写测试（描述期望行为）
Step 2: 让 AI 实现代码（让测试通过）
Step 3: 审查 AI 的实现
Step 4: 如果测试不完整，补充测试，回到 Step 2
```

**示例**：

```swift
// Step 1: 你先写测试
@Suite("PasswordValidator 测试")
struct PasswordValidatorTests {
    @Test("8位以上密码通过验证")
    func validPassword() {
        #expect(PasswordValidator.validate("Abc12345!") == true)
    }

    @Test("少于8位密码失败")
    func tooShort() {
        #expect(PasswordValidator.validate("Ab1!") == false)
    }

    @Test("没有大写字母失败")
    func noUppercase() {
        #expect(PasswordValidator.validate("abc12345!") == false)
    }

    @Test("没有数字失败")
    func noDigit() {
        #expect(PasswordValidator.validate("Abcdefgh!") == false)
    }

    @Test("没有特殊字符失败")
    func noSpecialChar() {
        #expect(PasswordValidator.validate("Abc123456") == false)
    }
}
```

```swift
// Step 2: 让 AI 实现（Prompt: "请实现 PasswordValidator，让以上测试全部通过"）
struct PasswordValidator {
    static func validate(_ password: String) -> Bool {
        guard password.count >= 8 else { return false }
        guard password.contains(where: { $0.isUppercase }) else { return false }
        guard password.contains(where: { $0.isNumber }) else { return false }
        guard password.contains(where: { "!@#$%^&*()_+-=[]{}|;:',.<>?/`~".contains($0) }) else { return false }
        return true
    }
}
```

### 7.3 Spec → 测试 → 代码的完整流程

这是 Spec 驱动开发与 TDD 的完美结合：

```
编写 Spec（需求规格）
    ↓
从 Spec 生成测试（描述期望行为）
    ↓
运行测试（🔴 全部失败）
    ↓
让 AI 逐个实现功能（🟢 测试逐个通过）
    ↓
重构优化（🔵 测试保持通过）
    ↓
验收
```

**完整示例**：

```markdown
# Spec: 密码验证器

## 功能描述
验证用户密码是否符合安全要求

## 验收标准
- 至少 8 个字符
- 包含至少一个大写字母
- 包含至少一个数字
- 包含至少一个特殊字符（!@#$%^&* 等）
- 验证结果返回 Bool 值

## 错误处理
- 返回验证失败的具体原因（可选 P1）
```

从 Spec 到测试，从测试到代码——每一步都有明确的输入和输出，AI 在每个环节都能高效工作。

## 8. 实战：为一个 SwiftUI 模块生成完整测试套件

让我们以一个"待办事项"模块为例，完整演示 AI 生成测试套件的过程。

### 8.1 被测模块代码

```swift
// Models/Todo.swift
struct Todo: Identifiable, Equatable {
    let id: UUID
    var title: String
    var isCompleted: Bool
    var createdAt: Date

    init(id: UUID = UUID(), title: String, isCompleted: Bool = false, createdAt: Date = Date()) {
        self.id = id
        self.title = title
        self.isCompleted = isCompleted
        self.createdAt = createdAt
    }
}

// ViewModels/TodoViewModel.swift
@MainActor
@Observable
final class TodoViewModel {
    private(set) var todos: [Todo] = []
    private(set) var isLoading = false
    private(set) var errorMessage: String?

    private let repository: TodoRepository

    init(repository: TodoRepository) {
        self.repository = repository
    }

    func loadTodos() async {
        isLoading = true
        errorMessage = nil
        do {
            todos = try await repository.fetchAll()
        } catch {
            errorMessage = error.localizedDescription
        }
        isLoading = false
    }

    func addTodo(title: String) async {
        guard !title.trimmingCharacters(in: .whitespaces).isEmpty else {
            errorMessage = "标题不能为空"
            return
        }
        let todo = Todo(title: title)
        do {
            let saved = try await repository.save(todo)
            todos.append(saved)
            errorMessage = nil
        } catch {
            errorMessage = error.localizedDescription
        }
    }

    func toggleComplete(_ todo: Todo) async {
        var updated = todo
        updated.isCompleted.toggle()
        do {
            let saved = try await repository.save(updated)
            if let index = todos.firstIndex(where: { $0.id == todo.id }) {
                todos[index] = saved
            }
        } catch {
            errorMessage = error.localizedDescription
        }
    }

    func deleteTodo(id: UUID) async {
        do {
            try await repository.delete(id: id)
            todos.removeAll { $0.id == id }
        } catch {
            errorMessage = error.localizedDescription
        }
    }
}

// Protocols/TodoRepository.swift
protocol TodoRepository {
    func fetchAll() async throws -> [Todo]
    func save(_ todo: Todo) async throws -> Todo
    func delete(id: UUID) async throws -> Bool
}
```

### 8.2 AI 生成的 Mock

```swift
final class MockTodoRepository: TodoRepository {
    var fetchAllResult: Result<[Todo], Error> = .success([])
    var saveResult: Result<Todo, Error> = .success(Todo(title: "mock"))
    var deleteResult: Result<Bool, Error> = .success(true)

    private(set) var fetchAllCallCount = 0
    private(set) var saveCallCount = 0
    private(set) var deleteCallCount = 0
    private(set) var lastSavedTodo: Todo?
    private(set) var lastDeletedId: UUID?

    func fetchAll() async throws -> [Todo] {
        fetchAllCallCount += 1
        return try fetchAllResult.get()
    }

    func save(_ todo: Todo) async throws -> Todo {
        saveCallCount += 1
        lastSavedTodo = todo
        return try saveResult.get()
    }

    func delete(id: UUID) async throws -> Bool {
        deleteCallCount += 1
        lastDeletedId = id
        return try deleteResult.get()
    }
}
```
