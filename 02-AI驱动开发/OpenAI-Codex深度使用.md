# OpenAI Codex 深度使用

> 🎯 **本章目标**：掌握 OpenAI Codex 的安装配置、任务描述技巧、代码审查方法、GitHub 集成方式，并能根据实际场景在 Codex 和 Claude Code 之间做出合理选择。

## Codex 是什么？

### OpenAI 推出的 AI 编程代理（Coding Agent）

OpenAI Codex 是 OpenAI 推出的**AI 编程代理**（Coding Agent）。和之前我们学的 Claude Code 类似，它也是一个能"自主完成编程任务"的 AI 工具——你用自然语言描述需求，它就能读取项目文件、编写代码、运行命令，甚至提交 Pull Request。

💡 **一句话理解**：如果说 ChatGPT 是"AI 顾问"，那 Codex 就是"AI 程序员"——不只是给你建议，而是直接帮你干活。

### 与 ChatGPT 编程功能的区别

很多同学会问：ChatGPT 不是也能写代码吗？Codex 和它有什么不同？

| 对比维度 | ChatGPT 编程 | OpenAI Codex |
|---------|-------------|--------------|
| 运行环境 | 浏览器 / App | 终端（命令行）+ 云端沙箱 |
| 访问你的文件 | ❌ 需要手动上传 | ✅ 直接读取本地项目文件 |
| 修改你的文件 | ❌ 不能，只能输出代码让你复制 | ✅ 能，直接编辑和创建文件 |
| 运行命令 | ❌ 不能 | ✅ 能，在沙箱环境中执行 |
| 理解项目上下文 | ❌ 有限，只能看上传的文件 | ✅ 自动扫描整个项目 |
| 自主程度 | 低：你问它答 | 高：你描述任务，它自主完成 |
| 适合场景 | 问答、讨论方案、学习概念 | 实际编码、项目开发、批量任务 |

### Codex 的定位：自主完成编程任务

Codex 的核心理念是**自主编程**。你不需要一步步指导它怎么做，只需要告诉它"做什么"，它会自己决定"怎么做"：

```
传统方式（ChatGPT）：
  你：帮我写一个登录接口 → ChatGPT 输出代码 → 你复制 → 你粘贴 → 你手动测试

Codex 方式：
  你：给用户模块添加邮箱登录功能 → Codex 读完项目 → 自己写代码 → 自己运行测试 → 自己修复问题 → 交付结果
```

⚠️ **注意**：Codex 的"自主"并不意味着你可以完全不管。你仍然需要审查它生成的代码、验证结果是否正确。AI 是你的助手，你始终是代码的负责人。

## 安装与配置

### 环境要求：Node.js、OpenAI API Key

在安装 Codex 之前，请确保你的电脑满足以下条件：

| 软件/条件 | 要求 | 如何检查 | 如何安装 |
|----------|------|---------|---------|
| Node.js | 22.0 或更高版本 | 终端输入 `node -v` | 访问 [nodejs.org](https://nodejs.org) 下载安装 |
| npm | 随 Node.js 一起安装 | 终端输入 `npm -v` | 安装 Node.js 后自动可用 |
| OpenAI API Key | 需要提前申请 | — | 访问 [platform.openai.com](https://platform.openai.com) 注册获取 |
| Git | 建议安装 | 终端输入 `git --version` | 访问 [git-scm.com](https://git-scm.com) 下载安装 |

💡 **提示**：Codex 对 Node.js 版本要求较高（22+），如果你之前安装的是旧版本，需要先升级。推荐使用 `nvm` 管理 Node.js 版本：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.zshrc
nvm install 22
nvm use 22
```

### 安装步骤

确认环境就绪后，一行命令安装 Codex CLI：

```bash
npm install -g @openai/codex
```

安装完成后，验证是否安装成功：

```bash
codex --version
```

如果显示版本号，说明安装成功 ✅

⚠️ **常见安装问题**：

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| `EACCES` 权限错误 | npm 全局安装权限不足 | 在命令前加 `sudo`：`sudo npm install -g @openai/codex` |
| `command not found: codex` | 安装路径未加入 PATH | 重新打开终端，或检查 npm 全局安装路径 |
| Node.js 版本不满足 | Codex 需要 Node.js 22+ | 使用 `nvm install 22` 升级 |
| 网络超时 | 国内网络访问 npm 较慢 | 使用镜像：`npm install -g @openai/codex --registry=https://registry.npmmirror.com` |

### API Key 配置

Codex 需要 OpenAI API Key 才能工作。API Key 就像是你的"通行证"，让 Codex 知道是谁在调用。

**获取 API Key 的步骤**：

1. 访问 [platform.openai.com](https://platform.openai.com)
2. 注册/登录 OpenAI 账号
3. 进入 API Keys 页面
4. 点击 "Create new secret key" 创建新的 API Key
5. 复制生成的 Key（以 `sk-` 开头）

⚠️ **重要**：API Key 是你的私密信息，**绝对不要**分享给别人或提交到 Git 仓库！一旦泄露，别人可以用你的账号产生费用。

**配置 API Key**：

方法一：设置环境变量（推荐）

```bash
# 临时设置（当前终端窗口有效）
export OPENAI_API_KEY=sk-your-key-here

# 永久设置（写入 shell 配置文件）
echo 'export OPENAI_API_KEY=sk-your-key-here' >> ~/.zshrc
source ~/.zshrc
```

方法二：首次运行时输入

```bash
codex
# 首次运行会提示你输入 API Key
```

💡 **提示**：推荐使用方法一，这样每次打开终端都不需要重新输入。记得把 `sk-your-key-here` 替换成你自己的真实 Key。

### 首次运行

配置好 API Key 后，进入你的项目目录，启动 Codex：

```bash
# 进入你的项目目录
cd /path/to/your/project

# 启动 Codex
codex
```

首次启动时，Codex 会：
1. 扫描当前目录的项目结构
2. 读取关键文件（如 package.json、README 等）
3. 进入交互模式，等待你的指令

你会看到类似这样的界面：

```
╭──────────────────────────────────────╮
│                                      │
│   Welcome to OpenAI Codex!           │
│                                      │
│   Type your request and press Enter  │
│                                      │
╰──────────────────────────────────────╯
>
```

试试输入你的第一个指令：

```
> 请介绍一下这个项目的结构
```

Codex 会分析你的项目并给出回答。如果项目是空的，它会告诉你当前目录没有项目文件。

💡 **提示**：Codex 运行任务时会在一个**沙箱环境**中执行命令，这意味着它不会直接修改你的系统文件，安全性有保障。但你仍然需要审查它的代码修改。

## 任务描述最佳实践

### 如何描述任务让 Codex 理解

Codex 的能力很强，但它不是"读心术"。你描述得越清楚，它完成得越好。好的任务描述应该包含以下要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| **做什么** | 明确目标 | "添加用户注册功能" |
| **在哪些文件** | 指定范围 | "修改 src/pages/Register.tsx 和 src/api/user.ts" |
| **用什么技术** | 指定方案 | "使用 React Hook Form 处理表单" |
| **不要做什么** | 限定边界 | "不要修改现有的登录逻辑" |
| **验收标准** | 怎样算完成 | "注册成功后跳转到首页，并显示欢迎提示" |

### 好的任务描述 vs 差的任务描述（对比示例）

| ❌ 差的描述 | ✅ 好的描述 | 为什么好 |
|------------|-----------|---------|
| "改一下用户模块" | "在用户模块中添加邮箱验证功能，修改 Register.tsx 添加邮箱输入框，修改 user.ts 添加验证接口" | 目标明确、范围清晰 |
| "优化代码" | "把 UserService 类拆分成 UserAuthService 和 UserProfileService，保持所有现有接口不变" | 有具体方向和约束 |
| "修 bug" | "修复登录页面点击'记住我'后，下次打开仍需重新登录的问题，检查 src/utils/auth.ts 的 token 存储逻辑" | 问题描述具体、指定了相关文件 |
| "加个功能" | "在任务列表页面添加搜索框，支持按任务名称模糊搜索，搜索结果实时过滤，使用现有的 TaskList 组件" | 需求完整、技术方案明确 |
| "写测试" | "给 src/utils/formatDate.ts 的所有函数写单元测试，使用 jest 框架，覆盖正常输入和边界情况" | 范围、工具、覆盖要求都明确了 |

### 任务拆分原则

对于复杂任务，**拆分后逐步执行**比一次性描述效果更好：

**原则 1：一次只做一件事**

```
❌ 不好的做法：
> 帮我搭建完整的用户系统，包括注册、登录、个人设置、权限管理、密码找回

✅ 好的做法：
> 第一步：创建用户注册页面和接口
（完成后）
> 第二步：创建用户登录页面和接口
（完成后）
> 第三步：创建个人设置页面
```

**原则 2：先框架，再细节**

```
> 第一步：创建用户设置页面的基本框架，只包含页面结构和路由
（确认后）
> 第二步：添加修改昵称的功能
（确认后）
> 第三步：添加修改密码的功能
（确认后）
> 第四步：添加头像上传功能
```

**原则 3：每步验证**

```
> 给 src/utils/formatDate.ts 添加一个 parseDate 函数，然后运行 npm test 确保测试通过
```

💡 **提示**：拆分任务不仅能让 Codex 更好地理解需求，也方便你在每一步检查结果，避免"一步错，步步错"。

## 代码生成与审查

### Codex 生成代码的流程

当你给 Codex 一个任务后，它会按以下流程工作：

```
1. 理解任务 → 分析你的需求，确定要做什么
2. 扫描项目 → 读取相关文件，理解现有代码结构
3. 制定计划 → 决定要修改哪些文件、怎么改
4. 生成代码 → 在沙箱中编写/修改代码
5. 运行验证 → 执行测试、构建等命令验证结果
6. 交付结果 → 展示修改内容，等待你确认
```

💡 **关键点**：Codex 会自主完成整个流程，你只需要在最后一步审查和确认。

### 审查 Codex 生成的代码

虽然 Codex 能自主生成代码，但**审查是必不可少的环节**。以下是审查要点：

| 审查维度 | 关注点 | 常见问题 |
|---------|--------|---------|
| **功能正确性** | 代码是否实现了需求 | 遗漏边界情况、逻辑错误 |
| **代码风格** | 是否符合项目规范 | 命名不一致、缺少错误处理 |
| **安全性** | 是否有安全漏洞 | SQL 注入、XSS、硬编码密钥 |
| **性能** | 是否有明显性能问题 | 不必要的循环、内存泄漏 |
| **兼容性** | 是否破坏现有功能 | 修改了公共接口、删除了依赖 |
| **依赖** | 是否引入了不必要的包 | 安装了已有替代品的库 |

**审查实操建议**：

```
> 修改前，先告诉我你打算怎么改，列出要修改的文件和修改方案，等我确认后再动手
```

你也可以让 Codex 自己解释修改内容：

```
> 请解释一下你刚才的修改，每处修改的原因是什么
```

⚠️ **重要提醒**：不要盲目接受所有修改。至少检查它修改了哪些文件，关键逻辑是否正确。养成审查习惯是使用 AI 编程工具的基本素养。

### 测试和验证

让 Codex 生成代码后，务必进行测试验证：

**1. 让 Codex 自己运行测试**

```
> 运行 npm test，如果有失败的测试，请修复它们
```

**2. 手动验证关键功能**

即使自动化测试通过了，也要手动验证关键功能是否正常工作。

**3. 检查边界情况**

```
> 检查刚才写的注册功能，如果用户输入空邮箱、超长密码、特殊字符会怎样？请补充边界情况的处理
```

**4. 用 Git 管理变更**

在让 Codex 做大改动之前，先提交当前代码：

```bash
git add .
git commit -m "保存当前状态"
```

这样如果 Codex 改坏了，你可以轻松回退：

```bash
git checkout .
```

## 与 GitHub 集成

### Codex 与 GitHub 的协作方式

Codex 与 GitHub 有深度集成，这是它区别于其他 AI 编程工具的一大亮点。它可以在 GitHub 生态中完成完整的开发循环：

| 能力 | 说明 |
|------|------|
| 读取仓库 | 直接读取 GitHub 仓库的代码和结构 |
| 创建分支 | 自动为任务创建新分支 |
| 提交代码 | 将修改提交到分支 |
| 创建 PR | 自动创建 Pull Request |
| PR 审查 | 审查已有的 Pull Request |
| 评论互动 | 在 PR 中回复评论 |

### PR 审查

Codex 可以帮你审查 Pull Request，发现潜在问题：

**在 GitHub 上使用**：

1. 在 PR 页面中 `@codex` 提及 Codex
2. Codex 会自动分析 PR 的代码变更
3. 给出审查意见，包括潜在 bug、代码风格建议、改进方案

**在终端中使用**：

```
> 审查当前分支相对于 main 分支的变更，指出潜在问题
```

Codex 会检查：
- 逻辑错误和潜在 bug
- 安全漏洞
- 代码风格不一致
- 性能问题
- 缺失的错误处理

💡 **提示**：Codex 的 PR 审查是辅助性的，不能完全替代人工审查。但对于快速发现明显问题（如遗漏的错误处理、硬编码的密钥等）非常有效。

### CI/CD 集成

Codex 可以与 CI/CD 流程结合，在持续集成中发挥作用：

**场景 1：自动修复 CI 失败**

```
> CI 构建失败了，错误日志如下：[粘贴日志]，请修复问题
```

**场景 2：自动生成测试**

```
> 给 src/services/payment.ts 生成单元测试，确保覆盖所有公开方法
```

**场景 3：代码质量检查**

```
> 检查 src/ 目录下的所有文件，找出不符合项目编码规范的地方，并修复
```

⚠️ **注意**：在 CI/CD 中集成 AI 工具时，要注意 API 调用费用和执行时间。建议在关键节点（如 PR 审查、部署前检查）使用，而不是每个步骤都调用。

## Codex vs Claude Code 对比与选择

### 详细对比表

| 对比维度 | OpenAI Codex | Claude Code |
|---------|-------------|-------------|
| **开发公司** | OpenAI | Anthropic |
| **运行方式** | 终端 CLI + 云端沙箱 | 终端 CLI |
| **底层模型** | OpenAI o3/o4-mini 等 | Claude Sonnet/Opus |
| **代码执行** | 云端沙箱（隔离环境） | 本地终端（直接执行） |
| **文件操作** | 读取本地文件，在沙箱中修改 | 直接读取和修改本地文件 |
| **GitHub 集成** | ✅ 深度集成，支持 PR 审查 | ⚠️ 通过 Git 命令间接使用 |
| **多文件编辑** | ✅ 支持 | ✅ 支持 |
| **项目规范文件** | 无专用文件（可用 AGENTS.md） | CLAUDE.md（专用规范文件） |
| **自主程度** | 高：自主规划、执行、验证 | 高：自主规划、执行、验证 |
| **上下文窗口** | 较大（依赖具体模型） | 200K token |
| **代码补全** | ❌ 不支持 | ❌ 不支持 |
| **国内可用性** | ❌ 需要科学上网 + 海外 API Key | ❌ 需要科学上网 + 海外 API Key |
| **价格** | 按 API 用量计费（o4-mini 较便宜） | 按 API 用量计费 |

### 优缺点对比

| | OpenAI Codex | Claude Code |
|---|-------------|-------------|
| **优点** | 云端沙箱更安全；GitHub 集成好；o4-mini 模型性价比高 | 项目上下文理解更深；CLAUDE.md 规范文件成熟；社区活跃 | 
| **缺点** | 沙箱环境有时与本地环境不一致；规范文件支持较弱 | 直接操作本地文件有风险；GitHub 集成不如 Codex 深入 |

### 何时选择 Codex

- ✅ 你的项目托管在 GitHub 上，需要频繁的 PR 审查和代码协作
- ✅ 你更关注安全性，希望 AI 在隔离环境中执行代码
- ✅ 你已经在使用 OpenAI 生态（ChatGPT、GPT-4 等）
- ✅ 你需要处理大量独立的小任务（o4-mini 性价比高）
- ✅ 你想要 AI 自主完成"写代码→运行→修复"的完整循环

### 何时选择 Claude Code

- ✅ 你需要深度理解大型项目上下文
- ✅ 你想要通过 CLAUDE.md 精细控制 AI 的行为
- ✅ 你更信任 Anthropic 的安全理念
- ✅ 你需要在本地环境直接执行和调试代码
- ✅ 你需要频繁的多文件重构

### 可以同时使用吗

**当然可以！** 而且推荐组合使用。不同工具各有优势，搭配使用效果更好：

| 场景 | 推荐工具 | 原因 |
|------|---------|------|
| GitHub PR 审查 | Codex | GitHub 集成更好 |
| 大型项目重构 | Claude Code | 上下文理解更强 |
| 快速修复小 bug | Codex（o4-mini） | 性价比更高 |
| 编写项目规范 | Claude Code | CLAUDE.md 机制成熟 |
| 代码安全审查 | Codex | 沙箱环境更安全 |

💡 **提示**：同时使用多个 AI 工具时，建议用 Git 管理所有变更，这样无论哪个工具改坏了，都能轻松回退。

## 小结

本章我们深入学习了 OpenAI Codex 的使用方法：

1. **Codex 是 OpenAI 推出的 AI 编程代理**，能自主完成编程任务，在云端沙箱中执行代码，安全性有保障
2. **安装只需一行命令**：`npm install -g @openai/codex`，配置好 OpenAI API Key 即可使用
3. **任务描述是关键**——描述得越清楚，Codex 完成得越好；复杂任务要拆分，逐步执行
4. **审查不可省略**——每次都要检查功能正确性、代码风格、安全性和兼容性
5. **GitHub 集成是 Codex 的强项**，支持 PR 审查、代码协作、CI/CD 集成
6. **Codex 和 Claude Code 各有优势**——Codex 擅长 GitHub 协作和安全执行，Claude Code 擅长项目理解和规范控制
7. **推荐组合使用**——根据场景选择最合适的工具，用 Git 管理所有变更
