# App Store Connect 完整配置

> 🎯 **本章目标**：掌握 App Store Connect 中所有必填和推荐配置项，包括 App 记录创建、定价、年龄分级、类别选择、关键词优化、描述编写和审核信息填写，确保提交审核时信息完整、专业。

## App 记录创建

> 🎯 **本节目标**：在 App Store Connect 中创建你的 App 记录，这是上架的第一步。

### 创建新 App

**操作步骤：**

1. 打开 [App Store Connect](https://appstoreconnect.apple.com)
2. 使用你的 Apple 开发者账号登录
3. 点击左侧菜单「我的 App」
4. 点击左上角的 **"+"** 按钮，选择「新建 App」
5. 填写弹窗中的信息

**新建 App 弹窗字段说明：**

| 字段 | 填写说明 | 示例 |
|------|----------|------|
| 平台 | 选择 iOS | iOS |
| 名称 | App 在 App Store 中显示的名称 | 天气小助手 |
| 主要语言 | App 的主要语言 | 简体中文 |
| Bundle ID | 选择在 Xcode 中使用的 Bundle ID | com.example.weather |
| SKU | App 的唯一标识符（内部使用） | weatherhelper2024 |
| 全屏访问 | 是否支持全屏 | 根据实际情况选择 |

⚠️ **警告**：App 名称一旦创建后**不能随意修改**（每次版本更新时可修改），Bundle ID 创建后**不可更改**，请务必仔细确认后再提交。

💡 **提示**：App 名称最多 30 个字符，建议包含核心关键词但不要堆砌。例如"天气小助手 - 实时天气预报"比单纯的"天气"更好。

### Bundle ID 关联

Bundle ID 是你的 App 在 Apple 生态中的唯一标识，必须确保 Xcode 项目和 App Store Connect 中一致。

**确认 Bundle ID 的步骤：**

1. 打开 Xcode 项目
2. 点击项目导航器中的项目文件
3. 选择 Target →「General」标签
4. 查看「Bundle Identifier」字段

```
Xcode 中的路径：
项目文件 → Target → General → Identity → Bundle Identifier
```

**在 App Store Connect 中关联：**

| 步骤 | 操作 |
|------|------|
| 1 | 创建 App 时在「Bundle ID」下拉菜单中选择 |
| 2 | 下拉菜单只显示你已注册的 App ID |
| 3 | 如果看不到你的 Bundle ID，需要先去 [Apple Developer](https://developer.apple.com) 注册 |

**常见问题：**

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 下拉菜单看不到 Bundle ID | 未在 Developer 中注册 | 去 Certificates, Identifiers & Profiles 注册 |
| Bundle ID 已被使用 | 同一个 ID 不能创建两个 App | 使用不同的 Bundle ID |
| 想修改 Bundle ID | 创建后不可修改 | 只能删除 App 记录重新创建 |

⚠️ **警告**：Bundle ID 格式必须是反向域名格式，如 `com.company.appname`。不要使用 Apple 保留的前缀（如 `com.apple.*`）。

### SKU 设置

SKU（Stock Keeping Unit）是 App 的内部标识符，不会显示给用户，仅供你自己在 App Store Connect 中识别。

**什么是 SKU：**

- SKU 是你自己定义的唯一字符串
- 不会显示在 App Store 上
- 用于在报表和销售数据中标识你的 App
- 创建后不可修改

**设置建议：**

| 建议 | 说明 | 示例 |
|------|------|------|
| 使用有意义的字符串 | 方便你自己识别 | weatherhelper2024 |
| 包含产品名 | 便于区分多个 App | myapp_weather_v1 |
| 避免特殊字符 | 只用字母、数字、下划线、连字符 | my_app_sku_001 |
| 保持简洁 | 不需要太长 | weather001 |

💡 **提示**：SKU 不需要和 Bundle ID 一样，它只是一个内部标识。如果你只有一个 App，随便起一个有意义的名字就行。

## 定价与销售范围

> 🎯 **本节目标**：了解 App Store 的定价机制，选择合适的定价策略和销售地区。

### 定价策略

**免费 vs 付费对比：**

| 对比项 | 免费 App | 付费 App |
|--------|----------|----------|
| 下载门槛 | 低 | 高 |
| 用户量 | 通常更多 | 通常较少 |
| 收入模式 | 内购/广告 | 下载费 + 内购 |
| 用户心理 | 先用再决定 | 先付费再使用 |
| 审核要求 | 相对宽松 | 需提供足够价值 |
| 适合场景 | 工具、社交、内容平台 | 专业工具、游戏 |

**App Store 定价层级：**

Apple 使用"定价层级"系统，每个层级对应不同国家/地区的本地化价格。

| 层级 | 美元价格 | 人民币价格（约） | 适合场景 |
|:----:|:--------:|:----------------:|----------|
| 免费 | $0 | ¥0 | 免费 App |
| Tier 1 | $0.99 | ¥6 | 小工具、简单游戏 |
| Tier 2 | $1.99 | ¥12 | 中等功能 App |
| Tier 3 | $2.99 | ¥18 | 功能较丰富的 App |
| Tier 5 | $4.99 | ¥30 | 专业工具 |
| Tier 10 | $9.99 | ¥68 | 高级专业工具 |
| Tier 50 | $49.99 | ¥328 | 企业级应用 |

💡 **提示**：Apple 会不定期调整定价层级和对应价格。你可以在 App Store Connect 的「定价和销售范围」中查看最新的价格表。

**价格调整规则：**

| 规则 | 说明 |
|------|------|
| 可以随时调整价格 | 修改后立即生效 |
| 已购买用户不受影响 | 降价不影响已付费用户 |
| 可以设置限时免费 | 通过价格调整实现 |
| Apple 抽成 30% | 订阅第二年降为 15% |

### 销售地区选择

**全球发布 vs 特定地区：**

| 策略 | 优点 | 缺点 | 适合场景 |
|------|------|------|----------|
| 全球发布 | 覆盖面广、用户多 | 需要多语言支持 | 通用型 App |
| 特定地区 | 集中精力、本地化好 | 用户量受限 | 本地服务类 App |
| 先选几个地区试水 | 风险可控 | 覆盖面小 | 新团队首次发布 |

**中国区注意事项：**

| 注意事项 | 说明 |
|----------|------|
| ICP 备案 | 必须提供备案号 |
| 隐私政策 | 必须提供符合中国法规的隐私政策 |
| 内容合规 | 内容需符合中国法律法规 |
| 支付方式 | 需支持支付宝、微信支付等（通过内购） |
| 数据存储 | 用户数据存储需符合数据出境规定 |

### 国内定价注意事项

**人民币定价：**

App Store 的中国区价格由 Apple 根据定价层级自动换算，你不需要手动设置人民币价格。但你需要了解：

| 要点 | 说明 |
|------|------|
| 价格由 Apple 定 | 你选择层级，Apple 自动换算 |
| 含税 | 显示的价格已含增值税 |
| 定价建议 | 参考同类 App 的定价 |
| 心理定价 | ¥6、¥12、¥18 是常见价位 |

**税费说明：**

| 税费类型 | 说明 |
|----------|------|
| 增值税 | Apple 代扣代缴，你不需要单独处理 |
| 所得税 | 根据你的收入情况自行申报 |
| Apple 佣金 | 标准为 30%，小企业计划为 15% |

💡 **提示**：如果你年收入不超过 100 万美元，可以申请 [App Store 小企业计划](https://developer.apple.com/cn/app-store/small-business-program/)，佣金从 30% 降至 15%，能多拿一倍收入！

## 年龄分级

> 🎯 **本节目标**：正确填写年龄分级问卷，确保 App 获得合适的分级。

### 分级问卷填写

App Store 使用年龄分级来帮助用户了解 App 内容是否适合他们。你需要如实填写一份内容分级问卷。

**操作路径：**

```
App Store Connect → 我的 App → 选择 App → App 信息 → 年龄分级
```

**填写原则：**

| 原则 | 说明 |
|------|------|
| 如实填写 | 不要为了降低分级而隐瞒内容 |
| 考虑最极端情况 | 按 App 中可能出现的最极端内容填写 |
| 包含用户生成内容 | 如果 App 有社交功能，需考虑 UGC 内容 |
| 包含内购内容 | 如果有内购解锁的内容，也要纳入评估 |

⚠️ **警告**：如果 Apple 发现你的实际内容与分级不符，可能会被拒绝审核或强制下架。不如实填写分级的后果比高分级更严重。

### 常见分级问题

以下是分级问卷中常见的问题及对应分级影响：

**暴力内容：**

| 内容类型 | 分级影响 | 示例 |
|----------|----------|------|
| 无暴力内容 | 4+ | 天气 App、笔记 App |
| 卡通/幻想暴力 | 9+ | 卡通风格打斗游戏 |
| 现实主义暴力 | 12+ | 有战斗场景的游戏 |
| 频繁/强烈的暴力 | 17+ | 射击游戏、战争游戏 |
| 极端暴力 | 可能被拒 | 真实暴力画面 |

**赌博内容：**

| 内容类型 | 分级影响 | 示例 |
|----------|----------|------|
| 无赌博内容 | 4+ | 不涉及 |
| 模拟赌博 | 17+ | 扑克、老虎机游戏 |
| 真实赌博 | 需特殊资质 | 在线赌场 |

⚠️ **警告**：模拟赌博（即使不涉及真钱）也会导致 17+ 分级。如果你的 App 包含任何赌博元素，务必如实申报。

**性暗示内容：**

| 内容类型 | 分级影响 | 示例 |
|----------|----------|------|
| 无性暗示 | 4+ | 不涉及 |
| 轻微暗示 | 12+ | 暧昧对话 |
| 性暗示内容 | 17+ | 暴露画面 |
| 色情内容 | 被拒 | App Store 禁止 |

**各分级对应年龄：**

| 分级 | 年龄 | 说明 |
|------|:----:|------|
| 4+ | 4 岁以上 | 无不当内容 |
| 9+ | 9 岁以上 | 可能含轻微暴力 |
| 12+ | 12 岁以上 | 可能含轻微暴力、偶尔粗话 |
| 17+ | 17 岁以上 | 可能含频繁暴力、性暗示等 |

💡 **提示**：分级越高，潜在用户越少。如果你的 App 面向大众用户，尽量控制内容使其获得 4+ 或 9+ 分级。例如，用卡通风格代替写实风格可以降低暴力分级。

## 类别选择策略

> 🎯 **本节目标**：选择最合适的 App 类别，帮助用户更容易找到你的 App。

### 主类别与副类别

每个 App 必须选择一个主类别，可选一个副类别。

**操作路径：**

```
App Store Connect → 我的 App → 选择 App → App 信息 → 分类
```

**常见类别列表：**

| 类别 | 英文名 | 适合的 App 类型 |
|------|--------|----------------|
| 工具 | Utilities | 计算器、天气、手电筒 |
| 效率 | Productivity | 笔记、待办、日历 |
| 社交 | Social Networking | 聊天、社区 |
| 生活 | Lifestyle | 美食、购物、出行 |
| 教育 | Education | 学习、课程 |
| 健康健美 | Health & Fitness | 运动、冥想、健康记录 |
| 财务 | Finance | 记账、投资 |
| 摄影与录像 | Photo & Video | 相机、修图、视频编辑 |
| 音乐 | Music | 音乐播放、乐器 |
| 商务 | Business | 办公、会议 |
| 新闻 | News | 资讯、阅读 |
| 旅游 | Travel | 机票、酒店、攻略 |
| 美食佳饮 | Food & Drink | 菜谱、外卖 |
| 图书 | Books | 阅读、漫画 |
| 医疗 | Medical | 健康管理、问诊 |
| 娱乐 | Entertainment | 段子、直播 |
| 游戏 | Games | 各类游戏 |

**类别对下载量的影响：**

| 因素 | 说明 |
|------|------|
| 竞争程度 | 热门类别竞争激烈，冷门类别容易上榜 |
| 用户搜索 | 类别影响 App Store 分类榜单排名 |
| 推荐机会 | Apple 编辑推荐时会按类别筛选 |
| 用户预期 | 类别影响用户对 App 功能的预期 |

### 类别选择技巧

**技巧一：选择竞争较小的类别**

| 策略 | 说明 | 示例 |
|------|------|------|
| 避开红海 | 不选最热门的类别 | "工具"比"社交"竞争小 |
| 选择细分 | 找到更精准的类别 | 记账 App 选"财务"而非"工具" |
| 利用副类别 | 副类别也能带来流量 | 主选"效率"，副选"商务" |

**技巧二：选择与 App 最相关的类别**

| App 功能 | 可选类别 | 推荐选择 | 原因 |
|----------|----------|----------|------|
| 天气查询 | 工具、生活 | 工具 | 用户找天气 App 习惯去工具类 |
| 记账 | 财务、效率 | 财务 | 更精准，竞争更小 |
| 运动记录 | 健康健美、生活 | 健康健美 | 目标用户更集中 |
| 学习英语 | 教育、图书 | 教育 | 最直接相关 |
| 菜谱 | 美食佳饮、生活 | 美食佳饮 | 精准匹配用户需求 |

💡 **提示**：不要为了追求低竞争而选择与 App 无关的类别。Apple 审核时会检查类别是否合理，如果发现类别与 App 内容不符，可能会被要求修改或直接拒绝。

## 关键词优化基础

> 🎯 **本节目标**：掌握 App Store 关键词的填写规则和优化策略，让你的 App 更容易被搜到。

### 关键词字段规则

App Store 的关键词字段有严格的规则，必须了解：

| 规则 | 说明 |
|------|------|
| 字符限制 | 最多 100 个字符 |
| 分隔方式 | 用英文逗号 `,` 分隔 |
| 不需要空格 | 逗号后不加空格 |
| 不需要重复 | App 名称中的词不需要再写 |
| 不需要类别名 | 类别名称会自动关联 |
| 禁止竞品名称 | 不能写其他 App 的名称 |
| 禁止不当词汇 | 不能包含脏话、敏感词 |

**正确 vs 错误示例：**

| 类型 | 示例 | 说明 |
|------|------|------|
| ✅ 正确 | `天气,预报,温度,湿度,风力,穿衣,出行` | 逗号分隔，无空格 |
| ❌ 错误 | `天气, 预报, 温度` | 逗号后多了空格，浪费字符 |
| ❌ 错误 | `天气 预报 温度` | 没用逗号分隔 |
| ❌ 错误 | `天气,天气app,天气预报` | "天气"重复，浪费字符 |
| ❌ 错误 | `天气,墨迹天气` | 包含竞品名称 |

⚠️ **警告**：100 个字符非常珍贵，每个字符都要用在刀刃上。不要浪费在重复词、空格、App 名称已有的词上。

### 关键词选择策略

**策略一：从用户搜索角度思考**

想象你的目标用户会在 App Store 搜索什么词：

| 思考维度 | 问题 | 示例（天气 App） |
|----------|------|-----------------|
| 核心功能 | App 做什么？ | 天气、预报 |
| 使用场景 | 什么时候用？ | 出行、穿衣、跑步 |
| 用户痛点 | 解决什么问题？ | 下雨、雾霾、高温 |
| 同义词 | 还能怎么说？ | 气象、气候、温度 |

**策略二：避免太泛的词**

| 类型 | 示例 | 问题 |
|------|------|------|
| 太泛 | `工具`、`生活`、`好用` | 竞争太大，搜不到你 |
| 太窄 | `朝阳区今天下午3点天气` | 没人这么搜 |
| 合适 | `天气提醒`、`穿衣指南` | 有一定搜索量，竞争适中 |

**策略三：长尾关键词**

长尾关键词是指搜索量较小但更精准的词组：

| 类型 | 示例 | 搜索量 | 竞争度 | 转化率 |
|------|------|:------:|:------:|:------:|
| 短尾词 | 天气 | 高 | 极高 | 低 |
| 中尾词 | 天气预报 | 中 | 高 | 中 |
| 长尾词 | 跑步天气提醒 | 低 | 低 | 高 |

💡 **提示**：App Store 的关键词是按词组合的。你填了 `天气,提醒,跑步`，用户搜"跑步天气提醒"也能找到你，因为 Apple 会自动组合关键词。所以不需要填完整短语，拆开填更省字符。

### 竞品关键词分析

了解竞品用了什么关键词，可以帮助你找到机会。

**分析方法：**

| 方法 | 说明 | 操作 |
|------|------|------|
| 搜索联想词 | 在 App Store 搜索框输入关键词看联想 | 手动操作 |
| 竞品标题分析 | 分析竞品 App 的标题和副标题 | 查看竞品页面 |
| 评论区分析 | 看用户怎么描述竞品 | 阅读竞品评论 |
| 工具分析 | 使用专业工具 | 见下表 |

**关键词分析工具推荐：**

| 工具 | 功能 | 价格 | 适合人群 |
|------|------|------|----------|
| 七麦数据（qimai.cn） | 关键词排名、竞品分析 | 基础免费 | 国内开发者首选 |
| 蝉大师（chandashi.com） | ASO 优化、关键词挖掘 | 基础免费 | 国内开发者 |
| Sensor Tower | 全球市场分析 | 付费为主 | 海外市场 |
| App Annie | 市场数据、竞品分析 | 付费为主 | 专业团队 |

💡 **提示**：免费工具已经足够新手使用。不要花大量时间在关键词优化上，先把 App 做好才是根本。关键词优化是一个持续迭代的过程，每次版本更新都可以调整。

## App 描述与宣传文本

> 🎯 **本节目标**：写出吸引人的 App 描述和宣传文本，提高用户的下载意愿。

### 描述编写技巧

App 描述是用户了解你 App 的重要窗口，写得好能显著提高下载率。

**核心原则：前 3 行最重要！**

用户在 App Store 中默认只能看到描述的前 3 行（约 120 个字符），需要点击"更多"才能看到完整描述。所以前 3 行必须抓住用户。

**描述结构建议：**

```
第 1-3 行：核心卖点（最重要！）
─────────────────
一段话说明 App 是什么、解决什么问题

第 4-10 行：功能亮点
─────────────────
用列表形式展示主要功能

第 11-20 行：使用场景
─────────────────
描述用户在什么场景下会用到

第 21 行以后：补充信息
─────────────────
关于我们、联系方式、隐私政策链接等
```

**中文示例（天气 App）：**

```

### 宣传文本（中英文）

**什么是宣传文本：**

宣传文本（Promotional Text）是显示在 App 描述之前的一段文字，最多 170 个字符。

| 特点 | 说明 |
|------|------|
| 显示位置 | 描述文字之前 |
| 字符限制 | 最多 170 个字符 |
| 可随时修改 | 不需要提交新版本即可更新 |
| 不参与搜索 | 不影响关键词搜索排名 |
| 用途 | 宣传新功能、活动、限时优惠 |

**编写建议：**

| 建议 | 说明 |
|------|------|
| 突出最新变化 | "全新上线！现在支持 Apple Watch" |
| 制造紧迫感 | "限时免费！仅剩 3 天" |
| 强调核心价值 | "3 秒知道今天穿什么" |
| 使用 emoji | 适当使用 emoji 增加视觉吸引力 |

**中文示例：**

```
🎉 全新上线！天气小助手现在支持 Apple Watch，抬腕即可查看天气。限时免费下载！
```

```

### 新增功能文本

**什么是新增功能文本：**

每次版本更新时，你需要填写"新增功能"（What's New），告诉用户这个版本更新了什么。

| 特点 | 说明 |
|------|------|
| 显示位置 | App 详情页的"版本历史"区域 |
| 字符限制 | 最多 4000 个字符 |
| 必须填写 | 每次提交新版本都必须填写 |
| 可用 emoji | 建议使用 emoji 增加可读性 |

**编写建议：**

| 建议 | 说明 | 示例 |
|------|------|------|
| 写具体内容 | 不要只写"修复了 bug" | "修复了部分城市天气数据不显示的问题" |
| 按重要性排序 | 最重要的更新放最前面 | 新功能 > 改进 > 修复 |
| 使用列表 | 清晰易读 | 每条更新一行 |
| 感谢用户 | 增加亲和力 | "感谢您的反馈和建议！" |

## 审核信息填写

> 🎯 **本节目标**：正确填写审核信息，帮助审核员快速理解你的 App，减少被拒概率。

### 审核备注编写

审核备注（Review Notes）是给 Apple 审核员看的说明，用户看不到。写好审核备注可以大大提高审核通过率。

**什么时候需要写审核备注：**

| 场景 | 是否需要写 | 说明 |
|------|:----------:|------|
| 普通 App | 建议写 | 简单说明 App 功能即可 |
| 需要登录的 App | ✅ 必须写 | 提供测试账号 |
| 有特殊功能的 App | ✅ 必须写 | 说明功能如何使用 |
| 涉及敏感内容的 App | ✅ 必须写 | 解释为什么需要这些内容 |
| 使用了特殊权限的 App | ✅ 必须写 | 解释为什么需要该权限 |

**审核备注编写模板：**

```
【App 简介】
这是一款天气查询工具，帮助用户查看实时天气和未来预报。

【测试账号】
账号：test@example.com
密码：Test1234

【特殊功能说明】
- 定位权限：用于获取用户当前位置的天气信息
- 通知权限：用于推送降雨提醒

【注意事项】
- 首次打开需要授权定位权限才能显示天气
- 如需测试通知功能，请在设置中开启通知

【联系方式】
如有问题请联系：developer@example.com
```

💡 **提示**：审核备注不需要写得很长，关键是把审核员可能疑惑的地方解释清楚。想象审核员是第一次使用你的 App，他们需要知道什么才能顺利测试。

### 联系方式

审核信息中的联系方式是 Apple 审核团队在有问题时联系你的渠道。

| 字段 | 填写说明 | 建议 |
|------|----------|------|
| 名字 | 你的姓名 | 真实姓名 |
| 姓氏 | 你的姓氏 | 真实姓氏 |
| 电话号码 | 可联系到你的电话 | 建议填手机号 |
| 邮箱 | 审核沟通邮箱 | 经常查看的邮箱 |

⚠️ **警告**：确保电话和邮箱是有效的！Apple 审核团队有时会电话联系开发者确认信息。如果联系不上，审核可能会被暂停。

### 演示账号

**何时需要提供演示账号：**

| 场景 | 是否需要 | 说明 |
|------|:--------:|------|
| App 有登录功能 | ✅ 必须 | 审核员需要登录才能测试 |
| App 有注册功能但可跳过 | ⚠️ 建议 | 方便审核员快速测试 |
| App 完全不需要登录 | ❌ 不需要 | 审核员可以直接使用 |
| 企业内部 App | ✅ 必须 | 审核员无法自行注册 |

**如何提供演示账号：**

| 字段 | 填写说明 | 示例 |
|------|----------|------|
| 用户名 | 测试账号的用户名/邮箱 | test@example.com |
| 密码 | 测试账号的密码 | Test1234 |

**注意事项：**

| 注意事项 | 说明 |
|----------|------|
| 账号必须有效 | 审核时账号必须能正常登录 |
| 密码不要过期 | 确保密码在审核期间不会过期 |
| 数据不要删除 | 不要在审核期间删除测试账号的数据 |
| 账号权限完整 | 测试账号应能访问 App 的所有功能 |
| 不要用真实用户数据 | 测试账号中不要包含真实用户数据 |

💡 **提示**：建议专门创建一个测试账号用于审核，这个账号的数据和状态要保持稳定。不要用你自己的开发账号，因为审核员操作时可能会修改数据。

**演示账号常见问题：**

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 审核员说账号无法登录 | 密码错误或账号被锁定 | 提交前先测试一遍 |
| 审核员说功能无法使用 | 测试账号权限不够 | 确保测试账号有完整权限 |
| 审核员说看不到内容 | 账号没有测试数据 | 预先在测试账号中添加一些数据 |
| 账号过期 | 密码设置了过期策略 | 关闭密码过期或定期更新 |

## 小结

本章涵盖了 App Store Connect 的所有关键配置项，核心要点总结如下：

| 配置项 | 核心要点 |
|--------|----------|
| App 记录创建 | Bundle ID 不可改，名称最多 30 字符 |
| 定价与销售 | 中国区需备案号，小企业计划佣金 15% |
| 年龄分级 | 如实填写，分级不符比高分级更严重 |
| 类别选择 | 选最相关的类别，不要为了低竞争选无关类别 |
| 关键词优化 | 100 字符精打细算，从用户搜索角度选词 |
| 描述编写 | 前 3 行最重要，突出核心卖点 |
| 宣传文本 | 可随时修改，用于宣传新功能和活动 |
| 审核信息 | 提供测试账号，写清楚特殊功能说明 |

**App Store Connect 配置清单：**

```
✅ 创建 App 记录（Bundle ID、SKU）
✅ 设置定价和销售地区
✅ 填写年龄分级问卷
✅ 选择主类别和副类别
✅ 优化关键词（100 字符）
✅ 编写 App 描述（前 3 行最关键）
✅ 填写宣传文本
✅ 编写新增功能文本
✅ 填写审核备注
✅ 提供演示账号（如需要）
✅ 填写联系方式
```
