# 89-隐私政策与用户协议

## 本章目标

- 理解为什么 App 必须有隐私政策和用户协议
- 掌握隐私政策必须包含的核心内容
- 掌握用户协议必须包含的核心内容
- 了解 Apple 审核对隐私政策的硬性要求
- 了解国内《个人信息保护法》等额外合规要求
- 能使用模板快速生成自己的隐私政策和用户协议
- 知道如何托管和版本管理这些法律文档

---

## 1. 为什么需要隐私政策和用户协议

### 生活类比

想象你开了一家餐厅。门口贴一张"本店使用摄像头"的告示，就是**隐私政策**——告诉顾客你会收集什么信息；墙上挂一张"用餐须知"，就是**用户协议**——告诉顾客在你这里吃饭要遵守什么规矩。

没有这两样东西，顾客不知道自己的权益，你也没有法律依据保护自己。App 也是一样。

### 必须做的三个理由

| 理由 | 说明 |
|------|------|
| **App Store 强制要求** | 提交审核时必须填写隐私政策 URL，没有就直接被拒 |
| **法律合规** | 国内《个人信息保护法》、欧盟 GDPR、美国 COPPA 等法律强制要求 |
| **用户信任** | 一份清晰的隐私政策能让用户更放心地使用你的 App |

> ⚠️ **不是可选项！** 隐私政策是上架的硬性门槛，不是"有了更好"的加分项。没有隐私政策 = 无法上架。

## 2. 隐私政策（Privacy Policy）

### 2.1 隐私政策必须包含的内容

一份合格的隐私政策，至少要回答以下 5 个核心问题：

| 核心问题 | 对应章节 | 举例 |
|----------|----------|------|
| 你收集了哪些数据？ | 信息收集 | 设备型号、位置信息、相册照片 |
| 你怎么用这些数据？ | 信息使用 | 用于提供导航服务、用于改进产品 |
| 你会不会把数据给别人？ | 信息共享 | 会不会分享给第三方、分享给谁 |
| 数据存多久？ | 数据保留 | 账号注销后 30 天内删除 |
| 用户有什么权利？ | 用户权利 | 查看数据、删除数据、撤回同意 |

### 2.2 国内 App 额外要求

国内合规要求比国外更细致，以下是必须额外关注的内容：

| 要求 | 对应法规 | 具体内容 |
|------|----------|----------|
| 个人信息保护法 | 《个人信息保护法》 | 需明确告知收集目的、方式、范围，取得用户单独同意 |
| 数据出境 | 《数据出境安全评估办法》 | 数据传到境外服务器需做安全评估 |
| 儿童隐私 | 《儿童个人信息网络保护规定》 | 收集 14 岁以下儿童信息需监护人同意 |
| 个人信息收集清单 | 工信部要求 | 需在 App 内展示收集清单，列出每种信息的目的 |
| 用户注销 | 《个人信息保护法》 | 必须提供账号注销功能，注销后删除数据 |

> 💡 **国内上架特别注意：** 国内应用市场（如华为、小米应用商店）审核比 App Store 更严格，隐私政策必须逐条列出收集的信息和用途，不能笼统地说"我们可能收集您的信息"。

### 2.3 常见数据收集类型速查表

| 数据类型 | 具体内容 | 常见用途 | 敏感程度 |
|----------|----------|----------|----------|
| 设备信息 | 设备型号、操作系统版本、设备标识符 | 兼容性适配、统计分析 | 🟢 低 |
| 日志信息 | IP 地址、访问时间、操作记录 | 故障排查、安全防护 | 🟡 中 |
| 位置信息 | GPS 定位、Wi-Fi 定位 | 地图导航、附近推荐 | 🔴 高 |
| 相册/相机 | 照片、视频 | 头像设置、扫码功能 | 🔴 高 |
| 剪贴板 | 粘贴板内容 | 粘贴口令码、链接识别 | 🔴 高 |
| 通讯录 | 手机联系人 | 好友推荐、邀请功能 | 🔴 高 |
| 麦克风 | 录音 | 语音输入、语音通话 | 🔴 高 |
| 账号信息 | 用户名、手机号、邮箱 | 注册登录、身份验证 | 🟡 中 |
| 支付信息 | 订单号、支付金额 | 购买商品、交易记录 | 🔴 高 |
| 推送通知 | 设备 Token | 消息推送 | 🟢 低 |

> ⚠️ **剪贴板特别提醒：** 从 iOS 16 开始，读取剪贴板会弹出系统提示。如果你的 App 读取剪贴板，必须在隐私政策中明确说明，否则容易被拒。

### 2.4 隐私政策模板

以下模板可直接复制修改使用：

---

**《[你的 App 名称]隐私政策》**

**更新日期：202X年X月X日**
**生效日期：202X年X月X日**

**[你的公司名称]**（以下简称"我们"）深知个人信息对您的重要性，我们将按照法律法规的规定，保护您的个人信息及隐私安全。我们制定本隐私政策以帮助您了解我们如何收集、使用、存储和保护您的个人信息。请您在使用我们的产品/服务前，仔细阅读并充分理解本隐私政策。

**一、我们收集您的哪些信息**

我们在您使用我们的服务时，可能会收集以下信息：

| 信息类型 | 具体内容 | 收集目的 | 收集方式 |
|----------|----------|----------|----------|
| 设备信息 | 设备型号、操作系统版本、设备标识符（IDFA/IDFV） | 兼容性适配、统计分析 | 自动收集 |
| 日志信息 | IP 地址、访问时间、操作日志 | 故障排查、安全防护 | 自动收集 |
| 位置信息 | 大致位置/精确位置 | [填写用途，如：附近推荐] | 需您授权 |
| 相册/相机 | 照片、视频 | [填写用途，如：头像设置] | 需您授权 |
| 账号信息 | 手机号、邮箱、昵称 | 注册登录、身份验证 | 您主动填写 |

> 上述表格请根据实际情况增删，不要保留你没有收集的项目。

**二、我们如何使用您的信息**

我们将收集的信息用于以下目的：

1. 提供、维护和改进我们的产品/服务；
2. 为您提供个性化的服务体验；
3. 进行统计分析，以优化产品性能和用户体验；
4. 保障产品安全和稳定运行；
5. 经您同意的其他用途。

**三、我们如何共享您的信息**

我们不会将您的个人信息出售给任何第三方。但在以下情况下，我们可能会共享您的信息：

1. **服务提供商：** 我们可能委托第三方服务商为您提供特定服务（如推送服务、数据分析服务），我们仅会共享提供服务所必需的信息；
2. **法律要求：** 根据法律法规、法律程序、诉讼或政府主管部门的强制性要求；
3. **经您同意：** 获得您的明确同意后，我们可能会与第三方共享您的信息。

我们共享信息的第三方包括：

| 第三方名称 | 共享信息类型 | 共享目的 |
|------------|------------|----------|
| [如：友盟] | 设备信息、日志信息 | 数据统计分析 |
| [如：极光推送] | 设备 Token | 消息推送 |

**四、数据保留期限**

我们仅在实现本隐私政策所述目的所必需的期限内保留您的个人信息。超出保留期限后，我们将删除或匿名化处理您的个人信息。

- 账号信息：在您使用我们的服务期间保留，账号注销后 30 天内删除；
- 日志信息：保留 180 天；
- 其他信息：在实现收集目的后立即删除或匿名化处理。

**五、您的权利**

根据相关法律法规，您享有以下权利：

1. **查阅和复制：** 您可以在 App 内查阅您的个人信息；
2. **更正和补充：** 您可以更正或补充您的个人信息；
3. **删除：** 在特定情形下，您可以要求我们删除您的个人信息；
4. **撤回同意：** 您可以通过关闭设备权限的方式撤回对特定信息收集的同意；
5. **注销账号：** 您可以在 App 内申请注销账号，注销后我们将在 30 天内删除您的个人信息；
6. **获取副本：** 您可以请求获取您的个人信息副本。

**六、未成年人保护**

我们非常重视对未成年人个人信息的保护。如果您是未满 14 周岁的未成年人，请在您的监护人指导下使用我们的产品/服务，并在取得监护人同意后向我们提供个人信息。

**七、隐私政策的更新**

我们可能会适时修订本隐私政策。当隐私政策发生变更时，我们会在 App 内通过弹窗、公告等方式通知您。对于重大变更，我们会征求您的明确同意。

**八、联系我们**

如您对本隐私政策有任何疑问、意见或建议，可通过以下方式联系我们：

- 邮箱：[你的联系邮箱]
- 地址：[你的公司地址]

---

> 💡 **模板使用提示：** 方括号 `[...]` 中的内容必须替换为你自己的真实信息。没有收集的数据类型要删掉，不要留空模板。

### 2.5 隐私政策英文版模板（面向 App Store）

如果你的 App 面向海外用户，还需要一份英文隐私政策。核心结构与中文版一致，以下为关键章节标题：

```
Privacy Policy

Last Updated: [Date]

1. Information We Collect
2. How We Use Your Information
3. How We Share Your Information
4. Data Retention
5. Your Rights
6. Children's Privacy
7. Changes to This Privacy Policy
8. Contact Us
```

> 💡 **多语言建议：** 如果同时面向国内外用户，建议中英文各写一份，在页面顶部提供语言切换。

## 4. Apple 审核对隐私政策的要求

### 4.1 App Store Connect 中填写隐私政策 URL

在 App Store Connect 中，隐私政策 URL 是**必填项**：

1. 登录 [App Store Connect](https://appstoreconnect.apple.com)
2. 进入你的 App → **App 信息**
3. 在"隐私政策 URL"栏填写你的隐私政策网页地址
4. 该 URL 必须是 **HTTPS** 链接，且**可以正常访问**

> ⚠️ **常见错误：** 填了本地文件路径（如 `file:///...`）或内网地址，审核人员无法访问，直接被拒。

### 4.2 数据收集声明与隐私政策的一致性

App Store Connect 中有一个"App 隐私"部分，需要你声明 App 收集了哪些数据。**这个声明必须和隐私政策的内容完全一致**。

| 声明位置 | 常见不一致问题 | 后果 |
|----------|----------------|------|
| App 隐私声明 | 声明收集了"位置信息"，但隐私政策没提 | 被拒 |
| App 隐私声明 | 声明不收集数据，但代码里有 IDFA 采集 | 被拒 |
| App 隐私声明 | 声明数据"不关联到用户身份"，但实际有账号体系 | 被拒 |

> 💡 **一致性检查清单：**
> - [ ] App 隐私声明中勾选的每一项数据，隐私政策中都有提及
> - [ ] 隐私政策中提到的每一项数据收集，App 隐私声明中都有勾选
> - [ ] 数据用途描述一致
> - [ ] 数据共享情况一致

### 4.3 常见被拒原因

| 被拒原因 | 具体情况 | 解决方法 |
|----------|----------|----------|
| 没有隐私政策 | 未填写隐私政策 URL | 上传隐私政策页面并填写 URL |
| 隐私政策无法访问 | 链接打不开、404 | 确保链接可正常访问 |
| 隐私政策与声明不一致 | 声明和实际内容矛盾 | 逐一核对并修改 |
| 收集数据但未说明用途 | 只说"我们收集数据"但没说为什么 | 逐项列出收集目的 |
| 缺少用户权利说明 | 没有告知用户可以删除数据 | 补充用户权利章节 |
| 第三方 SDK 未披露 | 用了友盟、微信 SDK 但没提 | 在共享章节列出第三方 |

> ⚠️ **Guideline 5.1.1：** Apple 审核指南 5.1.1 明确要求：App 必须包含隐私政策，且必须明确说明收集了哪些数据、如何使用、与谁共享。这是被拒的高频条款。

## 5. 国内合规额外要求

### 5.1 《个人信息保护法》要点

2021 年 11 月 1 日施行的《个人信息保护法》是国内数据保护的最高法律，要点如下：

| 要点 | 说明 | 你的 App 需要做什么 |
|------|------|---------------------|
| 知情同意 | 收集个人信息必须取得用户同意 | 首次启动时弹窗告知并获取同意 |
| 最小必要 | 只收集实现功能所必需的信息 | 不要收集与功能无关的数据 |
| 目的明确 | 收集信息的目的必须明确 | 隐私政策中逐项说明用途 |
| 单独同意 | 敏感个人信息需取得单独同意 | 收集位置、相册等敏感信息时单独弹窗 |
| 撤回同意 | 用户有权撤回同意 | 提供关闭权限的入口 |
| 数据出境 | 数据传到境外需安全评估 | 如使用境外服务器，需做安全评估 |

### 5.2 《网络安全法》要点

| 要点 | 说明 | 你的 App 需要做什么 |
|------|------|---------------------|
| 网络安全等级保护 | 按等级采取安全措施 | 做好数据加密和安全防护 |
| 用户真实身份 | 需要用户提供真实身份信息 | 注册时手机号验证 |
| 数据安全事件通知 | 发生数据泄露需通知用户 | 制定应急预案 |

### 5.3 用户注销功能

这是国内合规的**硬性要求**，很多开发者容易忽略：

| 要求 | 说明 |
|------|------|
| 必须提供注销入口 | 在 App 内设置页面提供"注销账号"功能 |
| 注销流程不能太复杂 | 不能要求用户打电话、发邮件才能注销 |
| 注销后删除数据 | 注销后 30 天内删除或匿名化个人信息 |
| 注销后不能登录 | 注销后原账号无法登录 |

> ⚠️ **工信部通报：** 每次工信部通报的违规 App 中，"账号注销难"都是高频问题。如果你的 App 有注册功能，注销功能是必须的。

### 5.4 个人信息收集清单

工信部要求 App 内必须展示"个人信息收集清单"，格式如下：

| 个人信息类型 | 收集目的 | 使用场景 | 收集方式 |
|-------------|---------|---------|---------|
| 设备型号 | 兼容性适配 | App 启动时 | 自动收集 |
| 位置信息 | 附近推荐 | 使用推荐功能时 | 需用户授权 |
| 手机号 | 注册登录 | 注册/登录时 | 用户填写 |

> 💡 **实现方式：** 在 App 的"设置 → 隐私"页面中，增加一个"个人信息收集清单"入口，点击后展示上述表格内容。

## 8. 最佳实践

### 8.1 版本管理

隐私政策和用户协议是法律文档，必须做好版本管理：

| 实践 | 说明 |
|------|------|
| 标注版本号 | 如 v1.0、v1.1、v2.0 |
| 标注更新日期 | 每次修改都要更新日期 |
| 保留历史版本 | 在页面底部提供"历史版本"链接 |
| 记录变更内容 | 维护一个变更日志，记录每次修改了什么 |

```
版本变更日志示例：

v2.0 - 2024-06-01
- 新增：剪贴板读取说明
- 修改：数据保留期限从 90 天调整为 180 天
- 删除：不再收集通讯录信息

v1.1 - 2024-01-15
- 新增：第三方 SDK 共享说明
- 修改：更新公司地址

v1.0 - 2023-09-01
- 初始版本
```

### 8.2 更新通知

当隐私政策发生重大变更时，必须通知用户：

| 通知方式 | 适用场景 | 实现难度 |
|----------|----------|----------|
| App 内弹窗 | 重大变更（如新增收集数据类型） | ⭐⭐ |
| 启动页公告 | 中等变更 | ⭐⭐ |
| 设置页红点提示 | 小幅修改 | ⭐ |
| 推送通知 | 紧急变更 | ⭐⭐ |

> ⚠️ **重要：** 如果新增了敏感信息收集（如位置、相册），必须取得用户**明确同意**，不能仅靠公告通知。

### 8.3 多语言版本

如果你的 App 面向多个国家/地区，需要提供多语言版本：

| 语言 | 适用地区 | 优先级 |
|------|----------|--------|
| 中文 | 中国大陆 | 必须 |
| 英文 | 全球 | 必须（面向海外时） |
| 日文 | 日本 | 按需 |
| 韩文 | 韩国 | 按需 |
| 欧盟语言 | 欧盟国家 | 按需（GDPR 要求） |

多语言实现方式：

```html
<!-- 在页面顶部添加语言切换 -->
<div class="language-switch">
    <a href="/privacy.html">中文</a> |
    <a href="/privacy-en.html">English</a>
</div>
```

> 💡 **翻译建议：** 法律文档的翻译最好请专业法律翻译，不要用机器翻译直接替代，尤其是涉及免责条款和争议解决的部分。

### 8.4 完整检查清单

在提交审核前，用以下清单逐项检查：

- [ ] 隐私政策 URL 已填写且可正常访问（HTTPS）
- [ ] 隐私政策包含：收集信息、使用方式、共享情况、保留期限、用户权利
- [ ] App 隐私声明与隐私政策内容一致
- [ ] 所有第三方 SDK 已在隐私政策中披露
- [ ] 用户协议包含：服务范围、行为规范、知识产权、免责声明、终止条款
- [ ] 国内合规：个人信息收集清单、账号注销功能
- [ ] 隐私政策标注了版本号和更新日期
- [ ] 如有敏感信息收集，首次使用时弹窗获取单独同意
- [ ] 多语言版本（如需要）

## 小结

| 知识点 | 一句话总结 |
|--------|-----------|
| 为什么需要 | App Store 强制要求 + 法律合规 + 用户信任 |
| 隐私政策核心 | 回答 5 个问题：收集什么、怎么用、给谁、存多久、用户权利 |
| 用户协议核心 | 服务范围 + 行为规范 + 知识产权 + 免责 + 终止 |
| Apple 审核重点 | URL 可访问 + 声明与政策一致 + 第三方 SDK 披露 |
| 国内额外要求 | 个人信息保护法 + 注销功能 + 收集清单 |
| 生成工具 | 海外用 iubenda/Termly，国内用模板或法大大 |
| 托管方案 | GitHub Pages / Vercel / Cloudflare Pages 免费托管 |
| 最佳实践 | 版本管理 + 更新通知 + 多语言 |

> 💡 **核心原则：** 隐私政策和用户协议不是应付审核的摆设，而是你对用户的承诺。写得越清晰、越诚实，用户越信任你，审核也越容易通过。当你在犹豫"要不要写"的时候，答案永远是——**写**。
