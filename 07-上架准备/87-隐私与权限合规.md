# 87-隐私与权限合规

> 🎯 **本章目标**：了解 iOS App 必须遵守的隐私与权限规范，学会正确配置 Info.plist 权限描述、编写隐私政策、填写 App Privacy 营养标签，确保你的 App 在国内外法规下完全合规。

---

## Info.plist 权限描述

当你的 App 需要访问用户的相机、相册、位置等敏感信息时，iOS 会弹出一个系统权限请求弹窗。弹窗中的文字就是你在 Info.plist 中配置的权限描述。

### 必填权限项

⚠️ **核心规则**：只要你的 App 代码中引用了某个权限相关的 API，就**必须**在 Info.plist 中添加对应的权限描述，否则 App 会直接崩溃！

| 权限 | Info.plist Key | 何时需要 |
|------|---------------|---------|
| 相机 | `NSCameraUsageDescription` | 拍照、扫码、视频通话 |
| 相册（读取） | `NSPhotoLibraryUsageDescription` | 读取相册图片、选择头像 |
| 相册（写入） | `NSPhotoLibraryAddUsageDescription` | 保存图片/视频到相册 |
| 位置（使用时） | `NSLocationWhenInUseUsageDescription` | 导航、附近搜索、打卡 |
| 位置（始终） | `NSLocationAlwaysAndWhenInUseUsageDescription` | 后台定位、轨迹记录 |
| 通讯录 | `NSContactsUsageDescription` | 读取联系人、邀请好友 |
| 麦克风 | `NSMicrophoneUsageDescription` | 录音、语音消息 |
| 日历 | `NSCalendarsUsageDescription` | 读取/写入日历事件 |
| 提醒事项 | `NSRemindersUsageDescription` | 读取/写入提醒事项 |
| 健康 | `NSHealthShareUsageDescription` / `NSHealthUpdateUsageDescription` | 读取/写入健康数据 |
| 蓝牙 | `NSBluetoothAlwaysUsageDescription` | 连接蓝牙设备 |
| Face ID | `NSFaceIDUsageDescription` | 使用 Face ID 登录/验证 |
| 语音识别 | `NSSpeechRecognitionUsageDescription` | 语音转文字 |
| Apple Music | `NSAppleMusicUsageDescription` | 访问 Apple Music 库 |
| HomeKit | `NSHomeKitUsageDescription` | 控制智能家居 |
| 运动与健身 | `NSMotionUsageDescription` | 计步器、运动追踪 |

### 权限描述编写规范

权限描述是用户决定是否授予权限的关键依据，写得好不好直接影响用户信任度。

#### 编写原则

| 原则 | 说明 |
|------|------|
| **清楚说明为什么需要** | 告诉用户你用这个权限做什么 |
| **用户能理解的语言** | 不要写技术术语，用大白话 |
| **只说明实际用途** | 不要夸大或隐瞒用途 |
| **简明扼要** | 1-2 句话，不要写长篇大论 |

#### 好的 vs 差的描述对比

| 权限 | ❌ 差的描述 | ✅ 好的描述 |
|------|-----------|-----------|
| 相机 | "需要访问相机" | "用于拍摄照片来创建您的个人头像" |
| 相册 | "用于保存数据" | "用于选择照片作为您的头像和发布内容" |
| 位置 | "获取您的位置" | "用于为您推荐附近的餐厅和优惠信息" |
| 通讯录 | "访问通讯录" | "用于查找已在 App 中的好友，方便您添加联系" |
| 麦克风 | "录音功能" | "用于发送语音消息和语音搜索" |
| Face ID | "认证" | "用于快速安全地登录您的账户" |

💡 **提示**：想象你在向一个不懂技术的朋友解释——"我为什么要用你的相机？" 你的回答就是权限描述。

### 常见权限列表

| 权限名 | Key | 建议描述模板 |
|--------|-----|-------------|
| 相机 | `NSCameraUsageDescription` | "用于拍摄照片来[具体用途]" |
| 相册读取 | `NSPhotoLibraryUsageDescription` | "用于选择照片来[具体用途]" |
| 相册写入 | `NSPhotoLibraryAddUsageDescription` | "用于将[什么内容]保存到您的相册" |
| 位置（使用时） | `NSLocationWhenInUseUsageDescription` | "用于[具体功能，如：显示您附近的商家]" |
| 位置（始终） | `NSLocationAlwaysAndWhenInUseUsageDescription` | "用于[具体功能，如：记录您的运动轨迹]" |
| 通讯录 | `NSContactsUsageDescription` | "用于[具体功能，如：查找已在 App 中的好友]" |
| 麦克风 | `NSMicrophoneUsageDescription` | "用于[具体功能，如：发送语音消息]" |
| 日历 | `NSCalendarsUsageDescription` | "用于[具体功能，如：添加活动到日历]" |
| Face ID | `NSFaceIDUsageDescription` | "用于[具体功能，如：快速安全地登录]" |
| 蓝牙 | `NSBluetoothAlwaysUsageDescription` | "用于[具体功能，如：连接智能手环]" |

#### 在 Xcode 中添加权限描述

**方法一：通过 Info.plist 编辑器（推荐）**

1. 在 Xcode 项目导航器中点击项目根节点
2. 选择 `Info` 标签页
3. 在 `Custom iOS Target Properties` 中点击 `+` 按钮
4. 输入 Key（如 `Privacy - Camera Usage Description`）
5. 在 Value 中填写权限描述文字

**方法二：直接编辑 Info.plist 源码**

右键 Info.plist → `Open As` → `Source Code`，添加如下内容：

```xml
<key>NSCameraUsageDescription</key>
<string>用于拍摄照片来创建您的个人头像</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>用于选择照片作为您的头像和发布内容</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>用于为您推荐附近的餐厅和优惠信息</string>
```

⚠️ **警告**：如果你在代码中使用了某个权限 API（如 `UIImagePickerController` 选择相机），但没有在 Info.plist 中添加对应的描述，App 在运行到该代码时会**直接崩溃**！这是 iOS 开发中最常见的崩溃原因之一。

## 隐私政策页面编写

隐私政策是 App Store 上架的**强制要求**，没有隐私政策的 App 会被拒绝审核。

### 隐私政策模板

以下是一个适用于大多数个人开发者 App 的隐私政策模板：

```markdown
# 隐私政策

最后更新日期：2026年XX月XX日

欢迎使用「你的App名称」（以下简称"本应用"）。本应用由「你的名字/公司名」（以下简称"我们"）开发和运营。我们非常重视您的隐私保护，本隐私政策将帮助您了解我们如何收集、使用、存储和保护您的个人信息。

## 1. 我们收集哪些信息

### 1.1 您主动提供的信息
- 注册信息：手机号码、邮箱地址（如需注册）
- 个人资料：昵称、头像（如您选择填写）

### 1.2 自动收集的信息
- 设备信息：设备型号、操作系统版本
- 日志信息：访问时间、页面浏览记录
- 崩溃日志：用于改进应用稳定性

### 1.3 需要您授权的信息
- 相机权限：用于[具体用途]
- 相册权限：用于[具体用途]
- 位置权限：用于[具体用途]

## 2. 我们如何使用信息

我们收集的信息将用于以下目的：
- 提供、维护和改进我们的服务
- 处理您的请求和交易
- 向您发送服务相关的通知
- 保障应用安全，防止欺诈

## 3. 我们如何存储信息

- 存储地点：中华人民共和国境内
- 存储期限：在实现服务目的所必需的最短时间内保留
- 安全措施：采用加密存储、访问控制等技术手段保护您的信息

## 4. 信息共享

我们不会将您的个人信息出售给第三方。仅在以下情况下，我们可能会共享您的信息：
- 获得您的明确同意
- 根据法律法规的要求
- 与我们的关联公司共享（仅限于本政策所述目的）

## 5. 您的权利

根据适用的法律法规，您享有以下权利：
- 访问权：您有权访问您的个人信息
- 更正权：您有权要求更正不准确的个人信息
- 删除权：您有权要求删除您的个人信息
- 撤回同意权：您有权撤回之前给予的同意
- 数据可携权：您有权获取您的个人信息副本

## 6. 未成年人保护

我们非常重视对未成年人个人信息的保护。如果您是未满14周岁的未成年人，请在监护人的陪同下阅读本政策，并在取得监护人同意后使用本应用。

## 7. 隐私政策的更新

我们可能会不时更新本隐私政策。更新后的政策将在应用内公告，重大变更会通过弹窗等方式通知您。

## 8. 联系我们

如果您对本隐私政策有任何疑问，请通过以下方式联系我们：
- 邮箱：your-email@example.com
- 地址：你的联系地址
```

### 必须包含的内容

| 内容 | 说明 | 是否必须 |
|------|------|---------|
| **收集哪些数据** | 明确列出 App 收集的所有个人信息类型 | ✅ 必须 |
| **数据如何使用** | 说明每种数据的用途 | ✅ 必须 |
| **数据如何存储** | 存储地点、期限、安全措施 | ✅ 必须 |
| **第三方分享** | 是否分享给第三方，分享给谁，为什么 | ✅ 必须 |
| **用户权利** | 用户可以查看、修改、删除数据的权利 | ✅ 必须 |
| **联系方式** | 用户有问题时可以联系谁 | ✅ 必须 |
| **未成年人保护** | 对未成年人的特殊保护措施 | ✅ 必须（国内上架） |
| **Cookie 政策** | 如果使用 Cookie 或类似技术 | 视情况而定 |
| **政策更新方式** | 如何通知用户政策变更 | ✅ 必须 |

⚠️ **警告**：隐私政策中的内容必须与 App 实际行为一致！如果你的隐私政策说"不收集位置信息"，但 App 实际上请求了位置权限，App Store 审核会被拒绝。

### 在 App 内展示隐私政策

App 内必须提供隐私政策的入口，让用户随时可以查看。

#### 方式一：设置页链接（推荐）

在 App 的「设置」或「关于」页面添加隐私政策链接：

```swift
import SafariServices

func openPrivacyPolicy() {
    guard let url = URL(string: "https://your-domain.com/privacy-policy") else { return }
    let safariVC = SFSafariViewController(url: url)
    present(safariVC, animated: true)
}
```

💡 **提示**：使用 `SFSafariViewController` 而不是跳转到 Safari 浏览器，这样用户不需要离开 App 就能查看隐私政策。

#### 方式二：首次启动弹窗

在用户首次打开 App 时，弹窗展示隐私政策摘要：

```swift
func showPrivacyConsent() {
    let alert = UIAlertController(
        title: "隐私政策",
        message: "在使用本应用前，请您阅读并同意我们的隐私政策。我们重视您的隐私保护。",
        preferredStyle: .alert
    )
    
    alert.addAction(UIAlertAction(title: "查看隐私政策", style: .default) { _ in
        self.openPrivacyPolicy()
    })
    
    alert.addAction(UIAlertAction(title: "同意并继续", style: .default) { _ in
        UserDefaults.standard.set(true, forKey: "hasAgreedPrivacyPolicy")
    })
    
    alert.addAction(UIAlertAction(title: "不同意", style: .cancel) { _ in
        exit(0)
    })
    
    present(alert, animated: true)
}
```

⚠️ **注意**：国内上架要求首次启动必须弹窗让用户同意隐私政策，用户不同意则不能使用 App。

## 数据收集声明

### App Privacy 营养标签

#### 什么是营养标签？

App Privacy 营养标签（App Privacy Nutrition Label）是 Apple 在 App Store 页面上展示的隐私信息摘要，类似于食品包装上的营养成分表，让用户在下载前就能了解 App 会收集哪些数据。

```
┌─────────────────────────────┐
│  App Privacy                │
│  ─────────────────────────  │
│  以下数据可能用于追踪：      │
│  · 标识符                   │
│                             │
│  以下数据可能关联到你：      │
│  · 联系信息 · 位置          │
│                             │
│  以下数据不会关联到你：      │
│  · 诊断数据                 │
└─────────────────────────────┘
```

#### 为什么要填写？

- **App Store 强制要求**：不填写无法提交审核
- **用户信任**：透明的隐私声明能增加用户信任
- **法律合规**：符合 GDPR、国内个保法等法规要求

#### 如何填写

1. 登录 [App Store Connect](https://appstoreconnect.apple.com)
2. 选择你的 App
3. 点击「App 隐私」
4. 点击「开始」
5. 回答问题：你的 App 是否收集数据？
6. 选择收集的数据类型
7. 对每种数据说明用途和是否关联到用户身份

### 数据类型分类

Apple 将数据收集分为以下几大类：

| 大类 | 包含的数据类型 | 常见示例 |
|------|--------------|---------|
| **联系信息** | 邮箱、电话、姓名 | 注册账号、联系客服 |
| **健康与健身** | 健康数据、健身数据 | 运动记录、心率监测 |
| **财务信息** | 支付信息、信用信息 | 应用内购买 |
| **位置** | 精确位置、粗略位置 | 附近搜索、导航 |
| **敏感信息** | 种族、宗教、性取向等 | 极少 App 需要 |
| **联系人** | 通讯录、社交图谱 | 好友推荐 |
| **用户内容** | 邮件、照片、视频 | 社交分享 |
| **浏览历史** | 浏览的网页、App 内搜索 | 内容推荐 |
| **搜索历史** | 搜索关键词 | 搜索建议 |
| **标识符** | 用户 ID、设备 ID | 用户登录、数据分析 |
| **购买记录** | 购买历史 | 会员订阅 |
| **诊断数据** | 崩溃日志、性能数据 | App 稳定性改进 |
| **其他数据** | 不属于以上类别的数据 | 自定义数据 |

### 填写指南

#### 步骤说明

**步骤 1：进入 App Privacy 页面**

1. 登录 App Store Connect
2. 选择你的 App
3. 左侧菜单点击「App 隐私」

**步骤 2：选择数据收集类型**

1. 点击「开始」
2. 回答「你的 App 是否从该 App 收集数据？」→ 选择「是，从此 App 收集数据」
3. 勾选你的 App 实际收集的数据类型

**步骤 3：对每种数据说明用途**

对每种勾选的数据类型，需要回答三个问题：

| 问题 | 选项 | 说明 |
|------|------|------|
| **是否用于追踪？** | 是/否 | 是否将数据用于跨 App 追踪用户 |
| **是否关联到用户身份？** | 是/否 | 数据是否可以识别到具体用户 |
| **收集目的** | 多选 | 分析、产品个性化、广告、开发等 |

**步骤 4：发布**

确认所有信息无误后，点击「发布」。

#### 常见问题

| 问题 | 回答 |
|------|------|
| 我的 App 只收集崩溃日志，需要申报吗？ | ✅ 需要，崩溃日志属于「诊断数据」 |
| 第三方 SDK 收集的数据也要申报吗？ | ✅ 是的，你的 App 中所有代码（包括第三方 SDK）收集的数据都需要申报 |
| 我不确定某个 SDK 收集了什么数据怎么办？ | 查看该 SDK 的文档或联系开发者确认 |
| 申报后可以修改吗？ | ✅ 可以随时修改并重新发布 |
| 如果不收集任何数据呢？ | 选择「不从此 App 收集数据」即可 |

⚠️ **警告**：务必如实填写！如果 Apple 发现你的 App 实际收集了未声明的数据，App 可能会被下架。第三方 SDK（如友盟、Firebase 等）收集的数据也需要一并申报。

## GDPR / 国内个人信息保护法

### GDPR 要求

GDPR（通用数据保护条例）是欧盟的隐私保护法规，如果你的 App 面向欧洲用户，就必须遵守。

| 要求 | 说明 | 你需要做什么 |
|------|------|------------|
| **用户同意** | 收集数据前必须获得用户明确同意 | 首次启动弹窗请求同意 |
| **数据最小化** | 只收集实现功能所必需的数据 | 不收集与功能无关的数据 |
| **数据可携** | 用户有权获取自己的数据副本 | 提供数据导出功能 |
| **被遗忘权** | 用户有权要求删除自己的所有数据 | 提供账号注销功能 |
| **隐私设计** | 从设计阶段就考虑隐私保护 | 默认不收集，按需请求 |

💡 **提示**：即使你的 App 只面向中国用户，遵循 GDPR 的原则也是最佳实践，因为这些原则和国内个保法高度一致。

### 国内个保法要求

《中华人民共和国个人信息保护法》（简称"个保法"）是国内 App 必须遵守的隐私法规。

| 要求 | 说明 | 你需要做什么 |
|------|------|------------|
| **个人信息处理规则** | 必须公开个人信息处理规则 | 编写并公示隐私政策 |
| **用户同意** | 处理个人信息前必须获得用户同意 | 首次启动弹窗请求同意 |
| **最小必要原则** | 只收集实现功能所必需的个人信息 | 不超范围收集 |
| **数据安全** | 采取必要措施保障数据安全 | 加密存储、传输加密 |
| **用户权利** | 用户有权查阅、复制、更正、删除个人信息 | 提供相关功能入口 |
| **账号注销** | 用户有权注销账号 | 提供账号注销功能 |
| **未成年人保护** | 对未满14周岁未成年人有特殊保护 | 增加监护人同意机制 |

⚠️ **严重警告**：国内 App 上架各大应用商店时，工信部会进行隐私合规检测。如果发现以下问题，App 会被要求整改甚至下架：
- 首次启动未弹窗请求隐私政策同意
- 收集与功能无关的个人信息
- 频繁弹窗索取权限
- 不提供账号注销功能
- 隐私政策内容不完整或不准确

### 用户同意机制

#### 首次启动弹窗（国内必须）

国内上架要求 App 首次启动时必须弹出隐私政策弹窗，用户同意后才能使用：

```swift
class PrivacyConsentManager {
    
    static let hasAgreedKey = "hasAgreedPrivacyPolicy"
    
    static func shouldShowConsent() -> Bool {
        return !UserDefaults.standard.bool(forKey: hasAgreedKey)
    }
    
    static func showConsentIfNeeded(from viewController: UIViewController) {
        guard shouldShowConsent() else { return }
        
        let alert = UIAlertController(
            title: "用户协议与隐私政策",
            message: "请您仔细阅读《用户协议》和《隐私政策》，了解我们如何处理您的个人信息。当您点击"同意"即表示您已阅读并同意上述协议。",
            preferredStyle: .alert
        )
        
        alert.addAction(UIAlertAction(title: "同意", style: .default) { _ in
            UserDefaults.standard.set(true, forKey: hasAgreedKey)
        })
        
        alert.addAction(UIAlertAction(title: "不同意", style: .cancel) { _ in
            exit(0)
        })
        
        viewController.present(alert, animated: true)
    }
}
```

💡 **提示**：弹窗文案中应同时提及《用户协议》和《隐私政策》，并提供可点击的链接让用户查看完整内容。

#### 设置中管理权限

用户应该能在 App 设置中随时管理已授予的权限：

```swift
func openAppSettings() {
    if let url = URL(string: UIApplication.openSettingsURLString) {
        UIApplication.shared.open(url)
    }
}
```

💡 **提示**：这段代码会跳转到系统的 App 设置页面，用户可以在那里管理权限。这是 iOS 提供的标准方式，不需要自己实现权限管理界面。

#### 权限请求最佳实践

| 做法 | 说明 | ✅ 推荐 | ❌ 不推荐 |
|------|------|--------|---------|
| **按需请求** | 只在用户使用相关功能时才请求权限 | 用户点击"拍照"按钮时请求相机 | App 启动时一次性请求所有权限 |
| **解释原因** | 请求权限前先解释为什么需要 | 自定义弹窗说明用途后请求 | 直接弹出系统权限弹窗 |
| **优雅降级** | 用户拒绝权限后提供替代方案 | 用户拒绝相机权限时提供从相册选择 | 用户拒绝后功能完全不可用 |
| **不频繁弹窗** | 用户拒绝后不要反复请求 | 引导用户去设置中手动开启 | 每次打开 App 都弹权限请求 |

## 小结

| 内容 | 关键要点 |
|------|---------|
| **Info.plist 权限描述** | 使用权限 API 必须添加描述，否则 App 崩溃；描述要清楚说明用途 |
| **隐私政策** | App Store 强制要求，必须包含数据收集、使用、存储、分享、用户权利、联系方式 |
| **App Privacy 营养标签** | App Store Connect 中填写，第三方 SDK 收集的数据也要申报 |
| **GDPR** | 用户同意、数据最小化、数据可携、被遗忘权 |
| **国内个保法** | 首次启动弹窗、最小必要原则、账号注销、未成年人保护 |
| **权限请求最佳实践** | 按需请求、解释原因、优雅降级、不频繁弹窗 |
