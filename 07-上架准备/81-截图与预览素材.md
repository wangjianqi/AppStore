# 81-截图与预览素材

> 🎯 **本章目标**：掌握 App Store 截图的尺寸规范和制作方法，学会设计吸引人的截图和预览视频，让你的 App 在商店页面脱颖而出。

---

## App Store 截图尺寸规范

App Store 对截图有严格的尺寸和数量要求，不同设备需要不同尺寸的截图。

### 详细尺寸表

| 设备类型 | 对角线尺寸 | 分辨率（像素） | 状态 |
|----------|-----------|---------------|------|
| **6.7" iPhone** | 6.7 英寸 | 1290 × 2796 | ✅ 必需（如 iPhone 15 Pro Max / 16 Pro Max） |
| **6.5" iPhone** | 6.5 英寸 | 1284 × 2778 | ✅ 必需（如 iPhone 14 Plus / 15 Plus） |
| **5.5" iPhone** | 5.5 英寸 | 1242 × 2208 | ✅ 必需（如 iPhone 8 Plus） |
| **12.9" iPad Pro** | 12.9 英寸 | 2048 × 2732 | 可选（仅 iPad App 需要） |
| **11" iPad Pro** | 11 英寸 | 1668 × 2388 | 可选（仅 iPad App 需要） |

### 必需尺寸 vs 可选尺寸

| 类型 | 说明 |
|------|------|
| **必需** | 6.7" 或 6.5" 至少提供一种尺寸的截图 |
| **推荐** | 同时提供 6.7" 和 6.5" 的截图，覆盖更多设备展示 |
| **5.5"** | 仍然需要提供，用于旧设备展示 |
| **iPad** | 仅当你的 App 支持 iPad 时才需要 |

💡 **提示**：如果你只提供 6.7" 的截图，App Store 会自动缩放显示在其他设备上。但为了最佳效果，建议至少提供 6.7" 和 6.5" 两种尺寸。

### 分辨率要求

| 要求 | 说明 |
|------|------|
| **格式** | PNG 或 JPEG |
| **色彩空间** | sRGB |
| **方向** | 竖屏（Portrait）或横屏（Landscape），但同一套截图方向必须一致 |
| **数量** | 每种尺寸 3-10 张截图 |
| **文件大小** | 每张不超过 8MB |

⚠️ **警告**：截图方向必须和 App 的支持方向一致。如果你的 App 只支持竖屏，截图就必须是竖屏的。混用方向会被 App Store Connect 拒绝！

## 截图制作工具

### Simulator 截图

最简单的方式——直接用 Xcode 模拟器截图。

#### 模拟器截图方法

**步骤 1：启动模拟器**

1. 打开 Xcode
2. 选择菜单 `Xcode` → `Open Developer Tool` → `Simulator`
3. 选择目标设备（如 iPhone 15 Pro Max）

**步骤 2：运行 App**

1. 在模拟器中运行你的 App
2. 导航到你想截图的页面

**步骤 3：截图**

| 方式 | 操作 |
|------|------|
| **快捷键** | `⌘ + S`（在模拟器窗口激活时） |
| **菜单** | `File` → `Save Screen` |
| **系统截图** | `⌘ + Shift + 4` + 空格 + 点击模拟器窗口 |

💡 **提示**：使用 `⌘ + S` 截图会保存模拟器的原始分辨率，不包含模拟器边框，直接符合 App Store 要求。

⚠️ **注意**：使用 `⌘ + Shift + 4` 截图会包含模拟器边框和状态栏阴影，需要额外裁剪。推荐使用模拟器自带的 `⌘ + S` 截图。

### 快截图工具

如果你需要批量截图（多语言、多页面），手动截图效率太低，推荐使用自动化工具：

| 工具 | 特点 | 适合人群 |
|------|------|---------|
| **Snapshot（fastlane）** | 自动化截图，支持多语言 | 有命令行基础的开发者 |
| **SimGen** | 简单易用的模拟器截图工具 | 想要快速截图的开发者 |
| **ScreenShot Maker** | 在线工具，上传截图自动美化 | 零基础小白 |

#### Snapshot（fastlane）使用方法

```bash
# 1. 安装 fastlane
gem install fastlane -NV

# 2. 在项目目录初始化
fastlane init

# 3. 配置 Snapfile
# 在项目根目录创建 Snapfile，内容如下：
```

```ruby
# Snapfile 配置示例
devices([
  "iPhone 15 Pro Max",
  "iPhone 15 Plus",
  "iPhone 8 Plus"
])

languages([
  "zh-Hans",
  "en"
])

scheme("YourAppScheme")

clear_previous_screenshots(true)
```

```bash
# 4. 运行截图
fastlane snapshot

# 5. 截图保存在 ./screenshots/ 目录
```

💡 **提示**：fastlane 的 Snapshot 需要配合 UI 测试代码使用，它会自动运行你写好的 UI 测试，在每个页面自动截图。适合需要大量截图的项目。

### 设计工具制作

如果你想在截图上添加标题、说明文字和装饰，推荐使用设计工具：

| 工具 | 特点 | 模板资源 |
|------|------|---------|
| **Figma** | 专业设计工具，社区模板丰富 | 搜索 "App Store Screenshot Template" |
| **Sketch** | Mac 专属设计工具 | Sketch App Sources 有免费模板 |
| **Canva** | 在线设计，零基础友好 | 搜索 "App Store Screenshot" |

#### Figma 模板使用

1. 打开 [Figma](https://figma.com)
2. 搜索 "App Store Screenshot Template"
3. 选择一个喜欢的模板，点击「Duplicate」
4. 替换模板中的截图和文字为你的内容
5. 导出为 PNG

💡 **推荐模板**：
- [App Store Screenshot Generator](https://www.figma.com/community/search?resource_type=mixed&sort_by=relevancy&query=app+store+screenshot&editor_type=all)

## 截图内容设计

### 首屏截图策略

第一张截图是用户在 App Store 最先看到的，决定了用户是否继续浏览——**它是最重要的截图！**

| 策略 | 说明 |
|------|------|
| **展示核心功能** | 第一张截图必须展示 App 最核心、最有吸引力的功能 |
| **添加标题文案** | 用一句简短有力的标题说明 App 的价值 |
| **视觉冲击力** | 使用鲜明的颜色和大字体，在搜索结果中脱颖而出 |

#### 首屏截图布局参考

```
┌─────────────────┐
│                  │
│  📱 标题文案     │  ← 大号粗体标题
│  "一键记录生活"  │
│                  │
│  ┌───────────┐  │
│  │           │  │  ← App 界面截图
│  │  App界面  │  │
│  │           │  │
│  └───────────┘  │
│                  │
└─────────────────┘
```

💡 **提示**：在 App Store 搜索结果中，只有第一张截图会显示。所以第一张截图必须能独立说明 App 是做什么的！

### 功能展示截图

| 截图序号 | 内容建议 | 文案建议 |
|----------|---------|---------|
| **第 1 张** | 核心功能/主界面 | App 的核心价值主张 |
| **第 2 张** | 第二重要的功能 | 功能亮点说明 |
| **第 3 张** | 第三重要的功能 | 功能亮点说明 |
| **第 4 张** | 特色功能/差异化 | "还有更多..." |
| **第 5 张** | 社交证明/用户评价 | "用户都在用" |

#### 设计要点

- **每张只展示一个核心功能**：不要在一张截图里塞太多内容
- **保持风格一致**：所有截图使用相同的字体、颜色、排版风格
- **从左到右讲故事**：截图排列应该有逻辑，像翻书一样

### 文案与标注

#### 标题文案编写

| 原则 | 说明 | ✅ 好的文案 | ❌ 差的文案 |
|------|------|------------|------------|
| **简短有力** | 5-8 个字最佳 | "一键记账" | "这是一款非常好用的记账工具" |
| **突出价值** | 告诉用户能得到什么 | "3 秒完成记账" | "支持多种记账方式" |
| **使用动词** | 动词更有行动力 | "记录你的每一天" | "日记功能" |
| **避免技术术语** | 用户不关心技术 | "智能分类" | "基于 CoreML 的分类算法" |

#### 字体和颜色建议

| 元素 | 建议 |
|------|------|
| **标题字体** | 粗体无衬线字体（如 PingFang SC Bold、SF Pro Display Bold） |
| **标题大小** | 截图宽度的 8%-12% |
| **标题颜色** | 白色或深色，与背景形成强对比 |
| **背景色** | App 品牌色或渐变色，避免纯白（太单调） |

## 预览视频录制

### 视频规格要求

| 要求项 | 说明 |
|--------|------|
| **时长** | 15-30 秒 |
| **分辨率** | 与对应设备截图分辨率一致 |
| **格式** | M4V、MP4 或 MOV |
| **帧率** | 30fps 或 60fps |
| **方向** | 与截图方向一致（竖屏或横屏） |
| **数量** | 每种设备尺寸最多 3 个视频 |

⚠️ **警告**：视频时长不要超过 30 秒！App Store 会截断超长视频。15-30 秒是最佳长度，足够展示核心功能又不会让用户失去耐心。

### 录制工具

| 工具 | 适用场景 | 操作方式 |
|------|---------|---------|
| **模拟器录制** | 最简单，直接录模拟器画面 | 模拟器菜单 → `File` → `Record Screen` |
| **QuickTime** | 录制真机画面 | `文件` → `新建影片录制` → 选择 iPhone |
| **Xcode** | 录制模拟器或真机 | `Debug` → `Start Recording` |
| **ScreenFlow** | 专业录屏 + 编辑 | 第三方付费工具 |
| **OBS** | 免费录屏工具 | 开源，功能强大 |

#### 模拟器录制步骤

1. 打开模拟器，运行你的 App
2. 点击模拟器菜单栏 `File` → `Record Screen`（或快捷键 `⌘ + R`）
3. 操作 App，展示核心功能
4. 点击 `File` → `Stop Recording`（或快捷键 `⌘ + R`）
5. 视频自动保存为 `.mov` 文件

#### 真机录制步骤（QuickTime）

1. 用数据线连接 iPhone 到 Mac
2. 打开 QuickTime Player
3. `文件` → `新建影片录制`
4. 点击录制按钮旁的下拉箭头，选择你的 iPhone
5. 在 iPhone 上操作 App，QuickTime 会录制画面
6. 点击停止按钮，保存视频

💡 **提示**：真机录制的画面更真实流畅，推荐使用真机录制预览视频。

### 视频编辑

| 工具 | 价格 | 难度 | 适合人群 |
|------|------|------|---------|
| **iMovie** | 免费（Mac 内置） | ⭐ | 零基础小白 |
| **剪映** | 免费 | ⭐ | 零基础小白，功能丰富 |
| **Final Cut Pro** | 付费 | ⭐⭐⭐ | 专业视频编辑 |
| **DaVinci Resolve** | 免费 | ⭐⭐⭐ | 专业视频编辑 |

#### 添加字幕和标注

1. 将录制好的视频导入编辑工具
2. 在关键操作处添加文字说明
3. 使用箭头或圆圈标注重点区域
4. 添加淡入淡出转场效果
5. 导出为 MP4 格式

💡 **提示**：预览视频是**静音自动播放**的，很多用户不会开声音。所以重要信息一定要用文字展示，不要只靠旁白！

## 截图美化

### 背景与边框

好的背景能让截图更有层次感和品牌感：

| 背景类型 | 效果 | 适合场景 | 制作难度 |
|----------|------|---------|---------|
| **纯色背景** | 简洁大方 | 极简风格 App | ⭐ |
| **渐变背景** | 时尚现代 | 大多数 App | ⭐⭐ |
| **图片背景** | 丰富有氛围 | 旅行/摄影类 App | ⭐⭐⭐ |
| **模糊背景** | 突出前景 | 社交/内容类 App | ⭐⭐ |

#### 纯色背景

```
┌─────────────────┐
│  ████████████    │  ← 纯色背景（品牌色）
│  ████ 标题 ████  │
│  ████████████    │
│  ┌───────────┐  │
│  │  App 截图  │  │
│  └───────────┘  │
│  ████████████    │
└─────────────────┘
```

#### 渐变背景

```
┌─────────────────┐
│  ░░░░░░░░░░░░    │  ← 渐变色背景
│  ░░ 标题 ░░░░    │     从上到下或从左到右
│  ░░░░░░░░░░░░    │
│  ┌───────────┐  │
│  │  App 截图  │  │
│  └───────────┘  │
│  ▓▓▓▓▓▓▓▓▓▓▓▓    │
└─────────────────┘
```

### 设备框

给截图加上 iPhone 设备框，能让用户更直观地感受到 App 在真实设备上的效果。

| 资源 | 网址 | 说明 |
|------|------|------|
| **Figma 设备框** | 搜索 "iPhone Mockup Figma" | 免费模板最多 |
| **Facebook Design** | facebook.com/design/devices | 官方设备框资源 |
| **Mockup World** | mockupworld.co | 高质量免费 Mockup |
| **Angle** | angled.io | 专为 App 截图设计 |

💡 **提示**：使用设备框时，确保框内的截图分辨率足够高，否则在 App Store 放大后会模糊。

### 文案排版

| 元素 | 规范 |
|------|------|
| **标题位置** | 截图上方 1/4 区域 |
| **副标题位置** | 标题下方，字号为标题的 60%-70% |
| **字体选择** | PingFang SC（中文）、SF Pro（英文） |
| **标题字号** | 截图宽度的 8%-12% |
| **行间距** | 标题字号的 120%-150% |
| **对齐方式** | 居中或左对齐，整套截图保持一致 |

#### 排版示例

```
方案 A：标题在上，截图在下（最常见）
┌─────────────────┐
│                  │
│   大标题文字     │  ← 粗体，大字号
│   副标题说明     │  ← 常规，小字号
│                  │
│  ┌───────────┐  │
│  │           │  │
│  │  App 截图  │  │
│  │           │  │
│  └───────────┘  │
└─────────────────┘

方案 B：标题在左，截图在右（横屏常用）
┌─────────────────────────┐
│           │              │
│  大标题   │              │
│  副标题   │  App 截图    │
│           │              │
│           │              │
└─────────────────────────┘
```

⚠️ **警告**：所有截图的排版风格必须保持一致！如果第一张是标题在上，后面的截图也要标题在上。不一致的排版会让你的 App 看起来很不专业。

## 小结

| 内容 | 关键要点 |
|------|---------|
| **截图尺寸** | 必需 6.7"（1290×2796）或 6.5"（1284×2778），推荐同时提供两种 |
| **截图数量** | 每种尺寸 3-10 张，第一张最重要 |
| **制作工具** | 模拟器截图（⌘+S）、fastlane Snapshot（批量）、Figma（美化） |
| **首屏策略** | 展示核心功能 + 简短有力的标题文案 |
| **预览视频** | 15-30 秒，静音自动播放，重要信息用文字展示 |
| **截图美化** | 渐变背景 + 设备框 + 统一排版 = 专业感 |
| **文案编写** | 5-8 字简短标题，突出价值，避免技术术语 |
