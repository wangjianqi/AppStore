## 一、App Icon 设计

### 1.1 Icon 设计原则

App Icon 是用户对你的第一印象，就像人的脸。记住三个核心原则：

| 原则 | 说明 | 生活类比 |
|------|------|----------|
| **简洁** | 元素不超过 3 个，避免细节过多 | 远看也能认出是哪个 App，就像麦当劳的 M |
| **辨识度** | 在一堆图标中能一眼找到 | 人群中穿红衣服的人最显眼 |
| **多尺寸适配** | 从 1024px 到 29px 都要清晰可辨 | 名片上和广告牌上的 Logo 都要好看 |

> ⚠️ 最常见的错误：在 1024x1024 的大图上看着很棒，缩小到手机桌面的 60px 时糊成一团。**设计时先画小尺寸，确认清晰后再放大。**

### 1.2 设计工具推荐

| 工具 | 适合人群 | 价格 | 特点 |
|------|----------|------|------|
| **Figma** | 有一定设计基础 | 免费（个人版） | 在线协作、插件丰富、模板多 |
| **Sketch** | Mac 用户 | $10/月 | 矢量设计、iOS 生态友好 |
| **Canva** | 零基础小白 | 免费（基础版） | 拖拽式、模板海量、上手极快 |
| **AI 生成** | 想快速出方案 | 按量付费 | 出图快、风格多样、需后期调整 |

> 💡 零基础推荐路线：Canva（熟悉基本操作）→ Figma（进阶设计）→ AI 辅助（提效）

### 1.3 用 AI 生成 App Icon 的完整流程

#### 第一步：确定设计方向

在写 Prompt 之前，先想清楚：

- App 是什么品类？（工具/社交/游戏/效率…）
- 目标用户是谁？（年轻人/商务人士/儿童…）
- 想传达什么感觉？（专业/活泼/温暖/科技…）

#### 第二步：编写 Prompt

以下是经过验证的 Prompt 模板：

**Midjourney Prompt 模板：**

```
A minimalist app icon for a [App类型] app, [核心图形描述], [配色方案], 
flat design, clean background, no text, iOS app icon style, 
centered composition, high contrast, --v 6 --ar 1:1
```

示例——天气 App：

```
A minimalist app icon for a weather app, a smiling sun with a small cloud, 
gradient blue sky background, flat design, clean background, no text, 
iOS app icon style, centered composition, high contrast, --v 6 --ar 1:1
```

**DALL-E Prompt 模板：**

```
Design an iOS app icon for a [App类型] application. 
The icon should feature [核心图形描述] in [配色方案] color scheme. 
Style: flat design, minimalist, no text, centered, 
suitable for App Store, professional quality.
```

**SDXL Prompt 模板：**

```
ios app icon, [核心图形描述], [配色方案], flat design, 
minimalist, centered, no text, clean, professional, 
simple shape, high contrast, 4k quality
```

> 💡 AI 生成 Icon 的关键技巧：
> 1. 一定要写 "no text"——AI 生成的文字通常是乱码
> 2. 一定要写 "flat design"——避免过于写实
> 3. 多生成几组（至少 4 组），挑选最好的
> 4. 选中后用 Figma 微调细节

#### 第三步：后期调整

AI 生成的图通常需要以下调整：

| 调整项 | 工具 | 说明 |
|--------|------|------|
| 去除多余元素 | Figma / Photoshop | AI 可能添加不需要的细节 |
| 统一圆角 | Figma | iOS Icon 自动圆角，但设计时要考虑 |
| 调整配色 | Figma / Skala | 确保与品牌色一致 |
| 导出多尺寸 | Figma / App Icon Generator | 见下方尺寸表 |

### 1.4 Icon 尺寸规格表

| 用途 | 尺寸（px） | 说明 |
|------|-----------|------|
| App Store（上传用） | 1024 x 1024 | 唯一需要上传到 App Store Connect 的尺寸 |
| iPhone 主屏幕 @3x | 180 x 180 | iPhone 12 及之后 |
| iPhone 主屏幕 @2x | 120 x 120 | iPhone SE 等旧机型 |
| iPhone 设置 @3x | 87 x 87 | 设置页面 |
| iPhone 设置 @2x | 58 x 58 | 设置页面 |
| iPhone 通知 @3x | 60 x 60 | 通知中心 |
| iPhone 通知 @2x | 40 x 40 | 通知中心 |
| iPad 主屏幕 @2x | 152 x 152 | iPad |
| iPad 设置 @2x | 76 x 76 | iPad 设置 |
| iPad 通知 @2x | 40 x 40 | iPad 通知 |
| App Store 搜索列表 | 60 x 60（@3x 显示） | 系统自动缩放 |

> 💡 实际操作中，你只需要准备 **1024 x 1024** 的一张图上传到 App Store Connect，Xcode 会自动生成其他尺寸。但设计时要检查小尺寸下的显示效果。

### 1.5 圆角裁切与安全区

iOS 会自动为 Icon 添加圆角（Superellipse 超椭圆），你不需要手动裁切。但需要注意**安全区**：

```
┌─────────────────────────┐
│  ┌───────────────────┐  │  ← 圆角区域（系统自动裁切）
│  │                   │  │
│  │    ┌─────────┐    │  │  ← 安全区（重要内容放这里）
│  │    │  核心图  │    │  │
│  │    │   形区   │    │  │
│  │    └─────────┘    │  │
│  │                   │  │
│  └───────────────────┘  │
│                         │
└─────────────────────────┘

安全区约为 Icon 尺寸的 80%（即中心 820x820 区域）
边缘 10% 可能被圆角裁切，不要放重要内容
```

> ⚠️ 常见错误：把文字或重要图形放在 Icon 边缘，结果被圆角裁掉一半。

### 1.6 Icon 审核常见被拒原因

| 被拒原因 | 具体表现 | 解决方案 |
|----------|----------|----------|
| **与系统 Icon 相似** | 模仿设置、相机等系统 App 的 Icon | 避免使用系统图标的配色和形状组合 |
| **包含误导性内容** | Icon 显示的功能 App 里没有 | Icon 要真实反映 App 功能 |
| **使用 Apple 商标** | 包含 Apple Logo、iPhone 外形等 | 严禁使用任何 Apple 受保护元素 |
| **文字过小** | Icon 上的文字在手机上看不清 | 尽量不用文字，用则字号要大 |
| **低分辨率** | 1024x1024 图模糊或有锯齿 | 确保导出时选择 @1x、矢量绘制 |
| **含价格信息** | Icon 上写"免费""$0.99"等 | App Store 禁止在 Icon 上标注价格 |
| **含评级/奖项** | 写"5星""编辑推荐"等 | 这些信息不允许出现在 Icon 上 |

### 1.7 Icon 设计检查清单

在提交前，逐项检查：

- [ ] 1024 x 1024 像素，PNG 格式，无透明通道
- [ ] 缩小到 60px 时核心图形仍然清晰可辨
- [ ] 重要内容在安全区内（中心 80%）
- [ ] 没有使用 Apple 商标或受保护元素
- [ ] 没有包含价格、评级、奖项文字
- [ ] Icon 真实反映了 App 的核心功能
- [ ] 配色与 App 内部风格一致
- [ ] 在浅色和深色壁纸上都好看
- [ ] 与同品类竞品的 Icon 有明显区分

## 二、App Store 截图设计

### 2.1 截图为什么是 ASO 转化的第一要素

> 💡 想象你在刷短视频，决定是否看完一个视频只需要 **0.3 秒**。App Store 也一样——用户决定是否下载你的 App，截图的影响力占 **70% 以上**。

数据说话：

| 因素 | 对下载决策的影响 | 你能控制吗？ |
|------|------------------|-------------|
| 截图 | 70%+ | ✅ 完全可控 |
| App 描述 | 10-15% | ✅ 可控 |
| 评分/评论 | 10-15% | ⚠️ 部分可控 |
| 标题/副标题 | 5-10% | ✅ 可控 |

截图是用户浏览 App Store 时**最先看到、最直观**的信息，比文字描述有力 10 倍。

### 2.2 截图规格要求

#### 三种必填尺寸

| 设备类型 | 分辨率（px） | 对应设备 | 是否必填 |
|----------|-------------|----------|----------|
| **6.7"** | 1290 x 2778 | iPhone 15 Pro Max / 14 Pro Max 等 | ✅ 必填 |
| **6.5"** | 1284 x 2778 | iPhone 15 Plus / 14 Plus 等 | ✅ 必填 |
| **5.5"** | 1242 x 2208 | iPhone 8 Plus 等 | ✅ 必填 |

> ⚠️ 6.7" 和 6.5" 的分辨率非常接近（仅差 6px 宽度），但 Apple 要求分别上传。最简单的做法是做 1290x2778 的设计，然后微调导出 1284x2778 版本。

#### 格式要求

| 项目 | 要求 |
|------|------|
| 格式 | PNG 或 JPEG |
| 色彩空间 | sRGB |
| 单张最大 | 8MB |
| 数量 | 最少 3 张，最多 10 张 |
| 方向 | 竖屏（推荐）或横屏 |

> 💡 推荐上传 **5-7 张**截图。太少展示不充分，太多用户不会翻到最后。前 3 张最重要。

### 2.3 截图设计原则

#### 原则一：第一张最重要

搜索结果页直接展示第一张截图，这是用户的第一印象：

```
┌──────────────────────────────┐
│  搜索结果页展示内容：          │
│                              │
│  [Icon]  App 标题             │
│         副标题               │
│  [截图1]  ★★★★★ 评分         │
│          价格                 │
│                              │
│  截图1 占据了最大的视觉面积    │
└──────────────────────────────┘
```

**第一张截图的设计公式：**

```
大标题（核心卖点）+ 设备截图 + 品牌色背景
```

#### 原则二：大标题 + 核心卖点 + 设备截图

每张截图的结构：

```
┌──────────────────────────┐
│                          │
│   ┌──────────────────┐   │
│   │                  │   │
│   │   大标题文字      │   │  ← 3-5 个字，核心卖点
│   │                  │   │
│   └──────────────────┘   │
│                          │
│   ┌──────────────────┐   │
│   │                  │   │
│   │                  │   │
│   │   iPhone 设备     │   │  ← App 界面截图
│   │   框架内截图      │   │
│   │                  │   │
│   │                  │   │
│   └──────────────────┘   │
│                          │
│   副标题/补充说明          │  ← 可选
│                          │
└──────────────────────────┘
```

#### 原则三：颜色与品牌一致

| 品类 | 推荐配色方向 | 示例 |
|------|-------------|------|
| 工具/效率 | 冷色调（蓝/紫/灰） | Things、Notion |
| 社交/娱乐 | 暖色调（橙/红/黄） | Instagram、TikTok |
| 健康/运动 | 绿色/蓝色 | Keep、Nike Run |
| 金融/商务 | 深蓝/深绿/金 | 支付宝、招商银行 |
| 教育/儿童 | 彩色/活泼 | Duolingo |

#### 原则四：文字要大

> ⚠️ 用户在手机上看截图时，文字的实际显示高度只有约 3-4mm。如果文字太小，用户根本看不清。

文字大小参考（6.7" 截图 1290x2778）：

| 元素 | 推荐字号（px） | 说明 |
|------|---------------|------|
| 主标题 | 120-160 px | 3-5 个字的核心卖点 |
| 副标题 | 60-80 px | 补充说明 |
| 功能标注 | 40-60 px | 界面上的标注文字 |

### 2.4 截图设计工具

| 工具 | 特点 | 价格 | 推荐度 |
|------|------|------|--------|
| **Figma + 模板** | 最灵活，设计师首选 | 免费 | ⭐⭐⭐⭐⭐ |

### 2.5 用 AI 辅助设计截图文案

截图上的文案直接影响转化率。用 AI 来帮你生成和优化文案：

**Prompt 模板：**

```
我正在为一款 [App类型] App 设计 App Store 截图。
App 的核心功能是：[功能1]、[功能2]、[功能3]。
目标用户是：[用户画像]。

请帮我生成 5 张截图的标题文案，要求：
1. 每个标题 3-5 个字，简洁有力
2. 突出用户痛点或使用场景
3. 有递进关系，从核心功能到附加功能
4. 风格：[专业/活泼/温暖]
```

**示例输出（天气 App）：**

| 截图序号 | 标题文案 | 对应功能 |
|----------|----------|----------|
| 1 | 精准到分钟 | 逐小时天气预报 |
| 2 | 出门不纠结 | 穿衣/带伞建议 |
| 3 | 降雨实时追踪 | 降水雷达图 |
| 4 | 空气质量早知道 | AQI 指数 |
| 5 | 你的天气管家 | 小组件/通知 |

### 2.6 截图 A/B 测试策略

> 💡 A/B 测试就像考试做选择题——不确定哪个好，就两个都试试，看哪个得分高。

App Store 原生不支持截图 A/B 测试，但可以通过以下方式实现：

| 方法 | 工具 | 说明 |
|------|------|------|
| **第三方 A/B 测试平台** | StoreMaven / SplitMetrics | 创建模拟页面，投放真实流量测试 |
| **版本更新轮换** | App Store Connect | 每次更新换一组截图，对比下载量变化 |
| **广告素材测试** | Apple Search Ads | 用不同截图做广告素材，看 CTR 差异 |

**A/B 测试要点：**

1. **每次只改一个变量**（标题/配色/布局），否则不知道哪个因素起作用
2. **测试时间至少 7 天**，覆盖工作日和周末
3. **样本量至少 1000 次展示**，数据才有统计意义
4. **关注核心指标**：页面转化率（浏览→下载）

### 2.7 截图审核常见被拒原因

| 被拒原因 | 具体表现 | 解决方案 |
|----------|----------|----------|
| **截图与实际不符** | 截图展示的功能 App 里没有 | 截图必须真实反映 App 功能 |
| **使用了 iPhone 外框但型号不对** | 6.7" 截图用了 iPhone X 的外框 | 设备框必须与截图尺寸匹配 |
| **包含价格信息** | 截图上写"免费""限时优惠" | 不允许在截图中标注价格 |
| **包含其他平台元素** | 出现 Android 状态栏、Windows 界面 | 截图必须是 iOS 界面 |
| **文字太小看不清** | 功能标注文字过小 | 增大文字，确保手机上可读 |
| **截图模糊** | 低分辨率截图 | 使用规定分辨率，导出 @1x |
| **包含真人面部** | 未经授权的人物照片 | 使用授权素材或插画 |
| **截图含无关内容** | 纯宣传图，没有 App 界面 | 必须包含真实的 App 界面 |

> ⚠️ Apple 越来越严格地审核截图真实性。截图中的 App 界面必须是真实截图，不能是设计稿或示意图。

## 三、App 预览视频制作

### 3.1 预览视频的价值

> 💡 如果说截图是"照片"，那预览视频就是"电影预告片"。好的预告片能让票房翻倍，好的预览视频能让下载量提升 20-40%。

| 指标 | 有预览视频 | 无预览视频 | 提升 |
|------|-----------|-----------|------|
| 页面停留时间 | 45 秒 | 20 秒 | +125% |
| 下载转化率 | 35% | 25% | +40% |
| 搜索结果点击率 | 12% | 8% | +50% |

### 3.2 视频规格要求

| 项目 | 要求 |
|------|------|
| 时长 | 15-30 秒 |
| 格式 | H.264（.m4v / .mp4 / .mov） |
| 分辨率 | 与对应截图尺寸一致 |
| 最大文件 | 500MB |
| 帧率 | 30fps |
| 音频 | AAC，可选（不推荐加背景音乐） |

各尺寸视频分辨率：

| 设备类型 | 视频分辨率（px） |
|----------|-----------------|
| 6.7" | 1290 x 2778 |
| 6.5" | 1284 x 2778 |
| 5.5" | 1242 x 2208 |

### 3.3 视频内容规划

> 💡 预览视频就像电梯演讲——你只有 30 秒，必须在前 3 秒抓住注意力。

**30 秒视频时间分配：**

```
0-3 秒   ┃ 开场钩子：展示最核心/最酷的功能
3-10 秒  ┃ 核心功能演示：2-3 个主要功能
10-20 秒 ┃ 使用场景：真实场景中的使用效果
20-28 秒 ┃ 附加亮点：独特功能或差异化
28-30 秒 ┃ 结尾：品牌 Logo / App 名称
```

**前 3 秒的关键性：**

- 搜索结果页自动静音播放前 3 秒
- 如果前 3 秒无聊，用户直接划走
- 前 3 秒不要放 Logo 动画，直接展示功能

### 3.4 录制方式

#### 方式一：Xcode 录制模拟器

最简单的方式，适合纯 UI 展示：

```bash
# 1. 启动模拟器
open -a Simulator

# 2. 选择目标设备（如 iPhone 15 Pro Max）
# 在 Simulator 菜单：File → Open Simulator → iOS 17 → iPhone 15 Pro Max

# 3. 运行 App
xcodebuild -scheme "YourApp" -destination 'platform=iOS Simulator,name=iPhone 15 Pro Max' build

# 4. 开始录制（在模拟器窗口中）
# 菜单：File → Record Screen（或快捷键 Cmd + R）

# 5. 操作 App 演示流程

# 6. 停止录制
# 菜单：File → Stop Recording
```

录制完成后，视频保存在桌面，格式为 `.mov`。

#### 方式二：QuickTime 录制真机

适合需要展示真实性能、动画效果的场景：

```
步骤：
1. 用数据线连接 iPhone 到 Mac
2. 打开 QuickTime Player
3. 菜单：文件 → 新建影片录制
4. 点击录制按钮旁的下拉箭头
5. 选择你的 iPhone 作为摄像头
6. 开始录制
7. 在 iPhone 上操作演示
8. 停止录制，保存文件
```

> 💡 真机录制的画面更真实，但需要额外裁切和调整分辨率。

#### 方式三：第三方工具

| 工具 | 平台 | 价格 | 特点 |

### 3.6 添加字幕和动效

预览视频默认静音播放，**字幕是必须的**：

```
字幕设计要点：
1. 字幕位置：画面下方 1/3 处（不遮挡 App 界面）
2. 字幕大小：占画面宽度的 60-80%
3. 字幕时长：每条字幕至少显示 2 秒
4. 字幕风格：白字 + 半透明黑色背景条
5. 动效：淡入淡出，不要花哨
```

**剪映添加字幕流程：**

```
1. 导入录制好的视频
2. 点击"文字" → "识别字幕"（自动生成）
3. 修正识别错误的文字
4. 调整字幕出现时间和位置
5. 选择字幕样式（白字+黑底条）
6. 导出视频
```

### 3.7 视频审核常见被拒原因

| 被拒原因 | 具体表现 | 解决方案 |
|----------|----------|----------|
| **非真实录制** | 用动画/PPT 代替真实操作 | 必须是 App 的真实操作录制 |
| **时长不符** | 少于 15 秒或超过 30 秒 | 严格控制在 15-30 秒 |
| **包含真人** | 出现手、脸等真人画面 | 只展示 App 界面 |
| **设备框不匹配** | 6.7" 视频用了旧设备框 | 设备框与尺寸对应 |
| **有无关内容** | 像广告片，没有 App 操作 | 必须以 App 操作演示为主 |
| **音频问题** | 背景音乐过大或无意义 | 建议不加音乐，或用极轻的背景音 |
| **包含其他平台** | 出现 Android 或网页界面 | 只展示 iOS 版本 |

### 3.8 各尺寸视频是否需要单独制作

> 💡 好消息：如果你只提供一种尺寸的视频，App Store 会自动缩放到其他尺寸。但自动缩放可能导致画面变形或模糊。

**推荐策略：**

| 策略 | 工作量 | 效果 | 推荐 |
|------|--------|------|------|
| 只做 6.7" 视频 | ⭐ | 其他尺寸自动缩放，可能模糊 | 适合快速上架 |
| 做 6.7" + 5.5" 两个 | ⭐⭐ | 覆盖主流尺寸 | ✅ 推荐 |
| 三个尺寸都做 | ⭐⭐⭐ | 最佳效果 | 适合大团队 |

## 六、格式问题速查表

### 6.1 所有素材格式/尺寸/大小要求汇总

| 素材类型 | 尺寸（px） | 格式 | 最大大小 | 数量 | 其他要求 |
|----------|-----------|------|----------|------|----------|
| App Icon | 1024 x 1024 | PNG | - | 1 | 无透明通道、无圆角 |
| 截图 6.7" | 1290 x 2778 | PNG/JPEG | 8MB/张 | 3-10 | 竖屏或横屏 |
| 截图 6.5" | 1284 x 2778 | PNG/JPEG | 8MB/张 | 3-10 | 竖屏或横屏 |
| 截图 5.5" | 1242 x 2208 | PNG/JPEG | 8MB/张 | 3-10 | 竖屏或横屏 |
| 预览视频 6.7" | 1290 x 2778 | M4V/MP4/MOV | 500MB | 0-3 | 15-30秒，H.264 |
| 预览视频 6.5" | 1284 x 2778 | M4V/MP4/MOV | 500MB | 0-3 | 15-30秒，H.264 |
| 预览视频 5.5" | 1242 x 2208 | M4V/MP4/MOV | 500MB | 0-3 | 15-30秒，H.264 |

### 6.2 常见格式错误与解决方案

| 错误 | 报错信息/表现 | 原因 | 解决方案 |
|------|--------------|------|----------|
| **Icon 有透明通道** | 上传被拒 | PNG 包含 Alpha 通道 | 导出时取消透明通道，或用纯白背景 |
| **截图分辨率不对** | "Invalid screenshot size" | 像素差了 1px 都不行 | 严格按规格表导出 |
| **截图超过 8MB** | 上传失败 | PNG 未压缩 | 用 TinyPNG 压缩，或转 JPEG |
| **视频格式不对** | "Invalid video format" | 用了 HEVC 等非 H.264 | 重新导出为 H.264 |
| **视频超过 30 秒** | 上传被拒 | 多了 0.5 秒也不行 | 精确裁剪到 30 秒内 |
| **视频超过 500MB** | 上传失败 | 码率过高 | 降低码率，目标 10-20Mbps |
| **6.7" 和 6.5" 截图一样** | 审核通过但显示异常 | Apple 要求不同文件 | 至少微调后分别上传 |
| **截图方向不一致** | 审核被拒 | 有的竖屏有的横屏 | 所有截图保持同一方向 |
| **视频帧率不是 30fps** | 部分设备播放异常 | 用了 60fps 录制 | 剪辑时设置为 30fps |
| **色彩空间不是 sRGB** | 颜色偏色 | 用了 Display P3 | 导出时选择 sRGB |

> ⚠️ 最容易被忽略的问题：**6.7" 和 6.5" 截图必须分别上传不同文件**，即使它们看起来几乎一样。直接上传相同文件会被 App Store Connect 拒绝。

## 小结

本章我们学习了 App Store 视觉素材设计的完整知识体系：

1. **App Icon 设计**：遵循简洁、辨识度、多尺寸适配三大原则，用 AI + Figma 的组合快速出图，注意安全区和审核规范

2. **截图设计**：截图是 ASO 转化的第一要素，第一张截图最重要，大标题 + 核心卖点 + 设备截图是万能公式

3. **预览视频**：15-30 秒，前 3 秒定生死，静音播放必须加字幕，Xcode 录制 + 剪映剪辑是最简工具链

4. **ASO 视觉优化**：理解搜索结果页和详情页的浏览路径，通过竞品分析找到视觉差异化机会

5. **实战流程**：Icon → 截图 → 视频，AI 辅助 + 专业工具，一个人也能完成全套视觉素材

> 💡 记住：视觉素材不是"锦上添花"，而是"生死攸关"。在 App Store 这个货架上，包装决定了用户是否愿意拿起你的产品。花在设计上的每一分钟，都会在下载量上得到回报。
