# 免费部署平台实战

## 本章目标

读完本章后，你将能够：

- 理解为什么 iOS 上架需要部署平台，以及它和 App Store 审核的关系
- 对比主流免费部署平台的优缺点，选出最适合自己的方案
- 动手完成 GitHub Pages、Cloudflare Pages、Vercel、Supabase 的实战部署
- 用一个完整的 HTML 模板，一键部署隐私政策 + Support + Landing Page
- 掌握自定义域名绑定和 DNS 配置的全流程

## 1. 为什么需要部署平台

### 1.1 App Store 审核的硬性要求

把 App 提交到 App Store 时，Apple 会检查你是否提供了以下 URL：

| 必需 URL | 用途 | 不提供的后果 |
|---|---|---|
| 隐私政策 URL | 说明 App 如何收集、使用用户数据 | **直接拒审** |
| Support URL | 用户遇到问题时联系你的入口 | **直接拒审** |
| Marketing URL（可选） | App 的宣传落地页 | 不影响审核，但建议提供 |

> 💡 **生活类比**：开一家实体店，隐私政策就像门口贴的"监控提示"，Support URL 就像店里的"客服台"，Landing Page 就像店外的"广告招牌"。Apple 要求你必须有"监控提示"和"客服台"，否则不让开业。

### 1.2 这些 URL 必须是可访问的

Apple 的审核机器人会实际访问你填写的 URL。如果：

- URL 打不开 → 拒审
- 内容是空页面 → 拒审
- 内容和 App 无关 → 拒审
- 没有 HTTPS → 可能拒审

所以你需要一个**稳定、免费、支持 HTTPS** 的地方来托管这些页面——这就是部署平台的作用。

### 1.3 部署平台能帮你做什么

```
你写的 HTML/CSS/JS 文件
        ↓
   部署平台（自动处理）
        ↓
  ┌─────────────────────┐
  │ 1. 分配 HTTPS 域名   │
  │ 2. 全球 CDN 加速     │
  │ 3. 自动部署更新      │
  │ 4. 自定义域名绑定    │
  └─────────────────────┘
        ↓
  Apple 审核员可以访问 ✅
```

## 3. GitHub Pages 实战

GitHub Pages 是最简单的免费部署方案，适合托管隐私政策、Support 页面等静态内容。

> 💡 **生活类比**：GitHub Pages 就像一个免费的"展示柜"，你把做好的页面放进去，它自动帮你摆到橱窗里，全世界都能看到。

### 3.1 创建仓库

1. 打开 [github.com](https://github.com)，登录你的账号
2. 点击右上角 **+** → **New repository**
3. 填写仓库信息：

| 字段 | 填写内容 | 说明 |
|---|---|---|
| Repository name | `my-app-pages` | 任意名称即可 |
| Description | `App 隐私政策与支持页面` | 可选 |
| Visibility | **Public** | Pages 免费版需要公开仓库 |
| Initialize with README | ✅ 勾选 | 方便后续操作 |

4. 点击 **Create repository**

### 3.2 项目结构

在本地创建以下文件结构：

```
my-app-pages/
├── index.html          # Landing Page
├── privacy-policy.html # 隐私政策
├── support.html        # Support 页面
├── css/
│   └── style.css       # 样式文件
└── README.md
```

### 3.4 配置 GitHub Pages

1. 进入仓库页面，点击 **Settings**
2. 左侧菜单找到 **Pages**
3. 配置如下：

| 配置项 | 选择 |
|---|---|
| Source | **Deploy from a branch** |
| Branch | `main` |
| Folder | `/ (root)` |

4. 点击 **Save**
5. 等待 1-2 分钟，页面顶部会显示：

```
Your site is live at https://yourusername.github.io/my-app-pages/
```

### 3.5 推送代码到 GitHub

```bash
# 克隆仓库
git clone https://github.com/yourusername/my-app-pages.git
cd my-app-pages

# 复制你创建的 HTML 文件到目录中
# ...

# 提交并推送
git add .
git commit -m "Add privacy policy and support pages"
git push origin main
```

> ⚠️ **注意**：推送后需要等待 1-2 分钟，GitHub Pages 才会完成构建和部署。你可以在仓库的 **Actions** 标签页查看部署进度。

### 3.6 自定义域名绑定

如果你有自己的域名（如 `myapp.com`），可以绑定到 GitHub Pages：

**步骤一：在 GitHub 配置自定义域名**

1. 进入仓库 **Settings** → **Pages**
2. 在 **Custom domain** 输入你的域名，如 `pages.myapp.com`
3. 勾选 **Enforce HTTPS**
4. 点击 **Save**

**步骤二：在域名服务商配置 DNS**

| 记录类型 | 名称 | 值 |
|---|---|---|
| CNAME | pages | yourusername.github.io |

**步骤三：等待 DNS 生效**

DNS 生效通常需要几分钟到 48 小时。你可以用以下命令检查：

```bash
dig pages.myapp.com
```

> 💡 **提示**：GitHub Pages 会自动在仓库根目录创建一个 `CNAME` 文件，内容为你的自定义域名。不要删除这个文件，否则域名绑定会失效。

## 4. Cloudflare Pages 实战

Cloudflare Pages 拥有全球最多的 CDN 节点，部署速度极快，还支持 Workers 做 API 代理。

> 💡 **生活类比**：Cloudflare 就像一个全球连锁的"快递站"，你的页面被复制到世界各地的快递站，用户访问时从最近的站点取货，速度飞快。

### 4.1 注册与配置

1. 打开 [dash.cloudflare.com](https://dash.cloudflare.com)，注册账号
2. 登录后，左侧菜单选择 **Workers & Pages**
3. 点击 **Create application** → **Pages** 标签

### 4.2 连接 GitHub 仓库

1. 选择 **Connect to Git**
2. 授权 Cloudflare 访问你的 GitHub 账号
3. 选择你要部署的仓库（如 `my-app-pages`）
4. 配置构建设置：

| 配置项 | 值 |
|---|---|
| Production branch | `main` |
| Build command | 留空（纯静态页面） |
| Build output directory | `/` |

5. 点击 **Save and Deploy**
6. 等待部署完成（通常 30 秒以内）

部署成功后，你会得到一个 URL：

```
https://my-app-pages.pages.dev
```

### 4.4 Workers 基础（API 代理）

如果你的 App 需要调用第三方 API，但不想暴露 API Key，可以用 Cloudflare Workers 做代理：

1. 在 Cloudflare Dashboard，进入 **Workers & Pages**
2. 点击 **Create application** → **Worker**
3. 编写代理代码：

```javascript
export default {
  async fetch(request) {
    const url = new URL(request.url);
    const targetUrl = `https://api.example.com${url.pathname}`;

    const response = await fetch(targetUrl, {
      headers: {
        'Authorization': `Bearer ${API_KEY}`,
        'Content-Type': 'application/json',
      },
    });

    const data = await response.json();

    return new Response(JSON.stringify(data), {
      headers: {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*',
      },
    });
  },
};
```

4. 在 **Settings** → **Variables** 中添加 `API_KEY` 环境变量
5. 部署后，你的 Worker URL 类似：`https://my-api-proxy.your-subdomain.workers.dev`

> ⚠️ **注意**：Workers 免费版每天有 100,000 次请求限制，对于个人 App 来说完全够用。

### 5.2 环境变量配置

如果你的项目需要环境变量（如 API Key）：

1. 在 Vercel Dashboard 进入项目
2. **Settings** → **Environment Variables**
3. 添加变量：

| Key | Value | Environment |
|---|---|---|
| `NEXT_PUBLIC_APP_NAME` | MyApp | Production, Preview, Development |
| `API_SECRET_KEY` | your-secret-key | Production only |

4. 在代码中使用：

```tsx
const appName = process.env.NEXT_PUBLIC_APP_NAME;
```

> ⚠️ **注意**：只有以 `NEXT_PUBLIC_` 开头的环境变量才会暴露到浏览器端。不要把密钥放在 `NEXT_PUBLIC_` 变量中。

### 5.3 自定义域名

1. 在 Vercel Dashboard 进入项目
2. **Settings** → **Domains**
3. 输入你的域名，如 `myapp.com`
4. 按照提示在你的域名服务商添加 DNS 记录：

| 记录类型 | 名称 | 值 |
|---|---|---|
| A | @ | 76.76.21.21 |
| CNAME | www | cname.vercel-dns.com |

5. 等待 DNS 生效，Vercel 会自动配置 HTTPS

## 6. Supabase 实战

Supabase 是 Firebase 的开源替代品，提供 PostgreSQL 数据库、用户认证、文件存储和实时功能，免费额度对个人开发者非常友好。

> 💡 **生活类比**：Supabase 就像一个"全能管家"，数据库、用户登录、文件存储它全包了，你不需要自己搭建后端服务器。

### 6.1 创建项目

1. 打开 [supabase.com](https://supabase.com)，注册账号
2. 点击 **New Project**
3. 填写项目信息：

| 字段 | 填写内容 |
|---|---|
| Project name | my-app |
| Database Password | 设置一个强密码并保存好 |

### 6.2 数据库表设计

进入项目后，点击左侧 **SQL Editor**，执行以下 SQL：

```sql
-- 创建用户资料表
CREATE TABLE profiles (
    id UUID REFERENCES auth.users ON DELETE CASCADE PRIMARY KEY,
    username TEXT UNIQUE NOT NULL,
    avatar_url TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 设置行级安全策略（RLS）
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;

-- 用户只能查看和修改自己的资料
CREATE POLICY "Users can view own profile"
    ON profiles FOR SELECT
    USING (auth.uid() = id);

CREATE POLICY "Users can update own profile"
    ON profiles FOR UPDATE
    USING (auth.uid() = id);

-- 创建任务表（示例）
CREATE TABLE tasks (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    user_id UUID REFERENCES auth.users ON DELETE CASCADE NOT NULL,
    title TEXT NOT NULL,
    completed BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE tasks ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own tasks"
    ON tasks FOR SELECT
    USING (auth.uid() = user_id);

CREATE POLICY "Users can create own tasks"
    ON tasks FOR INSERT
    WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own tasks"
    ON tasks FOR UPDATE
    USING (auth.uid() = user_id);

CREATE POLICY "Users can delete own tasks"
    ON tasks FOR DELETE
    USING (auth.uid() = user_id);
```

> ⚠️ **重要**：一定要启用 Row Level Security（RLS），否则任何人都可以读写你的数据库！

        case createdAt = "created_at"

func fetchTasks() async throws -> [Task] {

        .from("tasks")

## 8. 自定义域名

拥有自己的域名看起来更专业，也更容易通过审核。

### 8.1 购买域名

推荐域名注册商：

| 注册商 | 优势 | .com 域名价格（约） |
|---|---|---|
| Cloudflare Registrar | 成本价，无加价 | ~$10/年 |
| Namecheap | 价格实惠，界面友好 | ~$9/年 |
| Google Domains | 简洁好用 | ~$12/年 |
| 阿里云 | 国内访问快 | ~$55/年 |

> 💡 **选择建议**：如果用户主要在国内，选阿里云；如果用户在全球，选 Cloudflare 或 Namecheap。

### 8.2 DNS 配置

以将 `pages.myapp.com` 指向 GitHub Pages 为例：

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 在域名注册商添加 CNAME 记录 | 名称：`pages`，值：`yourusername.github.io` |
| 2 | 在 GitHub 仓库 Settings → Pages 填写自定义域名 | 输入 `pages.myapp.com` |
| 3 | 勾选 Enforce HTTPS | 确保全站 HTTPS |
| 4 | 等待 DNS 生效 | 通常 5-30 分钟 |

不同平台的 DNS 配置：

| 平台 | 记录类型 | 名称 | 值 |
|---|---|---|---|
| GitHub Pages | CNAME | 子域名 | `yourusername.github.io` |
| Cloudflare Pages | CNAME | 子域名 | `your-project.pages.dev` |
| Vercel | A | @ | `76.76.21.21` |
| Vercel | CNAME | www | `cname.vercel-dns.com` |
| Netlify | CNAME | 子域名 | `your-site.netlify.app` |

### 8.3 HTTPS 配置

所有主流部署平台都**自动提供免费的 HTTPS 证书**：

| 平台 | 证书提供商 | 是否需要手动配置 |
|---|---|---|
| GitHub Pages | Let's Encrypt | ❌ 自动 |
| Cloudflare Pages | Cloudflare Universal SSL | ❌ 自动 |
| Vercel | Let's Encrypt | ❌ 自动 |
| Netlify | Let's Encrypt | ❌ 自动 |

> ⚠️ **注意**：绑定自定义域名后，一定要在平台设置中开启 **Enforce HTTPS**（强制 HTTPS），否则用户访问 HTTP 版本时数据可能不安全。

### 9.2 页面性能

快速加载的页面给用户和审核员更好的体验：

| 优化手段 | 说明 | 效果 |
|---|---|---|
| 压缩图片 | 使用 TinyPNG 等工具 | 减少 50-80% 图片大小 |
| 使用 WebP 格式 | 替代 PNG/JPG | 减少 25-35% 大小 |
| 内联关键 CSS | 首屏样式直接写在 HTML 中 | 消除渲染阻塞 |
| 延迟加载图片 | `loading="lazy"` 属性 | 减少首屏加载量 |
| 最小化 CSS/JS | 去除空格和注释 | 减少 20-30% 文件大小 |

```html
<img src="screenshot.webp" alt="MyApp 截图" loading="lazy" width="390" height="844">
```

> 💡 **性能检测工具**：用 [PageSpeed Insights](https://pagespeed.web.dev/) 测试你的页面，目标是移动端得分 > 90。

### 9.3 多语言页面

如果你的 App 支持多语言，页面也应该提供对应语言版本：

**方案一：单页面内切换语言**

```html
<select id="lang-switch" onchange="switchLang(this.value)">
    <option value="zh">中文</option>
    <option value="en">English</option>
    <option value="ja">日本語</option>
</select>

<h1>
    <span data-lang="zh">让生活更简单</span>
    <span data-lang="en" style="display:none">Make Life Simpler</span>
    <span data-lang="ja" style="display:none">生活をもっとシンプルに</span>
</h1>

<script>
function switchLang(lang) {
    document.querySelectorAll('[data-lang]').forEach(el => {
        el.style.display = el.dataset.lang === lang ? '' : 'none';
    });
}
</script>
```

**方案二：多页面方案**

```
/
├── index.html          # 默认（中文）
├── en/
│   └── index.html      # 英文版
└── ja/
    └── index.html      # 日文版
```

在 `<head>` 中添加语言替代链接：

```html
<link rel="alternate" hreflang="zh" href="https://myapp.com/">
<link rel="alternate" hreflang="en" href="https://myapp.com/en/">
<link rel="alternate" hreflang="ja" href="https://myapp.com/ja/">
<link rel="alternate" hreflang="x-default" href="https://myapp.com/">
```

> ⚠️ **App Store 要求**：如果你的 App 在多个地区上架，隐私政策和支持页面需要提供对应语言版本，或者至少提供英文版本。

## 小结

本章我们学习了：

| 内容 | 关键要点 |
|---|---|
| 为什么需要部署平台 | App Store 审核要求隐私政策和支持页面必须有可访问的 URL |
| 平台对比 | GitHub Pages 最简单、Cloudflare 全球最快、Vercel 最适合 Next.js、Supabase 提供后端能力 |
| GitHub Pages 实战 | 创建仓库 → 推送 HTML → 启用 Pages → 自动部署 |
| Cloudflare Pages 实战 | 连接 GitHub → 自动构建 → Workers 做 API 代理 |
| Vercel 实战 | 部署 Next.js 项目 → 配置环境变量 → 绑定域名 |
| Supabase 实战 | 创建数据库表 → 配置认证 → Swift SDK 集成到 iOS App |
| 完整实战 | 一个 HTML 模板搞定隐私政策 + Support + Landing Page |
| 自定义域名 | 购买域名 → 配置 DNS → 启用 HTTPS |
| 最佳实践 | SEO 优化、性能提升、多语言支持 |

> 💡 **新手推荐路线**：
> 1. 先用 **GitHub Pages** 部署隐私政策和 Support 页面（最快搞定审核）
> 2. 再用 **Cloudflare Pages** 部署更精美的 Landing Page
> 3. 需要后端时再引入 **Supabase**
> 4. 等有预算了再考虑自定义域名
