# 附录 E：国内上架合规清单

> 📖 本附录整理了在中国大陆上架 App 所需的合规要求，以清单形式呈现，方便逐项检查。
>
> ⚠️ 注意：国内合规要求更新频繁，请以最新法规为准。本清单最后更新于 2025 年，建议提交前再次核实。

---

## 清单使用说明

| 符号 | 含义 |
|------|------|
| ☐ | 待完成，需要你去做 |
| ✅ | 已完成，可以打勾确认 |
| ⭐ | 高优先级，不完成可能导致上架失败 |
| 📌 | 需要特别注意的项 |

> 💡 建议做法：打印本清单或复制到笔记 App 中，每完成一项就打勾，确保不遗漏。

## ICP 备案

ICP 备案是国内上架的**硬性前提**。没有备案号，App 无法在国内应用商店上架，Apple 也可能因合规问题拒绝审核。

### 域名准备

- [ ] 域名已注册
  - 选择可靠的域名注册商（如阿里云、腾讯云）
  - 建议使用 `.cn` 或 `.com` 域名
  - 域名主体需与备案主体一致

- [ ] 域名已完成实名认证
  - 在域名注册商处完成实名认证
  - 个人备案用身份证，企业备案用营业执照
  - 实名认证通常需要 1-3 个工作日

- [ ] 域名证书已下载
  - 从域名注册商下载域名证书
  - 备案时需要上传域名证书

### 服务器准备

- [ ] 国内云服务器已准备
  - 必须使用中国大陆境内的服务器
  - 推荐阿里云、腾讯云、华为云等
  - 境外服务器（如 AWS 海外节点）无法备案

- [ ] 服务器已完成备案
  - 服务器需与域名一起备案
  - 云服务商通常提供免费备案服务

### 备案申请

- [ ] 营业执照/身份证已准备
  - 企业：营业执照扫描件
  - 个人：身份证正反面扫描件
  - 法人身份证扫描件（企业备案）

- [ ] 备案申请已提交
  - 通过云服务商的备案系统提交
  - 填写网站/App 信息、主体信息、负责人信息
  - 上传所需材料

- [ ] 备案审核已通过
  - 初审：云服务商审核（1-3 个工作日）
  - 复审：管局审核（5-20 个工作日）
  - 审核期间保持电话畅通，管局可能电话核实

- [ ] 备案号已获取
  - 审核通过后会收到备案号
  - 格式如：京ICP备XXXXXXXX号

### 备案号展示

- [ ] ⭐ App 内已展示备案号
  - 在 App 的"关于"或"设置"页面展示备案号
  - 这是国内法规的硬性要求

- [ ] ⭐ 备案号链接到工信部查询页
  - 备案号需可点击，跳转到工信部备案查询页面
  - 查询地址：`https://beian.miit.gov.cn/`

> 📌 备案常见问题：
> - 备案期间网站不能访问（需关闭或设置"备案中"页面）
> - 备案主体变更需要重新备案
> - 备案信息变更需及时更新
> - App 备案和网站备案可以合并办理

## 隐私合规

隐私合规是国内监管的**重点领域**，违规可能面临下架甚至罚款。

### 隐私政策

- [ ] ⭐ 隐私政策已编写
  - 必须有独立的隐私政策文档
  - 隐私政策需放在可公开访问的网页上
  - 隐私政策链接需在 App Store Connect 中填写

- [ ] ⭐ 隐私政策包含所有必要内容

  隐私政策必须包含以下内容：

  | 必要内容 | 说明 |
  |---------|------|
  | 收集的信息类型 | 列出所有收集的用户信息（如设备ID、位置、通讯录等） |
  | 收集目的 | 说明每种信息的收集目的 |
  | 使用方式 | 说明信息如何被使用 |
  | 共享情况 | 是否与第三方共享，共享给谁 |
  | 存储方式 | 信息存储在哪里、存储多久 |
  | 安全措施 | 采取了哪些安全保护措施 |
  | 用户权利 | 用户如何查看、修改、删除个人信息 |
  | 未成年人保护 | 如适用，说明如何保护未成年人信息 |
  | 第三方SDK | 列出所有第三方SDK及其收集的信息 |
  | 联系方式 | 提供开发者联系方式 |

- [ ] ⭐ 首次启动展示隐私政策弹窗
  - App 首次启动时必须弹出隐私政策
  - 弹窗必须包含"同意"和"不同意"两个选项
  - 用户点击"不同意"应退出 App 或进入非数据收集模式
  - 弹窗内容需清晰可读，字号不能过小

### 数据收集规范

- [ ] ⭐ 用户同意后才收集数据
  - 不得在用户同意前收集任何个人信息
  - 不得以"不同意就不能用"的方式强制同意（核心功能除外）
  - 应提供分项同意选项（如"位置信息""通讯录"分别同意）

- [ ] 数据收集已声明（App Privacy 营养标签）
  - 在 App Store Connect 中填写 App Privacy
  - 如实声明所有收集的数据类型
  - 数据类型与实际收集行为一致

### 权限规范

- [ ] 权限使用已说明（Info.plist）
  - 每个请求的权限都必须在 Info.plist 中说明用途
  - 说明文字要具体，不能只写"需要此权限"

  | 权限 | ❌ 错误写法 | ✅ 正确写法 |
  |------|-----------|-----------|
  | 相机 | "需要访问相机" | "用于拍摄头像和扫描二维码" |
  | 位置 | "需要获取位置" | "用于为您推荐附近的商家" |
  | 通讯录 | "需要访问通讯录" | "用于查找已在App中的好友" |
  | 相册 | "需要访问相册" | "用于选择和上传个人头像" |

- [ ] 权限描述清晰准确
  - 说明文字必须与实际用途一致
  - 不能申请与功能无关的权限

- [ ] 未使用的权限已移除
  - 检查 Info.plist，移除不需要的权限声明
  - 第三方 SDK 引入的权限也要检查

### 第三方 SDK 合规

- [ ] 第三方 SDK 隐私政策已链接
  - 在隐私政策中列出所有第三方 SDK
  - 说明每个 SDK 收集了哪些信息
  - 提供第三方 SDK 的隐私政策链接

- [ ] 第三方 SDK 已在隐私政策中声明

  常见需要声明的 SDK：

  | SDK 类型 | 举例 | 收集的信息 |
  |---------|------|-----------|
  | 统计分析 | 友盟、神策 | 设备信息、使用行为 |
  | 崩溃收集 | Bugly、Crashlytics | 设备信息、崩溃日志 |
  | 推送服务 | 极光推送、个推 | 设备Token、设备信息 |
  | 广告平台 | 穿山甲、优量汇 | 设备信息、广告标识符 |
  | 地图服务 | 高德地图、百度地图 | 位置信息 |
  | 支付服务 | 微信支付、支付宝 | 订单信息 |

### 用户数据权利

- [ ] ⭐ 用户可以删除账号和数据
  - 必须提供账号删除功能
  - 删除后所有相关数据必须彻底清除
  - 删除功能入口要明显，不能藏在深层
  - Apple 审核也会检查此功能

## 内容合规

内容合规是国内监管的红线，违反可能导致 App 被下架，开发者承担法律责任。

### 基本内容要求

- [ ] ⭐ 无违法违规内容
  - 不包含任何违反中国法律法规的内容
  - 不包含赌博相关内容
  - 不包含非法集资、传销等内容

- [ ] ⭐ 无政治敏感内容
  - 不包含危害国家安全的内容
  - 不包含破坏民族团结的内容
  - 不包含颠覆国家政权的内容

- [ ] ⭐ 无色情暴力内容
  - 不包含色情、淫秽内容
  - 不包含过度暴力的内容
  - 不包含教唆犯罪的内容

### 用户生成内容（UGC）管理

- [ ] ⭐ 用户生成内容有审核机制
  - 发布前审核或发布后即时审核
  - 配备足够的内容审核人员
  - 建立审核标准和流程

- [ ] ⭐ 举报功能已实现
  - 用户可以举报不当内容
  - 举报入口要显眼
  - 举报后需及时处理

- [ ] 内容过滤已实现
  - 图片过滤：识别色情、暴力图片
  - 视频过滤：识别违规视频内容
  - 可使用第三方内容审核服务（如阿里云内容安全、腾讯云天御）

- [ ] ⭐ 敏感词过滤已实现
  - 建立敏感词库，定期更新
  - 对用户输入的文字进行实时过滤
  - 敏感词库应包含政治、色情、暴力等类别

- [ ] 评论审核机制已实现
  - 评论发布前审核，或发布后自动过滤 + 人工复核
  - 违规评论及时删除
  - 违规用户及时封禁

> 📌 内容合规建议：
> - 建议使用第三方内容审核服务，比自己建词库更全面
> - 保留审核日志，以备监管部门检查
> - 定期审查和更新审核标准

## 支付合规

支付合规需要同时满足 Apple 的 IAP 规则和国内法规要求。

### Apple IAP 合规

- [ ] ⭐ 虚拟商品使用 IAP
  - 所有虚拟商品（金币、会员、电子书等）必须通过 IAP 购买
  - 不得引导用户到网页或其他渠道购买虚拟商品
  - 详见附录 D 的 3.1 条款

- [ ] IAP 产品已正确配置

  | IAP 类型 | 适用场景 | 举例 |
  |---------|---------|------|
  | 消耗型 | 用完即消失的虚拟物品 | 游戏金币、钻石 |
  | 非消耗型 | 一次购买永久拥有 | 去广告、解锁功能 |
  | 自动续期订阅 | 按周期自动扣费 | 月度会员、年度会员 |
  | 非续期订阅 | 限时订阅，不自动续费 | 季度会员 |

- [ ] 订阅说明清晰
  - 明确说明订阅内容、价格、续费周期
  - 免费试用需说明试用时长和后续费用
  - 退款政策需说明

### 国内法规合规

- [ ] 价格符合国内法规
  - 定价需合理，不得存在价格欺诈
  - 自动续费需提前 5 日通知用户
  - 用户有权随时取消自动续费

- [ ] ⭐ 未引导用户绕过 IAP
  - App 内不得出现"去网页购买更便宜"等引导
  - 不得在 App 内展示外部支付链接
  - 客服也不得引导用户到外部购买

- [ ] 退款政策已说明
  - 在 App 内展示退款政策
  - 说明退款条件和流程
  - 遵守 Apple 的退款政策

## 数据安全

数据安全是近年来国内监管的重点，相关法规包括《数据安全法》《个人信息保护法》等。

### 数据存储安全

- [ ] ⭐ 用户数据加密存储
  - 密码使用 bcrypt/Argon2 等算法加密
  - 敏感信息（身份证号、银行卡号）加密存储
  - iOS 本地敏感数据使用 Keychain 存储

- [ ] ⭐ 网络传输使用 HTTPS
  - 所有网络请求必须使用 HTTPS
  - 不允许 HTTP 明文传输
  - 在 Info.plist 中设置 `NSAllowsArbitraryLoads = NO`

### 日志安全

- [ ] 敏感信息不记录日志
  - 密码、Token 不写入日志
  - 身份证号、银行卡号不写入日志
  - 日志文件设置自动清理

### 数据备份

- [ ] 数据备份机制已实现
  - 用户数据定期备份
  - 备份数据加密存储
  - 备份恢复功能可用

### 应急预案

- [ ] 数据泄露应急预案已准备
  - 制定数据泄露应急响应流程
  - 明确责任人和联系方式
  - 定期演练应急预案

> 📌 数据安全法规要点：
> - 《个人信息保护法》：收集个人信息需获得用户明确同意
> - 《数据安全法》：对数据进行分类分级保护
> - 《网络安全法》：网络运营者需保障数据安全

## 其他合规

### 适龄分级

- [ ] App 适龄分级正确
  - 在 App Store Connect 中正确设置年龄分级
  - 分级需与 App 实际内容匹配

  | 分级 | 适用内容 |
  |------|---------|
  | 4+ | 无任何限制内容 |
  | 9+ | 偶尔轻微卡通暴力 |
  | 12+ | 轻微暴力、偶尔恐怖主题 |
  | 17+ | 频繁暴力、色情内容、真实赌博 |

### 特殊行业资质

- [ ] 特殊行业资质已获取（如需要）

  需要特殊资质的行业：

  | 行业 | 所需资质 | 发证机关 |
  |------|---------|---------|
  | 金融/借贷 | 金融牌照 | 银保监会/证监会 |
  | 医疗健康 | 互联网医疗资质 | 卫健委 |
  | 新闻资讯 | 互联网新闻信息服务许可 | 网信办 |
  | 网络出版 | 网络出版服务许可 | 新闻出版署 |
  | 网络视听 | 信息网络传播视听节目许可 | 广电总局 |
  | 在线教育 | 办学许可证（部分） | 教育局 |
  | 地图导航 | 测绘资质 | 自然资源部 |

- [ ] 数据安全评估已完成（如需要）
  - 处理个人信息超过 100 万人的需进行数据安全评估
  - 向境外提供个人信息的需进行安全评估
  - 评估需向省级网信部门申报

- [ ] 网络安全等级保护（如需要）
  - 信息系统需进行等级保护备案
  - 一般 App 为二级等保
  - 金融、医疗等敏感行业可能需要三级等保

### 其他检查项

- [ ] App 签名未被篡改
  - 确保使用正确的开发者证书签名
  - 不使用任何绕过签名验证的方式

- [ ] 第三方 SDK 已更新到最新版
  - 使用最新版 SDK 确保安全漏洞已修复
  - 关注 SDK 的安全公告和更新日志

- [ ] 已阅读 Apple 审核指南
  - 通读 Apple 官方审核指南
  - 重点关注与本 App 相关的条款
  - 参考附录 D 的精要解读

- [ ] 已阅读国内相关法规

  建议阅读的法规：

  | 法规名称 | 关注重点 |
  |---------|---------|
  | 《个人信息保护法》 | 个人信息收集、使用、存储规范 |
  | 《数据安全法》 | 数据分类分级、安全保护义务 |
  | 《网络安全法》 | 网络安全义务、数据保护 |
  | 《App违法违规收集使用个人信息行为认定方法》 | 具体的违规行为认定标准 |
  | 《常见类型移动互联网应用程序必要个人信息范围规定》 | 各类App可收集的必要信息范围 |

## 特殊行业额外清单

如果你的 App 属于以下特殊行业，除了上述通用清单外，还需要满足额外的合规要求。

### 金融类

金融类 App 是监管最严格的类别之一，合规要求极高。

- [ ] 金融牌照已获取
  - 根据业务类型获取相应牌照
  - 常见牌照：支付牌照、小贷牌照、基金销售牌照等
  - 无牌照不得开展金融业务

- [ ] 风控系统已实现
  - 建立用户风险评估体系
  - 实现反洗钱（AML）机制
  - 实现实名认证（KYC）流程
  - 设置交易限额和异常监控

- [ ] 用户资金安全措施
  - 用户资金与平台资金隔离（银行存管）
  - 交易过程加密
  - 资金变动实时通知
  - 提供交易记录查询

- [ ] 信息披露
  - 清晰展示年化利率
  - 展示所有费用明细
  - 提供风险提示
  - 不得使用"保本保息"等违规宣传

### 医疗类

医疗类 App 涉及用户健康数据，隐私和安全要求极高。

- [ ] 医疗资质已获取
  - 互联网医院资质（如提供在线问诊）
  - 医疗器械注册证（如涉及医疗器械功能）
  - 医生执业资格验证

- [ ] 医疗信息准确性保证
  - 医疗建议需由持证医生提供
  - 不得提供未经验证的偏方或疗法
  - 明确标注"不能替代线下就医"
  - 药品信息需与国家药监局数据一致

- [ ] 患者隐私保护
  - 医疗数据加密存储
  - 问诊记录严格保密
  - 不得泄露患者信息
  - 遵守《医疗机构病历管理规定》

- [ ] 药品相关合规
  - 不得在线销售处方药（除非有资质）
  - 药品信息需标注批准文号
  - 不得发布虚假药品广告

### 教育类

教育类 App 需要特别关注未成年人保护和内容合规。

- [ ] 教育资质已获取（如需要）
  - 学历教育需办学许可证
  - 职业培训需相关资质
  - 在线教育平台需ICP许可证

- [ ] 内容审核机制
  - 课程内容需审核后上架
  - 教师资质需验证
  - 不得包含违规教学内容

- [ ] 未成年人保护措施
  - 青少年模式：限制使用时长和消费金额
  - 不得在青少年模式下推送广告
  - 22:00 - 次日 8:00 不得为未成年人提供服务
  - 实名认证区分成年/未成年用户

- [ ] 收费合规
  - 不得一次性收取超过 3 个月的费用
  - 收费标准需公示
  - 退费规则需明确

### 新闻类

新闻类 App 需要获取特殊资质，内容审核要求严格。

- [ ] 新闻资质已获取
  - 互联网新闻信息服务许可（必需）
  - 由网信办审批
  - 无此资质不得开展新闻采编和发布业务

- [ ] 内容审核机制
  - 新闻内容发布前需审核
  - 转载新闻需注明来源
  - 不得传播未经核实的消息
  - 建立虚假信息辟谣机制

- [ ] 信息来源标注
  - 每条新闻必须标注来源
  - 转载新闻标注原始发布媒体
  - 原创新闻标注"原创"
  - 不得篡改新闻标题和内容

- [ ] 评论区管理
  - 评论需审核后显示（先审后发）
  - 配备专职评论审核人员
  - 违规评论及时删除

## 合规检查流程建议

建议按以下顺序进行合规检查，确保不遗漏：

| 步骤 | 检查内容 | 预计耗时 | 优先级 |
|------|---------|---------|-------|
| 1 | ICP 备案 | 15-30 天 | ⭐⭐⭐ |
| 2 | 特殊行业资质（如需要） | 30-90 天 | ⭐⭐⭐ |
| 3 | 隐私政策编写 | 3-5 天 | ⭐⭐⭐ |
| 4 | 数据安全措施 | 5-10 天 | ⭐⭐⭐ |
| 5 | 内容合规检查 | 3-5 天 | ⭐⭐⭐ |
| 6 | 支付合规检查 | 2-3 天 | ⭐⭐ |
| 7 | 权限和 Info.plist 检查 | 1-2 天 | ⭐⭐ |
| 8 | App Privacy 营养标签填写 | 1 天 | ⭐⭐ |
| 9 | 最终全面检查 | 1 天 | ⭐ |

> 💡 关键提醒：ICP 备案和特殊行业资质耗时最长，建议最先启动。其他检查项可以在开发过程中同步进行。
