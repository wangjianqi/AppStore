# 20-状态管理：@State 与 @Binding

> 🎯 **本章目标**：理解 SwiftUI 单向数据流的核心思想，掌握 @State 管理本地状态、@Binding 实现父子组件通信，能够独立完成计数器、开关、表单等常见状态管理场景。

---

## SwiftUI 数据流核心概念

在 SwiftUI 中，**界面是状态的函数**——你不需要手动操作 UI 元素，只需要修改数据，界面就会自动更新。这和以前 UIKit 的"命令式"开发方式完全不同。

### 单向数据流

SwiftUI 采用**单向数据流（Unidirectional Data Flow）**架构，核心规则只有两条：

1. **数据向下流动**：父视图把数据传给子视图
2. **事件向上传递**：子视图通过回调/绑定通知父视图

用文字来描述这个过程：

```
┌─────────────────────────────────────────────┐
│  父视图（拥有数据 @State）                     │
│                                             │
│  @State var isOn = false                    │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │  子视图（接收数据 @Binding）           │    │
│  │                                     │    │
│  │  @Binding var isOn: Bool            │    │
│  │                                     │    │
│  │  Toggle("开关", isOn: $isOn)        │    │
│  │      ↓ 用户拨动开关                   │    │
│  │      isOn 变为 true                  │    │
│  │      ↑ 事件通过 @Binding 传回父视图    │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  父视图的 isOn 也变为 true → 界面自动刷新     │
└─────────────────────────────────────────────┘
```

**为什么单向数据流更好？**

| 优势 | 说明 |
|------|------|
| 数据流向清晰 | 数据只能从上往下传，不会出现"谁改了数据"的困惑 |
| 调试简单 | 出了 bug 只需要顺着数据流方向排查 |
| 避免循环更新 | 不会出现 A 改 B、B 又改 A 的死循环 |
| 性能更好 | SwiftUI 能精确知道哪些视图需要刷新 |

> 💡 **提示**：如果你之前学过 Vue 或 React，SwiftUI 的单向数据流和它们非常相似。React 的 `useState` 对应 SwiftUI 的 `@State`，React 的 props 回调对应 SwiftUI 的 `@Binding`。

### 视图刷新机制

SwiftUI 的刷新机制可以用一句话概括：**状态变化 → 视图自动刷新**。

具体流程：

```
1. 用户操作（点击按钮、输入文字、滑动开关……）
2. @State 变量的值发生变化
3. SwiftUI 检测到变化，标记依赖该状态的视图为"脏"（dirty）
4. SwiftUI 重新计算 body 属性
5. 新旧 body 对比（diff），只更新有变化的部分
6. 屏幕上看到更新后的界面
```

**哪些变化会触发刷新？**

| 变化类型 | 是否触发刷新 | 示例 |
|---------|------------|------|
| 修改 @State 变量 | ✅ 是 | `count += 1` |
| 修改 @Binding 变量 | ✅ 是 | `isOn.toggle()` |
| 修改普通 let/var 变量 | ❌ 否 | `let name = "Tom"` |
| 修改计算属性依赖的 @State | ✅ 是 | 计算属性引用了 @State 变量 |
| 在后台线程修改 @State | ❌ 不安全 | 必须在主线程修改 |

⚠️ **警告**：修改 @State 必须在**主线程**进行！如果在后台线程（如网络请求回调）中修改，可能导致崩溃或界面不更新。使用 `DispatchQueue.main.async { ... }` 切回主线程。

## @State 本地状态

`@State` 是 SwiftUI 中最简单的状态管理方式，用于在**当前视图内部**存储可变数据。

### 基本使用

```swift
import SwiftUI

struct CounterView: View {
    @State private var count = 0

    var body: some View {
        VStack(spacing: 20) {
            Text("计数：\(count)")
                .font(.largeTitle)

            HStack(spacing: 20) {
                Button("−1") {
                    count -= 1
                }
                .buttonStyle(.bordered)

                Button("+1") {
                    count += 1
                }
                .buttonStyle(.borderedProminent)
            }
        }
    }
}

#Preview {
    CounterView()
}
```

逐行解读：

| 代码 | 含义 |
|------|------|
| `@State private var count = 0` | 声明一个本地状态变量，初始值为 0 |
| `@State` | 属性包装器，告诉 SwiftUI "这个变量变化时要刷新视图" |
| `private` | 访问控制，@State 变量应该设为 private |
| `count += 1` | 修改 @State 变量，SwiftUI 自动刷新界面 |
| `\(count)` | 字符串插值，在 Text 中显示变量值 |

> 💡 **提示**：`@State` 就像一个"信号灯"——当你修改它时，SwiftUI 就知道"嘿，这个视图需要更新了！"

### 状态更新与视图刷新

来看一个更直观的例子，感受状态变化如何驱动界面刷新：

```swift
import SwiftUI

struct MoodView: View {
    @State private var mood = "😊"

    var body: some View {
        VStack(spacing: 30) {
            Text(mood)
                .font(.system(size: 100))

            Text("当前心情：\(moodDescription)")
                .font(.title3)
                .foregroundColor(.secondary)

            HStack(spacing: 16) {
                Button("开心") { mood = "😊" }
                    .buttonStyle(.bordered)
                Button("一般") { mood = "😐" }
                    .buttonStyle(.bordered)
                Button("难过") { mood = "😢" }
                    .buttonStyle(.bordered)
            }
        }
    }

    var moodDescription: String {
        switch mood {
        case "😊": return "开心"
        case "😐": return "一般"
        case "😢": return "难过"
        default: return "未知"
        }
    }
}

#Preview {
    MoodView()
}
```

当你点击不同按钮时：

1. `mood` 的值改变（如从 `"😊"` 变为 `"😢"`）
2. SwiftUI 检测到 `@State` 变化
3. 重新执行 `body`，计算属性 `moodDescription` 也随之更新
4. 界面上大表情和文字同时刷新

> 💡 **提示**：计算属性（如 `moodDescription`）本身不是 @State，但它依赖 @State 变量，所以当 @State 变化时，计算属性也会重新计算。

### 使用注意事项

#### 1. @State 应该设为 private

```swift
// ✅ 正确：@State 设为 private
@State private var count = 0

// ❌ 错误：@State 不应该对外暴露
@State var count = 0
```

原因：@State 是视图的**内部状态**，外部不应该直接访问或修改。如果其他视图需要访问这个数据，应该通过 @Binding 传递。

#### 2. @State 只适合简单值类型

```swift
// ✅ 适合 @State：简单值类型
@State private var count = 0
@State private var name = ""
@State private var isOn = false
@State private var selectedColor: Color = .blue

// ❌ 不适合 @State：复杂引用类型
@State private var user = User()      // 不要这样！
@State private var items = [Todo]()   // 简单数组可以，但复杂场景用 @Observable
```

| 适合 @State | 不适合 @State |
|------------|--------------|
| Int、Double、String | 自定义 class 对象 |
| Bool | 包含复杂逻辑的对象 |
| 简单枚举 | 需要在多个视图共享的数据 |
| 简单数组（少量数据） | 大量数据的集合 |

> 💡 **提示**：@State 为值类型（struct、enum）做了优化。对于引用类型（class），应该使用 `@StateObject` 或 `@Observable`，我们会在后续章节学习。

#### 3. 不要在 @State 中存储大对象

```swift
// ❌ 错误：在 @State 中存储大量数据
@State private var allImages = [UIImage]()  // 可能占用大量内存

// ✅ 正确：用专门的数据管理对象
// 后续学习 @Observable 后会知道怎么做
```

⚠️ **警告**：@State 变量的值在视图重新创建时**会被保留**（SwiftUI 帮你管理了持久化），但这不代表它是永久存储！当视图从视图层级中彻底移除后，@State 的值也会消失。需要持久化请使用 UserDefaults 或数据库。

## @Binding 父子组件通信

`@Binding` 用于在**父子视图之间**建立双向数据通道。子视图通过 @Binding 可以读取和修改父视图的 @State 数据。

### 基本使用

来看一个开关组件的例子：

```swift
import SwiftUI

struct ParentView: View {
    @State private var isDarkMode = false

    var body: some View {
        VStack(spacing: 30) {
            Text(isDarkMode ? "🌙 暗色模式" : "☀️ 亮色模式")
                .font(.largeTitle)

            // 把 $isOn 传给子视图
            ThemeToggle(isOn: $isDarkMode)
        }
        .padding()
        .background(isDarkMode ? Color.black : Color.white)
        .foregroundColor(isDarkMode ? Color.white : Color.black)
        .animation(.easeInOut, value: isDarkMode)
    }
}

struct ThemeToggle: View {
    @Binding var isOn: Bool

    var body: some View {
        Toggle("暗色模式", isOn: $isOn)
            .font(.title3)
            .padding()
            .background(
                RoundedRectangle(cornerRadius: 12)
                    .fill(Color.gray.opacity(0.15))
            )
            .padding(.horizontal)
    }
}

#Preview {
    ParentView()
}
```

数据流向分析：

```
父视图 @State var isDarkMode = false
  │
  ├── 传给子视图：$isDarkMode（创建 Binding）
  │
  └── 子视图 @Binding var isOn: Bool
        │
        ├── 读取：isOn → false
        └── 修改：isOn = true → 父视图的 isDarkMode 也变为 true
```

> 💡 **提示**：可以把 @Binding 想象成一根"数据管道"——它把父视图的 @State 和子视图连接起来，两边都能读写同一份数据。

### $ 前缀的含义

在 SwiftUI 中，`$` 是一个非常重要的符号，它表示**创建绑定（Binding）**。

```swift
@State private var name = "Tom"

// 三种访问方式：
name      // "Tom"    —— 读取值（String 类型）
$name     // Binding<String> —— 创建绑定（可以传给子视图）
```

| 写法 | 类型 | 含义 | 使用场景 |
|------|------|------|---------|
| `name` | `String` | 读取变量的值 | 在 Text 中显示、条件判断 |
| `$name` | `Binding<String>` | 创建对变量的绑定引用 | 传给 @Binding 参数、TextField 的 text 参数 |

来看一个完整的对比示例：

```swift
import SwiftUI

struct DollarSignView: View {
    @State private var username = ""
    @State private var isAgreed = false

    var body: some View {
        Form {
            // $username：绑定，TextField 需要双向绑定
            TextField("用户名", text: $username)

            // username：读取值，在 Text 中显示
            Text("你输入了：\(username)")

            // $isAgreed：绑定，Toggle 需要双向绑定
            Toggle("同意协议", isOn: $isAgreed)

            // isAgreed：读取值，做条件判断
            if isAgreed {
                Text("✅ 已同意协议")
                    .foregroundColor(.green)
            } else {
                Text("❌ 请先同意协议")
                    .foregroundColor(.red)
            }
        }
    }
}

#Preview {
    DollarSignView()
}
```

⚠️ **警告**：`$` 只能用在 `@State`、`@Binding`、`@ObservedObject`、`@StateObject` 等属性包装器修饰的变量前面。普通变量不能加 `$`。

### 双向绑定

"双向绑定"的意思是：**子视图的修改会自动反映到父视图，反之亦然**。

```swift
import SwiftUI

struct TwoWayBindingView: View {
    @State private var sliderValue = 50.0
    @State private var isFeatureOn = false

    var body: some View {
        VStack(spacing: 30) {
            Text("主视图的值")
                .font(.headline)

            Text("滑块值：\(Int(sliderValue))")
            Text("开关状态：\(isFeatureOn ? "开启" : "关闭")")

            Divider()

            // 子视图通过 @Binding 修改数据
            // 修改会自动反映到上面的 Text 显示中
            SliderControl(value: $sliderValue, isOn: $isFeatureOn)
        }
        .padding()
    }
}

struct SliderControl: View {
    @Binding var value: Double
    @Binding var isOn: Bool

    var body: some View {
        VStack(spacing: 20) {
            Text("子视图控制面板")
                .font(.headline)
                .foregroundColor(.secondary)

            Slider(value: $value, in: 0...100) {
                Text("数值")
            }

            Toggle("功能开关", isOn: $isOn)
        }
        .padding()
        .background(
            RoundedRectangle(cornerRadius: 12)
                .fill(Color.gray.opacity(0.1))
        )
        .padding(.horizontal)
    }
}

#Preview {
    TwoWayBindingView()
}
```

双向绑定的关键点：

| 要点 | 说明 |
|------|------|
| 父视图用 `@State` 声明数据 | 数据的"源头"在父视图 |
| 子视图用 `@Binding` 接收数据 | 子视图不拥有数据，只是"借用" |
| 父视图传 `$变量名` | `$` 创建绑定，把数据通道传给子视图 |
| 任何一方修改都同步 | 父改子看到，子改父看到 |

> 💡 **提示**：@Binding 不拥有数据，它只是一个"引用"。就像你借了朋友的书——你可以看、可以写批注，但书还是朋友的。朋友在自己的书上做标记，你也能看到。

## 实战：状态管理综合练习

### 计数器

一个完整的计数器，包含加、减、重置功能：

```swift
import SwiftUI

struct CounterApp: View {
    @State private var count = 0
    @State private var step = 1

    var body: some View {
        NavigationStack {
            VStack(spacing: 40) {
                Text("\(count)")
                    .font(.system(size: 80, weight: .bold, design: .rounded))
                    .foregroundStyle(count > 0 ? .green : count < 0 ? .red : .primary)
                    .animation(.easeInOut, value: count)

                Text("步长：\(step)")
                    .font(.subheadline)
                    .foregroundColor(.secondary)

                Stepper("调整步长", value: $step, in: 1...10)
                    .labelsHidden()
                    .padding(.horizontal, 80)

                HStack(spacing: 30) {
                    Button {
                        count -= step
                    } label: {
                        Image(systemName: "minus.circle.fill")
                            .font(.system(size: 50))
                            .foregroundColor(.red)
                    }

                    Button {
                        count = 0
                    } label: {
                        Image(systemName: "arrow.counterclockwise.circle.fill")
                            .font(.system(size: 40))
                            .foregroundColor(.gray)
                    }

                    Button {
                        count += step
                    } label: {
                        Image(systemName: "plus.circle.fill")
                            .font(.system(size: 50))
                            .foregroundColor(.green)
                    }
                }
            }
            .navigationTitle("计数器")
        }
    }
}

#Preview {
    CounterApp()
}
```

### 开关与滑块

Toggle + Slider 综合使用，模拟一个"灯光控制"界面：

```swift
import SwiftUI

struct LightControlView: View {
    @State private var isLightOn = true
    @State private var brightness = 80.0
    @State private var colorTemperature = 4000.0

    var body: some View {
        NavigationStack {
            Form {
                Section("灯光开关") {
                    Toggle("灯光", isOn: $isLightOn)
                        .tint(.yellow)
                }

                Section("灯光设置") {
                    VStack(alignment: .leading) {
                        Text("亮度：\(Int(brightness))%")
                        Slider(value: $brightness, in: 0...100, step: 5)
                            .tint(.yellow)
                    }
                    .disabled(!isLightOn)
                    .opacity(isLightOn ? 1 : 0.4)

                    VStack(alignment: .leading) {
                        Text("色温：\(Int(colorTemperature))K")
                        Slider(value: $colorTemperature, in: 2700...6500, step: 100) {
                            Text("色温")
                        }
                        .tint(.orange)
                    }
                    .disabled(!isLightOn)
                    .opacity(isLightOn ? 1 : 0.4)
                }

                Section("预览") {
                    LightPreview(isOn: $isLightOn, brightness: $brightness)
                }
            }
            .navigationTitle("灯光控制")
        }
    }
}

struct LightPreview: View {
    @Binding var isOn: Bool
    @Binding var brightness: Double

    var body: some View {
        ZStack {
            RoundedRectangle(cornerRadius: 16)
                .fill(
                    isOn
                    ? Color.yellow.opacity(brightness / 100 * 0.8)
                    : Color.gray.opacity(0.2)
                )
                .frame(height: 120)
                .animation(.easeInOut, value: isOn)
                .animation(.easeInOut, value: brightness)

            Image(systemName: isOn ? "lightbulb.fill" : "lightbulb")
                .font(.system(size: 50))
                .foregroundColor(isOn ? .orange : .gray)
                .animation(.easeInOut, value: isOn)
        }
    }
}

#Preview {
    LightControlView()
}
```

> 💡 **提示**：注意 `.disabled(!isLightOn)` 的用法——当灯光关闭时，滑块变灰且不可拖动。`.opacity()` 则让禁用状态更明显。这是常见的 UI 模式。

### 表单数据绑定

一个完整的注册表单示例，展示多个 @State 和 @Binding 的配合：

```swift
import SwiftUI

struct RegistrationFormView: View {
    @State private var username = ""
    @State private var email = ""
    @State private var password = ""
    @State private var isAgreed = false
    @State private var selectedGender = "请选择"
    @State private var showSuccess = false

    let genders = ["男", "女", "其他"]

    var isFormValid: Bool {
        !username.isEmpty
        && username.count >= 2
        && email.contains("@")
        && password.count >= 6
        && isAgreed
    }

    var body: some View {
        NavigationStack {
            Form {
                Section("基本信息") {
                    TextField("用户名（至少2个字符）", text: $username)
                        .textInputAutocapitalization(.never)

                    TextField("邮箱", text: $email)
                        .keyboardType(.emailAddress)
                        .textInputAutocapitalization(.never)

                    SecureField("密码（至少6位）", text: $password)
                }

                Section("其他") {
                    Picker("性别", selection: $selectedGender) {
                        ForEach(genders, id: \.self) { gender in
                            Text(gender)
                        }
                    }

                    Toggle("同意用户协议", isOn: $isAgreed)
                }

                Section {
                    Button("注册") {
                        showSuccess = true
                    }
                    .buttonStyle(.borderedProminent)
                    .disabled(!isFormValid)
                    .frame(maxWidth: .infinity)
                }
            }
            .navigationTitle("注册")
            .alert("注册成功！", isPresented: $showSuccess) {
                Button("好的") {
                    username = ""
                    email = ""
                    password = ""
                    isAgreed = false
                    selectedGender = "请选择"
                }
            } message: {
                Text("欢迎你，\(username)！")
            }
        }
    }
}

#Preview {
    RegistrationFormView()
}
```

表单中用到的状态管理总结：

| 状态变量 | 类型 | 用途 | 绑定方式 |
|---------|------|------|---------|
| `username` | `String` | 存储用户名 | `$username` → TextField |
| `email` | `String` | 存储邮箱 | `$email` → TextField |
| `password` | `String` | 存储密码 | `$password` → SecureField |
| `isAgreed` | `Bool` | 是否同意协议 | `$isAgreed` → Toggle |
| `selectedGender` | `String` | 选择的性别 | `$selectedGender` → Picker |
| `showSuccess` | `Bool` | 是否显示成功弹窗 | `$showSuccess` → alert |

> 💡 **提示**：`isFormValid` 是一个计算属性，它依赖多个 @State 变量。当任何一个 @State 变化时，`isFormValid` 都会重新计算，注册按钮的禁用状态也会自动更新。这就是 SwiftUI 响应式编程的威力！

## 小结

本章我们学习了 SwiftUI 状态管理的核心知识：

| 知识点 | 核心要点 |
|-------|---------|
| **单向数据流** | 数据向下流动，事件向上传递；清晰、可调试、高效 |
| **视图刷新机制** | @State 变化 → body 重新计算 → 界面自动更新 |
| **@State** | 本地状态，private 修饰，适合简单值类型 |
| **@Binding** | 父子通信，子视图通过 $ 获得绑定引用 |
| **$ 前缀** | 创建绑定，`name` 是值，`$name` 是绑定 |
| **双向绑定** | 父子视图共享同一份数据，任何一方修改都同步 |

**@State vs @Binding 对比**：

| 对比项 | @State | @Binding |
|-------|--------|----------|
| 谁拥有数据 | 当前视图拥有 | 不拥有，引用父视图的数据 |
| 数据来源 | 自己创建初始值 | 父视图通过 $ 传入 |
| 是否需要初始值 | ✅ 需要 | ❌ 不需要 |
| 访问控制 | 应该设为 private | 不能设为 private |
| 适用场景 | 视图内部的可变状态 | 父子视图共享数据 |

**核心心法**：记住 SwiftUI 的数据流口诀——**@State 是源头，@Binding 是管道，数据往下流，事件往上冒**。
