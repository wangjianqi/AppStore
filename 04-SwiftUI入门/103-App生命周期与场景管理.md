## 1. iOS App 生命周期概述

### 1.1 四种核心状态

iOS App 在运行过程中会在以下四种状态之间切换：

| 状态 | 英文名 | 说明 | 用户可见 | 可执行代码 | 系统资源 |
|------|--------|------|---------|-----------|---------|
| 前台活跃 | Active | 用户正在与 App 交互 | ✅ | ✅ 全部 | 正常 |
| 前台非活跃 | Inactive | 前台但失去焦点（如来电、控制中心） | ✅ 部分 | ✅ 受限 | 正常 |
| 后台 | Background | 退到后台，仍有短暂执行时间 | ❌ | ✅ 有限 | 受限 |
| 挂起 | Suspended | 后台挂起，代码停止执行 | ❌ | ❌ | 仅保留内存 |

> 💡 **生活类比**：把 App 想象成一个餐厅服务员——**前台活跃**是正在为客人点菜；**前台非活跃**是被经理叫住问话，客人还在但暂时顾不上；**后台**是回到后厨传菜，还能干活但看不到客人；**挂起**是在休息室等着，完全不能动，但随时可能被叫回去。

### 1.2 状态转换图

```
                    ┌─────────────┐
                    │   Not       │
          启动      │   Running   │
        ──────────► │  (未运行)    │
        │           └─────────────┘
        │                 │
        │            应用启动
        │                 │
        │                 ▼
        │           ┌─────────────┐
        │           │  Inactive   │◄──────────────┐
        │           │  (前台非活跃) │                │
        │           └──────┬──────┘                │
        │                  │                       │
        │            获得焦点                  失去焦点
        │                  │                       │
        │                  ▼                       │
        │           ┌─────────────┐                │
        │           │   Active    │────────────────┘
        │           │  (前台活跃)  │
        │           └──────┬──────┘
        │                  │
        │            退到后台/锁屏
        │                  │
        │                  ▼
        │           ┌─────────────┐
        │           │ Background  │
        │           │   (后台)     │
        │           └──────┬──────┘
        │                  │
        │           系统挂起/内存不足
        │                  │
        │                  ▼
        │           ┌─────────────┐
        │           │ Suspended   │
        │           │  (挂起)      │─── 系统终止 ───► Not Running
        │           └─────────────┘
        │                  │
        │            用户切回前台
        │                  │
        └──────────────────┘
```

### 1.3 与 Android 生命周期对比

如果你有 Android 开发经验，下表能帮你快速建立映射关系：

| iOS 状态 | Android 对应状态 | 触发时机 |
|---------|-----------------|---------|
| Active | `onResume()` | 获得焦点，可交互 |
| Inactive | `onPause()` | 失去焦点但仍在前景 |
| Background | `onStop()` | 完全不可见 |
| Suspended | 无直接对应（Android 由系统回收） | 系统自动挂起 |
| Not Running | `onDestroy()` | 进程被终止 |

> ⚠️ **关键区别**：Android 的 `onPause()` / `onStop()` / `onDestroy()` 是回调方法，开发者必须手动实现；而 iOS SwiftUI 通过声明式的方式，用 `scenePhase` 环境变量来响应状态变化，更加简洁。

## 2. SwiftUI App 协议

### 2.1 @main 标注与 App 协议

从 SwiftUI 2.0（iOS 14）开始，App 的入口不再是 `AppDelegate`，而是一个遵循 `App` 协议的结构体：

```swift
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
```

`@main` 标注告诉编译器：这是程序的入口点。整个 App 的启动流程变为：

```
系统启动 App
    │
    ▼
查找 @main 标注的类型
    │
    ▼
调用 MyApp.init()
    │
    ▼
计算 body 属性，创建 Scene
    │
    ▼
渲染第一个 View
```

> 💡 **生活类比**：`@main` 就像是公司的法人代表——一个公司只能有一个法人，系统通过法人找到公司；一个 App 也只能有一个 `@main`，系统通过它找到入口。

### 2.2 App 协议的核心要求

`App` 协议只有一个必须实现的属性：

| 要求 | 类型 | 说明 |
|------|------|------|
| `body` | `some Scene` | App 的场景内容 |

此外，`App` 协议还提供了可选的生命周期方法：

```swift
@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }

    init() {
        print("App 初始化完成")
    }
}
```

### 2.3 WindowGroup 与 Scene 协议

`WindowGroup` 是最常用的 Scene 类型，它负责管理一组窗口：

```swift
WindowGroup {
    ContentView()
}
```

`Scene` 协议是所有场景类型的根基协议，其继承关系如下：

```
Scene（协议）
  ├── WindowGroup    — 管理一组相同内容的窗口
  ├── Window         — 管理单个独立窗口
  ├── DocumentGroup  — 管理文档型窗口
  └── Settings       — macOS 设置窗口（iOS 不可用）
```

> ⚠️ **注意**：`Settings` 场景仅在 macOS 上可用，iOS 上不生效。如果你在 iOS 项目中添加 `Settings`，编译不会报错，但不会有任何效果。

## 3. scenePhase 环境变量

### 3.1 监听前后台切换

SwiftUI 提供了 `@Environment(\.scenePhase)` 来监听当前场景的生命周期状态，这是 SwiftUI 中响应生命周期事件的核心方式：

```swift
struct ContentView: View {
    @Environment(\.scenePhase) var scenePhase

    var body: some View {
        Text("当前状态: \(scenePhase.description)")
            .font(.title2)
            .padding()
            .onChange(of: scenePhase) { oldPhase, newPhase in
                switch newPhase {
                case .active:
                    print("进入前台活跃")
                case .inactive:
                    print("进入前台非活跃")
                case .background:
                    print("进入后台")
                @unknown default:
                    break
                }
            }
    }
}
```

### 3.2 ScenePhase 三种状态

`ScenePhase` 是一个枚举，定义了三种状态：

| ScenePhase 值 | 含义 | 典型触发场景 |
|---------------|------|-------------|
| `.active` | 前台活跃 | 用户正在使用 App |
| `.inactive` | 前台非活跃 | 来电、下拉控制中心、多任务切换器 |
| `.background` | 后台 | 用户按 Home 键、切换到其他 App |

> 💡 **注意**：SwiftUI 的 `ScenePhase` 没有 `.suspended` 状态。当 App 被挂起时，`scenePhase` 仍然保持 `.background`。挂起是系统行为，App 无法感知——就像你睡着了不知道自己睡着了一样。

### 3.3 在 App 级别监听 scenePhase

如果你需要在 App 入口处就监听生命周期，可以在 `WindowGroup` 上添加 `onChange`：

```swift
@main
struct MyApp: App {
    @Environment(\.scenePhase) var scenePhase

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .onChange(of: scenePhase) { oldPhase, newPhase in
            switch newPhase {
            case .active:
                setupForegroundTasks()
            case .inactive:
                prepareForBackground()
            case .background:
                saveUserData()
            @unknown default:
                break
            }
        }
    }

    func setupForegroundTasks() {
        print("恢复前台任务：刷新数据、重启动画")
    }

    func prepareForBackground() {
        print("准备进入后台：暂停动画")
    }

    func saveUserData() {
        print("保存用户数据到磁盘")
    }
}
```

## 4. Scene 类型详解

### 4.1 WindowGroup

`WindowGroup` 是最常用的场景类型，适用于大多数 App。它管理一组内容相同的窗口：

```swift
WindowGroup {
    ContentView()
}
```

**特点**：

| 特性 | 说明 |
|------|------|
| 默认场景 | Xcode 模板自动生成 |
| 支持多窗口 | iPad 和 macOS 上用户可创建多个窗口 |
| 自动管理 | 系统自动处理窗口的创建和销毁 |
| 适用于 | 大多数标准 App |

你可以为 `WindowGroup` 指定 ID，用于区分不同的窗口组：

```swift
WindowGroup(id: "main") {
    MainView()
}

WindowGroup(id: "detail") {
    DetailView()
}
```

### 4.2 Window

`Window` 用于创建单个独立窗口，适用于工具类 App 或辅助面板：

```swift
Window("颜色选择器", id: "color-picker") {
    ColorPickerView()
}
```

| 特性 | 说明 |
|------|------|
| 单实例 | 同一 ID 只能存在一个窗口 |
| 独立性 | 与主窗口内容不同 |
| 适用平台 | iPadOS 13+、macOS |
| 典型用途 | 浮动面板、工具窗口 |

> ⚠️ **注意**：`Window` 在 iPhone 上不会生效——iPhone 不支持多窗口。仅在 iPad 和 macOS 上可用。

### 4.3 DocumentGroup

`DocumentGroup` 用于文档型 App，自动提供文档浏览器界面：

```swift
DocumentGroup(newDocument: TextDocument()) { file in
    TextEditorView(document: file.$document)
}
```

使用 `DocumentGroup` 需要先定义一个遵循 `FileDocument` 协议的文档类型：

```swift
import SwiftUI
import UniformTypeIdentifiers

struct TextDocument: FileDocument {
    var text: String

    static var readableContentTypes: [UTType] {
        [.plainText]
    }

    init(text: String = "") {
        self.text = text
    }

    init(configuration: ReadConfiguration) throws {
        guard let data = configuration.file.regularFileContents,
              let string = String(data: data, encoding: .utf8)
        else {
            throw CocoaError(.fileReadCorruptFile)
        }
        text = string
    }

    func fileWrapper(configuration: WriteConfiguration) throws -> FileWrapper {
        let data = text.data(using: .utf8)!
        return FileWrapper(regularFileWithContents: data)
    }
}
```

### 4.4 Settings Scene

`Settings` 场景仅在 macOS 上可用，用于创建 App 的偏好设置窗口：

```swift
Settings {
    SettingsView()
}
```

### 4.5 Scene 类型对比总览

| Scene 类型 | iPhone | iPad | macOS | 多实例 | 用途 |
|-----------|--------|------|-------|--------|------|
| WindowGroup | ✅ | ✅ | ✅ | ✅ | 通用主界面 |
| Window | ❌ | ✅ | ✅ | ❌ | 独立面板/工具 |
| DocumentGroup | ✅ | ✅ | ✅ | ✅ | 文档编辑器 |
| Settings | ❌ | ❌ | ✅ | ❌ | 偏好设置 |

## 5. 多窗口与多场景管理

### 5.1 iPad 多窗口支持

在 iPadOS 上，`WindowGroup` 默认支持多窗口。用户可以通过以下方式创建新窗口：

- 从多任务界面拖拽 App 图标
- 长按 App 图标选择"新建窗口"
- 通过代码打开新窗口

通过 `openWindow` 环境动作可以在代码中打开指定场景的新窗口：

```swift
struct SidebarView: View {
    @Environment(\.openWindow) var openWindow

    var body: some View {
        List {
            Button("打开主窗口") {
                openWindow(id: "main")
            }
            Button("打开颜色选择器") {
                openWindow(id: "color-picker")
            }
            Button("打开指定文档") {
                openWindow(value: "report.txt")
            }
        }
    }
}
```

### 5.2 场景间数据共享

多个窗口/场景之间需要共享数据时，推荐使用以下方式：

| 方式 | 适用场景 | 特点 |
|------|---------|------|
| `@AppStorage` | 简单键值数据 | 自动持久化，所有场景共享 |
| `@EnvironmentObject` | 运行时共享对象 | 需要在 App 层注入 |
| `FileManager` | 文件型数据 | 手动读写，最灵活 |
| `@Observable` + 单例 | 复杂共享状态 | 响应式更新 |

使用 `@Observable` 类实现跨场景数据共享：

```swift
@Observable
class SharedStore {
    static let shared = SharedStore()
    var counter = 0
    var lastActiveScene = ""
}

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .environment(SharedStore.shared)
        }
    }
}
```

### 5.3 dismissWindow

在 iPadOS 上，你可以通过 `@Environment(\.dismissWindow)` 关闭指定窗口：

```swift
struct ToolPanelView: View {
    @Environment(\.dismissWindow) var dismissWindow

    var body: some View {
        VStack {
            Text("工具面板")
            Button("关闭此面板") {
                dismissWindow(id: "tool-panel")
            }
        }
    }
}
```

> 💡 **提示**：`dismissWindow` 是 iOS 17+ 新增的 API。在更早版本中，需要通过 `NSApplication`（macOS）或其他方式间接关闭窗口。

## 6. UIKit 生命周期对比

### 6.1 AppDelegate / SceneDelegate / SwiftUI 对比表

| 功能 | AppDelegate | SceneDelegate | SwiftUI |
|------|------------|---------------|---------|
| App 启动 | `application(_:didFinishLaunchingWithOptions:)` | — | `App.init()` |
| 进入前台 | `applicationDidBecomeActive` | `sceneDidBecomeActive` | `scenePhase == .active` |
| 失去焦点 | `applicationWillResignActive` | `sceneWillResignActive` | `scenePhase == .inactive` |
| 进入后台 | `applicationDidEnterBackground` | `sceneDidEnterBackground` | `scenePhase == .background` |
| 返回前台 | `applicationWillEnterForeground` | `sceneWillEnterForeground` | `scenePhase` 从 `.background` 变为 `.inactive` |
| 场景创建 | — | `scene(_:willConnectTo:options:)` | `Scene.body` 计算 |
| 场景销毁 | — | `sceneDidDisconnect` | 系统自动管理 |

### 6.2 混合使用场景

在 SwiftUI 项目中，有时仍需要 `AppDelegate` 的能力（如接收远程推送、处理 URL Scheme）。SwiftUI 提供了 `@UIApplicationDelegateAdaptor` 来桥接：

```swift
class MyAppDelegate: NSObject, UIApplicationDelegate {
    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        print("AppDelegate: 启动完成")
        return true
    }

    func application(
        _ application: UIApplication,
        didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data
    ) {
        print("AppDelegate: 收到推送 Token")
    }
}

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(MyAppDelegate.self) var appDelegate

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
```

> ⚠️ **注意**：当同时使用 `@UIApplicationDelegateAdaptor` 和 `scenePhase` 时，两者的回调都会触发，但顺序不保证。不要在两处重复执行相同逻辑。

### 6.3 何时使用 AppDelegate

| 场景 | 推荐方式 |
|------|---------|
| 普通前后台切换 | `@Environment(\.scenePhase)` |
| 远程推送注册 | `@UIApplicationDelegateAdaptor` |
| URL Scheme 处理 | `.onOpenURL` 修饰符 |
| 后台任务（Background Tasks） | `@UIApplicationDelegateAdaptor` + BGTaskScheduler |
| 本地通知处理 | `@UIApplicationDelegateAdaptor` |

## 7. 生命周期中的数据保存与恢复

### 7.1 场景状态恢复

当系统因内存压力终止了后台 App，用户再次打开时，App 应恢复到之前的状态。SwiftUI 提供了 `sceneStorage` 修饰符来保存和恢复场景级别的简单数据：

```swift
struct ContentView: View {
    @SceneStorage("selectedTab") var selectedTab: String = "home"
    @SceneStorage("scrollOffset") var scrollOffset: Double = 0

    var body: some View {
        TabView(selection: $selectedTab) {
            HomeView()
                .tabItem { Label("首页", systemImage: "house") }
                .tag("home")

            ProfileView()
                .tabItem { Label("我的", systemImage: "person") }
                .tag("profile")
        }
    }
}
```

`@SceneStorage` 与 `@AppStorage` 的区别：

| 特性 | @SceneStorage | @AppStorage |
|------|-------------|------------|
| 存储范围 | 当前场景 | 全局所有场景 |
| 持久化 | 系统自动管理，可能丢失 | 写入 UserDefaults，持久保存 |
| 适用数据 | 选中标签、滚动位置 | 用户偏好、设置项 |
| 数据丢失场景 | 系统强制重启 | 除非用户卸载 App |

### 7.2 @AppStorage 持久化

`@AppStorage` 是基于 `UserDefaults` 的属性包装器，适合存储用户偏好和简单配置：

```swift
struct SettingsView: View {
    @AppStorage("userName") var userName: String = ""
    @AppStorage("isDarkMode") var isDarkMode: Bool = false
    @AppStorage("launchCount") var launchCount: Int = 0
    @AppStorage("fontSize") var fontSize: Double = 16.0

    var body: some View {
        Form {
            TextField("用户名", text: $userName)
            Toggle("深色模式", isOn: $isDarkMode)
            Stepper("字体大小: \(fontSize, specifier: "%.0f")", value: $fontSize, in: 12...24)
            Text("已启动 \(launchCount) 次")
        }
    }
}
```

> ⚠️ **警告**：`@AppStorage` 不适合存储敏感数据（如密码、Token）。敏感数据应使用 Keychain。`@AppStorage` 也不适合存储大量数据——它底层是 `UserDefaults`，整个文件会在启动时一次性加载到内存。

### 7.3 用户活动恢复 NSUserActivity

`NSUserActivity` 用于实现 Handoff 和 Siri 建议功能，让用户可以在不同设备上继续未完成的操作：

```swift
struct ReadingView: View {
    let articleId: String
    let articleTitle: String

    var body: some View {
        ScrollView {
            Text("文章内容...")
        }
        .userActivity("com.example.app.reading") { activity in
            activity.title = "正在阅读: \(articleTitle)"
            activity.userInfo = ["articleId": articleId]
            activity.isEligibleForSearch = true
            activity.isEligibleForPrediction = true
        }
    }
}
```

在 App 入口处恢复用户活动：

```swift
@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .onContinueUserActivity("com.example.app.reading") { activity in
                    if let articleId = activity.userInfo?["articleId"] as? String {
                        print("恢复阅读文章: \(articleId)")
                    }
                }
        }
    }
}
```

### 7.4 数据保存策略总结

| 数据类型 | 推荐方式 | 保存时机 | 恢复时机 |
|---------|---------|---------|---------|
| UI 状态（选中标签、滚动位置） | `@SceneStorage` | 系统自动 | 场景重建时 |
| 用户偏好（主题、字号） | `@AppStorage` | 值变化时自动 | App 启动时 |
| 结构化数据（文档、记录） | FileManager / SwiftData | `scenePhase` 变为 `.background` | App 启动时 |
| 用户活动（阅读进度） | `NSUserActivity` | 视图出现时 | `onContinueUserActivity` |
| 敏感数据（Token、密码） | Keychain | 值变化时 | 需要时读取 |

## 8. 实战：一个完整的生命周期感知 App

下面我们构建一个完整的生命周期感知 App，演示前后台切换时保存数据、场景切换处理等核心功能。

### 8.1 需求分析

我们要实现一个"专注计时器"App，核心功能：

- 计时器在前台运行
- 进入后台时自动保存计时进度
- 返回前台时恢复计时
- 记录每次前后台切换的时间
- 使用 `@AppStorage` 持久化用户设置

### 8.2 数据模型

```swift
import SwiftUI
import Observation

@Observable
class TimerModel {
    var elapsedSeconds: Int = 0
    var isRunning: Bool = false
    var lastBackgroundTime: Date?
    var stateChangeLog: [String] = []

    func start() {
        isRunning = true
    }

    func stop() {
        isRunning = false
    }

    func enterBackground() {
        lastBackgroundTime = Date()
        isRunning = false
        stateChangeLog.append("后台: \(Date.now.formatted(date: .omitted, time: .shortened))")
        if stateChangeLog.count > 20 {
            stateChangeLog.removeFirst()
        }
    }

    func enterForeground() {
        if let bgTime = lastBackgroundTime {
            let gap = Date.now.timeIntervalSince(bgTime)
            elapsedSeconds += Int(gap)
        }
        lastBackgroundTime = nil
        isRunning = true
        stateChangeLog.append("前台: \(Date.now.formatted(date: .omitted, time: .shortened))")
    }

    func formattedTime() -> String {
        let hours = elapsedSeconds / 3600
        let minutes = (elapsedSeconds % 3600) / 60
        let seconds = elapsedSeconds % 60
        return String(format: "%02d:%02d:%02d", hours, minutes, seconds)
    }
}
```

### 8.3 主视图

```swift
struct ContentView: View {
    @State private var model = TimerModel()
    @Environment(\.scenePhase) var scenePhase
    @AppStorage("focusGoalMinutes") var focusGoalMinutes: Int = 25
    @AppStorage("totalFocusSessions") var totalFocusSessions: Int = 0
    @AppStorage("isSoundEnabled") var isSoundEnabled: Bool = true

    var body: some View {
        TabView {
            timerTab
                .tabItem {
                    Label("计时", systemImage: "timer")
                }

            logTab
                .tabItem {
                    Label("记录", systemImage: "list.bullet.clipboard")
                }

            settingsTab
                .tabItem {
                    Label("设置", systemImage: "gearshape")
                }
        }
        .onChange(of: scenePhase) { oldPhase, newPhase in
            handleScenePhaseChange(oldPhase: oldPhase, newPhase: newPhase)
        }
    }

    private var timerTab: some View {
        VStack(spacing: 30) {
            Text(model.formattedTime())
                .font(.system(size: 64, weight: .thin, design: .monospaced))
                .foregroundStyle(model.isRunning ? .primary : .secondary)

            Text("目标: \(focusGoalMinutes) 分钟")
                .font(.subheadline)
                .foregroundStyle(.secondary)

            HStack(spacing: 20) {
                Button(model.isRunning ? "暂停" : "开始") {
                    if model.isRunning {
                        model.stop()
                    } else {
                        model.start()
                    }
                }
                .buttonStyle(.borderedProminent)
                .controlSize(.large)

                Button("重置") {
                    model.elapsedSeconds = 0
                    model.isRunning = false
                }
                .buttonStyle(.bordered)
                .controlSize(.large)
            }

            if model.elapsedSeconds >= focusGoalMinutes * 60 {
                Label("已完成目标！", systemImage: "checkmark.circle.fill")
                    .foregroundStyle(.green)
                    .font(.headline)
            }
        }
        .padding()
    }

    private var logTab: some View {
        List {
            Section("状态变更日志") {
                if model.stateChangeLog.isEmpty {
                    Text("暂无记录")
                        .foregroundStyle(.secondary)
                } else {
                    ForEach(model.stateChangeLog.reversed(), id: \.self) { log in
                        Text(log)
                    }
                }
            }

            Section("统计") {
                LabeledContent("累计专注次数", value: "\(totalFocusSessions)")
                LabeledContent("当前已计时", value: model.formattedTime())
            }
        }
    }

    private var settingsTab: some View {
        Form {
            Stepper("专注时长: \(focusGoalMinutes) 分钟", value: $focusGoalMinutes, in: 5...120, step: 5)
            Toggle("提示音", isOn: $isSoundEnabled)
        }
    }

    private func handleScenePhaseChange(oldPhase: ScenePhase, newPhase: ScenePhase) {
        switch newPhase {
        case .active:
            model.enterForeground()
            if oldPhase == .background {
                totalFocusSessions += 1
            }
        case .inactive:
            break
        case .background:
            model.enterBackground()
        @unknown default:
            break
        }
    }
}
```

### 8.5 关键实现要点

| 要点 | 实现方式 | 说明 |
|------|---------|------|
| 计时器后台恢复 | `lastBackgroundTime` 记录进入后台时间 | 返回前台时计算时间差，补上计时 |
| 状态日志 | `stateChangeLog` 数组 | 每次 scenePhase 变化时追加记录 |
| 用户设置持久化 | `@AppStorage` | 专注时长、提示音开关自动保存 |
| 专注次数统计 | `@AppStorage("totalFocusSessions")` | 每次从后台返回前台时 +1 |
| AppDelegate 桥接 | `@UIApplicationDelegateAdaptor` | 预留后台任务等高级功能入口 |

> 💡 **提示**：这个实战项目中的计时器使用了"时间差补算"策略——进入后台时记录时间戳，返回前台时计算差值。这比使用 `Timer` 在后台持续计时更可靠，因为后台状态下 `Timer` 会被系统挂起。

> ⚠️ **警告**：如果你的 App 需要在后台持续运行计时器（如番茄钟、运动追踪），需要申请后台模式（Background Modes）。否则 App 进入后台后很快就会被挂起，任何代码都无法执行。

## 本章小结

| 知识点 | 核心内容 |
|--------|---------|
