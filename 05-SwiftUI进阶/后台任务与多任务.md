## 1. iOS 后台机制概述

### 1.1 App 生命周期状态

iOS 对后台执行有严格限制，这是为了省电和保护用户体验。App 的生命周期就像一个人的一天——有清醒工作的时候，也有休息甚至"睡着"的时候。

| 状态 | 类比 | 说明 |
|------|------|------|
| Not Running | 还没起床 | App 未启动，不占用任何资源 |
| Active | 全神贯注工作 | 前台运行，接收所有事件 |
| Inactive | 走神了 | 前台但失去焦点（如拉下通知中心） |
| Background | 在后台默默干活 | 离开前台但仍在执行代码 |
| Suspended | 午休打盹 | 在后台但被冻结，不执行代码 |
| Terminated | 被叫走了 | App 被系统终止，需重新启动 |

> 💡 **类比理解**：想象你是一个员工——Active 是你在工位上全力工作；Inactive 是有人跟你说话但你分心了；Background 是你离开工位但还在处理任务；Suspended 是你被要求停下手中一切工作去午休；Terminated 是你直接被下班赶走了。

### 1.2 状态转换流程

```
启动 → Inactive → Active
                  ↓ (按 Home)
           Inactive → Background → Suspended
                                    ↓ (内存不足)
                                 Terminated
                  ↑ (重新打开)
           Inactive → Active
```

关键规则：
- 普通App 进入后台后，系统只给约 **30 秒** 执行时间
- 30 秒后 App 进入 Suspended 状态，代码不再执行
- 系统内存不足时，会优先终止 Suspended 的 App
- 只有声明了特定 Background Mode 的 App 才能获得额外后台时间

> ⚠️ **重要**：iOS 不像 Android 那样允许后台服务长期运行。这是 iOS 省电策略的核心设计，开发者必须适应这种"受限的后台"模式。

## 2. Background Modes 全览

### 2.1 后台模式分类

在 Xcode 的 Signing & Capabilities 中添加 Background Modes，或在 Info.plist 中声明 `UIBackgroundModes`。

| 模式 | Info.plist 键值 | 典型场景 | 后台时长 |
|------|-----------------|---------|---------|
| Audio | audio | 音乐播放、语音通话 | 持续（需实际播放） |
| Location | location | 导航、运动追踪 | 持续 |
| VoIP | voip | 网络电话 | 接收来电时唤醒 |
| Background Fetch | fetch | 定期获取新数据 | 约 30 秒 |
| Remote Notifications | remote-notification | 静默推送唤醒 | 约 30 秒 |
| Background Processing | processing | 数据处理、ML 训练 | 数分钟（系统决定） |
| External Accessories | external-accessory | 外设通信 | 持续 |
| Bluetooth Central | bluetooth-central | BLE 外设通信 | 持续 |
| Bluetooth Peripheral | bluetooth-peripheral | BLE 外设模式 | 持续 |

### 2.2 如何选择合适的后台模式

| 你的需求 | 推荐模式 | 原因 |
|---------|---------|------|
| 音乐 App 播放 | Audio | 唯一能持续播放的方式 |
| 跑步记录轨迹 | Location | 需持续获取位置 |
| 定期刷新新闻 | Background Fetch / Remote Notification | 按需获取，省电 |
| 大文件下载 | URLSession Background | 系统接管下载进程 |
| 夜间数据库维护 | Background Processing | 系统选择合适时机执行 |
| 即时通讯收到消息 | Remote Notification | 服务器主动唤醒 |

> 💡 **选择原则**：能用 Remote Notification 就不用 Background Fetch，能用 Background Processing 就不用常驻后台。让系统帮你决定执行时机，最省电也最稳定。

## 3. BGTaskScheduler 框架

BGTaskScheduler 是 iOS 13+ 引入的后台任务调度框架，替代了旧的 Background Fetch 机制。它就像一个"智能管家"——你告诉它要做什么，它根据电量、网络、使用习惯来决定最佳执行时机。

### 3.1 两种后台任务类型

| 类型 | 类名 | 用途 | 执行时长 | 时机 |
|------|------|------|---------|------|
| 后台刷新 | BGAppRefreshTask | 获取新数据、更新 UI | 约 30 秒 | 频繁（用户使用 App 后更频繁） |
| 后台处理 | BGProcessingTask | 数据库维护、ML 训练、清理 | 数分钟 | 不频繁（充电+闲时） |

### 3.2 配置与调度

**第一步：Info.plist 配置**

```xml
<key>BGTaskSchedulerPermittedIdentifiers</key>
<array>
    <string>com.example.app.refresh</string>
    <string>com.example.app.processing</string>
</array>
<key>UIBackgroundModes</key>
<array>
    <string>fetch</string>
    <string>processing</string>
</array>
```

**第二步：App 入口注册任务**

```swift
import SwiftUI
import BackgroundTasks

@main
struct MyApp: App {
    init() {
        registerBackgroundTasks()
    }

    func registerBackgroundTasks() {
        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "com.example.app.refresh",
            using: nil
        ) { task in
            handleAppRefresh(task: task as! BGAppRefreshTask)
        }

        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "com.example.app.processing",
            using: nil
        ) { task in
            handleProcessing(task: task as! BGProcessingTask)
        }
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
```

**第三步：调度任务**

```swift
func scheduleAppRefresh() {
    let request = BGAppRefreshTaskRequest(identifier: "com.example.app.refresh")
    request.earliestBeginDate = Date(timeIntervalSinceNow: 15 * 60)

    do {
        try BGTaskScheduler.shared.submit(request)
        print("✅ 后台刷新任务已调度")
    } catch {
        print("❌ 调度失败: \(error)")
    }
}

func scheduleProcessingTask() {
    let request = BGProcessingTaskRequest(identifier: "com.example.app.processing")
    request.earliestBeginDate = Date(timeIntervalSinceNow: 60 * 60)
    request.requiresNetworkConnectivity = true
    request.requiresExternalPower = true
    request.earliestBeginDate = Calendar.current.date(
        bySettingHour: 2, minute: 0, second: 0, of: Date()
    )

    do {
        try BGTaskScheduler.shared.submit(request)
        print("✅ 后台处理任务已调度")
    } catch {
        print("❌ 调度失败: \(error)")
    }
}
```

### 3.3 处理任务

```swift
func handleAppRefresh(task: BGAppRefreshTask) {
    scheduleAppRefresh()

    task.expirationHandler = {
        task.setTaskCompleted(success: false)
    }

    fetchNewData { success in
        task.setTaskCompleted(success: success)
    }
}

func handleProcessing(task: BGProcessingTask) {
    scheduleProcessingTask()

    task.expirationHandler = {
        task.setTaskCompleted(success: false)
    }

    performDatabaseMaintenance { success in
        task.setTaskCompleted(success: success)
    }
}

func fetchNewData(completion: @escaping (Bool) -> Void) {
    guard let url = URL(string: "https://api.example.com/latest") else {
        completion(false)
        return
    }
    URLSession.shared.dataTask(with: url) { data, _, error in
        guard let data = data, error == nil else {
            completion(false)
            return
        }
        UserDefaults.standard.set(Date(), forKey: "lastRefreshTime")
        completion(true)
    }.resume()
}

func performDatabaseMaintenance(completion: @escaping (Bool) -> Void) {
    DispatchQueue.global(qos: .utility).async {
        Thread.sleep(forTimeInterval: 5)
        completion(true)
    }
}
```

> ⚠️ **关键要点**：任务处理函数中必须做两件事——① 设置 `expirationHandler` 处理超时；② 在任务完成后调度下一次任务，形成"链式调度"保证持续刷新。

## 4. 后台下载与上传

### 4.1 URLSession Background Session

后台下载就像"代购服务"——你下单后即使 App 关了，系统也会帮你把东西下载好，等你回来直接取。

```swift
import UIKit

class DownloadManager {
    static let shared = DownloadManager()

    private lazy var session: URLSession = {
        let config = URLSessionConfiguration.background(
            withIdentifier: "com.example.app.backgroundDownload"
        )
        config.isDiscretionary = true
        config.sessionSendsLaunchEvents = true
        return URLSession(configuration: config, delegate: self, delegateQueue: nil)
    }()

    func downloadFile(from urlString: String) {
        guard let url = URL(string: urlString) else { return }
        let task = session.downloadTask(with: url)
        task.resume()
    }
}

extension DownloadManager: URLSessionDownloadDelegate {
    func urlSession(
        _ session: URLSession,
        downloadTask: URLSessionDownloadTask,
        didFinishDownloadingTo location: URL
    ) {
        let documentsDir = FileManager.default.urls(
            for: .documentDirectory, in: .userDomainMask
        )[0]
        let destination = documentsDir.appendingPathComponent(
            downloadTask.response?.suggestedFilename ?? "downloaded_file"
        )

        try? FileManager.default.removeItem(at: destination)
        try? FileManager.default.copyItem(at: location, to: destination)

        print("✅ 下载完成: \(destination.path)")
    }

    func urlSession(
        _ session: URLSession,
        downloadTask: URLSessionDownloadTask,
        didWriteData bytesWritten: Int64,
        totalBytesWritten: Int64,
        totalBytesExpectedToWrite: Int64
    ) {
        let progress = Double(totalBytesWritten) / Double(totalBytesExpectedToWrite)
        print("下载进度: \(Int(progress * 100))%")
    }
}
```

### 4.2 断点续传

```swift
class ResumableDownloadManager: NSObject {
    private var session: URLSession!
    private var resumeData: Data?

    override init() {
        super.init()
        let config = URLSessionConfiguration.background(
            withIdentifier: "com.example.app.resumable"
        )
        session = URLSession(configuration: config, delegate: self, delegateQueue: nil)
    }

    func startDownload(from url: URL) {
        let task = session.downloadTask(with: url)
        task.resume()
    }

    func pauseDownload(task: URLSessionDownloadTask) {
        task.cancel(byProducingResumeData: { data in
            self.resumeData = data
        })
    }

    func resumeDownload() {
        guard let resumeData = resumeData else { return }
        let task = session.downloadTask(withResumeData: resumeData)
        task.resume()
    }
}

extension ResumableDownloadManager: URLSessionDownloadDelegate {
    func urlSession(
        _ session: URLSession,
        downloadTask: URLSessionDownloadTask,
        didFinishDownloadingTo location: URL
    ) {
        resumeData = nil
        let dest = FileManager.default.urls(
            for: .documentDirectory, in: .userDomainMask
        )[0].appendingPathComponent(downloadTask.response?.suggestedFilename ?? "file")
        try? FileManager.default.copyItem(at: location, to: dest)
    }
}
```

### 4.3 在 App 启动时处理后台下载完成

```swift
@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

class AppDelegate: NSObject, UIApplicationDelegate {
    func application(
        _ application: UIApplication,
        handleEventsForBackgroundURLSession identifier: String,
        completionHandler: @escaping () -> Void
    ) {
        DownloadManager.shared.backgroundCompletionHandler = completionHandler
    }
}
```

> 💡 **注意**：系统在后台下载完成后会唤醒 App，必须保存并调用 `completionHandler`，否则系统会认为 App 没有正确处理，可能影响后续调度。

## 5. 后台定位与区域监控

### 5.1 位置权限

| 权限级别 | Info.plist 键 | 说明 |
|---------|--------------|------|
| When In Use | NSLocationWhenInUseUsageDescription | 前台使用 |
| Always | NSLocationAlwaysAndWhenInUseUsageDescription | 前后台均可 |

> ⚠️ **注意**：从 iOS 13 起，即使请求 Always 权限，用户首次也只能授予 When In Use。App 需要再次请求才能升级为 Always。

### 5.2 后台持续定位

```swift
import CoreLocation

class LocationManager: NSObject, ObservableObject, CLLocationManagerDelegate {
    private let manager = CLLocationManager()
    @Published var currentLocation: CLLocation?

    override init() {
        super.init()
        manager.delegate = self
        manager.desiredAccuracy = kCLLocationAccuracyBest
        manager.allowsBackgroundLocationUpdates = true
        manager.pausesLocationUpdatesAutomatically = true
        manager.showsBackgroundLocationIndicator = true
        manager.requestAlwaysAuthorization()
    }

    func startUpdating() {
        manager.startUpdatingLocation()
    }

    func locationManager(_ manager: CLLocationManager, didUpdateLocations locations: [CLLocation]) {
        currentLocation = locations.last
        if let location = currentLocation {
            print("📍 位置更新: \(location.coordinate.latitude), \(location.coordinate.longitude)")
        }
    }
}
```

### 5.3 Significant Location Changes（重大位置变化）

当不需要精确轨迹，只需知道用户"换了一个区域"时使用。这种方式极其省电，就像你只关心"从家到公司"，而不是每一步的精确位置。

```swift
func startSignificantLocationChanges() {
    manager.startMonitoringSignificantLocationChanges()
}
```

| 对比项 | 标准定位 | Significant Location Changes |
|--------|---------|------------------------------|
| 精度 | 高（米级） | 低（基站/Wi-Fi 级） |
| 耗电 | 高 | 极低 |
| 频率 | 持续更新 | 仅重大变化时 |
| 需要权限 | Always | Always |
| 能唤醒 App | ❌ | ✅（即使 Terminated） |

### 5.4 区域监控

```swift
func monitorRegion(latitude: Double, longitude: Double, radius: Double, identifier: String) {
```

## 6. 后台音频播放

### 6.1 AVAudioSession 配置

后台音频就像"电台广播"——只要你真的在播放声音，系统就允许你留在后台。

```swift
import AVFoundation

class AudioPlayerManager: ObservableObject {
    private var player: AVAudioPlayer?

    func configureSession() {
        do {
            let session = AVAudioSession.sharedInstance()
            try session.setCategory(.playback, mode: .default, options: [])
            try session.setActive(true)
            print("✅ 音频会话配置成功")
        } catch {
            print("❌ 音频会话配置失败: \(error)")
        }
    }

    func play(url: URL) {
        do {
            player = try AVAudioPlayer(contentsOf: url)
            player?.play()
        } catch {
            print("❌ 播放失败: \(error)")
        }
    }

    func stop() {
        player?.stop()
        try? AVAudioSession.sharedInstance().setActive(false)
    }
}
```

### 6.3 Audio Category 对比

| Category | 后台播放 | 静音开关 | 场景 |
|----------|---------|---------|------|
| `.ambient` | ❌ | 遵循 | 游戏音效 |
| `.playback` | ✅ | 忽略 | 音乐播放器 |
| `.playAndRecord` | ✅ | 遵循 | 语音通话 |
| `.recording` | ❌ | 遵循 | 录音 |

> ⚠️ **关键**：`.playback` 类别是后台播放的必要条件。如果使用 `.ambient`，切到后台后音频会被系统暂停。同时必须在 Info.plist 中声明 `audio` 后台模式。

## 7. 静默推送唤醒

### 7.1 什么是静默推送？

静默推送就像"悄悄话"——用户看不到任何通知，但 App 被唤醒执行任务。它通过设置 `content-available: 1` 实现。

### 7.2 服务端推送格式

```json
{
    "aps": {
        "content-available": 1
    },
    "action": "refresh_data",
    "data_id": "12345"
}
```

### 7.3 客户端处理

```swift
class AppDelegate: NSObject, UIApplicationDelegate, UNUserNotificationCenterDelegate {
    func application(
        _ application: UIApplication,
        didReceiveRemoteNotification userInfo: [AnyHashable: Any],
        fetchCompletionHandler completionHandler: @escaping (UIBackgroundFetchResult) -> Void
    ) {
        guard let aps = userInfo["aps"] as? [String: Any],
              aps["content-available"] as? Int == 1 else {
            completionHandler(.noData)
            return
        }

        let action = userInfo["action"] as? String ?? ""

        switch action {
        case "refresh_data":
            refreshData { success in
                completionHandler(success ? .newData : .failed)
            }
        default:
            completionHandler(.noData)
        }
    }

    func refreshData(completion: @escaping (Bool) -> Void) {
        guard let url = URL(string: "https://api.example.com/sync") else {
            completion(false)
            return
        }
        URLSession.shared.dataTask(with: url) { data, _, error in
            guard data != nil, error == nil else {
                completion(false)
                return
            }
            completion(true)
        }.resume()
    }
}
```

### 7.4 静默推送 vs Background Fetch

| 对比项 | 静默推送 | Background Fetch |
|--------|---------|-----------------|
| 触发方式 | 服务器主动推送 | 系统根据使用习惯调度 |
| 实时性 | 高（秒级） | 低（可能数小时） |
| 可控性 | 服务端完全控制 | 系统决定时机 |
| 频率限制 | 有（系统会限流） | 有（系统根据配额） |
| 需要服务器 | ✅ | ❌ |
| 适用场景 | 即时数据同步 | 定期内容预取 |

> 💡 **最佳实践**：两者结合使用——静默推送处理紧急更新，Background Fetch 处理常规预取。

## 8. SwiftUI 中监听 App 生命周期

### 8.1 scenePhase 环境变量

SwiftUI 提供了 `@Environment(\.scenePhase)` 来监听 App 前后台切换，就像给 App 装了一个"门铃"——每次进出都会响。

```swift
import SwiftUI

struct ContentView: View {
    @Environment(\.scenePhase) var scenePhase

    var body: some View {
        VStack {
            Text("当前状态: \(scenePhaseDescription)")
                .font(.title2)
        }
        .onChange(of: scenePhase) { oldPhase, newPhase in
            switch newPhase {
            case .active:
                print("🟢 进入前台活跃")
                resumeTasks()
            case .inactive:
                print("🟡 失去焦点")
            case .background:
                print("🔴 进入后台")
                saveState()
                scheduleBackgroundTasks()
            @unknown default:
                break
            }
        }
    }

    var scenePhaseDescription: String {
        switch scenePhase {
        case .active: return "活跃"
        case .inactive: return "非活跃"
        case .background: return "后台"
        default: return "未知"
        }
    }

    func saveState() {
        UserDefaults.standard.set(Date(), forKey: "lastBackgroundTime")
    }

    func resumeTasks() {
        if let lastTime = UserDefaults.standard.object(forKey: "lastBackgroundTime") as? Date {
            let interval = Date().timeIntervalSince(lastTime)
            print("⏱ 后台停留: \(Int(interval)) 秒")
        }
    }

    func scheduleBackgroundTasks() {
        let request = BGAppRefreshTaskRequest(identifier: "com.example.app.refresh")
        request.earliestBeginDate = Date(timeIntervalSinceNow: 15 * 60)
        try? BGTaskScheduler.shared.submit(request)
    }
}
```

### 8.2 使用 NotificationCenter 监听

对于需要更细粒度控制的场景，可以使用 NotificationCenter：

```swift
struct LifecycleMonitor: View {
    var body: some View {
        Text("生命周期监控")
            .onAppear {
                addNotificationObservers()
            }
    }

    func addNotificationObservers() {
        NotificationCenter.default.addObserver(
            forName: UIApplication.didEnterBackgroundNotification,
            object: nil, queue: .main
        ) { _ in
            print("📱 App 进入后台")
        }

        NotificationCenter.default.addObserver(
            forName: UIApplication.willEnterForegroundNotification,
            object: nil, queue: .main
        ) { _ in
            print("📱 App 即将进入前台")
        }

        NotificationCenter.default.addObserver(
            forName: UIApplication.didBecomeActiveNotification,
            object: nil, queue: .main
        ) { _ in
            print("📱 App 变为活跃")
        }

        NotificationCenter.default.addObserver(
            forName: UIApplication.willResignActiveNotification,
            object: nil, queue: .main
        ) { _ in
            print("📱 App 即将失去焦点")
        }

        NotificationCenter.default.addObserver(
            forName: UIApplication.didReceiveMemoryWarningNotification,
            object: nil, queue: .main
        ) { _ in
            print("⚠️ 收到内存警告")
            clearCache()
        }
    }

    func clearCache() {
        let cacheURL = FileManager.default.urls(
            for: .cachesDirectory, in: .userDomainMask
        )[0]
        try? FileManager.default.removeItem(at: cacheURL)
    }
}
```

### 8.3 scenePhase vs NotificationCenter

| 对比项 | scenePhase | NotificationCenter |
|--------|-----------|-------------------|
| 框架 | SwiftUI 原生 | UIKit 传统方式 |
| 声明方式 | @Environment | addObserver |
| 粒度 | Scene 级别 | Application 级别 |
| 多窗口 | ✅ 各窗口独立 | ❌ 全局通知 |
| 推荐度 | SwiftUI 项目首选 | 需要兼容 UIKit 时使用 |

## 9. 后台任务最佳实践

### 9.1 省电原则

后台任务最大的敌人不是技术难度，而是电池消耗。遵循以下原则：

| 原则 | 说明 | 示例 |
|------|------|------|
| 最小化网络请求 | 合并请求，减少次数 | 一次请求获取所有数据 |
| 使用增量更新 | 只获取变化的部分 | 带上 lastModified 时间戳 |
| 延迟非紧急操作 | 交给 BGProcessingTask | 数据库清理放夜间 |
| 避免轮询 | 用推送代替轮询 | 静默推送替代定时器 |
| 降低定位精度 | 按需选择精度 | 导航用高精度，打卡用低精度 |

### 9.2 配额管理

iOS 对后台任务有隐式配额，系统根据以下因素决定是否执行你的任务：

```
执行概率 = f(用户使用频率, 任务成功率, 电量, 网络状况)
```

提高执行概率的方法：

```swift
func handleAppRefresh(task: BGAppRefreshTask) {
    scheduleAppRefresh()

    task.expirationHandler = {
        task.setTaskCompleted(success: false)
    }

    let operationQueue = OperationQueue()
    operationQueue.maxConcurrentOperationCount = 1

    let fetchOp = BlockOperation {
        self.fetchNewData { success in
            task.setTaskCompleted(success: success)
        }
    }

    task.expirationHandler = {
        fetchOp.cancel()
        task.setTaskCompleted(success: false)
    }

    operationQueue.addOperation(fetchOp)
}
```

> 💡 **关键**：`setTaskCompleted(success: true)` 告诉系统任务成功完成，系统会提高你 App 的后台配额。频繁返回 `false` 会导致系统降低执行频率。

### 9.3 调试技巧

**模拟后台任务启动（仅模拟器/调试可用）：**

在 Xcode 中运行 App 后，在 Debug 菜单中可以模拟后台任务：

```
Debug → Simulate Background Fetch
```

或使用命令行参数：

```
--bg-task-scheduler-permitted-identifier com.example.app.refresh
```

在代码中强制调度（调试用）：

```swift
#if DEBUG
func simulateBackgroundTask() {
    let task = BGAppRefreshTask(identifier: "com.example.app.refresh")
    handleAppRefresh(task: task)
}
#endif
```

### 9.4 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 任务不执行 | 配额不足或条件不满足 | 检查 earliestBeginDate、连接电源 |
| 任务立即被终止 | expirationHandler 未设置 | 必须设置 expirationHandler |
| 后台定位停止 | pausesLocationUpdatesAutomatically | 设置为 false 或处理暂停 |
| 后台下载不回调 | completionHandler 未调用 | 保存并调用 completionHandler |
| 静默推送收不到 | 频率被系统限流 | 减少推送频率 |
| BGTaskScheduler submit 失败 | 标识符未在 plist 声明 | 检查 BGTaskSchedulerPermittedIdentifiers |

## 10. Info.plist 配置与权限声明

### 10.1 完整配置示例

```xml
<dict>
    <key>UIBackgroundModes</key>
    <array>
        <string>audio</string>
        <string>location</string>
        <string>fetch</string>
        <string>remote-notification</string>
        <string>processing</string>
    </array>

    <key>BGTaskSchedulerPermittedIdentifiers</key>
    <array>
        <string>com.example.app.refresh</string>
        <string>com.example.app.processing</string>
    </array>

    <key>NSLocationWhenInUseUsageDescription</key>
    <string>我们需要您的位置来提供附近的服务信息</string>

    <key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
    <string>我们需要始终访问您的位置以记录运动轨迹</string>

    <key>NSLocationAlwaysUsageDescription</key>
    <string>我们需要始终访问您的位置以提供导航服务</string>
</dict>
```

### 10.2 权限声明对照表

| 后台功能 | UIBackgroundModes 值 | 额外 Info.plist 键 | 运行时权限 |
|---------|---------------------|-------------------|-----------|
| 音频播放 | `audio` | 无 | 无 |
| 后台定位 | `location` | NSLocationAlwaysAndWhenInUseUsageDescription | requestAlwaysAuthorization() |
| 后台刷新 | `fetch` | BGTaskSchedulerPermittedIdentifiers | 无 |
| 静默推送 | `remote-notification` | 无 | 通知权限 |
| 后台处理 | `processing` | BGTaskSchedulerPermittedIdentifiers | 无 |
| VoIP | `voip` | 无 | 无 |
| 蓝牙 | `bluetooth-central` | NSBluetoothAlwaysUsageDescription | CBCentralManager |

### 10.3 Xcode 图形化配置

除了手动编辑 Info.plist，还可以在 Xcode 中：

1. 选择项目 Target → Signing & Capabilities
2. 点击 "+ Capability" → 添加 "Background Modes"
3. 勾选需要的模式
4. 在 Info 标签页添加自定义权限描述

> ⚠️ **警告**：不要声明你不需要的后台模式。App Store 审核会检查后台模式的使用合理性，如果声明了 `audio` 但实际没有播放音频，会被拒审。

## 本章小结

| 主题 | 核心要点 | 关键 API |
|------|---------|---------|
| 后台机制 | iOS 严格限制后台执行，Suspended 后代码不运行 | UIApplicationDelegate 生命周期方法 |
| Background Modes | 按需声明，审核会验证合理性 | UIBackgroundModes |
| BGTaskScheduler | 智能调度，链式提交，必须设置 expirationHandler | BGAppRefreshTask、BGProcessingTask |
| 后台下载 | 系统接管下载进程，App 关闭也不影响 | URLSession background configuration |
| 断点续传 | cancel(byProducingResumeData:) 保存恢复数据 | URLSessionDownloadTask |
| 后台定位 | Always 权限 + allowsBackgroundLocationUpdates | CLLocationManager |
| 区域监控 | 进入/离开地理围栏触发回调 | CLCircularRegion |
| 重大位置变化 | 极省电，能唤醒已终止的 App | startMonitoringSignificantLocationChanges() |
| 后台音频 | .playback 类别 + audio 后台模式 | AVAudioSession |
| 静默推送 | content-available:1，用户无感知 | didReceiveRemoteNotification |
| App 生命周期 | SwiftUI 用 scenePhase，UIKit 用 NotificationCenter | @Environment(\\.scenePhase) |
| 最佳实践 | 省电优先、提高成功率、合理选择模式 | BGTaskScheduler submit + setTaskCompleted |
| Info.plist | 声明后台模式和任务标识符 | UIBackgroundModes、BGTaskSchedulerPermittedIdentifiers |
