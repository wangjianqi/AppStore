## 1. 推送通知概述

### 什么是推送通知？

推送通知就像手机上的"小喇叭"——即使你没有打开 App，App 也能通过它来"喊"你一声，告诉你有新消息、新提醒或者该做某件事了。

想想看：闹钟到了时间会响、微信收到消息会弹窗、外卖 App 告诉你骑手已接单……这些都是推送通知在发挥作用。

### 本地通知 vs 远程通知

推送通知分为两大类，它们的区别就像"自己定闹钟"和"别人打电话叫你起床"：

| 对比项 | 本地通知 | 远程通知 |
|--------|---------|---------|
| 触发方式 | App 自己在本地创建和调度 | 服务器通过网络发送到设备 |
| 需要服务器？ | ❌ 不需要 | ✅ 需要 |
| 需要网络？ | ❌ 不需要 | ✅ 需要 |
| 典型场景 | 闹钟、待办提醒、计时器 | 聊天消息、新闻推送、活动通知 |
| 实时性 | 需提前调度，按时触发 | 服务器随时可发，实时到达 |
| 复杂度 | 较低 | 较高（涉及服务端配置） |
| 框架 | UserNotifications | UserNotifications + APNs |

> 💡 **类比理解**：本地通知就像你在手机上设了个闹钟，到点了自己响；远程通知就像朋友从远方给你发微信消息，你手机立刻收到提醒。

### 使用场景一览

| 场景 | 推荐类型 | 说明 |
|------|---------|------|
| 每天定时提醒喝水 | 本地通知 | 固定时间触发，无需服务器 |
| 倒计时结束提醒 | 本地通知 | 倒计时类 App |
| 聊天收到新消息 | 远程通知 | 实时性要求高，由服务器推送 |
| 新闻/资讯推送 | 远程通知 | 内容来自服务端 |
| 日历事件提醒 | 本地通知 | 基于本地日历数据 |
| 促销活动通知 | 远程通知 | 运营人员从后台发送 |

## 2. 权限请求

### 为什么需要请求权限？

iOS 非常注重用户隐私——App 不能偷偷发通知骚扰用户，必须先获得用户的"许可"。这就像你要在别人的公告栏上贴告示，得先征得主人同意。

### 请求通知权限的完整代码

```swift
import SwiftUI
import UserNotifications

struct ContentView: View {
    var body: some View {
        VStack(spacing: 20) {
            Text("推送通知示例")
                .font(.largeTitle)

            Button("请求通知权限") {
                requestNotificationPermission()
            }
            .buttonStyle(.borderedProminent)
        }
    }

    func requestNotificationPermission() {
        UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .badge, .sound]) { granted, error in
            if granted {
                print("✅ 用户同意了通知权限")
            } else {
                print("❌ 用户拒绝了通知权限")
            }

            if let error = error {
                print("⚠️ 权限请求出错：\(error.localizedDescription)")
            }
        }
    }
}
```

### 权限选项说明

| 选项 | 说明 | 效果 |
|------|------|------|
| `.alert` | 显示通知横幅 | 锁屏/下拉通知中心显示通知内容 |
| `.badge` | App 图标角标 | 图标右上角显示红色数字 |
| `.sound` | 通知提示音 | 收到通知时播放声音 |
| `.criticalAlert` | 紧急警报 | 绕过静音模式（需额外审核） |
| `.carPlay` | 车载显示 | 在 CarPlay 上显示通知 |
| `.providesAppNotificationSettings` | 提供App内通知设置 | 在系统设置中显示跳转到App设置的按钮 |
| `.provisional` | 临时通知 | 通知静默显示在通知中心，不打扰用户 |

> ⚠️ **重要提示**：权限请求弹窗只会出现一次！如果用户拒绝了，只能引导用户去"设置"中手动开启。

### 引导用户前往系统设置

```swift
func openAppSettings() {
    if let url = URL(string: UIApplication.openSettingsURLString) {

            UIApplication.shared.open(url)
```

### 检查当前权限状态

```swift
func checkNotificationPermission() {
    UNUserNotificationCenter.current().getNotificationSettings { settings in
        switch settings.authorizationStatus {
        case .notDetermined:
            print("尚未请求权限")
        case .denied:
            print("用户已拒绝")
        case .authorized, .provisional, .ephemeral:
            print("用户已授权")
        @unknown default:
            break
        }
    }
}
```

> 💡 **最佳实践**：不要在 App 一启动就弹权限请求！应该在用户真正需要通知功能的场景下再请求，比如用户设置了提醒、订阅了消息等，这样用户更容易同意。

## 3. 本地通知实现

### 3.1 创建本地通知的基本步骤

创建本地通知就像寄一封定时信，需要三步：

1. **写内容**（UNMutableNotificationContent）—— 信里写什么
2. **设触发器**（UNTimeIntervalNotificationTrigger 等）—— 什么时候寄出
3. **发请求**（UNNotificationRequest）—— 把信交给邮局

### 3.2 基本示例：5 秒后发送通知

```swift
import UserNotifications

func scheduleSimpleNotification() {
    // 第 1 步：创建通知内容
    let content = UNMutableNotificationContent()
    content.title = "喝水提醒"
    content.body = "你已经很久没喝水了，快去喝一杯吧！💧"
    content.sound = .default

    // 第 2 步：创建触发器（5 秒后触发）
    let trigger = UNTimeIntervalNotificationTrigger(
        timeInterval: 5,
        repeats: false
    )

    // 第 3 步：创建请求
    let request = UNNotificationRequest(
        identifier: "waterReminder",
        content: content,
        trigger: trigger
    )

    // 第 4 步：添加到通知中心
    UNUserNotificationCenter.current().add(request) { error in
        if let error = error {
            print("调度通知失败：\(error.localizedDescription)")
        } else {
            print("✅ 通知已调度，5 秒后触发")
        }
    }
}
```

### 3.3 触发器类型

| 触发器 | 说明 | 示例场景 |
|--------|------|---------|
| `UNTimeIntervalNotificationTrigger` | 从现在起多少秒后触发 | 倒计时结束、延时提醒 |
| `UNCalendarNotificationTrigger` | 指定日期/时间触发 | 每天早上 8 点提醒 |
| `UNLocationNotificationTrigger` | 进入/离开某个区域触发 | 到达超市提醒购物 |
| `UNPushNotificationTrigger` | 由远程推送触发 | 一般不直接使用 |

#### 日历触发器示例：每天早上 8 点提醒

```swift
func scheduleDailyMorningNotification() {
    let content = UNMutableNotificationContent()
    content.title = "早安问候"
    content.body = "新的一天开始了，加油！☀️"
    content.sound = .default

    // 设置触发时间：每天 8:00
    var dateComponents = DateComponents()
    dateComponents.hour = 8
    dateComponents.minute = 0

    let trigger = UNCalendarNotificationTrigger(
        dateMatching: dateComponents,
        repeats: true
    )

    let request = UNNotificationRequest(
        identifier: "morningGreeting",
        content: content,
        trigger: trigger
    )

    UNUserNotificationCenter.current().add(request)
}
```

#### 位置触发器示例：到达某地提醒

```swift
import CoreLocation

func scheduleLocationNotification() {
    let content = UNMutableNotificationContent()
    content.title = "到达超市"
    content.body = "别忘了买牛奶和鸡蛋！🥚"
    content.sound = .default

    // 设置地理围栏：超市周围 100 米
    let center = CLLocationCoordinate2D(latitude: 39.9042, longitude: 116.4074)
    let region = CLCircularRegion(
        center: center,
        radius: 100,
        identifier: "supermarket"
    )
    region.notifyOnEntry = true
    region.notifyOnExit = false

    let trigger = UNLocationNotificationTrigger(
        region: region,
        repeats: true
    )

    let request = UNNotificationRequest(
        identifier: "supermarketReminder",
        content: content,
        trigger: trigger
    )

    UNUserNotificationCenter.current().add(request)
}
```

> ⚠️ **注意**：使用位置触发器需要在项目中配置位置权限（`NSLocationWhenInUseUsageDescription` 或 `NSLocationAlwaysAndWhenInUseUsageDescription`）。

```swift
import SwiftUI
import UserNotifications

@main
struct WaterReminderApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

    func userNotificationCenter(

}

struct ReminderView: View {
    @State private var interval: Double = 3600
    @State private var isScheduled = false
    @State private var permissionGranted = false

        } else {

            return "\(hours) 小时"
        }
    }

    var body: some View {
        NavigationStack {
            VStack(spacing: 30) {
                Image(systemName: "drop.fill")
                    .font(.system(size: 80))
                    .foregroundStyle(.blue)

                Text("喝水提醒")
                    .font(.largeTitle)
                    .bold()

                Text("提醒间隔：\(intervalText)")
                    .font(.title3)
                    .foregroundStyle(.secondary)

                Slider(value: $interval, in: 300...7200, step: 300) {
                    Text("提醒间隔")
                }

                HStack(spacing: 20) {
                    Button(isScheduled ? "取消提醒" : "开始提醒") {
                        if isScheduled {
                            cancelReminder()
                        } else {
                            startReminder()
                        }
                    }
                    .buttonStyle(.borderedProminent)
                    .tint(isScheduled ? .red : .blue)
                }

                if permissionGranted == false {
                    Button("开启通知权限") {
                        requestPermission()
                    }
                    .buttonStyle(.bordered)
                }
            }
            .padding()
            .navigationTitle("喝水提醒")
            .onAppear {
                checkPermission()
            }
        }
    }

    func requestPermission() {
        UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .badge, .sound]) { granted, _ in
            DispatchQueue.main.async {
                permissionGranted = granted
            }
        }
    }

    func checkPermission() {
        UNUserNotificationCenter.current().getNotificationSettings { settings in
            DispatchQueue.main.async {
                permissionGranted = settings.authorizationStatus == .authorized
            }
        }
    }

    func startReminder() {
        let content = UNMutableNotificationContent()
        content.title = "喝水提醒 💧"
        content.body = "该喝水了！保持每天 8 杯水的好习惯。"
        content.sound = .default
        content.badge = NSNumber(value: 1)

        let trigger = UNTimeIntervalNotificationTrigger(
            timeInterval: interval,
            repeats: true
        )

        let request = UNNotificationRequest(
            identifier: "waterReminder",
            content: content,
            trigger: trigger
        )

        UNUserNotificationCenter.current().add(request) { error in
            DispatchQueue.main.async {
                if error == nil {
                    isScheduled = true
                }
            }
        }
    }

    func cancelReminder() {
        UNUserNotificationCenter.current().removePendingNotificationRequests(withIdentifiers: ["waterReminder"])
        isScheduled = false
    }
}
```

## 4. 远程通知（APNs）

### 4.1 什么是 APNs？

APNs（Apple Push Notification service）是苹果提供的远程推送服务。它就像一个"传话员"——你的服务器把消息告诉 APNs，APNs 再把消息转达给用户的 iPhone。

```
你的服务器  →  APNs（苹果推送服务器）  →  用户的 iPhone
  发消息         中转传递                  收到通知
```

> 💡 **类比理解**：APNs 就像一个邮局。你（服务器）把信交给邮局（APNs），邮局负责把信送到收件人（用户设备）手里。你不需要知道收件人住哪，邮局知道怎么送。

### 4.2 远程通知配置流程

配置远程通知比本地通知复杂得多，需要多个步骤：

| 步骤 | 说明 | 在哪操作 |
|------|------|---------|
| 1. 开启推送能力 | 在项目中启用 Push Notifications | Xcode → Signing & Capabilities |
| 2. 获取设备 Token | App 向 APNs 注册获取唯一标识 | 代码中实现 |
| 3. 配置认证方式 | 选择证书认证或 Token 认证 | Apple Developer 网站 |
| 4. 搭建推送服务 | 服务端向 APNs 发送推送请求 | 你的服务器 |
| 5. 处理收到的通知 | App 接收并处理远程通知 | 代码中实现 |

### 4.3 在 Xcode 中开启推送能力

1. 打开 Xcode 项目
2. 选择项目 Target → Signing & Capabilities
3. 点击 "+ Capability"
4. 搜索并添加 "Push Notifications"
5. 同时添加 "Background Modes"，勾选 "Remote notifications"

### 4.5 认证方式对比

| 对比项 | 证书认证（.p8） | Token 认证（.p8 Key） |
|--------|----------------|---------------------|
| 文件格式 | .cer / .p12 | .p8 |
| 有效期 | 1 年需续期 | 不会过期（Key 本身） |
| 配置复杂度 | 较高 | 较低 |
| 推荐程度 | 旧方式，不推荐 | ✅ 苹果推荐 |
| 支持多环境 | 需要分别配置 | 一个 Key 支持所有 App |

### 4.6 服务端推送基础（伪代码）

```python
# Python 示例：使用 http2 向 APNs 发送推送
import httpx
import jwt
import time

# 1. 生成 JWT Token
def create_jwt(key_id, team_id, key_path):
    with open(key_path, 'r') as f:
        key = f.read()

    token = jwt.encode(
        {
            'iss': team_id,
            'iat': int(time.time())
        },
        key,
        algorithm='ES256',
        headers={'kid': key_id}
    )
    return token

# 2. 发送推送
async def send_push(device_token, title, body, jwt_token):
    headers = {
        'authorization': f'bearer {jwt_token}',
        'apns-topic': 'com.yourapp.bundleid',
        'apns-push-type': 'alert'
    }

    payload = {
        'aps': {
            'alert': {
                'title': title,
                'body': body
            },
            'sound': 'default',
            'badge': 1
        }
    }

    async with httpx.AsyncClient(http2=True) as client:
        response = await client.post(
            f'https://api.push.apple.com/3/device/{device_token}',
            json=payload,
            headers=headers
        )
        print(f"推送结果: {response.status_code}")
```

> 💡 **提示**：服务端推送开发通常由后端工程师负责，iOS 开发者主要确保 App 端正确获取 Token 和处理通知即可。实际项目中可使用第三方推送服务（如极光推送、个推等）来简化服务端开发。

## 5. 通知内容定制

### 5.1 通知内容字段说明

| 字段 | 说明 | 显示位置 |
|------|------|---------|
| `title` | 通知标题 | 第一行，加粗显示 |

### 5.2 添加图片附件

通知中可以添加图片，让通知更醒目。就像信封上贴了张照片，一眼就知道是什么内容。

```swift
func createNotificationWithImage() {
    let content = UNMutableNotificationContent()
    content.title = "今日推荐"
    content.body = "新鲜草莓上市了，限时特价！"
    content.sound = .default

    // 添加图片附件
    if let imageURL = Bundle.main.url(forResource: "strawberry", withExtension: "jpg") {
        do {
            let attachment = try UNNotificationAttachment(
                identifier: "productImage",
                url: imageURL,
                options: [
                    UNNotificationAttachmentOptionsTypeHintKey: "public.jpeg"
                ]
            )
            content.attachments = [attachment]
        } catch {
            print("添加图片附件失败：\(error)")
        }
    }

    let trigger = UNTimeIntervalNotificationTrigger(timeInterval: 5, repeats: false)
    let request = UNNotificationRequest(identifier: "productNotification", content: content, trigger: trigger)
    UNUserNotificationCenter.current().add(request)
}
```

> ⚠️ **注意**：图片附件大小有限制——图片最大 10MB，音频最大 5MB，视频最大 50MB。图片会自动裁剪为合适尺寸。

### 5.3 添加操作按钮

通知可以添加自定义操作按钮，让用户不用打开 App 就能快速响应。就像快递到了，你可以直接在通知上点"签收"或"拒收"。

#### 第一步：定义操作类别和按钮

```swift
func setupNotificationCategories() {
    // 定义操作按钮
    let acceptAction = UNNotificationAction(
        identifier: "ACCEPT_ACTION",
        title: "接受",
        options: [.foreground]
    )

    let declineAction = UNNotificationAction(
        identifier: "DECLINE_ACTION",
        title: "拒绝",
        options: [.destructive]
    )

    let replyAction = UNTextInputNotificationAction(
        identifier: "REPLY_ACTION",
        title: "回复",
        options: [],
        textInputButtonTitle: "发送",
        textInputPlaceholder: "输入回复内容..."
    )

    // 将操作分组为类别
    let category = UNNotificationCategory(
        identifier: "INVITE_CATEGORY",
        actions: [acceptAction, declineAction, replyAction],
        intentIdentifiers: [],
        options: .customDismissAction
    )

    // 注册类别
    UNUserNotificationCenter.current().setNotificationCategories([category])
}
```

#### 第三步：处理按钮点击

```swift
class AppDelegate: NSObject, UIApplicationDelegate, UNUserNotificationCenterDelegate {
    func userNotificationCenter(
        _ center: UNUserNotificationCenter,
        didReceive response: UNNotificationResponse
    ) async {
        let actionIdentifier = response.actionIdentifier
        let userInfo = response.notification.request.content.userInfo

        switch actionIdentifier {
        case "ACCEPT_ACTION":
            print("✅ 用户接受了邀请")
            handleAccept(userInfo)
        case "DECLINE_ACTION":
            print("❌ 用户拒绝了邀请")
            handleDecline(userInfo)
        case "REPLY_ACTION":
            if let textResponse = response as? UNTextInputNotificationResponse {
                let replyText = textResponse.userText
                print("💬 用户回复：\(replyText)")
                handleReply(replyText, userInfo)
            }
        default:
            print("用户点击了通知本身")
            handleNotificationTap(userInfo)
        }
    }
}
```

### 5.4 操作按钮选项说明

| 选项 | 说明 |
|------|------|
| `.foreground` | 点击后打开 App 到前台 |
| `.destructive` | 红色危险操作样式 |
| `.authenticationRequired` | 需要解锁设备才能执行 |
| `.none` | 无特殊选项 |

## 6. 通知点击处理

当用户点击通知时，App 可能处于三种状态，处理方式各不相同：

| App 状态 | 触发方法 | 说明 |
|----------|---------|------|
| 前台运行 | `willPresent` | App 正在使用，通知到达 |
| 后台运行 | `didReceive` | App 在后台，用户点击通知 |
| 未启动 | `didReceive` | App 已终止，点击通知启动 App |

> 💡 **类比理解**：就像你在家（前台）、出门了（后台）、睡着了（未启动）三种状态下，快递员敲门（通知到达）你的反应不同。

### 6.1 前台收到通知

当 App 在前台时，默认不会显示通知横幅。需要通过 `willPresent` 方法来决定如何展示：

```swift
func userNotificationCenter(
    _ center: UNUserNotificationCenter,
    willPresent notification: UNNotification
) async -> UNNotificationPresentationOptions {
    let userInfo = notification.request.content.userInfo
    print("📱 前台收到通知：\(userInfo)")

    // 返回要展示的方式
    return [.banner, .sound, .badge]
}
```

| 返回选项 | 效果 |
|---------|------|
| `.banner` | 显示通知横幅 |
| `.sound` | 播放提示音 |
| `.badge` | 更新角标 |
| `.list` | 在通知中心列表显示 |

### 6.2 后台/未启动时点击通知

无论是后台还是未启动状态，用户点击通知后都会调用 `didReceive` 方法：

```swift
func userNotificationCenter(
    _ center: UNUserNotificationCenter,
    didReceive response: UNNotificationResponse
) async {
    let userInfo = response.notification.request.content.userInfo
    let actionIdentifier = response.actionIdentifier

    // 区分是点击了通知本身还是操作按钮
    if actionIdentifier == UNNotificationDefaultActionIdentifier {
        print("👆 用户点击了通知本身")
        handleNotificationTap(userInfo: userInfo)
    }
}
```

### 6.3 完整处理示例：根据通知跳转页面

```swift
import SwiftUI

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate
    @StateObject var navigationState = NavigationState()

    var body: some Scene {
        WindowGroup {
            ContentView()
                .environmentObject(navigationState)
        }
    }
}

class NavigationState: ObservableObject {
    @Published var selectedTab: Int = 0
    @Published var targetChatId: String?
}

class AppDelegate: NSObject, UIApplicationDelegate, UNUserNotificationCenterDelegate {
    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        UNUserNotificationCenter.current().delegate = self

        if let notification = launchOptions?[.remoteNotification] as? [String: Any] {
            print("App 通过通知启动")
        }

        return true
    }

    func userNotificationCenter(
        _ center: UNUserNotificationCenter,
        willPresent notification: UNNotification
    ) async -> UNNotificationPresentationOptions {
        handleIncomingNotification(notification.request.content.userInfo)
        return [.banner, .sound, .badge]
    }

    func userNotificationCenter(
        _ center: UNUserNotificationCenter,
        didReceive response: UNNotificationResponse
    ) async {
        let userInfo = response.notification.request.content.userInfo
        handleIncomingNotification(userInfo)
    }

    func handleIncomingNotification(_ userInfo: [AnyHashable: Any]) {
        guard let type = userInfo["type"] as? String else { return }

        switch type {
        case "chat":
            NotificationCenter.default.post(
                name: .navigateToChat,
                object: nil,
                userInfo: userInfo
            )
        case "order":
            NotificationCenter.default.post(
                name: .navigateToOrder,
                object: nil,
                userInfo: userInfo
            )
        default:
            break
        }
    }
}

extension Notification.Name {
    static let navigateToChat = Notification.Name("navigateToChat")
    static let navigateToOrder = Notification.Name("navigateToOrder")
}
```

### 6.4 处理流程图

```
通知到达
  │
  ├─ App 在前台 ──→ willPresent 被调用
  │                   ├─ 返回 [.banner] → 显示横幅
  │                   └─ 返回 [] → 静默处理
  │
  ├─ App 在后台 ──→ 系统显示通知
  │                   └─ 用户点击 → didReceive 被调用
  │
  └─ App 未运行 ──→ 系统显示通知
                      └─ 用户点击 → App 启动 → didReceive 被调用
```

## 7. 通知最佳实践

### 7.1 频率控制

没有人喜欢被通知轰炸。推送频率要合理，就像朋友发消息——偶尔问候很贴心，每分钟一条就是骚扰了。

| 原则 | 说明 | 建议 |
|------|------|------|
| 控制频率 | 不要短时间内连续推送 | 同类通知每天不超过 3-5 条 |
| 合并通知 | 多条同类消息合并为一条 | 使用 `UNNotification` 的线程标识符 |
| 避免深夜推送 | 尊重用户休息时间 | 22:00 - 8:00 不推送 |
| 提供关闭选项 | 让用户自主选择 | App 内提供通知偏好设置 |

### 7.2 合并同类通知

```swift
func scheduleGroupedNotifications() {
    // 第一条消息
    let content1 = UNMutableNotificationContent()
    content1.title = "张三"
    content1.body = "在吗？"
    content1.sound = .default
    content1.threadIdentifier = "chat_group_123"

    // 第二条消息
    let content2 = UNMutableNotificationContent()
    content2.title = "李四"
    content2.body = "明天有空吗？"
    content2.sound = .default
    content2.threadIdentifier = "chat_group_123"

    // 相同 threadIdentifier 的通知会自动分组显示
    let trigger = UNTimeIntervalNotificationTrigger(timeInterval: 2, repeats: false)
    UNUserNotificationCenter.current().add(
        UNNotificationRequest(identifier: "msg1", content: content1, trigger: trigger)
    )
    UNUserNotificationCenter.current().add(
        UNNotificationRequest(identifier: "msg2", content: content2, trigger: trigger)
    )
}
```

### 7.4 用户通知偏好设置页面

```swift
struct NotificationSettingsView: View {
    @AppStorage("enableDailyReminder") var enableDailyReminder = true
    @AppStorage("enablePromotion") var enablePromotion = false
    @AppStorage("reminderTime") var reminderTime = Date()
    @AppStorage("enableSound") var enableSound = true

    var body: some View {
        Form {
            Section("提醒通知") {
                Toggle("每日提醒", isOn: $enableDailyReminder)
                    .onChange(of: enableDailyReminder) { _, newValue in
                        if newValue {
                            scheduleDailyReminder()
                        } else {
                            cancelDailyReminder()
                        }
                    }

                if enableDailyReminder {
                    DatePicker("提醒时间", selection: $reminderTime, displayedComponents: .hourAndMinute)
                        .onChange(of: reminderTime) { _, _ in
                            scheduleDailyReminder()
                        }
                }
            }

            Section("其他通知") {
                Toggle("促销活动", isOn: $enablePromotion)
                Toggle("通知声音", isOn: $enableSound)
            }

            Section {
                Button("前往系统通知设置") {
                    if let url = URL(string: UIApplication.openSettingsURLString) {
                        UIApplication.shared.open(url)
                    }
                }
            }
        }
        .navigationTitle("通知设置")
    }

    func scheduleDailyReminder() {
        UNUserNotificationCenter.current().removePendingNotificationRequests(withIdentifiers: ["dailyReminder"])

        guard enableDailyReminder else { return }

        let content = UNMutableNotificationContent()
        content.title = "每日提醒"
        content.body = "别忘了完成今天的任务！"
        content.sound = enableSound ? .default : nil

        let calendar = Calendar.current
        let components = calendar.dateComponents([.hour, .minute], from: reminderTime)

        let trigger = UNCalendarNotificationTrigger(dateMatching: components, repeats: true)
        let request = UNNotificationRequest(identifier: "dailyReminder", content: content, trigger: trigger)
        UNUserNotificationCenter.current().add(request)
    }

    func cancelDailyReminder() {
        UNUserNotificationCenter.current().removePendingNotificationRequests(withIdentifiers: ["dailyReminder"])
    }
}
```

## 8. 国内推送注意

### 8.1 为什么国内推送不一样？

在中国大陆，Google 的 FCM（Firebase Cloud Messaging）不可用，而苹果的 APNs 在国内可以正常使用。但问题在于——**当 App 被用户强制杀掉后，APNs 仍然可以送达通知，但很多国内 App 需要在后台持续保活来接收消息**。

此外，国内 Android 生态碎片化，各手机厂商都有自己的推送通道，iOS 开发者虽然主要面对 APNs，但如果你的 App 同时有 Android 版本，就需要了解各厂商通道。

### 8.2 国内厂商推送通道简介

| 厂商 | 推送服务 | 特点 |
|------|---------|------|
| 华为 | HMS Push（华为推送） | 系统级通道，杀后台也能收到 |
| 小米 | MiPush（小米推送） | MIUI 系统级通道 |
| OPPO | OPPO Push | ColorOS 系统级通道 |
| vivo | vivo Push | OriginOS 系统级通道 |
| 通用 | 极光推送、个推、信鸽 | 聚合多家厂商通道，一次接入全覆盖 |

### 8.3 iOS 开发者的注意事项

对于纯 iOS 开发，你只需要关注 APNs。但以下情况需要注意：

| 注意事项 | 说明 |
|---------|------|
| APNs 在国内可用 | ✅ 不需要额外配置，APNs 在中国大陆正常工作 |
| 服务器部署位置 | 建议使用国内云服务器，减少推送延迟 |
| 使用第三方推送服务 | 极光推送、个推等提供统一的 SDK，简化开发 |
| 合规要求 | 推送内容需符合国内法规，不能推送违法违规内容 |
| 用户隐私 | 收集设备 Token 等信息需在隐私政策中说明 |

### 8.4 常用第三方推送服务对比

| 服务 | 支持平台 | 免费额度 | 特点 |
|------|---------|---------|------|
| 极光推送（JPush） | iOS / Android | 一定免费额度 | 国内最流行，文档齐全 |
| 个推 | iOS / Android | 一定免费额度 | 老牌推送服务 |
| 信鸽（腾讯） | iOS / Android | 一定免费额度 | 腾讯出品，与微信生态打通 |
| 阿里云推送 | iOS / Android | 按量计费 | 阿里云生态集成 |

> 💡 **建议**：对于个人开发者或小团队，如果只需要 iOS 推送，直接使用 APNs 即可，无需接入第三方服务。如果需要同时支持 iOS 和 Android，且要适配国内各厂商通道，建议使用极光推送等第三方聚合服务。

### 8.5 极光推送 iOS 集成示例（简要）

```swift
// 在 AppDelegate 中集成极光推送
import JCore
import JPush

class AppDelegate: NSObject, UIApplicationDelegate, JPUSHRegisterDelegate {
    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        // 初始化极光推送
        let entity = JPUSHRegisterEntity()
        entity.types = Int(UNAuthorizationOptions.alert.rawValue |
                           UNAuthorizationOptions.badge.rawValue |
                           UNAuthorizationOptions.sound.rawValue)
        JPUSHService.register(forRemoteNotificationConfig: entity, delegate: self)

        // 启动极光 SDK
        JPUSHService.setup(
            withOption: launchOptions,
            appKey: "你的 AppKey",
            channel: "App Store",
            apsForProduction: false
        )

        JPUSHService.registrationIDCompletionHandler { resCode, registrationID in
            if resCode == 0 {
                print("📱 极光 Registration ID: \(registrationID ?? "")")
            }
        }

        return true
    }

    func application(
        _ application: UIApplication,
        didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data
    ) {
        JPUSHService.registerDeviceToken(deviceToken)
    }

    // 极光推送回调
    func jpushNotificationCenter(
        _ center: UNUserNotificationCenter!,
        didReceive response: UNNotificationResponse!,
        withUserInfo userInfo: [AnyHashable: Any]!
    ) {
        print("收到极光推送：\(userInfo)")
    }
}
```

## 小结

| 知识点 | 核心内容 |
|--------|---------|
| 推送通知概述 | 本地通知由 App 自行调度，远程通知由服务器通过 APNs 推送 |
| 权限请求 | 使用 `UNUserNotificationCenter.requestAuthorization()` 请求权限，注意不要在启动时立即请求 |
| 本地通知 | 内容 + 触发器 + 请求 = 本地通知三要素；支持时间、日历、位置三种触发器 |
| 远程通知 | 需要获取设备 Token、配置 APNs 认证、搭建推送服务端 |
| 内容定制 | 可设置标题/副标题/正文、添加图片附件、自定义操作按钮 |
| 点击处理 | 前台用 `willPresent`，后台/未启动用 `didReceive`，根据 userInfo 跳转页面 |
| 最佳实践 | 控制频率、合并通知、个性化内容、提供偏好设置 |
| 国内推送 | iOS 只需关注 APNs；Android 需适配各厂商通道；可用第三方聚合服务简化开发 |

> 💡 **学习建议**：先从本地通知入手，这是最简单也最常用的方式。等本地通知熟练后，再尝试配置远程通知。远程通知涉及服务端开发，可以先用第三方推送服务（如极光推送）降低门槛。
