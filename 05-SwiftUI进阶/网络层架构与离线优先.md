# 网络层架构与离线优先

> 🎯 **本章目标**：掌握工程级网络层架构设计，学会 API Client 封装与请求拦截器模式，理解缓存策略与离线优先架构，能够处理请求重试、竞态、取消等复杂场景，构建健壮的网络层。

---

## 从基础到工程：为什么需要网络层架构

### 基础 URLSession 的局限性

在前一章中，我们学会了用 URLSession 发起网络请求、解析 JSON、处理加载状态。这些知识足以完成一个 Demo，但在真实工程中，你会发现以下问题：

- 每个请求都要重复编写 URL 构建、Header 拼接、错误处理代码
- Token 过期后需要手动刷新，散落在各个请求调用处
- 没有统一的日志记录，调试网络问题如同大海捞针
- 请求失败后缺少自动重试机制，用户体验差
- 弱网环境下 App 直接崩溃或白屏，没有任何降级方案

基础 URLSession 就像一把锤子——能钉钉子，但盖房子还需要脚手架、搅拌机和安全网。

### 工程级网络层需要解决的问题

| 问题 | 基础方案 | 工程方案 |
|------|----------|----------|
| 请求配置重复 | 每次手动拼接 URL/Header | APIRequest 协议 + 请求构建器 |
| 认证 Token 管理 | 手动添加 Authorization | 认证拦截器自动附加 |
| 请求/响应日志 | print 散落各处 | 日志拦截器统一记录 |
| 错误重试 | 用户手动刷新 | 指数退避自动重试 |
| 缓存 | 无缓存，每次重新请求 | 双层缓存 + HTTP 缓存策略 |
| 离线支持 | 无网络即白屏 | 离线优先架构 + 本地数据库 |
| 请求取消 | 不处理 | Task 取消 + 竞态处理 |
| 可测试性 | 无法单元测试 | Mock URLProtocol 注入 |

### 网络层架构的核心原则

1. **单一职责**：每个组件只做一件事——请求构建、拦截、发送、缓存、解析各司其职
2. **开闭原则**：通过拦截器/中间件扩展功能，而不是修改核心代码
3. **依赖倒转**：上层依赖抽象协议，不依赖具体 URLSession 实现，方便测试和替换
4. **声明式请求**：用类型描述"我要什么"，而不是"怎么做"
5. **离线优先**：始终假设网络不可靠，本地数据作为唯一真相源

## API Client 封装

### 请求模型设计：APIRequest 协议

工程级网络层的第一步，是用协议声明"一个请求长什么样"：

```swift
enum HTTPMethod: String {
    case get = "GET"
    case post = "POST"
    case put = "PUT"
    case delete = "DELETE"
    case patch = "PATCH"
}

protocol APIRequest {
    associatedtype Response: Decodable

    var path: String { get }
    var method: HTTPMethod { get }
    var headers: [String: String] { get }
    var queryItems: [URLQueryItem] { get }
    var body: Encodable? { get }
}

extension APIRequest {
    var method: HTTPMethod { .get }
    var headers: [String: String] { [:] }
    var queryItems: [URLQueryItem] { [] }
    var body: Encodable? { nil }
}
```

`associatedtype Response` 让每个请求类型自带其响应类型，编译器会在解码阶段检查类型安全。

### 响应模型设计：APIResponse 泛型

```swift
struct APIResponse<T> {
    let data: T
    let statusCode: Int
    let headers: [String: String]
}

enum APIError: Error, LocalizedError {
    case invalidURL
    case networkError(Error)
    case invalidResponse(statusCode: Int)
    case decodingError(Error)
    case unauthorized
    case serverError(String)
    case timeout

    var errorDescription: String? {
        switch self {
        case .invalidURL:
            return "无效的请求地址"
        case .networkError(let error):
            return "网络错误：\(error.localizedDescription)"
        case .invalidResponse(let statusCode):
            return "服务器返回异常状态码：\(statusCode)"
        case .decodingError(let error):
            return "数据解析失败：\(error.localizedDescription)"
        case .unauthorized:
            return "认证已过期，请重新登录"
        case .serverError(let message):
            return "服务器错误：\(message)"
        case .timeout:
            return "请求超时，请检查网络连接"
        }
    }
}
```

### APIClient 核心实现

```swift
actor APIClient {
    let baseURL: URL
    let session: URLSession
    let interceptors: [any Interceptor]

    init(
        baseURL: URL,
        session: URLSession = .shared,
        interceptors: [any Interceptor] = []
    ) {
        self.baseURL = baseURL
        self.session = session
        self.interceptors = interceptors
    }

    func send<R: APIRequest>(_ request: R) async throws -> APIResponse<R.Response> {
        var urlRequest = try buildURLRequest(from: request)

        for interceptor in interceptors {
            urlRequest = await interceptor.intercept(request: urlRequest)
        }

        let (data, urlResponse) = try await session.data(for: urlRequest)

        guard let httpResponse = urlResponse as? HTTPURLResponse else {
            throw APIError.invalidResponse(statusCode: -1)
        }

        switch httpResponse.statusCode {
        case 200...299:
            let decoded = try JSONDecoder().decode(R.Response.self, from: data)
            return APIResponse(
                data: decoded,
                statusCode: httpResponse.statusCode,
                headers: httpResponse.allHeaderFields as? [String: String] ?? [:]
            )
        case 401:
            throw APIError.unauthorized
        case 400...499:
            throw APIError.invalidResponse(statusCode: httpResponse.statusCode)
        case 500...599:
            let message = String(data: data, encoding: .utf8) ?? "未知错误"
            throw APIError.serverError(message)
        default:
            throw APIError.invalidResponse(statusCode: httpResponse.statusCode)
        }
    }

    private func buildURLRequest<R: APIRequest>(from request: R) throws -> URLRequest {
        var components = URLComponents(url: baseURL.appendingPathComponent(request.path), resolvingAgainstBaseURL: false)
        components?.queryItems = request.queryItems.isEmpty ? nil : request.queryItems

        guard let url = components?.url else {
            throw APIError.invalidURL
        }

        var urlRequest = URLRequest(url: url)
        urlRequest.httpMethod = request.method.rawValue
        urlRequest.allHTTPHeaderFields = request.headers

        if let body = request.body {
            urlRequest.httpBody = try JSONEncoder().encode(body)
        }

        return urlRequest
    }
}
```

> 💡 **提示**：使用 `actor` 而非 `class` 确保 APIClient 的线程安全。在并发环境下，多个 Task 同时调用 `send` 时，actor 会自动串行化访问，避免竞态问题。

### 请求构建器模式

对于需要灵活组合参数的场景，可以用 Builder 模式逐步构建请求：

```swift
struct RequestBuilder<R: APIRequest> {
    let request: R
    var additionalHeaders: [String: String] = [:]
    var timeoutInterval: TimeInterval = 30
    var cachePolicy: URLRequest.CachePolicy = .useProtocolCachePolicy

    func withHeader(_ key: String, _ value: String) -> RequestBuilder {
        var copy = self
        copy.additionalHeaders[key] = value
        return copy
    }

    func withTimeout(_ interval: TimeInterval) -> RequestBuilder {
        var copy = self
        copy.timeoutInterval = interval
        return copy
    }

    func build(using client: APIClient) async throws -> APIResponse<R.Response> {
        try await client.send(request)
    }
}
```

## 请求拦截器 / 中间件模式

### 拦截器的设计思想

拦截器模式借鉴自 OkHttp 的 Interceptor 机制——每个拦截器就像一条流水线上的工位，请求依次经过每个工位，工位可以查看、修改请求，也可以查看、修改响应。

```
请求 → [认证拦截器] → [日志拦截器] → [重试拦截器] → 网络发送
                                                              ↓
响应 ← [认证拦截器] ← [日志拦截器] ← [重试拦截器] ← 服务器响应
```

```swift
protocol Interceptor {
    func intercept(request: URLRequest) async -> URLRequest
}
```

> 💡 **提示**：拦截器模式的核心优势是"可插拔"——新增功能只需添加一个拦截器，无需修改 APIClient 核心代码。这完美体现了开闭原则。

### 认证拦截器：自动附加 Token

```swift
actor TokenManager {
    private var accessToken: String?
    private var refreshToken: String?

    func setTokens(access: String, refresh: String) {
        self.accessToken = access
        self.refreshToken = refresh
    }

    func getAccessToken() -> String? {
        accessToken
    }

    func refreshAccessToken() async throws -> String {
        guard let refresh = refreshToken else {
            throw APIError.unauthorized
        }

        let url = URL(string: "https://api.example.com/auth/refresh")!
        var request = URLRequest(url: url)
        request.httpMethod = "POST"
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.httpBody = try JSONEncoder().encode(["refresh_token": refresh])

        let (data, response) = try await URLSession.shared.data(for: request)
        guard let httpResponse = response as? HTTPURLResponse,
              httpResponse.statusCode == 200 else {
            throw APIError.unauthorized
        }

        let tokenResponse = try JSONDecoder().decode(TokenResponse.self, from: data)
        self.accessToken = tokenResponse.accessToken
        self.refreshToken = tokenResponse.refreshToken
        return tokenResponse.accessToken
    }
}

struct TokenResponse: Decodable {
    let accessToken: String
    let refreshToken: String

    enum CodingKeys: String, CodingKey {
        case accessToken = "access_token"
        case refreshToken = "refresh_token"
    }
}

struct AuthInterceptor: Interceptor {
    let tokenManager: TokenManager

    func intercept(request: URLRequest) async -> URLRequest {
        var request = request
        if let token = await tokenManager.getAccessToken() {
            request.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
        }
        return request
    }
}
```

### 日志拦截器：请求/响应日志

```swift
struct LoggingInterceptor: Interceptor {
    let logger: (String) -> Void

    func intercept(request: URLRequest) async -> URLRequest {
        let method = request.httpMethod ?? "GET"
        let url = request.url?.absoluteString ?? "unknown"
        let headers = request.allHTTPHeaderFields ?? [:]

        logger("📤 REQUEST: \(method) \(url)")
        if !headers.isEmpty {
            logger("   Headers: \(headers.map { "\($0.key): \($0.value)" }.joined(separator: ", "))")
        }
        if let body = request.httpBody,
           let bodyString = String(data: body, encoding: .utf8) {
            logger("   Body: \(bodyString.prefix(500))")
        }

        return request
    }
}
```

### 重试拦截器：指数退避重试

```swift
struct RetryInterceptor: Interceptor {
    let maxRetries: Int
    let baseDelay: TimeInterval
    let maxDelay: TimeInterval

    init(maxRetries: Int = 3, baseDelay: TimeInterval = 1.0, maxDelay: TimeInterval = 30.0) {
        self.maxRetries = maxRetries
        self.baseDelay = baseDelay
        self.maxDelay = maxDelay
    }

    func intercept(request: URLRequest) async -> URLRequest {
        request
    }

    func executeWithRetry(
        request: URLRequest,
        using session: URLSession
    ) async throws -> (Data, URLResponse) {
        var lastError: Error?

        for attempt in 0...maxRetries {
            do {
                let (data, response) = try await session.data(for: request)
                if let httpResponse = response as? HTTPURLResponse,
                   (500...599).contains(httpResponse.statusCode) {
                    throw APIError.serverError("服务端错误 \(httpResponse.statusCode)")
                }
                return (data, response)
            } catch {
                lastError = error
                if attempt < maxRetries {
                    let delay = min(baseDelay * pow(2.0, Double(attempt)), maxDelay)
                    let jitter = Double.random(in: 0...(delay * 0.1))
                    try await Task.sleep(for: .seconds(delay + jitter))
                }
            }
        }

        throw lastError ?? APIError.networkError(URLError(.unknown))
    }
}
```

### 拦截器链的组合与执行顺序

拦截器的注册顺序决定了执行顺序——先注册的拦截器先处理请求，后处理响应：

```swift
let client = APIClient(
    baseURL: URL(string: "https://api.example.com")!,
    interceptors: [
        LoggingInterceptor(logger: { print($0) }),
        AuthInterceptor(tokenManager: tokenManager),
        RetryInterceptor(maxRetries: 3)
    ]
)
```

执行流程：

```
请求 → LoggingInterceptor → AuthInterceptor → RetryInterceptor → 网络发送
```

> ⚠️ **警告**：拦截器顺序很重要！日志拦截器应放在最前面，确保记录所有请求（包括被后续拦截器修改后的版本）。认证拦截器应在重试拦截器之前，这样每次重试都能携带最新的 Token。

## 缓存策略

### HTTP 缓存基础：Cache-Control、ETag、Last-Modified

HTTP 协议本身提供了缓存机制，理解这些头信息是设计缓存策略的基础：

| 头信息 | 作用 | 示例值 |
|--------|------|--------|
| `Cache-Control` | 控制缓存行为 | `max-age=3600, public` |
| `ETag` | 资源的唯一标识符 | `"abc123"` |
| `Last-Modified` | 资源最后修改时间 | `Wed, 21 Oct 2025 07:28:00 GMT` |
| `If-None-Match` | 条件请求，携带上次 ETag | `"abc123"` |
| `If-Modified-Since` | 条件请求，携带上次修改时间 | `Wed, 21 Oct 2025 07:28:00 GMT` |

缓存协商流程：

```
客户端                                服务器
  │                                    │
  │  GET /api/articles                 │
  │  If-None-Match: "abc123"          │
  │ ──────────────────────────────────►│
  │                                    │
  │  304 Not Modified                  │
  │  (无 Body，使用本地缓存)            │
  │◄────────────────────────────────── │
```

### 内存缓存 + 磁盘缓存双层架构

URLCache 只能缓存符合 HTTP 缓存语义的响应。对于需要精确控制的业务数据，我们需要自建双层缓存：

```swift
actor CacheLayer<T: Codable> {
    private var memoryCache: [String: CacheEntry<T>] = [:]
    private let diskCacheURL: URL
    private let defaultTTL: TimeInterval

    struct CacheEntry<T: Codable>: Codable {
        let data: T
        let expiration: Date

        var isExpired: Bool {
            Date() > expiration
        }
    }

    init(diskCachePath: String, defaultTTL: TimeInterval = 300) {
        self.diskCacheURL = FileManager.default.urls(for: .cachesDirectory, in: .userDomainMask)[0]
            .appendingPathComponent(diskCachePath)
        self.defaultTTL = defaultTTL
        try? FileManager.default.createDirectory(at: diskCacheURL, withIntermediateDirectories: true)
    }

    func get(forKey key: String) -> T? {
        if let entry = memoryCache[key], !entry.isExpired {
            return entry.data
        }
        memoryCache.removeValue(forKey: key)

        if let entry = loadFromDisk(forKey: key), !entry.isExpired {
            memoryCache[key] = entry
            return entry.data
        }

        return nil
    }

    func set(_ value: T, forKey key: String, ttl: TimeInterval? = nil) {
        let entry = CacheEntry(data: value, expiration: Date().addingTimeInterval(ttl ?? defaultTTL))
        memoryCache[key] = entry
        saveToDisk(entry: entry, forKey: key)
    }

    func remove(forKey key: String) {
        memoryCache.removeValue(forKey: key)
        let fileURL = diskCacheURL.appendingPathComponent(key.md5Hash)
        try? FileManager.default.removeItem(at: fileURL)
    }

    func removeAll() {
        memoryCache.removeAll()
        try? FileManager.default.removeItem(at: diskCacheURL)
        try? FileManager.default.createDirectory(at: diskCacheURL, withIntermediateDirectories: true)
    }

    private func loadFromDisk(forKey key: String) -> CacheEntry<T>? {
        let fileURL = diskCacheURL.appendingPathComponent(key.md5Hash)
        guard let data = try? Data(contentsOf: fileURL) else { return nil }
        return try? JSONDecoder().decode(CacheEntry<T>.self, from: data)
    }

    private func saveToDisk(entry: CacheEntry<T>, forKey key: String) {
        let fileURL = diskCacheURL.appendingPathComponent(key.md5Hash)
        guard let data = try? JSONEncoder().encode(entry) else { return }
        try? data.write(to: fileURL)
    }
}

extension String {
    var md5Hash: String {
        var hash: [UInt8] = Array(repeating: 0, count: Int(CC_MD5_DIGEST_LENGTH))
        self.utf8CString.withUnsafeBufferPointer { buffer in
            CC_MD5(buffer.baseAddress, CC_LONG(buffer.count - 1), &hash)
        }
        return hash.map { String(format: "%02x", $0) }.joined()
    }
}
```

### 缓存失效策略

| 策略 | 适用场景 | 实现方式 |
|------|----------|----------|
| TTL 过期 | 列表数据、配置信息 | CacheEntry 记录过期时间 |
| 主动失效 | 用户修改数据后刷新 | 调用 `remove(forKey:)` 清除 |
| 版本号失效 | API 版本升级 | 缓存 key 包含 API 版本号 |
| ETag 协商 | 数据变化不频繁 | 服务端返回 ETag，客户端条件请求 |

### SwiftUI 中的缓存数据驱动 UI

```swift
@Observable
class ArticleListViewModel {
    var articles: [Article] = []
    var isLoading = false
    var error: APIError?

    private let client: APIClient
    private let cache: CacheLayer<[Article]>

    init(client: APIClient, cache: CacheLayer<[Article]>) {
        self.client = client
        self.cache = cache
    }

    func loadArticles(page: Int = 1) async {
        let cacheKey = "articles_page_\(page)"

        if let cached = await cache.get(forKey: cacheKey) {
            articles = cached
        }

        isLoading = true
        defer { isLoading = false }

        do {
            let request = ListArticlesRequest(page: page, pageSize: 20)
            let response = try await client.send(request)
            articles = response.data.items
            await cache.set(articles, forKey: cacheKey, ttl: 300)
        } catch {
            if articles.isEmpty {
                self.error = error as? APIError ?? .networkError(error)
            }
        }
    }
}

struct ArticleListView: View {
    @State private var viewModel: ArticleListViewModel

    init(client: APIClient) {
        let cache = CacheLayer<[Article]>(diskCachePath: "articles", defaultTTL: 300)
        _viewModel = State(wrappedValue: ArticleListViewModel(client: client, cache: cache))
    }

    var body: some View {
        List(viewModel.articles) { article in
            VStack(alignment: .leading) {
                Text(article.title)
                    .font(.headline)
                Text(article.createdAt)
                    .font(.caption)
                    .foregroundStyle(.secondary)
            }
        }
        overlay {
            if viewModel.isLoading && viewModel.articles.isEmpty {
                ProgressView("加载中...")
            }
        }
        task {
            await viewModel.loadArticles()
        }
        refreshable {
            await viewModel.loadArticles()
        }
    }
}
```

## 离线优先架构

### 离线优先的核心思想

传统架构：**网络优先**——先请求网络，失败才读本地。问题是无网络时用户体验极差。

离线优先：**本地数据优先**——始终从本地读取数据展示，网络同步在后台静默进行。

```
传统架构：                        离线优先架构：
用户操作 → 网络请求 → 展示        用户操作 → 读取本地 → 立即展示
           ↓ 失败                       ↓ 后台同步
         读本地 → 展示                  网络请求 → 更新本地 → 刷新UI
```

### 写入策略：乐观更新

乐观更新（Optimistic Update）是指用户操作时先立即更新本地数据，再异步同步到服务器。如果同步失败，再回滚本地数据。

```swift
actor OfflineSyncManager {
    let client: APIClient
    let modelContext: ModelContext

    func createArticle(title: String, content: String) async throws -> CachedArticle {
        let localArticle = CachedArticle(
            id: Int(Date().timeIntervalSince1970 * 1000),
            title: title,
            content: content,
            createdAt: Date()
        )
        localArticle.isSynced = false
        modelContext.insert(localArticle)
        try modelContext.save()

        do {
            let request = CreateArticleRequest(title: title, content: content)
            let response = try await client.send(request)
            localArticle.id = response.data.id
            localArticle.isSynced = true
            try modelContext.save()
        } catch {
            localArticle.isSynced = false
            try modelContext.save()
        }

        return localArticle
    }

    func deleteArticle(_ article: CachedArticle) async throws {
        let articleId = article.id

        modelContext.delete(article)
        try modelContext.save()

        do {
            let request = DeleteArticleRequest(id: articleId)
            _ = try await client.send(request)
        } catch {
            let restoredArticle = CachedArticle(
                id: articleId,
                title: article.title,
                content: article.content,
                createdAt: article.createdAt
            )
            restoredArticle.isSynced = false
            modelContext.insert(restoredArticle)
            try modelContext.save()
        }
    }
}
```

### 同步策略：网络恢复后自动同步

```swift
actor SyncQueue {
    private var pendingOperations: [SyncOperation] = []

    struct SyncOperation: Codable {
        let id: UUID
        let type: SyncOperationType
        let payload: Data
        let createdAt: Date
        let retryCount: Int

        enum SyncOperationType: String, Codable {
            case create
            case update
            case delete
        }
    }

    func enqueue(_ operation: SyncOperation) {
        pendingOperations.append(operation)
        saveToDisk()
    }

    func processAll(using client: APIClient) async {
        for operation in pendingOperations {
            do {
                try await execute(operation, using: client)
                pendingOperations.removeAll { $0.id == operation.id }
            } catch {
                if let index = pendingOperations.firstIndex(where: { $0.id == operation.id }) {
                    pendingOperations[index] = SyncOperation(
                        id: operation.id,
                        type: operation.type,
                        payload: operation.payload,
                        createdAt: operation.createdAt,
                        retryCount: operation.retryCount + 1
                    )
                }
            }
        }
        saveToDisk()
    }

    private func execute(_ operation: SyncOperation, using client: APIClient) async throws {
        switch operation.type {
        case .create:
            let request = try JSONDecoder().decode(CreateArticleRequest.self, from: operation.payload)
            _ = try await client.send(request)
        case .update:
            let request = try JSONDecoder().decode(UpdateArticleRequest.self, from: operation.payload)
            _ = try await client.send(request)
        case .delete:
            let request = try JSONDecoder().decode(DeleteArticleRequest.self, from: operation.payload)
            _ = try await client.send(request)
        }
    }

    private func saveToDisk() {
        guard let data = try? JSONEncoder().encode(pendingOperations) else { return }
        let url = FileManager.default.urls(for: .applicationSupportDirectory, in: .userDomainMask)[0]
            .appendingPathComponent("sync_queue.json")
        try? data.write(to: url)
    }
}
```

### 冲突解决策略

| 策略 | 原理 | 适用场景 | 优缺点 |
|------|------|----------|--------|
| Last Write Wins | 时间戳最新的写入胜出 | 冲突少的场景 | 简单但可能丢数据 |
| 服务端权威 | 服务端数据始终优先 | 服务端是唯一真相源 | 安全但可能覆盖本地修改 |
| 合并策略 | 自动合并非冲突字段 | 协作编辑场景 | 最优但实现复杂 |
| 用户选择 | 弹窗让用户选择保留哪个 | 重要数据冲突 | 用户体验中断 |

```swift
enum ConflictResolution {
    case lastWriteWins
    case serverWins
    case merge((CachedArticle, ServerArticle) -> CachedArticle)
    case askUser

    func resolve(local: CachedArticle, server: ServerArticle) -> CachedArticle {
        switch self {
        case .lastWriteWins:
            return local.lastModified > server.lastModified
                ? local
                : mergeServerToLocal(local: local, server: server)
        case .serverWins:
            return mergeServerToLocal(local: local, server: server)
        case .merge(let merger):
            return merger(local, server)
        case .askUser:
            return local
        }
    }

    private func mergeServerToLocal(local: CachedArticle, server: ServerArticle) -> CachedArticle {
        local.title = server.title
        local.content = server.content
        local.isSynced = true
        local.lastModified = server.lastModified
        return local
    }
}

struct ServerArticle: Decodable {
    let id: Int
    let title: String
    let content: String
    let lastModified: Date
}
```

### 国内弱网场景的特殊考虑

国内移动网络环境复杂——地铁、电梯、高铁等场景频繁切换网络，需要额外关注：

- **请求超时设置**：国内运营商网络延迟波动大，建议连接超时 15 秒、读取超时 30 秒
- **DNS 预解析**：使用 HTTPDNS 服务绕过运营商 DNS 劫持和延迟
- **请求压缩**：上传数据启用 gzip 压缩，减少弱网传输时间
- **断点续传**：大文件下载支持 Range 请求，网络中断后可续传
- **网络状态监听**：实时监听网络变化，恢复后自动触发同步队列

```swift
class NetworkMonitor: ObservableObject {

            }
        }
        monitor.start(queue: queue)
    }

    func stop() {
        monitor.cancel()
    }
}
```

## 请求重试与错误恢复

### 指数退避算法

指数退避是网络重试的黄金法则——每次重试的等待时间翻倍，避免大量请求同时重试导致服务器雪崩：

```
第1次重试：等待 1 秒
第2次重试：等待 2 秒
第3次重试：等待 4 秒
第4次重试：等待 8 秒
...
```

加入随机抖动（Jitter）防止多个客户端同步重试：

```swift
struct ExponentialBackoff {
    let baseDelay: TimeInterval
    let maxDelay: TimeInterval
    let jitterFactor: Double

    init(baseDelay: TimeInterval = 1.0, maxDelay: TimeInterval = 60.0, jitterFactor: Double = 0.1) {
        self.baseDelay = baseDelay
        self.maxDelay = maxDelay
        self.jitterFactor = jitterFactor
    }

    func delay(forAttempt attempt: Int) -> TimeInterval {
        let exponentialDelay = baseDelay * pow(2.0, Double(attempt))
        let cappedDelay = min(exponentialDelay, maxDelay)
        let jitter = cappedDelay * Double.random(in: -jitterFactor...jitterFactor)
        return max(0, cappedDelay + jitter)
    }
}
```

### 可重试错误 vs 不可重试错误

并非所有错误都值得重试：

| 错误类型 | 是否可重试 | 原因 |
|----------|:----------:|------|
| 网络超时 | ✅ | 可能是临时网络波动 |
| 服务端 5xx | ✅ | 服务端可能临时故障 |
| 429 Too Many Requests | ✅ | 需要等待后重试 |
| DNS 解析失败 | ✅ | 可能是临时 DNS 问题 |
| 400 Bad Request | ❌ | 请求本身有问题 |
| 401 Unauthorized | ❌ | Token 无效，需重新登录 |
| 403 Forbidden | ❌ | 无权限，重试无意义 |
| 404 Not Found | ❌ | 资源不存在 |
| 解码失败 | ❌ | 数据格式不匹配 |

```swift
extension APIError {

        switch self {
        case .networkError, .timeout, .serverError:
            return true
        case .invalidURL, .invalidResponse, .decodingError, .unauthorized:
            return false
        }
    }
}
```

### 最大重试次数与退避上限

```swift
actor RetryableAPIClient {
    let client: APIClient
    let backoff: ExponentialBackoff
    let maxRetries: Int

    init(client: APIClient, maxRetries: Int = 3) {
        self.client = client
        self.backoff = ExponentialBackoff()
        self.maxRetries = maxRetries
    }

    func send<R: APIRequest>(_ request: R) async throws -> APIResponse<R.Response> {
        var lastError: APIError?

        for attempt in 0...maxRetries {
            do {
                return try await client.send(request)
            } catch let error as APIError {
                lastError = error
                guard error.isRetryable, attempt < maxRetries else { break }
                let delay = backoff.delay(forAttempt: attempt)
                try await Task.sleep(for: .seconds(delay))
            } catch {
                lastError = .networkError(error)
                guard attempt < maxRetries else { break }
                let delay = backoff.delay(forAttempt: attempt)
                try await Task.sleep(for: .seconds(delay))
            }
        }

        throw lastError ?? .networkError(URLError(.unknown))
    }
}
```

### 网络可达性检测（NWPathMonitor）

在发起请求前检测网络状态，可以避免无谓的请求和等待：

```swift
actor ReachabilityChecker {
    private var monitor: NWPathMonitor?
    private var currentPath: NWPath = NWPath()

    var isReachable: Bool {
        currentPath.status == .satisfied
    }

    func startMonitoring() {
        let monitor = NWPathMonitor()
        monitor.pathUpdateHandler = { [weak self] path in
            Task { [weak self] in
                await self?.updatePath(path)
            }
        }
        self.monitor = monitor
        monitor.start(queue: DispatchQueue(label: "reachability"))
    }

    func stopMonitoring() {
        monitor?.cancel()
        monitor = nil
    }

    private func updatePath(_ path: NWPath) {
        currentPath = path
    }

    func waitForConnection() async {
        guard !isReachable else { return }

        while !isReachable {
            try? await Task.sleep(for: .seconds(1))
        }
    }
}
```

```swift
@Observable
class SearchViewModel {

    var results: [Article] = []
    var isLoading = false

        searchTask?.cancel()

            } catch is CancellationError {

            } catch {

            }
        }
    }
```

### 竞态请求处理

搜索场景中，用户快速输入会产生多个请求，后发出的请求可能先返回，导致显示旧结果。两种常见处理方式：

**方式一：取消旧请求**

```swift
actor DebouncedSearchClient {
    private var currentTask: Task<Void, Never>?

    func search(query: String, client: APIClient) async -> [Article] {
        currentTask?.cancel()

        return await withTaskCancellationHandler {
            try? await Task.sleep(for: .milliseconds(300))
            guard !Task.isCancelled else { return [] }

            let request = SearchArticlesRequest(query: query)
            let result = try? await client.send(request)
            return result?.data.items ?? []
        } onCancel: {
            currentTask?.cancel()
        }
    }
}
```

**方式二：版本号校验**

```swift
@Observable
class SearchViewModel {
    var results: [Article] = []
    private var searchVersion = 0

    func search(query: String) async {
        let currentVersion = { searchVersion += 1; return searchVersion }()

        try? await Task.sleep(for: .milliseconds(300))

        guard currentVersion == searchVersion else { return }

        do {
            let request = SearchArticlesRequest(query: query)
            let response = try await client.send(request)
            guard currentVersion == searchVersion else { return }
            results = response.data.items
        } catch {
            guard currentVersion == searchVersion else { return }
        }
    }
}
```

> ⚠️ **警告**：竞态请求是极容易出 Bug 的地方。任何涉及用户输入触发网络请求的场景（搜索、筛选、分页）都必须处理竞态。推荐使用版本号校验方式，因为它不会取消正在进行的请求，只是忽略过期结果。

### Mock URLProtocol 测试方案

通过自定义 URLProtocol，可以在不修改任何业务代码的情况下拦截网络请求，返回预设数据：

```swift
class MockURLProtocol: URLProtocol {
    static var mockResponseHandler: ((URLRequest) throws -> (HTTPURLResponse, Data))?

    override class func canInit(with request: URLRequest) -> Bool {
        true
    }

    override class func canonicalRequest(for request: URLRequest) -> URLRequest {
        request
    }

    override func startLoading() {
        guard let handler = MockURLProtocol.mockResponseHandler else {
            client?.urlProtocolDidFinishLoading(self)
            return
        }

        do {
            let (response, data) = try handler(request)
            client?.urlProtocol(self, didReceive: response, cacheStoragePolicy: .notAllowed)
            client?.urlProtocol(self, didLoad: data)
            client?.urlProtocolDidFinishLoading(self)
        } catch {
            client?.urlProtocol(self, didFailWithError: error)
        }
    }

    override func stopLoading() {}
}
```

## 小结

本章从基础 URLSession 出发，逐步构建了工程级网络层架构。以下是核心知识点总结：

| 主题 | 核心概念 | 关键技术 |
|------|----------|----------|
| 网络层架构 | 单一职责、开闭原则、依赖倒转 | APIRequest 协议、APIClient actor |
| API Client 封装 | 声明式请求、类型安全响应 | 泛型 APIResponse、请求构建器 |
| 拦截器模式 | 可插拔中间件、请求/响应拦截 | Interceptor 协议、链式组合 |
| 认证拦截器 | 自动 Token 管理 | TokenManager actor、Bearer Token |
| 日志拦截器 | 统一请求/响应日志 | 自定义 logger 闭包 |
| 重试拦截器 | 指数退避、抖动 | ExponentialBackoff、最大重试次数 |
| 缓存策略 | HTTP 缓存 + 双层缓存 | URLCache、CacheLayer、TTL |
| 离线优先 | 本地优先、网络同步在后 | SwiftData、乐观更新、同步队列 |
| 冲突解决 | Last Write Wins、服务端权威 | ConflictResolution 枚举 |
| 请求重试 | 可重试错误识别、退避上限 | isRetryable、NWPathMonitor |
| 请求取消 | Task 取消、竞态处理 | searchTask?.cancel()、版本号校验 |
| 网络层测试 | Mock URLProtocol、Fixture | MockURLProtocol、ephemeral Session |

> 💡 **提示**：网络层架构不是一次性搭建完成的。建议从 APIRequest + APIClient 开始，随着项目复杂度增加，逐步添加拦截器、缓存、离线支持。每一层都可以独立测试和替换。
