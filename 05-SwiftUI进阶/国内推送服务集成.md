# 国内推送服务集成

> 🎯 **本章目标**：了解国内推送服务生态，掌握极光推送、个推等主流第三方推送 SDK 的集成方法，理解厂商通道（华为/小米/OPPO/vivo）的概念与配置，学会在 SwiftUI 项目中实现完整的推送功能。

---

## 1. 国内推送生态概述

### 1.1 为什么国内需要第三方推送服务

在海外市场，Android 设备依赖 Google FCM（Firebase Cloud Messaging）实现系统级推送，iOS 设备使用 APNs（Apple Push Notification service）。然而国内的情况截然不同：

- **Google FCM 不可用**：由于 Google 服务框架在国内 Android 设备上缺失，FCM 推送通道完全不可用，Android 端必须依赖第三方推送服务或厂商自有通道
- **APNs 在国内存在延迟**：APNs 服务器部署在海外，国内网络环境下偶尔出现推送延迟或丢失，影响用户体验
- **Android 后台进程受限**：国内 Android 厂商（华为、小米、OPPO、vivo）对后台进程管控严格，App 被杀后无法维持长连接，导致推送无法送达
- **统一推送联盟进展缓慢**：国内曾推动统一推送标准（UPS），但各厂商推进速度不一，尚未形成统一生态

因此，国内开发者通常选择集成第三方推送平台，通过一条 SDK 同时对接 APNs（iOS）和各厂商通道（Android），大幅降低接入成本。

### 1.2 国内推送服务商一览

| 服务商 | 所属公司 | 核心优势 | 适用场景 |
|--------|---------|---------|---------|
| 极光推送（JPush） | 深圳极光 | 文档完善、社区活跃、功能全面 | 中小型 App 首选 |
| 个推（Getui） | 每日互动 | 大数据能力、精准推送 | 需要智能推送的 App |
| 信鸽（XGPush） | 腾讯 | 与微信生态打通 | 腾讯系 App |
| 华为推送（HMS Push） | 华为 | 系统级通道、到达率高 | 华为设备必接 |
| 小米推送（Mi Push） | 小米 | MIUI 系统级通道 | 小米设备必接 |
| OPPO 推送 | OPPO | ColorOS 系统级通道 | OPPO 设备必接 |
| vivo 推送 | vivo | OriginOS 系统级通道 | vivo 设备必接 |

### 1.3 各服务商对比

| 服务商 | 免费额度 | 厂商通道支持 | 到达率（Android） | 价格（超出部分） |
|--------|---------|-------------|------------------|----------------|
| 极光推送 | 100万条/月 | 华为/小米/OPPO/vivo/魅族 | 85%-95% | 约 0.002 元/条 |
| 个推 | 100万条/月 | 华为/小米/OPPO/vivo/魅族 | 85%-95% | 约 0.002 元/条 |
| 信鸽 | 50万条/月 | 华为/小米/OPPO/vivo | 80%-90% | 约 0.003 元/条 |
| 华为推送 | 无限（自有通道） | 仅华为 | 95%+（华为设备） | 免费 |
| 小米推送 | 无限（自有通道） | 仅小米 | 95%+（小米设备） | 免费 |
| OPPO 推送 | 无限（自有通道） | 仅 OPPO | 95%+（OPPO 设备） | 免费 |
| vivo 推送 | 无限（自有通道） | 仅 vivo | 95%+（vivo 设备） | 免费 |

> 💡 **提示**：对于 iOS 端，所有第三方推送服务最终都走 APNs 通道，到达率差异不大。第三方推送的核心价值在于 Android 端的厂商通道整合和统一的推送管理后台。

### 1.4 APNs vs 第三方推送的架构差异

| 对比项 | APNs 直连 | 第三方推送平台 |
|--------|----------|--------------|
| iOS 推送路径 | 服务器 → APNs → 设备 | 服务器 → 推送平台 → APNs → 设备 |
| Android 推送路径 | 不适用 | 服务器 → 推送平台 → 厂商通道/自有长连接 → 设备 |
| 设备 Token 管理 | 自行维护 | 平台自动管理 |
| 推送统计 | 需自行实现 | 平台提供完整统计 |
| 多平台支持 | 仅 iOS | iOS + Android 统一接口 |
| 运维成本 | 高（需自建推送服务） | 低（SaaS 服务） |
| 到达率监控 | 需自行实现 | 平台提供实时数据 |
| A/B 测试 | 需自行实现 | 部分平台支持 |

> ⚠️ **警告**：使用第三方推送意味着设备 Token 和推送内容会经过第三方服务器。如果推送内容涉及敏感信息（如医疗、金融），需要评估数据安全合规风险，并与推送服务商签署数据安全协议。

## 2. 极光推送集成

### 2.1 极光开发者账号注册与 App 创建

1. 访问 [极光推送官网](https://www.jiguang.cn/) 注册开发者账号
2. 进入控制台，点击"创建应用"
3. 填写应用名称，选择"推送"服务
4. 获取 **AppKey** 和 **Master Secret**（服务端使用）
5. 在应用设置中填写 Bundle ID，上传 APNs 证书

### 2.2 SDK 集成

**CocoaPods 方式：**

```ruby
pod 'JCore', '~> 3.6'
pod 'JPush', '~> 5.0'
```

**SPM 方式：**

极光推送目前对 SPM 的支持有限，推荐使用 CocoaPods 集成。如果项目使用 SPM，可以通过 Xcode 的 `Add Package Dependency` 添加极光官方提供的 Swift Package。

### 2.3 APNs 证书配置

极光推送需要 APNs 证书才能向 iOS 设备推送消息：

1. 登录 Apple Developer 网站，进入 Certificates 页面
2. 创建 APNs 证书（开发环境用 Sandbox，生产环境用 Production）
3. 导出 `.p12` 文件并设置密码
4. 在极光控制台 → 应用设置 → 推送设置中上传 `.p12` 文件和密码

> 💡 **提示**：从 2021 年起，Apple 支持基于 Token 的 APNs 认证（.p8 文件），相比证书方式不会过期，推荐优先使用。极光控制台也支持上传 `.p8` 认证文件。

### 2.4 初始化与注册

在 `App` 入口文件中完成极光推送的初始化：

```swift
import SwiftUI
import JPush

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

class AppDelegate: NSObject, UIApplicationDelegate {
    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        let entity = JPUSHRegisterEntity()
        entity.types = Int(UNAuthorizationOptions.alert.rawValue |
                          UNAuthorizationOptions.badge.rawValue |
                          UNAuthorizationOptions.sound.rawValue)
        JPUSHService.register(forRemoteNotificationConfig: entity, delegate: self)

        #if DEBUG
        JPUSHService.setup(withOption: launchOptions, appKey: "your_app_key", channel: "debug", apsForProduction: false)
        #else
        JPUSHService.setup(withOption: launchOptions, appKey: "your_app_key", channel: "appstore", apsForProduction: true)
        #endif

        JPUSHService.registrationIDCompletionHandler { resCode, registrationID in
            if resCode == 0 {
                print("Registration ID: \(registrationID ?? "")")
            }
        }

        return true
    }

    func application(
        _ application: UIApplication,
        didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data
    ) {
        JPUSHService.registerDeviceToken(deviceToken)
    }

    func application(
        _ application: UIApplication,
        didFailToRegisterForRemoteNotificationsWithError error: Error
    ) {
        print("APNs registration failed: \(error)")
    }
}
```

### 2.5 SwiftUI 中处理推送回调

极光推送通过 `JPUSHRegisterDelegate` 协议回调推送事件，需要在 `AppDelegate` 中实现：

```swift
extension AppDelegate: JPUSHRegisterDelegate {
    func jpushNotificationCenter(
        _ center: UNUserNotificationCenter!,
        willPresent notification: UNNotification!,
        withCompletionHandler completionHandler: ((Int) -> Void)!
    ) {
        let userInfo = notification.request.content.userInfo

        if notification.request.trigger is UNPushNotificationTrigger {
            JPUSHService.handleRemoteNotification(userInfo)
        }

        completionHandler(Int(UNNotificationPresentationOptions.alert.rawValue |
                              UNNotificationPresentationOptions.badge.rawValue |
                              UNNotificationPresentationOptions.sound.rawValue))
    }

    func jpushNotificationCenter(
        _ center: UNUserNotificationCenter!,
        didReceive response: UNNotificationResponse!,
        withCompletionHandler completionHandler: (() -> Void)!
    ) {
        let userInfo = response.notification.request.content.userInfo

        if response.notification.request.trigger is UNPushNotificationTrigger {
            JPUSHService.handleRemoteNotification(userInfo)
            handlePushPayload(userInfo)
        }

        completionHandler()
    }
}
```

在 SwiftUI 视图中响应推送跳转：

```swift
import SwiftUI

struct ContentView: View {
    @StateObject private var pushRouter = PushRouter()

    var body: some View {
        NavigationStack {
            VStack(spacing: 20) {
                Text("推送消息示例")
                    .font(.largeTitle)

                if let target = pushRouter.navigationTarget {
                    NavigationLink(destination: target, isActive: $pushRouter.shouldNavigate) {
                        EmptyView()
                    }
                }
            }
        }
        .environmentObject(pushRouter)
    }
}

class PushRouter: ObservableObject {
    @Published var navigationTarget: AnyView?
    @Published var shouldNavigate = false

    func handlePayload(_ userInfo: [AnyHashable: Any]) {
        guard let type = userInfo["type"] as? String else { return }

        switch type {
        case "message":
            if let id = userInfo["id"] as? String {
                navigationTarget = AnyView(MessageDetailView(messageId: id))
                shouldNavigate = true
            }
        case "promotion":
            if let id = userInfo["id"] as? String {
                navigationTarget = AnyView(PromotionView(promotionId: id))
                shouldNavigate = true
            }
        default:
            break
        }
    }
}
```

### 2.6 别名与标签设置

极光推送通过别名（Alias）和标签（Tag）实现精准推送：

```swift
JPUSHService.setAlias("user_\(userId)", completion: { resCode, alias, seq in
    if resCode == 0 {
        print("Alias set successfully: \(alias ?? "")")
    }
}, seq: 1)

JPUSHService.setTags(["vip", "beijing"], completion: { resCode, tags, seq in
    if resCode == 0 {
        print("Tags set successfully")
    }
}, seq: 2)
```

| 概念 | 说明 | 典型用途 |
|------|------|---------|
| 别名（Alias） | 每个设备唯一标识，通常用用户 ID | 给特定用户推送 |
| 标签（Tag） | 设备可设置多个标签，用于分组 | 按城市、会员等级等分组推送 |
| Registration ID | 极光为每台设备分配的唯一 ID | 精确推送到指定设备 |

> 💡 **提示**：别名设置应在用户登录成功后立即执行，登出后调用 `JPUSHService.deleteAlias` 清除，避免推送消息发送给错误的用户。

### 2.7 推送消息的接收与处理

推送消息分为通知栏消息和自定义消息两种：

| 消息类型 | 是否显示通知栏 | 是否走 APNs | 典型场景 |
|---------|--------------|------------|---------|
| 通知栏消息 | ✅ 是 | ✅ 是 | 营销推送、系统通知 |
| 自定义消息 | ❌ 否 | ❌ 否（App 在线时通过长连接） | 静默同步数据、指令下发 |
| 静默推送 | ❌ 否 | ✅ 是（content-available: 1） | 后台数据同步 |

自定义消息的接收：

```swift
func jpushCustomMessage(_ message: JPUSHCustomMessage!) {
    guard let data = message.data(using: .utf8) else { return }
    guard let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any] else { return }

    DispatchQueue.main.async {
        NotificationCenter.default.post(
            name: .init("CustomPushMessage"),
            object: nil,
            userInfo: json
        )
    }
}
```

### 2.8 富媒体推送

iOS 10+ 支持富媒体推送，可以在通知中展示图片、GIF 和视频：

1. 创建 Notification Service Extension Target
2. 在 Extension 中集成极光 SDK 的富媒体推送支持
3. 推送 payload 中添加 `mutable-content: 1` 和媒体 URL

```swift
import UserNotifications

class NotificationService: UNNotificationServiceExtension {
    var contentHandler: ((UNNotificationContent) -> Void)?
    var bestAttemptContent: UNMutableNotificationContent?

    override func didReceive(
        _ request: UNNotificationRequest,
        withContentHandler contentHandler: @escaping (UNNotificationContent) -> Void
    ) {
        self.contentHandler = contentHandler
        bestAttemptContent = (request.content.mutableCopy() as? UNMutableNotificationContent)

        if let bestAttemptContent = bestAttemptContent {
            if let imageURLString = bestAttemptContent.userInfo["image"] as? String,
               let imageURL = URL(string: imageURLString) {
                downloadAndAttach(imageURL, to: bestAttemptContent, contentHandler: contentHandler)
            } else {
                contentHandler(bestAttemptContent)
            }
        }
    }

    func downloadAndAttach(
        _ url: URL,
        to content: UNMutableNotificationContent,
        contentHandler: @escaping (UNNotificationContent) -> Void
    ) {
        let task = URLSession.shared.downloadTask(with: url) { location, _, error in
            guard let location = location, error == nil else {
                contentHandler(content)
                return
            }
            let tmpDir = NSTemporaryDirectory()
            let tmpFile = "attachment.\(url.pathExtension)"
            let tmpPath = tmpDir + tmpFile
            try? FileManager.default.moveItem(atPath: location.path, toPath: tmpPath)
            if let attachment = try? UNNotificationAttachment(identifier: "image", url: URL(fileURLWithPath: tmpPath)) {
                content.attachments = [attachment]
            }
            contentHandler(content)
        }
        task.resume()
    }
}
```

### 3.1 个推开发者平台注册

1. 访问 [个推开发者平台](https://dev.getui.com/) 注册账号
2. 创建应用，选择 iOS 平台
3. 获取 **AppID**、**AppKey**、**AppSecret** 和 **MasterSecret**
4. 上传 APNs 证书（与极光推送类似）

## 4. 厂商通道详解

### 4.1 什么是厂商通道

厂商通道是手机厂商提供的系统级推送通道。当 App 进程被杀死后，常规的长连接推送无法送达，而厂商通道作为系统级服务，始终存活，可以确保推送消息送达用户设备。

| 特性 | 常规长连接推送 | 厂商通道推送 |
|------|--------------|------------|
| App 被杀后能否送达 | ❌ 不能 | ✅ 能 |
| 到达率 | 50%-70% | 90%+ |
| 实现方式 | App 内维持 TCP 长连接 | 系统级推送服务 |
| 耗电 | 较高（维持长连接） | 低（系统统一管理） |
| 限制 | 无特殊限制 | 各厂商有不同的推送频率和内容限制 |

> ⚠️ **警告**：厂商通道仅适用于 Android 端。iOS 端统一走 APNs，不存在厂商通道的概念。本节内容主要帮助你理解推送全貌，在服务端配置时需要关注。

### 4.2 华为推送配置

1. 注册 [华为开发者联盟](https://developer.huawei.com/) 账号
2. 创建应用，获取 **App ID** 和 **App Secret**
3. 开通推送服务，下载 `agconnect-services.json` 配置文件
4. 在 Android 项目中集成 HMS Core Push SDK
5. 在推送平台（极光/个推）后台配置华为通道的 App ID 和 App Secret

**华为推送注意事项：**
- 需要使用华为签名证书打包
- 消息分类：分为"服务与通讯"和"资讯与营销"两类，营销类消息受频次限制
- 通知样式支持大文本、大图、按钮等

### 4.3 小米推送配置

1. 注册 [小米开放平台](https://dev.mi.com/) 账号
2. 创建应用，获取 **App ID**、**App Key** 和 **App Secret**
3. 在 Android 项目中集成 Mi Push SDK
4. 在推送平台后台配置小米通道参数

**小米推送注意事项：**
- 支持通知栏消息和透传消息
- 通知栏消息到达率高，透传消息受后台限制
- 需要在小米开发者后台申请推送权限

### 4.4 OPPO 推送配置

1. 注册 [OPPO 开放平台](https://open.oppomobile.com/) 账号
2. 创建应用，获取 **App Key** 和 **App Secret**
3. 在 Android 项目中集成 OPPO Push SDK
4. 在推送平台后台配置 OPPO 通道参数

**OPPO 推送注意事项：**
- 对推送频率有严格限制，每天每个用户最多收到若干条推送
- 通知内容需审核，营销类消息限制更严
- 必须在 OPPO 开放平台申请推送权限后才能使用

### 4.5 vivo 推送配置

1. 注册 [vivo 开放平台](https://dev.vivo.com.cn/) 账号
2. 创建应用，获取 **App ID** 和 **App Key**
3. 在 Android 项目中集成 vivo Push SDK
4. 在推送平台后台配置 vivo 通道参数

**vivo 推送注意事项：**
- 同样有推送频率限制
- 分类推送：系统类消息优先级高于运营类消息
- 需要在 vivo 开放平台审核通过后才能使用

### 4.6 厂商通道的统一接入方案

逐个接入各厂商通道成本极高，推荐使用第三方推送平台统一接入：

```
服务端
  ↓
第三方推送平台（极光/个推）
  ↓
  ├── iOS → APNs
  ├── 华为设备 → 华为推送通道
  ├── 小米设备 → 小米推送通道
  ├── OPPO 设备 → OPPO 推送通道
  ├── vivo 设备 → vivo 推送通道
  └── 其他设备 → 自有长连接
```

统一接入的优势：
- **一套 API**：服务端只需调用一个推送接口，平台自动路由到对应厂商通道
- **统一管理**：在推送平台后台统一查看各通道的送达率、点击率
- **自动降级**：厂商通道不可用时自动降级为长连接推送
- **降低维护成本**：无需关注各厂商 SDK 更新和通道变化

## 5. 推送最佳实践

### 5.1 推送频率与时机控制

推送频率直接影响用户留存，过度推送是用户关闭通知权限的首要原因：

| 频率 | 适用场景 | 用户接受度 |
|------|---------|-----------|
| 实时 | 即时通讯、交易提醒 | ⭐⭐⭐⭐⭐ |
| 每日 1-3 条 | 资讯、社交动态 | ⭐⭐⭐⭐ |
| 每周 2-5 条 | 运营活动、产品更新 | ⭐⭐⭐ |
| 每月 1-3 条 | 月度报告、重大公告 | ⭐⭐ |

**推送时机建议：**
- 避免在 22:00 - 08:00 发送非紧急推送
- 工作日推送打开率高峰：08:00-09:00、12:00-13:00、18:00-20:00
- 周末推送打开率整体低于工作日
- 根据用户所在时区调整推送时间

### 5.2 推送内容合规要求

国内推送内容需遵守以下法规和规范：

- **《个人信息保护法》**：推送内容不得泄露用户个人信息
- **《互联网信息服务管理办法》**：不得推送违法违规内容
- **《通信短信息服务管理规定》**：提供退订方式
- **App Store 审核 5.4 条**：推送必须与 App 功能直接相关，不得用于广告或促销（除非用户明确同意）

> ⚠️ **警告**：App Store 审核对推送内容有严格要求。如果推送内容与 App 核心功能无关（如纯广告推送），可能导致审核被拒。确保推送内容对用户有明确价值。

                        }
                    }

                }
            } else {
                Label("通知已开启", systemImage: "checkmark.circle.fill")
                    .foregroundStyle(.green)
                    .font(.title3)
            }
        }
        .padding()
        .onAppear {
            checkAuthorizationStatus()
        }
        .alert("无法开启通知", isPresented: $showAlert) {
            Button("去设置") {
                if let url = URL(string: UIApplication.openSettingsURLString) {
                    UIApplication.shared.open(url)
                }
            }
            Button("取消", role: .cancel) {}
        } message: {
            Text("请在系统设置中允许本应用发送通知")
        }
    }

    func checkAuthorizationStatus() {
        UNUserNotificationCenter.current().getNotificationSettings { settings in
            DispatchQueue.main.async {
                authorizationStatus = settings.authorizationStatus
            }
        }
    }

    func requestPermission() {
        UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .badge, .sound]) { granted, _ in
            DispatchQueue.main.async {
                if granted {
                    authorizationStatus = .authorized
                    UIApplication.shared.registerForRemoteNotifications()
                } else {
                    authorizationStatus = .denied
                    showAlert = true
                }
            }
        }
    }

### 5.5 推送数据分析与优化

推送不是"发了就行"，需要持续分析数据并优化：

| 指标 | 计算方式 | 优化方向 |
|------|---------|---------|
| 送达率 | 送达数 / 发送数 | 优化厂商通道配置，提升 Android 送达率 |
| 展示率 | 展示数 / 送达数 | 优化推送时机，避免免打扰时段 |
| 点击率 | 点击数 / 展示数 | 优化标题和内容，A/B 测试文案 |
| 转化率 | 目标行为数 / 点击数 | 优化落地页体验 |
| 退订率 | 关闭通知数 / 总用户数 | 降低推送频率，提升内容质量 |

### 5.6 推送与 App 内消息的统一管理

实际项目中，消息来源多样（推送、App 内通知、系统公告），需要统一管理：

```swift
import SwiftUI

struct AppMessage: Identifiable {
    let id: String
    let type: MessageType
    let title: String
    let body: String
    let timestamp: Date
    let isRead: Bool
    let payload: [String: Any]?

    enum MessageType {
        case push
        case inApp
        case system
    }
}

@MainActor
class MessageCenter: ObservableObject {
    @Published var messages: [AppMessage] = []
    @Published var unreadCount: Int = 0

    func addPushMessage(userInfo: [AnyHashable: Any]) {
        let message = AppMessage(
            id: userInfo["_j_msgid"] as? String ?? UUID().uuidString,
            type: .push,
            title: userInfo["title"] as? String ?? "",
            body: userInfo["body"] as? String ?? "",
            timestamp: Date(),
            isRead: false,
            payload: userInfo
        )
        messages.insert(message, at: 0)
        updateUnreadCount()
    }

    func addInAppMessage(title: String, body: String) {
        let message = AppMessage(
            id: UUID().uuidString,
            type: .inApp,
            title: title,
            body: body,
            timestamp: Date(),
            isRead: false,
            payload: nil
        )
        messages.insert(message, at: 0)
        updateUnreadCount()
    }

    func markAsRead(_ messageId: String) {
        if let index = messages.firstIndex(where: { $0.id == messageId }) {
            messages[index] = AppMessage(
                id: messages[index].id,
                type: messages[index].type,
                title: messages[index].title,
                body: messages[index].body,
                timestamp: messages[index].timestamp,
                isRead: true,
                payload: messages[index].payload
            )
            updateUnreadCount()
        }
    }

    func updateUnreadCount() {
        unreadCount = messages.filter { !$0.isRead }.count
    }
}

struct MessageCenterView: View {
    @StateObject private var center = MessageCenter()

    var body: some View {
        List(center.messages) { message in
            HStack(alignment: .top) {
                Circle()
                    .fill(message.isRead ? Color.clear : Color.blue)
                    .frame(width: 8, height: 8)
                    .padding(.top, 6)

                VStack(alignment: .leading, spacing: 4) {
                    HStack {
                        Text(message.title)
                            .font(.headline)
                        Spacer()
                        Text(message.timestamp, style: .relative)
                            .font(.caption)
                            .foregroundStyle(.secondary)
                    }
                    Text(message.body)
                        .font(.subheadline)
                        .foregroundStyle(.secondary)
                        .lineLimit(2)
                }
            }
            .contentShape(Rectangle())
            .onTapGesture {
                center.markAsRead(message.id)
            }
        }
        .navigationTitle("消息中心")
        .toolbar {
            ToolbarItem(placement: .topBarTrailing) {
                Text("\(center.unreadCount)")
                    .font(.caption)
                    .padding(6)
                    .background(Color.red)
                    .foregroundStyle(.white)
                    .clipShape(Circle())
            }
        }
    }
}
```
