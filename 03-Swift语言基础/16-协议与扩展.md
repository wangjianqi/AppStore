## protocol 协议

协议就像是一份**合同**——它规定了"必须做什么"，但不关心"怎么做"。任何类型只要签了这份合同，就必须实现合同里规定的所有要求。

💡 **生活类比**：协议 = 驾照考试标准。标准规定了"必须会倒车入库、侧方停车"，但不管你是用手动挡还是自动挡练的——只要考试通过就行。

### 定义协议

用 `protocol` 关键字定义协议，里面可以声明**属性要求**和**方法要求**。

```swift
protocol Describable {
    var description: String { get }
    func describe() -> String
}
```

逐行解读：

| 代码 | 含义 |
|------|------|
| `protocol Describable` | 定义一个名为 Describable 的协议 |
| `var description: String { get }` | 要求有一个 String 类型的属性，至少可读（`get`） |
| `func describe() -> String` | 要求有一个返回 String 的方法 |

⚠️ **警告**：协议中的属性要求**必须**用 `var` 声明，不能用 `let`。`{ get }` 表示可读，`{ get set }` 表示可读可写。

再看一个更实际的例子：

```swift
protocol Identifiable {
    var id: String { get }
    func identify() -> String
}

protocol Weighted {
    var weight: Double { get set }
    func isHeavy() -> Bool
}
```

| 声明方式 | 含义 | 遵循类型需要 |
|----------|------|-------------|
| `{ get }` | 只读属性要求 | 提供至少可读的属性（可以是 `let` 或 `var`） |
| `{ get set }` | 可读可写属性要求 | 必须提供 `var` 属性，不能是 `let` |

💡 **提示**：协议只定义"有什么"，不包含任何实现代码。方法不写花括号 `{}`，属性不写初始值。

### 遵循协议

#### 类型遵循协议

一个类型要遵循协议，就在类型名后面加 `: 协议名`，然后实现协议要求的所有内容。

```swift
struct User: Identifiable {
    let id: String
    var name: String

    func identify() -> String {
        return "用户ID：\(id)，姓名：\(name)"
    }
}

let user = User(id: "U001", name: "小明")
print(user.identify())
```

输出：
```
用户ID：U001，姓名：小明
```

⚠️ **警告**：如果遵循了协议却没有实现所有要求，编译器会直接报错，不会让你通过。这是 Swift 的"安全第一"设计。

#### 多协议遵循

一个类型可以同时遵循多个协议，用逗号隔开：

```swift
struct Product: Identifiable, Weighted {
    let id: String
    var name: String
    var weight: Double

    func identify() -> String {
        return "商品ID：\(id)，名称：\(name)"
    }

    func isHeavy() -> Bool {
        return weight > 5.0
    }
}

let apple = Product(id: "P001", name: "苹果", weight: 0.3)
let dumbbell = Product(id: "P002", name: "哑铃", weight: 10.0)

print(apple.identify())
print("苹果重吗？\(apple.isHeavy())")
print("哑铃重吗？\(dumbbell.isHeavy())")
```

输出：
```
商品ID：P001，名称：苹果
苹果重吗？false
哑铃重吗？true
```

💡 **提示**：Swift 中一个类型可以遵循任意多个协议，但只能继承一个父类（单继承）。如果既有父类又有协议，写法是 `class 子类: 父类, 协议1, 协议2`，父类必须写在最前面。

### 协议继承

协议可以继承其他协议，继承后就要同时满足父协议和子协议的所有要求：

```swift
protocol Named {
    var name: String { get }
}

protocol Aged {
    var age: Int { get }
}

protocol Person: Named, Aged {
    func introduce() -> String
}

struct Employee: Person {
    var name: String
    var age: Int

    func introduce() -> String {
        return "我叫\(name)，今年\(age)岁"
    }
}

let emp = Employee(name: "小李", age: 28)
print(emp.introduce())
```

输出：
```
我叫小李，今年28岁
```

| 概念 | 说明 |
|------|------|
| 协议继承 | 协议可以继承一个或多个协议 |
| 效果 | 遵循子协议的类型必须实现所有（父+子）要求 |
| 与 class 继承的区别 | 协议可以多继承，class 只能单继承 |

💡 **提示**：协议的多继承设计非常灵活，可以把功能拆成小协议再组合，这也是面向协议编程的核心思路。

## extension 扩展

扩展就像给已有类型**外挂新技能**——不需要修改原始代码，就能给类型添加新功能。

💡 **生活类比**：扩展 = 给手机装 App。手机出厂时没有这个功能，但装了 App 之后就有了，而且不需要拆开手机改硬件。

### 扩展类型

#### 给已有类型添加方法

```swift
extension String {
    func shout() -> String {
        return self.uppercased() + "!!!"
    }

    func isLonger(than length: Int) -> Bool {
        return self.count > length
    }
}

let message = "hello"
print(message.shout())
print(message.isLonger(than: 3))
```

输出：
```
HELLO!!!
true
```

💡 **提示**：`self` 在扩展中代表调用方法的那个实例本身。上面代码中 `self` 就是那个字符串。

#### 给已有类型添加计算属性

```swift
extension String {
    var wordCount: Int {
        return self.split(separator: " ").count
    }

    var isFirstLetterUppercase: Bool {
        guard let first = self.first else { return false }
        return first.isUppercase
    }
}

let sentence = "Hello world from Swift"
print("单词数：\(sentence.wordCount)")
print("首字母大写：\(sentence.isFirstLetterUppercase)")
```

输出：
```
单词数：4
首字母大写：true
```

⚠️ **警告**：扩展**不能**添加存储属性（如 `var x: Int = 0`），只能添加计算属性。因为存储属性会影响类型的内存布局，而扩展不允许改变原有内存结构。

#### 给 Int 添加实用方法

```swift
extension Int {
    var isEven: Bool {
        return self % 2 == 0
    }

    var isPositive: Bool {
        return self > 0
    }

    func times(_ action: () -> Void) {
        for _ in 0..<self {
            action()
        }
    }
}

print(4.isEven)
print((-3).isPositive)

3.times {
    print("你好！")
}
```

输出：
```
true
false
你好！
你好！
你好！
```

💡 **提示**：Swift 的 `Int`、`String`、`Array`、`Dictionary` 等基础类型都是用 struct 实现的，都可以用 extension 扩展！

### 扩展协议（协议默认实现）

扩展最强大的用法之一：给协议提供**默认实现**。这样遵循协议的类型就不必每个方法都自己写了。

```swift
protocol Greetable {
    var name: String { get }
    func greet() -> String
}

extension Greetable {
    func greet() -> String {
        return "你好，我是\(name)！"
    }
}

struct Teacher: Greetable {
    let name: String
}

struct Student: Greetable {
    let name: String

    func greet() -> String {
        return "老师好！我是学生\(name)"
    }
}

let teacher = Teacher(name: "王老师")
let student = Student(name: "小明")

print(teacher.greet())
print(student.greet())
```

输出：
```
你好，我是王老师！
老师好！我是学生小明
```

| 情况 | 行为 |
|------|------|
| 类型没有自己实现 | 使用协议扩展中的默认实现 |
| 类型自己实现了 | 使用类型自己的实现（覆盖默认实现） |

💡 **提示**：协议默认实现是 Swift 面向协议编程的基石。SwiftUI 标准库大量使用了这个特性——很多协议方法都有默认实现，你只需要覆盖你关心的部分。

## 面向协议编程思想入门

### 什么是面向协议编程

面向协议编程（Protocol-Orientated Programming，简称 POP）是 Apple 在 Swift 中大力推崇的编程范式。核心思想是：

> **用协议定义能力，用扩展提供默认实现，用组合代替继承。**

💡 **生活类比**：
- 面向对象编程像"家族继承"——儿子继承爸爸的能力，但只能有一个爸爸
- 面向协议编程像"考资格证"——你可以同时拥有驾照、厨师证、教师资格证，每个证代表一种能力

### 与面向对象编程的区别

| 对比维度 | 面向对象编程（OOP） | 面向协议编程（POP） |
|----------|---------------------|---------------------|
| 核心思想 | 通过继承复用代码 | 通过协议组合复用代码 |
| 继承方式 | 单继承（只有一个父类） | 多协议（可遵循多个协议） |
| 代码复用 | 父类提供实现，子类继承 | 协议扩展提供默认实现 |
| 耦合度 | 高（子类强依赖父类） | 低（类型只需关心协议要求） |
| 适用类型 | 仅 class 可继承 | struct、class、enum 都可遵循 |
| SwiftUI 契合度 | ❌ 视图不能用 class 继承 | ✅ 视图用 struct + 协议组合 |

⚠️ **警告**：POP 不是要完全替代 OOP，两者各有适用场景。SwiftUI 中 POP 用得更多，但在需要共享可变状态时 class 仍然不可替代。

### SwiftUI 中的协议应用

在 SwiftUI 中，协议无处不在。先看一个最经典的例子：

```swift
struct ContentView: View {
    var body: some View {
        Text("Hello, SwiftUI!")
    }
}
```

这段代码背后发生了什么？

| 代码 | 含义 |
|------|------|
| `struct ContentView` | 定义一个结构体 |
| `: View` | 遵循 View 协议 |
| `var body: some View` | 实现 View 协议要求的 body 属性 |
| `some View` | 返回某种遵循 View 协议的类型 |

`View` 协议的简化定义长这样：

```swift
protocol View {
    associatedtype Body: View
    var body: Body { get }
}
```

💡 **提示**：你不需要现在完全理解 `associatedtype`，只需知道：遵循 `View` 协议就必须提供 `body` 属性，这就是协议的"合同"作用。

再看一个 SwiftUI 中常见的协议组合：

```swift
struct MovieCard: View, Identifiable {
    let id: String
    let title: String

    var body: some View {
        Text(title)
    }
}
```

- `View` 协议 → 让它能在界面中显示
- `Identifiable` 协议 → 让它能在 `List` / `ForEach` 中唯一标识

这就是面向协议编程的威力：**按需组合能力，灵活又清晰**。

## 泛型基础

泛型让你写出**不限定具体类型**的代码，就像一个万能模板——写一次，适用于多种类型。

💡 **生活类比**：泛型 = 快递柜。快递柜不关心你放的是书、衣服还是零食，只要尺寸放得下就行。不同类型的包裹用同一个柜子。

### 泛型函数

#### 为什么需要泛型

假设你要写一个交换两个值的函数，不用泛型的话：

```swift
func swapInts(_ a: inout Int, _ b: inout Int) {
    let temp = a
    a = b
    b = temp
}

func swapStrings(_ a: inout String, _ b: inout String) {
    let temp = a
    a = b
    b = temp
}

func swapDoubles(_ a: inout Double, _ b: inout Double) {
    let temp = a
    a = b
    b = temp
}
```

三个函数逻辑完全一样，只是类型不同！用泛型只需写一次：

```swift
func swapValues<T>(_ a: inout T, _ b: inout T) {
    let temp = a
    a = b
    b = temp
}

var x = 10
var y = 20
swapValues(&x, &y)
print("x=\(x), y=\(y)")

var a = "Hello"
var b = "World"
swapValues(&a, &b)
print("a=\(a), b=\(b)")
```

输出：
```
x=20, y=10
a=World, b=Hello
```

#### 泛型函数语法

```swift
func 函数名<占位类型>(参数: 占位类型) -> 占位类型 {
    // 函数体
}
```

| 语法元素 | 含义 |
|----------|------|
| `<T>` | 声明一个类型占位符，`T` 是常用名（Type 的首字母） |
| `T` 在参数中 | 表示"这个参数的类型是 T" |
| `T` 在返回值中 | 表示"返回值的类型也是 T" |

💡 **提示**：`T` 只是约定俗成的名字，你也可以用其他名字，如 `<Element>`、`<ItemType>`。但 `T`、`U`、`V` 是最通用的写法。

### 泛型类型

泛型不仅可以用在函数上，还可以用在结构体、类、枚举上。

#### 泛型结构体

```swift
struct Stack<Element> {
    private var items: [Element] = []

    mutating func push(_ item: Element) {
        items.append(item)
    }

    mutating func pop() -> Element? {
        return items.popLast()
    }

    var top: Element? {
        return items.last
    }

    var count: Int {
        return items.count
    }
}

var intStack = Stack<Int>()
intStack.push(1)
intStack.push(2)
intStack.push(3)
print(intStack.pop()!)
print(intStack.top!)

var stringStack = Stack<String>()
stringStack.push("Swift")
stringStack.push("iOS")
print(stringStack.pop()!)
```

输出：
```
3
2
iOS
```

💡 **提示**：Swift 标准库中的 `Array<Element>`、`Dictionary<Key, Value>`、`Optional<Wrapped>` 都是泛型类型！你现在知道为什么声明数组要写 `[Int]` 了吧——它就是 `Array<Int>` 的语法糖。

#### 泛型枚举

上一章见过的 `APIResponse<T>` 就是泛型枚举，Swift 标准库中的 `Optional` 也是：

```swift
enum Optional<Wrapped> {
    case some(Wrapped)
    case none
}
```

`Int?` 其实就是 `Optional<Int>` 的语法糖！

### 类型约束

#### 限制泛型类型

有时候你需要限制泛型类型必须满足某些条件，比如"必须是数字"或"必须遵循某个协议"。

```swift
func findIndex<T: Equatable>(of value: T, in array: [T]) -> Int? {
    for (index, item) in array.enumerated() {
        if item == value {
            return index
        }
    }
    return nil
}

let names = ["Alice", "Bob", "Charlie"]
if let index = findIndex(of: "Bob", in: names) {
    print("Bob 在第 \(index) 个位置")
}

let numbers = [10, 20, 30, 40]
if let index = findIndex(of: 30, in: numbers) {
    print("30 在第 \(index) 个位置")
}
```

输出：
```
Bob 在第 1 个位置
30 在第 2 个位置
```

| 约束写法 | 含义 |
|----------|------|
| `<T: Equatable>` | T 必须遵循 Equatable 协议（可以用 `==` 比较） |
| `<T: Comparable>` | T 必须遵循 Comparable 协议（可以用 `<` `>` 比较） |
| `<T: Numeric>` | T 必须是数字类型 |
| `<T: View>` | T 必须遵循 View 协议 |

⚠️ **警告**：不加约束的泛型只能赋值和传参，不能使用 `==`、`<` 等运算符，因为编译器不知道这个类型是否支持这些操作。

#### where 子句

`where` 子句可以写更复杂的约束条件：

```swift
func allEqual<T>(_ array: [T]) -> Bool where T: Equatable {
    guard let first = array.first else { return true }
    for item in array {
        if item != first {
            return false
        }
    }
    return true
}

print(allEqual([1, 1, 1]))
print(allEqual([1, 2, 1]))
print(allEqual(["a", "a", "a"]))
```

输出：
```
true
false
true
```

💡 **提示**：`where` 子句在 SwiftUI 中非常常见，比如 `func body(content: Content) -> some View where Content: View`，表示 content 参数必须遵循 View 协议。

#### SwiftUI 中的泛型初窥

你会在 SwiftUI 中频繁看到泛型，这里先混个眼熟：

```swift
// List 的泛型参数
struct List<Content>: View where Content: View {
    // ...
}

// @State 的泛型
@propertyWrapper
struct State<Value> {
    // ...
}

// Environment 的泛型
struct Environment<Value> {
    // ...
}
```

现在不需要理解细节，只需知道：**泛型让 SwiftUI 的组件可以处理各种类型的数据**。

## 小结

| 概念 | 关键字 | 核心作用 | 一句话总结 |
|------|--------|----------|-----------|
| 协议 | `protocol` | 定义能力合同 | "你必须实现这些功能" |
| 遵循协议 | `: ProtocolName` | 签合同、兑现承诺 | 类型名后加冒号和协议名 |
| 协议继承 | `protocol B: A` | 协议组合升级 | 子协议 = 父协议要求 + 自己的要求 |
| 扩展 | `extension` | 给已有类型加功能 | 不改原码，外挂新技能 |
| 协议默认实现 | `extension Protocol` | 给协议方法写默认代码 | 不想写就帮你写好，想自定义就覆盖 |
| 泛型函数 | `<T>` | 函数不限定类型 | 一个模板套多种类型 |
| 泛型类型 | `struct Stack<T>` | 类型不限定元素类型 | Array、Optional 都是泛型 |
| 类型约束 | `<T: Protocol>` | 限制泛型必须有能力 | "T 至少要支持某某操作" |

⚠️ **重点记忆**：
1. **协议只定义要求，不提供实现**（除非用协议扩展给默认实现）
2. **扩展不能添加存储属性**，只能添加计算属性和方法
3. **协议默认实现**是 Swift 面向协议编程的核心武器
4. **泛型**让你写一次代码适配多种类型，SwiftUI 中无处不在
5. **类型约束**保证泛型类型具备必要的能力（如 `Equatable` 才能用 `==`）
