## 1. 为什么需要异步编程

### 同步 vs 异步——生活类比

想象你去银行办事：

| | 同步（排队） | 异步（取号） |
|---|---|---|
| **方式** | 站在窗口前等，直到轮到你 | 取个号，坐着等叫号 |
| **等待时** | 什么都不能做，干等 | 可以刷手机、喝水、聊天 |
| **效率** | 一个人卡住，后面全堵 | 大家可以同时做别的事 |
| **对应编程** | 代码一行行执行，遇到耗时操作就卡住 | 耗时操作放到后台，主流程继续走 |

> 💡 在 iOS 开发中，网络请求、文件读写、图片加载等都是耗时操作。如果用同步方式，界面会"冻住"，用户体验极差。异步编程就是让这些耗时操作在后台执行，不阻塞主线程。

### 一个直观的例子

```swift
// 同步方式——界面会卡住
func downloadImageSync() -> Data {
    let url = URL(string: "https://example.com/image.png")!
    let data = try! Data(contentsOf: url) // 卡在这里，直到下载完成
    return data
}

// 异步方式——界面不会卡住
func downloadImage() async throws -> Data {
    let url = URL(string: "https://example.com/image.png")!
    let (data, _) = try await URLSession.shared.data(from: url)
    return data
}
```

> ⚠️ iOS 的主线程（Main Thread）负责处理 UI 更新和用户交互。如果在主线程执行耗时操作，界面就会"冻住"，用户无法操作，系统甚至可能终止你的 App。

## 2. 错误处理基础

### 2.1 定义错误类型

在 Swift 中，错误通常用遵循 `Error` 协议的枚举来表示：

```swift
enum VendingMachineError: Error {
    case invalidSelection
    case insufficientFunds(coinsNeeded: Int)
    case outOfStock
}
```

> 💡 用枚举定义错误的好处：每种错误情况都是明确的，编译器会帮你检查是否处理了所有情况。

### 2.2 throws 函数——可能出错的函数

用 `throws` 关键字标记一个函数，表示它可能抛出错误：

```swift
func vend(itemName: String) throws -> String {
    guard itemName != "Candy Bar" else {
        throw VendingMachineError.outOfStock
    }
    guard itemName != "Chips" else {
        throw VendingMachineError.insufficientFunds(coinsNeeded: 2)
    }
    return "Dispensing \(itemName)"
}
```

> ⚠️ `throw` 会立即中断函数执行，后面的代码不会运行。就像你点外卖发现没开门，直接打道回府，不会继续等。

### 2.3 do-catch——捕获并处理错误

```swift
do {
    let result = try vend(itemName: "Chips")
    print(result)
} catch VendingMachineError.insufficientFunds(let coinsNeeded) {
    print("余额不足，还需要 \(coinsNeeded) 个硬币")
} catch VendingMachineError.outOfStock {
    print("已售罄")
} catch {
    print("发生了未知错误：\(error)")
}
```

**执行流程：**

| 步骤 | 说明 |
|---|---|
| 1 | 进入 `do` 块，执行 `try` 语句 |
| 2 | 如果没有错误，正常执行 `do` 块剩余代码 |
| 3 | 如果抛出错误，跳到 `catch` 块匹配对应错误 |
| 4 | 匹配成功则执行该 `catch` 块；都不匹配则执行最后的通用 `catch` |

### 2.4 try?、try!——简化错误处理

| 方式 | 行为 | 返回值 | 适用场景 |
|---|---|---|---|
| `try` | 必须配合 `do-catch` 或 `throws` 函数 | 原返回值或抛出错误 | 需要详细处理错误时 |
| `try?` | 忽略错误，出错返回 `nil` | Optional | 不关心具体错误，只关心成功与否 |
| `try!` | 出错直接崩溃 | 原返回值（强制解包） | 100% 确定不会出错时 |

```swift
// try? —— 出错返回 nil，不会崩溃
let result1 = try? vend(itemName: "Chips")
// result1 的类型是 String?，如果出错则为 nil

// try! —— 出错直接崩溃！
let result2 = try! vend(itemName: "Water")
// 只有你 100% 确定不会出错时才用
```

> ⚠️ `try!` 非常危险！就像你断言"这根桥一定不会断"然后全速冲过去——一旦出错，App 直接崩溃。实际开发中尽量避免使用 `try!`，除非你完全确定不会出错（比如加载 App 内置的资源文件）。

### 2.5 错误处理的完整示例

```swift
enum NetworkError: Error {
    case badURL
    case noConnection
    case serverError(code: Int)
}

func fetchUserData(userId: String) throws -> String {
    guard !userId.isEmpty else {
        throw NetworkError.badURL
    }
    // 模拟网络请求
    let success = Bool.random()
    if !success {
        throw NetworkError.serverError(code: 500)
    }
    return "用户 \(userId) 的数据"
}

// 使用 do-catch 处理
do {
    let data = try fetchUserData(userId: "123")
    print("获取成功：\(data)")
} catch NetworkError.badURL {
    print("URL 无效")
} catch NetworkError.serverError(let code) {
    print("服务器错误，状态码：\(code)")
} catch {
    print("其他错误：\(error)")
}

// 使用 try? 简化
if let data = try? fetchUserData(userId: "123") {
    print("获取成功：\(data)")
} else {
    print("获取失败，但我不关心具体原因")
}
```

## 3. Result 类型

### 3.1 什么是 Result 类型

`Result` 是 Swift 标准库提供的枚举，专门用来封装一个操作的"成功"或"失败"结果：

```swift
enum Result<Success, Failure: Error> {
    case success(Success)
    case failure(Failure)
}
```

> 💡 你可以把 `Result` 想象成一个快递包裹——要么里面是你要的东西（success），要么是一张退货单（failure）。你收到包裹时必须处理这两种情况。

### 3.2 使用 Result 类型

```swift
enum LoadError: Error {
    case fileNotFound
    case permissionDenied
    case dataCorrupted
}

func loadConfig(fileName: String) -> Result<String, LoadError> {
    guard fileName != "" else {
        return .failure(.fileNotFound)
    }
    guard fileName != "secret" else {
        return .failure(.permissionDenied)
    }
    return .success("配置内容加载成功")
}

// 处理 Result
let result = loadConfig(fileName: "config")

switch result {
case .success(let content):
    print(content)
case .failure(.fileNotFound):
    print("文件未找到")
case .failure(.permissionDenied):
    print("没有权限")
case .failure(.dataCorrupted):
    print("数据损坏")
}
```

### 3.3 Result 的实用方法

```swift
// get() —— 将 Result 转为 throws 调用
let result = loadConfig(fileName: "config")
do {
    let content = try result.get()
    print(content)
} catch {
    print("加载失败：\(error)")
}

// map() —— 转换成功值
let upperResult = loadConfig(fileName: "config").map { $0.uppercased() }

// flatMap() —— 链式转换
let finalResult = loadConfig(fileName: "config")
    .flatMap { content in
        .success(content.count)
    }
```

### 3.4 Result vs throws 对比

| 特性 | `throws` | `Result` |
|---|---|---|
| 错误传播 | 自动向上传播 | 需要手动处理 |
| 存储与传递 | 不能直接存储"可能失败的操作" | 可以作为属性、返回值存储 |
| 异步回调 | 需要配合 completion handler | 天然适合回调模式 |
| 风格 | 偏向"异常"风格 | 偏向"值"风格 |

> 💡 在现代 Swift 中，`async/await` + `throws` 是首选方案。但 `Result` 在回调风格的 API、存储异步操作结果等场景中仍然很有用。

## 4. async/await 基础

### 4.1 什么是 async/await

`async/await` 是 Swift 5.5 引入的异步编程语法，让你像写同步代码一样写异步代码：

| 关键字 | 作用 | 类比 |
|---|---|---|
| `async` | 标记函数为异步函数 | 给任务贴上"需要等待"的标签 |
| `await` | 等待异步操作完成 | 排队等叫号，到了你再继续 |

```swift
// 定义异步函数
func fetchWeather(city: String) async throws -> String {
    let url = URL(string: "https://api.weather.com/\(city)")!
    let (data, _) = try await URLSession.shared.data(from: url)
    return String(data: data, encoding: .utf8) ?? "无数据"
}

// 调用异步函数
func loadWeather() async {
    do {
        let weather = try await fetchWeather(city: "Beijing")
        print("天气：\(weather)")
    } catch {
        print("获取天气失败：\(error)")
    }
}
```

> 💡 `await` 不是"阻塞等待"，而是"暂停当前函数，让出线程去做别的事，等结果回来再继续"。就像你在餐厅点餐后坐下等，服务员不会一直站在你旁边，而是去服务其他客人，你的菜好了再端给你。

### 4.2 异步函数的调用规则

```swift
// 规则1：异步函数只能在异步上下文中调用
func example() async {
    // ✅ 正确：async 函数中可以调用 async 函数
    let data = await fetchData()
}

// 规则2：普通函数不能直接调用异步函数
// func syncExample() {
//     let data = await fetchData() // ❌ 编译错误！
// }

// 规则3：使用 Task 在普通函数中调用异步函数
func syncExample() {
    Task {
        let data = await fetchData()
        print(data)
    }
}
```

### 4.3 Task——创建异步任务

`Task` 是启动异步操作的入口，可以在任何地方创建：

```swift
// 在普通函数中创建异步任务
func viewDidLoad() {
    Task {
        do {
            let data = try await fetchUserData(userId: "1")
            print(data)
        } catch {
            print(error)
        }
    }
}

// Task 的优先级
Task(priority: .high) {
    await importantWork()
}

Task(priority: .background) {
    await cleanupWork()
}

// 获取 Task 的结果
let task = Task {
    return 42
}
let value = await task.value // 42

// 取消 Task
let longTask = Task {
    try await Task.sleep(nanoseconds: 10_000_000_000) // 睡10秒
}
longTask.cancel() // 取消任务
```

| Task 属性/方法 | 说明 |
|---|---|
| `task.value` | 获取任务结果（需要 `await`） |
| `task.cancel()` | 取消任务 |
| `task.isCancelled` | 检查是否已取消 |
| `Task.currentPriority` | 当前任务优先级 |
| `Task.sleep(nanoseconds:)` | 异步等待（不阻塞线程） |

> ⚠️ `Task.sleep` 和 `Thread.sleep` 完全不同！`Thread.sleep` 会阻塞当前线程，`Task.sleep` 只是暂停当前任务，线程可以去做别的事。

## 5. 并发任务

### 5.1 async let——并发执行多个任务

当你需要同时执行多个独立任务时，用 `async let`：

```swift
// 串行执行——一个接一个，总时间 = 时间1 + 时间2 + 时间3
func loadSerial() async throws {
    let user = try await fetchUser()       // 等2秒
    let posts = try await fetchPosts()     // 等3秒
    let friends = try await fetchFriends() // 等1秒
    // 总共等 6 秒
}

// 并发执行——同时开始，总时间 = 最慢的那个
func loadConcurrent() async throws {
    async let user = fetchUser()       // 同时开始
    async let posts = fetchPosts()     // 同时开始
    async let friends = fetchFriends() // 同时开始

    // 等待所有结果
    let (userData, postsData, friendsData) = try await (user, posts, friends)
    // 总共约 3 秒（最慢的那个）
}
```

> 💡 `async let` 就像同时点三个菜，哪个先做好就先上，最后等所有菜都齐了再开吃。比一个一个点菜快多了！

### 5.2 TaskGroup——动态并发任务

当任务数量不确定时，使用 `TaskGroup`：

```swift
func fetchAllImages(urls: [URL]) async throws -> [Data] {
    try await withThrowingTaskGroup(of: Data.self) { group in
        for url in urls {
            group.addTask {
                let (data, _) = try await URLSession.shared.data(from: url)
                return data
            }
        }

        var images: [Data] = []
        for try await image in group {
            images.append(image)
        }
        return images
    }
}

// 使用
let urls = [
    URL(string: "https://example.com/1.png")!,
    URL(string: "https://example.com/2.png")!,
    URL(string: "https://example.com/3.png")!,
]
let images = try await fetchAllImages(urls: urls)
```

### 5.3 async let vs TaskGroup 对比

| 特性 | `async let` | `TaskGroup` |
|---|---|---|
| 任务数量 | 固定、编译时已知 | 动态、运行时确定 |
| 结果收集 | 逐个 `await` | 循环遍历 |
| 错误处理 | 每个任务单独处理 | 统一处理 |
| 取消 | 需要手动管理 | 可统一取消 |
| 适用场景 | 2~3 个固定并发任务 | N 个动态并发任务 |

## 6. 主线程与后台线程

### 6.1 为什么需要关心线程

iOS 中，UI 操作必须在主线程执行。如果你在后台线程更新 UI，可能会出现：

- UI 不刷新
- 闪烁或错乱
- 直接崩溃

> 💡 主线程就像餐厅的大堂经理，专门负责接待客人（用户交互）和上菜（更新 UI）。如果让后厨（后台线程）直接上菜，可能会搞乱顺序。

### 6.2 @MainActor——标记主线程执行

`@MainActor` 表示某个类型或函数必须在主线程上执行：

```swift
// 标记整个类在主线程执行
@MainActor
class ViewModel: ObservableObject {
    @Published var userName: String = ""
    @Published var isLoading: Bool = false

    func loadUser() async throws {
        isLoading = true
        // 即使 fetchData 在后台执行
        let data = try await fetchData()
        // 回到这里时仍在主线程，可以安全更新 UI
        userName = data.name
        isLoading = false
    }
}
```

```swift
// 标记单个函数在主线程执行
@MainActor
func updateUI(with data: String) {
    label.text = data
}
```

### 6.3 MainActor.run——临时切换到主线程

当你需要在后台任务中临时回到主线程时：

```swift
func processImage() async {
    // 在后台线程处理图片
    let processedImage = await heavyImageProcessing()

    // 切换到主线程更新 UI
    await MainActor.run {
        imageView.image = processedImage
        loadingIndicator.isHidden = true
    }
}
```

### 6.4 线程切换总结

| 方式 | 用途 | 示例 |
|---|---|---|
| `@MainActor` (类/结构体) | 整个类型的所有属性和方法都在主线程 | `@MainActor class ViewModel` |
| `@MainActor` (函数) | 某个函数在主线程执行 | `@MainActor func updateUI()` |
| `MainActor.run` | 在后台代码中临时切换到主线程 | `await MainActor.run { ... }` |
| `nonisolated` | 在 @MainActor 类型中标记不需要主线程的方法 | `nonisolated func compute() -> Int` |

> ⚠️ `@MainActor` 不会让异步操作本身变慢。`await` 等待结果时，当前线程会被释放去做别的事，结果回来后才在主线程继续执行。

## 7. 异步序列

### 7.1 for await in——遍历异步数据流

有些数据不是一次性到齐的，而是像流水一样陆续到来。`for await in` 就是用来处理这种情况的：

```swift
// 遍历异步序列
func processNotifications() async {
    for await notification in NotificationCenter.default.notifications(named: .MyNotification) {
        print("收到通知：\(notification)")
    }
}
```

> 💡 普通的 `for in` 是遍历已经存在的集合，就像读一本已经写好的书。`for await in` 是遍历正在产生的数据流，就像听直播——内容是实时产生的，你不知道什么时候结束。

### 7.2 AsyncStream——自定义异步序列

```swift
func watchMessages() -> AsyncStream<String> {
    AsyncStream { continuation in
        let observer = NotificationCenter.default.addObserver(
            forName: .NewMessage,
            object: nil,
            queue: nil
        ) { notification in
            if let text = notification.userInfo?["text"] as? String {
                continuation.yield(text)
            }
        }

        continuation.onTermination = { _ in
            NotificationCenter.default.removeObserver(observer)
        }
    }
}

// 使用
func listenMessages() async {
    let stream = watchMessages()
    for await message in stream {
        print("新消息：\(message)")
    }
}
```

### 7.3 异步序列 vs 同步序列

| 特性 | 同步序列 (`for in`) | 异步序列 (`for await in`) |
|---|---|---|
| 数据来源 | 已有集合 | 实时产生的数据流 |
| 阻塞 | 会阻塞当前线程 | 暂停当前任务，不阻塞线程 |
| 结束条件 | 遍历完集合 | 数据流结束或被取消 |
| 典型场景 | 遍历数组 | 实时通知、WebSocket 消息、文件逐行读取 |

## 8. 实际应用场景

### 8.1 网络请求

```swift
enum APIError: Error {
    case invalidURL
    case networkError
    case decodingError
}

struct User: Codable {
    let id: Int
    let name: String
}

@MainActor
class UserViewModel: ObservableObject {
    @Published var user: User?
    @Published var errorMessage: String?

    func fetchUser(id: Int) async {
        guard let url = URL(string: "https://api.example.com/users/\(id)") else {
            errorMessage = "无效的 URL"
            return
        }

        do {
            let (data, response) = try await URLSession.shared.data(from: url)

            guard let httpResponse = response as? HTTPURLResponse,
                  (200...299).contains(httpResponse.statusCode) else {
                throw APIError.networkError
            }

            user = try JSONDecoder().decode(User.self, from: data)
            errorMessage = nil
        } catch {
            errorMessage = "加载失败：\(error.localizedDescription)"
        }
    }
}
```

### 8.2 文件读取

```swift
func readLogFile(at path: String) async throws -> [String] {
    let url = URL(fileURLWithPath: path)
    let content = try String(contentsOf: url, encoding: .utf8)
    return content.components(separatedBy: .newlines).filter { !$0.isEmpty }
}

// 使用
func analyzeLogs() async {
    do {
        let lines = try await readLogFile(at: "/tmp/app.log")
        for line in lines {
            if line.contains("ERROR") {
                print("发现错误：\(line)")
            }
        }
    } catch {
        print("读取日志失败：\(error)")
    }
}
```

### 8.3 延迟操作

```swift
// 延迟执行——不阻塞线程
func showSplashThenContinue() async {
    // 显示启动画面
    isShowingSplash = true

    // 等待 2 秒（不阻塞 UI）
    try? await Task.sleep(nanoseconds: 2_000_000_000)

    // 切换到主界面
    isShowingSplash = false
}

// 带取消的延迟
func countdown(seconds: Int) async {
    for i in (1...seconds).reversed() {
        guard !Task.isCancelled else { return }
        print("\(i)...")
        try? await Task.sleep(nanoseconds: 1_000_000_000)
    }
    print("时间到！")
}
```

### 8.4 综合：带加载状态的完整网络请求

```swift
@MainActor
class ArticleViewModel: ObservableObject {
    @Published var articles: [Article] = []
    @Published var isLoading = false
    @Published var error: Error?

    func loadArticles() async {
        isLoading = true
        error = nil

        do {
            async let trending = fetchTrending()
            async let latest = fetchLatest()
            async let recommended = fetchRecommended()

            let (trendingData, latestData, recommendedData) = try await (
                trending, latest, recommended
            )

            articles = trendingData + latestData + recommendedData
        } catch {
            self.error = error
        }

        isLoading = false
    }

    private func fetchTrending() async throws -> [Article] {
        let url = URL(string: "https://api.example.com/trending")!
        let (data, _) = try await URLSession.shared.data(from: url)
        return try JSONDecoder().decode([Article].self, from: data)
    }

    private func fetchLatest() async throws -> [Article] {
        let url = URL(string: "https://api.example.com/latest")!
        let (data, _) = try await URLSession.shared.data(from: url)
        return try JSONDecoder().decode([Article].self, from: data)
    }

    private func fetchRecommended() async throws -> [Article] {
        let url = URL(string: "https://api.example.com/recommended")!
        let (data, _) = try await URLSession.shared.data(from: url)
        return try JSONDecoder().decode([Article].self, from: data)
    }
}
```

## 9. 常见陷阱与最佳实践

### 9.1 常见陷阱

#### 陷阱1：在主线程执行耗时操作

```swift
// ❌ 错误：在主线程做耗时计算
@MainActor
func processImage() {
    let result = heavyProcessing() // 界面冻住！
    imageView.image = result
}

// ✅ 正确：耗时操作放后台，结果回主线程
func processImage() async {
    let result = await heavyProcessing() // 后台执行
    await MainActor.run {
        imageView.image = result
    }
}
```

#### 陷阱2：忘记处理错误

```swift
// ❌ 错误：吞掉错误，出问题时毫无头绪
func loadData() async {
    let data = try? await fetchData()
    // data 为 nil 时，你完全不知道为什么
}

// ✅ 正确：至少打印错误信息
func loadData() async {
    do {
        let data = try await fetchData()
        updateUI(with: data)
    } catch {
        print("加载失败：\(error)")
        showError(message: error.localizedDescription)
    }
}
```

#### 陷阱3：过度使用 Task

```swift
// ❌ 错误：在 async 函数中不需要 Task
func loadUser() async {
    Task {  // 多余！
        let user = await fetchUser()
        print(user)
    }
}

// ✅ 正确：直接 await
func loadUser() async {
    let user = await fetchUser()
    print(user)
}
```

#### 陷阱4：Task 创建后不管理

```swift
// ❌ 错误：创建了一堆 Task 但不管理
func loadAll() {
    Task { await loadA() }
    Task { await loadB() }
    Task { await loadC() }
    // 无法取消，无法获取结果，无法处理错误
}

// ✅ 正确：使用 async let 或 TaskGroup 管理并发
func loadAll() async throws {
    async let a = loadA()
    async let b = loadB()
    async let c = loadC()
    let results = try await (a, b, c)
}
```

### 9.2 最佳实践

| 实践 | 说明 |
|---|---|
| **优先使用 async/await** | 比回调、闭包更清晰易读 |
| **ViewModel 加 @MainActor** | 确保状态更新在主线程 |
| **错误类型要具体** | 用枚举定义明确的错误，别只用笼统的 `Error` |
| **避免 try!** | 除非 100% 确定不会出错 |
| **检查 Task.isCancelled** | 长时间任务中定期检查是否被取消 |
| **合理使用并发** | 独立任务用 `async let`，动态任务用 `TaskGroup` |
| **耗时操作放后台** | 网络、文件、计算等不要在主线程 |
| **UI 更新回主线程** | 使用 `@MainActor` 或 `MainActor.run` |

### 9.3 异步编程检查清单

在写异步代码时，问自己这几个问题：

- [ ] 这个耗时操作是否在后台执行？
- [ ] UI 更新是否在主线程？
- [ ] 错误是否被正确处理？
- [ ] 并发任务之间是否有依赖关系？（有依赖就串行，无依赖就并发）
- [ ] 长时间任务是否支持取消？
- [ ] 是否避免了 `try!`？

## 小结

本章我们学习了 Swift 异步编程与错误处理的核心知识：

1. **异步编程的必要性**：耗时操作不能阻塞主线程，异步编程让 App 保持流畅
2. **错误处理**：`throws` 标记可能出错的函数，`do-catch` 捕获错误，`try?` 简化处理，`try!` 谨慎使用
3. **Result 类型**：用枚举封装成功与失败，适合存储和传递异步操作结果
4. **async/await**：像写同步代码一样写异步代码，`async` 标记函数，`await` 等待结果
5. **并发任务**：`async let` 处理固定并发，`TaskGroup` 处理动态并发
6. **线程管理**：`@MainActor` 确保主线程执行，`MainActor.run` 临时切换
7. **异步序列**：`for await in` 处理实时数据流
8. **实际应用**：网络请求、文件读取、延迟操作都是典型的异步场景
9. **最佳实践**：耗时操作放后台、UI 更新回主线程、正确处理错误、合理使用并发

> 💡 异步编程是 iOS 开发中最重要的技能之一。一开始可能觉得概念很多，但只要记住核心原则——**耗时操作不阻塞主线程，UI 更新必须在主线程**——在实际项目中多练习，很快就能熟练掌握！
