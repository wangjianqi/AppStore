# 68-提交审核

> 🎯 **本章目标**：掌握构建版本上传、审核信息填写、TestFlight 内测分发、提交审核操作、加急审核申请和审核状态跟踪的完整流程，让你的 App 顺利进入 Apple 审核环节。

---

## 上传构建版本

> 🎯 **本节目标**：学会通过 Xcode 和 Transporter 两种方式上传构建版本，并了解上传后的处理流程。

### 通过 Xcode 上传

这是最直接的上传方式，在 Archive 完成后直接操作。

**上传步骤：**

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | 在 Organizer 中选择归档 | Product → Archive 后 Organizer 自动打开 |
| 2 | 点击 **Distribute App** | 进入分发向导 |
| 3 | 选择 **App Store Connect** | 上架发布方式 |
| 4 | 选择 **Upload** | 将构建版本上传到 App Store Connect |
| 5 | 勾选上传选项 | 建议保持默认勾选 |
| 6 | 确认签名信息 | 检查证书和描述文件 |
| 7 | 点击 **Upload** | 开始上传 |
| 8 | 等待上传完成 | 根据网速和 App 大小，通常 5-30 分钟 |

**上传选项说明：**

| 选项 | 说明 | 建议 |
|------|------|------|
| Upload your app's symbols | 上传符号文件，用于崩溃日志解析 | ✅ 建议勾选 |
| Manage Version and Build Number | 自动管理版本号 | 按需选择 |
| Sign App with Distribution Certificate | 使用发布证书签名 | ✅ 保持勾选 |

💡 **提示**：上传过程中如果网络不稳定导致中断，不需要重新 Archive，直接重新执行上传操作即可。

### 通过 Transporter 上传

Transporter 是 Apple 提供的专用上传工具，适合需要先导出 .ipa 文件再上传的场景。

**Transporter App 下载：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开 Mac App Store |
| 2 | 搜索 "Transporter" |
| 3 | 点击"获取"下载安装（免费） |

**导出 .ipa 文件：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 在 Organizer 中选择归档 |
| 2 | 点击 **Distribute App** |
| 3 | 选择 **App Store Connect** |
| 4 | 选择 **Export**（注意：不是 Upload） |
| 5 | 按照向导完成导出 |
| 6 | 选择保存位置，得到 .ipa 文件 |

**使用 Transporter 上传：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开 Transporter App |
| 2 | 点击 **"+"** 或直接拖入 .ipa 文件 |
| 3 | Transporter 自动验证 .ipa 文件 |
| 4 | 验证通过后点击 **交付** |
| 5 | 等待上传完成 |

**Xcode 上传 vs Transporter 上传对比：**

| 对比项 | Xcode 直接上传 | Transporter 上传 |
|--------|:--------------:|:----------------:|
| 操作步骤 | 较少，一步到位 | 需要先导出再上传 |
| 上传稳定性 | 偶尔不稳定 | 更稳定，支持断点续传 |
| 适用场景 | 日常发布 | 网络不稳定或需要保留 .ipa |
| 验证功能 | 上传时自动验证 | 上传前可先验证 |
| 是否需要 .ipa | 不需要 | 需要 |

💡 **提示**：如果 Xcode 上传经常失败或超时，建议改用 Transporter。Transporter 的上传机制更健壮，对网络波动容忍度更高。

### 构建版本处理

上传完成后，构建版本不会立即可用，需要等待 Apple 服务器处理。

**处理时间：**

| 阶段 | 时间 | 说明 |
|------|------|------|
| 上传中 | 5-30 分钟 | 取决于 App 大小和网速 |
| 处理中 | 15-30 分钟 | Apple 服务器验证和处理 |
| 可用 | 处理完成后 | 出现在 App Store Connect 中 |

⚠️ **警告**：处理时间可能长达数小时，尤其是新账号首次上传时。不要反复重新上传，耐心等待即可。

**处理状态说明：**

| 状态 | 含义 | 你需要做什么 |
|------|------|-------------|
| 正在处理 | Apple 正在验证你的构建版本 | 耐心等待 |
| 可用 | 处理成功，可以选择提交审核 | 去选择构建版本 |
| 无效 | 处理失败，构建版本不可用 | 查看失败原因，修复后重新上传 |

**处理失败常见原因及解决方法：**

| 失败原因 | 说明 | 解决方法 |
|----------|------|----------|
| 包含模拟器架构 | .ipa 中包含 x86_64/arm64-sim 代码 | 添加脚本移除模拟器架构（见上一章） |
| 缺少隐私清单 | 未提供 PrivacyInfo.xcprivacy | 添加隐私清单文件 |
| API 滥用声明缺失 | 使用了特定 API 但未声明原因 | 在隐私清单中声明 API 使用原因 |
| Info.plist 缺少必要字段 | 如缺少 ITSAppUsesNonExemptEncryption | 添加缺失字段 |
| 构建号未递增 | 与已上传的构建号相同 | 递增 Build 号后重新打包 |

💡 **提示**：Apple 从 2024 年开始要求所有 App 必须包含隐私清单（PrivacyInfo.xcprivacy），并声明"所需理由 API"的使用原因。如果处理失败提示缺少隐私清单，请参考第 37 章的内容添加。

## 填写审核信息

> 🎯 **本节目标**：学会编写审核备注、提供演示账号和上传附件，帮助审核员顺利测试你的 App。

### 审核备注编写

审核备注（App Review Notes）是给 Apple 审核员看的说明文字，用户看不到。写好审核备注能帮助审核员快速理解你的 App，减少被拒概率。

**审核备注的核心原则：**

| 原则 | 说明 |
|------|------|
| 说清楚 App 是做什么的 | 一两句话概括核心功能 |
| 提供测试指引 | 告诉审核员如何使用关键功能 |
| 解释特殊功能 | 如果有需要特别说明的功能，写清楚 |
| 提供联系方式 | 让审核员有问题时能联系到你 |

**审核备注模板：**

```
【App 简介】
这是一款[一句话描述你的 App]，主要功能包括[核心功能列表]。

【测试账号】
账号：test@example.com
密码：Test1234

【功能测试指引】
1. 打开 App 后，允许定位权限以获取天气信息
2. 在搜索栏输入城市名可查看其他城市天气
3. 点击"设置"可配置通知提醒
4. 下拉刷新可更新天气数据

【特殊功能说明】
- 定位权限：用于获取用户当前位置的天气
- 通知权限：用于推送降雨提醒
- 相机权限：用于扫描二维码分享天气

【联系方式】
如有问题请联系：developer@example.com
```

💡 **提示**：审核备注不需要写得很长，关键是把审核员可能疑惑的地方解释清楚。想象审核员是第一次使用你的 App，他们需要知道什么才能顺利测试。

### 演示账号提供

如果你的 App 需要登录才能使用，**必须**提供演示账号，否则审核员无法测试，会直接拒绝。

**何时需要提供演示账号：**

| 场景 | 是否需要 | 说明 |
|------|:--------:|------|
| App 有登录功能 | ✅ 必须 | 审核员需要登录才能测试 |
| App 有注册但可跳过 | ⚠️ 建议 | 方便审核员快速测试 |
| App 完全不需要登录 | ❌ 不需要 | 审核员可以直接使用 |
| 企业/内部 App | ✅ 必须 | 审核员无法自行注册 |

**如何创建演示账号：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 在你的 App 中注册一个专用测试账号 |
| 2 | 预先在账号中添加一些测试数据 |
| 3 | 确保账号有完整权限，能访问所有功能 |
| 4 | 在审核信息中填写账号和密码 |

**注意事项：**

| 注意事项 | 说明 |
|----------|------|
| 账号必须有效 | 审核时账号必须能正常登录 |
| 密码不要过期 | 确保密码在审核期间不会过期 |
| 数据不要删除 | 不要在审核期间删除测试数据 |
| 权限要完整 | 测试账号应能访问 App 的所有功能 |
| 不要用真实用户数据 | 测试账号中不要包含真实用户数据 |

⚠️ **警告**：审核员说"无法登录"是被拒的常见原因之一。提交审核前，请务必自己用演示账号登录测试一遍！

### 附件上传

某些情况下，你需要上传附件来辅助审核。

**何时需要附件：**

| 场景 | 需要上传的附件 |
|------|---------------|
| App 需要特殊硬件 | 硬件与 App 配对使用的视频 |
| App 需要特定环境 | 演示视频说明使用场景 |
| 金融/医疗类 App | 相关资质证明文件 |
| 涉及加密的 App | ERC 分类号或合规声明 |

**支持的格式：**

| 格式 | 说明 |
|------|------|
| 图片 | PNG、JPG、JPEG |
| 文档 | PDF |
| 视频 | MOV、MP4 |
| 压缩包 | ZIP |

💡 **提示**：如果你的 App 需要蓝牙硬件或其他外部设备才能使用，强烈建议录制一段演示视频上传，这样审核员即使没有硬件也能理解你的 App 是如何工作的。

## TestFlight 内测分发全流程

> 🎯 **本节目标**：学会使用 TestFlight 进行内测分发，在正式提交审核前收集测试反馈。

TestFlight 是 Apple 官方的 App 测试平台，让你在正式上架前邀请用户测试你的 App。

### 创建测试组

**操作路径：**

```
App Store Connect → 我的 App → 选择 App → TestFlight
```

**两种测试组对比：**

| 对比项 | 内部测试组 | 外部测试组 |
|--------|:----------:|:----------:|
| 人数上限 | 最多 100 人 | 最多 10,000 人 |
| 谁可以加入 | 团队成员（Apple ID 邮箱） | 任何人（通过邀请链接） |
| 是否需要审核 | ❌ 不需要 | ✅ 需要（Beta App 审核） |
| 测试员管理 | 自动添加团队成员 | 手动添加或通过链接邀请 |
| 构建版本可用时间 | 上传后立即可用 | 通过审核后才可用 |
| 适合场景 | 开发团队内部快速测试 | 邀请外部用户参与测试 |

**创建步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | App Store Connect → TestFlight |
| 2 | 在"内部测试"或"外部测试"区域点击 **"+"** |
| 3 | 输入测试组名称 |
| 4 | 添加测试员 |
| 5 | 选择构建版本 |

💡 **提示**：建议先创建内部测试组，让团队成员验证基本功能没问题后，再创建外部测试组邀请更多用户测试。

### 添加测试员

**内部测试员：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 在内部测试组中点击 **"+"** |
| 2 | 输入团队成员的 Apple ID 邮箱 |
| 3 | 该成员必须已在 App Store Connect 的"用户和访问"中 |
| 4 | 添加后自动收到 TestFlight 邀请邮件 |

**外部测试员：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 在外部测试组中点击 **"+"** |
| 2 | 输入测试员的邮箱地址 |
| 3 | 或开启公开链接，让任何人通过链接加入 |
| 4 | 测试员收到邀请后需安装 TestFlight App |

**公开链接设置：**

| 设置项 | 说明 |
|--------|------|
| 开启公开链接 | 生成一个邀请 URL，任何人点击即可加入测试 |
| 限制人数 | 可以设置最多邀请人数 |
| 关闭链接 | 随时可以关闭，关闭后链接失效 |

⚠️ **警告**：外部测试组的构建版本需要通过 Beta App 审核后才能分发。Beta 审核通常比正式审核快（几小时到 1 天），但仍然需要等待。

### 分发构建版本

| 步骤 | 操作 |
|:----:|------|
| 1 | 在 TestFlight 中选择已处理完成的构建版本 |
| 2 | 填写测试信息（What to Test） |
| 3 | 选择要分发的测试组 |
| 4 | 点击 **分发** |

**测试信息编写建议：**

| 要素 | 说明 | 示例 |
|------|------|------|
| 测试重点 | 本次测试需要关注什么 | "请重点测试新的搜索功能" |
| 已知问题 | 哪些问题已知但不影响测试 | "首次加载可能较慢，不影响功能" |
| 操作指引 | 如何触发新功能 | "点击首页搜索图标，输入城市名" |

**测试信息模板：**

```
【本次测试重点】
- 新增搜索功能：支持按城市名搜索天气
- 新增通知设置：可自定义提醒时间和条件

【操作指引】
1. 点击首页右上角搜索图标
2. 输入城市名（如"北京"）
3. 在设置中开启"降雨提醒"

【已知问题】
- 首次搜索可能需要 2-3 秒加载
- 部分小城市数据可能不完整
```

### 收集反馈

TestFlight 提供了多种收集测试反馈的方式：

**截图反馈：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 测试员在 App 中截图 |
| 2 | 截图后 TestFlight 自动弹出反馈选项 |
| 3 | 测试员可以添加文字描述 |
| 4 | 反馈自动发送到 App Store Connect |

**崩溃报告：**

| 类型 | 说明 |
|------|------|
| 自动收集 | App 崩溃时 TestFlight 自动收集崩溃日志 |
| 符号化 | 如果上传了符号文件（dSYM），崩溃日志会自动符号化 |
| 实时通知 | 新崩溃发生时可以在 App Store Connect 中查看 |

**管理反馈：**

```
App Store Connect → TestFlight → 崩溃 / 反馈
```

| 操作 | 说明 |
|------|------|
| 查看反馈 | 查看测试员提交的截图和文字反馈 |
| 回复反馈 | 可以回复测试员的问题 |
| 标记状态 | 将反馈标记为"已修复"、"已忽略"等 |
| 导出反馈 | 导出反馈数据进行分析 |

💡 **提示**：鼓励测试员通过 TestFlight 提交反馈，而不是通过微信、邮件等渠道。TestFlight 的反馈会自动附带设备信息、系统版本和截图，比口头描述有用得多。

## 提交审核操作

> 🎯 **本节目标**：完成提交审核前的最终检查，确认所有信息完整后正式提交审核。

### 选择构建版本

构建版本处理完成后，需要在 App Store Connect 中选择它。

**操作步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | App Store Connect → 我的 App → 选择 App |
| 2 | 进入对应版本的页面 |
| 3 | 在"构建版本"区域点击 **"选择构建版本"** |
| 4 | 从列表中选择已处理完成的构建版本 |
| 5 | 确认选择 |

⚠️ **警告**：如果看不到构建版本，说明它还在处理中或处理失败。请回到 TestFlight 标签页查看构建版本的状态。

### 确认信息

提交审核前，必须确保所有必填信息都已完整填写。这是最后一道关卡，漏填任何一项都会导致无法提交。

**提交审核检查清单：**

| 检查项 | 是否必填 | 说明 |
|--------|:--------:|------|
| 构建版本 | ✅ 必填 | 已选择处理完成的构建版本 |
| 截图 | ✅ 必填 | 至少包含 6.7 寸 iPhone 的截图 |
| App 名称 | ✅ 必填 | 最多 30 个字符 |
| 副标题 | 选填 | 最多 30 个字符 |
| 隐私政策 URL | ✅ 必填 | 必须提供有效的隐私政策链接 |
| App 类别 | ✅ 必填 | 主类别必选 |
| App 描述 | ✅ 必填 | 最多 4000 字符 |
| 关键词 | 选填 | 最多 100 字符 |
| 技术支持 URL | ✅ 必填 | 必须提供有效的技术支持链接 |
| 营销 URL | 选填 | App 的宣传页面链接 |
| 版权 | ✅ 必填 | 如 "© 2024 Your Name" |
| 年龄分级 | ✅ 必填 | 已填写分级问卷 |
| 审核备注 | 选填 | 建议填写 |
| 演示账号 | 按需 | 有登录功能时必填 |
| App 审核联系方式 | ✅ 必填 | 姓名、电话、邮箱 |
| 定价 | ✅ 必填 | 已选择定价层级 |
| 销售范围 | ✅ 必填 | 已选择销售地区 |

💡 **提示**：截图是最容易被忽略的必填项。不同设备尺寸需要不同的截图，至少需要提供 6.7 寸 iPhone 的截图。详细截图要求请参考第 36 章。

**常见遗漏项：**

| 遗漏项 | 后果 | 解决方法 |
|--------|------|----------|
| 隐私政策 URL 无效 | 无法提交 | 确保链接可正常访问 |
| 截图不完整 | 无法提交 | 补充所有必需尺寸的截图 |
| 年龄分级未填写 | 无法提交 | 完成分级问卷 |
| 演示账号无法登录 | 被拒 | 提交前用演示账号登录测试 |
| 技术支持 URL 无效 | 无法提交 | 确保链接可正常访问 |

### 提交审核

所有信息确认无误后，就可以提交审核了。

**操作步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 确认所有必填项已完整 |
| 2 | 页面右上角点击 **"提交审核"** |
| 3 | 弹出确认对话框，确认提交 |
| 4 | 状态变为"等待审核" |
| 5 | 等待 Apple 审核团队审核 |

⚠️ **警告**：提交审核后，部分信息（如截图、描述等）仍然可以修改，但构建版本不能更换。如果需要更换构建版本，必须先"拒绝"当前提交，重新选择构建版本后再提交。

## 加急审核申请

> 🎯 **本节目标**：了解加急审核的条件和申请方式，在紧急情况下加快审核进度。

### 加急审核条件

加急审核是 Apple 提供的特殊通道，可以让你的 App 优先审核。但 Apple 对加急审核的审批比较严格。

**可以申请加急审核的情况：**

| 情况 | 说明 | 示例 |
|------|------|------|
| 时间敏感的修复 | App 存在严重影响用户的 bug | 支付功能崩溃、数据丢失 |
| 重大事件 | App 与即将发生的重大事件相关 | 奥运会期间上线的赛事 App |
| 法规要求 | 因法规变更需要及时更新 | 隐私政策合规更新 |
| 安全漏洞修复 | 发现并修复了安全漏洞 | 用户数据泄露风险修复 |
| 节日/活动相关 | App 功能与特定节日/活动相关 | 春节红包功能 |

**不太可能获批的情况：**

| 情况 | 原因 |
|------|------|
| 营销活动 | 营销计划不是加急的理由 |
| 想早点上线 | 单纯想快点审核不构成理由 |
| 频繁申请 | 短时间内多次申请会被拒绝 |
| 功能更新 | 常规功能更新不属于紧急情况 |

### 申请方式

**通过 App Store Connect 申请：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 提交审核后，在 App 详情页找到审核信息 |
| 2 | 点击 **"请求加急审核"**（Request Expedited Review） |
| 3 | 选择加急原因 |
| 4 | 填写详细理由 |
| 5 | 提交申请 |

**加急审核理由模板：**

```
【加急原因】
紧急 Bug 修复

【详细说明】
我们的 App 在最新版本中发现了一个严重 bug：
用户在使用支付功能时，特定情况下会导致支付失败但
仍然扣款。这严重影响了用户的资金安全。

【影响范围】
所有使用支付功能的用户均受影响，约占总用户的 30%。

【已采取的措施】
我们已定位问题并修复，新版本已提交审核。

【期望审核时间】
希望能在 24 小时内完成审核，以尽快修复此问题，
减少用户损失。
```

### 注意事项

| 注意事项 | 说明 |
|----------|------|
| 不要滥用 | 加急审核是有限资源，滥用会导致后续申请被拒 |
| 每年限额 | Apple 没有公开限额，但频繁申请会被限制 |
| 不保证通过 | 提交加急申请不一定会被批准 |
| 理由要真实 | 虚假理由一旦被发现，可能影响后续所有审核 |
| 先提交再申请 | 必须先正常提交审核，才能申请加急 |

⚠️ **警告**：绝对不要编造加急理由！Apple 审核团队会核实你提供的信息。如果发现理由不实，不仅加急申请会被拒绝，还可能影响你后续所有 App 的审核。

## 审核状态跟踪

> 🎯 **本节目标**：了解各种审核状态的含义，知道大概需要等多久，以及每个状态下你应该做什么。

### 状态说明

提交审核后，你的 App 会经历以下状态：

| 状态 | 英文 | 含义 | 你需要做什么 |
|------|------|------|-------------|
| 等待审核 | Waiting for Review | 排队等待审核员审核 | 耐心等待 |
| 正在审核 | In Review | 审核员正在测试你的 App | 保持手机畅通，可能接到电话 |
| 等待开发者操作 | Developer Rejected | 你自己拒绝了提交 | 修改后重新提交 |
| 被拒绝 | Rejected | 审核未通过 | 查看拒绝原因，修改后重新提交 |
| 元数据被拒 | Metadata Rejected | 信息填写有问题 | 修改信息后重新提交（不需要新构建版本） |
| 准备销售 | Ready for Sale | 审核通过，即将上架 | 等待 App 上线 |
| 正在处理 | Processing | App 正在准备上架 | 耐心等待，通常几小时内上线 |

💡 **提示**：状态从"等待审核"变为"正在审核"时，说明审核员已经开始测试你的 App 了。此时你的演示账号可能会被登录使用，不要修改或删除测试数据。

**状态流转图：**

```
提交审核 → 等待审核 → 正在审核 → 审核通过 → 准备销售
                ↑          ↓
                │      被拒绝/元数据被拒
                │          ↓
                └── 修改后重新提交
```

### 等待时间参考

审核时间因各种因素而异，以下是参考时间：

| 提交类型 | 参考时间 | 说明 |
|----------|----------|------|
| 首次提交 | 1-3 天 | 新 App 首次提交，审核更仔细 |
| 常规更新 | 1-2 天 | 已上架 App 的版本更新 |
| 被拒后重新提交 | 1-2 天 | 修复问题后重新提交 |
| 加急审核 | 几小时 | 申请通过后优先审核 |
| 节假日期间 | 可能更长 | 圣诞节等假期审核较慢 |

**影响审核时间的因素：**

| 因素 | 影响 |
|------|------|
| App 类型 | 涉及支付、社交、医疗等敏感领域的审核更久 |
| 首次提交 | 新 App 首次提交比更新审核更仔细 |
| 审核队列 | 提交量大时排队更久 |
| 节假日 | Apple 审核团队在节假日期间人手较少 |
| 信息完整性 | 信息不完整可能需要来回沟通，延长审核时间 |

**如何查看审核进度：**

| 方式 | 操作 |
|------|------|
| App Store Connect | 我的 App → 选择 App → 查看状态 |
| 邮件通知 | 状态变更时 Apple 会发邮件通知 |
| 手机通知 | 安装 App Store Connect App 可接收推送 |

💡 **提示**：审核期间请保持手机和邮箱畅通。Apple 审核团队有时会电话联系开发者确认信息或要求补充说明。如果联系不上你，审核可能会被暂停。

## 小结

本章涵盖了从上传构建版本到跟踪审核状态的完整提审流程，核心要点总结如下：

| 知识点 | 核心要点 |
|--------|----------|
| 上传构建版本 | Xcode 直接上传或 Transporter 上传，上传后等待 15-30 分钟处理 |
| 审核信息 | 审核备注写清楚、演示账号必须有效、附件按需上传 |
| TestFlight | 内部测试无需审核、外部测试需 Beta 审核，先内测再外测 |
| 提交审核 | 确认所有必填项完整、选择构建版本、点击提交 |
| 加急审核 | 紧急 bug 修复可申请，不要滥用，不保证通过 |
| 审核状态 | 等待审核→正在审核→审核通过/被拒，首次 1-3 天 |

**提交审核清单：**

```
✅ 构建版本已上传并处理完成
✅ 在 App Store Connect 中选择了构建版本
✅ 截图已上传（所有必需尺寸）
✅ App 名称、描述、关键词已填写
✅ 隐私政策 URL 有效可访问
✅ 技术支持 URL 有效可访问
✅ 年龄分级已填写
✅ 类别已选择
✅ 定价和销售范围已设置
✅ 审核备注已编写（建议填写）
✅ 演示账号已提供（有登录功能时必须）
✅ 审核联系方式已填写
✅ 所有信息确认无误后点击"提交审核"
```
