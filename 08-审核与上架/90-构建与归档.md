## Archive 打包全流程

> 🎯 **本节目标**：从零开始完成一次完整的 Archive 打包操作，把你的 App 从 Xcode 项目变成可以上传到 App Store 的归档文件。

### 准备工作

在点击 Archive 之前，有几件关键的事情必须确认，否则打包大概率会失败。

**1. 确认版本号和构建号**

版本号（Version）和构建号（Build）是 App 的"身份证号"，每次提交审核都必须递增。

| 字段 | 位置 | 说明 | 示例 |
|------|------|------|------|
| Version（版本号） | General → Identity | 用户可见的版本号，格式为 `主.次.修` | `1.0.0` |
| Build（构建号） | General → Identity | 每次打包递增的数字，同一版本号内必须唯一 | `1`、`2`、`3` |

```
Xcode 中的路径：
项目文件 → Target → General → Identity → Version / Build
```

💡 **提示**：版本号规则——当你只是修复 bug，修改第三位（`1.0.0` → `1.0.1`）；新增功能，修改第二位（`1.0.1` → `1.1.0`）；大改版，修改第一位（`1.1.0` → `2.0.0`）。构建号每次打包都必须比上一次大，最简单的做法是每次 +1。

**2. 选择正确的运行目标**

这一步很多人会忽略，但非常关键：

| 选择 | 说明 | 是否能 Archive |
|------|------|:--------------:|
| iPhone 模拟器 | 在电脑上模拟运行 | ❌ 不能 |
| Any iOS Device (arm64) | 真机设备，通用目标 | ✅ 可以 |
| 你的 iPhone | 连接的特定真机 | ✅ 可以 |

⚠️ **警告**：如果顶部设备选择的是模拟器（如 "iPhone 15 Pro"），Product → Archive 菜单会是灰色不可点击状态！必须切换到 **Any iOS Device (arm64)** 或连接的真机。

**3. 检查证书和描述文件**

确保你拥有有效的签名凭证：

```
Xcode 中的路径：
项目文件 → Target → Signing & Capabilities
```

| 检查项 | 正确状态 | 异常状态 |
|--------|----------|----------|
| Team | 已选择你的开发者账号 | 显示 "None" 或报错 |
| Bundle Identifier | 与 App Store Connect 中一致 | 不一致 |
| Signing Certificate | 显示有效证书 | 显示 "None" 或过期 |
| Provisioning Profile | 显示有效描述文件 | 显示 "None" 或过期 |

**4. 清理项目**

打包前清理一下旧的编译缓存，可以避免很多莫名其妙的错误：

```
菜单栏：Product → Clean Build Folder
快捷键：Shift + Command + K
```

💡 **提示**：如果之前改过 Bundle ID 或签名配置，强烈建议先 Clean 再 Archive，否则可能会用到旧的缓存导致签名异常。

### Archive 操作步骤

准备工作完成后，就可以开始打包了。

**详细步骤：**

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | 确认设备选择为 **Any iOS Device (arm64)** | 顶部工具栏的设备选择器 |
| 2 | 点击菜单 **Product → Archive** | 快捷键没有默认设置 |
| 3 | 等待编译完成 | 可能需要 1-10 分钟，取决于项目大小 |
| 4 | **Organizer 窗口**自动弹出 | 显示归档列表和操作选项 |
| 5 | 选择刚才的归档，点击 **Distribute App** | 进入分发流程 |

**Organizer 窗口说明：**

```
┌──────────────────────────────────────────────────────┐
│  Organizer                                           │
│  ┌──────────┐  ┌──────────────────────────────────┐  │
│  │ 归档列表  │  │  归档详情                         │  │
│  │          │  │  App 名称：天气小助手              │  │
│  │ 1.0.0    │  │  版本号：1.0.0 (Build 1)          │  │
│  │ 1.0.1    │  │  归档日期：2024-01-15 10:30       │  │
│  │          │  │                                   │  │
│  │          │  │  [Distribute App]  [Validate]     │  │
│  │          │  │  [Export]         [Delete]        │  │
│  └──────────┘  └──────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

**分发方式选择：**

| 分发方式 | 用途 | 说明 |
|----------|------|------|
| App Store Connect | 上架发布 | 通过 App Store Connect 分发到 App Store |
| Ad Hoc | 有限范围测试 | 生成 .ipa 给已注册的测试设备安装 |
| Enterprise | 企业内部分发 | 需要企业开发者账号（$299/年） |
| Development | 开发测试 | 用于开发阶段的真机调试 |
| Copy App | 仅导出 .app | 不做签名处理，直接复制 .app 文件 |

💡 **提示**：上架发布选择 **App Store Connect** → 然后选择 **Upload** 即可将构建版本上传到 App Store Connect。

### 常见打包问题

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| Archive 按钮灰色 | 选择了模拟器设备 | 切换到 Any iOS Device (arm64) |
| 编译报错 "No signing certificate" | 没有有效的签名证书 | 参考本章"证书与描述文件管理"一节 |
| 编译报错 "Unsupported architecture" | 架构不匹配 | 确认 Build Settings → Architectures 设置 |
| 第三方库链接错误 | CocoaPods/SPM 未正确集成 | 执行 `pod install` 或重新解析 SPM |
| "Bitcode" 报错 | 某些库不支持 Bitcode | Build Settings → Enable Bitcode 设为 No |
| 打包成功但上传失败 | 架构包含模拟器代码 | 确认 Release 配置排除模拟器架构 |

⚠️ **警告**：Xcode 14 之后，Apple 不再要求 Bitcode，新项目默认关闭。如果你的项目是老项目，建议在 Build Settings 中将 Enable Bitcode 设为 No。

## 证书与描述文件管理

> 🎯 **本节目标**：理解证书和描述文件的作用和类型，学会创建、下载和管理它们。

### 开发证书

**iOS Development 证书**用于真机调试，让你开发的 App 能安装到 iPhone 上运行。

| 属性 | 说明 |
|------|------|
| 证书类型 | iOS Development |
| 用途 | 真机调试、开发阶段测试 |
| 有效期 | 1 年 |
| 数量限制 | 每个开发者账号最多 2 个开发证书 |
| 关联 | 与开发描述文件配合使用 |

**创建步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开 Xcode → Preferences（Settings）→ Accounts |
| 2 | 点击你的 Apple ID → 点击 "Manage Certificates…" |
| 3 | 点击左下角 "+" → 选择 "Apple Development" |
| 4 | 证书自动创建并下载到钥匙串 |

💡 **提示**：如果你使用自动签名（推荐），Xcode 会帮你自动创建和管理开发证书，不需要手动操作。

### 发布证书

**iOS Distribution 证书**用于上架发布，只有用这个证书签名的 App 才能上传到 App Store。

| 属性 | 说明 |
|------|------|
| 证书类型 | Apple Distribution |
| 用途 | App Store 上架发布 |
| 有效期 | 1 年 |
| 数量限制 | 每个开发者账号最多 3 个发布证书 |
| 关联 | 与 App Store 描述文件配合使用 |

**创建步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 登录 [Apple Developer](https://developer.apple.com) |
| 2 | 进入 Certificates, Identifiers & Profiles |
| 3 | 点击 Certificates → 点击 "+" 按钮 |
| 4 | 选择 "Apple Distribution" → Continue |
| 5 | 上传 Certificate Signing Request（CSR）文件 |
| 6 | 下载并双击安装证书 |

**CSR 文件生成方法：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开"钥匙串访问"（Keychain Access） |
| 2 | 菜单栏：钥匙串访问 → 证书助理 → 从证书颁发机构请求证书… |
| 3 | 填写邮箱和名称，选择"存储到磁盘" |
| 4 | 保存 .certSigningRequest 文件 |

⚠️ **警告**：发布证书的私钥只存在于创建它的 Mac 上。如果你换了电脑或重装了系统，没有备份私钥的话，旧证书就无法使用了，只能吊销后重新创建。吊销证书会使使用该证书的所有描述文件失效！

### 描述文件类型

描述文件（Provisioning Profile）是连接证书、设备和 App ID 的"桥梁"，告诉 Apple"这个 App 可以装到哪些设备上"。

**三种描述文件对比：**

| 对比项 | Development | App Store | Ad Hoc |
|--------|:-----------:|:---------:|:------:|
| 用途 | 真机调试 | App Store 上架 | 有限范围测试 |
| 关联证书 | 开发证书 | 发布证书 | 发布证书 |
| 设备限制 | 需注册设备 UDID | 无限制 | 需注册设备 UDID |
| 最大设备数 | 100 台/年 | 无限制 | 100 台/年 |
| 安装方式 | Xcode 直接安装 | 通过 App Store | 通过链接/文件安装 |
| 需要 Apple 审核 | 否 | 是 | 否 |
| 适合场景 | 日常开发调试 | 正式发布上架 | 内测分发 |

💡 **提示**：对于新手来说，日常开发用 Development 描述文件，上架发布用 App Store 描述文件，这两种是最常用的。Ad Hoc 主要用于不通过 TestFlight 的内测分发。

### 证书创建与下载

**方法一：通过 Apple Developer 网站操作**

| 步骤 | 操作 |
|:----:|------|
| 1 | 登录 [developer.apple.com](https://developer.apple.com) |
| 2 | 进入 Certificates, Identifiers & Profiles |
| 3 | 在左侧菜单选择 Certificates / Identifiers / Profiles |
| 4 | 点击 "+" 创建新的证书/标识符/描述文件 |
| 5 | 按照向导填写信息 |
| 6 | 下载生成的文件，双击安装到钥匙串 |

**方法二：通过 Xcode 管理**

| 步骤 | 操作 |
|:----:|------|
| 1 | Xcode → Settings（Preferences）→ Accounts |
| 2 | 选择你的 Apple ID → 点击 Team 旁边的 "Manage Certificates…" |
| 3 | 可以查看、创建开发证书 |
| 4 | 描述文件在 Target → Signing & Capabilities 中管理 |

⚠️ **警告**：Xcode 中只能管理开发证书，发布证书必须通过 Apple Developer 网站创建。

**描述文件创建步骤（Apple Developer 网站）：**

| 步骤 | 操作 |
|:----:|------|
| 1 | Certificates, Identifiers & Profiles → Profiles → "+" |
| 2 | 选择类型（iOS App Development / App Store / Ad Hoc） |
| 3 | 选择 App ID（即你的 Bundle ID） |
| 4 | 选择对应的证书 |
| 5 | 选择设备（Development 和 Ad Hoc 需要选择） |
| 6 | 命名并生成 |
| 7 | 下载 .mobileprovision 文件，双击安装 |

## 自动签名 vs 手动签名

> 🎯 **本节目标**：理解自动签名和手动签名的区别，知道什么时候用哪种方式，并能正确配置。

### 自动签名配置

自动签名是 Xcode 提供的便利功能，它会帮你自动管理证书和描述文件的创建、更新和下载。

**配置步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开项目，选择 Target |
| 2 | 点击 Signing & Capabilities 标签 |
| 3 | ✅ 勾选 **"Automatically manage signing"** |
| 4 | 在 Team 下拉菜单选择你的开发者账号 |
| 5 | 确认 Bundle Identifier 正确 |
| 6 | Xcode 自动生成并匹配证书和描述文件 |

```
Xcode 中的路径：
项目文件 → Target → Signing & Capabilities → ☑️ Automatically manage signing
```

**自动签名优缺点：**

| 优点 | 缺点 |
|------|------|
| 配置简单，几乎零操作 | 只能管理开发证书，不能管理发布证书 |
| 自动处理证书更新和续期 | 不适合多人协作场景 |
| 自动下载和安装描述文件 | CI/CD 环境中不太适用 |
| 新手友好，减少出错 | 对签名过程缺乏控制 |

💡 **提示**：对于个人开发者和小团队，强烈推荐使用自动签名。它能帮你省去 90% 的签名配置工作。

### 手动签名配置

手动签名意味着你需要自己管理证书和描述文件的创建、下载、安装和更新。

**配置步骤：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开项目，选择 Target |
| 2 | 点击 Signing & Capabilities 标签 |
| 3 | ❌ 取消勾选 **"Automatically manage signing"** |
| 4 | 在 Provisioning Profile 下拉菜单选择已安装的描述文件 |
| 5 | 在 Signing Certificate 下拉菜单选择对应的证书 |
| 6 | 确认没有报错提示 |

**手动签名优缺点：**

| 优点 | 缺点 |
|------|------|
| 完全控制签名过程 | 配置复杂，容易出错 |
| 适合多人协作 | 证书更新需要手动操作 |
| 适合 CI/CD 环境 | 新手容易配错 |
| 可以使用发布证书 | 描述文件过期需要手动更新 |

### 何时需要手动签名

以下场景建议使用手动签名：

| 场景 | 原因 | 说明 |
|------|------|------|
| 多人协作 | 自动签名会互相覆盖 | 每个开发者的 Xcode 可能生成不同的证书，导致冲突 |
| CI/CD | 服务器上没有你的 Apple ID | CI 机器无法使用自动签名，需要手动指定证书和描述文件 |
| 企业分发 | 需要企业证书 | 企业分发需要使用 Enterprise 证书，必须手动配置 |
| 发布证书签名 | 自动签名不支持发布证书 | Archive 打包上架时，如果不用自动签名，需要手动配置 |
| 多 Bundle ID | 同一项目多个 App ID | 如免费版和付费版使用不同 Bundle ID |

⚠️ **警告**：在 CI/CD 环境中使用手动签名时，务必妥善保管证书的 .p12 文件和描述文件。这些文件如果泄露，别人可以用你的身份发布 App！建议将签名文件存储在安全的密钥管理系统中，不要直接放在代码仓库里。

## 常见打包错误排查

> 🎯 **本节目标**：学会识别和解决最常见的打包错误，不再被签名问题困扰。

### 签名错误

**错误 1："No signing certificate found"**

```
错误信息：
No signing certificate "iOS Development" found: No "iOS Development" signing certificate matching team ID "XXXXXXXXXX" with a private key was found.
```

| 原因 | 解决方法 |
|------|----------|
| 没有安装开发证书 | Xcode → Settings → Accounts → Manage Certificates → 创建证书 |
| 证书私钥丢失 | 在创建证书的 Mac 上导出 .p12 文件，拷贝到当前 Mac 安装 |
| 选择了错误的 Team | Signing & Capabilities 中切换到正确的 Team |
| 证书已过期 | 重新创建证书 |

**错误 2："Failed to create provisioning profile"**

| 原因 | 解决方法 |
|------|----------|
| Bundle ID 未注册 | 去 Apple Developer 网站注册 App ID |
| Bundle ID 与已有 App 冲突 | 修改 Bundle ID 为唯一值 |
| 设备 UDID 未注册 | 在 Apple Developer 网站添加设备 |

### 证书过期

证书有效期为 **1 年**，过期后必须重新创建。

**如何检查证书过期：**

| 方法 | 操作 |
|------|------|
| 钥匙串访问 | 打开"钥匙串访问"→"我的证书"→ 查看过期日期 |
| Apple Developer 网站 | Certificates, Identifiers & Profiles → Certificates → 查看过期日期 |
| Xcode 提示 | 过期证书会在 Signing & Capabilities 中显示警告 |

**续期方法：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 在 Apple Developer 网站创建新证书 |
| 2 | 下载并安装新证书 |
| 3 | 更新所有使用旧证书的描述文件 |
| 4 | 在 Xcode 中重新选择新证书 |
| 5 | 吊销旧证书（可选，建议保留到自然过期） |

⚠️ **警告**：不要轻易吊销（Revoke）还有效的证书！吊销发布证书会导致所有使用该证书的描述文件立即失效，影响团队其他成员和正在上架的 App。如果证书快过期但还有效，建议先创建新证书，等旧证书自然过期。

### 描述文件不匹配

**常见原因及解决方法：**

| 错误信息 | 原因 | 解决方法 |
|----------|------|----------|
| "Provisioning profile doesn't include the current device" | 设备 UDID 未添加到描述文件 | 在 Apple Developer 网站添加设备，重新生成描述文件 |
| "Provisioning profile doesn't match the bundle identifier" | 描述文件的 App ID 与项目不一致 | 检查 Bundle ID 是否正确，或重新生成描述文件 |
| "Provisioning profile has expired" | 描述文件已过期 | 重新生成描述文件 |
| "Provisioning profile doesn't include signing certificate" | 描述文件未关联当前证书 | 重新生成描述文件，选择正确的证书 |

💡 **提示**：遇到描述文件问题时，最快的解决方法是直接删除旧的描述文件，让 Xcode 自动重新生成（自动签名模式下）。手动签名模式下则需要去 Apple Developer 网站重新创建。

**删除旧描述文件的方法：**

```
Xcode → Settings → Accounts → 选择 Apple ID → 点击 Team → Download Manual Profiles
或者：直接去 ~/Library/MobileDevice/Provisioning Profiles/ 删除对应文件
```

### 架构不匹配

**错误："Unsupported architecture" 或 "Unsupported architectures"**

| 原因 | 解决方法 |
|------|----------|
| 项目包含了模拟器架构（x86_64/arm64-sim） | 在 Build Settings 中添加排除项 |
| 第三方库包含了模拟器代码 | 配置 Build Phase 脚本移除模拟器架构 |
| Architectures 设置不正确 | 确认设置为 `$(ARCHS_STANDARD)` |

**解决方法——在 Build Phase 中添加脚本移除模拟器架构：**

```bash
# 在 Target → Build Phases → 添加 New Run Script Phase
# 粘贴以下脚本：

APP_PATH="${TARGET_BUILD_DIR}/${INFOPLIST_PATH%/*}"

# This script loops through the frameworks embedded in the application and
# removes unused architectures.
find "$APP_PATH" -type f -name "*.framework" -o -name "*.dylib" | while read -r FRAMEWORK; do
    FRAMEWORK_EXECUTABLE_NAME=$(defaults read "$FRAMEWORK/Info.plist" CFBundleExecutable)
    FRAMEWORK_EXECUTABLE_PATH="$FRAMEWORK/$FRAMEWORK_EXECUTABLE_NAME"
    echo "Executable is $FRAMEWORK_EXECUTABLE_PATH"

    EXTRACTED_ARCHS=()
    for ARCH in $ARCHS; do
        echo "Extracting $ARCH from $FRAMEWORK_EXECUTABLE_NAME"
        lipo -extract "$ARCH" "$FRAMEWORK_EXECUTABLE_PATH" -o "$FRAMEWORK_EXECUTABLE_PATH-$ARCH"
        EXTRACTED_ARCHS+=("$FRAMEWORK_EXECUTABLE_PATH-$ARCH")
    done

    echo "Merging extracted architectures: ${EXTRACTED_ARCHS[*]}"
    lipo -o "$FRAMEWORK_EXECUTABLE_PATH-merged" -create "${EXTRACTED_ARCHS[@]}"
    rm "${EXTRACTED_ARCHS[@]}"

    echo "Replacing original executable with thinned version"
    rm "$FRAMEWORK_EXECUTABLE_PATH"
    mv "$FRAMEWORK_EXECUTABLE_PATH-merged" "$FRAMEWORK_EXECUTABLE_PATH"
done
```

⚠️ **警告**：从 Xcode 14 开始，Apple 要求上传的 App 不再包含模拟器架构。如果你的项目使用了 CocoaPods 或手动集成的第三方库，很可能包含模拟器架构，需要用上面的脚本移除。

## Xcode Cloud CI/CD 入门

> 🎯 **本节目标**：了解 Xcode Cloud 的基本概念，学会配置自动化构建和测试流程。

CI/CD 是 **持续集成/持续交付**（Continuous Integration / Continuous Delivery）的缩写。简单来说，就是让电脑自动帮你完成"编译→测试→打包"这些重复性工作。

### Xcode Cloud 配置

Xcode Cloud 是 Apple 官方提供的 CI/CD 服务，深度集成在 Xcode 和 App Store Connect 中。

**前提条件：**

| 条件 | 说明 |
|------|------|
| Apple Developer Program 会员 | 需要付费的开发者账号 |
| 项目使用 Git | 项目必须在 Git 仓库中（GitHub、GitLab、Bitbucket 等） |
| Xcode 13+ | 需要 Xcode 13 或更高版本 |
| App Store Connect 中有 App 记录 | 需要先在 App Store Connect 创建 App |

**创建 Workflow：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 打开 Xcode → 菜单栏 Product → Xcode Cloud → Create Workflow |
| 2 | 或在 App Store Connect 中 → Xcode Cloud 标签页 → Start |
| 3 | 选择你的仓库和项目 |
| 4 | 配置 Workflow 的触发条件和操作 |

**配置触发条件：**

| 触发条件 | 说明 | 适合场景 |
|----------|------|----------|
| 每次推送到 main 分支 | 代码合入主分支时自动构建 | 保证主分支始终可编译 |
| Pull Request | 创建或更新 PR 时自动构建 | 代码审查前验证 |
| 定时触发 | 每天定时构建 | 夜间构建 |
| 手动触发 | 手动点击开始构建 | 随时按需构建 |

**配置操作（Actions）：**

| 操作 | 说明 | 用途 |
|------|------|------|
| Build | 编译项目 | 确保代码能编译通过 |
| Test | 运行测试 | 自动验证功能正确性 |
| Analyze | 静态分析 | 检测代码质量问题 |
| Archive | 打包归档 | 生成可分发的构建版本 |

💡 **提示**：Xcode Cloud 对小型团队有免费额度——每月 25 小时计算时间，对于个人开发者和小项目完全够用。

### 自动化构建

**每次提交自动构建：**

配置 Workflow 在每次推送到主分支时自动构建：

| 配置项 | 推荐设置 |
|--------|----------|
| 触发条件 | Branch: main, 事件: Push |
| 操作 | Build + Test |
| 环境 | Latest Xcode, macOS |
| 超时 | 默认 60 分钟 |

**PR 自动构建：**

配置 Workflow 在创建或更新 Pull Request 时自动构建：

| 配置项 | 推荐设置 |
|--------|----------|
| 触发条件 | 事件: Pull Request |
| 操作 | Build + Test |
| 环境 | Latest Xcode, macOS |

**构建结果通知：**

| 通知方式 | 说明 |
|----------|------|
| Xcode 内通知 | 构建完成后在 Xcode 中弹出通知 |
| 邮件通知 | 构建失败时发送邮件 |
| App Store Connect | 在 Xcode Cloud 标签页查看 |
| Git 集成 | 在 PR 页面显示构建状态 |

### 自动化测试

**配置测试：**

| 步骤 | 操作 |
|:----:|------|
| 1 | 在 Workflow 编辑器中添加 Test 操作 |
| 2 | 选择要运行的 Test Target |
| 3 | 选择测试设备（模拟器） |
| 4 | 配置测试条件 |

**测试设备选择：**

| 设备类型 | 说明 | 推荐 |
|----------|------|------|
| iPhone 模拟器 | 在模拟器上运行测试 | iPhone 15 Pro (iOS 17) |
| iPad 模拟器 | 在 iPad 模拟器上运行测试 | 如需支持 iPad |
| 多设备并行 | 同时在多个设备上测试 | 覆盖不同屏幕尺寸 |

**测试报告：**

Xcode Cloud 会自动生成测试报告，包含：

| 报告内容 | 说明 |
|----------|------|
| 测试通过率 | 通过/失败/跳过的测试数量 |
| 失败详情 | 具体哪个测试失败、失败原因 |
| 测试耗时 | 每个测试用例的执行时间 |
| 截图 | UI 测试的截图（如果有） |
| 崩溃日志 | 测试过程中的崩溃信息 |

💡 **提示**：如果你还没有写单元测试，可以先不配置测试操作，只配置 Build。等后续写了测试用例再添加。关于如何编写测试，可以参考 Apple 官方文档 [Testing in Xcode](https://developer.apple.com/documentation/xcode/testing)。

## 小结

本章涵盖了从打包到 CI/CD 的完整流程，核心要点总结如下：

| 知识点 | 核心要点 |
|--------|----------|
| Archive 打包 | 先确认版本号、选择真机设备、检查签名，再 Product → Archive |
| 证书管理 | 开发证书用于调试，发布证书用于上架，有效期 1 年 |
| 描述文件 | Development 用于调试，App Store 用于上架，Ad Hoc 用于内测 |
| 自动签名 | 新手推荐，Xcode 自动管理，简单省心 |
| 手动签名 | 多人协作/CI/CD 必须用，完全控制但配置复杂 |
| 打包错误 | 签名错误最常见，检查证书和描述文件是第一反应 |
| Xcode Cloud | Apple 官方 CI/CD，免费额度够小团队用，自动化构建和测试 |

**Archive 打包清单：**

```
✅ 确认版本号（Version）和构建号（Build）已更新
✅ 选择 Any iOS Device (arm64) 作为运行目标
✅ 检查证书和描述文件有效
✅ Clean Build Folder（Shift + Command + K）
✅ Product → Archive
✅ 在 Organizer 中选择分发方式
✅ 上传到 App Store Connect
```
