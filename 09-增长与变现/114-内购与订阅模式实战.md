# 114-内购与订阅模式实战

## 本章目标

- 理解 iOS 变现的五大模式及其适用场景
- 掌握付费 App 的定价策略
- 能够使用 StoreKit 2 实现消耗型和非消耗型内购
- 深入理解订阅模式的设计与定价心理学
- 避开内购/订阅审核的常见坑

---

## 一、变现模式全景

想象你开了一家店——你可以收门票（付费下载），可以在店里卖东西（内购），可以挂广告牌（广告变现），也可以组合着来（混合模式）。iOS 变现也是同样的道理。

### 1.1 五大变现模式

| 模式 | 通俗理解 | 典型案例 | 收入特点 |
|------|----------|----------|----------|
| 下载收费 | 收门票才能进 | Minecraft、Procreate | 一次性收入，无后续 |
| 消耗型内购 | 买游戏币、买道具 | 游戏钻石、直播礼物 | 可重复购买，天花板高 |
| 非消耗型内购 | 一次性买断功能 | 去广告、解锁高级功能 | 一次性收入，用户决策成本低 |
| 自动续期订阅 | 包月/包年会员 | Netflix、iCloud+ | 持续性收入，LTV 最高 |
| 广告变现 | 免费看内容，插播广告 | 免费游戏、资讯 App | 按展示/点击计费，收入不稳定 |

### 1.2 混合模式

大多数成功的 App 并不只靠一种方式，而是组合使用：

| 组合方式 | 示例 |
|----------|------|
| 免费 + 内购 + 广告 | 免费游戏：看广告去广告，内购买道具 |
| 免费 + 订阅 + 非消耗型 | 笔记 App：基础免费，订阅解锁云同步，一次性买断本地高级功能 |
| 付费 + 内购 | 付费绘图 App：基础功能付费，额外笔刷内购 |
| 免费 + 订阅 + 广告 | 音乐 App：免费听（有广告），订阅去广告+离线 |

> 💡 **黄金法则**：不要为了变现而变现。先让用户爱上你的 App，再考虑怎么赚钱。用户体验差的变现方式，最终会赶走用户。

## 二、下载收费实战

### 2.1 App Store 定价层级

App Store 使用"定价层级"（Price Tier）系统，每个层级对应不同国家/地区的本地化价格。以下是最常用的几个层级：

| 层级 | 美元价格 | 人民币价格（约） | 常见用途 |
|------|----------|------------------|----------|
| Tier 1 | $0.99 | ¥6 | 小工具、入门级 App |
| Tier 2 | $1.99 | ¥12 | 中等复杂度工具 |
| Tier 3 | $2.99 | ¥18 | 专业小工具 |
| Tier 5 | $4.99 | ¥28 | 高质量独立 App |
| Tier 10 | $9.99 | ¥68 | 专业级 App |
| Tier 20 | $19.99 | ¥128 | 专业生产力工具 |
| Tier 50 | $49.99 | ¥328 | 专业创意软件 |
| Tier 100 | $99.99 | ¥648 | 企业级/专业级软件 |

> 💡 Apple 会不定期调整价格层级表，具体价格以 App Store Connect 后台为准。

### 2.2 如何选择定价层级

| 考虑因素 | 建议 |
|----------|------|
| App 复杂度 | 越复杂，定价越高 |
| 竞品价格 | 参考同类 App 的定价区间 |
| 目标用户付费意愿 | 专业用户 > 普通消费者 |
| 更新频率 | 频繁更新的 App 考虑订阅而非一次性付费 |
| 品牌溢价 | 知名开发者可以定更高价 |

### 2.3 付费 App 的优劣势

| 优势 | 劣势 |
|------|------|
| 用户质量高，付费即认可 | 下载量远低于免费 App |
| 无需设计内购/订阅系统 | 难以获得持续收入 |
| 审核相对简单 | 用户期望值高，差评风险大 |
| 无广告体验更纯粹 | 难以通过免费体验转化用户 |

### 2.4 什么时候适合付费下载

- ✅ App 功能完整，无需后续付费解锁
- ✅ 目标用户是专业人群（设计师、开发者等）
- ✅ 已有品牌知名度（如 Procreate）
- ✅ 不需要大量用户基数
- ❌ 面向大众消费者
- ❌ 需要持续更新内容
- ❌ 依赖网络效应（社交类）

> ⚠️ **现实提醒**：2024 年付费 App 仅占 App Store 总下载量的不到 5%。对于大多数独立开发者，免费 + 内购/订阅是更现实的选择。

## 三、内购（IAP）实战

### 3.1 消耗型内购

就像在游乐场买游戏币——用完了可以再买，买了不退。

**适用场景**：
- 虚拟货币（金币、钻石）
- 游戏道具（装备、皮肤）
- 直播礼物
- 增值服务次数（如 AI 生成次数）

**关键特点**：
- 可以重复购买
- 用完即消耗，不自动恢复
- 需要自己实现服务端验证，防止作弊

### 3.2 非消耗型内购

就像买了一件衣服——买一次就永远拥有。

**适用场景**：
- 解锁高级功能
- 去广告
- 永久买断
- 额外内容包（主题、字体）

**关键特点**：
- 只需购买一次
- 必须提供恢复购买功能
- 跨设备可用（同一 Apple ID）

### 3.3 App Store Connect 配置步骤

#### 第一步：签署协议

1. 登录 [App Store Connect](https://appstoreconnect.apple.com)
2. 进入"商务"→"协议、税务和银行业务"
3. 签署"付费 App 协议"
4. 填写银行账户和税务信息

> ⚠️ 没有签署付费协议，内购产品无法上线！

#### 第二步：创建内购产品

1. 进入 App Store Connect → 你的 App → "App 内购买项目"
2. 点击"+"创建新产品
3. 选择产品类型：

| 字段 | 消耗型示例 | 非消耗型示例 |
|------|-----------|-------------|
| 类型 | 消耗型 | 非消耗型 |
| 引用名称 | 100 金币 | 去广告 |
| 产品 ID | com.example.app.coins100 | com.example.app.removeads |
| 价格 | Tier 1（¥6） | Tier 3（¥18） |
| 显示名称 | 100 金币 | 永久去广告 |
| 描述 | 购买 100 金币 | 一次性购买，永久去除所有广告 |

4. 上传审核截图（内购产品的截图）
5. 提交审核

> 💡 **产品 ID 命名规范**：使用反向域名格式，如 `com.yourcompany.app.productname`，一旦创建不可修改。

#### 第三步：Xcode 配置

在 Xcode 中：
1. 打开项目 → Signing & Capabilities
2. 点击"+ Capability" → 添加"In-App Purchase"
3. 确认 Bundle ID 与 App Store Connect 一致

### 3.4 StoreKit 2 代码实现

StoreKit 2 是 Apple 在 iOS 15 推出的现代内购框架，基于 Swift 并发（async/await），比旧版 StoreKit 简洁得多。

#### 3.4.1 查询产品信息

```swift
import StoreKit

class StoreManager: ObservableObject {
    @Published var products: [Product] = []

    func loadProducts() async {
        do {
            let storeProducts = try await Product.products(for: [
                "com.example.app.coins100",
                "com.example.app.removeads"
            ])
            products = storeProducts
        } catch {
            print("加载产品失败: \(error)")
        }
    }
}
```

#### 3.4.2 购买

```swift
func purchase(_ product: Product) async -> Bool {
    do {
        let result = try await product.purchase()

        switch result {
        case .success(let verification):
            let transaction = try checkVerified(verification)
            await transaction.finish()
            return true

        case .userCancelled:
            return false

        case .pending:
            return false

        @unknown default:
            return false
        }
    } catch {
        print("购买失败: \(error)")
        return false
    }
}

func checkVerified<T>(_ result: VerificationResult<T>) throws -> T {
    switch result {
    case .unverified:
        throw StoreError.failedVerification
    case .verified(let safe):
        return safe
    }
}

enum StoreError: Error {
    case failedVerification
}
```

> 💡 `checkVerified` 是安全验证的关键步骤。StoreKit 2 会在本地自动验证 JWS 签名，但你仍需检查验证结果。对于消耗型内购，建议同时做服务端验证。

#### 3.4.3 恢复购买

```swift
func restorePurchases() async {
    do {
        try await AppStore.sync()
    } catch {
        print("恢复购买失败: \(error)")
    }
}
```

> ⚠️ **非消耗型内购必须提供恢复购买按钮**，否则会被 App Store 审核拒绝！

#### 3.4.4 监听交易更新

```swift
class StoreManager: ObservableObject {
    @Published var purchasedProductIDs: Set<String> = []
    private var transactionListener: Task<Void, Never>?

    init() {
        transactionListener = listenForTransactions()
    }

    deinit {
        transactionListener?.cancel()
    }

    func listenForTransactions() -> Task<Void, Never> {
        Task.detached {
            for await result in Transaction.updates {
                do {
                    let transaction = try self.checkVerified(result)
                    self.purchasedProductIDs.insert(transaction.productID)
                    await transaction.finish()
                } catch {
                    print("交易验证失败")
                }
            }
        }
    }

    func updatePurchasedProducts() async {
        for await result in Transaction.currentEntitlements {
            do {
                let transaction = try checkVerified(result)
                purchasedProductIDs.insert(transaction.productID)
            } catch {
                print("验证失败")
            }
        }
    }
}
```

### 3.5 完整 SwiftUI 示例

```swift
import SwiftUI
import StoreKit

struct StoreView: View {
    @StateObject private var store = StoreManager()

    var body: some View {
        List {
            Section("内购商品") {
                ForEach(store.products, id: \.id) { product in
                    HStack {
                        VStack(alignment: .leading, spacing: 4) {
                            Text(product.displayName)
                                .font(.headline)
                            Text(product.description)
                                .font(.caption)
                                .foregroundColor(.secondary)
                        }

                        Spacer()

                        if store.purchasedProductIDs.contains(product.id) {
                            Image(systemName: "checkmark.circle.fill")
                                .foregroundColor(.green)
                        } else {
                            Button {
                                Task {
                                    _ = await store.purchase(product)
                                }
                            } label: {
                                Text(product.displayPrice)
                                    .font(.subheadline)
                                    .bold()
                            }
                            .buttonStyle(.borderedProminent)
                        }
                    }
                    .padding(.vertical, 4)
                }
            }

            Section {
                Button("恢复购买") {
                    Task {
                        await store.restorePurchases()
                        await store.updatePurchasedProducts()
                    }
                }
            }
        }
        .navigationTitle("商店")
        .task {
            await store.loadProducts()
            await store.updatePurchasedProducts()
        }
    }
}
```

> 💡 `product.displayPrice` 会自动显示用户所在地区的本地化价格（如 ¥6、$0.99），无需手动处理汇率。

## 四、订阅模式深度解析

订阅就像办健身卡——按月/按年付费，持续享受服务。这是目前 iOS 开发者最主流也最赚钱的变现方式。

### 4.1 自动续期订阅 vs 非续期订阅

| 特性 | 自动续期订阅 | 非续期订阅 |
|------|-------------|-----------|
| 自动续费 | ✅ 到期自动扣费 | ❌ 到期不续 |
| 用户主动取消 | 随时可取消，到期停 | 无需取消，到期即止 |
| 免费试用 | ✅ 支持 | ❌ 不支持 |
| 优惠促销 | ✅ 支持（intro/promo/offer code） | ❌ 不支持 |
| Apple 管理 | ✅ Apple 处理续费/退款 | ❌ 开发者自行管理 |
| 分组 | 必须放入订阅组 | 不需要 |
| 适用场景 | 持续服务（云存储、会员） | 限时访问（季度课程） |

> 💡 **绝大多数场景选择自动续期订阅**。非续期订阅只在极少数场景使用（如限时课程访问），且需要自己处理到期逻辑。

### 4.2 订阅周期选择

#### 周订阅

就像买一杯奶茶——单次不贵，但长期累积不少。

- **适合**：高频使用的工具类 App（如 AI 对话、每日打卡）
- **定价区间**：¥6-12/周
- **优势**：用户决策门槛低，容易冲动订阅
- **劣势**：用户感知"每周都在扣钱"，取消率较高

#### 月订阅

最主流的选择，就像手机话费——每月固定支出，用户心理接受度高。

- **适合**：绝大多数内容/工具/社交 App
- **定价区间**：¥18-68/月
- **优势**：用户最习惯的付费周期，转化率最佳
- **劣势**：需要持续提供价值，否则用户会取消

#### 年订阅

就像年卡——一次性付清，享受折扣，用户留存率高。

- **适合**：有长期价值的内容/工具 App
- **定价区间**：¥98-348/年
- **优势**：单笔收入高，留存率高，减少扣费摩擦
- **劣势**：初始决策门槛高

#### 年分期（iOS 17+ Pay Later）

Apple 在 iOS 17 引入的分期付款功能——把年费分成 4 期支付，降低用户决策门槛。

- **适合**：年订阅价格较高的 App
- **优势**：降低用户一次性支付压力
- **劣势**：仅支持部分市场，用户认知度尚低

### 4.3 各周期优劣势对比表

| 维度 | 周订阅 | 月订阅 | 年订阅 |
|------|--------|--------|--------|
| 用户决策门槛 | 最低 | 中等 | 最高 |
| 单用户年化收入 | ¥312-624 | ¥216-816 | ¥98-348 |
| 取消率 | 高 | 中 | 低 |
| 用户感知 | "每周都在扣" | "月付还行" | "一次搞定" |
| 管理成本 | 高（频繁续费） | 中 | 低 |
| 推荐指数 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |

### 4.4 订阅组设计

一个订阅组就像餐厅的套餐菜单——不同档位满足不同需求。

#### 典型订阅组结构

| 档位 | 价格 | 包含功能 | 目标用户 |
|------|------|----------|----------|
| 基础版 | ¥18/月 | 核心功能 + 基础云存储 | 轻度用户 |
| 专业版 | ¥38/月 | 全部功能 + 大容量云存储 + 优先支持 | 重度用户 |
| 全家桶 | ¥58/月 | 专业版全部 + 6 人家庭共享 | 家庭用户 |

> 💡 **订阅组规则**：同一订阅组内，用户只能同时订阅一个档位。升级/降级时，Apple 会自动处理差价和时长换算。

#### 在 App Store Connect 中创建订阅组

1. 进入 App → 订阅 → 管理
2. 创建订阅组（如"会员套餐"）
3. 在组内添加不同档位的订阅
4. 设置订阅的定价、试用期、优惠等

### 4.5 免费试用策略

免费试用就像试吃——先尝后买，降低用户决策门槛。

| 试用时长 | 适用场景 | 转化率参考 |
|----------|----------|-----------|
| 3 天 | 功能简单、快速体验 | 较低 |
| 7 天 | 最常见，适合大多数 App | 中等 |
| 14 天 | 复杂功能，需要时间探索 | 较高 |
| 1 个月 | 高价值服务，建立习惯 | 最高 |

> ⚠️ **试用规则**：
> - 试用开始即需要用户确认订阅
> - 试用结束前 24 小时内 Apple 会发送提醒
> - 用户可随时在试用期内取消，不收费
> - 同一订阅产品的免费试用，每个 Apple ID 只能享受一次

### 4.6 优惠促销

#### 介绍性优惠（Introductory Offer）

新用户专属优惠——就像"新店开业，首月半价"。

| 类型 | 说明 | 示例 |
|------|------|------|
| 免费试用 | 试用期内免费 | 7 天免费试用 |
| 付费试用 | 优惠价体验 | 首月 ¥1，之后 ¥18/月 |
| 前期优惠 | 前几期优惠 | 前 3 个月 ¥6/月，之后 ¥18/月 |

#### 促销性优惠（Promotional Offer）

面向**已有订阅历史的用户**（已退订的流失用户）——就像"老客户回归享 8 折"。

- 需要在服务端生成签名（Subscription Offer API）
- 可设置优惠价格和优惠期数
- 适合召回流失用户

#### 优惠码（Offer Code）

类似优惠券——生成一组兑换码，用户手动输入享受优惠。

- 在 App Store Connect 生成
- 可设置有效期和总数量
- 适合营销活动、KOL 推广、线下活动
- 用户在 App Store 兑换或在 App 内通过 `presentOfferCodeRedeemSheet()` 兑换

```swift
Button("兑换优惠码") {
    SKPaymentQueue.default().presentOfferCodeRedeemSheet()
}
```

## 五、变现策略选择

### 5.1 按 App 类型选择变现模式

| App 类型 | 推荐变现模式 | 理由 |
|----------|-------------|------|
| 工具类（天气、计算器） | 免费 + 非消耗型/订阅 | 基础功能免费引流，高级功能付费 |
| 社交类 | 免费 + 订阅 + 虚拟道具 | 需要大量用户基数，订阅增值 |
| 内容类（新闻、视频） | 免费 + 订阅 + 广告 | 内容为王的订阅模式，广告补充 |
| 创意类（绘图、剪辑） | 免费/付费 + 订阅 | 专业功能订阅，基础功能一次性买断 |
| 游戏类 | 免费 + 消耗型内购 + 广告 | 道具内购是游戏变现核心 |

### 5.2 变现策略决策树

```
你的 App 是什么类型？
│
├─ 游戏
│   └─ 免费 + 消耗型内购 + 广告
│
├─ 工具/效率
│   ├─ 功能更新频繁？→ 免费 + 订阅
│   └─ 功能稳定不变？→ 免费 + 非消耗型解锁
│
├─ 内容/媒体
│   ├─ 有独家内容？→ 免费 + 订阅
│   └─ 内容可替代？→ 免费 + 广告 + 订阅
│
├─ 社交
│   └─ 免费 + 订阅 + 虚拟道具
│
└─ 创意/专业
    ├─ 面向专业用户？→ 付费下载 + 内购
    └─ 面向大众？→ 免费 + 订阅
```

### 5.3 从免费到付费的过渡策略

1. **先积累用户**：免费上线，积累口碑和用户基础
2. **验证价值**：通过用户反馈确认哪些功能最有价值
3. **逐步变现**：先加非消耗型内购，再加订阅
4. **保持免费层**：始终保留免费基础功能，避免赶走老用户

> ⚠️ 不要突然把免费功能改成付费，这会导致大量差评和用户流失。

### 5.4 Apple 小型企业计划

| 项目 | 标准分成 | 小型企业计划 |
|------|----------|-------------|
| 开发者分成 | 70% | **85%** |
| Apple 抽成 | 30% | **15%** |
| 适用条件 | — | 上一年总收入 ≤ 100 万美元 |
| 加入方式 | — | App Store Connect 中主动申请 |
| 超出后 | — | 超出部分恢复 70/30 分成 |

> 💡 **对于独立开发者，小型企业计划几乎是必选项**。15% 的抽成差异意味着同样 ¥100 的收入，你可以多拿 ¥15。

## 六、订阅定价心理学

### 6.1 锚定效应

先展示年价，再展示月价——用户会觉得月价"很划算"。

```
❌ 错误展示顺序：
  月订阅：¥28/月
  年订阅：¥268/年

✅ 正确展示顺序：
  年订阅：¥268/年（等价 ¥22.3/月）
  月订阅：¥28/月
```

用户先看到 ¥268，再看到 ¥28，会觉得月订阅"才 28 块"，反而更容易选择月订阅。而如果你想让用户选年订阅，可以这样：

```
✅ 推荐年订阅：
  年订阅：¥268/年  ← 最受欢迎 🌟 等价 ¥22.3/月
  月订阅：¥28/月
```

### 6.2 省钱标签

| 标签文案 | 效果 |
|----------|------|
| 年付省 40% | 直观，转化提升明显 |
| 等价 ¥22.3/月 | 降低心理门槛 |
| 最受欢迎 | 社会认同，引导选择 |
| 限时优惠 | 制造紧迫感 |

### 6.3 试用期转化的最佳实践

1. **试用期就是产品体验期**：确保试用期内用户能体验到核心价值
2. **引导 Aha Moment**：在试用期内引导用户到达"顿悟时刻"——即感受到产品价值的那一刻
3. **适时提醒**：试用期结束前 2-3 天温和提醒（不要过度催促）
4. **数据驱动**：追踪试用期内的用户行为，找出转化用户和流失用户的差异
5. **试用期长度选择**：

| 试用期 | 策略 |
|--------|------|
| 3 天 | 功能简单，快速体验即可感知价值 |
| 7 天 | 最常见，给用户一周时间形成习惯 |
| 14 天 | 复杂产品，需要时间深度体验 |
| 30 天 | 高价值服务，让用户充分依赖 |

> 💡 **试用期不是越长越好**。过长的试用期反而降低紧迫感，7 天是大多数 App 的甜蜜点。

## 七、常见审核被拒原因

### 7.1 内购相关被拒

| 被拒原因 | 说明 | 解决方案 |
|----------|------|----------|
| 缺少恢复购买按钮 | 非消耗型/订阅必须提供恢复购买 | 添加"恢复购买"按钮 |
| 引导外部支付 | App 内引导用户去网站/其他渠道付费 | 所有数字内容必须走 IAP |
| 虚拟货币未走 IAP | App 内的虚拟货币/道具通过第三方支付 | 使用 StoreKit 内购 |
| 内购产品描述不清 | 产品描述与实际功能不符 | 确保描述准确反映功能 |
| 缺少隐私政策 | 提供 IAP 的 App 必须有隐私政策 | 在 App Store Connect 填写隐私政策 URL |

> ⚠️ **3.1.1 条款**：App 内所有数字内容/服务/功能必须使用 IAP，不得引导用户使用其他支付方式。这是最常见的被拒原因！

### 7.2 订阅相关被拒

| 被拒原因 | 说明 | 解决方案 |
|----------|------|----------|
| 订阅用途不明确 | 用户不清楚订阅包含什么 | 在购买页面清晰列出订阅内容 |
| 缺少订阅管理入口 | 用户无法方便地管理/取消订阅 | 提供跳转到订阅管理的入口 |
| 试用信息不清晰 | 未明确说明试用期后自动扣费 | 明确标注"试用期后 ¥XX/月自动续费" |
| 订阅价格不显示 | 未在 App 内显示订阅价格 | 使用 `product.displayPrice` 展示价格 |
| 订阅内容与免费内容无差异 | 付费和免费功能没有明显区别 | 确保订阅有明确增值内容 |

跳转到订阅管理的代码：

```swift
if let url = URL(string: "https://apps.apple.com/account/subscriptions") {
    UIApplication.shared.open(url)
}
```

### 7.3 定价相关被拒

| 被拒原因 | 说明 | 解决方案 |
|----------|------|----------|
| 价格与价值不匹配 | 定价远高于同类 App | 参考竞品定价，合理定价 |
| 隐藏费用 | 未提前告知需要内购才能使用核心功能 | 在 App 描述和界面中明确说明 |
| 误导性优惠 | 标注"限时优惠"但实际长期有效 | 优惠信息必须真实 |
| 跨平台价格不一致 | 同一内容在 iOS 上比其他平台贵很多 | 尽量保持跨平台价格一致 |

## 八、实战案例：3 种典型 App 的变现方案设计

### 案例 1：AI 写作助手

**App 定位**：帮助用户生成、润色、翻译文本的 AI 工具

| 变现设计 | 详情 |
|----------|------|
| 模式 | 免费 + 订阅 |
| 免费层 | 每日 3 次 AI 生成，基础模板 |
| 订阅档位 | 基础版 ¥18/月（每日 50 次）<br>专业版 ¥38/月（无限次 + 高级模板 + 优先响应） |
| 年订阅 | 基础版 ¥128/年（省 40%）<br>专业版 ¥268/年（省 41%） |
| 试用期 | 7 天免费试用专业版 |
| 优惠策略 | 新用户首月 ¥1 体验 |

**设计理由**：
- AI 调用有成本，免费层限制次数控制成本
- 订阅而非一次性买断，因为 AI 服务有持续成本
- 7 天试用让用户体验到"无限次"的爽感，回归免费层后形成落差，驱动转化

### 案例 2：习惯打卡 App

**App 定位**：帮助用户养成好习惯的打卡工具

| 变现设计 | 详情 |
|----------|------|
| 模式 | 免费 + 非消耗型内购 + 订阅 |
| 免费层 | 3 个习惯追踪，基础统计 |
| 非消耗型内购 | 永久解锁：¥28（无限习惯 + 高级统计图表） |
| 订阅 | ¥12/月（云同步 + 数据导出 + 社群功能） |
| 年订阅 | ¥98/年（省 32%） |
| 无广告 | 所有用户均无广告 |

**设计理由**：
- 核心功能（打卡）免费，降低使用门槛
- 非消耗型内购满足"一次性买断"用户的需求
- 订阅提供需要持续成本的服务（云同步、社群）
- 不做广告变现，保持清爽体验，符合习惯养成类 App 调性

### 案例 3：儿童教育游戏

**App 定位**：3-6 岁儿童的识字、算术互动游戏

| 变现设计 | 详情 |
|----------|------|
| 模式 | 免费 + 订阅 + 非消耗型内购 |
| 免费层 | 2 个主题关卡，每日 1 个小游戏 |
| 订阅 | ¥28/月（全部关卡 + 每周更新内容） |
| 年订阅 | ¥198/年（省 41%） |
| 非消耗型内购 | 单主题买断 ¥12（不需要订阅也能永久玩） |
| 试用期 | 14 天免费试用（家长需要时间观察孩子是否喜欢） |
| 家庭共享 | 支持 Family Sharing |

**设计理由**：
- 儿童内容需要家长决策，14 天试用给足观察时间
- 年订阅定价 ¥198 在家长可接受范围内（相当于一门线下课一节课的钱）
- 单主题买断满足不想订阅的家长
- Family Sharing 让多孩家庭更愿意付费
- 持续更新内容是订阅的核心价值

> 💡 **儿童类 App 特别注意**：必须遵守 App Store 的"儿童类别"审核规则，不得包含广告、不得收集个人信息、内购需要家长授权。

## 小结

| 本章要点 | 一句话总结 |
|----------|-----------|
| 变现模式 | 五大模式各有适用场景，混合模式最常见 |
| 付费下载 | 适合专业/品牌 App，大众 App 不推荐 |
| 消耗型内购 | 游戏道具/虚拟货币，可重复购买 |
| 非消耗型内购 | 一次性买断功能，必须支持恢复购买 |
| 自动续期订阅 | 最主流的变现方式，持续性收入 |
| 订阅定价 | 月订阅最常见，年订阅留存最高，周订阅慎用 |
| 免费试用 | 7 天是甜蜜点，试用期就是产品体验期 |
| 定价心理学 | 锚定效应 + 省钱标签 + 社会认同 |
| 审核避坑 | 数字内容必须走 IAP，订阅信息必须透明 |
| StoreKit 2 | async/await 风格，代码简洁，iOS 15+ 必选 |

> 💡 **最后的建议**：变现不是一锤子买卖，而是一个持续优化的过程。先上线最小可行方案，收集数据，再迭代。记住——用户愿意为真正有价值的东西付费，把产品做好才是最好的变现策略。
