# 归因与广告效果衡量

> 🎯 **本章目标**：系统掌握移动广告归因的核心原理和技术方案，理解 SKAdNetwork、MMP、深度链接归因等关键概念，学会计算 ROAS、ROI 等广告效果指标，并能在 iOS 隐私框架下构建可靠的广告效果衡量体系。

---

## 为什么归因很重要

你花了 ¥10,000 投广告，带来了 500 个下载。但你知道这 500 个下载分别来自哪个广告、哪个关键词、哪个素材吗？

```text
没有归因：
"广告好像有效果，下载量增加了" → 凭感觉投，浪费预算

有归因：
"ASA 的'记账'关键词 CPA ¥8，转化率 25%"
"抖音信息流的 CPA ¥20，转化率 8%"
"小红书 KOL 带来的用户 7 日留存 35%"
→ 精准投放，砍掉低效渠道，加大高效渠道
```

> 💡 **提示**：归因是"花钱买用户"的前提。不知道钱花在哪了，就无法优化投放策略。独立开发者预算有限，每一分钱都要花在刀刃上。

## 移动归因基础

### 什么是移动归因

移动归因（Mobile Attribution）是指**确定一次 App 安装或用户行为是由哪个广告、哪个渠道带来的**。

```text
归因链路：

用户看到广告 → 点击广告 → 跳转 App Store → 下载安装 → 打开 App → 归因系统记录

关键问题：如何把"看到广告"和"下载安装"关联起来？
```

### 归因的核心挑战

| 挑战 | 说明 | 影响 |
|------|------|------|
| **iOS 隐私限制** | ATT 框架限制 IDFA 追踪 | 无法精确归因 |
| **跨平台追踪** | 用户在手机看广告，iPad 下载 | 归因断裂 |
| **延迟深度链接** | 首次安装无法直接跳转到特定页面 | 体验差 |
| **广告欺诈** | 虚假点击、虚假安装 | 数据失真 |
| **多触点归因** | 用户看了多个广告才下载 | 归因归属难 |

## iOS 归因技术方案

### 方案一：IDFA + ATT（精确归因）

IDFA（Identifier for Advertisers）是 Apple 为广告追踪提供的设备标识符。在用户授权 ATT 后，可以精确追踪。

```text
流程：
1. App 请求 ATT 授权
2. 用户选择"允许追踪"
3. 获取 IDFA
4. 归因平台用 IDFA 匹配广告点击和安装

授权率：
全球平均：25-40%
国内平均：15-30%
```

```swift
import AppTrackingTransparency
import AdSupport

func requestIDFA() {
    ATTrackingManager.requestTrackingAuthorization { status in
        switch status {
        case .authorized:
            let idfa = ASIdentifierManager.shared().advertisingIdentifier.uuidString
            print("IDFA: \(idfa)")
        case .denied, .restricted, .notDetermined:
            print("无法获取 IDFA")
        @unknown default:
            break
        }
    }
}
```

> ⚠️ **警告**：ATT 授权率持续走低，全球平均约 30%。这意味着 70% 的用户无法通过 IDFA 精确归因。你必须准备替代方案。

### 方案二：SKAdNetwork（Apple 官方归因）

SKAdNetwork 是 Apple 提供的**隐私友好的归因方案**，不依赖 IDFA，所有用户都可归因。

```text
SKAdNetwork 流程：

1. 用户点击广告 → 广告平台注册 click
2. 用户安装 App → App 注册 install
3. App 更新 conversion value（0-63）→ 最多 6 次
4. 等待 24-48 小时 → Apple 发送 postback 给广告平台
5. 广告平台收到归因数据

关键限制：
- 归因结果延迟 24-48 小时
- conversion value 只有 0-63（6 位）
- 最多 6 次更新 conversion value
- 不包含用户级别数据（只有聚合数据）
- 没有点击/安装的精确时间
```

#### SKAdNetwork Conversion Value 设计

Conversion Value 是 SKAdNetwork 最核心的概念，你需要精心设计它的含义：

```text
6 位（0-63）的设计方案：

方案一：按用户行为深度（推荐）

值 0：安装（默认）
值 1：打开 App
值 2：完成注册
值 3：完成新手引导
值 4：使用核心功能 1 次
值 5：使用核心功能 3 次
值 6：查看付费墙
值 7：开始免费试用
值 8：完成首次付费
值 9-15：付费金额区间
值 16-63：保留给高级行为

方案二：按收入区间

值 0：安装
值 1-10：低价值（¥0-¥10）
值 11-30：中价值（¥10-¥100）
值 31-50：高价值（¥100-¥500）
值 51-63：超高价值（¥500+）
```

```swift
import StoreKit

func updateSKAdNetworkConversionValue(event: UserEvent) {
    let value: Int
    switch event {
    case .appOpened: value = 1
    case .registered: value = 2
    case .onboardingCompleted: value = 3
    case .coreFeatureUsed: value = 4
    case .paywallViewed: value = 6
    case .trialStarted: value = 7
    case .firstPurchase: value = 8
    default: return
    }

    SKAdNetwork.updateConversionValue(value)
}
```

#### SKAdNetwork 4.0 新特性

| 特性 | 说明 | 影响 |
|------|------|------|
| **Web-to-App 归因** | 支持网页广告到 App 安装的归因 | 覆盖更多广告场景 |
| **多层 Conversion Value** | 粗粒度值 + 细粒度值 | 更灵活的归因设计 |
| **多次 Postback** | 支持发送多个归因回调 | 更长时间窗口观察 |
| **Crowd Anonymous Tier** | 根据安装量决定数据精度 | 大 App 获得更精确数据 |

### 方案三：MMP（Mobile Measurement Partner）

MMP 是第三方归因平台，整合了 IDFA、SKAdNetwork 等多种归因方式，提供统一的归因报告。

```text
主流 MMP 平台：

| 平台 | 国内可用 | 特点 | 价格 |
|------|---------|------|------|
| AppsFlyer | ✅ | 全球最大，功能最全 | 免费版可用 |
| Adjust | ✅ | 欧洲最大，反欺诈强 | 免费版可用 |
| Branch | ✅ | 深度链接强 | 免费版可用 |
| Singular | ⚠️ | ROI 分析强 | 付费 |
| 神策分析 | ✅ | 国内生态好 | 付费为主 |
```

#### MMP 集成示例（AppsFlyer）

```swift
import AppsFlyerLib

@main
struct MyApp: App {
    init() {
        AppsFlyerLib.shared().appsFlyerDevKey = "YOUR_DEV_KEY"
        AppsFlyerLib.shared().appleAppID = "1234567890"
        AppsFlyerLib.shared().delegate = AttributionManager.shared
        AppsFlyerLib.shared().waitForATTUserAuthorization(timeoutInterval: 60)
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
                .onAppear {
                    ATTrackingManager.requestTrackingAuthorization { _ in
                        AppsFlyerLib.shared().start()
                    }
                }
        }
    }
}

class AttributionManager: NSObject, AppsFlyerLibDelegate {
    static let shared = AttributionManager()

    func onConversionDataSuccess(_ conversionInfo: [AnyHashable: Any]) {
        print("归因数据: \(conversionInfo)")
        if let campaign = conversionInfo["campaign"] as? String {
            print("广告系列: \(campaign)")
        }
        if let mediaSource = conversionInfo["media_source"] as? String {
            print("媒体来源: \(mediaSource)")
        }
    }

    func onConversionDataFail(_ error: Error) {
        print("归因失败: \(error)")
    }
}
```

## 深度链接与归因

### 什么是深度链接

深度链接（Deep Link）是**让用户从广告/分享链接直接跳转到 App 内特定页面**的技术。

```text
没有深度链接：
广告 → App Store → 打开 App → 首页 → 用户自己找内容 → 大部分人放弃

有深度链接：
广告 → App Store → 打开 App → 直接跳到广告对应的内容 → 转化率高
```

### 深度链接的三种类型

| 类型 | 原理 | 适用场景 | 限制 |
|------|------|---------|------|
| **Custom URL Scheme** | `myapp://page/detail` | 简单跳转 | 其他 App 也可注册，不安全 |
| **Universal Links** | `https://myapp.com/page` | 安全跳转 | 需要配置 apple-app-site-association |
| **Deferred Deep Link** | 延迟深度链接 | 首次安装后跳转 | iOS 原生不支持，需 MMP |

### Universal Links 配置

**步骤 1：配置 apple-app-site-association 文件**

```json
{
    "applinks": {
        "details": [
            {
                "appIDs": ["TEAMID.com.example.myapp"],
                "components": [
                    {
                        "/": "/share/*",
                        "comment": "分享页面"
                    },
                    {
                        "/": "/promo/*",
                        "comment": "促销活动页面"
                    }
                ]
            }
        ]
    }
}
```

**步骤 2：上传到服务器**

```text
URL: https://myapp.com/.well-known/apple-app-site-association
要求：
- HTTPS
- 无重定向
- Content-Type: application/json
- 无 .json 后缀
```

**步骤 3：Xcode 配置 Associated Domains**

```text
Signing & Capabilities → Associated Domains
添加：applinks:myapp.com
```

**步骤 4：SwiftUI 处理 Universal Links**

```swift
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .onOpenURL { url in
                    handleDeepLink(url)
                }
        }
    }

    func handleDeepLink(_ url: URL) {
        guard url.host == "myapp.com" else { return }

        switch url.path {
        case let p where p.hasPrefix("/share/"):
            let id = p.replacingOccurrences(of: "/share/", with: "")
            navigateToShare(id: id)
        case let p where p.hasPrefix("/promo/"):
            let id = p.replacingOccurrences(of: "/promo/", with: "")
            navigateToPromo(id: id)
        default:
            break
        }
    }
}
```

### 延迟深度链接（Deferred Deep Link）

延迟深度链接是**用户首次安装 App 后，打开时自动跳转到广告对应的页面**。这是营销场景最需要的功能。

```text
场景：
1. 用户看到广告："限时 5 折优惠"
2. 用户点击广告 → 跳转 App Store
3. 用户下载安装 App（首次安装）
4. 用户打开 App → 直接看到"5 折优惠"页面

问题：iOS 原生不支持延迟深度链接
解决：使用 MMP（AppsFlyer/Adjust/Branch）实现
```

```swift
import AppsFlyerLib

func setupDeferredDeepLink() {
    AppsFlyerLib.shared().delegate = self
    AppsFlyerLib.shared().deepLinkDelegate = self
}

class DeepLinkHandler: DeepLinkDelegate {
    func didResolveDeepLink(_ result: DeepLinkResult) {
        switch result.status {
        case .found:
            guard let deepLink = result.deepLink,
                  let path = deepLink["deeplink_path"] as? String else { return }
            handleDeepLink(URL(string: path)!)
        case .notFound:
            print("无延迟深度链接")
        @unknown default:
            break
        }
    }
}
```

## 广告效果衡量指标

### ROAS（Return On Ad Spend）广告支出回报率

ROAS 是**每花 1 元广告费能带来多少收入**，是衡量广告效果的核心指标。

```text
ROAS = 广告带来的收入 ÷ 广告支出 × 100%

示例：
广告支出：¥5,000
广告带来的收入：¥15,000
ROAS = 15,000 ÷ 5,000 × 100% = 300%

含义：每花 ¥1 广告费，带来 ¥3 收入
```

#### ROAS 的计算维度

| 维度 | 计算方式 | 用途 |
|------|---------|------|
| **ROAS（7日）** | 7 日收入 ÷ 广告支出 | 短期效果评估 |
| **ROAS（30日）** | 30 日收入 ÷ 广告支出 | 中期效果评估 |
| **ROAS（LTV）** | LTV 收入 ÷ 广告支出 | 长期效果评估 |

```text
示例（订阅 App）：

广告支出：¥5,000
7 日收入：¥2,000 → ROAS(7日) = 40%
30 日收入：¥8,000 → ROAS(30日) = 160%
LTV 收入：¥20,000 → ROAS(LTV) = 400%

→ 短期看亏本（7日 ROAS < 100%）
→ 中期看回本（30日 ROAS > 100%）
→ 长期看盈利（LTV ROAS = 400%）
```

> ⚠️ **警告**：不同 App 的 ROAS 回本周期差异巨大。订阅制 App 通常需要 30-90 天才能 ROAS > 100%，而广告变现 App 可能 7 天就能回本。

### ROI（Return On Investment）投资回报率

ROI 和 ROAS 容易混淆，区别如下：

```text
ROAS = 收入 ÷ 广告支出
ROI = (收入 - 成本) ÷ 成本 × 100%

示例：
广告支出：¥5,000
广告带来的收入：¥15,000
App Store 抽成（30%）：¥4,500
净收入：¥15,000 - ¥4,500 = ¥10,500

ROAS = 15,000 ÷ 5,000 = 300%
ROI = (10,500 - 5,000) ÷ 5,000 × 100% = 110%

→ ROAS 300% 看起来很好
→ 但扣除平台抽成后，ROI 只有 110%
→ 真正的利润 = ¥10,500 - ¥5,000 = ¥5,500
```

| 指标 | 公式 | 含义 |
|------|------|------|
| **ROAS** | 收入 ÷ 广告支出 | 每元广告带来多少收入 |
| **ROI** | (净收入 - 成本) ÷ 成本 | 每元成本带来多少利润 |
| **CPA** | 广告支出 ÷ 转化次数 | 每次转化的成本 |
| **CPI** | 广告支出 ÷ 安装次数 | 每次安装的成本 |

### CPA 与 CPI 的区别

```text
CPI（Cost Per Install）：每次安装的成本
CPA（Cost Per Action）：每次目标行动的成本

示例：
广告支出：¥5,000
安装数：250
注册数：150
付费用户：10

CPI = 5,000 ÷ 250 = ¥20
CPA（注册）= 5,000 ÷ 150 = ¥33
CPA（付费）= 5,000 ÷ 10 = ¥500

→ CPI 最低但意义有限（安装 ≠ 使用）
→ CPA（付费）最高但最有价值（直接关联收入）
```

## 广告效果追踪实战

### Apple Search Ads 效果追踪

Apple Search Ads 是 iOS 开发者最常用的付费获客渠道，它有内置的归因功能：

```text
Apple Search Ads 归因：

1. 用户在 App Store 搜索并点击 ASA 广告
2. 用户下载安装 App
3. App 内调用 ADClient 框架获取归因数据
4. 匹配到具体的 Campaign、Ad Group、Keyword
```

```swift
import AdServices
import iAd

func fetchASAAttribution() async {
    do {
        let token = try AAAttribution.attributionToken()
        let url = URL(string: "https://api-adservices.apple.com/api/v1/attribution")!
        var request = URLRequest(url: url)
        request.httpMethod = "POST"
        request.setValue("text/plain", forHTTPHeaderField: "Content-Type")
        request.httpBody = Data(token.utf8)

        let (data, _) = try await URLSession.shared.data(for: request)
        if let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any] {
            print("ASA 归因: \(json)")
        }
    } catch {
        print("ASA 归因获取失败: \(error)")
    }
}
```

### 自建归因系统（轻量方案）

对于预算有限的独立开发者，可以不依赖 MMP，自建轻量归因：

```text
方案：UTM 参数 + 深度链接 + 本地记录

1. 广告链接带 UTM 参数
   https://myapp.com/promo?utm_source=wechat&utm_medium=kol&utm_campaign=spring_sale

2. 用户点击链接 → Universal Links 跳转 App
3. App 解析 UTM 参数并记录到本地
4. 用户完成关键行为时，带上 UTM 信息上报

限制：
- 无法追踪首次安装的归因（延迟深度链接需要 MMP）
- 无法跨设备追踪
- 数据精度低于 MMP
```

```swift
struct AttributionData: Codable {
    let source: String
    let medium: String
    let campaign: String
    let content: String?
    let timestamp: Date
}

class AttributionTracker: ObservableObject {
    static let shared = AttributionTracker()

    @Published var currentAttribution: AttributionData?

    func trackFromURL(_ url: URL) {
        guard let components = URLComponents(url: url, resolvingAgainstBaseURL: false),
              let queryItems = components.queryItems else { return }

        let source = queryItems.first(where: { $0.name == "utm_source" })?.value ?? "unknown"
        let medium = queryItems.first(where: { $0.name == "utm_medium" })?.value ?? "unknown"
        let campaign = queryItems.first(where: { $0.name == "utm_campaign" })?.value ?? "unknown"
        let content = queryItems.first(where: { $0.name == "utm_content" })?.value

        currentAttribution = AttributionData(
            source: source,
            medium: medium,
            campaign: campaign,
            content: content,
            timestamp: Date()
        )

        saveAttribution()
    }

    private func saveAttribution() {
        guard let data = try? JSONEncoder().encode(currentAttribution) else { return }
        UserDefaults.standard.set(data, forKey: "attribution_data")
    }

    func logEvent(_ event: String, value: Double = 0) {
        guard let attr = currentAttribution else { return }
        print("[归因事件] \(event) | 来源: \(attr.source) | 渠道: \(attr.medium) | 活动: \(attr.campaign) | 值: \(value)")
    }
}
```

## 广告效果优化策略

### 渠道效果对比

```text
渠道效果对比模板：

| 渠道 | CPI | CPA(注册) | CPA(付费) | 7日ROAS | 30日ROAS | 留存率 |
|------|-----|----------|----------|---------|----------|--------|
| ASA  | ¥8  | ¥15      | ¥120     | 45%     | 180%     | 35%    |
| 抖音 | ¥12 | ¥25      | ¥200     | 20%     | 80%      | 22%    |
| 小红书 | ¥10 | ¥20     | ¥180     | 25%     | 100%     | 28%    |
| 微信 | ¥15 | ¥30      | ¥250     | 15%     | 60%      | 18%    |

→ ASA 性价比最高，应加大投入
→ 微信渠道效果差，考虑暂停或优化素材
```

### 广告素材优化

| 优化维度 | 做法 | 预期效果 |
|----------|------|---------|
| **素材类型** | 视频 > 图片 > 纯文字 | 视频点击率高 2-3 倍 |
| **前 3 秒** | 展示核心价值/痛点 | 决定 80% 的用户是否继续看 |
| **CTA 文案** | "免费试用" > "立即购买" | 降低心理门槛 |
| **社交证明** | 展示用户评价/使用场景 | 提升信任度 |
| **A/B 测试** | 同时测试 2-3 个素材版本 | 数据驱动选择 |

### 出价策略

```text
ASA 出价策略：

1. 冷启动期（前 2 周）
   - 使用"自动出价"让 Apple 算法学习
   - 不急于追求低 CPA，先积累数据

2. 优化期（2-4 周）
   - 切换到"手动出价"
   - 高转化关键词提高出价
   - 低转化关键词降低出价或暂停

3. 规模期（1 个月+）
   - 核心关键词维持 Top 3 排名
   - 长尾关键词低价覆盖
   - 定期添加否定关键词
```

## 隐私合规与归因

### ATT 对归因的影响

```text
ATT 授权前后的归因能力对比：

| 能力 | 授权前 | 授权后 |
|------|--------|--------|
| IDFA 追踪 | ❌ | ✅ |
| SKAdNetwork | ✅ | ✅ |
| 精确归因 | ❌ | ✅ |
| 用户级数据 | ❌ | ✅ |
| 聚合数据 | ✅ | ✅ |
| 延迟深度链接 | ⚠️ 有限 | ✅ |

→ 即使 ATT 授权率低，SKAdNetwork 仍然可用
→ 建议同时使用 IDFA + SKAdNetwork 双重归因
```

### 隐私合规最佳实践

```text
1. 先请求 ATT，再初始化归因 SDK
2. 明确告知用户为什么需要追踪
3. 不追踪的用户也要能用 App 全部功能
4. 归因数据不与第三方共享（除广告平台外）
5. 遵守 GDPR/PIPL 等隐私法规
```

```swift
func setupAttribution() {
    ATTrackingManager.requestTrackingAuthorization { status in
        switch status {
        case .authorized:
            AppsFlyerLib.shared().start()
            fetchASAAttribution()
        case .denied, .restricted, .notDetermined:
            AppsFlyerLib.shared().start()
            fetchASAAttribution()
        @unknown default:
            break
        }
    }
}
```

## 归因指标速查表

| 指标 | 全称 | 公式 | 核心关注 |
|------|------|------|---------|
| ROAS | Return On Ad Spend | 广告收入 ÷ 广告支出 | 广告投入产出比 |
| ROI | Return On Investment | (净收入 - 成本) ÷ 成本 | 投资利润率 |
| CPI | Cost Per Install | 广告支出 ÷ 安装数 | 每次安装成本 |
| CPA | Cost Per Action | 广告支出 ÷ 转化数 | 每次转化成本 |
| CTR | Click-Through Rate | 点击数 ÷ 展示数 | 广告吸引力 |
| CVR | Conversion Rate | 转化数 ÷ 点击数 | 落地页/商店页效果 |
| eCPA | Effective CPA | 实际支出 ÷ 有效转化 | 扣除欺诈后的真实成本 |
| TTR | Tap-Through Rate | 点击率（ASA 专用） | ASA 广告点击率 |

---

## 本章小结

- **归因**是付费获客的基础，不知道钱花在哪就无法优化
- **SKAdNetwork** 是 iOS 隐私框架下的主要归因方案，Conversion Value 设计至关重要
- **MMP**（AppsFlyer/Adjust/Branch）提供统一归因平台，整合多种归因方式
- **深度链接**提升广告转化率，延迟深度链接需要 MMP 支持
- **ROAS** 衡量广告投入产出比，**ROI** 衡量实际利润率，两者不要混淆
- 独立开发者可以从 ASA 内置归因 + 自建 UTM 追踪开始，逐步升级到 MMP
