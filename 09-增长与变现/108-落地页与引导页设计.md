# 108-落地页与引导页设计

## 本章目标

- 理解落地页和引导页的概念与作用
- 掌握落地页的必备元素和设计原则
- 学会用 SwiftUI 实现引导页
- 了解引导页与付费墙的衔接策略
- 能够快速搭建落地页并追踪关键数据

## 一、落地页（Landing Page）是什么

想象你开了一家奶茶店。App Store 页面就像商场里的店铺门面——顾客必须先走进商场才能看到。而落地页就像你在商场门口发的传单，上面写着"扫码立享买一送一"，直接把路人拉进店里。

**落地页 = App 的线上名片 + 转化入口**

它是一个独立的网页，专门为"让访客下载你的 App"这一个目标而设计。用户通过搜索引擎、社交媒体广告、二维码等渠道来到这个页面，看完后被说服去下载。

> 💡 落地页的核心使命只有一个：**让访客变成用户**。页面上的一切元素都应该为这个目标服务。

---

## 二、落地页 vs App Store 页面

| 对比维度 | 落地页 | App Store 页面 |
|---------|--------|---------------|
| 访问方式 | 任何 URL 链接 | 必须在 App Store 内打开 |
| 自由度 | 完全自定义设计、文案、布局 | 受 Apple 模板限制 |
| 数据追踪 | 可追踪访问量、点击率、来源 | 数据有限，主要靠 App Store Connect |
| SEO | 可被搜索引擎收录 | App Store 搜索引擎收录 |
| 更新速度 | 随时修改，即时生效 | 需提交审核，1-2 天生效 |
| 转化路径 | 落地页 → App Store → 下载 | 直接下载 |
| 成本 | 域名+托管费用 | 免费 |
| A/B 测试 | 轻松实现 | 需要苹果的 Product Page Optimization |

> ⚠️ 落地页和 App Store 页面不是"二选一"的关系，而是**互补**的。落地页负责引流和说服，App Store 页面负责最终转化。

**典型转化路径：**

```
社交媒体广告 → 落地页（说服用户）→ App Store（完成下载）→ 引导页（留住用户）
```

## 三、落地页必备元素

一个完整的落地页就像一份精心设计的菜单——从开胃菜到甜点，每道菜都有它的位置和目的。

### 3.1 Hero 区域（首屏）

Hero 区域是用户打开页面第一眼看到的内容，相当于奶茶店门口的招牌。如果招牌不够吸引人，路人不会走进来。

**必备元素：**

| 元素 | 说明 | 示例 |
|------|------|------|
| App 名称 | 醒目大字 | "FocusTimer" |
| 一句话描述 | 说清 App 解决什么问题 | "让专注变得简单的时间管理工具" |
| 下载按钮（CTA） | 最醒目的按钮 | "免费下载" |
| 设备截图 | iPhone/iPad 上的真实效果 | 带设备边框的截图 |

```html
<!-- Hero 区域示例 -->
<section class="hero">
  <h1>FocusTimer</h1>
  <p class="tagline">让专注变得简单的时间管理工具</p>
  <a href="https://apps.apple.com/app/idxxxxx" class="cta-button">
    <img src="appstore-badge.svg" alt="Download on the App Store">
  </a>
  <img src="iphone-screenshot.png" alt="App 截图" class="device-mockup">
</section>
```

> 💡 Hero 区域的"一句话描述"是最难写也最重要的文案。不要写"一款时间管理 App"，要写"让专注变得简单"——前者是功能描述，后者是用户收益。

### 3.2 功能展示区

用 3-5 个核心功能告诉用户"这个 App 能帮我做什么"。每个功能配一个图标+标题+简短描述。

```
┌─────────────────────────────────────────┐
│  🎯 专注模式    📊 数据统计    🏆 成就系统  │
│  番茄钟+白噪音   每日/每周报告   连续打卡奖励  │
└─────────────────────────────────────────┘
```

**功能展示的写法对比：**

| ❌ 错误写法 | ✅ 正确写法 |
|-----------|-----------|
| 支持番茄钟功能 | 番茄钟帮你进入心流状态 |
| 内置数据统计 | 一目了然看到你的专注趋势 |
| 成就系统 | 每一次专注都值得被记录 |
| 支持白噪音 | 用自然声音屏蔽干扰 |

> ⚠️ 功能描述要写"用户能得到什么"，而不是"App 有什么功能"。就像卖钻头，用户要的不是钻头，而是墙上的洞。

### 3.3 社会证明（Social Proof）

社会证明就像餐厅门口排队的长龙——看到别人都在用，新用户也会放心。

| 类型 | 示例 |
|------|------|
| 用户评价 | "这是我用过最好的专注 App！" —— 小明 |
| 媒体报道 | "被 ProductHunt 评为本周最佳 App" |
| 下载量 | "已有 100,000+ 用户正在使用" |
| 评分 | "App Store 4.8 分" |
| 知名用户 | "被 XX 公司团队推荐使用" |

### 3.4 FAQ 区域

解答用户最后的疑虑，降低下载的心理门槛。

```html
<section class="faq">
  <h2>常见问题</h2>
  <div class="faq-item">
    <h3>FocusTimer 免费吗？</h3>
    <p>基础功能完全免费。Pro 版本提供高级统计和无限白噪音，每月 ¥12。</p>
  </div>
  <div class="faq-item">
    <h3>支持哪些设备？</h3>
    <p>支持 iPhone、iPad 和 Mac，数据通过 iCloud 自动同步。</p>
  </div>
  <div class="faq-item">
    <h3>数据会丢失吗？</h3>
    <p>所有数据自动备份到 iCloud，换设备也能恢复。</p>
  </div>
</section>
```

### 3.5 页脚

页脚虽然不起眼，但包含了法律和信任相关的必要信息。

| 元素 | 作用 |
|------|------|
| 隐私政策链接 | 合规要求，App Store 审核也需要 |
| 用户协议链接 | 法律保护 |
| 联系方式 | 用户反馈渠道 |
| 版权声明 | © 2026 YourCompany |
| 社交媒体链接 | 增加触达渠道 |

> ⚠️ App Store 审核时，审核员会检查你的隐私政策和用户协议链接。如果落地页上没有这些链接，可能导致审核被拒。

## 四、落地页设计原则

### 4.1 一屏一信息

每滚动一屏，只传达一个核心信息。就像翻书一样，一页一个画面，不要把所有内容塞进一屏。

```
第 1 屏：Hero —— "这是什么 App"
第 2 屏：核心功能 —— "能帮我做什么"
第 3 屏：社会证明 —— "别人用得怎么样"
第 4 屏：FAQ —— "还有什么疑问"
第 5 屏：页脚 CTA —— "现在就下载"
```

### 4.2 移动端优先

超过 60% 的落地页访问来自手机。设计时先做手机版，再扩展到桌面版。

| 设计要点 | 移动端 | 桌面端 |
|---------|--------|--------|
| 字号 | 正文 ≥ 16px | 正文 ≥ 18px |
| CTA 按钮 | 全宽，高度 ≥ 48px | 宽度 200-300px |
| 截图 | 1 张居中 | 2-3 张并排 |
| 间距 | 留白更多 | 适当紧凑 |

### 4.3 CTA 醒目

CTA（Call To Action）按钮是落地页最重要的元素，就像收银台——前面的所有展示都是为了让用户走到这里。

```
✅ 好的 CTA：          ❌ 差的 CTA：
- "免费下载"           - "了解更多"
- "立即体验"           - "提交"
- "开始专注"           - "点击这里"
- 按钮颜色与背景对比强   - 按钮和背景融为一体
```

### 4.4 加载速度 < 3 秒

加载速度就像实体店的等位时间——等太久，客人就走了。

| 加载时间 | 用户流失率 |
|---------|-----------|
| 1 秒 | ~7% |
| 3 秒 | ~40% |
| 5 秒 | ~53% |
| 10 秒 | ~70% |

**提速方法：**

- 图片使用 WebP 格式，压缩到 100KB 以内
- 使用 CDN 加速静态资源
- 延迟加载（Lazy Load）非首屏图片
- 最小化 CSS/JS 文件

> 💡 用 Google PageSpeed Insights（pagespeed.web.dev）可以免费检测落地页的加载速度和优化建议。

## 五、引导页（Onboarding）是什么

引导页是用户**首次打开 App** 时看到的引导流程。就像新员工入职第一天的培训——告诉他们"这里有什么、怎么用、能帮你做什么"。

**引导页的核心目标：**

1. **让用户快速理解 App 的价值**（30 秒内）
2. **帮助用户完成关键设置**（降低使用门槛）
3. **引导用户到达"Aha Moment"**（第一次感受到价值的时刻）

> ⚠️ 引导页不是产品说明书。用户不想读说明书，他们想尽快开始使用。引导页应该像电梯演讲——30 秒内让人产生兴趣。

## 六、引导页类型

### 6.1 功能介绍型

最经典的引导页形式，滑动展示 3-5 个核心功能。

```
┌──────────┐   ┌──────────┐   ┌──────────┐
│  🎯      │   │  📊      │   │  🏆      │
│ 专注模式  │ → │ 数据统计  │ → │ 成就系统  │
│          │   │          │   │          │
│  ● ○ ○   │   │  ○ ● ○   │   │  ○ ○ ●   │
│ [跳过] [下一步]│ [跳过] [下一步]│ [开始使用] │
└──────────┘   └──────────┘   └──────────┘
```

**适用场景：** 功能独特、需要解释才能理解的 App（如专业工具类）

### 6.2 个性化设置型

让用户选择偏好，直接定制自己的体验。

```
┌──────────────────────┐
│  你最想提升哪方面？     │
│                      │
│  ☑ 专注力             │
│  ☐ 睡眠质量           │
│  ☑ 学习效率           │
│  ☐ 运动习惯           │
│                      │
│  每天想专注多久？       │
│  [1小时] [2小时] [3小时]│
│                      │
│       [开始]          │
└──────────────────────┘
```

**适用场景：** 内容推荐类、可定制化程度高的 App（如健身、阅读、音乐）

### 6.3 注册/登录型

引导用户创建账号，通常在功能介绍之后。

```
┌──────────────────────┐
│  创建你的账户          │
│                      │
│  [🍎 通过 Apple 登录]  │
│  [📧 通过邮箱注册]     │
│                      │
│  已有账户？登录        │
│                      │
│  跳过，稍后再说        │
└──────────────────────┘
```

**适用场景：** 需要账号才能使用的 App（如社交、云同步类）

> ⚠️ 如果 App 不强制需要账号，务必提供"跳过"选项。强制注册会大幅降低转化率。

### 6.4 混合型

组合以上多种类型，通常为：功能介绍 → 个性化设置 → 注册登录。

### 各类型适用场景对比表

| 类型 | 页数 | 完成率 | 适用 App 类型 | 优点 | 缺点 |
|------|------|--------|-------------|------|------|
| 功能介绍型 | 3-5 页 | 高（~80%） | 工具类、专业类 | 简单直接 | 信息可能被快速滑过 |
| 个性化设置型 | 2-3 页 | 中（~65%） | 健身、阅读、音乐 | 用户参与感强 | 需要更多开发工作 |
| 注册/登录型 | 1-2 页 | 低（~45%） | 社交、云同步类 | 获取用户信息 | 流失率高 |
| 混合型 | 4-7 页 | 中低（~55%） | 功能丰富的 App | 信息全面 | 太长导致用户放弃 |

> 💡 经验法则：引导页总步骤不超过 5 步。每多一步，完成率下降约 10-15%。

## 七、SwiftUI 引导页实现

### 7.1 基础结构：TabView 滑动引导

SwiftUI 的 `TabView` 配合 `.tabViewStyle(.page)` 可以轻松实现滑动引导页。

```swift
import SwiftUI

struct OnboardingView: View {
    @State private var currentPage = 0
    @AppStorage("hasCompletedOnboarding") private var hasCompletedOnboarding = false

    let pages = [
        OnboardingPage(
            icon: "target",
            title: "专注模式",
            subtitle: "用番茄钟帮你进入心流状态，屏蔽一切干扰",
            color: .blue
        ),
        OnboardingPage(
            icon: "chart.bar.fill",
            title: "数据统计",
            subtitle: "一目了然看到你的专注趋势，持续进步",
            color: .purple
        ),
        OnboardingPage(
            icon: "trophy.fill",
            title: "成就系统",
            subtitle: "每一次专注都值得被记录和奖励",
            color: .orange
        )
    ]

    var body: some View {
        if hasCompletedOnboarding {
            ContentView()
        } else {
            VStack(spacing: 0) {
                TabView(selection: $currentPage) {
                    ForEach(Array(pages.enumerated()), id: \.offset) { index, page in
                        OnboardingPageView(page: page)
                            .tag(index)
                    }
                }
                .tabViewStyle(PageTabViewStyle(indexDisplayMode: .never))

                OnboardingFooter(
                    currentPage: currentPage,
                    totalPages: pages.count,
                    onSkip: completeOnboarding,
                    onNext: nextPage,
                    onGetStarted: completeOnboarding
                )
                .padding(.horizontal, 24)
                .padding(.bottom, 20)
            }
        }
    }

    private func nextPage() {
        withAnimation {
            currentPage += 1
        }
    }

    private func completeOnboarding() {
        withAnimation {
            hasCompletedOnboarding = true
        }
    }
}
```

### 7.2 数据模型

```swift
}
```

### 7.4 分页指示器 + 按钮

```swift
struct OnboardingFooter: View {
    let currentPage: Int
    let totalPages: Int
    let onSkip: () -> Void
    let onNext: () -> Void
    let onGetStarted: () -> Void

    var isLastPage: Bool {
        currentPage == totalPages - 1
    }

    var body: some View {
        VStack(spacing: 20) {
            HStack(spacing: 8) {
                ForEach(0..<totalPages, id: \.self) { index in
                    Capsule()
                        .fill(index == currentPage ? Color.blue : Color.gray.opacity(0.3))
                        .frame(width: index == currentPage ? 20 : 8, height: 8)
                        .animation(.easeInOut(duration: 0.3), value: currentPage)
                }
            }

            HStack {
                if !isLastPage {
                    Button("跳过") {
                        onSkip()
                    }
                    .foregroundStyle(.secondary)
                }

                Spacer()

                Button(isLastPage ? "开始使用" : "下一步") {
                    if isLastPage {
                        onGetStarted()
                    } else {
                        onNext()
                    }
                }
                .fontWeight(.semibold)
                .padding(.horizontal, 32)
                .padding(.vertical, 14)
                .background(Color.blue)
                .foregroundStyle(.white)
                .clipShape(Capsule())
            }
        }
    }
}
```

### 7.5 首次启动判断

使用 `@AppStorage`（底层是 `UserDefaults`）来判断用户是否已完成引导：

```swift
@main
struct FocusTimerApp: App {
    @AppStorage("hasCompletedOnboarding") private var hasCompletedOnboarding = false

    var body: some Scene {
        WindowGroup {
            if hasCompletedOnboarding {
                ContentView()
            } else {
                OnboardingView()
            }
        }
    }
}
```

> 💡 `@AppStorage` 是 SwiftUI 对 `UserDefaults` 的封装，数据会持久保存。即使用户杀掉 App 再打开，也不会重新显示引导页。

**UserDefaults vs AppStorage 对比：**

| 特性 | UserDefaults | @AppStorage |
|------|-------------|-------------|
| 使用方式 | `UserDefaults.standard.set(true, forKey: "key")` | `@AppStorage("key") var value = false` |
| 数据同步 | 手动读取 | 自动同步到视图 |
| SwiftUI 集成 | 需要手动触发刷新 | 视图自动刷新 |
| 推荐场景 | 非 SwiftUI 代码 | SwiftUI 视图 |

> ⚠️ `@AppStorage` 存储的数据在卸载 App 后会清除。如果需要跨安装保留数据，应使用 iCloud Key-Value Store。

## 八、引导页与付费墙的衔接

### 8.1 转化漏斗

从引导页到付费订阅，是一个层层递进的漏斗：

```
        ┌──────────────┐
        │  下载 App     │  100%
        └──────┬───────┘
               │
        ┌──────▼───────┐
        │  完成引导页    │  ~70%
        └──────┬───────┘
               │
        ┌──────▼───────┐
        │  到达 Aha     │  ~50%
        │  Moment       │
        └──────┬───────┘
               │
        ┌──────▼───────┐
        │  触发付费墙    │  ~40%
        └──────┬───────┘
               │
        ┌──────▼───────┐
        │  开始免费试用  │  ~15%
        └──────┬───────┘
               │
        ┌──────▼───────┐
        │  转为付费用户  │  ~5%
        └──────────────┘
```

### 8.2 最佳展示时机

| 时机 | 策略 | 适用场景 |
|------|------|---------|
| 引导页中 | ❌ 不推荐 | — |
| 引导页结束后立即 | ⚠️ 谨慎使用 | 功能明确的工具类 App |
| 首次使用核心功能时 | ✅ 推荐 | 大多数 App |
| 用户主动点击锁定功能 | ✅✅ 最推荐 | 内容/功能类 App |
| 使用 3-5 次后 | ✅ 推荐 | 需要建立使用习惯的 App |

### 8.3 不要在引导页就展示付费墙

这就像相亲第一次见面就谈彩礼——太早了，对方还没了解你呢。

**为什么不要在引导页展示付费墙：**

1. **用户还没感受到价值**——没有体验就说"请付费"，转化率极低
2. **增加引导页流失率**——用户本来可能完成引导，看到付费墙直接卸载
3. **破坏第一印象**——用户觉得"这个 App 就是来圈钱的"

**正确的做法：**

```
引导页（展示价值）→ 免费体验核心功能 → 触发付费需求 → 展示付费墙（提供免费试用）
```

> 💡 让用户先"尝到甜头"，再"请客买单"。免费试用（Free Trial）是连接引导页和付费墙的最好桥梁——用户零成本体验 Pro 功能，7 天后自动续费。

## 九、落地页快速搭建

### 9.1 HTML 模板

以下是一个可直接修改使用的落地页模板：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
```

### 9.3 部署到 GitHub Pages

GitHub Pages 提供免费的静态网站托管，非常适合落地页。

```bash
# 1. 创建仓库
# 在 GitHub 上创建一个名为 landing-page 的仓库

# 2. 克隆到本地
git clone https://github.com/你的用户名/landing-page.git
cd landing-page

# 3. 添加落地页文件
cp ~/index.html .

# 4. 推送代码
git add .
git commit -m "Add landing page"
git push origin main

# 5. 开启 GitHub Pages
# 进入仓库 Settings → Pages → Source 选择 main 分支 → Save
# 访问地址：https://你的用户名.github.io/landing-page/
```

### 9.4 部署到 Vercel

Vercel 比 GitHub Pages 更快，且支持自动部署。

```bash
# 1. 安装 Vercel CLI
npm i -g vercel

# 2. 在落地页目录下执行
cd ~/landing-page
vercel

# 按提示操作，首次需要登录
# 部署完成后会获得一个 .vercel.app 域名
```

### 9.5 自定义域名

| 步骤 | 操作 |
|------|------|
| 1. 购买域名 | 在 Namesilo / Cloudflare / 阿里云购买（约 ¥30-60/年） |
| 2. 添加 DNS 记录 | 在域名管理后台添加 CNAME 记录指向你的托管地址 |
| 3. 配置托管平台 | 在 GitHub Pages / Vercel 设置中添加自定义域名 |

> 💡 推荐使用 Cloudflare 管理域名 DNS，免费提供 CDN 加速和 HTTPS。

## 十、数据追踪

没有数据追踪的落地页就像蒙着眼睛开车——你不知道方向对不对。

### 10.1 落地页访问量追踪

**方法一：Google Analytics（免费）**

```html
<!-- 在 <head> 中添加 -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXXXXX');
</script>
```

**方法二：Plausible（轻量、隐私友好）**

```html
<script defer data-domain="yourdomain.com" src="https://plausible.io/js/script.js"></script>
```

### 10.2 下载按钮点击率

追踪"下载"按钮的点击次数，计算点击率：

```
点击率 = 下载按钮点击次数 ÷ 落地页访问量 × 100%
```

```html
<!-- 给下载按钮添加点击事件 -->
<a href="https://apps.apple.com/app/idxxxxx"
   class="cta-button"
   onclick="gtag('event', 'click', {
     event_category: 'download',

</a>
```

> 💡 在 Hero 区域和页脚各放一个下载按钮，分别追踪点击率。通常 Hero 区域的按钮点击率更高。

### 10.3 引导页完成率

在 App 内追踪引导页各步骤的完成情况：

```swift
struct OnboardingView: View {
    @State private var currentPage = 0

    var body: some View {
        VStack {
            TabView(selection: $currentPage) {
                ForEach(0..<pages.count, id: \.self) { index in
                    OnboardingPageView(page: pages[index])
                        .tag(index)
                }
            }
            .onChange(of: currentPage) { _, newValue in
                Analytics.track("onboarding_page_viewed", properties: [
                    "page": newValue,
                    "total_pages": pages.count
                ])
            }
        }
    }

    private func completeOnboarding() {
        Analytics.track("onboarding_completed", properties: [
            "total_pages": pages.count
        ])
        hasCompletedOnboarding = true
    }
}
```

### 10.4 各步骤流失分析

| 指标 | 计算方式 | 健康值 | 说明 |
|------|---------|--------|------|
| 引导页开始率 | 打开引导页 ÷ 首次启动 | > 95% | 几乎所有新用户应看到引导页 |
| 页面间流失率 | 下一页查看 ÷ 当前页查看 | < 15% | 每页流失不超过 15% |
| 引导页完成率 | 完成引导 ÷ 开始引导 | > 70% | 低于 60% 说明引导页太长或太无聊 |
| 跳过率 | 点击跳过 ÷ 开始引导 | < 20% | 过高说明引导页不够吸引人 |
| 引导页→注册转化 | 完成注册 ÷ 完成引导 | > 40% | 取决于注册是否必须 |

**流失分析示例：**

```
首次启动：1000 人
  ├─ 引导页第 1 页：980 人（流失 2%）
  ├─ 引导页第 2 页：880 人（流失 10%）← 这里有问题
  ├─ 引导页第 3 页：810 人（流失 8%）
  └─ 完成引导：760 人（总完成率 76%）
       ├─ 注册/登录：320 人（42%）
       └─ 跳过注册：440 人（58%）
```

> ⚠️ 如果某一页的流失率突然升高（比如第 2 页流失 10%），说明该页的内容或设计有问题，需要优化。

## 小结

| 知识点 | 核心要点 |
|--------|---------|
| 落地页 | App 的线上名片，唯一目标是让访客下载 App |
| 落地页 vs App Store | 互补关系：落地页引流说服，App Store 完成转化 |
| 落地页必备元素 | Hero + 功能展示 + 社会证明 + FAQ + 页脚 |
| 落地页设计原则 | 一屏一信息、移动端优先、CTA 醒目、加载 < 3 秒 |
| 引导页 | 首次打开 App 的引导流程，帮用户快速理解价值 |
| 引导页类型 | 功能介绍型、个性化设置型、注册登录型、混合型 |
| SwiftUI 实现 | TabView + PageTabViewStyle + @AppStorage |
| 引导页与付费墙 | 先让用户体验价值，再展示付费墙，不要在引导页就收费 |
| 落地页搭建 | HTML 模板 / AI 生成 → GitHub Pages / Vercel 部署 |
| 数据追踪 | 访问量、点击率、完成率、流失率——用数据驱动优化 |

> 💡 记住这个公式：**好的落地页让用户来，好的引导页让用户留，好的付费墙让用户付费。** 三者环环相扣，缺一不可。
