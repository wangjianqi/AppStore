## 付费下载定价策略

> 🎯 **本节目标**：理解定价心理学原理，学会价格测试和促销策略，让你的 App 定价既合理又有吸引力。

### 定价心理学

定价不是随便填个数字，背后有一套成熟的心理学原理。了解这些，能让你的定价更"值钱"。

#### 尾数定价（.99）

你可能注意过，超市里商品价格很少是整数，基本都是 9.99、19.99 这样的"尾数价"。这不是巧合，而是经过大量验证的定价技巧：

| 定价方式 | 用户感知 | 示例 |
|----------|---------|------|
| **整数定价** | 感觉"贵"，会仔细考虑 | ¥18.00 |
| **尾数定价** | 感觉"划算"，冲动消费 | ¥17.99 |

> 💡 **提示**：App Store 的价格层级本身就是按 .99 设计的（如 $0.99、$1.99、$2.99），所以你不需要手动设置尾数，选择对应的价格层级即可。

#### 锚定效应

锚定效应是指：用户对价格的判断会受到"第一个看到的价格"的影响。

```text
场景示例：
你先展示"专业版 ¥198/年"
再展示"基础版 ¥68/年"
用户会觉得基础版"很划算"

反过来，如果只展示"基础版 ¥68/年"
用户可能会觉得"有点贵"
```

> 💡 **提示**：在订阅层级设计中，先展示高价方案，再展示低价方案，能让低价方案看起来更有吸引力。这就是锚定效应的典型应用。

#### 价格敏感度

不同类型的 App，用户对价格的接受程度差异很大：

| App 类型 | 用户可接受价格范围 | 说明 |
|----------|-------------------|------|
| **工具类** | ¥6 - ¥25 | 用户期望不高，价格敏感 |
| **效率类** | ¥12 - ¥68 | 愿意为提升效率付费 |
| **创意类** | ¥18 - ¥98 | 专业用户愿意付更多 |
| **游戏类** | 免费 - ¥6 | 付费下载游戏很难卖，多数走 IAP |
| **教育类** | ¥12 - ¥68 | 家长愿意为教育投资 |

#### 示例

```text
假设你做了一款 Markdown 编辑器：

❌ 定价 ¥99 → 大部分用户觉得太贵，直接划走
✅ 定价 ¥25 → 用户觉得"试试也行"，下载转化率高
💡 更好的方案：免费下载 + ¥25 解锁高级功能（降低门槛，先让用户体验）
```

### 价格测试

定价不是一锤子买卖，你可以通过测试找到最优价格。

#### A/B 测试定价

A/B 测试定价就是让不同用户看到不同价格，比较哪个价格带来的总收入更高：

| 测试组 | 价格 | 下载量 | 总收入 |
|--------|------|--------|--------|
| A 组 | ¥12 | 1000 | ¥12,000 |
| B 组 | ¥18 | 700 | ¥12,600 |

> ⚠️ **警告**：App Store 不支持直接对不同用户展示不同价格。你可以通过"限时调整价格"来间接测试——先定价 ¥12 观察一周，再调到 ¥18 观察一周，对比数据。

#### 促销定价

促销定价是在原价基础上临时降价，制造"占便宜"的感觉：

```text
原价 ¥25 → 促销价 ¥12
用户心理："现在买省了一半，不买就亏了"
```

#### 限时优惠

限时优惠的核心是**紧迫感**——用户知道优惠会结束，所以更愿意现在就行动：

| 优惠类型 | 时间范围 | 适用场景 |
|----------|---------|---------|
| 首发优惠 | 上线后 7-14 天 | 新 App 上线 |
| 节日促销 | 3-7 天 | 春节、双11、圣诞节 |
| 版本更新优惠 | 3-5 天 | 大版本更新 |
| 周年庆优惠 | 5-7 天 | App 上线周年 |

### 促销策略

#### 首发优惠

新 App 上线时，用首发优惠吸引第一批用户：

```text
策略：
- 上线首周定价 ¥6（原价 ¥25）
- 在 App 描述中标注"首发优惠，限时 ¥6"
- 通过社交媒体宣传首发优惠

效果：
- 降低用户尝试门槛
- 快速积累初始下载量和评分
- 优惠结束后恢复原价
```

#### 节日促销

利用节日氛围做促销，用户在节日期间消费意愿更强：

| 节日 | 促销建议 | 折扣力度 |
|------|---------|---------|
| 春节 | "新年新气象"主题 | 5-7 折 |
| 618/双11 | "年度最低价" | 3-5 折 |
| 圣诞节 | "圣诞特惠" | 5-7 折 |
| 开学季 | "开学必备" | 6-8 折 |
| 情人节 | "送给 TA" | 7-8 折 |

#### 版本更新优惠

每次大版本更新都是一次促销机会：

```text
策略：
- 发布 2.0 大版本时，限时优惠 3 天
- 在更新日志中说明优惠信息
- 通过推送通知告知老用户

好处：
- 吸引新用户下载
- 唤醒老用户回流
- 提升版本更新的关注度
```

> 📌 **本节小结**：定价是门学问——尾数定价让价格"看起来便宜"，锚定效应让低价方案"感觉划算"，促销策略制造紧迫感促使用户下单。定价不是一成不变的，持续测试和调整才能找到最优价格。

## 应用内购买（IAP）接入全流程

> 🎯 **本节目标**：理解 IAP 的各种类型，掌握 StoreKit 2 的完整接入流程，包括产品查询、购买、验证和恢复购买，学会在 App Store Connect 中配置 IAP 产品。

### IAP 类型

App Store 提供了 4 种应用内购买类型，每种适用于不同场景：

| IAP 类型 | 说明 | 典型用途 | 可重复购买 | 示例 |
|----------|------|---------|-----------|------|
| **消耗型** | 用完即消失，可再次购买 | 游戏币、道具、积分 | ✅ 可以 | 游戏中 100 金币 ¥6 |
| **非消耗型** | 一次购买永久拥有 | 去广告、解锁功能 | ❌ 不可以 | 去广告 ¥12 |
| **自动续期订阅** | 周期性自动扣费 | 会员、VIP | 自动续费 | 月度会员 ¥18/月 |
| **非续期订阅** | 期限到期不自动续费 | 季度会员、年度服务 | 手动续费 | 3 个月课程 ¥68 |

> 💡 **提示**：如果你不确定选哪种类型，问自己一个问题——"用户买完之后，这个商品会消失吗？"会消失→消耗型；不会消失→非消耗型；按周期收费→订阅型。

### StoreKit 2 接入

StoreKit 2 是苹果在 iOS 15 推出的全新 IAP 框架，使用 Swift 原生 async/await 语法，比旧版 StoreKit 简单很多。

> ⚠️ **警告**：StoreKit 2 需要 iOS 15+。如果你的 App 需要支持 iOS 14 及以下，仍需使用旧版 StoreKit（本节以 StoreKit 2 为例）。

#### 导入 StoreKit

在 Swift 文件中导入 StoreKit 框架：

```swift
import StoreKit
```

#### 产品查询

在展示购买界面之前，你需要先从 App Store 查询可购买的产品信息：

```swift
import StoreKit

class StoreManager: ObservableObject {
    @Published var products: [Product] = []

    func loadProducts() async {
        do {
            let storeProducts = try await Product.products(for: [
                "com.yourapp.premium",
                "com.yourapp.removeads",
                "com.yourapp.monthlysub"
            ])
            products = storeProducts
        } catch {
            print("产品查询失败: \(error)")
        }
    }
}
```

#### 购买流程

用户点击购买按钮后，调用 `purchase()` 方法发起购买：

```swift
func purchase(_ product: Product) async -> Bool {
    do {
        let result = try await product.purchase()

        switch result {
        case .success(let verification):
            let transaction = try checkVerified(verification)
            await transaction.finish()
            return true

        case .userCancelled:
            print("用户取消购买")
            return false

        case .pending:
            print("购买待处理（需要家长批准等）")
            return false

        @unknown default:
            return false
        }
    } catch {
        print("购买失败: \(error)")
        return false
    }
}
```

#### 交易验证

每次购买完成后，必须验证交易是否合法，防止伪造购买：

```swift
func checkVerified<T>(_ result: VerificationResult<T>) throws -> T {
    switch result {
    case .unverified:
        throw StoreError.failedVerification
    case .verified(let safe):
        return safe
    }
}

enum StoreError: Error {
    case failedVerification
}
```

#### 完整代码示例

下面是一个完整的 StoreKit 2 商品列表和购买界面：

```swift
import SwiftUI
import StoreKit

class StoreManager: ObservableObject {
    @Published var products: [Product] = []
    @Published var purchasedProductIDs: Set<String> = []
    @Published var purchaseError: String?

    private let productIDs = [
        "com.yourapp.premium",
        "com.yourapp.removeads"
    ]

    func loadProducts() async {
        do {
            products = try await Product.products(for: productIDs)
        } catch {
            purchaseError = "加载商品失败: \(error.localizedDescription)"
        }
    }

    func purchase(_ product: Product) async -> Bool {
        do {
            let result = try await product.purchase()
            switch result {
            case .success(let verification):
                let transaction = try checkVerified(verification)
                purchasedProductIDs.insert(transaction.productID)
                await transaction.finish()
                return true
            case .userCancelled:
                return false
            case .pending:
                return false
            @unknown default:
                return false
            }
        } catch {
            purchaseError = "购买失败: \(error.localizedDescription)"
            return false
        }
    }

    func checkVerified<T>(_ result: VerificationResult<T>) throws -> T {
        switch result {
        case .unverified:
            throw StoreError.failedVerification
        case .verified(let safe):
            return safe
        }
    }

    func updatePurchasedProducts() async {
        for await result in Transaction.currentEntitlements {
            if case .verified(let transaction) = result {
                purchasedProductIDs.insert(transaction.productID)
            }
        }
    }
}

struct StoreView: View {
    @StateObject private var storeManager = StoreManager()

    var body: some View {
        List(storeManager.products) { product in
            HStack {
                VStack(alignment: .leading, spacing: 4) {
                    Text(product.displayName)
                        .font(.headline)
                    Text(product.description)
                        .font(.subheadline)
                        .foregroundColor(.secondary)
                }

                Spacer()

                if storeManager.purchasedProductIDs.contains(product.id) {
                    Text("已购买")
                        .foregroundColor(.green)
                        .fontWeight(.medium)
                } else {
                    Button {
                        Task {
                            _ = await storeManager.purchase(product)
                        }
                    } label: {
                        Text(product.displayPrice)
                            .fontWeight(.semibold)
                            .padding(.horizontal, 16)
                            .padding(.vertical, 8)
                            .background(Color.blue)
                            .foregroundColor(.white)
                            .cornerRadius(8)
                    }
                }
            }
            .padding(.vertical, 4)
        }
        .navigationTitle("商店")
        .task {
            await storeManager.loadProducts()
            await storeManager.updatePurchasedProducts()
        }
        .alert("提示", isPresented: .constant(storeManager.purchaseError != nil)) {
            Button("确定") {
                storeManager.purchaseError = nil
            }
        } message: {
            Text(storeManager.purchaseError ?? "")
        }
    }
}
```

> 💡 **提示**：在 Xcode 中调试 IAP 时，需要创建 StoreKit Configuration File（File → New → File → StoreKit Configuration File），这样可以在模拟器中测试购买流程，不需要真机。

### 订阅 vs 一次性购买

| 对比维度 | 一次性购买 | 自动续期订阅 |
|----------|-----------|-------------|
| **收入模式** | 一次性收入 | 持续性收入 |
| **用户心理门槛** | 较高（一次性付大额） | 较低（每月付小额） |
| **LTV（用户终身价值）** | 固定 | 持续增长 |
| **收入可预测性** | 低 | 高 |
| **用户维护成本** | 低 | 高（需要持续提供价值） |
| **流失风险** | 无（已付费） | 有（随时可能取消） |
| **适用场景** | 工具类、游戏 | 内容类、服务类 |
| **典型价格** | ¥18 - ¥68 | ¥6 - ¥30/月 |

**选择建议**：

- 你的 App 内容会**持续更新**（如新闻、课程、云存储）→ 选**订阅**
- 你的 App 功能**基本固定**（如计算器、格式转换器）→ 选**一次性购买**
- 你的 App 有**基础功能 + 高级功能**→ 选**免费 + IAP 解锁**

> 💡 **提示**：行业趋势是订阅模式越来越流行。苹果在 2023 年的数据显示，订阅收入占 App Store 总收入的比例已超过 50%。但订阅模式要求你持续为用户提供价值，否则用户会取消。

### 服务器验证

#### 为什么需要服务器验证

StoreKit 2 虽然在客户端做了验证，但在以下场景中，你还需要服务器端验证：

| 场景 | 为什么需要服务器验证 |
|------|---------------------|
| **防破解** | 越狱设备可能绕过客户端验证 |
| **多设备同步** | 用户换设备后需要验证购买状态 |
| **订阅状态查询** | 需要实时知道订阅是否有效 |
| **数据分析** | 在服务器端记录和分析购买数据 |
| **退款处理** | 苹果退款通知发送到服务器 |

#### 验证流程

```text
用户购买成功
    ↓
App 收到交易凭证
    ↓
App 将凭证发送到你的服务器
    ↓
你的服务器调用 App Store Server API 验证
    ↓
验证通过 → 解锁功能 / 验证失败 → 拒绝
```

#### App Store Server API

苹果提供了 App Store Server API，让你的服务器可以验证交易和管理订阅：

```text
主要 API 端点：
- GET /inApps/v1/transactions/{transactionId}  → 查询交易信息
- GET /inApps/v1/subscriptions/{transactionId}  → 查询订阅状态
- POST /inApps/v1/notifications/test            → 测试通知
```

#### 示例

服务器端验证的简化流程（以 Node.js 为例）：

```javascript
const jwt = require("jsonwebtoken");

async function verifyTransaction(signedTransaction) {
    // 1. 解码 JWT 获取交易信息
    const decoded = jwt.decode(signedTransaction, { complete: true });

    // 2. 从苹果服务器获取公钥验证签名
    // （实际项目中需要缓存苹果的公钥）
    const applePublicKey = await getApplePublicKey(decoded.header.kid);

    // 3. 验证签名
    const payload = jwt.verify(signedTransaction, applePublicKey, {
        algorithms: ["ES256"],
    });

    // 4. 检查交易是否有效
    if (payload.bundleId !== "com.yourapp.bundleid") {
        throw new Error("Bundle ID 不匹配");
    }

    return payload;
}
```

> ⚠️ **警告**：服务器验证涉及 JWT 签名验证和苹果公钥管理，实现较为复杂。建议使用苹果官方提供的 [App Store Server Library](https://github.com/apple/app-store-server-library-node)，而不是自己从头实现。

### 恢复购买

#### 为什么需要恢复购买

用户换了新设备、卸载重装 App 后，之前购买的非消耗型和订阅内容需要恢复。苹果**强制要求**所有提供非消耗型 IAP 的 App 必须提供恢复购买功能。

> ⚠️ **警告**：如果你的 App 有非消耗型 IAP 或订阅，但没有提供"恢复购买"按钮，苹果审核可能会被拒！

#### 实现方法

StoreKit 2 中，恢复购买非常简单：

```swift
func restorePurchases() async {
    do {
        try await AppStore.sync()
        await updatePurchasedProducts()
    } catch {
        purchaseError = "恢复购买失败: \(error.localizedDescription)"
    }
}
```

#### 代码示例

在购买界面添加一个"恢复购买"按钮：

```swift
struct StoreView: View {
    @StateObject private var storeManager = StoreManager()
    @State private var isRestoring = false

    var body: some View {
        List {
            Section {
                ForEach(storeManager.products) { product in
                    ProductRow(product: product, storeManager: storeManager)
                }
            }

            Section {
                Button {
                    isRestoring = true
                    Task {
                        await storeManager.restorePurchases()
                        isRestoring = false
                    }
                } label: {
                    HStack {
                        Spacer()
                        if isRestoring {
                            ProgressView()
                        } else {
                            Text("恢复购买")
                        }
                        Spacer()
                    }
                }
                .disabled(isRestoring)
            }
        }
        .navigationTitle("商店")
        .task {
            await storeManager.loadProducts()
            await storeManager.updatePurchasedProducts()
        }
    }
}
```

### App Store Connect 配置

在代码中接入 IAP 之前，你需要先在 App Store Connect 中创建和配置 IAP 产品。

#### 创建 IAP 产品

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 登录 App Store Connect | https://appstoreconnect.apple.com |
| 2 | 选择你的 App | 在"我的 App"中点击对应 App |
| 3 | 进入"App 内购买项目" | 在左侧菜单中找到 |
| 4 | 点击"+"创建新 IAP | 选择 IAP 类型 |
| 5 | 填写产品信息 | 参考名称、产品 ID、价格 |
| 6 | 提交审核 | 填写审核信息和截图 |

#### 配置价格

```text
价格配置步骤：
1. 在 IAP 产品页面点击"价格与销售范围"
2. 选择基准价格（如 $0.99）
3. 苹果会自动生成各国对应价格
4. 你也可以手动调整特定国家的价格
5. 保存后价格立即生效
```

> 💡 **提示**：产品 ID（如 `com.yourapp.premium`）一旦创建就**不能修改**，也不能删除后重新使用。所以命名时要谨慎，建议用有意义的命名规则。

#### 配置订阅组

如果你有多个订阅产品，需要将它们放入同一个订阅组：

```text
订阅组配置步骤：
1. 在 App Store Connect 中进入"订阅"
2. 点击"创建订阅组"
3. 填写组参考名称（如"会员订阅"）
4. 在组内添加多个订阅产品
5. 用户在同一组内只能有一个有效订阅

示例：
订阅组"会员订阅"
├── 月度会员 ¥18/月
├── 年度会员 ¥128/年
└── 终身会员 ¥298（一次性）
```

> 💡 **提示**：同一订阅组内的产品，用户可以自由升级或降级。比如从月度会员升级到年度会员，苹果会自动处理差价和续费逻辑。

> 📌 **本节小结**：IAP 是 App 变现的核心方式。掌握 4 种 IAP 类型的区别，使用 StoreKit 2 完成产品查询、购买、验证和恢复购买的全流程，并在 App Store Connect 中正确配置产品。服务器验证是安全的重要保障，恢复购买是苹果的强制要求。

## 订阅模式设计

> 🎯 **本节目标**：学会设计合理的订阅层级、免费试用策略和定价技巧，掌握订阅留存优化方法，让你的订阅收入持续增长。

### 自动续期订阅

自动续期订阅是目前最主流的变现模式之一。用户订阅后，系统会自动在每个计费周期扣费，直到用户主动取消。

#### 订阅类型

| 订阅周期 | 适用场景 | 典型价格 | 说明 |
|----------|---------|---------|------|
| **周订阅** | 短期需求、高频使用 | ¥3 - ¥12/周 | 容易让用户觉得"便宜"，但年化价格高 |
| **月订阅** | 最常见 | ¥6 - ¥30/月 | 平衡了用户接受度和收入 |
| **年订阅** | 长期用户 | ¥48 - ¥198/年 | 用户粘性高，但一次性支出大 |

> ⚠️ **警告**：周订阅虽然看起来单价低，但年化价格往往很高（如 ¥6/周 = ¥312/年），容易引发用户投诉和差评。建议谨慎使用，或同时提供月/年选项让用户选择。

#### 订阅组

订阅组是苹果管理多个订阅产品的方式：

```text
订阅组的规则：
- 同一组内的订阅互斥（用户只能有一个有效订阅）
- 用户可以在组内升级或降级
- 升级立即生效，降级在当前周期结束后生效
- 苹果自动处理差价退款

示例：
订阅组"Pro 会员"
├── 基础版 ¥12/月
├── 高级版 ¥25/月
└── 专业版 ¥48/月
```

#### 免费试用

免费试用是让用户体验付费功能的有效手段：

| 试用类型 | 说明 | 适用场景 |
|----------|------|---------|
| **免费试用** | 一定天数内免费使用 | 新用户首次订阅 |
| **介绍性优惠** | 首期折扣价 | 吸引犹豫的用户 |
| **促销优惠** | 特定折扣码 | 召回流失用户 |

#### 介绍性优惠

介绍性优惠有 3 种类型：

| 优惠类型 | 说明 | 示例 |
|----------|------|------|
| **免费试用** | 首个周期免费 | 前 7 天免费，之后 ¥18/月 |
| **首期折扣** | 首个周期折扣价 | 首月 ¥6，之后 ¥18/月 |
| **首期付费** | 首个周期固定价 | 前 3 个月 ¥6/月，之后 ¥18/月 |

#### 促销优惠

促销优惠是通过优惠码给特定用户折扣：

```text
促销优惠使用场景：
- 召回已取消订阅的用户
- 给老用户专属折扣
- 媒体评测和推广合作
- 特定活动优惠

配置方式：
1. 在 App Store Connect 中创建促销优惠
2. 设置优惠类型和折扣
3. 生成优惠码
4. 用户在 App 中输入优惠码享受折扣
```

### 订阅层级设计

合理的订阅层级能让不同需求的用户都找到适合自己的方案。

#### 基础版/高级版/专业版

| 层级 | 定位 | 典型功能 | 典型价格 |
|------|------|---------|---------|
| **免费版** | 吸引用户 | 基础功能，有广告 | ¥0 |
| **基础版** | 入门付费 | 去广告 + 基础高级功能 | ¥12/月 |
| **高级版** | 主力方案 | 全部功能 + 云同步 | ¥25/月 |
| **专业版** | 高端用户 | 高级版 + API + 优先支持 | ¥48/月 |

#### 功能差异化

设计订阅层级时，功能差异化要遵循以下原则：

```text
原则一：免费版要有足够价值
- 用户不付费也能完成核心任务
- 免费版不是"残废版"，而是"基础版"

原则二：付费功能要有明确感知
- 用户能清楚感受到付费带来的提升
- 不要做"暗戳戳"的付费墙

原则三：层级之间差距要明显
- 基础版和高级版的功能差异要一目了然
- 不要让用户觉得"高级版也没多什么"
```

#### 定价策略

```text
常见的订阅层级定价比例：

两层方案：
- 基础版 ¥12/月 + 专业版 ¥25/月（约 2:1 比例）

三层方案：
- 基础版 ¥12/月 + 高级版 ¥25/月 + 专业版 ¥48/月
  （大多数用户会选择中间的高级版——这就是"中间选项效应"）

💡 关键技巧：中间选项往往是你的目标价位
  - 用户会自动排除最便宜和最贵的
  - 中间选项看起来"最合理"
```

#### 示例

以一款云笔记 App 为例：

| 功能 | 免费版 | 基础版 ¥12/月 | 专业版 ¥25/月 |
|------|--------|--------------|--------------|
| 笔记数量 | 50 条 | 无限 | 无限 |
| 云同步 | ❌ | ✅ | ✅ |
| 存储空间 | - | 5GB | 50GB |
| Markdown | ❌ | ✅ | ✅ |
| 协作编辑 | ❌ | ❌ | ✅ |
| 版本历史 | ❌ | 7 天 | 无限 |
| 导出格式 | 纯文本 | PDF/Markdown | 全格式 |
| 优先支持 | ❌ | ❌ | ✅ |

### 免费试用策略

免费试用是提高订阅转化率的关键手段。

#### 3天/7天/14天/30天

| 试用时长 | 转化率（行业平均） | 适用场景 | 优缺点 |
|----------|-------------------|---------|--------|
| **3 天** | 20-30% | 功能简单、上手快 | 试用时间短，用户可能来不及体验核心价值 |
| **7 天** | 30-40% | 最常见，适合大多数 App | 平衡了体验时间和转化率 |
| **14 天** | 35-45% | 功能复杂、需要时间学习 | 用户有足够时间体验，但遗忘率也高 |
| **30 天** | 25-35% | 高价值产品、企业级 | 试用时间太长，用户可能忘记取消 |

#### 试用转付费率

```text
影响试用转付费率的关键因素：
1. 用户在试用期内是否体验到了核心价值 → 入职引导很重要
2. 试用结束前的提醒 → 提前 1-2 天通知用户
3. 产品的持续价值 → 用户觉得"离不开"就会付费
4. 定价是否合理 → 太贵会劝退，太便宜会怀疑质量
```

#### 选择建议

> 💡 **提示**：对于大多数 App，**7 天免费试用**是最佳选择。原因如下：
> - 足够让用户体验核心功能
> - 不会太长导致用户遗忘
> - 是苹果默认推荐的试用时长
> - 行业数据表明 7 天试用的转化率最稳定

### 订阅定价技巧

#### 锚定定价

在展示订阅选项时，利用锚定效应引导用户选择你期望的方案：

```text
示例：月订阅 vs 年订阅

❌ 只展示月订阅：
   月度会员 ¥18/月

✅ 同时展示月订阅和年订阅：
   月度会员 ¥18/月
   年度会员 ¥128/年（相当于 ¥10.7/月，省 40%）

💡 年订阅旁边标注"每月仅 ¥10.7"和"省 40%"
   用户会觉得年订阅"太划算了"
```

#### 年度优惠

| 定价方式 | 月价 | 年价 | 年化节省 | 用户感知 |
|----------|------|------|---------|---------|
| 无年度优惠 | ¥18/月 | ¥216/年 | 0% | 没有吸引力 |
| 小幅优惠 | ¥18/月 | ¥178/年 | 18% | 还行 |
| 中幅优惠 | ¥18/月 | ¥128/年 | 41% | 很划算！ |
| 大幅优惠 | ¥18/月 | ¥98/年 | 55% | 超值！但利润低 |

> 💡 **提示**：年度优惠 30-40% 是行业最佳平衡点。既能让用户觉得划算，又不会大幅降低收入。同时，年订阅的用户流失率远低于月订阅。

#### 对比表

| 策略 | 说明 | 效果 | 适用场景 |
|------|------|------|---------|
| **锚定定价** | 先展示高价方案 | 低价方案看起来更划算 | 多层级订阅 |
| **年度优惠** | 年付比月付便宜 30-40% | 提高年付比例，降低流失 | 所有订阅 App |
| **首月折扣** | 首月低价 | 降低尝试门槛 | 新 App |
| **免费试用** | 首个周期免费 | 提高转化率 | 功能体验型 App |
| **学生优惠** | 学生半价 | 扩大用户群 | 教育/工具类 App |

### 订阅留存优化

用户订阅只是开始，让他们持续续费才是关键。

#### 入职引导

新用户订阅后的前 7 天是决定续费的关键期：

```text
入职引导策略：
Day 1：欢迎 + 核心功能介绍
Day 2：引导完成第一个任务
Day 3：展示高级功能
Day 5：分享使用技巧
Day 6：提醒试用期即将结束
Day 7：试用到期，引导续费
```

#### 价值提醒

定期让用户感受到订阅的价值：

| 提醒方式 | 频率 | 示例 |
|----------|------|------|
| **使用报告** | 每周/每月 | "本周你用 Pro 功能节省了 2 小时" |
| **成就通知** | 触发时 | "你已完成 100 次同步！" |
| **新功能通知** | 有更新时 | "Pro 会员专属：新增 AI 助手功能" |
| **续费提醒** | 到期前 3-5 天 | "你的会员将在 3 天后续费" |

#### 流失挽回

用户取消订阅时，不要轻易放弃：

```text
挽回策略：
1. 取消前弹出挽留页面
   - 询问取消原因
   - 提供折扣优惠
   - 提供降级选项

2. 取消后发送邮件
   - 确认取消（保留到当前周期结束）
   - 提供限时回归优惠

3. 流失后定期召回
   - 30 天后发送召回邮件
   - 提供专属回归折扣
```

#### 策略表

| 策略 | 实施难度 | 效果 | 适用阶段 |
|------|---------|------|---------|
| **入职引导** | ⭐⭐ | ⭐⭐⭐⭐ | 新用户期 |
| **价值提醒** | ⭐⭐ | ⭐⭐⭐ | 持续使用期 |
| **续费提醒** | ⭐ | ⭐⭐⭐ | 即将续费期 |
| **取消挽留** | ⭐⭐⭐ | ⭐⭐⭐⭐ | 取消时 |
| **流失召回** | ⭐⭐ | ⭐⭐ | 流失后 |
| **新功能推送** | ⭐⭐ | ⭐⭐⭐ | 版本更新时 |

> 📌 **本节小结**：订阅模式设计的核心是——让用户感受到持续的价值。合理设计订阅层级，利用免费试用降低门槛，用锚定定价引导用户选择年订阅，通过入职引导和价值提醒提高留存率。

## 广告变现

> 🎯 **本节目标**：了解主流广告平台（AdMob、穿山甲），掌握不同广告位的设计要点，学会在广告收入和用户体验之间找到平衡。

### AdMob 接入

AdMob 是 Google 旗下的移动广告平台，是全球最大的移动广告网络之一，适合面向海外市场的 App。

#### 注册 AdMob

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 访问 https://admob.google.com | 使用 Google 账号登录 |
| 2 | 创建 AdMob 账号 | 填写付款信息 |
| 3 | 添加你的 App | 输入 App Store ID |
| 4 | 等待审核 | 通常 1-3 个工作日 |

#### 创建广告位

```text
广告位创建步骤：
1. 在 AdMob 控制台点击"广告位"
2. 选择广告类型（Banner/插屏/激励视频/原生）
3. 命名广告位
4. 获取广告单元 ID（格式：ca-app-pub-XXXXX/YYYYY）
5. 将广告单元 ID 填入代码中
```

#### 集成 SDK

在 Xcode 项目中集成 AdMob SDK：

```text
方式一：Swift Package Manager（推荐）
1. File → Add Package Dependencies
2. 输入 https://github.com/googleads/swift-package-manager-google-mobile-ads
3. 选择版本并添加

方式二：CocoaPods
1. 在 Podfile 中添加：pod 'Google-Mobile-Ads-SDK'
2. 运行 pod install
```

#### 代码示例

展示一个 Banner 广告的完整代码：

```swift
import SwiftUI
import GoogleMobileAds

struct BannerAdView: UIViewRepresentable {
    let adUnitID: String

    func makeUIView(context: Context) -> GADBannerView {
        let banner = GADBannerView(adSize: GADAdSizeBanner)
        banner.adUnitID = adUnitID
        banner.rootViewController = UIApplication.shared.connectedScenes
            .compactMap { ($0 as? UIWindowScene)?.keyWindow?.rootViewController }
            .first
        banner.load(GADRequest())
        return banner
    }

    func updateUIView(_ uiView: GADBannerView, context: Context) {}
}

struct AdExampleView: View {
    var body: some View {
        VStack {
            Text("主要内容区域")
                .frame(maxWidth: .infinity, maxHeight: .infinity)

            BannerAdView(adUnitID: "ca-app-pub-3940256099942544/2934735716")
                .frame(height: 50)
        }
    }
}
```

> 💡 **提示**：上面的广告单元 ID `ca-app-pub-3940256099942544/2934735716` 是 Google 提供的测试广告 ID。开发阶段务必使用测试广告，使用真实广告点击会被判定为无效点击，可能导致账号被封。

### 广告位设计

选择合适的广告位类型，直接影响广告收入和用户体验。

#### 开屏广告

```text
特点：
- App 启动时展示，3-5 秒后自动关闭
- 全屏展示，视觉冲击力强
- eCPM 较高

适用场景：
- App 启动时
- 每天首次启动展示一次
```

#### 插屏广告

```text
特点：
- 在页面切换时全屏展示
- 需要用户手动关闭
- eCPM 高，但打扰性强

适用场景：
- 关卡结束后（游戏）
- 完成一个任务后
- 切换主要功能页面时
```

#### 激励视频广告

```text
特点：
- 用户主动选择观看
- 看完获得奖励（游戏币、道具、功能等）
- eCPM 最高，用户接受度也最高
- 双赢模式：用户得奖励，你赚广告费

适用场景：
- 获取游戏币/道具
- 解锁付费功能（免费用户）
- 获得额外使用次数
- 去广告一段时间
```

#### Banner 广告

```text
特点：
- 固定在页面顶部或底部
- 占用屏幕空间小
- eCPM 最低

适用场景：
- 页面底部常驻
- 不影响主要操作的区域
```

#### 原生广告

```text
特点：
- 与 App 界面风格融合
- 用户感知度低（看起来像内容）
- eCPM 中等
- 开发成本较高

适用场景：
- 信息流中插入
- 列表页中混入
```

| 广告类型 | eCPM | 用户体验 | 展示频率 | 开发难度 | 推荐指数 |
|----------|------|---------|---------|---------|---------|
| **开屏广告** | ⭐⭐⭐⭐ | ⭐⭐⭐ | 每天 1 次 | ⭐⭐ | ⭐⭐⭐⭐ |
| **插屏广告** | ⭐⭐⭐⭐ | ⭐⭐ | 每 3-5 分钟 | ⭐⭐ | ⭐⭐⭐ |
| **激励视频** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 用户主动触发 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| **Banner** | ⭐⭐ | ⭐⭐⭐ | 常驻 | ⭐ | ⭐⭐ |
| **原生广告** | ⭐⭐⭐ | ⭐⭐⭐⭐ | 混入内容 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |

### 广告与用户体验平衡

广告是收入来源，但过度广告会赶走用户。找到平衡点至关重要。

#### 不要过度展示广告

```text
❌ 错误做法：
- 每次操作都弹插屏广告
- 页面上半部分都是广告
- 广告比内容还多
- 用户无法关闭广告

✅ 正确做法：
- 开屏广告每天最多 1 次
- 插屏广告间隔至少 3-5 分钟
- Banner 广告放在底部，不遮挡内容
- 广告必须有明显的关闭按钮
```

#### 激励视频用户接受度高

激励视频是目前最推荐的广告形式，因为：

```text
用户视角：
- "我选择看广告，看完获得奖励" → 主动选择，不反感
- "看 30 秒广告获得 50 金币" → 等价交换，公平

开发者视角：
- eCPM 最高 → 同样展示次数，收入更多
- 用户不反感 → 不会因为广告流失
- 用户更活跃 → 为了奖励更频繁使用 App
```

#### 付费去广告选项

提供"付费去广告"选项是最佳实践：

```text
方案：
- 免费用户：看广告
- ¥12 去广告：永久去除所有广告
- ¥18/月 Pro：去广告 + 高级功能

好处：
1. 不喜欢广告的用户可以付费去除
2. 增加一个 IAP 收入来源
3. 用户觉得"有选择"，不会因为广告给差评
4. 部分免费用户最终会转为付费用户
```

#### 建议

| 建议 | 说明 | 优先级 |
|------|------|--------|
| **激励视频优先** | eCPM 高、用户接受度高 | ⭐⭐⭐⭐⭐ |
| **控制广告频率** | 不要让广告打扰核心体验 | ⭐⭐⭐⭐⭐ |
| **提供去广告选项** | 让用户有选择 | ⭐⭐⭐⭐ |
| **开屏广告适度** | 每天最多 1 次 | ⭐⭐⭐⭐ |
| **慎用插屏广告** | 打扰性强，容易引起反感 | ⭐⭐⭐ |
| **原生广告融入** | 与界面风格统一 | ⭐⭐⭐ |

> 📌 **本节小结**：广告变现的关键是"不让用户讨厌"。激励视频是最推荐的广告形式，兼顾收入和体验。国内选穿山甲，海外选 AdMob。务必提供付费去广告选项，让用户有选择权。

## 混合变现策略

> 🎯 **本节目标**：学会组合多种变现方式，实现用户分层变现，掌握变现模式选择方法。

### 免费+IAP+广告组合

最常见也最有效的变现策略是"免费下载 + IAP 解锁 + 广告收入"三管齐下：

```text
收入来源：
1. 免费用户看广告 → 广告收入
2. 部分用户付费去广告 → IAP 收入
3. 重度用户订阅 Pro → 订阅收入

优势：
- 免费下载降低门槛，用户量大
- 广告覆盖所有免费用户
- IAP/订阅覆盖愿意付费的用户
- 三种收入互不冲突，总收入最大化
```

#### 示例

以一款天气 App 为例：

| 用户类型 | 体验 | 你获得的收入 |
|----------|------|-------------|
| **免费用户** | 基础天气 + Banner 广告 | 广告收入 ¥0.5-2/用户/月 |
| **去广告用户** | 基础天气，无广告 | IAP ¥12（一次性） |
| **Pro 用户** | 高级功能 + 无广告 + 每小时更新 | 订阅 ¥18/月 |

### 用户分层变现

不同用户的价值不同，应该用不同方式变现：

#### 免费用户：广告变现

```text
免费用户特点：
- 占比最大（约 80-90%）
- 不愿意付费
- 但可以看广告

变现策略：
- Banner 广告（持续收入）
- 激励视频（高 eCPM）
- 开屏广告（每天一次）
- 插屏广告（适度）
```

#### 付费用户：IAP/订阅

```text
付费用户特点：
- 占比约 10-20%
- 愿意为价值付费
- 付费后不想看广告

变现策略：
- 去广告 IAP
- 功能解锁 IAP
- 月度/年度订阅
```

#### 重度用户：高级订阅

```text
重度用户特点：
- 占比约 1-5%
- 高频使用，深度依赖
- 愿意为高级功能付更多

变现策略：
- Pro 订阅（¥30-50/月）
- 企业版订阅
- 定制服务
```

#### 示例

```text
一款记账 App 的用户分层变现：

免费用户（85%）：
├── 基础记账功能
├── 底部 Banner 广告
└── 每日开屏广告

付费用户（12%）：
├── 去广告 ¥12
├── 月度会员 ¥12/月（预算管理 + 报表）
└── 年度会员 ¥98/月

重度用户（3%）：
├── Pro 会员 ¥28/月
├── 多账本 + 家庭共享
├── 数据导出 + API
└── 优先客服支持

月收入估算（1 万活跃用户）：
- 广告收入：8500 × ¥1.5 = ¥12,750
- IAP 收入：1200 × ¥12 = ¥14,400（一次性，按月摊薄约 ¥1,200/月）
- 订阅收入：300 × ¥18 = ¥5,400（月度）+ 少量年度
- 总计约 ¥19,350/月
```

### 变现模式选择指南

#### 决策流程

```text
你的 App 是什么类型？
│
├── 游戏
│   ├── 休闲游戏 → 免费 + 广告 + IAP
│   └── 中重度游戏 → 免费 + IAP + 激励视频
│
├── 工具类
│   ├── 简单工具 → 付费下载 或 免费+去广告IAP
│   └── 复杂工具 → 免费 + IAP解锁 + 订阅
│
├── 内容类
│   ├── 资讯/阅读 → 免费 + 订阅 + 广告
│   └── 视频/音乐 → 订阅为主 + 免费试用
│
├── 社交类
│   ├── 通用社交 → 免费 + 虚拟商品IAP
│   └── 垂直社交 → 免费 + 订阅 + IAP
│
└── 效率类
    ├── 轻量效率 → 免费 + IAP
    └── 专业效率 → 免费 + 订阅
```

#### 各模式适用场景表

| 变现模式 | 适用 App 类型 | 收入天花板 | 实现难度 | 代表 App |
|----------|-------------|-----------|---------|---------|
| **付费下载** | 工具、游戏 | ⭐⭐ | ⭐ | Minecraft、Procreate |
| **免费+IAP** | 工具、效率 | ⭐⭐⭐ | ⭐⭐ | GoodNotes、Notability |
| **免费+订阅** | 内容、效率、创意 | ⭐⭐⭐⭐ | ⭐⭐⭐ | Spotify、Netflix |
| **免费+广告** | 游戏、工具 | ⭐⭐⭐ | ⭐⭐ | 抖音、微信小游戏 |
| **混合模式** | 所有类型 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 大多数成功 App |

> 📌 **本节小结**：混合变现是收入最大化的策略。通过用户分层——免费用户看广告、付费用户买 IAP、重度用户订阅 Pro——让每一类用户都贡献收入。选择变现模式时，先确定 App 类型，再匹配最合适的组合。

## 国内支付合规注意事项

> 🎯 **本节目标**：了解 Apple 支付政策、虚拟商品支付规范和国内法规要求，避免因合规问题导致 App 被拒或下架。

### 虚拟商品支付规范

#### Apple 支付政策

苹果对 App 内的虚拟商品支付有严格规定：

| 商品类型 | 支付方式 | 能否绕过 IAP | 示例 |
|----------|---------|-------------|------|
| **虚拟商品** | 必须使用 IAP | ❌ 不能 | 游戏币、会员、去广告 |
| **实物商品** | 可以用第三方支付 | ✅ 可以 | 电商购物、外卖点餐 |
| **服务类** | 看情况 | 视具体服务 | 打车、预约 |

> ⚠️ **警告**：苹果对 IAP 的审核非常严格。如果你的 App 销售虚拟商品但没有使用 IAP，或者引导用户到外部网站购买，几乎一定会被拒。这就是著名的"苹果税"争议。

#### 虚拟商品必须用 IAP

```text
必须使用 IAP 的场景：
✅ 解锁 App 功能
✅ 去除广告
✅ 购买游戏币/道具
✅ 订阅会员/VIP
✅ 购买数字内容（电子书、课程等）

不需要 IAP 的场景：
✅ 购买实物商品（衣服、食品等）
✅ 购买线下服务（打车、外卖等）
✅ App 之间的点对点转账
```

#### 实物商品可以用其他支付

如果你的 App 销售实物商品，可以使用第三方支付（如微信支付、支付宝）：

```text
允许使用第三方支付的场景：
- 电商平台（淘宝、京东）
- 外卖平台（美团、饿了么）
- 出行平台（滴滴）
- 其他实物商品交易

注意：
- 必须是真正的实物商品
- 不能把虚拟商品伪装成实物商品
- 苹果审核时会仔细检查
```

### Apple 支付政策

#### 30% 抽成

苹果对 IAP 收取 30% 的佣金，这就是所谓的"苹果税"：

```text
苹果抽成规则：
- 用户支付 ¥18 购买会员
- 苹果抽走 30% = ¥5.4
- 你实际获得 ¥12.6

对比：
- 如果用户直接在你网站付费 ¥18
- 你获得 ¥18（扣除支付通道费约 0.6%）
- 差距：¥12.6 vs ¥17.9
```

#### 小企业计划（15%）

苹果在 2021 年推出了小企业计划，降低了小开发者的抽成比例：

| 条件 | 抽成比例 | 说明 |
|------|---------|------|
| 年收入 ≤ $100 万 | **15%** | 小企业计划 |
| 年收入 > $100 万 | **30%** | 标准抽成 |
| 自动续期订阅第 2 年起 | **15%** | 订阅留存优惠 |

```text
小企业计划申请：
1. 在 App Store Connect 中查看资格
2. 如果上一年 App Store 净收入 ≤ $100 万，自动享受 15%
3. 不需要额外申请，系统自动判断
4. 如果当年收入超过 $100 万，下一年恢复 30%
```

> 💡 **提示**：对于大多数独立开发者来说，年收入很难超过 $100 万（约 ¥720 万），所以基本都能享受 15% 的小企业计划。这意味着你实际能拿到 85% 的收入，比想象中好很多。

#### 注意事项

```text
⚠️ 苹果支付政策注意事项：

1. 不能在 App 内引导用户到外部购买
   ❌ "去官网购买更便宜"
   ❌ 提供外部购买链接
   ✅ App 内只能展示 IAP 购买选项

2. 不能在 App 内展示其他支付方式
   ❌ 展示微信支付/支付宝二维码
   ❌ 提示用户"联系客服购买"
   ✅ 只展示 IAP 购买流程

3. 价格必须与 App Store 一致
   ❌ 官网 ¥12，App 内 ¥18
   ✅ 所有渠道价格一致

4. 不能差异化定价
   ❌ iOS 用户 ¥18，Android 用户 ¥12
   ✅ 所有平台价格一致
```

### 国内法规要求

#### 支付合规

在中国大陆发布 App，除了遵守 Apple 的规定，还需要注意国内法规：

```text
   - App Store 收入属于"劳务报酬"或"经营所得"

   - 苹果不会代扣中国个税，需自行申报

3. 发票流程

   - 你需要向苹果开具发票
   - 苹果收到发票后才会付款
```

#### 注意事项

> ⚠️ **警告**：以下是国内开发者容易踩的坑：

```text
1. 虚拟货币相关
   ❌ App 内不能涉及虚拟货币交易
   ❌ 不能有"充值-提现"闭环
   ✅ 游戏币只能消费，不能提现

2. 直播打赏
   ⚠️ 需要遵守《关于加强网络直播规范管理工作的指导意见》

   ⚠️ 单次打赏金额有上限

   ⚠️ 需要显著提示用户"将自动续费"
   ⚠️ 取消订阅的入口要明显
   ⚠️ 不能默认勾选自动续费

4. 未成年人保护
   ⚠️ 游戏类 App 需要接入防沉迷系统
   ⚠️ 未成年人充值有限额
   ⚠️ 需要实名认证
```

> 📌 **本节小结**：合规是底线。虚拟商品必须走 IAP，实物商品可以用第三方支付。苹果 30% 抽成（小企业 15%）是硬性成本。国内还需注意 ICP 备案、税务申报、未成年人保护等法规要求。

## StoreKit 2 技术实现

> 🎯 **本节目标**：从零开始掌握 StoreKit 2 的完整技术实现，包括环境配置、产品查询、购买流程、交易验证、订阅管理和沙盒测试，最终能独立完成一个可上线的内购功能。

### StoreKit 2 简介

StoreKit 2 是苹果在 WWDC 2022 上随 iOS 16 推出的新一代内购框架。相比旧版 StoreKit（现在被称为 StoreKit 1），它在开发体验上有质的飞跃。

#### 相比 StoreKit 1 的改进

| 对比维度 | StoreKit 1 | StoreKit 2 |
|----------|-----------|------------|
| **编程范式** | 基于回调（delegate / completion handler） | 原生 async/await，代码线性可读 |
| **交易验证** | 需要自己发送收据到苹果服务器验证 | 客户端自动验证（VerificationResult） |
| **订阅状态** | 需要解析收据字段判断 | 提供专门的 Product.SubscriptionInfo |
| **类型安全** | 大量字符串 key-value，容易拼错 | 强类型 Swift API，编译期检查 |
| **错误处理** | 错误码分散，难以统一处理 | 统一的 StoreKitError 类型 |
| **最低系统** | iOS 3+ | iOS 15+（部分 API 需要 iOS 16+） |

> 💡 **提示**：如果你的 App 最低支持 iOS 15，就可以使用 StoreKit 2。如果需要支持更早的系统，可以采用"StoreKit 2 为主 + StoreKit 1 兜底"的兼容方案。

#### async/await 原生支持

StoreKit 2 最大的亮点是全面采用了 Swift 的 async/await 语法。来看一个直观的对比：

```text
StoreKit 1（回调地狱）：
1. 请求产品 → SKProductsRequest + delegate 回调
2. 发起购买 → SKPaymentQueue + delegate 回调
3. 验证收据 → 自己发网络请求 + 回调
4. 完成交易 → SKPaymentQueue.finishTransaction()
代码分散在多个 delegate 方法中，逻辑跳来跳去

StoreKit 2（线性流程）：
1. let products = try await Product.products(for: ids)
2. let result = try await product.purchase()
3. let transaction = try checkVerified(result)
4. await transaction.finish()
代码从头到尾一条线，读起来像自然语言
```

### 配置 App Store Connect

在写代码之前，你需要先在 App Store Connect 中创建好内购产品。这一步是前提条件，没有配置好产品，代码跑起来也查不到任何商品。

#### 创建 App 内购买项目

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 登录 [App Store Connect](https://appstoreconnect.apple.com) | 使用开发者账号登录 |
| 2 | 选择你的 App | 在"我的 App"中点击对应 App |
| 3 | 进入"App 内购买项目" | 左侧菜单中找到 |
| 4 | 点击 "+" 创建新产品 | 选择 IAP 类型（消耗型/非消耗型/订阅） |
| 5 | 填写产品 ID | 如 `com.yourapp.premium`，一旦创建不可修改 |
| 6 | 填写参考名称 | 仅在 App Store Connect 中可见，不展示给用户 |
| 7 | 设置价格 | 选择基准价格层级，苹果自动生成各国价格 |
| 8 | 填写显示名称和描述 | 用户在 App 内看到的商品名和说明 |
| 9 | 添加审核信息 | 审核截图和备注，帮助审核员理解 |
| 10 | 提交审核 | 与 App 一起审核，或单独提交 |

> ⚠️ **警告**：产品 ID 一旦创建就**不能修改、不能删除、不能复用**。命名建议用"反域名 + 功能名"格式，如 `com.myapp.subscription.pro.monthly`。

#### 创建订阅组

如果你的 App 有多个订阅产品（如月度会员和年度会员），必须将它们放入同一个订阅组：

```text
订阅组配置步骤：
1. 在 App Store Connect 中进入"订阅"
2. 点击"创建订阅组"
3. 填写组参考名称（如"Pro 会员"）
4. 在组内逐个添加订阅产品

订阅组规则：
- 同一组内的订阅互斥（用户只能有一个有效订阅）
- 用户可以在组内升级或降级
- 升级立即生效，降级在当前周期结束后生效
- 苹果自动处理差价计算和退款

示例：
订阅组"Pro 会员"
├── 月度会员 ¥18/月（产品 ID: com.myapp.pro.monthly）
├── 年度会员 ¥128/年（产品 ID: com.myapp.pro.yearly）
└── 终身会员 ¥298（产品 ID: com.myapp.pro.lifetime）
```

#### 创建沙盒测试账号

沙盒测试账号让你在开发阶段就能测试购买流程，不需要真实付费：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 在 App Store Connect 进入"用户和访问" | 左侧菜单 |
| 2 | 选择"沙盒" → "测试账户" | |
| 3 | 点击 "+" 添加测试账号 | 填写邮箱、密码、地区 |
| 4 | 邮箱不需要是真实的 | 但不能与已有 Apple ID 重复 |

> 💡 **提示**：建议为不同测试场景创建多个沙盒账号，比如一个用于测试首次购买、一个用于测试续订、一个用于测试取消后重新订阅。每个账号的购买状态是独立的。

### 代码实现

接下来是最核心的部分——用 StoreKit 2 实现完整的内购功能。

#### 查询产品信息：Product.products(for:)

在展示购买界面之前，你需要先从 App Store 查询产品的详细信息（名称、价格、描述等）：

```swift
import StoreKit

class StoreManager: ObservableObject {
    @Published var products: [Product] = []

    private let productIDs = [
        "com.myapp.premium",
        "com.myapp.removeads",
        "com.myapp.pro.monthly"
    ]

    func loadProducts() async {
        do {
            let storeProducts = try await Product.products(for: productIDs)
            products = storeProducts.sorted { $0.price < $1.price }
        } catch {
            print("查询产品失败: \(error)")
        }
    }
}
```

查询成功后，每个 `Product` 对象包含以下关键信息：

| 属性 | 说明 | 示例 |
|------|------|------|
| `id` | 产品 ID | `"com.myapp.premium"` |
| `displayName` | 显示名称 | `"Pro 会员"` |
| `description` | 产品描述 | `"解锁全部高级功能"` |
| `displayPrice` | 格式化价格 | `"¥18.00"` |
| `price` | 价格数值 | `18.0` |
| `type` | 产品类型 | `.nonConsumable` / `.autoRenewable` |

> 💡 **提示**：`Product.products(for:)` 会返回所有能找到的产品。如果某个产品 ID 在 App Store Connect 中不存在或未通过审核，它会被静默跳过，不会报错。所以务必检查返回的产品数量是否与预期一致。

#### 发起购买：product.purchase()

用户点击购买按钮后，调用 `purchase()` 方法发起购买：

```swift
func purchase(_ product: Product) async -> Bool {
    do {
        let result = try await product.purchase()

        switch result {
        case .success(let verification):
            let transaction = try checkVerified(verification)
            await transaction.finish()
            return true

        case .userCancelled:
            print("用户取消了购买")
            return false

        case .pending:
            print("购买待处理（例如需要家长批准）")
            return false

        @unknown default:
            return false
        }
    } catch {
        print("购买失败: \(error)")
        return false
    }
}
```

购买结果有三种情况：

| 结果 | 说明 | 处理方式 |
|------|------|---------|
| `.success` | 购买成功，返回交易凭证 | 验证后调用 `transaction.finish()` |
| `.userCancelled` | 用户点击了取消 | 无需处理，静默返回 |
| `.pending` | 购买需要额外审批（如"询问家长"） | 等待 Transaction.updates 推送最终结果 |

> ⚠️ **警告**：购买成功后，**必须**调用 `transaction.finish()`，否则系统会认为交易未完成，每次启动 App 都会重新弹出购买确认。但也要注意，只有在你确认已经正确处理了交易（如解锁功能、记录到服务器）之后，才能调用 `finish()`。

#### 验证交易：Transaction.updates

StoreKit 2 在客户端自动完成交易验证，你不需要像 StoreKit 1 那样把收据发到服务器去验证。验证逻辑通过 `VerificationResult` 类型实现：

```swift
func checkVerified<T>(_ result: VerificationResult<T>) throws -> T {
    switch result {
    case .verified(let safe):
        return safe
    case .unverified:
        throw StoreError.failedVerification
    }
}

enum StoreError: Error {
    case failedVerification
}
```

`VerificationResult` 是一个枚举，苹果帮你做了签名验证：

| 验证结果 | 说明 | 处理方式 |
|----------|------|---------|
| `.verified` | 签名验证通过，交易合法 | 放心使用交易数据 |
| `.unverified` | 签名验证失败，交易可能被篡改 | 拒绝交易，不要解锁功能 |

除了购买时的即时验证，你还需要监听交易更新（如pending 交易最终获批、家庭共享带来的交易等）：

```swift
func listenForTransactions() -> Task<Void, Never> {
    Task.detached {
        for await result in Transaction.updates {
            do {
                let transaction = try self.checkVerified(result)
                await transaction.finish()
            } catch {
                print("交易验证失败: \(error)")
            }
        }
    }
}
```

> 💡 **提示**：`Transaction.updates` 是一个异步序列，它会在后台持续监听新的交易。建议在 App 启动时就创建这个监听任务，确保不遗漏任何交易。

#### 恢复购买：AppStore.sync()

用户换了新设备或重装 App 后，需要恢复之前的购买记录。苹果**强制要求**所有提供非消耗型 IAP 的 App 必须有恢复购买功能：

```swift
func restorePurchases() async {
    do {
        try await AppStore.sync()
    } catch {
        print("恢复购买失败: \(error)")
    }
}
```

`AppStore.sync()` 会触发与苹果服务器的同步，把该用户的所有有效交易重新推送过来。同步完成后，你可以通过 `Transaction.currentEntitlements` 查询用户当前拥有的权益：

```swift
func updatePurchasedProducts() async {
    for await result in Transaction.currentEntitlements {
        if case .verified(let transaction) = result {
            if transaction.productID == "com.myapp.premium" {
                // 用户已购买 premium
            }
        }
    }
}
```

> ⚠️ **警告**：如果你的 App 有非消耗型 IAP 或订阅，但没有提供"恢复购买"按钮，苹果审核**一定会被拒**。这是硬性要求，没有任何商量余地。

### 订阅管理

订阅比一次性购买复杂得多，因为订阅状态会随时间变化（续订、取消、宽限期等）。StoreKit 2 提供了专门的 API 来管理订阅。

#### 获取订阅状态

查询用户当前的订阅状态：

```swift
func getSubscriptionStatus(for product: Product) async -> Product.SubscriptionInfo.Status? {
    guard let subscription = product.subscription else {
        return nil
    }

    let statuses = try? await subscription.status
    let highestStatus = statuses?
        .filter { $0.state == .subscribed || $0.state == .inGracePeriod }
        .sorted { $0.state < $1.state }
        .first

    return highestStatus
}
```

订阅状态有以下几种：

| 状态 | 说明 | 用户能否使用付费功能 |
|------|------|---------------------|
| `.subscribed` | 订阅有效 | ✅ 可以 |
| `.expired` | 订阅已过期 | ❌ 不可以 |
| `.inGracePeriod` | 宽限期内（扣费失败但还没过期） | ✅ 可以 |
| `.inBillingRetryPeriod` | 计费重试期（苹果正在尝试扣费） | ⚠️ 视情况 |
| `.revoked` | 订阅被撤销（如退款） | ❌ 不可以 |

#### 处理续订

自动续期订阅会在每个计费周期结束时自动扣费续订。你不需要手动处理续订逻辑，但需要监听续订事件来更新 App 内的权益状态：

```swift
func listenForSubscriptionUpdates() -> Task<Void, Never> {
    Task.detached {
        for await result in Transaction.updates {
            do {
                let transaction = try self.checkVerified(result)

                if transaction.productType == .autoRenewable {
                    // 订阅续订成功，更新权益
                }

                await transaction.finish()
            } catch {
                print("订阅更新验证失败: \(error)")
            }
        }
    }
}
```

#### 处理取消

用户可能随时取消订阅。取消后，订阅在当前周期结束前仍然有效：

```swift
func checkRenewalState(for product: Product) async -> Product.SubscriptionInfo.RenewalState? {
    guard let subscription = product.subscription else {
        return nil
    }

    do {
        let statuses = try await subscription.status
        guard let status = statuses.first else { return nil }

        return status.renewalState
    } catch {
        return nil
    }
}
```

续订状态：

| 续订状态 | 说明 | 你的应对策略 |
|----------|------|-------------|
| `.willRenew` | 将自动续订 | 正常服务 |
| `.turnedOff` | 用户关闭了自动续订 | 提醒用户即将过期，提供优惠 |
| `.inBillingRetryPeriod` | 扣费失败，正在重试 | 提醒用户更新支付方式 |

#### 处理宽限期

当自动续订扣费失败时，苹果会给一个宽限期（通常 16 天），在此期间用户仍然可以使用订阅功能：

```swift
func isUserInGracePeriod(for product: Product) async -> Bool {
    guard let subscription = product.subscription else { return false }

    do {
        let statuses = try await subscription.status
        return statuses.contains { $0.state == .inGracePeriod }
    } catch {
        return false
    }
}
```

> 💡 **提示**：宽限期是苹果给用户的"缓冲期"。在此期间你应该让用户继续使用功能，同时提醒他们更新支付方式。如果你在宽限期内就取消权益，用户体验很差，容易导致差评。

### 完整 SwiftUI 示例

下面是一个完整的、可以直接使用的内购页面示例，包含产品展示、购买、恢复购买和订阅状态显示：

```swift
import SwiftUI
import StoreKit

class StoreManager: ObservableObject {
    @Published var products: [Product] = []
    @Published var purchasedIDs: Set<String> = []
    @Published var isLoading = false
    @Published var errorMessage: String?
    @Published var subscriptionStatus: Product.SubscriptionInfo.Status?

    private let productIDs = [
        "com.myapp.premium",
        "com.myapp.removeads",
        "com.myapp.pro.monthly"
    ]

    private var transactionListener: Task<Void, Never>?

    init() {
        transactionListener = listenForTransactions()
    }

    deinit {
        transactionListener?.cancel()
    }

    func loadProducts() async {
        isLoading = true
        do {
            products = try await Product.products(for: productIDs)
            await updatePurchasedProducts()
        } catch {
            errorMessage = "加载商品失败: \(error.localizedDescription)"
        }
        isLoading = false
    }

    func purchase(_ product: Product) async -> Bool {
        do {
            let result = try await product.purchase()
            switch result {
            case .success(let verification):
                let transaction = try checkVerified(verification)
                purchasedIDs.insert(transaction.productID)
                await transaction.finish()
                return true
            case .userCancelled:
                return false
            case .pending:
                errorMessage = "购买待处理，请稍后查看"
                return false
            @unknown default:
                return false
            }
        } catch {
            errorMessage = "购买失败: \(error.localizedDescription)"
            return false
        }
    }

    func restorePurchases() async {
        do {
            try await AppStore.sync()
            await updatePurchasedProducts()
        } catch {
            errorMessage = "恢复购买失败: \(error.localizedDescription)"
        }
    }

    func isPurchased(_ productID: String) -> Bool {
        purchasedIDs.contains(productID)
    }

    private func checkVerified<T>(_ result: VerificationResult<T>) throws -> T {
        switch result {
        case .verified(let safe):
            return safe
        case .unverified:
            throw StoreError.failedVerification
        }
    }

    private func updatePurchasedProducts() async {
        for await result in Transaction.currentEntitlements {
            if case .verified(let transaction) = result {
                purchasedIDs.insert(transaction.productID)
            }
        }
    }

    private func listenForTransactions() -> Task<Void, Never> {
        Task.detached { [weak self] in
            guard let self else { return }
            for await result in Transaction.updates {
                do {
                    let transaction = try self.checkVerified(result)
                    await self.updatePurchasedProducts()
                    await transaction.finish()
                } catch {
                    print("交易监听错误: \(error)")
                }
            }
        }
    }
}

enum StoreError: Error {
    case failedVerification
}

struct StoreView: View {
    @StateObject private var store = StoreManager()
    @State private var isRestoring = false

    var body: some View {
        Group {
            if store.isLoading {
                ProgressView("加载中...")
            } else if store.products.isEmpty {
                VStack(spacing: 12) {
                    Text("暂无可用商品")
                        .foregroundColor(.secondary)
                    Button("重新加载") {
                        Task { await store.loadProducts() }
                    }
                }
            } else {
                productListView
            }
        }
        .navigationTitle("商店")
        .task {
            await store.loadProducts()
        }
        .alert("提示", isPresented: .constant(store.errorMessage != nil)) {
            Button("确定") { store.errorMessage = nil }
        } message: {
            Text(store.errorMessage ?? "")
        }
    }

    private var productListView: some View {
        List {
            Section {
                ForEach(store.products) { product in
                    ProductRow(product: product, store: store)
                }
            }

            Section {
                Button {
                    isRestoring = true
                    Task {
                        await store.restorePurchases()
                        isRestoring = false
                    }
                } label: {
                    HStack {
                        Spacer()
                        if isRestoring {
                            ProgressView()
                                .controlSize(.small)
                        } else {
                            Text("恢复购买")
                        }
                        Spacer()
                    }
                }
                .disabled(isRestoring)
            }
        }
    }
}

struct ProductRow: View {
    let product: Product
    @ObservedObject var store: StoreManager

    var body: some View {
        HStack {
            VStack(alignment: .leading, spacing: 4) {
                Text(product.displayName)
                    .font(.headline)
                Text(product.description)
                    .font(.caption)
                    .foregroundColor(.secondary)
                    .lineLimit(2)
            }

            Spacer()

            if store.isPurchased(product.id) {
                Label("已拥有", systemImage: "checkmark.circle.fill")
                    .foregroundColor(.green)
                    .font(.subheadline)
            } else {
                Button {
                    Task { _ = await store.purchase(product) }
                } label: {
                    Text(product.displayPrice)
                        .font(.subheadline)
                        .fontWeight(.semibold)
                        .padding(.horizontal, 14)
                        .padding(.vertical, 7)
                        .background(Color.blue)
                        .foregroundColor(.white)
                        .cornerRadius(8)
                }
            }
        }
        .padding(.vertical, 4)
    }
}
```

> 💡 **提示**：这个示例覆盖了 StoreKit 2 的核心流程——产品查询、购买、验证、监听、恢复购买。你可以直接复制到项目中，修改 `productIDs` 为你自己的产品 ID 即可使用。

### 常见问题

在实际开发中，你可能会遇到以下问题。这里列出最常见的问题和解决方案。

#### 交易丢失

```text
症状：用户说已经购买了，但 App 内没有解锁功能

可能原因：
1. 没有调用 transaction.finish() → 交易不会永久记录
2. 没有监听 Transaction.updates → 漏掉了后台交易
3. App 重启后没有重新查询 Transaction.currentEntitlements

解决方案：
✅ 确保每次购买成功后都调用 transaction.finish()
✅ App 启动时创建 Transaction.updates 监听
✅ App 启动时调用 Transaction.currentEntitlements 查询已有权益
✅ 对于关键交易，发送到服务器做备份记录
```

#### 收据验证失败

```text
症状：VerificationResult 返回 .unverified

可能原因：
1. 设备时间不正确 → 签名验证依赖时间戳
2. 网络问题导致无法获取苹果公钥 → 验证需要联网
3. 越狱设备篡改了系统证书 → 安全机制触发

解决方案：
✅ 提示用户检查设备时间（设置 → 通用 → 日期与时间 → 自动）
✅ 验证失败时给用户友好提示，而不是直接崩溃
✅ 对于 .unverified 结果，不要解锁功能，但可以允许重试
✅ 关键业务走服务器验证，不依赖客户端验证
```

#### 审核被拒（内购相关）

```text
最常见的内购审核被拒原因：

1. 缺少"恢复购买"按钮
   ❌ 没有"恢复购买"功能
   ✅ 在购买页面添加明显的"恢复购买"按钮

2. 引导用户到外部购买
   ❌ App 内提示"去官网购买更便宜"
   ❌ 展示外部购买链接或二维码
   ✅ 只展示 IAP 购买选项

3. 虚拟商品没有使用 IAP
   ❌ 使用微信/支付宝购买会员
   ✅ 虚拟商品必须走 IAP

4. 订阅条款不清晰
   ❌ 没有说明订阅价格和续订规则
   ✅ 在购买页面明确展示：价格、周期、自动续订说明、取消方式

5. 免费试用信息不明确
   ❌ 没有告知试用结束后会自动扣费
   ✅ 明确说明"试用期 X 天，结束后自动续费 ¥XX/月"

6. 价格展示不完整
   ❌ 只显示月价，不说明年化总价
   ✅ 同时展示周期价格和每期等价价格
```

> 📌 **本节小结**：StoreKit 2 用 async/await 大幅简化了内购开发。核心流程是：查询产品 → 发起购买 → 验证交易 → 完成交易。订阅需要额外处理状态查询和续订监听。务必提供恢复购买功能，否则审核必被拒。开发阶段用 Xcode 本地 StoreKit 测试，发布前用沙盒账号做完整测试。

## 小结

本章全面解析了 App 变现的各种模式，核心要点如下：

| 模块 | 核心要点 |
|------|---------|
| **付费下载定价** | 尾数定价、锚定效应、促销策略 |
| **IAP 接入** | 4 种 IAP 类型、StoreKit 2 全流程、服务器验证、恢复购买 |
| **订阅设计** | 层级设计、免费试用、锚定定价、留存优化 |
| **广告变现** | AdMob（海外）/ 穿山甲（国内）、激励视频优先、控制频率 |
| **混合变现** | 免费用户看广告 + 付费用户 IAP + 重度用户订阅 |
| **合规注意** | 虚拟商品必须 IAP、苹果抽成 30%/15%、国内法规 |

**变现模式选择的黄金法则**：

```text
1. 先让用户免费体验 → 降低门槛
2. 用广告覆盖免费用户 → 基础收入
3. 用 IAP/订阅覆盖付费用户 → 核心收入
4. 用 Pro 订阅覆盖重度用户 → 高端收入
5. 持续优化 → 数据驱动决策
```

> 💡 **最后提示**：变现不是一蹴而就的。先做好产品，让用户觉得"值"，再考虑怎么收费。产品不行，再好的变现策略也没用。
