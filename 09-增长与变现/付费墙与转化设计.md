## 一、付费墙（Paywall）是什么？

想象你走进一家健身房：大门是敞开的（免费下载），你可以参观大厅、看看器材（免费功能），但想进力量区？抱歉，得办会员卡——那扇挡在你面前的"会员专用"门，就是**付费墙**。

**付费墙**是 App 内用于拦截用户、引导其付费或订阅的页面。它是整个变现链路的**核心转化节点**——用户从"感兴趣"到"掏钱"的关键一步。

```
用户旅程：下载 App → 体验免费功能 → 触达付费墙 → 决定付费/离开
                                        ↑
                                    转化发生在这里
```

> 💡 付费墙不是"收费站"，而是"价值展示台"。好的付费墙让用户觉得"花得值"，而不是"被拦住了"。

## 二、付费墙类型

### 2.1 硬付费墙

**必须付费才能使用核心功能**，没有免费午餐。

就像电影院——不买票，进不了放映厅。

```
用户打开 App → 付费墙（全屏）→ 付费 → 使用
                  ↓
               离开 App
```

**适用场景：**

- 工具类 App（如专业修图、VPN）
- 内容型 App（如新闻深度报道、电子书）
- 功能单一且价值明确的 App

### 2.2 软付费墙（Freemium）

**基础功能免费，高级功能付费**。用户可以先尝后买。

就像超市的试吃台——尝了一口觉得好，才会买整盒。

```
用户打开 App → 免费使用基础功能 → 需要高级功能 → 付费墙 → 付费 → 解锁
```

**适用场景：**

- 效率工具（如 Notion、Todoist）
- 社交/内容平台
- 大多数 App 的首选策略

### 2.3 计量付费墙

**免费使用 N 次后开始收费**，用够了再掏钱。

就像咖啡店的"第 10 杯免费"——前 9 杯让你养成习惯，第 10 杯开始收费。

```
用户使用 App → 第1次免费 → 第2次免费 → ... → 第N次 → 付费墙 → 付费 → 继续
```

**适用场景：**

- AI 对话类 App（每天免费 3 次）
- 翻译 App（每月免费 5000 字）
- 云存储类（免费 5GB）

### 2.4 时间付费墙

**免费使用 N 天后开始收费**，限时体验。

就像视频网站的 7 天免费试看——到期了想继续看？请充值。

```
用户下载 App → 7天全功能免费体验 → 体验到期 → 付费墙 → 付费 → 继续
```

**适用场景：**

- 订阅制 App（配合免费试用）
- 学习类 App
- 健身/冥想类 App

### 2.5 各类型适用场景对比表

| 付费墙类型 | 用户体验 | 转化难度 | 留存影响 | 适用阶段 | 典型 App |
|-----------|---------|---------|---------|---------|---------|
| 硬付费墙 | ⭐⭐ | 高 | 下载流失大 | 功能价值极高 | WallaCoder、1Password |
| 软付费墙 | ⭐⭐⭐⭐⭐ | 中 | 留存好 | 大多数阶段 | Notion、Spotify |
| 计量付费墙 | ⭐⭐⭐⭐ | 中低 | 习惯养成后转化好 | 需要培养习惯 | ChatGPT、DeepL |
| 时间付费墙 | ⭐⭐⭐⭐ | 中 | 试用后流失需关注 | 配合订阅试用 | Headspace、Calm |

> ⚠️ 没有绝对最好的付费墙类型，只有最适合你 App 的。新手建议从**软付费墙**开始，风险最低。

## 三、付费墙 UI 设计

### 3.1 布局结构

一个高转化付费墙的布局，就像一篇好文章——**标题抓眼球，内容说价值，结尾促行动**：

```
┌─────────────────────────┐
│      ✕ 关闭按钮          │  ← 允许用户关闭（否则会被拒）
├─────────────────────────┤
│                         │
│    🎯 大标题             │  ← 一句话说清核心价值
│    副标题说明             │  ← 补充说明
│                         │
├─────────────────────────┤
│                         │
│    ✅ 功能 1             │  ← 价值主张列表
│    ✅ 功能 2             │
│    ✅ 功能 3             │
│    ✅ 功能 4             │
│                         │
├─────────────────────────┤
│                         │
│  ┌─────┐ ┌─────┐ ┌────┐│  ← 定价卡片
│  │ 月卡 │ │年卡⭐│ │终身 ││
│  │¥18  │ │¥128 │ │¥298││
│  └─────┘ └─────┘ └────┘│
│                         │
├─────────────────────────┤
│                         │
│  [  开始 7 天免费试用  ]  │  ← CTA 按钮（大、醒目）
│                         │
│  恢复购买 | 条款 | 隐私   │  ← 必须有的链接
│                         │
└─────────────────────────┘
```

### 3.2 定价卡片设计

#### 单方案

最简单直接，适合只有一种订阅的 App：

```
┌───────────────────┐
│     年度会员        │
│                    │
│    ¥128/年         │
│   ≈ ¥10.7/月      │  ← 拆算月价，降低心理门槛
│                    │
│  [ 立即订阅 ]      │
└───────────────────┘
```

#### 双方案（推荐）

月卡 vs 年卡，利用**锚定效应**让年卡显得更划算：

```
┌──────────┐  ┌──────────────────┐
│  月度会员  │  │  年度会员 ⭐最划算  │
│           │  │                   │
│  ¥18/月   │  │  ¥128/年          │
│           │  │  ≈ ¥10.7/月       │
│           │  │  省 56%           │  ← 突出节省比例
│ [ 选择 ]  │  │  [ 选择 ]         │
└──────────┘  └──────────────────┘
```

#### 三方案

加入终身买断，给"不想订阅"的用户一个选择：

```
┌────────┐ ┌──────────────┐ ┌────────┐
│ 月度会员 │ │ 年度会员 ⭐最受欢迎│ │ 终身会员 │
│ ¥18/月  │ │ ¥128/年       │ │ ¥298   │
│         │ │ ≈ ¥10.7/月    │ │ 一次买断│
│         │ │ 省 56%        │ │        │
│[ 选择 ] │ │ [ 选择 ]      │ │[ 选择 ] │
└────────┘ └──────────────┘ └────────┘
```

> 💡 三方案是经典布局：月卡做"锚"让年卡显得划算，终身版给犹豫者另一个选择。行为经济学称之为**诱饵效应**。

### 3.3 推荐标签设计

推荐标签是引导用户选择的"小手指"：

| 标签文案 | 适用场景 | 效果 |
|---------|---------|------|
| 最受欢迎 | 年度方案 | 利用从众心理 |
| 最划算 | 年度方案 | 强调性价比 |
| 推荐 | 任意推荐方案 | 简洁通用 |
| 省XX% | 年度/终身 | 量化节省 |
| 限时优惠 | 促销方案 | 制造紧迫感 |

视觉设计要点：

- 用**品牌色**或**醒目色**作为标签背景
- 位置放在卡片**左上角**或**顶部居中**
- 可以加小图标（⭐、🔥、👑）

### 3.4 功能对比表设计

让用户一眼看清免费 vs 付费的区别：

```
┌──────────────────┬────────┬────────┐
│      功能         │  免费   │  高级   │
├──────────────────┼────────┼────────┤
│ 基础笔记          │   ✅   │   ✅   │
│ 云端同步          │   ❌   │   ✅   │
│ AI 写作助手       │   ❌   │   ✅   │
│ 无限存储          │   ❌   │   ✅   │
│ 导出 PDF          │   ❌   │   ✅   │
│ 优先客服          │   ❌   │   ✅   │
└──────────────────┴────────┴────────┘
```

> 💡 对比表中，免费列也要有 ✅，让用户觉得"免费也不错"，但"付费更值"。全是 ❌ 会让用户觉得免费版太鸡肋。

### 3.5 社会证明

人们倾向于跟随他人的选择——这就是社会证明的力量：

| 社会证明类型 | 示例 | 适用场景 |
|------------|------|---------|
| 用户评价 | "这个 App 改变了我的工作方式！" — 用户A | 所有 App |
| 评分 | ⭐⭐⭐⭐⭐ 4.8 分 | 所有 App |
| 下载量 | "已有 100 万用户选择" | 用户量大的 App |
| 媒体推荐 | "App Store 精选推荐" | 获得过推荐的 App |
| 名人背书 | "某某大佬推荐" | 有名人资源的 App |
| 数据证明 | "用户平均效率提升 40%" | 效率工具类 |

struct PlanCardView: View {

                            .font(.caption2)
                            .foregroundColor(isSelected ? .white.opacity(0.7) : .secondary)

### 4.3 完整付费墙组件

```swift
struct PaywallView: View {
    @Environment(\.dismiss) private var dismiss
    @State private var selectedPlanID: String = "yearly"
    @State private var isPurchasing = false
    @State private var errorMessage: String?

    private let plans = SubscriptionPlan.samples
    private let features = [
        ("🚀", "无限使用所有功能"),
        ("☁️", "云端同步，多设备访问"),
        ("🤖", "AI 智能助手"),
        ("📦", "无限存储空间"),
        ("🎨", "专属主题和模板"),
        ("💬", "优先客服支持")
    ]

    var body: some View {
        ScrollView {
            VStack(spacing: 24) {
                closeButton

                headerSection

                featuresSection

                planSelectionSection

                ctaButton

                footerLinks
            }
            .padding()
        }
        .alert("购买失败", isPresented: .constant(errorMessage != nil)) {
            Button("确定") { errorMessage = nil }
        } message: {
            Text(errorMessage ?? "")
        }
    }

    private var closeButton: some View {
        HStack {
            Spacer()
            Button {
                dismiss()
            } label: {
                Image(systemName: "xmark.circle.fill")
                    .font(.title2)
                    .foregroundColor(.secondary)
            }
        }
    }

    private var headerSection: some View {
        VStack(spacing: 8) {
            Text("解锁全部功能")
                .font(.largeTitle)
                .fontWeight(.bold)

            Text("升级高级会员，享受无限制体验")
                .font(.subheadline)
                .foregroundColor(.secondary)
        }
    }

    private var featuresSection: some View {
        VStack(alignment: .leading, spacing: 12) {
            ForEach(features, id: \.0) { icon, text in
                HStack(spacing: 12) {
                    Text(icon)
                        .font(.title3)
                    Text(text)
                        .font(.subheadline)
                    Spacer()
                }
            }
        }
        .padding()
        .background(Color(.systemGray6))
        .cornerRadius(12)
    }

    private var planSelectionSection: some View {
        HStack(spacing: 12) {
            ForEach(plans) { plan in
                PlanCardView(
                    plan: plan,
                    isSelected: selectedPlanID == plan.id
                ) {
                    withAnimation(.easeInOut(duration: 0.2)) {
                        selectedPlanID = plan.id
                    }
                }
            }
        }
    }

    private var ctaButton: some View {
        Button {
            purchaseSelectedPlan()
        } label: {
            HStack {
                if isPurchasing {
                    ProgressView()
                        .progressViewStyle(CircularProgressViewStyle(tint: .white))
                }
                Text(isPurchasing ? "处理中..." : "开始 7 天免费试用")
                    .fontWeight(.semibold)
            }
            .frame(maxWidth: .infinity)
            .padding()
            .background(Color.blue)
            .foregroundColor(.white)
            .cornerRadius(12)
        }
        .disabled(isPurchasing)
    }

    private var footerLinks: some View {
        VStack(spacing: 8) {
            Button("恢复购买") {
                restorePurchases()
            }
            .font(.subheadline)
            .foregroundColor(.secondary)

            HStack(spacing: 16) {
                Link("服务条款", destination: URL(string: "https://example.com/terms")!)
                Link("隐私政策", destination: URL(string: "https://example.com/privacy")!)
            }
            .font(.caption)
            .foregroundColor(.secondary)

            Text("试用结束后自动续费，可随时取消")
                .font(.caption2)
                .foregroundColor(.secondary)
        }
    }

    private func purchaseSelectedPlan() {
        guard let plan = plans.first(where: { $0.id == selectedPlanID }) else { return }
        isPurchasing = true

        Task {
            do {
                let products = try await Product.products(for: [plan.productID])
                guard let product = products.first else {
                    errorMessage = "无法获取产品信息"
                    isPurchasing = false
                    return
                }

                let result = try await product.purchase()

                switch result {
                case .success(let verification):
                    switch verification {
                    case .verified:
                        dismiss()
                    case .unverified:
                        errorMessage = "购买验证失败"
                    }
                case .userCancelled:
                    break
                case .pending:
                    errorMessage = "购买待处理，请稍后查看"
                @unknown default:
                    errorMessage = "未知错误"
                }
            } catch {
                errorMessage = error.localizedDescription
            }

            isPurchasing = false
        }
    }

    private func restorePurchases() {
        Task {
            do {
                try await AppStore.sync()
            } catch {
                errorMessage = "恢复购买失败：\(error.localizedDescription)"
            }
        }
    }
}
```

### 4.4 购买流程说明

```
用户点击 CTA
    ↓
调用 Product.products(for:) 获取产品信息
    ↓
调用 product.purchase() 发起购买
    ↓
StoreKit 弹出系统购买弹窗
    ↓
用户确认购买 / 取消
    ↓
验证购买结果 (VerificationResult)
    ↓
verified → 解锁功能，关闭付费墙
unverified → 提示验证失败
userCancelled → 不做处理
pending → 提示待处理
```

### 4.5 恢复购买按钮

> ⚠️ **必须提供恢复购买按钮！** Apple 审核明确要求：如果 App 支持自动续期订阅，必须提供恢复购买功能，否则会被拒审。

```swift
Button("恢复购买") {
    Task {
        do {
            try await AppStore.sync()
        } catch {
            errorMessage = "恢复购买失败：\(error.localizedDescription)"
        }
    }
}
```

### 4.6 条款与隐私链接

付费墙底部**必须**包含：

| 链接 | 要求 | 指向 |
|------|------|------|
| 服务条款 | 必须 | 你的服务条款页面 |
| 隐私政策 | 必须 | 你的隐私政策页面 |
| 恢复购买 | 必须（订阅类） | 调用 AppStore.sync() |

> 💡 这些链接不仅是合规要求，也能增加用户信任。没有这些链接，Apple 审核大概率会拒绝。

## 五、转化率优化（CRO）

### 5.1 A/B 测试付费墙

A/B 测试就像做菜——你不尝尝，永远不知道多加一勺盐好不好吃。

```
┌─────────────────────────────────────────┐
│            A/B 测试流程                   │
├─────────────────────────────────────────┤
│                                         │
│  版本 A（对照组）     版本 B（实验组）     │
│  "解锁全部功能"       "开启无限可能"       │
│       ↓                   ↓             │
│  50% 用户看到        50% 用户看到         │
│       ↓                   ↓             │
│  转化率 3.2%         转化率 4.1%         │
│       ↓                   ↓             │
│         B 胜出 → 全量上线 B              │
│                                         │
└─────────────────────────────────────────┘
```

**可测试的元素：**

| 测试元素 | 版本 A | 版本 B | 影响程度 |
|---------|--------|--------|---------|
| 标题 | 解锁全部功能 | 开启无限可能 | ⭐⭐⭐ |
| CTA 文案 | 立即订阅 | 开始免费试用 | ⭐⭐⭐⭐⭐ |
| 定价展示 | ¥128/年 | ≈ ¥10.7/月 | ⭐⭐⭐⭐ |
| 配色 | 蓝色 CTA | 绿色 CTA | ⭐⭐ |
| 布局 | 纵向列表 | 横向卡片 | ⭐⭐⭐ |
| 社会证明 | 无 | "100 万用户选择" | ⭐⭐⭐ |

> ⚠️ 每次 A/B 测试只改**一个变量**，否则你不知道是哪个改变导致了效果差异。

### 5.2 标题文案优化

标题是付费墙的"门面"——5 秒内决定用户是继续看还是关掉。

| ❌ 差标题 | ✅ 好标题 | 原因 |
|----------|----------|------|
| 升级 Pro | 解锁无限创作空间 | 好标题说价值，不说功能 |
| 订阅会员 | 让灵感不再受限 | 好标题有情感共鸣 |
| 付费解锁 | 开始你的高效之旅 | 好标题用行动词开头 |
| 购买高级版 | 释放你的全部潜力 | 好标题面向用户，不是产品 |

**标题公式：**

```
行动词 + 用户价值 + 情感共鸣

例：
- "解锁" + "无限创作空间" → 解锁无限创作空间
- "开始" + "7天免费体验" → 开始 7 天免费体验
- "释放" + "你的全部潜力" → 释放你的全部潜力
```

### 5.3 CTA 按钮文案

CTA（Call To Action）按钮是付费墙的"临门一脚"。

| 文案 | 心理效应 | 转化率影响 |
|------|---------|-----------|
| 立即订阅 | 直接，但压力大 | 基准 |
| 开始 7 天免费试用 | 降低门槛，先试后买 | +30%~50% |
| 立即解锁 | 强调即时获得 | +10%~20% |
| 继续使用全部功能 | 强调不付费就失去 | +5%~15% |
| 获取优惠 | 强调利益 | +15%~25% |

> 💡 **免费试用是转化率提升的最有效手段。** "开始 7 天免费试用"比"立即订阅"的转化率通常高出 30% 以上。用户心理是："反正免费，试试又不会亏。"

### 5.4 颜色心理学

颜色不只是好看，它在悄悄影响用户的决策：

| 颜色 | 心理暗示 | 适用场景 |
|------|---------|---------|
| 🔵 蓝色 | 信任、安全、专业 | 金融、工具类 |
| 🟢 绿色 | 成长、积极、确认 | 健康、效率类 |
| 🟠 橙色 | 活力、紧迫、行动 | 限时优惠、促销 |
| 🔴 红色 | 紧急、重要、热情 | 倒计时、警告 |
| 🟣 紫色 | 高端、创意、神秘 | 设计、创意类 |
| ⚫ 黑色 | 高级、简约、权威 | 高端品牌 |

**CTA 按钮配色建议：**

- 按钮颜色与页面背景形成**强对比**
- 使用品牌主色或**暖色调**（橙/绿）作为 CTA 色
- 避免用灰色或低饱和度色做 CTA

### 5.5 紧迫感设计

"过了这个村，没这个店"——紧迫感让用户从"再想想"变成"现在就买"。

| 紧迫感手法 | 示例 | 注意事项 |
|-----------|------|---------|
| 限时优惠 | "限时 5 折，仅剩 2 天" | 必须真实，虚假倒计时会被拒审 |
| 限量优惠 | "前 1000 名用户享 8 折" | 需要真实计数 |
| 新用户专享 | "新用户首月 ¥1" | 明确标注条件 |
| 节日促销 | "春节特惠，年卡 6 折" | 过期自动恢复原价 |

```swift
struct CountdownOfferView: View {
    let endDate: Date
    @State private var remaining: String = ""

    let timer = Timer.publish(every: 1, on: .main, in: .common).autoconnect()

    var body: some View {
        HStack {
            Image(systemName: "clock.fill")
                .foregroundColor(.orange)
            Text("限时优惠剩余 \(remaining)")
                .font(.subheadline)
                .fontWeight(.medium)
                .foregroundColor(.orange)
        }
        .padding(.horizontal, 16)
        .padding(.vertical, 8)
        .background(Color.orange.opacity(0.1))
        .cornerRadius(8)
        .onReceive(timer) { _ in
            updateRemaining()
        }
        .onAppear {
            updateRemaining()
        }
    }

    private func updateRemaining() {
        let diff = max(0, endDate.timeIntervalSince(Date()))
        let hours = Int(diff) / 3600
        let minutes = (Int(diff) % 3600) / 60
        let seconds = Int(diff) % 60
        remaining = String(format: "%02d:%02d:%02d", hours, minutes, seconds)
    }
}
```

> ⚠️ **绝对不要使用虚假倒计时！** 如果用户关掉 App 再打开，倒计时重置了——Apple 审核会发现并拒绝。紧迫感设计必须基于真实数据。

### 5.6 减少摩擦：免费试用 > 直接付费

"摩擦"就是用户在付费过程中遇到的每一个阻碍。减少摩擦 = 提高转化。

```
高摩擦路径：
用户 → 看到价格 → 犹豫 → 想想 → 再想想 → 算了

低摩擦路径：
用户 → 看到免费试用 → "反正免费" → 点击 → 开始体验 → 习惯后付费
```

| 摩擦点 | 优化方案 | 效果 |
|-------|---------|------|
| 直接要求付费 | 提供免费试用 | 转化率 +30%~50% |
| 复杂的注册流程 | 支持 Sign in with Apple | 注册完成率 +20% |
| 不清楚买了什么 | 清晰的功能列表 | 转化率 +15% |
| 担心取消困难 | 明确标注"随时取消" | 转化率 +10% |
| 没有价格对比 | 展示月均价格 | 转化率 +10%~20% |

## 六、常见付费墙错误

### 6.1 过早展示付费墙

```
❌ 错误流程：
下载 App → 打开 → 立刻弹出付费墙 → 用户懵了 → 卸载

✅ 正确流程：
下载 App → 打开 → 体验核心功能 → 发现价值 → 需要更多功能 → 付费墙
```

> 💡 让用户先体验到 App 的价值，再让他们付费。就像约会——第一次见面就求婚，大概率被拒绝。

**最佳展示时机：**

| App 类型 | 推荐展示时机 | 原因 |
|---------|------------|------|
| 工具类 | 用户第 3~5 次使用时 | 先让用户形成使用习惯 |
| 内容类 | 用户阅读 3~5 篇后 | 让用户认可内容质量 |
| 社交类 | 用户想使用高级互动功能时 | 功能需求驱动 |
| 游戏类 | 关卡失败/需要道具时 | 情绪高点，付费意愿强 |

### 6.2 价值主张不清晰

| ❌ 模糊的价值主张 | ✅ 清晰的价值主张 |
|-----------------|-----------------|
| 升级 Pro | 无限使用 AI 写作助手 |
| 解锁高级功能 | 解锁云端同步 + 100GB 存储 |
| 获取完整体验 | 享受无广告 + 离线模式 + 优先客服 |
| 会员特权 | 每月 1000 次 AI 对话 + 专属模板 |

**价值主张公式：**

```
具体功能 + 量化数据 + 用户收益

例：
- "无限使用 AI 写作"（功能）+ "每月省 10 小时"（量化）+ "告别写作焦虑"（收益）
```

### 6.3 缺少免费试用

| 情况 | 有免费试用 | 无免费试用 |
|------|----------|----------|
| 转化率 | 基准 | -30%~50% |
| 用户信任 | 高 | 低 |
| 试用→付费转化 | 25%~60% | — |
| 审核风险 | 低 | 中（Apple 倾向有试用） |

> ⚠️ Apple 从 2024 年开始更严格地审核没有免费试用的订阅 App，尤其是新 App。建议至少提供 3~7 天的免费试用。

### 6.4 没有恢复购买按钮

```
❌ 严重后果：
- Apple 审核直接拒绝（Guideline 3.1.2）
- 换设备用户无法恢复订阅
- 大量差评和投诉
```

```swift
// ✅ 必须添加恢复购买按钮
Button("恢复购买") {
    Task {
        try? await AppStore.sync()
    }
}
```

> ⚠️ 这不是"建议"，是**硬性要求**。没有恢复购买按钮 = 审核被拒，没有例外。

## 八、付费墙合规要求

### 8.1 Apple 审核对付费墙的要求

Apple 对付费墙有一系列硬性要求，不满足就会被拒：

| 要求 | 说明 | Guideline |
|------|------|-----------|
| 必须有恢复购买按钮 | 允许用户在其他设备恢复订阅 | 3.1.2 |
| 必须展示订阅条款 | 包括价格、周期、自动续期说明 | 3.1.2 |
| 必须有隐私政策链接 | 指向有效的隐私政策页面 | 5.1.1 |
| 必须有服务条款链接 | 指向有效的服务条款页面 | 3.1.2 |
| 不能使用虚假倒计时 | 倒计时必须真实 | 3.1.2 |
| 不能误导用户 | CTA 文案不能暗示免费但实际收费 | 3.1.1 |
| 免费试用必须明确 | 试用结束后会自动收费 | 3.1.2 |
| 不能使用"免费"误导 | 如果试用后收费，不能只说"免费" | 3.1.1 |

### 8.2 必须展示的信息

付费墙页面**必须**清晰展示以下信息：

```
┌─────────────────────────────────────────┐
│              必须展示的信息               │
├─────────────────────────────────────────┤
│                                         │
│  1. 订阅价格（明确标注货币单位）          │
│     例：¥128.00/年                      │
│                                         │
│  2. 订阅周期                            │
│     例：年度订阅 / 自动续期              │
│                                         │
│  3. 免费试用时长（如有）                 │
│     例：7 天免费试用                     │
│                                         │
│  4. 试用结束后自动续费价格               │
│     例：试用结束后按 ¥128/年 自动续费    │
│                                         │
│  5. 取消方式                            │
│     例：可随时在设置中取消               │
│                                         │
│  6. 恢复购买入口                        │
│     例：恢复购买按钮                     │
│                                         │
│  7. 隐私政策链接                        │
│  8. 服务条款链接                        │
│                                         │
└─────────────────────────────────────────┘
```

### 8.3 自动续期提醒

Apple 要求在以下场景中提醒用户自动续期：

| 场景 | 要求 |
|------|------|
| 付费墙展示时 | 明确标注"自动续期"和续费价格 |
| 免费试用结束时 | 提前 24 小时发送续费提醒通知 |
| 订阅续费前 | Apple 会自动发送续费提醒邮件 |
| 订阅价格上涨时 | 必须明确通知用户并获得同意 |

```swift
struct SubscriptionDisclaimerView: View {
    var body: some View {
        VStack(spacing: 4) {
            Text("• 付费确认后，费用将从 Apple ID 账户扣除")
            Text("• 订阅自动续期，除非在当前周期结束前至少 24 小时关闭自动续期")
            Text("• 账户将在当前周期结束前 24 小时内收取续费费用")
            Text("• 用户可以管理订阅，购买后可在用户设置中关闭自动续期")
        }
        .font(.caption2)
        .foregroundColor(.secondary)
        .padding(.horizontal)
    }
}
```

> ⚠️ 以上声明文字是 Apple 审核的"标准答案"，建议原样使用或微调。缺少这些声明是付费墙被拒的常见原因之一。

## 小结

| 知识点 | 核心要点 |
|-------|---------|
| 付费墙是什么 | App 内引导用户付费的转化页面 |
| 4 种类型 | 硬/软/计量/时间，新手首选软付费墙 |
| UI 设计 | 标题→价值主张→功能列表→定价卡片→CTA→底部链接 |
| SwiftUI 实现 | PlanCard + PaywallView + StoreKit 2 购买流程 |
| 转化率优化 | A/B 测试、文案优化、免费试用、减少摩擦 |
| 常见错误 | 过早展示、价值不清、缺试用、缺恢复购买 |
| 案例参考 | Spotify/Headspace/Notion/国内 App 各有特色 |
| 合规要求 | 恢复购买、订阅条款、隐私政策、自动续期声明 |

**记住付费墙设计的三个核心原则：**

1. **先给价值，再谈价格** —— 让用户体验到 App 的好处
2. **降低门槛，减少摩擦** —— 免费试用是最好的转化工具
3. **合规第一，创意第二** —— 不满足 Apple 要求，再好的设计也上不了架

> 💡 付费墙不是一锤子买卖。持续 A/B 测试、优化文案、调整定价，才能不断提升转化率。上线只是开始，优化才是长期工作。
