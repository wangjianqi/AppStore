# 国际化方案与多语言发布

## 本章目标

读完本章，你将能够：

- 理解国际化和本地化的区别，不再把两个概念搞混
- 掌握 iOS 国际化的三种主流方案，并知道该选哪个
- 用 String Catalog + SwiftUI 实现多语言切换
- 处理日期、数字、货币的本地化显示
- 适配 RTL 语言和文本长度变化带来的布局问题
- 在 App Store Connect 中配置多语言元数据和截图
- 用 AI 辅助翻译，高效完成多语言文案
- 拿着"国际化检查清单"逐项验收，不遗漏任何细节

---

## 1. 为什么要做国际化

### 全球市场有多大？

想象一下：你的 App 目前只支持中文，就像一家只挂中文招牌的餐厅——路过的人很多，但能看懂招牌的只有一小部分。加上英文、日文、韩文的招牌后，进门的顾客立刻翻倍。

来看一组真实数据：

| 指标 | 数据 |
|------|------|
| App Store 覆盖地区 | 175+ 个国家和地区 |
| 非英语市场下载占比 | 约 70% |
| 支持多语言的 App 平均下载量提升 | 2~5 倍 |
| 日本/韩国用户付费意愿 | 全球 Top 5 |

### 竞品在做什么？

打开 App Store 搜索任意品类的前 10 名，你会发现：

- 头部 App 几乎都支持 **5 种以上语言**
- 很多中国出海 App（TikTok、Shein、Temu）支持 **30+ 种语言**
- 不做国际化的独立开发者，正在把全球用户拱手让给竞品

> 💡 **一句话总结**：国际化不是"锦上添花"，而是"不做就亏了"的必选项。

## 2. 国际化（i18n）vs 本地化（l10n）

这两个词经常被混用，但它们是不同的阶段，就像"装修设计"和"搬家具入住"的关系：

| | 国际化 i18n | 本地化 l10n |
|---|---|---|
| **全称** | Internationalization | Localization |
| **缩写由来** | i 和 n 之间 18 个字母 | l 和 n 之间 10 个字母 |
| **做什么** | 让 App **具备**支持多语言的能力 | 把具体语言内容**填进去** |
| **类比** | 装修时预留好插座和管道 | 买来电器插上、通水使用 |
| **开发者负责** | ✅ 代码层面 | ✅ 配合翻译团队 |
| **示例** | 用 `String(localized:)` 替代硬编码字符串 | 把 "Hello" 翻译成 "こんにちは" |

**工作流程**：

```
国际化（i18n）→ 导出文案 → 翻译 → 本地化（l10n）→ 导入 → 测试 → 发布
```

> ⚠️ **常见误区**：很多新手以为"加个翻译文件"就是国际化了。实际上，国际化还包括日期格式、货币符号、布局方向等方方面面，翻译只是其中一环。

## 3. App 国际化方案全景

### 方案一：单一 App 多语言（⭐ 推荐）

一个 App 包含所有语言，系统根据用户设置自动切换。

| 优点 | 缺点 |
|------|------|
| 只需维护一个 App | 包体积稍大（多语言文件占用） |
| 用户切换语言无需重新下载 | 某些地区审核可能要求默认语言为当地语言 |
| App Store 评分和评论统一积累 | — |
| 更新一次，所有语言同步 | — |

**实现方式**：String Catalog（Xcode 15+）或 Localizable.strings

### 方案二：按地区发布不同版本

在 App Store Connect 创建多个 App 记录，每个面向不同市场。

| 优点 | 缺点 |
|------|------|
| 可以针对不同市场深度定制 | 维护成本极高，每个版本都要单独更新 |
| 包体积最小 | 评分分散，无法积累口碑 |
| 可以做差异化功能 | 用户跨国旅行时可能无法使用 |

> ⚠️ **不推荐**独立开发者使用此方案，除非你有特殊合规需求（如中国版和海外版功能差异巨大）。

### 方案三：服务端动态下发文案

文案存储在服务器，App 启动时下载对应语言。

| 优点 | 缺点 |
|------|------|
| 无需发版即可修改文案 | 首次启动需要网络 |
| A/B 测试方便 | 离线场景无法使用 |
| 翻译更新实时生效 | 实现复杂度高 |
| — | App Store 审核可能对动态内容有要求 |

> 💡 **建议**：核心界面文案用方案一（本地化），运营活动文案用方案三（动态下发），两者结合效果最佳。

### 方案选择决策表

| 你的情况 | 推荐方案 |
|---------|---------|
| 独立开发者，刚起步 | 方案一 |
| 有运营团队，需要频繁改文案 | 方案一 + 方案三 |
| 不同地区功能差异大 | 方案二 |
| 大公司，资源充足 | 方案一 + 方案三 |

## 4. String Catalog 实战（Xcode 15+）

String Catalog 是 Xcode 15 引入的新机制，可以把它理解为一个**翻译管理表格**——所有需要翻译的文案都集中在这里，一目了然。

### 4.1 创建 String Catalog

1. 在 Xcode 中，`File → New → File...`
2. 搜索 **String Catalog**
3. 命名为 `Localizable.xcstrings`，保存到项目根目录

创建后你会看到一个 JSON 格式的文件，Xcode 会用可视化表格展示：

| Key | English | 中文（简体） | State |
|-----|---------|-------------|-------|
| welcome_message | Welcome | 欢迎 | ✅ Translated |
| settings_title | Settings | 设置 | ✅ Translated |
| save_button | Save | 保存 | ✅ Translated |

### 4.2 添加语言

1. 在 Xcode 中选中项目 → 选中 Target → Info 标签页
2. 在 `Localizations` 区域点击 `+` 号
3. 选择要添加的语言，如 Japanese（ja）、Korean（ko）

添加后，String Catalog 中会自动出现新语言的列。

### 4.3 代码中使用 String(localized:)

**之前（硬编码，❌ 不推荐）**：

```swift
Text("Welcome to my app")
```

**之后（国际化，✅ 推荐）**：

```swift
Text(String(localized: "welcome_message"))
```

或者使用更简洁的写法：

```swift
// 使用字符串插值
let userName = "小明"
Text(String(localized: "hello_user \(userName)"))

// 在 String Catalog 中，key 为 "hello_user %@"，%@ 是占位符
```

### 4.4 SwiftUI Text 自动本地化

SwiftUI 的 `Text` 视图有一个超能力：**自动本地化**。

```swift
// 这行代码会自动查找 Localizable.xcstrings 中的 "settings" key
Text("settings")

// 如果你不想自动本地化（比如显示用户输入的内容），用 verbatim
Text(verbatim: userRawInput)
```

> 💡 **自动本地化的原理**：SwiftUI 的 `Text("settings")` 实际上调用了 `Text(LocalizedStringKey("settings"))`，它会自动在 String Catalog 中查找对应的翻译。

### 4.5 完整示例

假设我们要做一个简单的设置页面：

```swift
struct SettingsView: View {
    @AppStorage("language") var language: String = "en"

    var body: some View {
        NavigationStack {
            List {
                Section {
                    HStack {
                        Text("language_label")
                        Spacer()
                        Picker("", selection: $language) {
                            Text("English").tag("en")
                            Text("中文").tag("zh-Hans")
                            Text("日本語").tag("ja")
                            Text("한국어").tag("ko")
                        }
                        .pickerStyle(.menu)
                    }
                } header: {
                    Text("settings_title")
                }

                Section {
                    NavigationLink {
                        AboutView()
                    } label: {
                        Text("about_label")
                    }
                }
            }
            .navigationTitle("settings_title")
        }
    }
}
```

对应的 String Catalog 内容：

| Key | English | 中文（简体） | 日本語 | 한국어 |
|-----|---------|-------------|--------|--------|
| settings_title | Settings | 设置 | 設定 | 설정 |
| language_label | Language | 语言 | 言語 | 언어 |
| about_label | About | 关于 | 概要 | 정보 |

> ⚠️ **注意**：`NavigationLink` 里的 `Text("about_label")` 也会自动本地化，因为 SwiftUI 的 `Text` 默认行为就是查找本地化字符串。

## 5. 日期/数字/货币本地化

不同国家看日期、数字、货币的习惯差异巨大，就像不同地方的人开车靠左还是靠右——没有对错，但必须入乡随俗。

### 5.1 日期格式化

| 地区 | 同一日期的显示 |
|------|--------------|
| 中国 | 2026年5月20日 |
| 美国 | May 20, 2026 |
| 日本 | 2026/05/20 |
| 德国 | 20.05.2026 |

```swift
import Foundation

let date = Date()

// 自动根据用户地区格式化
let formatted = date.formatted(date: .long, time: .short)
// 中国: "2026年5月20日 上午10:30"
// 美国: "May 20, 2026 at 10:30 AM"

// 指定地区
let japanFormatted = date.formatted(
    .dateTime
    .year()
    .month()
    .day()
    .locale(Locale(identifier: "ja_JP"))
)
// "2026年5月20日"
```

### 5.2 数字格式化

| 地区 | 同一数字的显示 |
|------|--------------|
| 中国 | 1,234,567.89 |
| 德国 | 1.234.567,89 |
| 法国 | 1 234 567,89 |
| 印度 | 12,34,567.89 |

```swift
let number = 1234567.89

// 自动格式化
let formatted = number.formatted()
// 中国: "1,234,567.89"
// 德国: "1.234.567,89"

// 指定格式
let percent = 0.85.formatted(.percent)
// 中国: "85%"
// 美国: "85%"
```

### 5.3 货币格式化

| 地区 | 同一金额的显示 |
|------|--------------|
| 中国 | ¥1,234.57 |
| 美国 | $1,234.57 |
| 日本 | ¥1,235 |
| 欧洲 | 1.234,57 € |

```swift
let price = 1234.567

// 自动根据地区显示货币
let formatted = price.formatted(.currency(code: "CNY"))
// 中国: "¥1,234.57"
// 美国: "CN¥1,234.57"（美国会加 CN 前缀区分）

let usdFormatted = price.formatted(.currency(code: "USD"))
// 美国: "$1,234.57"
// 中国: "US$1,234.57"
```

> 💡 **最佳实践**：永远不要手动拼接货币符号！用 `.formatted(.currency(code:))` 让系统处理，它会自动处理符号位置（€ 在欧洲放在后面）、小数位数（日元没有小数）等细节。

## 6. 布局适配

### 6.1 RTL 语言适配

阿拉伯语、希伯来语是从右到左（RTL）书写的，就像你从书的最后一页往前翻。

```
英语（LTR）:  [返回]  标题  [设置]     ← 从左到右
阿拉伯语（RTL）: [设置]  标题  [返回]   ← 从右到左
```

**SwiftUI 的好消息**：SwiftUI 默认自动处理 RTL 布局！

```swift
HStack {
    Text("back_button")
    Spacer()
    Text("settings_title")
}
// LTR: [返回] -------- [设置]
// RTL: [设置] -------- [返回]  ← 自动翻转！
```

**需要注意的例外**：

```swift
// 不希望翻转的内容（如进度条方向、图标方向）
HStack {
    Image(systemName: "arrow.right")
        .environment(\.layoutDirection, .leftToRight) // 强制 LTR
    Text("next_step")
}
```

### 6.2 文本长度变化适配

翻译后文本长度可能剧烈变化，就像同一句话用不同字体写出来占的宽度不同：

| 语言 | "Settings" | 长度变化 |
|------|-----------|---------|
| English | Settings | 基准 |
| 中文 | 设置 | 更短 |
| 德语 | Einstellungen | 更长（约 2 倍） |
| 法语 | Paramètres | 更长 |
| 芬兰语 | Asetukset | 更长 |

**应对策略**：

```swift
// ❌ 固定宽度——德语文字会截断
Text("settings_title")
    .frame(width: 80)

// ✅ 自适应宽度
Text("settings_title")
    .frame(minWidth: 80, maxWidth: 200)

// ✅ 使用 padding 而非固定宽度
Text("settings_title")
    .padding(.horizontal, 16)

// ✅ 允许换行
Text("long_description_text")
    .lineLimit(2...4)
    .fixedSize(horizontal: false, vertical: true)
```

**按钮适配**：

```swift
// ❌ 按钮文字可能被截断
Button("save_action") {}
    .frame(width: 60, height: 40)

// ✅ 按钮自适应文字长度
Button("save_action") {}
    .padding(.horizontal, 20)
    .padding(.vertical, 10)
    .background(Color.blue)
    .clipShape(RoundedRectangle(cornerRadius: 8))
```

> ⚠️ **测试技巧**：在模拟器中切换到德语或阿拉伯语测试布局，德语是"最长的常见语言"，阿拉伯语测试 RTL。

## 7. App Store Connect 多语言配置

App Store Connect 的多语言配置，就像给你的店铺挂上不同语言的招牌和介绍——用户看到什么语言，取决于他们的 App Store 地区设置。

### 7.1 本地化元数据

在 App Store Connect → 你的 App → 左侧菜单可添加本地化版本：

| 元数据字段 | 是否必须本地化 | 说明 |
|-----------|--------------|------|
| App 名称 | ✅ 强烈建议 | 用户搜索的第一入口 |
| 副标题 | ✅ 强烈建议 | 名称下方的补充说明 |
| 关键词 | ✅ 必须 | 不同语言搜索习惯完全不同 |
| 描述 | ✅ 强烈建议 | 详尽功能介绍 |
| What's New | ✅ 建议 | 更新日志 |
| 隐私政策 URL | ⚠️ 视情况 | 某些地区要求本地化版本 |
| 支持 URL | ⚠️ 视情况 | 建议提供多语言支持页面 |
| 截图 | ✅ 必须 | 界面文字必须对应语言 |

### 7.2 本地化截图

截图中的界面文字必须与对应语言一致，这是审核要求。

**截图策略**：

| 策略 | 优点 | 缺点 |
|------|------|------|
| 每种语言单独截图 | 最规范，审核无忧 | 工作量大 |
| 只截英文 + 其他语言 | 折中方案 | 部分地区体验不佳 |
| 用模拟器自动化截图 | 效率高 | 需要搭建自动化流程 |

**自动化截图方案**（推荐）：

```swift
// 在 Xcode Scheme 中添加 Screenshot 参数
// 然后在代码中判断
if CommandLine.arguments.contains("--screenshots") {
    // 使用预设数据，确保截图内容一致
}
```

> 💡 **实用建议**：优先做英语和中文截图，其他语言可以用英语截图 + 本地化描述先上线，后续逐步补充。

### 7.3 每种语言的关键词策略

关键词本地化不是翻译，而是**重新做 ASO**：

| 语言 | "记账 App" 的关键词思路 |
|------|----------------------|
| 中文 | 记账, 理财, 记账本, 花销, 预算 |
| English | expense tracker, budget, money manager, spending |
| 日本語 | 家計簿, お金管理, 出費, 予算 |
| 한국어 | 가계부, 지출관리, 예산, 돈관리 |

> ⚠️ **关键提醒**：不要直接翻译关键词！每个市场的用户搜索习惯不同，要用当地人的思维方式选择关键词。比如日本人搜"家計簿"（家计簿）而不是"記帳"。

## 8. 翻译方案对比

### 方案总览

| 方案 | 质量 | 成本 | 速度 | 适合场景 |
|------|------|------|------|---------|
| 人工翻译 | ⭐⭐⭐⭐⭐ | 💰💰💰 | 🐢 | 核心文案、品牌用语 |
| AI 翻译 | ⭐⭐⭐⭐ | 💰 | 🚀 | 大量文案、快速迭代 |
| 翻译平台 | ⭐⭐⭐⭐ | 💰💰 | 🏃 | 团队协作、持续更新 |
| 社区翻译 | ⭐⭐⭐ | 免费 | 🐢🐢 | 开源项目、粉丝社区 |

### 8.1 人工翻译

找专业译员或翻译公司翻译。

- **优点**：质量最高，能处理文化差异、双关语
- **缺点**：贵（每个语言 ¥0.1~0.3/字），慢（几天到几周）
- **推荐平台**：有道翻译、译马网、Gengo

### 8.2 AI 翻译

用 Claude、GPT 等 AI 辅助翻译。

- **优点**：极快（分钟级），便宜，可批量处理
- **缺点**：可能不够地道，需要人工校对
- **推荐工具**：Claude、ChatGPT、DeepL

### 8.3 翻译平台

专业的翻译管理平台，支持协作、版本控制、API 集成。

| 平台 | 免费额度 | 特色 |
|------|---------|------|
| Crowdin | 开源项目免费 | 社区翻译友好 |
| Phrase | 14 天试用 | 开发者工具链完善 |
| Lokalise | 14 天试用 | 设计师协作强 |
| Transifex | 15 天试用 | 自动化工作流 |

### 8.4 社区翻译

让用户帮你翻译，开源项目常用。

- **优点**：免费，用户参与感强
- **缺点**：质量参差不齐，进度不可控
- **适合**：开源项目、有活跃社区的产品

> 💡 **推荐组合**：AI 翻译做初稿 → 人工校对核心文案 → 翻译平台管理版本。这是性价比最高的方案。

## 9. 用 AI 辅助翻译实战

### 9.1 翻译 Prompt 模板

```
你是一位专业的 iOS App 本地化翻译专家。

## 任务
将以下 iOS App 界面文案从中文翻译为{目标语言}。

## 要求
1. 翻译要自然地道，符合{目标语言}用户的日常表达习惯
2. 界面文案要简洁，按钮文字不超过 2 个词，标题不超过 4 个词
3. 保持占位符格式不变（如 %@、%d、%lld）
4. 如果某个词在{目标语言}中有更常用的外来语，优先使用外来语
5. 注意礼貌级别：中文的"您"对应{目标语言}的正式表达

## 待翻译内容
| Key | 中文 |
|-----|------|
| welcome_message | 欢迎使用 |
| settings_title | 设置 |
| save_button | 保存 |
| delete_confirm | 确定要删除吗？ |
| empty_state | 还没有内容，点击添加 |
| error_network | 网络连接失败，请重试 |
| subscription_price | 每月 %@ |
| item_count | 共 %lld 项 |

## 输出格式
| Key | {目标语言} |
|-----|-----------|
```

### 9.2 批量翻译工作流

```
步骤 1：导出 String Catalog 中的中文文案
        ↓
步骤 2：整理成表格格式，发给 AI 翻译
        ↓
步骤 3：AI 返回翻译结果，人工快速校对
        ↓
步骤 4：将翻译填入 String Catalog
        ↓
步骤 5：运行 App，切换语言检查显示效果
        ↓
步骤 6：截图提交 App Store Connect
```

### 9.3 AI 翻译的注意事项

| 注意事项 | 说明 |
|---------|------|
| 占位符 | 确保 `%@`、`%d`、`%lld` 等格式不变 |
| 复数形式 | 英语有单复数，日语没有——需要分别处理 |
| 敬语级别 | 日语/韩语有敬语体系，UI 文案通常用"礼貌体" |
| 文化差异 | 某些比喻/俚语无法直译，需要意译 |
| 文字长度 | AI 可能翻译过长，需要提醒简洁 |

**复数处理示例**：

```swift
// String Catalog 中配置复数
// Key: "item_count"
// English:
//   ^[共 %lld 项](inflect: true)  ← Swift 5.7+ 语法
// 或者手动配置:
//   one: "1 item"
//   other: "%lld items"

// 中文只有 other: "共 %lld 项"
// 阿拉伯语有 6 种复数形式！
```

> ⚠️ **校对重点**：AI 翻译最容易出错的地方是占位符丢失和文字过长。校对时优先检查这两项。

## 10. 各市场优先级建议

不是所有语言都要一次性做完，就像开连锁店——先开最赚钱的店，再逐步扩张。

### 优先级排序

| 优先级 | 语言 | 覆盖市场 | 理由 |
|--------|------|---------|------|
| 🥇 第一批 | 英语 | 全球通用 | 覆盖最广，很多非英语国家用户也能用 |
| 🥇 第一批 | 简体中文 | 中国大陆 | 母语市场，必须做好 |
| 🥈 第二批 | 日语 | 日本 | 付费意愿极高，ARPU 全球前列 |
| 🥈 第二批 | 韩语 | 韩国 | 付费意愿高，App 市场活跃 |
| 🥉 第三批 | 德语 | 德国/奥地利/瑞士 | 欧洲最大市场，付费习惯好 |
| 🥉 第三批 | 法语 | 法国/加拿大/非洲 | 覆盖广，法语区用户多 |
| 🥉 第三批 | 西班牙语 | 西班牙/拉美 | 覆盖 20+ 国家 |
| 🏅 第四批 | 葡萄牙语 | 巴西/葡萄牙 | 巴西市场增长快 |
| 🏅 第四批 | 繁体中文 | 台湾/香港 | 与简体中文翻译成本低 |
| 🏅 第四批 | 阿拉伯语 | 中东 | 市场潜力大，但 RTL 适配成本高 |

### 按品类调整

| App 品类 | 额外优先语言 | 原因 |
|---------|------------|------|
| 游戏 | 韩语、葡萄牙语 | 游戏市场大 |
| 工具类 | 德语、法语 | 付费意愿高 |
| 社交类 | 西班牙语、葡萄牙语 | 用户基数大 |
| 教育类 | 日语、韩语 | 重视教育投入 |

> 💡 **实用建议**：第一批语言（英语 + 中文）在 1.0 版本就做好。第二批语言可以在 1.1 版本加入。不要等到"完美"才上线，先覆盖核心市场再迭代。

## 11. 国际化检查清单

在提交多语言版本前，逐项检查：

### 代码层面

- [ ] 所有用户可见字符串都使用了 `String(localized:)` 或 SwiftUI `Text` 自动本地化
- [ ] 没有硬编码的字符串（搜索代码中的中文字面量）
- [ ] 日期使用 `.formatted()` 而非手动拼接
- [ ] 数字使用 `.formatted()` 而非手动格式化
- [ ] 货币使用 `.formatted(.currency(code:))` 而非手动拼接符号
- [ ] 复数形式已正确配置（特别是英语）
- [ ] 占位符格式正确（`%@`、`%lld` 等）

### 布局层面

- [ ] 使用自适应布局，没有固定宽度截断文字
- [ ] 测试了德语（最长文本）的布局
- [ ] 测试了阿拉伯语（RTL）的布局
- [ ] 图片/图标没有文化敏感内容
- [ ] 颜色在不同文化中没有负面含义

### 内容层面

- [ ] String Catalog 中所有 key 都有对应语言的翻译
- [ ] 翻译经过人工校对（至少核心文案）
- [ ] 没有未翻译的 key 显示为 key 名
- [ ] 截图中界面文字与语言一致

### App Store Connect 层面

- [ ] 每种语言的 App 名称已填写
- [ ] 每种语言的副标题已填写
- [ ] 每种语言的关键词已本地化（不是直译）
- [ ] 每种语言的描述已翻译
- [ ] 每种语言的 What's New 已翻译
- [ ] 截图已本地化（至少英语 + 中文）

### 测试层面

- [ ] 在模拟器中切换到每种语言测试
- [ ] 在模拟器中切换到阿拉伯语测试 RTL
- [ ] 检查所有界面的文字显示完整
- [ ] 检查日期/数字/货币显示正确
- [ ] 检查 App Store 预览页各语言显示正确

> ⚠️ **最后提醒**：国际化是一个持续的过程，不是一次性的任务。每次新增功能都要同步更新所有语言的文案，否则就会出现"一半中文一半英文"的尴尬局面。建议在代码审查流程中加入"是否有硬编码字符串"的检查项。

## 小结

| 知识点 | 一句话总结 |
|--------|-----------|
| 为什么要做国际化 | 不做就等于放弃 70% 的全球市场 |
| i18n vs l10n | i18n 是预留能力，l10n 是填入内容 |
| 方案选择 | 推荐"单一 App 多语言"方案 |
| String Catalog | Xcode 15+ 的翻译管理利器，可视化、易操作 |
| 日期/数字/货币 | 永远用 Formatter，不要手动拼接 |
| RTL 适配 | SwiftUI 自动处理大部分情况，注意例外 |
| App Store 本地化 | 名称、关键词、截图必须本地化 |
| 翻译方案 | AI 初稿 + 人工校对 = 性价比之王 |
| 市场优先级 | 英语 → 中日韩 → 欧洲语言 → 其他 |
| 检查清单 | 提交前逐项打勾，不遗漏 |

记住：**国际化不是一次做完就结束的项目，而是贯穿 App 生命周期的习惯**。从第一个字符串开始用 `String(localized:)`，你就已经走在正确的路上了。
