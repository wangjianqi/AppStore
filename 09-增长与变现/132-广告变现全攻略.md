- 理解移动广告生态的运作方式和常见广告类型

- 实战集成 Google AdMob SDK 到 SwiftUI 项目

## 一、广告变现概述

### 1.1 移动广告生态：一条"带货流水线"

想象一条流水线：工厂生产商品（广告主想推广）→ 批发商负责分发（广告平台撮合）→ 零售店铺展示给顾客（开发者的 App 展示给用户）。三方各取所需：

| 角色 | 类比 | 职责 |
|------|------|------|
| 广告主 | 工厂/品牌方 | 出钱投放广告，希望获取用户 |
| 广告平台 | 批发商/中介 | 撮合交易，提供 SDK，结算分成 |
| 开发者 | 零售店铺 | 提供 App 流量展示广告，赚取收入 |

> 💡 开发者赚的不是广告主的钱，而是广告平台从广告主那里收钱后分给你的"佣金"。一般分成比例在 60%~90% 不等。

### 1.2 常见广告类型

| 广告类型 | 样子 | 用户体验 | 收益 | 典型场景 |
|----------|------|----------|------|----------|
| **Banner** | 横幅条，常驻屏幕底部/顶部 | 干扰小，但容易被忽视 | 低 | 工具类 App 底部 |
| **插屏** | 全屏/半屏弹出，需关闭 | 中等干扰 | 中 | 关卡切换、页面跳转时 |
| **激励视频** | 看完视频获得奖励 | 用户主动选择 | 高 | 游戏复活、获取金币 |
| **原生** | 融入 App 内容流，样式自定义 | 干扰最小 | 中高 | 信息流、列表中穿插 |
| **开屏** | App 启动时全屏展示 | 等待感，可跳过 | 高 | App 冷启动时 |

> 💡 激励视频是"双赢"模式——用户主动看广告换奖励，广告主获得高关注度，开发者获得高 eCPM，三方都开心。

### 1.3 各广告类型 eCPM 参考表

eCPM（effective Cost Per Mille）= 每千次广告展示的有效收入，是衡量广告收益的核心指标。

| 广告类型 | 国内 eCPM（¥） | 海外 eCPM（$） | 说明 |
|----------|----------------|----------------|------|
| Banner | 2~8 | 0.3~1.5 | 收益最低，胜在稳定 |
| 插屏 | 15~50 | 3~12 | 中等收益，注意频次 |
| 激励视频 | 60~200 | 8~40 | 收益最高，游戏类尤其突出 |
| 原生 | 20~80 | 2~10 | 收益取决于融入程度 |
| 开屏 | 30~100 | 5~20 | 展示机会少但单价高 |

> ⚠️ eCPM 受行业、地区、用户质量、时段等影响极大，上表仅为参考范围，实际以平台数据为准。

### 1.4 什么类型的 App 适合广告变现？

| 适合程度 | App 类型 | 原因 |
|----------|----------|------|
| ⭐⭐⭐⭐⭐ | 休闲游戏 | 用户量大、停留时间长、激励视频天然场景 |
| ⭐⭐⭐⭐ | 工具类（天气、日历） | 高频使用、Banner/原生广告位多 |
| ⭐⭐⭐ | 资讯/内容类 | 信息流中原生广告融入自然 |
| ⭐⭐⭐ | 社交/社区类 | 用户粘性高，但需注意广告干扰体验 |
| ⭐⭐ | 效率/专业工具 | 用户付费意愿强，更适合内购 |
| ⭐ | 高端付费 App | 广告会严重损害品牌形象 |

> 💡 一个简单判断：如果你的 App 用户愿意免费使用但不太愿意付费，那广告变现就是好选择；如果用户付费意愿强，优先内购。

## 四、资质与合规要求

### 4.1 国内广告资质

做广告变现不是"挂个广告就完事"，国内有严格的资质要求：

| 资质 | 说明 | 是否必须 | 获取方式 |
|------|------|----------|----------|
| 营业执照 | 个体工商户或企业 | 必须 | 当地市场监管局办理 |
| ICP 备案 | 网站/App 备案号 | 必须 | 工信部备案系统 |
| App 备案 | 2023 年起新要求 | 必须 | 通过云服务商提交 |

> ⚠️ 2023 年 8 月起，工信部要求所有 App 上架前必须完成备案。未备案的 App 将无法上架应用商店，也无法接入国内广告平台。

**个人开发者怎么办？**

1. 注册个体工商户（最简单，费用低）
2. 用个体工商户营业执照申请 ICP 备案
3. 完成 App 备案后再接入广告平台

> 💡 个体工商户注册成本通常在 0~200 元，很多城市支持线上办理，1~3 个工作日即可拿到执照。

### 4.2 《广告法》合规

| 违规类型 | 说明 | 后果 |
|----------|------|------|
| 虚假宣传 | 夸大效果、伪造数据 | 罚款 20~100 万 |
| 医疗广告 | 未经审查发布医疗广告 | 罚款 + 下架 |
| 教育广告 | 承诺升学/通过率 | 罚款 + 下架 |
| 误导性广告 | 诱导点击、伪装成系统通知 | 平台封号 |

> ⚠️ 你作为开发者，虽然不直接制作广告内容，但如果你的 App 展示了违法广告，也可能承担连带责任。选择正规广告平台（如穿山甲、优量汇）可以规避大部分风险，因为平台会审核广告内容。

### 4.3 《个人信息保护法》

| 要求 | 说明 | 实操 |
|------|------|------|
| 用户同意 | 收集个人信息前需获得明确同意 | 展示隐私政策弹窗 |
| 最小必要 | 只收集必要的信息 | 不请求与功能无关的权限 |
| 数据安全 | 妥善保管用户数据 | 加密存储、不泄露 |
| 撤回同意 | 用户可随时撤回同意 | 提供设置入口 |

### 4.4 Apple 审核对广告的要求

这是 iOS 开发者最需要关注的部分，Apple 对广告有严格规定：

#### App Tracking Transparency（ATT）框架

从 iOS 14.5 开始，Apple 强制要求所有 App 在追踪用户跨应用行为前，必须通过 ATT 框架请求用户授权。

> ⚠️ 不请求 ATT 授权就使用 IDFA 追踪用户 = 直接被拒！这是目前广告相关被拒的第一大原因。

**ATT 授权流程：**

```
App 启动 → 展示 ATT 弹窗 → 用户选择
                              ├── 允许 → 可使用 IDFA
                              ├── 不允许 → IDFA 返回全零
                              └── 未选择 → IDFA 返回全零
```

**IDFA（广告标识符）使用规范：**

| 场景 | 是否需要 ATT | 说明 |
|------|-------------|------|
| 展示广告 | 需要 | 广告归因和定向需要 IDFA |
| 广告归因（安装来源追踪） | 需要 | 判断用户从哪个广告安装 |
| 个性化广告推荐 | 需要 | 基于用户行为推荐广告 |
| 非个性化广告 | 不需要 | 不使用 IDFA 也可展示 |

> 💡 即使不使用 IDFA，广告仍然可以展示，只是无法做到精准定向，eCPM 会降低。根据行业数据，ATT 授权率大约在 25%~40% 之间。

#### Info.plist 必填项

```xml
<key>NSUserTrackingUsageDescription</key>
<string>我们将使用您的数据向您提供更相关的个性化广告体验</string>
```

> ⚠️ 描述文字必须说明用途，不能为空或过于笼统，否则会被拒。

### 4.5 儿童隐私保护

| 法规 | 适用地区 | 核心要求 |
|------|----------|----------|
| COPPA | 美国 | 13 岁以下用户需家长同意 |
| 国内儿童个人信息保护规定 | 中国 | 14 岁以下需监护人同意 |
| App Store 审核 5.1.4 | 全球 | 儿童类 App 不得使用广告追踪 |

> ⚠️ 如果你的 App 定位为儿童类（Kids 类别），App Store 审核要求极其严格：不得使用 IDFA、不得展示行为定向广告、不得包含第三方广告追踪。建议儿童 App 直接走内购/付费模式。

### 5.2 Banner 广告实现

```swift
import GoogleMobileAds
import SwiftUI

struct BannerAdView: UIViewRepresentable {
    let adUnitID: String

    func makeUIView(context: Context) -> GADBannerView {
        let banner = GADBannerView(adSize: GADAdSizeBanner)
        banner.adUnitID = adUnitID
        banner.rootViewController = UIApplication.shared.connectedScenes
            .compactMap { ($0 as? UIWindowScene)?.keyWindow?.rootViewController }
            .first
        banner.load(GADRequest())
        return banner
    }

    func updateUIView(_ uiView: GADBannerView, context: Context) {}
}
```

```swift
            BannerAdView(adUnitID: "ca-app-pub-3940256099942544/2934735716")
                .frame(height: 50)
        }
    }
}
```

> 💡 上面的广告单元 ID `ca-app-pub-3940256099942544/2934735716` 是 Google 官方提供的测试 Banner ID，开发阶段请使用测试 ID，否则可能被判定为无效点击。

### 5.3 插屏广告实现

```swift
import GoogleMobileAds

class InterstitialAdManager: NSObject, GADFullScreenContentDelegate {
    private var interstitialAd: GADInterstitialAd?

    func loadAd(adUnitID: String) {
        GADInterstitialAd.load(
            withAdUnitID: adUnitID,
            request: GADRequest()
        ) { [weak self] ad, error in
            if let error = error {
                print("插屏广告加载失败: \(error.localizedDescription)")
                return
            }
            self?.interstitialAd = ad
            self?.interstitialAd?.fullScreenContentDelegate = self
        }
    }

    func showAd() {
        guard let ad = interstitialAd else {
            print("广告未就绪")
            return
        }

        guard let rootVC = UIApplication.shared.connectedScenes
            .compactMap({ ($0 as? UIWindowScene)?.keyWindow?.rootViewController })
            .first else {
            return
        }

        ad.present(fromRootViewController: rootVC)
    }

    func adDidDismissFullScreenContent(_ ad: GADFullScreenPresentingAd) {
        loadAd(adUnitID: ad.adUnitID)
    }
}
```

### 5.5 ATT 权限请求代码

```swift
import AppTrackingTransparency
import AdSupport

class ATTManager: ObservableObject {
    @Published var authorizationStatus: ATTrackingManager.AuthorizationStatus = .notDetermined

    func requestAuthorization() {
        ATTrackingManager.requestTrackingAuthorization { [weak self] status in
            DispatchQueue.main.async {
                self?.authorizationStatus = status
                switch status {
                case .authorized:
                    print("用户允许追踪，IDFA: \(ASIdentifierManager.shared().advertisingIdentifier)")
                case .denied:
                    print("用户拒绝追踪")
                case .notDetermined:
                    print("用户未选择")
                case .restricted:
                    print("追踪受限")
                @unknown default:
                    break
                }
            }
        }
    }
}
```

> ⚠️ ATT 请求时机很重要！不要在 App 启动时立即弹出，应该等用户与 App 互动后再请求。最佳实践：用户首次进入有广告的页面时请求，或者在"设置"页面提供手动开启选项。

## 六、广告优化策略

### 6.1 广告位设计：不干扰核心体验

广告位设计就像店铺里放广告牌——放在顾客必经之路但不挡路。

| 好的设计 ✅ | 坏的设计 ❌ |
|------------|------------|
| 页面底部固定 Banner | 页面顶部遮挡导航栏 |
| 关卡切换时展示插屏 | 游戏进行中弹出插屏 |
| 信息流中穿插原生广告 | 伪装成功能按钮诱导点击 |
| 用户主动选择看激励视频 | 强制看广告才能继续使用 |

### 6.2 水位优化：eCPM 最大化

"水位"就是广告的展示优先级。就像水库放水，先放高水位（高 eCPM）的，再放低水位的。

**Mediation（中介）策略：**

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 瀑布流（Waterfall） | 按 eCPM 从高到低排序，依次请求 | 传统方式，稳定 |
| 竞价（Bidding） | 多平台实时竞价，最高价获胜 | 新方式，收益更高 |
| 混合模式 | 瀑布流 + 竞价结合 | 推荐方式 |

> 💡 AdMob Mediation 支持接入穿山甲、优量汇等国内平台，实现"一个 SDK 多平台收益"。但配置较复杂，建议先单平台跑通再加 Mediation。

### 6.3 收益排序

```
激励视频 > 插屏 > 原生 > 开屏 > Banner
  (最高)    (高)   (中高)  (中高)  (最低)
```

**优化建议：**

1. 优先设计激励视频场景——这是收益最高的广告类型
2. 插屏放在自然断点——关卡结束、页面切换
3. Banner 作为兜底——覆盖面广但单价低
4. 原生融入内容——用户体验好但开发成本高

### 6.4 广告频次控制

| 广告类型 | 建议频次 | 说明 |
|----------|----------|------|
| Banner | 常驻展示 | 不需要频控，但注意位置 |
| 插屏 | 每 3~5 分钟一次 | 太频繁会导致用户流失 |
| 激励视频 | 不限（用户主动） | 用户自己选择，不需要频控 |
| 开屏 | 每次冷启动一次 | 自然限制，无需额外控制 |

```swift
class AdFrequencyManager {
    private var lastInterstitialTime: Date = .distantPast
    private let minimumInterval: TimeInterval = 180 // 3 分钟

    func canShowInterstitial() -> Bool {
        let now = Date()
        guard now.timeIntervalSince(lastInterstitialTime) >= minimumInterval else {
            return false
        }
        lastInterstitialTime = now
        return true
    }
}
```

### 6.5 A/B 测试广告位

| 测试变量 | 选项 A | 选项 B | 观察指标 |
|----------|--------|--------|----------|
| Banner 位置 | 底部 | 顶部 | eCPM、留存率 |
| 插屏频次 | 3 分钟 | 5 分钟 | ARPU、7 日留存 |
| 激励视频奖励 | 50 金币 | 100 金币 | 观看率、ARPU |
| 原生广告密度 | 每 5 条内容 | 每 10 条内容 | eCPM、用户停留时长 |

> ⚠️ A/B 测试至少运行 7 天，样本量足够大（每组至少 1000 用户）才能得出可靠结论。不要只看短期收益，留存率和用户满意度同样重要。

## 七、广告+内购混合变现

### 7.1 为什么需要混合变现？

纯广告变现的天花板很低——就像只靠门口发传单招揽顾客，而内购是让愿意付费的用户直接消费。两者结合才能最大化收入。

| 模式 | 优点 | 缺点 | ARPU |
|------|------|------|------|
| 纯广告 | 零门槛，用户多 | 收益低，体验差 | 低 |
| 纯内购 | 收益高，体验好 | 付费率低（1%~5%） | 中高 |
| 混合变现 | 覆盖全用户群 | 实现复杂 | 最高 |

### 7.2 去广告作为内购选项

最常见的混合模式：免费用户看广告，付费用户去广告。

```swift
import StoreKit

enum AdRemovalOption {
    case oneTimePurchase
    case monthlySubscription
    case yearlySubscription
}

class AdRemovalManager: ObservableObject {
    @Published var isAdRemoved = false

    func purchase(_ option: AdRemovalOption) async throws {
        let productID: String
        switch option {
        case .oneTimePurchase:
            productID = "com.example.app.remove_ads"
        case .monthlySubscription:
            productID = "com.example.app.remove_ads_monthly"
        case .yearlySubscription:
            productID = "com.example.app.remove_ads_yearly"
        }

        let products = try await Product.products(for: [productID])
        guard let product = products.first else { return }

        let result = try await product.purchase()
        switch result {
        case .success(let verification):
            switch verification {
            case .verified:
                isAdRemoved = true
            case .unverified:
                print("购买验证失败")
            }
        case .userCancelled:
            print("用户取消购买")
        case .pending:
            print("购买待处理")
        @unknown default:
            break
        }
    }

    func restorePurchases() async {
        for await result in Transaction.currentEntitlements {
            if case .verified(let transaction) = result {
                if transaction.productID.hasPrefix("com.example.app.remove_ads") {
                    isAdRemoved = true
                }
            }
        }
    }
}
```

### 7.3 订阅去广告 vs 一次性买断

| 对比项 | 订阅制 | 一次性买断 |
|--------|--------|------------|
| 收入模式 | 持续收入 | 一次性收入 |
| 用户接受度 | 较低（反感订阅） | 较高（买断安心） |
| LTV | 高（持续续费） | 低（一次付清） |
| 定价参考 | ¥6~18/月 | ¥18~68 |
| 适合场景 | 高频使用 App | 低频工具 App |

> 💡 最佳实践：同时提供两种选项！让用户自己选择。数据显示，约 70% 选择一次性买断，30% 选择订阅，但订阅用户的 LTV 远高于买断用户。

### 7.4 混合模式最佳实践

```
免费用户 → 看广告（Banner + 插屏 + 激励视频）
    ↓
轻度付费 → 去广告订阅（¥12/月）
    ↓
深度付费 → 去广告买断（¥48）+ 增值功能内购
```

**关键原则：**

1. **广告不能"惩罚"免费用户**——广告是免费使用的代价，不是折磨
2. **去广告选项要明显**——让用户知道可以付费去广告
3. **激励视频在付费后仍可保留**——付费用户也可能主动看广告换奖励
4. **不要同时弹内购和广告**——选择一种变现方式，不要叠加干扰

```swift
struct AdAwareView<AdContent: View, PremiumContent: View>: View {
    @ObservedObject var adRemoval: AdRemovalManager
    let adContent: () -> AdContent
    let premiumContent: () -> PremiumContent

    var body: some View {
        if adRemoval.isAdRemoved {
            premiumContent()
        } else {
            adContent()
        }
    }
}
```

## 八、常见审核被拒原因

### 8.1 广告相关被拒汇总

| 被拒原因 | 审核条款 | 解决方案 |
|----------|----------|----------|
| 未请求 ATT 就追踪用户 | 5.1.2 | 添加 ATT 请求代码 |
| 强制看广告才能使用核心功能 | 3.1.1 | 广告不能是使用 App 的前提条件 |
| 广告误触设计 | 2.1 / 3.1.1 | 广告与功能按钮保持足够间距 |
| 广告内容不当 | 4.2 | 使用正规广告平台，设置内容过滤 |
| 儿童类 App 使用广告追踪 | 5.1.4 | 儿童类 App 不使用 IDFA |
| 广告伪装成系统通知 | 3.1.1 | 广告必须明确标识 |
| 关闭按钮不可见/太小 | 3.1.1 | 关闭按钮清晰可见，最小 44pt |
| 广告刷新过快 | 3.1.1 | Banner 刷新间隔 ≥ 30 秒 |

### 8.2 强制看广告

**被拒场景：** 用户必须看完广告才能使用 App 的核心功能。

```swift
// ❌ 错误做法：强制看广告
func loadHomePage() {
    interstitialAd.show() // 必须看完才能继续
    showHomeContent()
}

// ✅ 正确做法：广告是可选的
func loadHomePage() {
    showHomeContent() // 先展示内容
    if adFrequencyManager.canShowInterstitial() {
        interstitialAd.show() // 在自然节点展示
    }
}
```

### 8.3 误触广告

**被拒场景：** 广告紧贴操作按钮，用户容易误点。

```swift
// ❌ 错误做法：广告紧贴按钮
VStack(spacing: 2) {
    Button("确认") { /* ... */ }
    BannerAdView(adUnitID: "...") // 太近了！
}

// ✅ 正确做法：保持足够间距
VStack(spacing: 0) {
    Button("确认") { /* ... */ }
        .padding(.bottom, 16)

    Spacer()

    BannerAdView(adUnitID: "...")
        .frame(height: 50)
}
```

> ⚠️ Apple 审核指南明确要求：广告与 App 的交互元素之间必须有足够的间距，防止用户误触。建议间距至少 8pt，最好 16pt 以上。

### 8.4 广告内容不当

| 不当内容 | 处理方式 |
|----------|----------|
| 赌博/色情广告 | AdMob 后台设置内容过滤等级 |
| 竞品广告 | 使用屏蔽控制排除竞品 |
| 与 App 受众不匹配 | 设置受众年龄和兴趣标签 |
| 虚假下载按钮 | 使用正规平台，避免低质广告网络 |

**AdMob 内容过滤设置：**

```
AdMob 控制台 → 屏蔽控制 → 广告内容审核
  - 最大广告内容评级：G（适合所有年龄）/ PG / T / MA
  - 品牌安全：屏蔽敏感类别
  - 竞品屏蔽：添加竞争对手域名
```

> 💡 对于面向大众的 App，建议将最大广告内容评级设为 G 或 PG，避免出现不适宜的广告内容。

## 小结

| 本章要点 | 关键内容 |
|----------|----------|
| 广告生态 | 广告主→广告平台→开发者，三方各取所需 |
| 广告类型 | 激励视频收益最高，Banner 最稳定 |
| 国内平台 | 穿山甲/优量汇/百度/快手，需营业执照+ICP 备案 |
| 国外平台 | AdMob 新手首选，无需特殊资质 |
| 合规要求 | ATT 授权、IDFA 规范、儿童隐私保护 |
| 集成实战 | AdMob SDK + SwiftUI，Banner/插屏/激励视频 |
| 优化策略 | 激励视频优先、频次控制、A/B 测试 |
| 混合变现 | 广告+内购，去广告作为付费选项 |
| 审核避坑 | 不强制看广告、防误触、内容过滤 |

**核心心法：** 广告变现不是"越多越好"，而是"越精准越好"。好的广告体验 = 用户不反感 + 广告主满意 + 开发者赚钱，三方共赢才是可持续的变现模式。

> 💡 下一步建议：先从 AdMob 单平台跑通，积累数据后再考虑 Mediation 和混合变现。不要一上来就接入所有平台，先把一个平台做到极致。
