## Git 安装与配置

### Git 是什么？

Git 是一个**版本管理工具**。通俗地说，它就像游戏的"存档系统"——你每写一段代码，就可以"存一次档"（提交 commit），以后如果代码改坏了，随时可以"读档"（回退 revert）回到之前的版本。

多人协作时，Git 更是不可或缺：每个人在自己的分支上开发，最后合并到一起，互不干扰。

### 验证 Git 是否已安装

macOS 自带 Git，打开终端输入以下命令验证：

```bash
git --version
```

如果输出类似 `git version 2.39.5`，说明已经安装好了。

> ⚠️ **注意**：如果提示"git 不是可用命令"，说明 Xcode Command Line Tools 未安装，执行以下命令安装：
> ```bash
> xcode-select --install
> ```
> 弹出安装窗口后，点击"安装"即可。

### 配置用户名和邮箱

Git 每次提交代码时，都会记录是谁提交的，所以需要先配置你的用户名和邮箱：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

💡 **提示**：这里的邮箱建议使用你注册 GitHub / GitLab 的邮箱，这样提交记录能正确关联到你的账号。

验证配置是否成功：

```bash
git config --global --list
```

输出中应该能看到你刚设置的 `user.name` 和 `user.email`。

### 生成 SSH Key

SSH Key 是一种加密认证方式，配置后你可以免密码推送代码到 GitHub / GitLab，而不需要每次都输入密码。

**生成新的 SSH Key：**

```bash
ssh-keygen -t ed25519 -C "你的邮箱@example.com"
```

执行后会依次提示：

| 提示 | 建议操作 |
|---|---|
| `Enter file in which to save the key` | 直接按 **回车**（使用默认路径 `~/.ssh/id_ed25519`） |
| `Enter passphrase` | 直接按 **回车**（不设密码），或输入一个密码增加安全性 |
| `Enter same passphrase again` | 再次按 **回车**，或重复输入密码 |

**查看公钥内容：**

```bash
cat ~/.ssh/id_ed25519.pub
```

输出类似：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... 你的邮箱@example.com
```

把整行内容**完整复制**，后面配置 GitHub / GitLab 时需要用到。

### 配置 GitHub SSH Key

1. 打开 [GitHub](https://github.com)，登录你的账号
2. 点击右上角头像 → **Settings**
3. 左侧菜单选择 **SSH and GPG keys**
4. 点击 **New SSH key**
5. Title 随便填（如"MacBook Pro"），Key 粘贴刚才复制的公钥
6. 点击 **Add SSH key**

**验证连接是否成功：**

```bash
ssh -T git@github.com
```

首次连接会提示 `Are you sure you want to continue connecting (yes/no/[fingerprint])?`，输入 `yes` 回车。如果看到：

```
Hi 你的用户名! You've successfully authenticated, but GitHub does not provide shell access.
```

说明配置成功！

### 配置 GitLab SSH Key

流程与 GitHub 类似：

1. 登录 GitLab
2. 点击头像 → **Preferences**（或 **Edit Profile**）
3. 左侧选择 **SSH Keys**
4. 粘贴公钥，点击 **Add key**

验证：

```bash
ssh -T git@gitlab.com
```

## Homebrew 包管理器

### Homebrew 是什么？

Homebrew 是 macOS 的**命令行版"应用商店"**。有了它，你只需要一行命令就能安装、更新、卸载各种开发工具和软件，不用到处找安装包、拖拽到 Applications 文件夹。

比如安装 wget，只需要：

```bash
brew install wget
```

就这么简单！

### 安装 Homebrew

打开终端，执行以下命令：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

安装过程中会提示你按 **回车** 确认，按提示操作即可。

> ⚠️ **注意**：安装过程可能较慢，取决于网络情况。如果下载失败，请参考下面的镜像配置。

**安装完成后的额外步骤：**

如果你使用的是 Apple Silicon（M1/M2/M3/M4）芯片的 Mac，Homebrew 默认安装在 `/opt/homebrew` 目录下，需要手动添加环境变量。安装脚本的末尾会提示你执行两条命令，类似：

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

> 💡 **提示**：安装脚本最后几行有 `Next steps` 提示，**务必按照提示执行**，否则终端可能找不到 `brew` 命令。

**验证安装：**

```bash
brew --version
```

输出类似 `Homebrew 4.x.x` 即安装成功。

### 国内用户镜像配置

如果你在国内，访问 GitHub 下载 Homebrew 及其软件包可能会很慢甚至失败。配置国内镜像源可以大幅提速。

**方法一：使用清华镜像源（推荐）**

在终端依次执行以下命令：

```bash
# 替换 Homebrew 核心仓库源
git -C "$(brew --repo)" remote set-url origin https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/brew.git

# 替换 Homebrew 核心软件源
git -C "$(brew --repo homebrew/core)" remote set-url origin https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/homebrew-core.git

# 替换 Homebrew cask 软件源
git -C "$(brew --repo homebrew/cask)" remote set-url origin https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/homebrew-cask.git

# 替换 Bottles 源（二进制预编译包）
echo 'export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles' >> ~/.zprofile
source ~/.zprofile
```

**方法二：使用中科大镜像源**

```bash
git -C "$(brew --repo)" remote set-url origin https://mirrors.ustc.edu.cn/brew.git
git -C "$(brew --repo homebrew/core)" remote set-url origin https://mirrors.ustc.edu.cn/homebrew-core.git
git -C "$(brew --repo homebrew/cask)" remote set-url origin https://mirrors.ustc.edu.cn/homebrew-cask.git
echo 'export HOMEBREW_BOTTLE_DOMAIN=https://mirrors.ustc.edu.cn/homebrew-bottles' >> ~/.zprofile
source ~/.zprofile
```

> 💡 **提示**：如果将来想恢复官方源，只需把上面的 URL 替换回 `https://github.com/Homebrew/brew.git` 等原始地址即可。

### 基本使用

| 命令 | 说明 |
|---|---|
| `brew install <包名>` | 安装软件 |
| `brew uninstall <包名>` | 卸载软件 |
| `brew search <关键词>` | 搜索软件 |
| `brew list` | 查看已安装的软件 |
| `brew info <包名>` | 查看软件信息 |
| `brew update` | 更新 Homebrew 自身和软件列表 |
| `brew upgrade` | 升级所有已安装的软件 |
| `brew upgrade <包名>` | 升级指定软件 |
| `brew cleanup` | 清理旧版本缓存，释放磁盘空间 |
| `brew doctor` | 诊断 Homebrew 是否有问题 |

> 💡 **提示**：建议定期执行 `brew update && brew upgrade && brew cleanup` 来保持工具链最新。

## 终端基础操作

### 终端是什么？

终端（Terminal）是你与 Mac 进行"文字对话"的窗口。你输入命令，Mac 执行命令并返回结果。在开发过程中，你会频繁使用终端来运行各种工具和命令。

### 打开终端的 3 种方式

| 方式 | 操作 |
|---|---|
| **方式一：聚焦搜索** | 按 `Command + 空格`，输入"终端"或"Terminal"，回车 |
| **方式二：Launchpad** | 打开 Launchpad → 其他 → 终端 |
| **方式三：Finder** | 打开 Finder → 应用程序 → 实用工具 → 终端 |

> 💡 **提示**：推荐使用方式一，`Command + 空格` 是 Mac 上最快捷的搜索方式，学会后效率翻倍！

### 常用命令速查表

| 命令 | 说明 | 示例 |
|---|---|---|
| `pwd` | 显示当前所在目录 | `pwd` → `/Users/你的用户名` |
| `ls` | 列出当前目录的文件和文件夹 | `ls` |
| `ls -la` | 列出详细信息（含隐藏文件） | `ls -la` |
| `cd <路径>` | 切换到指定目录 | `cd Documents` |
| `cd ..` | 返回上一级目录 | `cd ..` |
| `cd ~` | 返回用户主目录 | `cd ~` |
| `mkdir <目录名>` | 创建新文件夹 | `mkdir MyProject` |
| `rm <文件名>` | 删除文件 | `rm test.txt` |
| `rm -r <目录名>` | 删除文件夹及其内容 | `rm -r OldProject` |
| `cp <源> <目标>` | 复制文件 | `cp a.txt b.txt` |
| `mv <源> <目标>` | 移动/重命名文件 | `mv old.txt new.txt` |
| `cat <文件名>` | 查看文件内容 | `cat README.md` |
| `echo <内容>` | 输出文字 | `echo "Hello"` |
| `clear` | 清空终端屏幕 | `clear` |
| `man <命令>` | 查看命令帮助文档 | `man ls` |

> ⚠️ **警告**：`rm` 命令删除的文件**不会进入回收站**，删除即消失，务必小心！特别是 `rm -rf /` 这种命令，**绝对不要执行**，会删除整个系统。

### 文件路径概念

在终端中操作文件，需要理解"路径"的概念——它就是文件在电脑中的"地址"。

**绝对路径**：从根目录 `/` 开始的完整地址，类似于"中国→北京市→朝阳区→某某街道"

```
/Users/你的用户名/Documents/MyProject
```

**相对路径**：相对于你当前所在目录的地址，类似于"往前走50米右转"

```
# 假设你当前在 /Users/你的用户名 目录
cd Documents/MyProject    # 相对路径，等同于绝对路径的简写
```

常用路径符号：

| 符号 | 含义 |
|---|---|
| `/` | 根目录（最顶层） |
| `~` | 用户主目录，等同于 `/Users/你的用户名` |
| `.` | 当前目录 |
| `..` | 上一级目录 |

### 推荐终端工具：iTerm2

macOS 自带的终端已经够用，但 iTerm2 是更强大的替代品，提供分屏、搜索、自动补全等高级功能。

**安装 iTerm2：**

```bash
brew install --cask iterm2
```

安装后，在 Launchpad 或聚焦搜索中找到 iTerm 打开即可。

**iTerm2 常用快捷键：**

| 快捷键 | 功能 |
|---|---|
| `Command + D` | 垂直分屏 |
| `Command + Shift + D` | 水平分屏 |
| `Command + [` / `]` | 在分屏之间切换 |
| `Command + K` | 清空当前屏幕 |
| `Command + F` | 搜索终端内容 |

> 💡 **提示**：iTerm2 可以配合 Oh My Zsh 使用，打造更美观、更强大的终端体验。但作为新手，先熟悉基本操作即可，后续再考虑美化。

## VS Code 辅助编辑器安装

### 为什么需要 VS Code？

Xcode 是 iOS 开发的主力工具，但在某些场景下 VS Code 更方便：

| 场景 | Xcode | VS Code |
|---|---|---|
| Swift / SwiftUI 开发 | ✅ 首选 | ⚠️ 支持有限 |
| 编辑配置文件（JSON/YAML） | ❌ 不方便 | ✅ 非常方便 |
| 编辑 Markdown 文档 | ❌ 基本功能 | ✅ 实时预览 |
| 查看 Git 历史 | ⚠️ 基本功能 | ✅ GitLens 扩展很强大 |
| 快速打开和编辑小文件 | ❌ 启动慢 | ✅ 秒开 |

简单来说：**Xcode 写代码，VS Code 做辅助**，两者配合使用效率最高。

### 安装 VS Code

**方式一：通过 Homebrew 安装（推荐）**

```bash
brew install --cask visual-studio-code
```

**方式二：官网下载**

1. 访问 [https://code.visualstudio.com](https://code.visualstudio.com)
2. 点击下载 macOS 版本
3. 解压后将 Visual Studio Code 拖入 Applications 文件夹

**安装命令行工具：**

安装完成后，打开 VS Code，按 `Command + Shift + P` 打开命令面板，输入 `shell command`，选择 **Shell Command: Install 'code' command in PATH**。这样就可以在终端中用 `code .` 直接打开当前目录了。

```bash
# 用 VS Code 打开当前目录
code .

# 用 VS Code 打开指定文件
code README.md
```

### 推荐扩展

打开 VS Code 后，点击左侧边栏的扩展图标（或按 `Command + Shift + X`），搜索并安装以下扩展：

| 扩展名 | 用途 | 必要性 |
|---|---|---|
| **Swift** | Swift 语法高亮和代码补全 | ⭐⭐⭐ 推荐 |
| **Markdown All in One** | Markdown 编辑增强（快捷键、目录生成） | ⭐⭐⭐ 推荐 |
| **GitLens** | Git 增强工具（查看每行代码的提交者） | ⭐⭐⭐ 推荐 |
| **Prettier** | 代码格式化 | ⭐⭐ 可选 |
| **YAML** | YAML 文件语法支持 | ⭐⭐ 可选 |
| **DotENV** | .env 文件语法高亮 | ⭐ 可选 |

### 基本配置

按 `Command + ,` 打开设置，建议调整以下选项：

```json
{
  "editor.fontSize": 14,
  "editor.tabSize": 2,
  "editor.wordWrap": "on",
  "editor.minimap.enabled": false,
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 1000
}
```

> 💡 **提示**：点击设置界面右上角的 `{}` 图标可以切换到 JSON 编辑模式，直接粘贴上面的配置。

## 常用命令行工具

以下是 iOS 开发中经常用到的命令行工具，全部可以通过 Homebrew 一键安装。

### 工具介绍

| 工具 | 说明 | 典型用途 |
|---|---|---|
| **tree** | 以树形结构展示目录内容 | 查看项目文件结构 |

### tree：目录树展示

安装：

```bash
brew install tree
```

使用示例：

```bash
# 展示当前目录结构
tree

# 只展示 2 层深度
tree -L 2

# 忽略 .git 和 node_modules 目录
tree -I '.git|node_modules'
```

输出效果：

```
MyProject
├── App
│   ├── AppDelegate.swift
│   └── SceneDelegate.swift
├── Assets.xcassets

```

### wget / curl：下载工具

**wget** 安装：

```bash
brew install wget
```

使用示例：

```bash
# 下载文件
wget https://example.com/file.zip

# 断点续传下载
wget -c https://example.com/large-file.zip
```

**curl** 是 macOS 自带的，无需安装：

```bash
# 下载文件
curl -O https://example.com/file.zip

# 测试 API 接口
curl https://api.github.com/users/apple

# 带 Header 请求
curl -H "Authorization: Bearer YOUR_TOKEN" https://api.example.com/data
```

| 对比项 | wget | curl |
|---|---|---|
| 安装 | 需安装 | macOS 自带 |
| 下载文件 | 更简洁 | 需加 `-O` 参数 |
| 断点续传 | ✅ 原生支持 | ⚠️ 需加 `-C -` |
| 上传文件 | ❌ 不支持 | ✅ 支持 |
| 测试 API | ❌ 不方便 | ✅ 非常方便 |

### jq：JSON 处理

安装：

```bash
brew install jq
```

使用示例：

```bash
# 格式化 JSON（美化输出）
echo '{"name":"Tom","age":25}' | jq .

# 提取某个字段
echo '{"name":"Tom","age":25}' | jq '.name'
# 输出: "Tom"

# 处理 API 返回的 JSON
curl -s https://api.github.com/users/apple | jq '.login'
# 输出: "apple"

# 格式化 JSON 文件
jq . config.json
```

### gh：GitHub CLI

安装：

```bash
brew install gh
```

首次使用需要登录：

```bash

```

按提示选择 GitHub.com → HTTPS → 通过浏览器登录即可。

常用命令：

```bash

gh auth status

# 克隆仓库

# 查看 Issue 列表

# 创建 Pull Request

# 查看 PR 列表

# 在终端查看仓库信息

```

一键安装所有常用工具：

```bash

```

## Swift Package Manager（SPM）

### 什么是包管理器？

如果你之前接触过前端开发，可能用过 **npm**（Node.js 的包管理器）；如果用过 Python，可能用过 **pip**。它们的作用都一样：**帮你自动下载、安装和管理第三方库**，不用手动去网上找代码、拖进项目里。

**Swift Package Manager（简称 SPM）** 就是 Apple 官方提供的 Swift 包管理器，从 Xcode 11 开始内置，无需额外安装。它可以直接在 Xcode 中使用，体验非常丝滑。

打个比方：没有包管理器时，你想用一个第三方库，就像去超市买菜——得自己出门、找货架、挑商品、拎回家；有了包管理器，就像点外卖——说一声"我要 Alamofire"，它自动帮你下载好、配置好，直接就能用。

### SPM vs CocoaPods 对比

在 SPM 出现之前，iOS 开发中最流行的包管理器是 **CocoaPods**。两者对比如下：

| 对比项 | SPM | CocoaPods |
|---|---|---|
| **官方支持** | ✅ Apple 官方，Xcode 内置 | ❌ 第三方社区维护 |
| **安装方式** | 无需安装，Xcode 自带 | 需要手动安装（`sudo gem install cocoapods`） |
| **配置文件** | `Package.swift`（Swift 代码） | `Podfile`（Ruby 语法） |
| **工作方式** | 直接集成到 Xcode 项目 | 生成 `.xcworkspace` 工作区 |
| **构建速度** | ✅ 较快，原生支持 | ⚠️ 较慢，需要额外步骤 |
| **生态成熟度** | ⭐⭐⭐ 越来越多库支持 | ⭐⭐⭐⭐⭐ 几乎所有库都支持 |
| **学习成本** | ✅ 低，Xcode 图形界面操作 | ⚠️ 需要学习 Ruby 语法和命令行操作 |
| **未来趋势** | ✅ Apple 主推，持续改进 | ⚠️ 逐渐被 SPM 替代 |

> 💡 **建议**：新项目优先使用 SPM。只有在某个库只支持 CocoaPods 时，才考虑使用 CocoaPods。两者也可以在同一个项目中共存。

### 在 Xcode 中添加第三方包

这是最常用的操作，跟着步骤来就行：

**第一步：打开添加包界面**

在 Xcode 菜单栏中选择：**File → Add Package Dependencies...**

> 💡 **提示**：如果是第一次打开，Xcode 可能需要几秒钟加载。

**第二步：搜索或输入包地址**

在搜索框中，你可以：

- **直接粘贴包的 GitHub URL**（最准确），例如：
  ```
  https://github.com/Alamofire/Alamofire.git
  ```
- **输入关键词搜索**（部分包支持），例如输入 `Alamofire`

**第三步：选择版本规则**

找到包后，需要选择版本规则：

| 版本规则 | 含义 | 示例 |
|---|---|---|
| **Up to Next Major Version** | 允许自动更新到下一个大版本之前（推荐） | `5.0.0 < 6.0.0` |
| **Up to Next Minor Version** | 只允许小版本更新 | `5.8.0 < 5.9.0` |
| **Exact Version** | 锁定精确版本，不自动更新 | `5.8.1` |
| **Branch** | 指定某个 Git 分支 | `main` |
| **Commit** | 指定某个 Git 提交 | `abc1234` |

> 💡 **建议**：一般选择 **Up to Next Major Version**，既能获得 bug 修复和小功能更新，又不会因为大版本更新导致代码不兼容。

**第四步：选择需要的库并添加**

有些包包含多个库（Library），你可以勾选需要的那几个，然后点击 **Add Package**。

**第五步：验证**

添加成功后，在项目导航器（左侧边栏）中可以看到 `Package Dependencies` 文件夹，里面会列出已添加的包。

> ⚠️ **注意**：添加包时 Xcode 会从 GitHub 下载代码，国内网络可能较慢。如果下载失败，可以尝试配置代理或重试。

### 常用第三方包推荐

以下是 iOS 开发中最常用的第三方包，新手建议收藏：

| 包名 | 用途 | GitHub 地址 |
|---|---|---|
| **Alamofire** | 网络请求（HTTP 请求封装） | `https://github.com/Alamofire/Alamofire.git` |
| **Kingfisher** | 图片加载与缓存（从网络加载图片） | `https://github.com/onevcat/Kingfisher.git` |
| **SnapKit** | Auto Layout 布局简化（UIKit 项目用） | `https://github.com/SnapKit/SnapKit.git` |

**简单介绍：**

- **Alamofire**：Swift 最流行的网络请求库。虽然用原生的 `URLSession` 也能发请求，但 Alamofire 让代码更简洁、更易读。比如上传文件、处理 JSON 响应，用 Alamofire 几行代码就能搞定。

- **Kingfisher**：图片加载神器。从网络下载图片、显示到 UIImageView、自动缓存——这些全帮你处理好了。如果你做过前端，可以把它理解为 Swift 版的图片懒加载库。

- **SnapKit**：如果你使用 UIKit（而非 SwiftUI）开发，SnapKit 可以让布局代码更简洁。原生 Auto Layout 的约束写起来很啰嗦，SnapKit 用链式语法大幅简化。**注意：SwiftUI 项目不需要 SnapKit。**

> 💡 **提示**：作为新手，不要贪多！先把这几个常用包用好，遇到新需求再按需添加。每个包的 GitHub 仓库都有详细的使用文档。

### Package.swift 文件解析

如果你创建了一个 Swift Package，或者想深入了解 SPM 的工作原理，就需要理解 `Package.swift` 文件。它是 SPM 的核心配置文件，用 Swift 语法编写。

一个典型的 `Package.swift` 长这样：

```swift
// swift-tools-version: 5.9
import PackageDescription

let package = Package(
    name: "MyApp",
    platforms: [
        .iOS(.v15),
        .macOS(.v12)
    ],
    products: [
        .library(
            name: "MyApp",
            targets: ["MyApp"]
        )
    ],
    dependencies: [
        .package(url: "https://github.com/Alamofire/Alamofire.git", from: "5.8.0"),
        .package(url: "https://github.com/onevcat/Kingfisher.git", from: "7.0.0")
    ],
    targets: [
        .target(
            name: "MyApp",
            dependencies: [
                .product(name: "Alamofire", package: "Alamofire"),
                .product(name: "Kingfisher", package: "Kingfisher")
            ]
        ),
        .testTarget(
            name: "MyAppTests",
            dependencies: ["MyApp"]
        )
    ]
)
```

**各字段含义：**

| 字段 | 说明 |
|---|---|
| `swift-tools-version` | 最低 Swift 工具版本，写在文件第一行注释中 |
| `name` | 包的名称 |
| `platforms` | 支持的平台和最低版本，如 `.iOS(.v15)` 表示支持 iOS 15 及以上 |
| `products` | 包对外提供的产物（库或可执行文件） |
| `dependencies` | 依赖的其他包，指定 URL 和版本范围 |
| `targets` | 包内的构建目标，每个 target 可以有自己的依赖 |

**关键概念：**

- **dependencies（依赖）**：声明这个包需要用到的第三方包，包括 URL 和版本要求。
- **targets（目标）**：包内的构建单元。`.target` 是源码目标，`.testTarget` 是测试目标。每个 target 需要明确声明它依赖哪些外部包。
- **platforms（平台）**：如果不指定，默认支持所有 Apple 平台的所有版本。建议明确指定，避免兼容性问题。

> 💡 **提示**：普通 Xcode 项目（非 Swift Package）不会直接编辑 `Package.swift`，但理解它有助于排查依赖问题。

### 创建自己的 Swift Package

如果你想把自己写的代码封装成一个可复用的库，可以创建一个 Swift Package：

**第一步：创建 Package**

在终端中执行：

```bash
mkdir MyLibrary
cd MyLibrary
swift package init
```

这会生成如下目录结构：

```
MyLibrary/
├── Package.swift
├── Sources/
│   └── MyLibrary/
│       └── MyLibrary.swift
└── Tests/
    └── MyLibraryTests/
        └── MyLibraryTests.swift
```

**第二步：编写代码**

在 `Sources/MyLibrary/` 目录下编写你的库代码。例如：

```swift
public struct MyLibrary {
    public static func greet(name: String) -> String {
        return "Hello, \(name)!"
    }
}
```

> ⚠️ **注意**：想要被外部使用的函数和类型，必须标记为 `public`，否则外部无法访问。

**第三步：编写测试**

在 `Tests/MyLibraryTests/` 目录下编写测试代码：

```swift
import XCTest
@testable import MyLibrary

final class MyLibraryTests: XCTestCase {
    func testGreet() {
        XCTAssertEqual(MyLibrary.greet(name: "World"), "Hello, World!")
    }
}
```

**第四步：运行测试**

```bash
swift test
```

**第五步：发布到 GitHub**

1. 在 GitHub 上创建一个新仓库
2. 将本地代码推送到 GitHub
3. 打上版本标签（如 `git tag 1.0.0` → `git push origin 1.0.0`）

之后，其他人就可以通过 `https://github.com/你的用户名/MyLibrary.git` 来添加你的包了！

> 💡 **提示**：也可以在 Xcode 中创建 Swift Package：**File → New → Package...**，Xcode 会自动生成模板代码。

### 常见问题

#### 1. 版本冲突

**问题**：项目同时依赖包 A 和包 B，A 要求某依赖版本 `>= 2.0`，B 要求同一依赖版本 `< 2.0`，导致冲突。

**解决方法**：

- 在 Xcode 中选择项目 → **Package Dependencies** 标签页，查看依赖关系图
- 尝试统一各包的版本要求，找到兼容的版本范围
- 如果无法解决，考虑升级或替换其中一个包

#### 2. 包下载失败 / 超时

**问题**：国内访问 GitHub 不稳定，添加包时经常下载失败。

**解决方法**：

- 重试几次，有时网络波动导致
- 配置 Git 代理：
  ```bash
  git config --global http.proxy http://127.0.0.1:端口号
  ```
- 使用镜像源（部分包有国内镜像）

#### 3. 缓存清理

**问题**：SPM 缓存了旧版本的包，导致更新后仍然使用旧代码。

**解决方法**：

```bash
# 清理 SPM 全局缓存
rm -rf ~/Library/Caches/org.swift.swiftpm
rm -rf ~/Library/Developer/Xcode/DerivedData

# 在 Xcode 中重置包缓存
# File → Packages → Reset Package Caches
```

```bash
# 更新包到最新版本（在 Xcode 中）
# File → Packages → Update to Latest Package Versions
```

> 💡 **提示**：如果遇到奇怪的编译错误，先试试清理缓存，能解决大部分问题。
