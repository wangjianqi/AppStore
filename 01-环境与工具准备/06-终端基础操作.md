# 06-终端基础操作

> 🎯 **本章目标**：帮助从未使用过命令行的开发者克服对终端的恐惧，掌握 macOS 终端的基本操作，为后续使用 AI CLI 工具、Fastlane、SPM 等打下基础。读完本章后，你将能够熟练使用终端完成日常开发任务，不再害怕黑底白字的命令行界面。

---

## 终端是什么

### 图形界面 vs 命令行

你平时使用 Mac 的方式是**图形界面（GUI）**——点击图标、拖拽文件、双击打开应用。这种方式直观易用，但有些操作用图形界面很难完成，或者效率很低。

**命令行界面（CLI）** 则是通过输入文字命令来操作电脑。看起来像这样：

```
wjq@MacBook ~ % cd Documents
wjq@MacBook Documents % ls
MyProject    Notes    Screenshots
wjq@MacBook Documents % mkdir NewFolder
wjq@MacBook Documents % ls
MyProject    Notes    Screenshots    NewFolder
```

两种方式的对比：

| 维度 | 图形界面 | 命令行 |
|------|---------|--------|
| 学习难度 | 低，直观 | 较高，需要记忆命令 |
| 操作效率 | 点击多次才能完成 | 一行命令搞定 |
| 批量操作 | 困难 | 轻松（循环、管道） |
| 自动化 | 需要额外工具 | 天然支持脚本 |
| 远程操作 | 需要远程桌面 | SSH 即可 |
| 资源占用 | 较高 | 极低 |

### 为什么 iOS 开发者需要终端

在 iOS 开发中，以下场景必须或推荐使用终端：

| 场景 | 命令示例 | 必要性 |
|------|---------|--------|
| 安装 Homebrew 包 | `brew install wget` | 必须用终端 |
| 使用 Claude Code | `claude` | 必须用终端 |
| 使用 Fastlane 自动化 | `fastlane release` | 必须用终端 |
| 操作 Swift Package | `swift package resolve` | 推荐用终端 |
| 使用 xcodebuild | `xcodebuild -scheme MyApp` | CI/CD 必须用 |
| Git 操作 | `git commit -m "fix"` | 推荐用终端 |
| 查看 Xcode 日志 | `xcrun simctl list` | 推荐用终端 |
| 管理模拟器 | `xcrun simctl boot "iPhone 16"` | 推荐用终端 |

> 💡 **提示**：不要害怕终端！它只是一个工具，和 Xcode 一样。掌握了基本命令后，你会发现终端在很多场景下比图形界面更高效。

### 克服对终端的恐惧

很多新手看到终端的黑底白字就感到紧张，这是正常的。但请记住以下几点：

1. **终端不会"咬人"**——你输入的每一条命令都是可预测的
2. **大部分命令是安全的**——只要你不执行 `rm -rf /` 这种危险命令
3. **可以随时撤销**——很多操作都有对应的撤销方式
4. **AI 可以帮你**——不确定命令时，问 AI 就好

## 打开终端的方式

### 方式一：Terminal.app（系统自带）

这是 macOS 自带的终端应用，所有 Mac 都有。

| 打开方式 | 操作 |
|---------|------|
| **聚焦搜索（推荐）** | 按 `Command + 空格`，输入"终端"或"Terminal"，回车 |
| **Launchpad** | 打开 Launchpad → 其他 → 终端 |
| **Finder** | 打开 Finder → 应用程序 → 实用工具 → 终端 |

> 💡 **提示**：`Command + 空格` 是 Mac 上最快捷的搜索方式，不仅能打开终端，还能打开任何应用、文件。养成这个习惯，效率翻倍！

### 方式二：iTerm2（推荐进阶使用）

iTerm2 是 macOS 上最流行的第三方终端应用，比系统自带终端功能更强大。

**安装 iTerm2：**

```bash
brew install --cask iterm2
```

**iTerm2 相比 Terminal.app 的优势：**

| 功能 | Terminal.app | iTerm2 |
|------|-------------|--------|
| 分屏 | ❌ | ✅ 水平/垂直分屏 |
| 搜索 | 基本搜索 | 正则搜索、高亮 |
| 自动补全 | ❌ | ✅ 命令补全 |
| 主题定制 | 有限 | 丰富 |
| 热键窗口 | ❌ | ✅ 全局快捷键呼出 |
| 剪贴板历史 | ❌ | ✅ |
| Shell 集成 | 基础 | ✅ 深度集成 |

**iTerm2 常用快捷键：**

| 快捷键 | 功能 |
|--------|------|
| `Command + D` | 垂直分屏 |
| `Command + Shift + D` | 水平分屏 |
| `Command + [` / `]` | 在分屏之间切换 |
| `Command + K` | 清空当前屏幕 |
| `Command + F` | 搜索终端内容 |
| `Command + Shift + H` | 剪贴板历史 |
| `Option + Command + I` | 广播模式（同时向所有分屏输入） |

### 方式三：VS Code 内置终端

如果你已经在使用 VS Code，它内置了一个终端，无需切换应用：

- 打开方式：`Ctrl + `` `（反引号）或菜单 **Terminal → New Terminal**
- 支持多终端标签页
- 与编辑器在同一窗口，方便对照代码

### 方式四：Xcode 终端区域

Xcode 也有终端功能，在调试区域可以执行 LLDB 命令，但功能有限，不适合日常终端操作。

### 终端外观设置

**Terminal.app 美化：**

1. 打开终端 → **终端 → 设置（Settings）**
2. 在 **描述文件（Profiles）** 中选择一个主题
3. 推荐主题：Pro、Basic、Solarized Dark

**iTerm2 美化：**

1. 打开 iTerm2 → **iTerm2 → Settings → Profiles**
2. 在 **Colors** 标签页选择配色方案
3. 推荐配色：Solarized Dark、Dracula、One Dark

> 💡 **提示**：新手阶段不需要花太多时间美化终端，先熟悉基本操作。等你觉得终端用得多了，再考虑安装 Oh My Zsh 等美化工具。

## 基本命令

### 命令的基本格式

终端命令的通用格式：

```
命令 [选项] [参数]
```

例如：

```bash
ls -la /Users/wjq/Documents
```

| 部分 | 内容 | 说明 |
|------|------|------|
| 命令 | `ls` | 列出目录内容 |
| 选项 | `-la` | 显示详细信息（l）+ 包含隐藏文件（a） |
| 参数 | `/Users/wjq/Documents` | 要列出的目录路径 |

选项的两种写法：

| 写法 | 示例 | 说明 |
|------|------|------|
| 短选项 | `-l`、`-a`、`-la` | 一个减号，可以合并 |
| 长选项 | `--all`、`--human-readable` | 两个减号，更易读 |

### pwd：我在哪里

`pwd`（Print Working Directory）显示你当前所在的目录：

```bash
pwd
```

输出：

```
/Users/wjq
```

这就像在商场里看"您在此处"的地图标识。

### ls：这里有什么

`ls`（List）列出当前目录下的文件和文件夹：

```bash
# 基本用法
ls

# 显示详细信息（权限、大小、修改时间）
ls -l

# 显示隐藏文件（以 . 开头的文件）
ls -a

# 组合使用：详细信息 + 隐藏文件
ls -la

# 按修改时间排序（最新的在最后）
ls -lt

# 按修改时间排序（最新的在最前）
ls -ltr

# 显示人类可读的文件大小
ls -lh

# 指定目录
ls /Applications
```

输出示例（`ls -la`）：

```
total 48
drwxr-xr-x   12 wjq  staff   384 May 25 10:00 .
drwxr-xr-x    6 root  admin   192 May 24 15:30 ..
-rw-r--r--    1 wjq  staff  6148 May 25 10:00 .DS_Store
drwxr-xr-x    5 wjq  staff   160 May 25 09:30 .git
-rw-r--r--    1 wjq  staff    73 May 25 09:30 .gitignore
-rw-r--r--    1 wjq  staff  1024 May 25 09:30 README.md
drwxr-xr-x    8 wjq  staff   256 May 25 09:30 MyFirstApp
```

每列含义：

| 列 | 含义 | 示例说明 |
|----|------|---------|
| 第1列 | 文件权限 | `drwxr-xr-x`，d 表示目录 |
| 第2列 | 硬链接数 | 12 |
| 第3列 | 所有者 | wjq |
| 第4列 | 所属组 | staff |
| 第5列 | 文件大小 | 384 字节 |
| 第6-8列 | 修改时间 | May 25 10:00 |
| 第9列 | 文件名 | .DS_Store |

### cd：去哪里

`cd`（Change Directory）切换当前目录：

```bash
# 进入指定目录
cd Documents

# 进入子目录
cd Documents/MyProject

# 返回上一级目录
cd ..

# 返回用户主目录
cd ~

# 返回上一次所在的目录
cd -

# 进入根目录
cd /
```

> 💡 **提示**：`cd` 不加任何参数也会回到用户主目录，等同于 `cd ~`。

### mkdir：创建目录

`mkdir`（Make Directory）创建新文件夹：

```bash
# 创建单个目录
mkdir MyProject

# 创建多级目录（父目录不存在时自动创建）
mkdir -p Projects/iOS/MyFirstApp

# 同时创建多个目录
mkdir Assets Models Views Controllers
```

> 💡 **提示**：`mkdir -p` 非常实用，可以一次创建多层嵌套的目录结构，不用担心父目录是否存在。

### rm：删除文件或目录

`rm`（Remove）删除文件或目录：

```bash
# 删除文件
rm test.txt

# 删除多个文件
rm file1.txt file2.txt file3.txt

# 删除目录及其内容
rm -r OldProject

# 强制删除，不询问确认
rm -rf OldProject

# 交互式删除，逐个确认
rm -i *.txt
```

⚠️ **警告**：
- `rm` 删除的文件**不会进入回收站**，删除即消失！
- `rm -rf /` 或 `rm -rf *` 这种命令**绝对不要执行**，会删除整个系统
- 删除前先确认路径是否正确，避免误删
- 建议使用 `rm -i`（交互模式），删除前会逐个确认

### cp：复制文件

`cp`（Copy）复制文件或目录：

```bash
# 复制文件
cp source.txt destination.txt

# 复制文件到指定目录
cp source.txt /Users/wjq/Documents/

# 复制目录及其内容
cp -r SourceDir/ DestinationDir/

# 保留文件属性（修改时间、权限等）
cp -p source.txt destination.txt

# 复制前确认是否覆盖
cp -i source.txt destination.txt
```

### mv：移动或重命名

`mv`（Move）移动文件或重命名：

```bash
# 重命名文件
mv oldname.txt newname.txt

# 移动文件到指定目录
mv file.txt /Users/wjq/Documents/

# 移动目录
mv OldDir/ /Users/wjq/Projects/

# 移动多个文件到指定目录
mv file1.txt file2.txt file3.txt /Users/wjq/Documents/
```

> 💡 **提示**：`mv` 既可以移动文件，也可以重命名文件。区别在于目标路径——如果目标是目录，就是移动；如果目标是文件名，就是重命名。

### cat：查看文件内容

`cat`（Concatenate）查看文件内容：

```bash
# 查看文件内容
cat README.md

# 查看多个文件（内容会连续显示）
cat file1.txt file2.txt

# 显示行号
cat -n AppDelegate.swift

# 创建新文件（输入内容后按 Ctrl+D 保存）
cat > newfile.txt
```

### echo：输出文字

`echo` 用于输出文字或变量值：

```bash
# 输出文字
echo "Hello, World!"

# 输出环境变量
echo $HOME
echo $PATH

# 输出到文件（覆盖）
echo "Hello" > test.txt

# 输出到文件（追加）
echo "World" >> test.txt
```

### 其他常用命令

```bash
# 查找文件
find . -name "*.swift"

# 在文件中搜索文本
grep "import UIKit" AppDelegate.swift

# 查看文件前几行
head -20 README.md

# 查看文件后几行
tail -20 log.txt

# 实时查看文件更新（查看日志时很有用）
tail -f /var/log/system.log

# 统计文件行数
wc -l AppDelegate.swift

# 比较两个文件
diff file1.txt file2.txt

# 查看命令帮助
man ls

# 查看命令的简要说明
tldr ls

# 清空终端屏幕
clear

# 查看磁盘使用情况
df -h

# 查看目录大小
du -sh /Users/wjq/Projects

# 查看当前运行的进程
ps aux

# 查看端口占用
lsof -i :8080

# 查看网络连接
ping google.com

# 下载文件
curl -O https://example.com/file.zip
```

## 文件路径概念

### 绝对路径 vs 相对路径

理解路径是使用终端的基础——路径就是文件在电脑中的"地址"。

**绝对路径**：从根目录 `/` 开始的完整地址

```
/Users/wjq/Documents/MyProject/AppDelegate.swift
```

类比：就像"中国→北京市→朝阳区→某某街道1号"，完整且唯一。

**相对路径**：相对于当前目录的地址

```
# 假设你当前在 /Users/wjq/Documents 目录
cd MyProject                    # 相对路径
# 等同于
cd /Users/wjq/Documents/MyProject  # 绝对路径
```

类比：就像"往前走50米右转"，简洁但取决于你的当前位置。

### 特殊路径符号

| 符号 | 含义 | 示例 |
|------|------|------|
| `/` | 根目录（最顶层） | `cd /` |
| `~` | 用户主目录，等同于 `/Users/你的用户名` | `cd ~` |
| `.` | 当前目录 | `ls .` |
| `..` | 上一级目录 | `cd ..` |
| `-` | 上一次所在的目录 | `cd -` |

**路径组合示例：**

```bash
# 从任何位置回到主目录
cd ~

# 进入主目录下的 Documents
cd ~/Documents

# 返回上一级
cd ..

# 返回上两级
cd ../..

# 从当前目录的子目录进入
cd ./Assets/Images

# 引用上级目录的文件
cat ../README.md
```

### macOS 目录结构

了解 macOS 的基本目录结构有助于你更好地理解路径：

| 目录 | 说明 | 示例 |
|------|------|------|
| `/` | 根目录 | — |
| `/Applications` | 应用程序 | Xcode.app |
| `/Users` | 用户目录 | /Users/wjq |
| `/Users/wjq` | 你的主目录 | ~ |
| `/Users/wjq/Desktop` | 桌面 | ~/Desktop |
| `/Users/wjq/Documents` | 文稿 | ~/Documents |
| `/Users/wjq/Downloads` | 下载 | ~/Downloads |
| `/Library` | 系统级资源库 | — |
| `/System` | 系统文件 | — |
| `/usr/local` | 用户安装的命令行工具 | Homebrew |
| `/opt/homebrew` | Apple Silicon 上的 Homebrew | — |
| `/tmp` | 临时文件 | — |

> ⚠️ **警告**：不要随意修改 `/System`、`/Library` 等系统目录的内容，可能导致系统不稳定。

### 文件名和路径中的空格

macOS 的文件名经常包含空格（如 `My Project`），在终端中需要特殊处理：

```bash
# 方法一：用反斜杠转义空格
cd My\ Project

# 方法二：用引号包裹
cd "My Project"

# 方法三：用单引号包裹
cd 'My Project'
```

> 💡 **提示**：推荐使用方法二（双引号），最直观且不易出错。

## 命令补全和历史

### Tab 键自动补全

这是终端中**最常用**的效率技巧。输入命令或路径的前几个字符，按 Tab 键，终端会自动补全：

```bash
# 输入 cd Doc 然后按 Tab
cd Doc<Tab>
# 自动补全为：
cd Documents/

# 输入 git che 然后按 Tab
git che<Tab>
# 自动补全为：
git checkout

# 如果有多个匹配项，按两次 Tab 显示所有选项
cd D<Tab><Tab>
# 显示：
Desktop/    Documents/  Downloads/
```

Tab 补全支持：

| 补全类型 | 示例 |
|---------|------|
| 命令名 | `git<Tab>` → `git` |
| 文件名 | `cd Doc<Tab>` → `cd Documents/` |
| 目录名 | `ls App<Tab>` → `ls Applications/` |
| Git 分支 | `git checkout fe<Tab>` → `git checkout feature/` |
| 命令选项 | `git --<Tab><Tab>` → 显示所有选项 |

> 💡 **提示**：养成频繁按 Tab 的习惯，不仅能提高输入速度，还能避免拼写错误。如果 Tab 没有补全，说明你输入的前缀不唯一或有误。

### 命令历史

终端会记录你执行过的所有命令，可以快速重复使用：

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 上一条命令 | `↑`（上箭头） | 向上翻阅历史 |
| 下一条命令 | `↓`（下箭头） | 向下翻阅历史 |
| 搜索历史 | `Ctrl + R` | 输入关键词搜索 |
| 历史列表 | `history` | 显示所有历史命令 |
| 执行第 N 条 | `!N` | 如 `!42` 执行第 42 条命令 |
| 执行上一条 | `!!` | 重复执行上一条命令 |

**Ctrl + R 搜索示例：**

```
# 按 Ctrl + R，然后输入关键词
(reverse-i-search)`git push': git push -u origin main
# 找到后按回车执行，或按左右箭头编辑
```

**history 命令：**

```bash
# 查看最近 20 条命令
history 20

# 清空历史记录
history -c

# 搜索历史命令
history | grep "git commit"
```

> 💡 **提示**：`!!` 是一个很实用的技巧。比如你忘了加 `sudo`：
> ```bash
> brew install something
> # 提示权限不足
> sudo !!
> # 等同于 sudo brew install something
> ```

## 环境变量和 PATH

### 什么是环境变量

环境变量是系统级别的配置值，影响程序的行为。你可以把它们理解为"全局设置"。

查看所有环境变量：

```bash
env
```

查看某个环境变量：

```bash
echo $HOME
echo $SHELL
echo $USER
```

### 常用环境变量

| 变量 | 说明 | 示例值 |
|------|------|--------|
| `HOME` | 用户主目录 | `/Users/wjq` |
| `USER` | 当前用户名 | `wjq` |
| `SHELL` | 当前 Shell | `/bin/zsh` |
| `PATH` | 命令搜索路径 | 见下文 |
| `LANG` | 语言设置 | `zh_CN.UTF-8` |
| `TERM` | 终端类型 | `xterm-256color` |
| `EDITOR` | 默认编辑器 | `code --wait` |

### PATH 详解

PATH 是最重要的环境变量，它告诉系统去哪里找可执行命令。

```bash
echo $PATH
```

输出类似：

```
/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

PATH 中的路径用 `:` 分隔，系统按从左到右的顺序搜索命令。

**为什么需要理解 PATH？**

当你安装了一个新工具（如 Homebrew），但终端提示"command not found"时，通常是因为工具的安装路径不在 PATH 中。

**添加路径到 PATH：**

```bash
# 临时添加（只在当前终端会话有效）
export PATH="/new/path:$PATH"

# 永久添加（写入配置文件）
echo 'export PATH="/new/path:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

> ⚠️ **警告**：修改 PATH 时，务必保留原有的 `$PATH`，否则系统将找不到基本命令。

### Shell 配置文件

macOS 从 Catalina（10.15）开始默认使用 **Zsh** 作为 Shell。Zsh 的配置文件：

| 文件 | 加载时机 | 用途 |
|------|---------|------|
| `~/.zshrc` | 每次打开新终端 | 别名、环境变量、PATH |
| `~/.zprofile` | 登录 Shell | 系统级环境变量 |
| `~/.zshenv` | 所有 Zsh 实例 | 最基本的环境变量 |

## Homebrew 安装和使用

### Homebrew 是什么

Homebrew 是 macOS 的**命令行版"应用商店"**。有了它，你只需要一行命令就能安装、更新、卸载各种开发工具和软件。

打个比方：没有 Homebrew 时，安装一个工具就像去超市买菜——得自己出门、找货架、挑商品、拎回家；有了 Homebrew，就像点外卖——说一声"我要 wget"，它自动帮你下载好、配置好，直接就能用。

### 安装 Homebrew

打开终端，执行以下命令：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

安装过程中会提示你按 **回车** 确认，按提示操作即可。

> ⚠️ **注意**：安装过程可能较慢，取决于网络情况。如果下载失败，请参考下面的镜像配置。

**安装完成后的额外步骤（Apple Silicon 用户必看）：**

如果你使用的是 Apple Silicon（M1/M2/M3/M4）芯片的 Mac，Homebrew 默认安装在 `/opt/homebrew` 目录下，需要手动添加环境变量。安装脚本的末尾会提示你执行两条命令，类似：

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

**验证安装：**

```bash
brew --version
```

输出类似 `Homebrew 4.x.x` 即安装成功。

### 国内用户镜像配置

## 常见问题与排错

### 问题 1：command not found

**症状**：输入命令后提示 `zsh: command not found: xxx`

**原因**：命令未安装，或安装路径不在 PATH 中。

**解决方法**：

```bash
# 检查命令是否存在
which xxx

# 检查是否通过 Homebrew 安装
brew list | grep xxx

# 如果是 Homebrew 安装的，检查 PATH 是否包含 Homebrew 路径
echo $PATH | grep homebrew

# 如果没有，添加到 PATH
eval "$(/opt/homebrew/bin/brew shellenv)"
```

### 问题 2：Permission denied

**症状**：提示 `Permission denied`

**原因**：当前用户没有执行权限。

**解决方法**：

```bash
# 给文件添加执行权限
chmod +x script.sh

# 使用 sudo 提权（谨慎使用）
sudo command
```

### 问题 3：端口被占用

**症状**：启动服务时提示端口已被占用。

**解决方法**：

```bash
# 查看占用端口的进程
lsof -i :8080

# 终止占用端口的进程
kill -9 PID
```

### 问题 4：终端卡住

**症状**：终端无响应，无法输入命令。

**解决方法**：

| 快捷键 | 功能 |
|--------|------|
| `Ctrl + C` | 终止当前运行的命令 |
| `Ctrl + Z` | 暂停当前命令 |
| `Ctrl + Q` | 恢复终端输出（如果被 Ctrl+S 暂停了） |
| `Ctrl + D` | 退出当前 Shell |

> 💡 **提示**：`Ctrl + S` 会暂停终端输出（XOFF），这是一个常见的"误触"——看起来像终端卡住了，但实际上只是输出被暂停了。按 `Ctrl + Q` 恢复。

### 问题 5：Homebrew 下载慢

**症状**：`brew install` 速度很慢或失败。

**解决方法**：

```bash
# 配置国内镜像源（见前面章节）
# 或者使用代理
export ALL_PROXY=socks5://127.0.0.1:7890
brew install xxx
```

### 问题 6：zsh compinit 警告

**症状**：打开终端时提示 `zsh compinit: insecure directories`

**解决方法**：

```bash
# 修复目录权限
chmod go-w '/opt/homebrew/share'
compaudit | xargs chmod go-w
```
