### 搜索逻辑

#### 实时搜索（debounce）

用户每输入一个字符就触发搜索，如果搜索逻辑比较重（比如网络请求），会造成性能问题。**debounce**（防抖）可以让搜索"等一等再执行"——用户停止输入 300 毫秒后才真正搜索。

```swift
import SwiftUI

struct DebouncedSearchView: View {
    @State private var searchText = ""
    @State private var debouncedText = ""
    @State private var records = SampleData.recentRecords

    private let timer = Timer.publish(every: 0.3, on: .main, in: .common).autoconnect()

    var filteredRecords: [Record] {
        if debouncedText.isEmpty {
            return records
        }
        return records.filter { record in
            record.category.localizedCaseInsensitiveContains(debouncedText) ||
            record.note.localizedCaseInsensitiveContains(debouncedText)
        }
    }

    var body: some View {
        NavigationStack {
            List(filteredRecords) { record in
                RecordRowView(record: record)
            }
            .searchable(text: $searchText, prompt: "搜索记录")
            .onChange(of: searchText) { _, newValue in
                debounceSearch(newValue)
            }
            .navigationTitle("搜索")
        }
    }

    private func debounceSearch(_ text: String) {
        Task {
            try? await Task.sleep(for: .milliseconds(300))
            if text == searchText {
                debouncedText = text
            }
        }
    }
}
```

> 💡 **提示**：如果搜索只是本地过滤（如上例），不需要 debounce，因为本地过滤速度很快。debounce 主要用于网络搜索场景，避免频繁发请求。

#### 模糊匹配

有时候用户输入"餐"想搜"餐饮"，输入"打"想搜"打车"。简单的 `contains` 就能做到基本的模糊匹配：

| 匹配方式 | 代码 | "餐"能匹配"餐饮"吗 | "cy"能匹配"餐饮"吗 |
|---------|------|-------------------|-------------------|
| 精确匹配 | `text == search` | ❌ | ❌ |
| 包含匹配 | `text.contains(search)` | ✅ | ❌ |
| 忽略大小写 | `text.localizedCaseInsensitiveContains(search)` | ✅ | ❌ |
| 拼音匹配 | 需要自定义 | ✅ | ✅ |

拼音匹配需要额外处理，这里提供一个简化版本：

```swift
extension String {
    var pinyin: String {
        let mutable = NSMutableString(string: self)
        CFStringTransform(mutable, nil, kCFStringTransformToLatin, false)
        CFStringTransform(mutable, nil, kCFStringTransformStripDiacritics, false)
        return (mutable as String).lowercased()
    }

    func fuzzyMatch(_ query: String) -> Bool {
        localizedCaseInsensitiveContains(query) || pinyin.contains(query.lowercased())
    }
}
```

使用：

```swift
var filteredRecords: [Record] {
    if searchText.isEmpty { return records }
    return records.filter { record in
        record.category.fuzzyMatch(searchText) ||
        record.note.fuzzyMatch(searchText)
    }
}
```

#### 多条件筛选

将搜索和筛选结合使用：

```swift
struct FilterableListView: View {
    @State private var records = SampleData.recentRecords
    @State private var searchText = ""
    @State private var filters = FilterOptions()
    @State private var showFilterSheet = false

    var filteredRecords: [Record] {
        var result = records

        if !searchText.isEmpty {
            result = result.filter { $0.category.fuzzyMatch(searchText) || $0.note.fuzzyMatch(searchText) }
        }

        if let type = filters.type {
            result = result.filter { $0.type == type }
        }

        if let dateRange = filters.dateRange {
            let calendar = Calendar.current
            let now = Date()
            result = result.filter { record in
                switch dateRange {
                case .thisWeek:
                    return calendar.isDate(record.date, equalTo: now, toGranularity: .weekOfYear)
                case .thisMonth:
                    return calendar.isDate(record.date, equalTo: now, toGranularity: .month)
                case .thisYear:
                    return calendar.isDate(record.date, equalTo: now, toGranularity: .year)
                }
            }
        }

        return result
    }

    var activeFilterCount: Int {
        var count = 0
        if filters.type != nil { count += 1 }
        if filters.dateRange != nil { count += 1 }
        return count
    }

    var body: some View {
        NavigationStack {
            List(filteredRecords) { record in
                RecordRowView(record: record)
            }
            .searchable(text: $searchText, prompt: "搜索记录")
            .toolbar {
                ToolbarItem(placement: .topBarTrailing) {
                    Button {
                        showFilterSheet = true
                    } label: {
                        HStack(spacing: 4) {
                            Image(systemName: "line.3.horizontal.decrease.circle")
                            if activeFilterCount > 0 {
                                Text("\(activeFilterCount)")
                                    .font(.caption2)
                                    .fontWeight(.bold)
                                    .foregroundStyle(.white)
                                    .padding(4)
                                    .background(.blue)
                                    .clipShape(Circle())
                            }
                        }
                    }
                }
            }
            .sheet(isPresented: $showFilterSheet) {
                FilterSheetView(filters: $filters)
            }
            .navigationTitle("记录")
        }
    }
}
```

> 💡 **提示**：筛选按钮上显示激活的筛选条件数量（如小蓝点数字），能让用户一眼看出"当前有没有筛选条件"。

### 用户偏好存储

#### @AppStorage

`@AppStorage` 是 SwiftUI 提供的属性包装器，底层使用 `UserDefaults`，值变化时自动刷新 UI。

```swift
@AppStorage("username") private var username = ""
@AppStorage("launchCount") private var launchCount = 0
@AppStorage("isDarkMode") private var isDarkMode = false
```

| 特点 | 说明 |
|------|------|
| 自动持久化 | 值变化自动保存到 UserDefaults |
| 自动刷新 UI | 值变化时 View 自动重绘 |
| 类型安全 | 支持 String、Int、Double、Bool、URL、Data 等 |
| 作用域 | 同一 App 内全局共享 |

> ⚠️ **警告**：`@AppStorage` 不适合存储大量数据或敏感数据（如密码、Token）。它本质是 `UserDefaults`，数据以明文存储在 plist 文件中，任何人都能读取。

#### UserDefaults 封装

当设置项很多时，散落的 `@AppStorage` 不好管理。可以封装一个统一的设置管理类：

```swift
import Foundation

@Observable
class AppSettings {
    static let shared = AppSettings()

    var currency: String {
        didSet { UserDefaults.standard.set(currency, forKey: "currency") }
    }

    var isNotificationEnabled: Bool {
        didSet { UserDefaults.standard.set(isNotificationEnabled, forKey: "isNotificationEnabled") }
    }

    var defaultRecordType: String {
        didSet { UserDefaults.standard.set(defaultRecordType, forKey: "defaultRecordType") }
    }

    private init() {
        self.currency = UserDefaults.standard.string(forKey: "currency") ?? "CNY"
        self.isNotificationEnabled = UserDefaults.standard.object(forKey: "isNotificationEnabled") as? Bool ?? true
        self.defaultRecordType = UserDefaults.standard.string(forKey: "defaultRecordType") ?? "支出"
    }
}
```

使用方式：

```swift
struct SettingsView: View {
    private let settings = AppSettings.shared

    var body: some View {
        Form {
            Picker("货币", selection: Bindable(settings).currency) {
                Text("人民币 (CNY)").tag("CNY")
                Text("美元 (USD)").tag("USD")
            }
        }
    }
}
```

> 💡 **提示**：简单项目直接用 `@AppStorage` 就够了。只有当设置项超过 10 个，或者需要在 ViewModel 中访问设置时，才考虑封装。

## 数据缓存策略

> 🎯 **本节目标**：理解内存缓存、磁盘缓存和缓存过期策略，学会为 App 添加合理的缓存机制。

如果你的 App 是纯本地存储（如记账 App），可以跳过本节。但如果你的 App 有网络请求（如天气 App、新闻 App），缓存能大幅提升用户体验。

### 内存缓存

#### NSCache

`NSCache` 是 Apple 提供的线程安全的内存缓存，类似字典但能自动清理：

| 特性 | NSCache | Dictionary |
|------|---------|------------|
| 线程安全 | ✅ 自动加锁 | ❌ 需手动加锁 |
| 内存不足时 | ✅ 自动清理 | ❌ 不会清理 |
| Key 要求 | AnyObject | Hashable |
| 用途 | 缓存图片、数据 | 普通键值存储 |

#### 简单缓存实现

```swift
import Foundation

final class MemoryCache<T: AnyObject> {
    private let cache = NSCache<NSString, CacheWrapper<T>>()

    init(countLimit: Int = 100, totalCostLimit: Int = 50 * 1024 * 1024) {
        cache.countLimit = countLimit
        cache.totalCostLimit = totalCostLimit
    }

    func set(_ value: T, forKey key: String, cost: Int = 0) {
        cache.setObject(CacheWrapper(value), forKey: key as NSString, cost: cost)
    }

    func get(forKey key: String) -> T? {
        cache.object(forKey: key as NSString)?.value
    }

    func remove(forKey key: String) {
        cache.removeObject(forKey: key as NSString)
    }

    func removeAll() {
        cache.removeAllObjects()
    }
}

private final class CacheWrapper<T> {
    let value: T
    init(_ value: T) { self.value = value }
}
```

使用示例：

```swift
let imageCache = MemoryCache<UIImage>()

func loadImage(url: String) async -> UIImage? {
    if let cached = imageCache.get(forKey: url) {
        return cached
    }

    guard let url = URL(string: url) else { return nil }
    guard let (data, _) = try? await URLSession.shared.data(from: url) else { return nil }
    let image = UIImage(data: data)
    if let image {
        imageCache.set(image, forKey: url.absoluteString, cost: data.count)
    }
    return image
}
```

### 磁盘缓存

内存缓存在 App 退出后就没了。磁盘缓存可以持久保存，下次启动还在。

#### 文件缓存

```swift
import Foundation

final class DiskCache {
    private let fileManager = FileManager.default
    private let cacheDirectory: URL

    init(directory: String = "AppCache") {
        let cachesDir = fileManager.urls(for: .cachesDirectory, in: .userDomainMask)[0]
        cacheDirectory = cachesDir.appendingPathComponent(directory)
        try? fileManager.createDirectory(at: cacheDirectory, withIntermediateDirectories: true)
    }

    func set(_ data: Data, forKey key: String) {
        let fileURL = cacheDirectory.appendingPathComponent(key.md5)
        try? data.write(to: fileURL)
    }

    func get(forKey key: String) -> Data? {
        let fileURL = cacheDirectory.appendingPathComponent(key.md5)
        return try? Data(contentsOf: fileURL)
    }

    func remove(forKey key: String) {
        let fileURL = cacheDirectory.appendingPathComponent(key.md5)
        try? fileManager.removeItem(at: fileURL)
    }

    func removeAll() {
        try? fileManager.removeItem(at: cacheDirectory)
        try? fileManager.createDirectory(at: cacheDirectory, withIntermediateDirectories: true)
    }

    var totalSize: Int {
        guard let enumerator = fileManager.enumerator(at: cacheDirectory, includingPropertiesForKeys: [.fileSizeKey]) else { return 0 }
        var size = 0
        for case let fileURL as URL in enumerator {
            if let resourceValues = try? fileURL.resourceValues(forKeys: [.fileSizeKey]),
               let fileSize = resourceValues.fileSize {
                size += fileSize
            }
        }
        return size
    }
}

extension String {
    var md5: String {
        var hash: [UInt8] = Array(repeating: 0, count: Int(CC_MD5_DIGEST_LENGTH))
        self.utf8CString.withUnsafeBufferPointer { buffer in
            CC_MD5(buffer.baseAddress, CC_LONG(buffer.count - 1), &hash)
        }
        return hash.map { String(format: "%02x", $0) }.joined()
    }
}
```

> ⚠️ **警告**：上例中的 `md5` 计算需要 `import CommonCrypto`。在 Swift 中使用 CommonCrypto 需要在 Bridging Header 中引入，或者使用纯 Swift 的 CryptoKit 替代。新手可以先简单用 `key.data(using: .utf8)!.base64EncodedString()` 代替 md5。

#### 缓存目录管理

| 目录 | 用途 | 系统清理 | 适合存什么 |
|------|------|---------|-----------|
| `cachesDirectory` | 缓存 | ✅ 系统空间不足时自动清理 | 图片缓存、API 缓存 |
| `applicationSupportDirectory` | 应用支持数据 | ❌ 不会自动清理 | 数据库、配置文件 |
| `documentDirectory` | 用户文档 | ❌ 不会自动清理 | 用户导出的文件 |
| `tmp` | 临时文件 | ✅ 系统可能清理 | 临时下载文件 |

> 💡 **提示**：缓存数据放 `cachesDirectory`，用户数据放 `documentDirectory`。放错位置可能导致 App Store 审核被拒（用户数据放 caches 会被系统清理，缓存放 documents 会被认为占空间）。

### 缓存过期策略

#### TTL 过期

TTL（Time To Live）是最简单的过期策略：每个缓存数据记录一个过期时间，读取时检查是否过期。

```swift
struct CacheEntry<T> {
    let value: T
    let expirationDate: Date

    var isExpired: Bool {
        Date() > expirationDate
    }
}

final class TTLCache<T> {
    private var storage: [String: CacheEntry<T>] = [:]
    private let defaultTTL: TimeInterval

    init(defaultTTL: TimeInterval = 300) {
        self.defaultTTL = defaultTTL
    }

    func set(_ value: T, forKey key: String, ttl: TimeInterval? = nil) {
        let expiration = Date().addingTimeInterval(ttl ?? defaultTTL)
        storage[key] = CacheEntry(value: value, expirationDate: expiration)
    }

    func get(forKey key: String) -> T? {
        guard let entry = storage[key] else { return nil }
        if entry.isExpired {
            storage.removeValue(forKey: key)
            return nil
        }
        return entry.value
    }

    func remove(forKey key: String) {
        storage.removeValue(forKey: key)
    }

    func removeAll() {
        storage.removeAll()
    }

    func cleanExpired() {
        storage = storage.filter { !$0.value.isExpired }
    }
}
```

#### LRU 淘汰

LRU（Least Recently Used）是"最近最少使用"策略：当缓存满了，优先淘汰最久没被访问的数据。

```swift
final class LRUCache<Key: Hashable, Value> {
    private var cache: [Key: Value] = [:]
    private var order: [Key] = []
    private let capacity: Int

    init(capacity: Int = 100) {
        self.capacity = capacity
    }

    func get(_ key: Key) -> Value? {
        guard let value = cache[key] else { return nil }
        moveToEnd(key)
        return value
    }

    func set(_ value: Value, forKey key: Key) {
        if cache[key] != nil {
            cache[key] = value
            moveToEnd(key)
        } else {
            if cache.count >= capacity, let oldest = order.first {
                cache.removeValue(forKey: oldest)
                order.removeFirst()
            }
            cache[key] = value
            order.append(key)
        }
    }

    private func moveToEnd(_ key: Key) {
        order.removeAll { $0 == key }
        order.append(key)
    }
}
```

#### 缓存策略对比

| 策略 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| TTL | 固定时间过期 | 简单，数据新鲜 | 可能频繁过期 | 新闻、天气等时效性数据 |
| LRU | 淘汰最久未用 | 缓存命中率高 | 实现稍复杂 | 图片、通用数据缓存 |
| FIFO | 先进先出 | 最简单 | 命中率低 | 不推荐 |

> 💡 **提示**：新手项目推荐 TTL 策略，实现简单、效果够用。等 App 用户量上来后，再考虑更复杂的 LRU 或混合策略。

### 重试机制

#### 自动重试

对于偶发的网络错误，自动重试比让用户手动点更友好：

```swift
actor RetryManager {
    private let maxRetries: Int
    private let baseDelay: TimeInterval

    init(maxRetries: Int = 3, baseDelay: TimeInterval = 1.0) {
        self.maxRetries = maxRetries
        self.baseDelay = baseDelay
    }

    func perform<T>(operation: @Sendable () async throws -> T) async throws -> T {
        var lastError: Error?

        for attempt in 0..<maxRetries {
            do {
                return try await operation()
            } catch {
                lastError = error
                if attempt < maxRetries - 1 {
                    let delay = baseDelay * pow(2.0, Double(attempt))
                    try? await Task.sleep(for: .seconds(delay))
                }
            }
        }

        throw lastError!
    }
}
```

重试策略说明：

| 重试次数 | 等待时间 | 说明 |
|---------|---------|------|
| 第 1 次 | 1 秒 | 快速重试 |
| 第 2 次 | 2 秒 | 稍等一下 |
| 第 3 次 | 4 秒 | 等久一点 |
| 放弃 | — | 提示用户手动重试 |

> ⚠️ **警告**：不是所有错误都应该自动重试。401（未登录）、400（参数错误）这类错误重试也不会成功，只有超时、网络中断等临时性错误才值得重试。

#### 手动重试

自动重试失败后，给用户提供手动重试按钮：

```swift
struct RetryableView: View {
    @State private var state: LoadingState<[Record]> = .idle
    @State private var retryCount = 0

    var body: some View {
        RemoteContentView(
            state: state,
            retryAction: {
                retryCount += 1
                loadData()
            }
        ) { records in
            List(records) { record in
                RecordRowView(record: record)
            }
        }
    }

    private func loadData() {
        state = .loading
        Task {
            do {
                let manager = RetryManager()
                let response: APIResponse<[Record]> = try await manager.perform {
                    try await NetworkManager.shared.get(url: "/records")
                }
                state = .success(response.data)
            } catch let error as NetworkError {
                state = .failure(error)
            } catch {
                state = .failure(.serverError(error.localizedDescription))
            }
        }
    }
}
```

> 🎯 **本节目标**：学会用 AI 工具帮你找 Bug、重构代码、优化性能，大幅提升开发效率。

### 让 AI 帮你找 Bug

当你遇到 Bug 但不知道原因时，把相关代码和错误信息发给 AI：

**Prompt 模板：**

```
我的 SwiftUI 代码出现了 Bug，请帮我分析原因。

现象：[描述 Bug 的具体表现]
期望：[描述正确的行为应该是什么]

相关代码：
```swift
// 粘贴你的代码
```

错误信息（如有）：
```
// 粘贴控制台输出或编译错误
```

请分析可能的原因，并给出修复方案。
```

**示例：**

```
我的 SwiftUI 代码出现了 Bug，请帮我分析原因。

现象：列表数据更新后，UI 没有刷新
期望：数据更新后，列表应该自动显示新数据

相关代码：
```swift
class RecordViewModel {
    var records: [Record] = []

    func addRecord(_ record: Record) {
        records.append(record)
    }
}
```

请分析可能的原因，并给出修复方案。
```

AI 会指出：`records` 没有标记为 `@Published`，SwiftUI 无法感知数据变化。修复方法是把 `var records` 改为 `@Published var records`，或使用 `@Observable` 宏。

### 让 AI 帮你重构代码

当你觉得代码"写得不好"但不知道怎么改时：

**Prompt 模板：**

```
请帮我重构以下 SwiftUI 代码，要求：
1. 遵循 MVVM 架构
2. View 代码不超过 80 行
3. 提取可复用组件
4. 改善命名

原始代码：
```swift
// 粘贴你的代码
```

请给出重构后的代码，并说明每处修改的原因。
```

当 App 出现卡顿、内存占用高等问题时：

**Prompt 模板：**

```
我的 SwiftUI App 出现了性能问题，请帮我优化。

问题：[描述性能问题，如"列表滑动卡顿"、"启动慢"等]

相关代码：
```swift
// 粘贴你的代码
```

请分析性能瓶颈，并给出优化方案。重点关注：
1. 是否有不必要的重绘

```

### Prompt 模板速查

| 场景 | Prompt 关键词 | 示例 |
|------|-------------|------|
| 找 Bug | 现象 + 期望 + 代码 + 错误信息 | "列表不刷新，代码如下..." |
| 重构 | 要求 + 原始代码 | "遵循 MVVM，提取组件..." |
| 优化 | 问题 + 代码 + 关注点 | "列表卡顿，关注重绘..." |
| 新功能 | 需求 + 现有代码 | "添加搜索功能，现有代码..." |
| 解释代码 | 代码 + 疑问 | "这段代码为什么用 @State..." |

> 💡 **提示**：AI 辅助的关键是**给够上下文**。你提供的信息越详细（代码、错误信息、期望行为），AI 给出的答案越精准。不要只说"代码有 Bug"，要说"点击保存按钮后列表不刷新"。

> ⚠️ **警告**：AI 给出的代码一定要自己理解和测试后再使用。AI 可能会生成看起来正确但有隐藏问题的代码，比如内存泄漏、线程安全问题等。

## 小结

本章我们完成了核心功能开发的下半部分：

| 主题 | 核心要点 | 一句话总结 |
|------|---------|-----------|
| 搜索与筛选 | .searchable + debounce + 多条件筛选 | 搜索要快，筛选要灵活 |
| 设置页面 | Form + @AppStorage + UserDefaults 封装 | 设置分组展示，偏好自动存储 |
| 数据缓存 | NSCache（内存）+ 磁盘缓存 + TTL/LRU | 内存缓存快但临时，磁盘缓存慢但持久 |
| 错误与空状态 | LoadingState + ErrorView + EmptyStateView | 错误要提示，空状态要引导 |
| AI 辅助 | 找 Bug / 重构 / 优化的 Prompt 模板 | 给够上下文，AI 才能帮到你 |

**记住这三个核心原则：**

1. **用户永远不该看到空白页**：加载中显示进度，出错显示提示，无数据显示引导
2. **缓存让 App 更快**：合理使用内存缓存和磁盘缓存，减少不必要的网络请求
3. **AI 是助手不是替代**：AI 给的代码要理解、要测试，不要盲目复制
