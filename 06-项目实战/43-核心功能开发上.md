| T02 | 创建 Category 数据模型 | ⬜ 待开始 |
| T03 | 实现主界面 TabBar + 导航 | ⬜ 待开始 |

> 💡 **提示**：把任务清单贴在显眼的地方（比如 Notion、Xcode 的 TODO 注释里），每完成一个就打勾。这种"看得见的进度"能有效防止拖延。

### 按优先级逐个完成

开发顺序不是随意的，要遵循**依赖关系**和**优先级**：

```
T01 (Record 模型) ──┬──► T03 (主界面) ──► T04 (首页)
                     │
T02 (Category 模型) ─┘         │
                               ▼
                    T05 (记账页面) ──► T06 (记录列表)
                                            │
                    T09 (网络层) ────────────┤
                                            ▼
                    T07 (统计) ──► T08 (设置) ──► T10 (搜索)
```

**核心原则：先做被依赖的任务，再做依赖别人的任务。**

### 每完成一个任务就测试

不要等所有功能都做完才测试！每完成一个任务，立刻验证：

| 测试类型 | 什么时候做 | 怎么做 |
|---------|-----------|--------|
| 编译测试 | 每次保存文件后 | Xcode 自动编译，看有没有红色错误 |
| 预览测试 | 写完 UI 代码后 | Canvas 实时预览，检查布局 |
| 功能测试 | 完成一个完整功能后 | 模拟器运行，手动操作验证 |
| 边界测试 | 功能测试通过后 | 输入空值、极大值、特殊字符 |

> ⚠️ **警告**：很多新手喜欢"一口气写完所有代码再测试"，结果出了 Bug 不知道是哪段代码引起的。养成"写一点、测一点"的习惯，问题定位效率提升 10 倍。

## 主界面与导航

> 🎯 **本节目标**：完成 App 的主界面框架，包括 TabBar、导航结构和首页布局，让 App 有一个清晰的"骨架"。

### TabBar 设计

TabBar 是 App 底部的标签栏，用户通过它切换不同功能模块。

#### Tab 数量选择

| Tab 数量 | 适合场景 | 示例 |
|----------|---------|------|
| 3 个 | 功能简单的 App | 首页 / 统计 / 设置 |
| 4 个 | 中等复杂度 | 首页 / 记账 / 统计 / 设置 |
| 5 个 | 功能丰富的 App | 首页 / 发现 / 记账 / 消息 / 我的 |

> 💡 **提示**：Tab 数量建议 3-5 个，不要超过 5 个。超过 5 个会被系统压缩成"更多"，用户体验很差。

#### TabView 使用

SwiftUI 用 `TabView` 来实现底部标签栏：

```swift
import SwiftUI

struct ContentView: View {
    @State private var selectedTab = 0

    var body: some View {
        TabView(selection: $selectedTab) {
            HomeView()
                .tabItem {
                    Label("首页", systemImage: "house.fill")
                }
                .tag(0)

            StatisticsView()
                .tabItem {
                    Label("统计", systemImage: "chart.pie.fill")
                }
                .tag(1)

            RecordAddView()
                .tabItem {
                    Label("记账", systemImage: "plus.circle.fill")
                }
                .tag(2)

            SettingsView()
                .tabItem {
                    Label("设置", systemImage: "gearshape.fill")
                }
                .tag(3)
        }
        .tint(.blue)
    }
}
```

### 导航结构

#### NavigationStack 嵌套

SwiftUI 用 `NavigationStack` 管理页面导航栈。用户点击跳转时，新页面"推入"栈顶；点击返回时，页面"弹出"栈顶。

```
┌─────────────────────────────┐
│  NavigationStack            │
│  ┌───────────────────────┐  │
│  │ 首页 (根页面)          │  │
│  │   └─► 记录详情页      │  │
│  │       └─► 编辑页面    │  │
│  └───────────────────────┘  │
└─────────────────────────────┘

┌─────────────────────────────┐
│  NavigationStack            │
│  ┌───────────────────────┐  │
│  │ 统计 (根页面)          │  │
│  │   └─► 分类详情页      │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

#### 页面层级设计

合理的页面层级应该是这样的：

| 层级 | 页面类型 | 示例 | 导航方式 |
|------|---------|------|---------|
| 第一层 | Tab 根页面 | 首页、统计、设置 | TabView 切换 |
| 第二层 | 列表详情页 | 记录详情、分类详情 | NavigationLink 推入 |
| 第三层 | 编辑/操作页 | 编辑记录、添加分类 | NavigationLink 推入 |
| 弹出层 | 模态页面 | 新增记账、筛选面板 | .sheet() 弹出 |

> 💡 **提示**：页面层级不要超过 3 层。超过 3 层用户会"迷路"，不知道怎么回到首页。深层操作用 `.sheet()` 弹出代替推入。

#### 示例

```swift
struct HomeView: View {
    let records: [Record] = []

    var body: some View {
        List(records) { record in
            NavigationLink {
                RecordDetailView(record: record)
            } label: {
                RecordRowView(record: record)
            }
        }
        .navigationTitle("小账本")
        .toolbar {
            ToolbarItem(placement: .topBarTrailing) {
                Button {
                    showAddSheet = true
                } label: {
                    Image(systemName: "plus")
                }
            }
        }
        .sheet(isPresented: $showAddSheet) {
            RecordAddView()
        }
    }

    @State private var showAddSheet = false
}

struct RecordDetailView: View {
    let record: Record

    var body: some View {
        VStack(spacing: 16) {
            Text(record.displayAmount)
                .font(.largeTitle)
            Text(record.category)
            Text(record.note)
        }
        .navigationTitle("记录详情")
        .navigationBarTitleDisplayMode(.inline)
        .toolbar {
            ToolbarItem(placement: .topBarTrailing) {
                NavigationLink {
                    RecordEditView(record: record)
                } label: {
                    Text("编辑")
                }
            }
        }
    }
}
```

### 首页布局

首页是用户打开 App 后看到的第一个页面，需要展示最核心的信息。

#### 首页内容设计

以记账 App 为例，首页应该包含：

| 区域 | 内容 | 优先级 |
|------|------|--------|
| 顶部卡片 | 本月收支概览 | P0 |
| 快捷操作 | 快速记账按钮 | P0 |
| 近期记录 | 最近 5-10 条记录 | P0 |
| 趋势预览 | 近 7 天支出趋势 | P1 |

#### ScrollView + LazyVStack

首页内容通常超过一屏，需要用 `ScrollView` 来支持滚动。`LazyVStack` 可以实现懒加载，只渲染可见区域的元素，性能更好。

| 容器 | 是否懒加载 | 适用场景 |
|------|-----------|---------|
| `VStack` | ❌ 全部渲染 | 内容少，不超过一屏 |
| `ScrollView + VStack` | ❌ 全部渲染 | 内容稍多但元素少 |
| `ScrollView + LazyVStack` | ✅ 按需渲染 | 内容多，元素多（推荐） |
| `List` | ✅ 按需渲染 | 列表场景，自带样式 |

#### 完整代码示例

```swift
import SwiftUI

struct HomeView: View {
    @State private var records = SampleData.recentRecords
    @State private var showAddSheet = false

    var totalExpense: Double {
        records.filter { $0.type == .expense }.reduce(0) { $0 + $1.amount }
    }

    var totalIncome: Double {
        records.filter { $0.type == .income }.reduce(0) { $0 + $1.amount }
    }

    var body: some View {
        NavigationStack {
            ScrollView {
                VStack(spacing: 20) {
                    overviewCard
                    recentRecordsSection
                }
                .padding()
            }
            .navigationTitle("小账本")
            .toolbar {
                ToolbarItem(placement: .topBarTrailing) {
                    Button {
                        showAddSheet = true
                    } label: {
                        Image(systemName: "plus.circle.fill")
                            .font(.title2)
                    }
                }
            }
            .sheet(isPresented: $showAddSheet) {
                Text("记账页面")
            }
        }
    }

    private var overviewCard: some View {
        VStack(spacing: 12) {
            Text("本月概览")
                .font(.headline)
                .foregroundStyle(.secondary)

            HStack(spacing: 40) {
                VStack(spacing: 4) {
                    Text("支出")
                        .font(.caption)
                        .foregroundStyle(.secondary)
                    Text("-\(String(format: "%.2f", totalExpense))")
                        .font(.title2)
                        .fontWeight(.bold)
                        .foregroundStyle(.red)
                }

                VStack(spacing: 4) {
                    Text("收入")
                        .font(.caption)
                        .foregroundStyle(.secondary)
                    Text("+\(String(format: "%.2f", totalIncome))")
                        .font(.title2)
                        .fontWeight(.bold)
                        .foregroundStyle(.green)
                }
            }
        }
        .frame(maxWidth: .infinity)
        .padding()
        .background(.ultraThinMaterial)
        .clipShape(RoundedRectangle(cornerRadius: 16))
    }

    private var recentRecordsSection: some View {
        VStack(alignment: .leading, spacing: 12) {
            HStack {
                Text("近期记录")
                    .font(.headline)
                Spacer()
                NavigationLink("查看全部") {
                    Text("全部记录")
                }
                .font(.subheadline)
            }

            LazyVStack(spacing: 8) {
                ForEach(records.prefix(10)) { record in
                    RecordRowView(record: record)
                }
            }
        }
    }
}

struct RecordRowView: View {
    let record: Record

    var body: some View {
        HStack {
            Image(systemName: "circle.fill")
                .foregroundStyle(record.type == .expense ? .red : .green)

            VStack(alignment: .leading, spacing: 2) {
                Text(record.category)
                    .font(.body)
                if !record.note.isEmpty {
                    Text(record.note)
                        .font(.caption)
                        .foregroundStyle(.secondary)
                }
            }

            Spacer()

            Text(record.displayAmount)
                .fontWeight(.medium)
                .foregroundStyle(record.type == .expense ? .red : .green)
        }
        .padding(.vertical, 4)
    }
}

#Preview {
    HomeView()
}
```

> 💡 **提示**：首页布局建议先做最简版本——一个概览卡片 + 一个记录列表。等核心功能跑通后，再逐步添加趋势图、快捷操作等。

## 数据模型设计

> 🎯 **本节目标**：学会根据技术方案定义数据模型，理解模型之间的关系，并创建预览用的示例数据。

### 核心模型定义

数据模型是 App 的"骨架"，所有功能都建立在模型之上。在 [30-Spec 驱动](30-Spec驱动编写完整项目Spec.md) 中，我们已经规划了核心模型，现在把它变成代码。

#### 根据技术方案定义模型

以记账 App 为例，核心模型有三个：

| 模型 | 用途 | 关键字段 |
|------|------|---------|
| Record | 记账记录 | 金额、分类、日期、备注 |
| Category | 分类 | 名称、图标、类型 |
| Budget | 预算 | 分类、金额、月份 |

#### @Model vs Codable 选择

| 方案 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| `@Model`（SwiftData） | 需要本地持久化存储 | 自动持久化、支持查询、支持关系 | 仅 iOS 17+ |
| `Codable` | 只需网络传输/临时使用 | 轻量、兼容性好 | 不会自动存储 |

> 💡 **提示**：如果你的 App 需要把数据保存到本地（绝大多数 App 都需要），用 `@Model`。如果只是从网络获取数据展示，用 `Codable`。两者也可以结合使用——网络层用 `Codable` 解码，存储层用 `@Model` 持久化。

#### 示例

```swift
import Foundation
import SwiftData

@Model
class Record {
    var id: UUID
    var amount: Double
    var type: RecordType
    var category: String
    var note: String
    var date: Date

    init(amount: Double, type: RecordType, category: String, note: String = "", date: Date = .now) {
        self.id = UUID()
        self.amount = amount
        self.type = type
        self.category = category
        self.note = note
        self.date = date
    }

    var isValid: Bool {
        amount > 0 && !category.isEmpty
    }

    var displayAmount: String {
        let prefix = type == .expense ? "-" : "+"
        return "\(prefix)\(String(format: "%.2f", amount))"
    }
}

enum RecordType: String, Codable, CaseIterable {
    case expense = "支出"
    case income = "收入"
}

@Model
class Category {
    var id: UUID
    var name: String
    var icon: String
    var type: RecordType
    var isDefault: Bool

    init(name: String, icon: String, type: RecordType, isDefault: Bool = false) {
        self.id = UUID()
        self.name = name
        self.icon = icon
        self.type = type
        self.isDefault = isDefault
    }
}

@Model
class Budget {
    var id: UUID
    var category: String
    var amount: Double
    var month: Date

    init(category: String, amount: Double, month: Date) {
        self.id = UUID()
        self.category = category
        self.amount = amount
        self.month = month
    }
}
```

### 模型关系

模型之间往往不是孤立的，而是存在关联关系。

#### 一对一

一个 Record 对应一个 Category：

```swift
@Model
class Record {
    var id: UUID
    var amount: Double
    var type: RecordType
    var note: String
    var date: Date
    var category: Category?

    init(amount: Double, type: RecordType, category: Category? = nil, note: String = "", date: Date = .now) {
        self.id = UUID()
        self.amount = amount
        self.type = type
        self.category = category
        self.note = note
        self.date = date
    }
}
```

#### 一对多

一个 Category 下有多条 Record：

```swift
@Model
class Category {
    var id: UUID
    var name: String
    var icon: String
    var type: RecordType
    var isDefault: Bool
    var records: [Record] = []

    init(name: String, icon: String, type: RecordType, isDefault: Bool = false) {
        self.id = UUID()
        self.name = name
        self.icon = icon
        self.type = type
        self.isDefault = isDefault
    }
}

@Model
class Record {
    var id: UUID
    var amount: Double
    var type: RecordType
    var note: String
    var date: Date
    var category: Category?

    init(amount: Double, type: RecordType, category: Category? = nil, note: String = "", date: Date = .now) {
        self.id = UUID()
        self.amount = amount
        self.type = type
        self.category = category
        self.note = note
        self.date = date
    }
}
```

> ⚠️ **警告**：SwiftData 的关系默认是**懒加载**的。如果你在 View 中直接访问 `category.records`，可能会触发多次数据库查询。建议在 ViewModel 中一次性查询好需要的数据，再传给 View。

#### 关系类型对比

| 关系类型 | 示例 | SwiftData 写法 |
|---------|------|---------------|
| 一对一 | 一个用户有一个头像 | `var avatar: Avatar?` |
| 一对多 | 一个分类有多条记录 | `var records: [Record] = []` |
| 多对多 | 一条记录有多个标签 | `var tags: [Tag] = []`（需加 `@Relationship`） |

> 💡 **提示**：新手项目建议先用简单关系（一对一、一对多），避免多对多关系的复杂性。等 App 成熟后再考虑引入多对多。

### 示例数据

开发 UI 时，我们需要一些假数据来预览效果。手动一条条创建太麻烦，写一个 `SampleData` 工具类来批量生成。

#### 创建预览数据

```swift
import Foundation

enum SampleData {
    static let expenseCategories: [Category] = {
        let names = ["餐饮", "交通", "购物", "娱乐", "居住", "医疗", "教育", "通讯"]
        let icons = ["fork.knife", "car.fill", "bag.fill", "gamecontroller.fill", "house.fill", "cross.case.fill", "book.fill", "phone.fill"]
        return zip(names, icons).map { name, icon in
            Category(name: name, icon: icon, type: .expense, isDefault: true)
        }
    }()

    static let incomeCategories: [Category] = {
        let names = ["工资", "兼职", "理财", "红包"]
        let icons = ["banknote.fill", "briefcase.fill", "chart.line.uptrend.xyaxis", "gift.fill"]
        return zip(names, icons).map { name, icon in
            Category(name: name, icon: icon, type: .income, isDefault: true)
        }
    }()

    static let recentRecords: [Record] = {
        let items: [(Double, RecordType, String, String)] = [
            (35.0, .expense, "餐饮", "午餐"),
            (128.0, .expense, "购物", "日用品"),
            (6.0, .expense, "交通", "地铁"),
            (5000.0, .income, "工资", "5月工资"),
            (25.0, .expense, "餐饮", "早餐"),
            (200.0, .expense, "娱乐", "电影"),
            (15.0, .expense, "通讯", "话费"),
            (50.0, .expense, "交通", "打车"),
        ]
        return items.enumerated().map { index, item in
            let date = Calendar.current.date(byAdding: .hour, value: -index * 3, to: .now) ?? .now
            return Record(amount: item.0, type: item.1, category: item.2, note: item.3, date: date)
        }
    }()
}
```

## 网络层封装

> 🎯 **本节目标**：学会封装一个通用的网络请求层，让 API 调用变得简洁、统一、易维护。

如果你的 App 是纯本地存储（如记账 App），可以跳过本节。但如果你的 App 需要请求服务器接口（如天气 App、新闻 App），网络层是必不可少的。

### API 基础配置

#### BaseURL

不同环境使用不同的服务器地址：

| 环境 | BaseURL | 用途 |
|------|---------|------|
| 开发 | `https://dev-api.example.com` | 开发调试 |
| 测试 | `https://staging-api.example.com` | 测试验证 |
| 生产 | `https://api.example.com` | 正式上线 |

```swift
enum APIEnvironment {
    case development
    case staging
    case production

    var baseURL: String {
        switch self {
        case .development: return "https://dev-api.example.com"
        case .staging: return "https://staging-api.example.com"
        case .production: return "https://api.example.com"
        }
    }
}
```

#### API Key 管理

> ⚠️ **警告**：API Key 绝对不能硬编码在代码里！推到 GitHub 就等于公开了你的密钥。

正确的做法是把 Key 存在 `Info.plist` 或 `xcconfig` 文件中：

**方式一：Info.plist**

在 `Info.plist` 中添加：

```xml
<key>API_KEY</key>
<string>your_api_key_here</string>
```

代码中读取：

```swift
enum APIConfig {
    static var apiKey: String {
        guard let key = Bundle.main.infoDictionary?["API_KEY"] as? String else {
            fatalError("API_KEY not found in Info.plist")
        }
        return key
    }

    static var environment: APIEnvironment {
        #if DEBUG
        return .development
        #else
        return .production
        #endif
    }
}
```

**方式二：xcconfig 文件（推荐）**

1. 创建 `Config.xcconfig` 文件：

```
API_KEY = your_api_key_here
BASE_URL = https://api.example.com
```

2. 在 Xcode 中配置：Project → Info → Configurations → 选择 xcconfig 文件

3. 在 `.gitignore` 中添加 `*.xcconfig`，避免提交到仓库

> 💡 **提示**：在 `.gitignore` 中加上 `Config.xcconfig`，再提供一个 `Config.xcconfig.example` 模板文件，方便团队其他成员使用。

#### 环境切换

通过编译标志自动切换环境：

```swift
enum APIConfig {
    static var baseURL: String {
        environment.baseURL
    }

    static var environment: APIEnvironment {
        #if DEBUG
        return .development
        #else
        return .production
        #endif
    }
}
```

### 请求封装

#### 泛型请求方法

封装一个通用的请求方法，支持任意类型的响应：

```swift
import Foundation

enum HTTPMethod: String {
    case get = "GET"
    case post = "POST"
    case put = "PUT"
    case delete = "DELETE"
}

class NetworkManager {
    static let shared = NetworkManager()

    private let session: URLSession

    private init() {
        let config = URLSessionConfiguration.default
        config.timeoutIntervalForRequest = 30
        config.timeoutIntervalForResource = 60
        self.session = URLSession(configuration: config)
    }

    func request<T: Decodable>(
        url: String,
        method: HTTPMethod = .get,
        parameters: [String: Any]? = nil,
        headers: [String: String]? = nil
    ) async throws -> T {
        guard var components = URLComponents(string: APIConfig.baseURL + url) else {
            throw NetworkError.invalidURL
        }

        if method == .get, let parameters {
            components.queryItems = parameters.map { key, value in
                URLQueryItem(name: key, value: "\(value)")
            }
        }

        guard let url = components.url else {
            throw NetworkError.invalidURL
        }

        var request = URLRequest(url: url)
        request.httpMethod = method.rawValue
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")

        if let headers {
            for (key, value) in headers {
                request.setValue(value, forHTTPHeaderField: key)
            }
        }

        if method != .get, let parameters {
            request.httpBody = try? JSONSerialization.data(withJSONObject: parameters)
        }

        let (data, response) = try await session.data(for: request)

        guard let httpResponse = response as? HTTPURLResponse else {
            throw NetworkError.invalidResponse
        }

        guard (200...299).contains(httpResponse.statusCode) else {
            throw NetworkError.statusCode(httpResponse.statusCode)
        }

        do {
            let decoder = JSONDecoder()
            decoder.dateDecodingStrategy = .iso8601
            return try decoder.decode(T.self, from: data)
        } catch {
            throw NetworkError.decodingFailed(error)
        }
    }
}
```

#### GET/POST 封装

在泛型方法基础上，提供更简洁的便捷方法：

```swift
extension NetworkManager {
    func get<T: Decodable>(
        url: String,
        parameters: [String: Any]? = nil
    ) async throws -> T {
        try await request(url: url, method: .get, parameters: parameters)
    }

    func post<T: Decodable>(
        url: String,
        parameters: [String: Any]? = nil
    ) async throws -> T {
        try await request(url: url, method: .post, parameters: parameters)
    }

    func put<T: Decodable>(
        url: String,
        parameters: [String: Any]? = nil
    ) async throws -> T {
        try await request(url: url, method: .put, parameters: parameters)
    }

    func delete<T: Decodable>(
        url: String,
        parameters: [String: Any]? = nil
    ) async throws -> T {
        try await request(url: url, method: .delete, parameters: parameters)
    }
}
```

#### 使用示例

```swift
Task {
    do {
        let response: APIResponse<[Record]> = try await NetworkManager.shared.get(
            url: "/api/v1/records",
            parameters: ["page": 1, "pageSize": 20]
        )
        print("获取到 \(response.data.count) 条记录")
    } catch {
        print("请求失败：\(error.localizedDescription)")
    }
}
```

### 响应处理

#### 统一响应模型

大多数后端 API 返回的 JSON 格式是统一的，比如：

```json
{
    "code": 0,
    "message": "success",
    "data": { ... }
}
```

对应的 Swift 模型：

```swift
struct APIResponse<T: Decodable>: Decodable {
    let code: Int
    let message: String
    let data: T

    var isSuccess: Bool {
        code == 0
    }
}
```

#### 错误码处理

| 错误码 | 含义 | 处理方式 |
|--------|------|---------|
| 0 | 成功 | 正常处理数据 |
| 40001 | 参数错误 | 提示用户检查输入 |
| 40101 | 未登录 | 跳转登录页 |
| 40301 | 无权限 | 提示无权限 |
| 50001 | 服务器错误 | 提示稍后重试 |

```swift
extension APIResponse {
    func validate() throws -> T {
        if isSuccess {
            return data
        }
        switch code {
        case 40001:
            throw NetworkError.parameterError(message)
        case 40101:
            throw NetworkError.unauthorized
        case 40301:
            throw NetworkError.forbidden
        case 50001:
            throw NetworkError.serverError(message)
        default:
            throw NetworkError.apiError(code: code, message: message)
        }
    }
}
```

### 错误统一处理

#### 自定义错误类型

```swift
enum NetworkError: LocalizedError {
    case invalidURL
    case invalidResponse
    case statusCode(Int)
    case decodingFailed(Error)
    case parameterError(String)
    case unauthorized
    case forbidden
    case serverError(String)
    case apiError(code: Int, message: String)
    case timeout
    case noNetwork

    var errorDescription: String? {
        switch self {
        case .invalidURL:
            return "请求地址无效"
        case .invalidResponse:
            return "服务器响应异常"
        case .statusCode(let code):
            return "服务器错误（\(code)）"
        case .decodingFailed:
            return "数据解析失败"
        case .parameterError(let message):
            return message
        case .unauthorized:
            return "请先登录"
        case .forbidden:
            return "无权限访问"
        case .serverError(let message):
            return message
        case .apiError(_, let message):
            return message
        case .timeout:
            return "请求超时，请稍后重试"
        case .noNetwork:
            return "网络不可用，请检查网络设置"
        }
    }
}
```

#### 错误展示

在 View 中统一展示错误信息：

```swift
struct ErrorAlertModifier: ViewModifier {
    @Binding var error: NetworkError?
    @State private var showAlert = false

    func body(content: Content) -> some View {
        content
            .alert("提示", isPresented: $showAlert) {
                Button("确定") {
                    error = nil
                }
            } message: {
                Text(error?.errorDescription ?? "未知错误")
            }
            .onChange(of: error) { _, newValue in
                showAlert = newValue != nil
            }
    }
}

extension View {
    func networkErrorAlert(_ error: Binding<NetworkError?>) -> some View {
        modifier(ErrorAlertModifier(error: error))
    }
}
```

使用方式：

```swift
struct MyView: View {
    @State private var error: NetworkError?

    var body: some View {
        Text("内容")
            .networkErrorAlert($error)
            .task {
                do {
                    let data: APIResponse<[Record]> = try await NetworkManager.shared.get(url: "/records")
                } catch let err as NetworkError {
                    error = err
                } catch {
                    error = .serverError(err.localizedDescription)
                }
            }
    }
}
```

> 💡 **提示**：错误处理要在开发早期就做好。不要到处写 `try?` 吞掉错误，否则出了问题完全不知道哪里出错了。至少要 `print(error)` 打印出来。

## 小结

本章我们完成了核心功能开发的上半部分：

| 主题 | 核心要点 | 一句话总结 |
|------|---------|-----------|
| 按 Spec 开发 | 按优先级和依赖关系逐步推进，完成一个测一个 | 别一口气写完再测，边写边测 |
| 主界面与导航 | TabView + NavigationStack + ScrollView | 每个 Tab 包裹 NavigationStack，层级不超过 3 层 |
| 数据模型设计 | @Model 定义模型，SampleData 生成预览数据 | 模型是骨架，先有骨架再填内容 |
| 网络层封装 | 泛型请求 + 统一响应 + 自定义错误 | 一次封装，到处复用 |

**记住这三个核心原则：**

1. **按 Spec 推进**：不要想到哪写到哪，按任务清单逐个完成
2. **模型先行**：先定义好数据模型，再写 UI 和逻辑
3. **错误不吞**：每个网络请求都要处理错误，不要用 `try?` 忽略
