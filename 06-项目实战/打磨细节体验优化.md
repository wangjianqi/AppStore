## 加载状态与骨架屏

> 🎯 **本节目标**：学会用 ProgressView 和自定义骨架屏提升加载体验，让用户在等待时不再面对空白页面。

### 加载指示器

#### ProgressView

`ProgressView` 是 SwiftUI 内置的加载指示器，有两种样式：

| 样式 | 效果 | 使用场景 |
|------|------|---------|
| `CircularProgressViewStyle`（默认） | 旋转圆圈 | 不确定时长的加载 |
| `LinearProgressViewStyle` | 水平进度条 | 可知进度的加载（如下载） |

```swift
struct LoadingExampleView: View {
    @State private var progress = 0.0
    let timer = Timer.publish(every: 0.1, on: .main, in: .common).autoconnect()

    var body: some View {
        VStack(spacing: 40) {
            ProgressView()
                .scaleEffect(1.5)

            ProgressView("加载中...")

            ProgressView(value: progress, total: 1.0)
                .progressViewStyle(.linear)
                .onReceive(timer) { _ in
                    if progress < 1.0 {
                        progress += 0.05
                    }
                }
        }
        .padding()
    }
}
```

#### .task 修饰符

`.task` 是 SwiftUI 提供的异步任务修饰符，视图出现时自动执行，视图消失时自动取消：

```swift
struct DataView: View {
    @State private var items: [String] = []
    @State private var isLoading = false

    var body: some View {
        Group {
            if isLoading {
                ProgressView("加载中...")
            } else {
                List(items, id: \.self) { item in
                    Text(item)
                }
            }
        }
        .task {
            await loadData()
        }
    }

    private func loadData() async {
        isLoading = true
        do {
            try await Task.sleep(for: .seconds(2))
            items = ["项目 A", "项目 B", "项目 C"]
        } catch {
            items = []
        }
        isLoading = false
    }
}
```

> 💡 **提示**：`.task` 和 `.onAppear` 的区别——`.task` 支持 async/await，会自动取消；`.onAppear` 是同步的，需要手动管理 Task。优先使用 `.task`。

### 骨架屏实现

#### 什么是骨架屏

骨架屏（Skeleton Screen）是在数据加载完成前，用灰色占位块模拟页面布局的加载方式。

| 加载方式 | 用户体验 | 实现难度 |
|---------|---------|---------|
| 空白页面 | ❌ 用户不知道在等什么 | 最简单 |
| 转圈圈（ProgressView） | ⚠️ 知道在加载，但不知道内容长什么样 | 简单 |
| 骨架屏 | ✅ 知道在加载，还能预览布局 | 中等 |

#### 自定义 Skeleton View

```swift
import SwiftUI

struct SkeletonView: View {
    let width: CGFloat
    let height: CGFloat
    let cornerRadius: CGFloat

    @State private var isAnimating = false

    init(width: CGFloat = .infinity, height: CGFloat = 20, cornerRadius: CGFloat = 4) {
        self.width = width
        self.height = height
        self.cornerRadius = cornerRadius
    }

    var body: some View {
        RoundedRectangle(cornerRadius: cornerRadius)
            .fill(
                LinearGradient(
                    colors: [
                        Color(.systemGray5),
                        Color(.systemGray6),
                        Color(.systemGray5)
                    ],
                    startPoint: .leading,
                    endPoint: .trailing
                )
            )
            .frame(maxWidth: width == .infinity ? .infinity : nil, minHeight: height)
            .frame(width: width == .infinity ? nil : width)
            .opacity(isAnimating ? 0.4 : 1.0)
            .animation(
                .easeInOut(duration: 1.0).repeatForever(autoreverses: true),
                value: isAnimating
            )
            .onAppear {
                isAnimating = true
            }
    }
}
```

#### 完整代码

下面是一个完整的骨架屏列表示例：

```swift
import SwiftUI

struct SkeletonListView: View {
    @State private var isLoading = true
    @State private var records: [Record] = []

    var body: some View {
        NavigationStack {
            Group {
                if isLoading {
                    skeletonContent
                } else {
                    recordContent
                }
            }
            .navigationTitle("记录")
            .task {
                try? await Task.sleep(for: .seconds(2))
                records = SampleData.recentRecords
                isLoading = false
            }
        }
    }

    private var skeletonContent: some View {
        List(0..<6, id: \.self) { _ in
            HStack(spacing: 12) {
                SkeletonView(width: 40, height: 40, cornerRadius: 20)

                VStack(alignment: .leading, spacing: 8) {
                    SkeletonView(height: 16)
                    SkeletonView(width: 120, height: 12)
                }

                Spacer()

                SkeletonView(width: 60, height: 16)
            }
            .padding(.vertical, 4)
        }
    }

    private var recordContent: some View {
        List(records) { record in
            RecordRowView(record: record)
        }
    }
}

#Preview {
    SkeletonListView()
}
```

> 💡 **提示**：骨架屏的布局要和真实内容的布局尽量一致，这样加载完成后不会有"跳动"感。建议先写好真实内容的布局，再对照着写骨架屏。

### 渐进式加载

不是所有内容都需要等全部加载完才显示。渐进式加载让用户先看到关键内容，非关键内容延迟加载。

#### 优先加载关键内容

```swift
struct ProgressiveLoadView: View {
    @State private var summary: String?
    @State private var records: [Record] = []
    @State private var chartData: [Double] = []

    var body: some View {
        NavigationStack {
            ScrollView {
                VStack(spacing: 20) {
                    if let summary {
                        SummaryCardView(text: summary)
                    } else {
                        SkeletonView(height: 100, cornerRadius: 16)
                    }

                    if records.isEmpty {
                        ForEach(0..<3, id: \.self) { _ in
                            SkeletonView(height: 60)
                        }
                    } else {
                        ForEach(records.prefix(5)) { record in
                            RecordRowView(record: record)
                        }
                    }

                    if chartData.isEmpty {
                        SkeletonView(height: 200, cornerRadius: 16)
                    } else {
                        ChartPlaceholderView(data: chartData)
                    }
                }
                .padding()
            }
            .navigationTitle("首页")
            .task {
                await loadSummary()
                await loadRecords()
                await loadChartData()
            }
        }
    }

    private func loadSummary() async {
        try? await Task.sleep(for: .milliseconds(500))
        summary = "本月支出 ¥1,234.56，收入 ¥5,000.00"
    }

    private func loadRecords() async {
        try? await Task.sleep(for: .seconds(1))
        records = SampleData.recentRecords
    }

    private func loadChartData() async {
        try? await Task.sleep(for: .seconds(2))
        chartData = [120, 80, 200, 150, 90, 180, 110]
    }
}

struct SummaryCardView: View {
    let text: String

    var body: some View {
        Text(text)
            .font(.headline)
            .frame(maxWidth: .infinity)
            .padding()
            .background(.ultraThinMaterial)
            .clipShape(RoundedRectangle(cornerRadius: 16))
    }
}

struct ChartPlaceholderView: View {
    let data: [Double]

    var body: some View {
        Text("图表区域（\(data.count) 个数据点）")
            .frame(maxWidth: .infinity)
            .frame(height: 200)
            .background(.gray.opacity(0.1))
            .clipShape(RoundedRectangle(cornerRadius: 16))
    }
}
```

> 💡 **提示**：渐进式加载的优先级：概览数据 > 列表数据 > 图表数据。用户最关心的是"花了多少钱"，其次是"花在哪了"，最后才是趋势图。

## 下拉刷新与上拉加载

> 🎯 **本节目标**：实现下拉刷新和上拉加载更多，让用户能主动获取最新数据和浏览更多内容。

### 下拉刷新

#### .refreshable

SwiftUI 提供了 `.refreshable` 修饰符，用户下拉时自动触发异步操作：

```swift
import SwiftUI

struct RefreshableListView: View {
    @State private var records = SampleData.recentRecords

    var body: some View {
        NavigationStack {
            List(records) { record in
                RecordRowView(record: record)
            }
            .refreshable {
                await refreshData()
            }
            .navigationTitle("记录")
        }
    }

    private func refreshData() async {
        try? await Task.sleep(for: .seconds(1))
        records = SampleData.recentRecords.shuffled()
    }
}
```

> 💡 **提示**：`.refreshable` 只能用在 `List` 和 `ScrollView` 上。如果你用的是 `ScrollView + LazyVStack`，也可以直接加 `.refreshable`。

### 上拉加载更多

#### 检测滚动到底部

SwiftUI 没有内置的"滚动到底部"检测，需要自己实现。最简单的方式是在列表末尾放一个"加载更多"的触发器：

```swift
import SwiftUI

struct LoadMoreListView: View {
    @State private var records: [Record] = SampleData.recentRecords
    @State private var isLoadingMore = false
    @State private var currentPage = 1
    @State private var hasMore = true

    var body: some View {
        NavigationStack {
            List {
                ForEach(records) { record in
                    RecordRowView(record: record)
                }

                if hasMore {
                    HStack {
                        Spacer()
                        if isLoadingMore {
                            ProgressView()
                        } else {
                            Text("加载更多")
                                .foregroundStyle(.secondary)
                        }
                        Spacer()
                    }
                    .onAppear {
                        loadMore()
                    }
                }
            }
            .navigationTitle("记录")
        }
    }

    private func loadMore() {
        guard !isLoadingMore, hasMore else { return }
        isLoadingMore = true
        currentPage += 1

        Task {
            try? await Task.sleep(for: .seconds(1))

            let newRecords = generateMoreRecords(page: currentPage)
            records.append(contentsOf: newRecords)
            hasMore = currentPage < 5
            isLoadingMore = false
        }
    }

    private func generateMoreRecords(page: Int) -> [Record] {
        (0..<8).map { i in
            Record(
                amount: Double.random(in: 5...200),
                type: Bool.random() ? .expense : .income,
                category: ["餐饮", "交通", "购物", "娱乐"].randomElement()!,
                note: "第\(page)页-记录\(i + 1)",
                date: .now.addingTimeInterval(-Double(page * 86400 + i * 3600))
            )
        }
    }
}
```

### 分页逻辑

#### Page/Offset 分页

| 分页方式 | 原理 | 优点 | 缺点 |
|---------|------|------|------|
| Page 分页 | `page=1&pageSize=20` | 简单，服务端支持好 | 插入/删除数据时可能重复或遗漏 |
| Offset 分页 | `offset=0&limit=20` | 灵活 | 数据量大时性能差 |
| Cursor 分页 | `after=last_id` | 不会重复遗漏 | 实现稍复杂 |

> 💡 **提示**：新手项目推荐 Page 分页，实现最简单。等数据量大了再考虑 Cursor 分页。

#### 状态管理

分页加载需要管理多个状态：

```swift
@Observable
class PaginationViewModel {
    var items: [Record] = []
    var currentPage = 1
    var isLoading = false
    var isLoadingMore = false
    var hasMore = true
    var error: NetworkError?

    let pageSize = 20

    func loadFirstPage() async {
        guard !isLoading else { return }
        isLoading = true
        error = nil
        currentPage = 1

        do {
            let response: APIResponse<PaginatedData<Record>> = try await NetworkManager.shared.get(
                url: "/records",
                parameters: ["page": 1, "pageSize": pageSize]
            )
            items = response.data.items
            hasMore = response.data.hasMore
        } catch let err as NetworkError {
            error = err
        } catch {
            error = .serverError(error!.localizedDescription)
        }

        isLoading = false
    }

    func loadNextPage() async {
        guard !isLoadingMore, hasMore else { return }
        isLoadingMore = true
        currentPage += 1

        do {
            let response: APIResponse<PaginatedData<Record>> = try await NetworkManager.shared.get(
                url: "/records",
                parameters: ["page": currentPage, "pageSize": pageSize]
            )
            items.append(contentsOf: response.data.items)
            hasMore = response.data.hasMore
        } catch {
            currentPage -= 1
        }

        isLoadingMore = false
    }
}

struct PaginatedData<T: Decodable>: Decodable {
    let items: [T]
    let total: Int
    let hasMore: Bool
}
```

## 无障碍适配（Accessibility）

> 🎯 **本节目标**：学会为 App 添加 VoiceOver 支持、动态字体和颜色对比度适配，让所有用户都能顺畅使用你的 App。

### VoiceOver 支持

VoiceOver 是 iOS 的屏幕阅读功能，为视障用户朗读屏幕上的内容。SwiftUI 的很多控件默认就有 VoiceOver 支持，但自定义内容需要手动添加标签。

#### .accessibilityLabel() / .accessibilityHint() / .accessibilityValue()

| 修饰符 | 作用 | 示例 |
|--------|------|------|
| `.accessibilityLabel()` | 描述元素是什么 | "记账按钮" |
| `.accessibilityHint()` | 描述操作后的结果 | "点击添加一条新记录" |
| `.accessibilityValue()` | 当前值 | "35.00 元" |

```swift
struct AccessibleRecordRowView: View {
    let record: Record

    var body: some View {
        HStack {
            Image(systemName: record.type == .expense ? "arrow.down.circle.fill" : "arrow.up.circle.fill")
                .foregroundStyle(record.type == .expense ? .red : .green)

            VStack(alignment: .leading, spacing: 2) {
                Text(record.category)
                if !record.note.isEmpty {
                    Text(record.note)
                        .font(.caption)
                        .foregroundStyle(.secondary)
                }
            }

            Spacer()

            Text(record.displayAmount)
                .fontWeight(.medium)
                .foregroundStyle(record.type == .expense ? .red : .green)
        }
        .accessibilityElement(children: .combine)
        .accessibilityLabel("\(record.type.rawValue)，\(record.category)")
        .accessibilityValue(record.displayAmount)
        .accessibilityHint("双击查看详情")
    }
}
```

> 💡 **提示**：`.accessibilityElement(children: .combine)` 把 HStack 中的多个子元素合并成一个 VoiceOver 元素，避免逐个朗读。

### 动态字体

#### .font(.title) 自动缩放

SwiftUI 的系统字体默认支持动态缩放——用户在"设置 → 辅助功能 → 更大字体"中调整字体大小后，App 会自动适配。

| 字体方式 | 是否支持动态缩放 | 推荐度 |
|---------|----------------|--------|
| `.font(.title)` | ✅ 自动缩放 | ⭐⭐⭐⭐⭐ |
| `.font(.system(size: 17))` | ✅ 自动缩放 | ⭐⭐⭐⭐ |
| `.font(.system(size: 17, weight: .bold))` | ✅ 自动缩放 | ⭐⭐⭐⭐ |
| `.font(.custom("字体名", size: 17))` | ❌ 不缩放 | ⭐ |

#### 支持用户字体大小设置

如果布局在字体放大后可能溢出，需要做适配：

```swift
struct AdaptiveFontView: View {
    @Environment(\.dynamicTypeSize) var dynamicTypeSize

    var body: some View {
        VStack(spacing: 12) {
            Text("本月支出")
                .font(.caption)
                .foregroundStyle(.secondary)

            Text("¥1,234.56")
                .font(.system(.title, design: .rounded, weight: .bold))
                .lineLimit(1)
                .minimumScaleFactor(0.5)

            if dynamicTypeSize <= .xxLarge {
                HStack(spacing: 20) {
                    Label("支出 ¥1,234", systemImage: "arrow.down")
                    Label("收入 ¥5,000", systemImage: "arrow.up")
                }
                .font(.subheadline)
            }
        }
        .padding()
    }
}
```

> ⚠️ **警告**：`.minimumScaleFactor(0.5)` 允许字体在空间不足时自动缩小到 50%，避免文字被截断。但不要过度依赖它，优先调整布局。

### 颜色对比度

#### WCAG 标准

WCAG（Web Content Accessibility Guidelines）定义了颜色对比度的最低标准：

| 等级 | 正文对比度 | 大字对比度 | 说明 |
|------|-----------|-----------|------|
| AA | ≥ 4.5:1 | ≥ 3:1 | 基本要求 |
| AAA | ≥ 7:1 | ≥ 4.5:1 | 最高标准 |

#### 检查方法

1. **Xcode Accessibility Inspector**：Xcode → Open Developer Tool → Accessibility Inspector，可以检查对比度
2. **在线工具**：[WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/)

```swift
extension Color {
    var isAccessible: Bool {
        let uiColor = UIColor(self)
        var red: CGFloat = 0
        var green: CGFloat = 0
        var blue: CGFloat = 0
        var alpha: CGFloat = 0
        uiColor.getRed(&red, green: &green, blue: &blue, alpha: &alpha)
        let luminance = 0.2126 * red + 0.7152 * green + 0.0722 * blue
        let whiteLuminance: CGFloat = 1.0
        let contrast = (whiteLuminance + 0.05) / (luminance + 0.05)
        return contrast >= 4.5
    }
}
```

> 💡 **提示**：使用系统语义颜色（如 `.primary`、`.secondary`）可以自动适配暗黑模式，同时满足对比度要求。避免使用自定义低对比度颜色。

### 辅助功能标签

#### 常用修饰符速查表

| 修饰符 | 作用 | 示例 |
|--------|------|------|
| `.accessibilityLabel()` | 设置朗读文本 | `.accessibilityLabel("关闭")` |
| `.accessibilityHint()` | 设置操作提示 | `.accessibilityHint("双击关闭弹窗")` |
| `.accessibilityValue()` | 设置当前值 | `.accessibilityValue("50%")` |
| `.accessibilityElement()` | 标记为无障碍元素 | `.accessibilityElement()` |
| `.accessibilityElement(children:)` | 合并/忽略子元素 | `.accessibilityElement(children: .combine)` |
| `.accessibilityAddTraits()` | 添加特性 | `.accessibilityAddTraits(.isButton)` |
| `.accessibilityRemoveTraits()` | 移除特性 | `.accessibilityRemoveTraits(.isButton)` |
| `.accessibilityHidden()` | 隐藏元素 | `.accessibilityHidden(true)` |
| `.accessibilitySortPriority()` | 朗读顺序 | `.accessibilitySortPriority(1)` |

> ⚠️ **警告**：装饰性图片（如背景花纹）一定要加 `.accessibilityHidden(true)`，否则 VoiceOver 会朗读"图片"，干扰用户。

## 本地化（多语言）基础

> 🎯 **本节目标**：学会字符串本地化、图片本地化和日期数字格式化，为 App 支持多语言打下基础。

### 字符串本地化

#### Localizable.strings

本地化的核心是 `Localizable.strings` 文件，每种语言一个：

```
项目目录/
├── zh-Hans.lproj/          # 简体中文
│   └── Localizable.strings
├── en.lproj/               # 英文
│   └── Localizable.strings
└── ja.lproj/               # 日文
    └── Localizable.strings
```

**zh-Hans.lproj/Localizable.strings：**

```
"app.name" = "小账本";
"tab.home" = "首页";
"tab.statistics" = "统计";
"tab.settings" = "设置";
"record.add" = "记一笔";
"record.empty" = "还没有记录";
"record.search" = "搜索分类或备注";
```

**en.lproj/Localizable.strings：**

```
"app.name" = "Little Ledger";
"tab.home" = "Home";
"tab.statistics" = "Statistics";
"tab.settings" = "Settings";
"record.add" = "Add Record";
"record.empty" = "No records yet";
"record.search" = "Search category or note";
```

#### String(localized:)

iOS 15+ 推荐使用 `String(localized:)` 来获取本地化字符串：

```swift
Text(String(localized: "tab.home", defaultValue: "首页"))
```

更简洁的方式——直接在 Text 中使用字符串目录（String Catalog）：

```swift
Text("tab.home")

Text("record.empty")

Button("record.add") {
    showAddSheet = true
}
```

> 💡 **提示**：Xcode 15 新增了 String Catalog（`.xcstrings` 文件），可以统一管理所有语言的翻译，比 `Localizable.strings` 更方便。新建项目时推荐使用 String Catalog。

### 图片本地化

#### Asset Catalog 本地化

如果不同语言需要不同的图片（如英文版 Logo 和中文版 Logo），可以在 Asset Catalog 中本地化：

1. 打开 `Assets.xcassets`
2. 选中图片资源
3. 在右侧 Inspector 中勾选需要支持的语言
4. 为每种语言拖入对应的图片

| 场景 | 是否需要本地化图片 | 示例 |
|------|-------------------|------|
| App 图标 | ❌ 不需要 | 所有语言用同一个图标 |
| 功能图标 | ❌ 不需要 | SF Symbols 自动适配 |
| 含文字的图片 | ✅ 需要 | "记账"按钮图片 vs "Add Record"按钮图片 |
| 文化相关图片 | ✅ 需要 | 不同地区的插画风格 |

### 日期与数字格式

#### Date.FormatStyle

不同地区的日期格式不同，使用 `FormatStyle` 可以自动适配：

```swift
import SwiftUI

struct DateFormatView: View {
    let now = Date()

    var body: some View {
        List {
            Section("日期格式") {
                Text(now.formatted(date: .complete, time: .omitted))
                Text(now.formatted(date: .abbreviated, time: .shortened))
                Text(now.formatted(.dateTime.year().month().day()))
            }

            Section("相对时间") {
                Text(now.formatted(.relative(presentation: .named)))
                Text(now.addingTimeInterval(-3600).formatted(.relative(presentation: .named)))
                Text(now.addingTimeInterval(-86400).formatted(.relative(presentation: .named)))
            }
        }
    }
}
```

| 格式 | 中文显示 | 英文显示 |
|------|---------|---------|
| `.complete` | 2024年1月15日 星期一 | Monday, January 15, 2024 |
| `.abbreviated` | 2024年1月15日 下午3:30 | Jan 15, 2024, 3:30 PM |
| `.relative` | 今天 | today |

#### NumberFormatStyle

数字格式也因地区而异：

```swift
import SwiftUI

struct NumberFormatView: View {
    var body: some View {
        List {
            Section("货币格式") {
                Text(1234.56, format: .currency(code: "CNY"))
                Text(1234.56, format: .currency(code: "USD"))
                Text(1234.56, format: .currency(code: "JPY"))
            }

            Section("数字格式") {
                Text(0.85, format: .percent)
                Text(1234567, format: .number)
            }
        }
    }
}
```

| 格式 | 中文显示 | 英文显示 |
|------|---------|---------|
| `.currency(code: "CNY")` | ¥1,234.56 | ¥1,234.56 |
| `.currency(code: "USD")` | US$1,234.56 | $1,234.56 |
| `.percent` | 85% | 85% |
| `.number` | 1,234,567 | 1,234,567 |

> ⚠️ **警告**：永远不要手动拼接日期和数字格式字符串（如 `"\(year)年\(month)月\(day)日"`）。用 `FormatStyle` 可以自动适配用户所在地区的格式，还能正确处理农历、希伯来历等特殊日历。

## 性能优化基础

> 🎯 **本节目标**：学会使用 Lazy 加载、图片优化和避免不必要重绘，让 App 运行流畅。

### Lazy 加载

#### LazyVStack/LazyHStack

SwiftUI 的 `Lazy` 容器只渲染可见区域的视图，大幅提升性能：

| 容器 | 渲染方式 | 适用场景 |
|------|---------|---------|
| `VStack` | 一次性渲染所有子视图 | 子视图少于 10 个 |
| `LazyVStack` | 只渲染可见的子视图 | 子视图可能很多 |
| `List` | 自动懒加载 | 列表场景（推荐） |

```swift
struct LazyExampleView: View {
    let items = Array(1...1000)

    var body: some View {
        ScrollView {
            LazyVStack(spacing: 12) {
                ForEach(items, id: \.self) { index in
                    HStack {
                        Image(systemName: "star.fill")
                            .foregroundStyle(.yellow)
                        Text("第 \(index) 项")
                        Spacer()
                        Text("详情")
                            .foregroundStyle(.secondary)
                    }
                    .padding()
                    .background(.background.secondary)
                    .clipShape(RoundedRectangle(cornerRadius: 8))
                }
            }
            .padding()
        }
    }
}
```

#### List 自动懒加载

`List` 天然就是懒加载的，不需要额外处理：

```swift
struct ListExampleView: View {
    let items = Array(1...1000)

    var body: some View {
        List(items, id: \.self) { index in
            HStack {
                Image(systemName: "star.fill")
                Text("第 \(index) 项")
            }
        }
    }
}
```

> 💡 **提示**：如果列表项超过 20 个，一定要用 `LazyVStack` 或 `List`。用 `VStack` 渲染 1000 个子视图会导致启动时间超过 1 秒。

### 图片优化

#### AsyncImage 缓存

`AsyncImage` 可以从 URL 加载图片，但默认没有缓存。每次视图重绘都会重新下载：

```swift
struct CachedAsyncImage: View {
    let url: URL?
    @State private var loadedImage: Image?

    var body: some View {
        Group {
            if let loadedImage {
                loadedImage
                    .resizable()
                    .aspectRatio(contentMode: .fill)
            } else {
                Rectangle()
                    .fill(.gray.opacity(0.2))
                    .overlay {
                        ProgressView()
                    }
            }
        }
        .task {
            await loadImage()
        }
    }

    private func loadImage() async {
        guard let url else { return }

        if let cached = ImageCacheManager.shared.get(forKey: url.absoluteString) {
            loadedImage = cached
            return
        }

        do {
            let (data, _) = try await URLSession.shared.data(from: url)
            if let uiImage = UIImage(data: data) {
                let image = Image(uiImage: uiImage)
                ImageCacheManager.shared.set(image, forKey: url.absoluteString)
                loadedImage = image
            }
        } catch {
            // 加载失败，保持占位图
        }
    }
}

final class ImageCacheManager {
    static let shared = ImageCacheManager()
    private let cache = NSCache<NSString, ImageWrapper>()

    func get(forKey key: String) -> Image? {
        cache.object(forKey: key as NSString)?.image
    }

    func set(_ image: Image, forKey key: String) {
        cache.setObject(ImageWrapper(image), forKey: key as NSString)
    }

    private final class ImageWrapper {
        let image: Image
        init(_ image: Image) { self.image = image }
    }
}
```

#### 图片压缩

如果 App 需要显示用户拍摄的照片，原图可能很大（几 MB），需要压缩：

```swift
extension UIImage {
    func compressed(quality: CGFloat = 0.5) -> Data? {
        jpegData(compressionQuality: quality)
    }

    func resized(to size: CGSize) -> UIImage {
        let renderer = UIGraphicsImageRenderer(size: size)
        return renderer.image { _ in
            self.draw(in: CGRect(origin: .zero, size: size))
        }
    }
}
```

| 压缩质量 | 文件大小（约） | 视觉效果 | 推荐场景 |
|---------|--------------|---------|---------|
| 1.0（原始） | 3-5 MB | 无损 | 不推荐 |
| 0.8 | 1-2 MB | 几乎无损 | 需要高清的场景 |
| 0.5 | 300-800 KB | 轻微损失 | 通用推荐 |
| 0.3 | 100-300 KB | 明显损失 | 缩略图 |

> 💡 **提示**：列表中的缩略图用 0.3 质量就够了，点击查看大图时再加载原图。这样列表滑动更流畅。

### 避免不必要的重绘

#### 识别重绘问题

SwiftUI 的 View 是 struct，每次状态变化时，依赖该状态的 View 及其子 View 都会重新计算 `body`。如果 `body` 计算量大（如复杂布局、大量数据），就会导致卡顿。

**如何判断是否有重绘问题：**

1. 在 `body` 中加 `let _ = print("XXXView 重绘了")`，观察控制台输出
2. 使用 Xcode Instruments 的 SwiftUI 工具分析

#### 提取子视图

把不依赖变化状态的部分提取为独立的子视图，SwiftUI 会自动跳过不需要重绘的子视图：

```swift
struct HomeView: View {
    @State private var records: [Record] = []
    @State private var showAddSheet = false

    var body: some View {
        VStack {
            OverviewCardView(totalExpense: totalExpense, totalIncome: totalIncome)
            RecordListView(records: records)
        }
        .sheet(isPresented: $showAddSheet) {
            Text("记账页面")
        }
    }

    var totalExpense: Double {
        records.filter { $0.type == .expense }.reduce(0) { $0 + $1.amount }
    }

    var totalIncome: Double {
        records.filter { $0.type == .income }.reduce(0) { $0 + $1.amount }
    }
}

struct OverviewCardView: View {
    let totalExpense: Double
    let totalIncome: Double

    var body: some View {
        VStack(spacing: 12) {
            Text("本月概览")
                .font(.headline)
            HStack(spacing: 40) {
                VStack(spacing: 4) {
                    Text("支出")
                        .font(.caption)
                    Text("-\(String(format: "%.2f", totalExpense))")
                        .font(.title2)
                        .fontWeight(.bold)
                        .foregroundStyle(.red)
                }
                VStack(spacing: 4) {
                    Text("收入")
                        .font(.caption)
                    Text("+\(String(format: "%.2f", totalIncome))")
                        .font(.title2)
                        .fontWeight(.bold)
                        .foregroundStyle(.green)
                }
            }
        }
        .frame(maxWidth: .infinity)
        .padding()
        .background(.ultraThinMaterial)
        .clipShape(RoundedRectangle(cornerRadius: 16))
    }
}
```

#### @Observable 精确追踪

`@Observable`（iOS 17+）比 `@ObservableObject` + `@Published` 更精确——只有实际使用的属性变化时才会触发重绘：

```swift
import Observation

@Observable
class RecordViewModel {
    var records: [Record] = []
    var searchText: String = ""
    var isLoading: Bool = false

    var filteredRecords: [Record] {
        if searchText.isEmpty { return records }
        return records.filter { $0.category.localizedCaseInsensitiveContains(searchText) }
    }
}

struct RecordListView: View {
    @State private var viewModel = RecordViewModel()

    var body: some View {
        List(viewModel.filteredRecords) { record in
            RecordRowView(record: record)
        }
        .searchable(text: $viewModel.searchText)
    }
}
```

| 方案 | 追踪粒度 | 最低版本 | 推荐度 |
|------|---------|---------|--------|
| `@ObservableObject` + `@Published` | 整个对象（任何属性变化都重绘） | iOS 14 | ⭐⭐ |
| `@Observable` | 精确到属性（只重绘用到变化属性的视图） | iOS 17 | ⭐⭐⭐⭐⭐ |

> ⚠️ **警告**：`@Observable` 是 iOS 17+ 才有的。如果你的最低版本是 iOS 16，只能用 `@ObservableObject`。但可以通过提取子视图来减少不必要的重绘。

## 小结

本章我们学习了体验优化的核心技巧：

| 主题 | 核心要点 | 一句话总结 |
|------|---------|-----------|
| 加载状态与骨架屏 | ProgressView + 自定义 SkeletonView | 别让用户看空白，加载时给预期 |
| 下拉刷新与上拉加载 | .refreshable + 底部触发器 + 分页状态管理 | 下拉刷新数据，上拉加载更多 |
| 无障碍适配 | VoiceOver + 动态字体 + 颜色对比度 | 让所有用户都能用你的 App |
| 本地化基础 | Localizable.strings + FormatStyle | 用系统 API，不要手动拼格式 |
| 性能优化 | Lazy 容器 + 图片缓存 + 避免重绘 | 懒加载省资源，提取子视图减重绘 |

**记住这三个核心原则：**

1. **感知性能 > 实际性能**：骨架屏不会让数据加载更快，但用户"感觉"更快
2. **无障碍不是可选项**：App Store 审核会检查无障碍支持，而且这是正确的事
3. **性能优化要有的放矢**：先用 Instruments 找到瓶颈，再针对性优化，不要盲目优化
