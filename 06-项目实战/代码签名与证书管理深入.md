# 代码签名与证书管理深入

> 🎯 **本章目标**：深入理解 Apple 代码签名体系，掌握证书和描述文件的创建与管理，学会排查签名相关的常见错误。

---

## 1. 代码签名的作用和原理

### 1.1 为什么需要代码签名

Apple 的代码签名体系是 iOS 生态安全的基石。每一行运行在 iOS 设备上的代码，都必须经过 Apple 认可的签名，否则系统拒绝执行。

> 💡 生活类比：代码签名就像"公章"——
> - 没有公章的文件不被认可
> - 公章由权威机构（Apple）颁发
> - 每次使用公章都留下可追溯的记录
> - 公章过期后必须续期才能继续使用

代码签名解决的核心问题：

| 问题 | 代码签名的解决方案 |
|------|---------------------|
| 恶意软件 | 只有经过签名的 App 才能安装和运行 |
| 篡改风险 | 签名验证确保代码未被修改 |
| 来源追溯 | 通过证书可追溯到具体开发者 |
| 权限控制 | 描述文件限定 App 可运行的范围 |
| 版权保护 | App Store 分发的 App 带有 Apple 的额外签名 |

### 1.2 代码签名的技术原理

代码签名基于**非对称加密**和**数字证书**技术：

```
签名过程：
源代码 → 编译 → Mach-O 二进制 → 计算哈希 → 私钥加密哈希 → 签名数据嵌入二进制

验证过程：
Mach-O 二进制 → 提取签名数据 → 公钥解密哈希 → 重新计算哈希 → 比较两个哈希值
```

**核心概念：**

| 概念 | 说明 |
|------|------|
| 证书（Certificate） | 包含公钥和开发者身份信息的数字文件，由 Apple CA 签发 |
| 私钥（Private Key） | 与证书配对的密钥，用于生成签名，必须妥善保管 |
| 签名（Signature） | 用私钥对代码哈希加密后的数据 |
| 描述文件（Provisioning Profile） | 将证书、设备、App ID 绑定在一起的授权文件 |
| Entitlements | App 声明需要的特殊权限（推送、iCloud 等） |

### 1.3 签名验证流程

iOS 设备安装 App 时的验证流程：

```
1. 检查描述文件是否有效（未过期、未被撤销）
2. 检查描述文件中的证书是否有效
3. 检查设备 UDID 是否在描述文件的设备列表中（开发/Ad Hoc）
4. 检查 App 的 Bundle ID 是否与描述文件匹配
5. 验证代码签名是否与证书中的公钥匹配
6. 验证代码完整性（哈希校验）
7. App Store 分发的 App 还需通过 Apple 的额外验证
```

⚠️ **警告**：任何一步验证失败，App 都无法安装或启动。理解这个流程是排查签名问题的基础。

### 1.4 代码签名的层级

```
Apple Root CA
    └── Apple Worldwide Developer Relations Certification Authority
            ├── Developer ID Certification Authority（分发证书）
            │       └── Developer ID Application: Your Name (Team ID)
            └── Apple Worldwide Developer Relations Certification Authority（开发证书）
                    └── Apple Development: Your Name (Team ID)
```

| 层级 | 作用 |
|------|------|
| Apple Root CA | Apple 根证书，预装在所有 Apple 设备中 |
| 中间 CA | 连接根证书和开发者证书的桥梁 |
| 开发者证书 | 具体开发者的身份证书 |

## 2. 证书类型详解

### 2.1 开发证书（Development Certificate）

开发证书用于在真机上调试和测试 App。

**类型：**

| 证书类型 | 用途 | 说明 |
|----------|------|------|
| Apple Development | 真机调试 | Xcode 11+ 统一的开发证书名称 |
| iOS Development | 真机调试 | 旧版名称，功能与 Apple Development 相同 |
| Apple Development (Sign to Run Locally) | Mac 开发 | 仅限 macOS App 本地运行 |

**特点：**

- 每个开发者账号最多可创建 **5 个**开发证书
- 开发证书绑定的描述文件需要包含设备 UDID
- 仅用于开发阶段，不能用于 App Store 分发
- 证书有效期 **5 年**

**创建开发证书的步骤：**

1. 打开 Xcode → Preferences → Accounts
2. 添加 Apple ID
3. 选择 Team → 点击 "Manage Certificates"
4. 点击左下角 "+" → 选择 "Apple Development"

或者通过 Apple Developer Portal：

1. 登录 [developer.apple.com](https://developer.apple.com)
2. Certificates, Identifiers & Profiles → Certificates
3. 点击 "+" → 选择 "Apple Development"
4. 上传 CSR 文件（Certificate Signing Request）

### 2.2 分发证书（Distribution Certificate）

分发证书用于将 App 发布到 App Store 或企业内部分发。

**类型：**

| 证书类型 | 用途 | 说明 |
|----------|------|------|
| Apple Distribution | App Store 分发 | Xcode 11+ 统一的分发证书名称 |
| iOS Distribution | App Store 分发 | 旧版名称 |
| Developer ID Application | Mac App Store 外分发 | 用于 macOS App 在 App Store 外分发 |
| Developer ID Installer | Mac 安装包签名 | 用于 macOS 安装包签名 |

**特点：**

- 每个开发者账号最多可创建 **3 个**分发证书
- 分发证书不需要指定设备 UDID
- 用于正式发布，必须妥善保管
- 证书有效期 **5 年**

⚠️ **警告**：分发证书的私钥丢失后无法恢复，只能撤销旧证书重新创建。撤销分发证书会使所有使用该证书签名的 App 失效（App Store 上的已有版本不受影响，但无法提交新版本）。

### 2.3 推送证书（Push Certificate）

推送证书用于向 APNs（Apple Push Notification service）发送推送通知。

**类型：**

| 证书类型 | 用途 | 环境 |
|----------|------|------|
| Apple Push Notification service SSL (Sandbox) | 开发环境推送 | sandbox.push.apple.com |
| Apple Push Notification service SSL (Production) | 生产环境推送 | api.push.apple.com |

**特点：**

- 每个 App ID 只能创建一个推送证书（沙盒和生产各一个）
- 证书有效期 **1 年**，必须定期续期
- 推送证书与 App 的 Bundle ID 绑定
- 续期时需要创建新证书，旧证书在过期前仍然有效

**推送证书续期流程：**

```
1. 在 Developer Portal 创建新的推送证书
2. 下载并导出 .p12 文件
3. 将 .p12 文件上传到推送服务提供商
4. 确认新证书工作正常
5. 旧证书过期后自动失效
```

💡 **提示**：建议在推送证书到期前 30 天开始续期流程，留出足够的测试时间。

### 2.4 其他证书类型

| 证书类型 | 用途 |
|----------|------|
| Pass Type ID Certificate | Apple Wallet 通证签名 |
| VoIP Services Certificate | VoIP 推送通知 |
| Apple Pay Payment Processing Certificate | Apple Pay 支付处理 |
| Apple Pay Merchant Identity Certificate | Apple Pay 商户身份验证 |
| Apple MDM Push Certificate | 移动设备管理推送 |
| Wireless Accessory Configuration Certificate | 无线配件配置 |
| Deveoper ID Kernel Extension Certificate | macOS 内核扩展签名 |

### 2.5 证书数量限制

| 证书类型 | 最大数量 | 有效期 |
|----------|----------|--------|
| Apple Development | 5 | 5 年 |
| Apple Distribution | 3 | 5 年 |
| APNs (Sandbox) | 每 App ID 1 个 | 1 年 |
| APNs (Production) | 每 App ID 1 个 | 1 年 |
| Developer ID Application | 5 | 5 年 |

## 3. 描述文件详解

### 3.1 描述文件的作用

描述文件（Provisioning Profile）是将证书、设备、App ID 和权限绑定在一起的授权文件。它告诉 iOS 设备："这个 App 被授权在这台设备上运行"。

```
描述文件的组成：
┌─────────────────────────────────────────┐
│           Provisioning Profile           │
│                                         │
│  ┌───────────┐  ┌──────────┐           │
│  │  App ID   │  │  证书     │           │
│  │ Bundle ID │  │ 公钥信息  │           │
│  └───────────┘  └──────────┘           │
│                                         │
│  ┌───────────┐  ┌──────────┐           │
│  │  设备列表  │  │ 权限声明  │           │
│  │  UDIDs    │  │Entitlements│          │
│  └───────────┘  └──────────┘           │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │       Apple 的数字签名           │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 3.2 描述文件类型

| 类型 | 用途 | 设备限制 | 有效期 |
|------|------|----------|--------|
| iOS App Development | 开发调试 | 最多 100 台设备 | 1 年 |
| iOS App Ad Hoc | 内测分发 | 最多 100 台设备 | 1 年 |
| iOS App Store | App Store 分发 | 无限制 | 1 年 |
| iOS App In House | 企业内部分发 | 无限制（仅企业账号） | 1 年 |
| tvOS App Development | tvOS 开发 | 最多 100 台设备 | 1 年 |
| tvOS App Store | tvOS 分发 | 无限制 | 1 年 |

### 3.3 开发描述文件（Development）

开发描述文件用于 Xcode 真机调试。

**特点：**

- 必须包含目标设备的 UDID
- 绑定开发证书
- 可以包含多个开发者的证书
- Debug 模式下可以使用调试器

**创建步骤：**

1. Developer Portal → Profiles → 点击 "+"
2. 选择 "iOS App Development"
3. 选择 App ID
4. 选择开发证书
5. 选择测试设备
6. 命名并生成
7. 下载并双击安装到 Xcode

### 3.4 Ad Hoc 描述文件

Ad Hoc 描述文件用于将 App 分发给指定设备进行测试，无需通过 TestFlight。

**适用场景：**

- 内部测试人员无法使用 TestFlight 的情况
- 需要快速分发给少量测试用户
- 企业内部测试

**与 TestFlight 的对比：**

| 特性 | Ad Hoc | TestFlight |
|------|--------|------------|
| 设备数量 | 100 台/年 | 10,000 个外部测试员 |
| 设备注册 | 需要收集 UDID | 只需邮箱 |
| 安装方式 | IPA + manifest | TestFlight App |
| 审核要求 | 无 | 外部测试需要审核 |
| 构建版本有效期 | 描述文件有效期内 | 90 天 |
| 适合场景 | 快速内测 | 正式 Beta 测试 |

### 3.5 App Store 描述文件

App Store 描述文件用于提交 App 到 App Store。

**特点：**

- 不需要指定设备
- 绑定分发证书
- 仅用于 App Store 分发
- 提交审核时必须使用此类型

### 3.6 Enterprise 描述文件

Enterprise 描述文件仅限企业开发者账号（$299/年）使用。

**特点：**

- 不需要指定设备
- 可以分发给企业内部任意员工
- 不能用于公开分发
- 滥用会导致账号被封

⚠️ **警告**：Apple 严格监控企业证书的使用。如果发现企业证书被用于面向公众分发 App（即所谓的"超级签名"），Apple 会立即撤销该企业证书，导致所有使用该证书的 App 无法运行。

### 3.7 描述文件的生命周期

```
创建 → 使用 → 即将过期 → 续期 → 继续使用
  │                    │
  │                    └── 过期后 App 无法安装（已安装的可能仍可运行）
  │
  └── 证书过期或撤销 → 描述文件失效 → 必须重新创建
```

💡 **提示**：描述文件的有效期最长 1 年，但绑定的证书可能有效期更长。如果证书被撤销或过期，关联的描述文件也会失效。

## 4. 自动签名 vs 手动签名

### 4.1 自动签名（Automatic Signing）

Xcode 8 引入了自动签名功能，Xcode 自动管理证书和描述文件的创建和更新。

**工作原理：**

```
Xcode 检测到签名配置缺失
    → 自动连接 Apple Developer Portal
    → 检查是否有合适的证书
    → 如果没有，自动创建证书（需要 CSR）
    → 检查是否有合适的描述文件
    → 如果没有，自动创建描述文件
    → 下载并安装到本地 Keychain
```

**配置方式：**

1. 打开 Xcode 项目
2. 选择 Target → Signing & Capabilities
3. 勾选 "Automatically manage signing"
4. 选择 Team

**优点：**

| 优点 | 说明 |
|------|------|
| 零配置 | Xcode 自动处理所有签名相关操作 |
| 适合个人开发者 | 一人开发无需关心证书管理 |
| 减少错误 | 避免手动配置导致的签名问题 |
| 快速上手 | 新项目开箱即用 |

**缺点：**

| 缺点 | 说明 |
|------|------|
| 团队冲突 | 多人开发时可能互相覆盖描述文件 |
| CI/CD 不友好 | 自动签名依赖 Xcode GUI，不适合命令行环境 |
| 灵活性差 | 无法精确控制签名配置 |
| 可能创建多余证书 | 每台 Mac 可能创建不同的证书 |

### 4.2 手动签名（Manual Signing）

手动签名需要开发者自行管理证书和描述文件的创建、下载和配置。

**配置方式：**

1. 打开 Xcode 项目
2. 选择 Target → Signing & Capabilities
3. 取消勾选 "Automatically manage signing"
4. 在 "Provisioning Profile" 下拉菜单中选择描述文件
5. 在 "Signing Certificate" 下拉菜单中选择证书

**优点：**

| 优点 | 说明 |
|------|------|
| 完全控制 | 精确控制使用哪个证书和描述文件 |
| 团队协作 | 所有人使用同一套签名配置 |
| CI/CD 友好 | 可以在命令行中指定签名配置 |
| 可追溯 | 签名配置明确，便于排查问题 |

**缺点：**

| 缺点 | 说明 |
|------|------|
| 配置复杂 | 需要理解证书和描述文件的关系 |
| 维护成本 | 证书过期、设备变更都需要手动更新 |
| 容易出错 | 配置错误会导致签名失败 |

### 4.3 自动签名 vs 手动签名对比

| 特性 | 自动签名 | 手动签名 |
|------|----------|----------|
| 配置难度 | ⭐ 简单 | ⭐⭐⭐ 复杂 |
| 团队协作 | ⭐⭐ 一般 | ⭐⭐⭐ 优秀 |
| CI/CD 支持 | ⭐ 差 | ⭐⭐⭐ 优秀 |
| 灵活性 | ⭐ 低 | ⭐⭐⭐ 高 |
| 适合场景 | 个人开发 / 原型 | 团队 / CI/CD |
| 证书管理 | Xcode 自动 | 开发者手动 |

### 4.4 推荐策略

```
个人开发者 / 小项目：
    → 自动签名（省心省力）

中型团队 / 多人协作：
    → 手动签名 + match（统一管理）

大型团队 / CI/CD 环境：
    → 手动签名 + match + CI 集成
```

💡 **提示**：即使使用自动签名，也建议了解手动签名的原理。当自动签名出现问题时，你需要知道如何手动排查和修复。

## 5. Apple Developer Portal 证书管理

### 5.1 CSR 文件生成

CSR（Certificate Signing Request）是申请证书时必须提交的文件，包含你的公钥和身份信息。

**使用 Keychain Access 生成 CSR：**

1. 打开 "钥匙串访问"（Keychain Access）
2. 菜单 → 钥匙串访问 → 证书助理 → 从证书颁发机构请求证书
3. 填写邮箱和名称
4. 选择 "存储到磁盘"
5. 保存 .certSigningRequest 文件

**使用命令行生成 CSR：**

```bash
# 生成私钥
openssl genrsa -out mykey.key 2048

# 生成 CSR
openssl req -new -key mykey.key -out CertificateSigningRequest.certSigningRequest \
    -subj "/emailAddress=your@email.com/CN=Your Name/C=CN"
```

⚠️ **警告**：CSR 对应的私钥保存在 Keychain 中。如果私钥丢失，即使有证书文件也无法签名。务必在创建证书后导出 .p12 备份。

### 5.2 证书创建流程

```
1. 生成 CSR 文件（Keychain Access 或命令行）
2. 登录 Developer Portal
3. Certificates → 点击 "+"
4. 选择证书类型
5. 上传 CSR 文件
6. 下载 .cer 证书文件
7. 双击 .cer 文件安装到 Keychain
8. 导出 .p12 文件备份（包含私钥）
```

### 5.3 证书导出和导入

**导出 .p12 文件（备份证书+私钥）：**

1. 打开 Keychain Access
2. 在 "我的证书" 分类中找到目标证书
3. 展开证书，确认下方有私钥
4. 右键点击证书 → "导出..."
5. 选择 .p12 格式
6. 设置保护密码
7. 保存到安全位置

**导入 .p12 文件：**

```bash
# 命令行导入
security import certificate.p12 -k ~/Library/Keychains/login.keychain-db \
    -P "password" -T /usr/bin/codesign

# CI 环境中导入到临时 Keychain
security create-keychain -p "" build.keychain
security import certificate.p12 -k build.keychain \
    -P "password" -T /usr/bin/codesign
security list-keychains -s build.keychain
```

### 5.4 证书撤销

当证书私钥丢失或不再需要时，可以撤销证书。

**撤销的影响：**

| 场景 | 影响 |
|------|------|
| 撤销开发证书 | 关联的描述文件失效，开发中的 App 无法运行 |
| 撤销分发证书 | 无法提交新版本到 App Store，已上架的版本不受影响 |
| 撤销推送证书 | 推送服务中断，必须使用新证书重新配置 |

⚠️ **警告**：撤销分发证书前务必确认：
1. 已备份 .p12 文件（如果还有的话）
2. 团队其他成员知晓此操作
3. CI/CD 流水线中的证书已更新
4. 推送服务已配置新证书

### 5.5 App ID 管理

App ID 是 App 在 Apple 生态中的唯一标识，与 Bundle ID 对应。

**App ID 类型：**

| 类型 | 格式 | 说明 |
|------|------|------|
| Explicit App ID | com.company.appname | 精确匹配单个 App |
| Wildcard App ID | com.company.* | 匹配同一团队下的所有 App |

**Explicit vs Wildcard 对比：**

| 特性 | Explicit | Wildcard |
|------|----------|----------|
| 精确匹配 | ✅ | ❌ |
| 推送通知 | ✅ | ❌ |
| Apple Pay | ✅ | ❌ |
| iCloud | ✅ | ❌ |
| Game Center | ✅ | ❌ |
| Sign in with Apple | ✅ | ❌ |
| App Groups | ✅ | ❌ |
| 适合场景 | 正式 App | 快速原型 / 内部工具 |

💡 **提示**：推荐始终使用 Explicit App ID。Wildcard App ID 不支持大部分高级功能，实际开发中很少使用。

### 5.6 设备注册

开发和 Ad Hoc 分发需要注册设备 UDID。

**获取设备 UDID 的方法：**

| 方法 | 步骤 |
|------|------|
| Xcode | Window → Devices and Simulators → 选择设备 → 复制 Identifier |
| Finder | 连接设备 → 点击序列号切换显示 UDID |
| iTunes | 连接设备 → 点击序列号切换显示 |
| 第三方工具 | 使用 UDID 获取工具（如 udid.io） |

**注册设备：**

1. Developer Portal → Devices → 点击 "+"
2. 输入设备名称和 UDID
3. 点击 Continue → Register

**设备数量限制：**

- 设备可以在每年续费时清除和重新注册
- 已注册的设备不能删除，只能禁用

### 6.5 Entitlements 文件

## 7. 多团队/多 App 的证书管理策略

### 7.1 多团队场景

开发者可能同时属于多个 Apple 开发者团队：

| 场景 | 说明 |
|------|------|
| 公司团队 + 个人团队 | 白天用公司账号，晚上用个人账号 |
| 多客户项目 | 外包公司为不同客户开发 App |
| 公司主团队 + 子团队 | 大公司有多个开发团队 |

**Xcode 中切换 Team：**

1. 项目设置 → Signing & Capabilities
2. Team 下拉菜单中选择对应团队
3. 不同 Team 的证书和描述文件是独立的

### 7.2 多 App 证书管理

当团队有多个 App 时，证书管理策略：

**方案一：共享分发证书**

```
Team Distribution Certificate
    ├── App A (描述文件 A)
    ├── App B (描述文件 B)
    └── App C (描述文件 C)
```

- 优点：证书数量少，管理简单
- 缺点：证书撤销影响所有 App

**方案二：独立分发证书**

```
Distribution Certificate 1 → App A
Distribution Certificate 2 → App B
Distribution Certificate 3 → App C
```

- 优点：证书互相独立，撤销不影响其他 App
- 缺点：受 3 个分发证书限制

💡 **提示**：对于大多数团队，推荐方案一（共享分发证书）。使用 match 工具可以很好地管理共享证书。

### 7.3 使用 match 统一管理

Fastlane 的 match 工具是团队证书管理的最佳实践：

**match 的工作原理：**

```
1. 在 Git 仓库中加密存储证书和描述文件
2. 团队成员通过 match 同步签名资源
3. 确保所有人使用同一套证书和描述文件
4. 使用 passphrase 加密，安全性有保障
```

**match 初始化：**

```bash
fastlane match init
# 选择存储方式：Git / Google Cloud / Amazon S3
# 输入 Git 仓库地址
# 设置 passphrase（加密密码）
```

**match 常用命令：**

```bash
# 同步开发证书和描述文件
fastlane match development

# 同步 App Store 证书和描述文件
fastlane match appstore

# 同步 Ad Hoc 证书和描述文件
fastlane match adhoc

# 只读模式（日常使用，不会修改证书）
fastlane match development --readonly true

# 为指定 App 同步
fastlane match appstore --app_identifier com.example.myapp

# 撤销并重新生成所有证书
fastlane match nuke
```

**在 Fastfile 中使用 match：**

```ruby
lane :beta do
  match(
    type: "adhoc",
    readonly: true,
    app_identifier: "com.example.myapp"
  )

  gym(
    scheme: "MyApp",
    export_method: "ad-hoc"
  )
end

lane :release do
  match(
    type: "appstore",
    readonly: true,
    app_identifier: "com.example.myapp"
  )

  gym(
    scheme: "MyApp",
    export_method: "app-store"
  )
end
```

### 7.4 证书管理最佳实践

| 实践 | 说明 |
|------|------|
| 使用 match | 统一管理团队签名资源 |
| .p12 备份 | 证书创建后立即导出 .p12 备份 |
| readonly 日常 | 日常构建使用 `readonly: true`，避免意外修改 |
| 专人管理 | 指定一人负责证书的创建和续期 |
| 文档记录 | 记录每个证书的用途和到期时间 |
| 监控提醒 | 设置证书到期提醒 |
| 最小权限 | CI 环境使用只读模式 |

## 8. 证书过期和续期处理

### 8.1 证书过期的影响

| 证书类型 | 过期影响 | 已安装 App 是否受影响 |
|----------|----------|------------------------|
| 开发证书 | 无法真机调试 | 否 |
| 分发证书 | 无法提交新版本 | 否（App Store 版本不受影响） |
| 推送证书 | 推送服务中断 | 推送无法送达 |
| 描述文件 | 无法安装新 App | 可能（取决于 iOS 版本） |

### 8.2 描述文件过期处理

描述文件过期后：

1. 已安装的 App **可能**无法启动（iOS 15+ 更严格）
2. 无法安装新的 App
3. Xcode 构建失败

**续期步骤：**

```
1. 检查关联证书是否仍然有效
2. 在 Developer Portal 重新生成描述文件
3. 下载并安装新描述文件
4. 在 Xcode 中选择新描述文件
5. 重新构建 App
```

**自动续期（使用 match）：**

```ruby
lane :update_profiles do
  match(
    type: "development",
    force: true
  )
  match(
    type: "appstore",
    force: true
  )
end
```

### 8.3 推送证书续期

推送证书有效期仅 1 年，是最常需要续期的证书。

**续期流程：**

```
1. 创建新的推送证书（不要撤销旧证书）
2. 下载 .cer 文件并安装到 Keychain
3. 导出 .p12 文件
4. 将 .p12 上传到推送服务提供商
5. 测试推送是否正常
6. 确认正常后，旧证书可等待自然过期
```

**推送证书续期脚本：**

```bash
#!/bin/bash
# push_cert_renew.sh - 推送证书续期提醒

# 检查推送证书到期时间
CERT_PATH="/path/to/push_cert.cer"

if [ -f "$CERT_PATH" ]; then
    EXPIRY_DATE=$(openssl x509 -enddate -noout -in "$CERT_PATH" | cut -d= -f2)
    EXPIRY_EPOCH=$(date -j -f "%b %d %H:%M:%S %Y %Z" "$EXPIRY_DATE" "+%s")
    NOW_EPOCH=$(date "+%s")
    DAYS_LEFT=$(( (EXPIRY_EPOCH - NOW_EPOCH) / 86400 ))

    if [ $DAYS_LEFT -lt 30 ]; then
        echo "⚠️ 推送证书将在 ${DAYS_LEFT} 天后过期！请尽快续期。"
    else
        echo "✅ 推送证书还有 ${DAYS_LEFT} 天过期。"
    fi
fi
```

### 8.4 证书到期监控

**使用脚本批量检查证书到期时间：**

```bash
#!/bin/bash
# check_certs.sh - 检查 Keychain 中所有开发者证书的到期时间

security find-identity -v -p codesigning ~/Library/Keychains/login.keychain-db | \
    grep "Apple Development\|Apple Distribution\|iOS Development\|iOS Distribution" | \
    while read line; do
        CERT_HASH=$(echo "$line" | awk '{print $2}')
        CERT_NAME=$(echo "$line" | sed "s/.*\"\(.*\)\".*/\1/")
        EXPIRY=$(security find-certificate -c "$CERT_NAME" -p ~/Library/Keychains/login.keychain-db | \
            openssl x509 -enddate -noout | cut -d= -f2)
        echo "$CERT_NAME → 过期时间: $EXPIRY"
    done
```

**设置日历提醒：**

建议在以下时间点设置提醒：

| 证书类型 | 提醒时间 |
|----------|----------|
| 开发证书 | 到期前 60 天 |
| 分发证书 | 到期前 90 天 |
| 推送证书 | 到期前 30 天 |
| 描述文件 | 到期前 30 天 |

## 9. 常见签名错误排查

### 9.1 错误速查表

| 错误信息 | 原因 | 解决方法 |
|----------|------|----------|
| no signing certificate found | Keychain 中没有有效证书 | 安装证书或创建新证书 |
| provisioning profile expired | 描述文件已过期 | 重新生成描述文件 |
| provisioning profile doesn't include device | 设备 UDID 未注册 | 注册设备并更新描述文件 |
| bundle identifier differs | Bundle ID 与描述文件不匹配 | 修改 Bundle ID 或创建匹配的描述文件 |
| certificate has expired | 证书已过期 | 续期证书 |
| certificate revoked | 证书已被撤销 | 创建新证书 |
| entitlements mismatch | 权限与描述文件不匹配 | 更新 Capability 或重新生成描述文件 |
| failed to create provisioning profile | 无法自动创建描述文件 | 检查 App ID 配置或手动创建 |
| signing certificate is invalid | 证书私钥缺失 | 重新导入 .p12 文件 |
| ambiguous match | 多个描述文件匹配 | 手动指定描述文件 |

### 9.2 "No signing certificate" 错误

**完整错误信息：**

```
error: No signing certificate "iOS Development" found: No "iOS Development" signing certificate matching team ID "XXXXXXXXXX" with a private key was found.
```

**排查步骤：**

```
1. 打开 Keychain Access → 我的证书
2. 查找是否有 "Apple Development" 证书
3. 展开证书，确认下方有私钥
4. 如果没有私钥：
   a. 从备份导入 .p12 文件
   b. 或使用 match 同步
   c. 或创建新证书
5. 如果证书存在且有私钥：
   a. 检查证书是否过期
   b. 检查证书是否被信任
   c. 清理 Xcode 派生数据
```

**清理派生数据：**

```bash
# 删除派生数据
rm -rf ~/Library/Developer/Xcode/DerivedData/*

# 或在 Xcode 中
# Xcode → Settings → Locations → Derived Data → 点击箭头 → 删除对应文件夹
```

### 9.3 "Provisioning profile expired" 错误

**排查步骤：**

```
1. 检查描述文件到期时间
   Xcode → Preferences → Accounts → 选择 Team → Download Manual Profiles
2. 如果已过期，重新生成
3. 下载新描述文件
4. 在 Xcode 中选择新描述文件
5. Clean Build Folder (Cmd+Shift+K)
6. 重新构建
```

**使用命令行检查描述文件：**

```bash
# 列出所有已安装的描述文件
ls ~/Library/MobileDevice/Provisioning\ Profiles/

# 查看描述文件详情
security cms -D -i ~/Library/MobileDevice/Provisioning\ Profiles/xxx.mobileprovision

# 查看到期时间
security cms -D -i ~/Library/MobileDevice/Provisioning\ Profiles/xxx.mobileprovision | \
    plutil -extract ExpirationDate raw -
```

### 9.4 "Provisioning profile doesn't include device" 错误

**排查步骤：**

```
1. 获取设备 UDID
2. 在 Developer Portal → Devices 中检查是否已注册
3. 如果未注册，添加设备
4. 更新描述文件（添加新设备）
5. 下载并安装新描述文件
6. 重新构建
```

### 9.5 签名不匹配错误

**错误信息：**

```
error: Provisioning profile "XXX" doesn't match the entitlements file's value for the application-identifier entitlement.
```

**原因：** Entitlements 文件中的权限与描述文件中的权限不一致。

**解决方法：**

```
1. 检查 .entitlements 文件中的权限声明
2. 检查 App ID 中启用的 Capability
3. 确保两者一致
4. 重新生成描述文件
5. Clean Build 后重新构建
```

### 9.6 通用排查流程

当遇到签名问题时，按以下流程排查：

```
Step 1: 确认证书
    → Keychain Access 中是否有有效证书？
    → 证书下方是否有私钥？
    → 证书是否过期？

Step 2: 确认描述文件
    → 是否有匹配的描述文件？
    → 描述文件是否过期？
    → 描述文件是否包含正确的 App ID？
    → 描述文件是否包含正确的证书？

Step 3: 确认设备
    → 设备 UDID 是否已注册？
    → 描述文件是否包含该设备？

Step 4: 确认配置
    → Xcode 中的 Team 是否正确？
    → Bundle ID 是否匹配？
    → Capability 是否与 App ID 一致？

Step 5: 清理重建
    → 清理派生数据
    → 删除已安装的描述文件
    → 重新下载描述文件
    → Clean Build Folder
    → 重新构建
```

### 9.7 终极修复方案

如果以上步骤都无法解决问题：

```bash
# 1. 清理所有签名缓存
rm -rf ~/Library/Developer/Xcode/DerivedData/*
rm -rf ~/Library/MobileDevice/Provisioning\ Profiles/*

# 2. 重置 Xcode 签名设置
# 在 Xcode 中取消勾选 "Automatically manage signing"
# 重新勾选

# 3. 重新下载所有描述文件
# Xcode → Preferences → Accounts → 选择 Team → Download Manual Profiles

# 4. 重启 Xcode

# 5. Clean Build Folder (Cmd+Shift+K)

# 6. 重新构建
```

## 10. CI/CD 环境的证书管理

### 10.1 CI/CD 签名挑战

在 CI/CD 环境中管理签名面临特殊挑战：

| 挑战 | 说明 |
|------|------|
| 无 GUI | CI 环境通常没有图形界面，无法使用 Xcode 的自动签名 |
| 临时环境 | CI Runner 可能每次都是全新环境 |
| 安全性 | 证书和私钥是敏感信息，需要安全传输 |
| 多人协作 | 需要确保 CI 使用与开发团队一致的签名资源 |
| Keychain 管理 | 需要创建和管理临时 Keychain |

### 10.2 CI 环境签名方案

**方案一：.p12 文件 + 描述文件**

最直接的方案，将 .p12 和描述文件上传到 CI 系统。

```bash
#!/bin/bash
# ci_setup_signing.sh - CI 环境签名配置

# 创建临时 Keychain
KEYCHAIN_PATH="$RUNNER_TEMP/build.keychain"
KEYCHAIN_PASSWORD="$(openssl rand -base64 24)"

security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
security list-keychains -s "$KEYCHAIN_PATH"

# 导入证书
security import "$CERTIFICATE_PATH" \
    -k "$KEYCHAIN_PATH" \
    -P "$CERTIFICATE_PASSWORD" \
    -T /usr/bin/codesign \
    -T /usr/bin/security

# 设置 ACL
security set-key-partition-list -S apple-tool:,apple: \
    -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"

# 安装描述文件
mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles
cp "$PROVISIONING_PROFILE_PATH" ~/Library/MobileDevice/Provisioning\ Profiles/

echo "✅ 签名配置完成"
```

**方案二：match + Git 仓库**

使用 match 从 Git 仓库同步签名资源。

```bash
#!/bin/bash
# ci_match_signing.sh - 使用 match 配置签名

# 安装 Fastlane
gem install fastlane

# 使用 match 同步签名资源
fastlane match appstore \
    --readonly true \
    --git_url "https://github.com/team/certificates" \
    --git_branch "main" \
    --app_identifier "com.example.myapp" \
    --username "$APPLE_ID"

echo "✅ Match 签名同步完成"
```

**方案三：App Store Connect API Key**

使用 API Key 认证，无需 Apple ID 和密码。

```bash
#!/bin/bash
# ci_api_key_signing.sh - 使用 API Key 配置签名

# 使用 Fastlane 的 app_store_connect_api_key
fastlane match appstore \
    --readonly true \
    --api_key_path "$API_KEY_PATH" \
    --app_identifier "com.example.myapp"
```

### 10.3 GitHub Actions 签名配置

```yaml
name: Build and Deploy

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install certificates
        env:
          CERTIFICATE_BASE64: ${{ secrets.CERTIFICATE_BASE64 }}
          PROVISION_PROFILE_BASE64: ${{ secrets.PROVISION_PROFILE_BASE64 }}
          CERTIFICATE_PASSWORD: ${{ secrets.CERTIFICATE_PASSWORD }}
          KEYCHAIN_PASSWORD: ${{ secrets.KEYCHAIN_PASSWORD }}
        run: |
          CERTIFICATE_PATH=$RUNNER_TEMP/certificate.p12
          PP_PATH=$RUNNER_TEMP/profile.mobileprovision
          KEYCHAIN_PATH=$RUNNER_TEMP/app.keychain-db

          echo "$CERTIFICATE_BASE64" | base64 --decode > "$CERTIFICATE_PATH"
          echo "$PROVISION_PROFILE_BASE64" | base64 --decode > "$PP_PATH"

          security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
          security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"

          security import "$CERTIFICATE_PATH" \
            -k "$KEYCHAIN_PATH" \
            -P "$CERTIFICATE_PASSWORD" \
            -T /usr/bin/codesign

          security set-key-partition-list -S apple-tool:,apple: \
            -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"

          mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles
          cp "$PP_PATH" ~/Library/MobileDevice/Provisioning\ Profiles/

      - name: Build
        run: |
          xcodebuild archive \
            -project MyApp.xcodeproj \
            -scheme MyApp \
            -archivePath build/MyApp.xcarchive \
            CODE_SIGN_STYLE=Manual \
            DEVELOPMENT_TEAM="${{ secrets.TEAM_ID }}"

      - name: Export IPA
        run: |
          xcodebuild -exportArchive \
            -archivePath build/MyApp.xcarchive \
            -exportPath build/ipa \
            -exportOptionsPlist ExportOptions.plist

      - name: Cleanup keychain
        if: always()
        run: security delete-keychain $RUNNER_TEMP/app.keychain-db
```

### 10.4 ExportOptions.plist 配置

导出 IPA 时需要指定 ExportOptions.plist：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>method</key>
    <string>app-store</string>
    <key>teamID</key>
    <string>XXXXXXXXXX</string>
    <key>signingStyle</key>
    <string>manual</string>
    <key>provisioningProfiles</key>
    <dict>
        <key>com.example.myapp</key>
        <string>MyApp AppStore Profile</string>
    </dict>
</dict>
</plist>
```

**method 可选值：**

| 值 | 说明 |
|-----|------|
| app-store | App Store 分发 |
| ad-hoc | Ad Hoc 分发 |
| development | 开发构建 |
| enterprise | 企业分发 |
| developer-id | Mac App Store 外分发 |

### 10.5 Xcode Cloud 签名

Xcode Cloud 自动管理签名，无需手动配置：

```
1. 在 App Store Connect 中配置 Xcode Cloud
2. Xcode Cloud 自动创建和管理证书
3. 自动管理描述文件
4. 无需上传 .p12 或描述文件
```

**Xcode Cloud 签名限制：**

| 限制 | 说明 |
|------|------|
| 仅限 Xcode Cloud | 签名资源不能导出到其他 CI 系统 |
| 自动管理 | 无法手动指定证书和描述文件 |
| 团队共享 | 与手动签名可能冲突 |

## 11. Keychain 中证书的管理

### 11.1 Keychain 概述

macOS 的 Keychain 是存储证书和私钥的安全容器。

**Keychain 类型：**

| 类型 | 路径 | 说明 |
|------|------|------|
| 登录 Keychain | ~/Library/Keychains/login.keychain-db | 用户登录后自动解锁 |
| 系统 Keychain | /Library/Keychains/System.keychain | 系统级别 |
| 临时 Keychain | 自定义路径 | CI 环境使用 |

### 11.2 查看签名证书

```bash
# 列出所有签名证书
security find-identity -v -p codesigning

# 输出示例：
# 1) ABC123... "Apple Development: Zhang San (XXXXXXXXXX)"
# 2) DEF456... "Apple Distribution: Zhang San (XXXXXXXXXX)"
# 3) GHI789... "Developer ID Application: Zhang San (XXXXXXXXXX)"
```

### 11.3 Keychain 常用操作

```bash
# 创建新 Keychain
security create-keychain -p "password" my.keychain

# 解锁 Keychain
security unlock-keychain -p "password" my.keychain

# 锁定 Keychain
security lock-keychain my.keychain

# 删除 Keychain
security delete-keychain my.keychain

# 列出所有 Keychain
security list-keychains

# 设置 Keychain 搜索列表
security list-keychains -s my.keychain

# 导入证书
security import cert.p12 -k my.keychain -P "password" -T /usr/bin/codesign

# 设置 Keychain 分区列表（允许 codesign 访问）
security set-key-partition-list -S apple-tool:,apple: -k "password" my.keychain

# 导出证书
security find-certificate -c "Apple Development" -p my.keychain > cert.pem

# 查看证书详情
security find-certificate -c "Apple Development" -Z my.keychain
```

### 11.4 常见 Keychain 问题

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| "User interaction is not allowed" | Keychain 被锁定 | 解锁 Keychain 或设置分区列表 |
| 证书不显示在 Xcode 中 | Keychain 搜索列表不包含 | 将 Keychain 添加到搜索列表 |
| 私钥缺失 | 只导入了 .cer 没有私钥 | 导入 .p12 文件 |
| 证书重复 | 多次导入同一证书 | 在 Keychain Access 中删除重复项 |
| codesign 无法访问私钥 | ACL 未设置 | `set-key-partition-list` |

### 11.5 CI 环境的 Keychain 最佳实践

```bash
#!/bin/bash
# ci_keychain.sh - CI 环境 Keychain 管理

# 1. 创建临时 Keychain
KEYCHAIN="build_$(date +%s).keychain"
KEYCHAIN_PASSWORD="$(openssl rand -base64 24)"

security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"
security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN"

# 2. 将临时 Keychain 设为默认
security list-keychains -s "$KEYCHAIN" login.keychain

# 3. 导入签名证书
security import "$CERT_PATH" \
    -k "$KEYCHAIN" \
    -P "$CERT_PASSWORD" \
    -T /usr/bin/codesign \
    -T /usr/bin/productsign

# 4. 设置分区列表
security set-key-partition-list \
    -S apple-tool:,apple:,codesign: \
    -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN"

# 5. 验证证书已安装
security find-identity -v -p codesigning "$KEYCHAIN"

# ... 构建操作 ...

# 6. 清理临时 Keychain
security delete-keychain "$KEYCHAIN"
```

💡 **提示**：CI 环境中务必在构建完成后清理临时 Keychain，避免证书泄露。

## 12. 代码签名命令行工具

### 12.1 codesign 命令

`codesign` 是 macOS 内置的代码签名工具。

```bash
# 签名 App
codesign --sign "Apple Development: Your Name (XXXXXXXXXX)" \
    --force \
    --timestamp \
    --identifier com.example.myapp \
    /path/to/MyApp.app

# 验证签名
codesign --verify --verbose /path/to/MyApp.app

# 查看签名信息
codesign --display --verbose=4 /path/to/MyApp.app

# 查看签名证书
codesign -dvvv /path/to/MyApp.app
```

**codesign 常用参数：**

| 参数 | 说明 |
|------|------|
| --sign | 指定签名证书 |
| --force | 强制重新签名 |
| --timestamp | 添加安全时间戳 |
| --identifier | 指定 Bundle Identifier |
| --entitlements | 指定 Entitlements 文件 |
| --keychain | 指定 Keychain |
| --deep | 递归签名所有嵌套代码 |

### 12.2 security 命令

`security` 是 macOS 的 Keychain 管理工具。

```bash
# 查找签名证书
security find-identity -v -p codesigning

# 查看描述文件信息
security cms -D -i profile.mobileprovision

# 导入证书
security import cert.p12 -k login.keychain -P "password"

# 创建 Keychain
security create-keychain -p "password" my.keychain

# 解锁 Keychain
security unlock-keychain -p "password" my.keychain
```

### 12.3 xcodebuild 签名参数

```bash
xcodebuild archive \
    -project MyApp.xcodeproj \
    -scheme MyApp \
    -archivePath build/MyApp.xcarchive \
    CODE_SIGN_STYLE=Manual \
    DEVELOPMENT_TEAM=XXXXXXXXXX \
    CODE_SIGN_IDENTITY="Apple Distribution" \
    PROVISIONING_PROFILE_SPECIFIER="MyApp AppStore Profile"
```

**常用签名参数：**

| 参数 | 说明 |
|------|------|
| CODE_SIGN_STYLE | 签名方式：Automatic / Manual |
| CODE_SIGN_IDENTITY | 签名证书 |
| DEVELOPMENT_TEAM | Team ID |
| PROVISIONING_PROFILE_SPECIFIER | 描述文件名称 |
| CODE_SIGN_ENTITLEMENTS | Entitlements 文件路径 |
| CODE_SIGNING_ALLOWED | 是否允许签名 |
| ENABLE_BITCODE | 是否启用 Bitcode |

### 12.4 检查 IPA 签名信息

```bash
# 解压 IPA
unzip MyApp.ipa -d MyApp_ipa

# 查看签名信息
```

## 13. 安全最佳实践

### 13.1 证书安全

| 实践 | 说明 |
|------|------|
| .p12 加密 | 导出 .p12 时必须设置强密码 |
| 私钥保护 | 私钥绝不通过明文渠道传输 |
| 最小权限 | CI 环境使用只读模式访问证书 |
| 定期轮换 | 定期更新证书，减少泄露风险 |
| 撤销机制 | 证书泄露后立即撤销 |

### 13.2 CI/CD 安全

| 实践 | 说明 |
|------|------|
| Secrets 管理 | 证书和密码通过 CI Secrets 传入 |
| 临时 Keychain | CI 环境使用临时 Keychain，构建后删除 |
| Base64 编码 | 证书文件以 Base64 编码存储在 Secrets 中 |
| 不提交到 Git | .p12、.mobileprovision 不提交到代码仓库 |
| 环境隔离 | 不同环境使用不同的签名配置 |

### 13.3 .gitignore 配置

```gitignore
# 签名相关文件
*.p12
*.mobileprovision
*.certSigningRequest
*.cer

# Fastlane
fastlane/AuthKey_*.p8
fastlane/README.md

# Xcode
*.xcuserdatad
xcuserdata/
```

### 13.4 match 仓库安全

```bash
# match 仓库的 .gitignore
*.p12
*.mobileprovision
*.cer

# match 使用 passphrase 加密
# 即使仓库泄露，没有 passphrase 也无法获取证书
```

💡 **提示**：match 仓库应设为私有，且只有授权人员才能访问。passphrase 应与仓库分开存储。

### 14.4 签名诊断脚本

```bash
#!/bin/bash
# diagnose_signing.sh - 签名问题诊断脚本

echo "===== 1. 签名证书检查 ====="
security find-identity -v -p codesigning

echo ""
echo "===== 2. 已安装描述文件 ====="
for profile in ~/Library/MobileDevice/Provisioning\ Profiles/*.mobileprovision; do
    if [ -f "$profile" ]; then
        NAME=$(security cms -D -i "$profile" 2>/dev/null | plutil -extract Name raw - 2>/dev/null)
        EXPIRY=$(security cms -D -i "$profile" 2>/dev/null | plutil -extract ExpirationDate raw - 2>/dev/null)
        APP_ID=$(security cms -D -i "$profile" 2>/dev/null | plutil -extract Entitlements.application-identifier raw - 2>/dev/null)
        echo "📄 $NAME"
        echo "   Bundle ID: $APP_ID"
        echo "   过期时间: $EXPIRY"
        echo ""
    fi
done

echo "===== 3. Keychain 搜索列表 ====="
security list-keychains

echo ""
echo "===== 4. Xcode 版本 ====="
xcodebuild -version

echo ""
echo "===== 5. 诊断完成 ====="
```

## 本章小结

| 主题 | 核心要点 |
|------|----------|
| 代码签名原理 | 基于非对称加密，确保代码来源可信、未被篡改 |
| 证书类型 | 开发证书（调试）、分发证书（发布）、推送证书（APNs） |
| 描述文件 | 绑定证书、设备、App ID 的授权文件，分为开发/Ad Hoc/App Store/Enterprise |
| 自动 vs 手动签名 | 自动签名适合个人开发，手动签名适合团队和 CI/CD |
| Developer Portal | 管理 App ID、证书、设备、描述文件的 Web 平台 |
| Xcode 签名配置 | Signing & Capabilities 面板、Capability、Entitlements |
| 多团队/多 App | 使用 match 统一管理，共享分发证书，专人管理 |
| 证书过期续期 | 推送证书 1 年、描述文件 1 年、开发/分发证书 5 年，提前续期 |
| 错误排查 | 按证书→描述文件→设备→配置的顺序逐步排查 |
| CI/CD 签名 | 临时 Keychain + .p12 导入，或使用 match/API Key |
| Keychain 管理 | 理解 Keychain 类型，CI 环境使用临时 Keychain |
| 安全实践 | .p12 加密、Secrets 管理、不提交到 Git、最小权限 |

> 💡 一句话总结：代码签名是 iOS 开发中"看不见但无处不在"的基础设施——理解它的原理和管理方式，是成为成熟 iOS 开发者的必经之路。
