# 32-需求分析与产品设计

> 🎯 **本章目标**：学会从零开始选择一个 App 选题，完成竞品分析，定义 MVP，规划命名与 Bundle ID，并掌握用 AI 辅助完成这些工作的方法。读完本章，你将拥有一份清晰的产品需求文档雏形。

## 如何选择 App 选题

### 从自身需求出发

做 App 最怕的就是"做出来没人用"。而最靠谱的选题来源，就是**你自己的真实需求**。

**为什么从自身需求出发？**

- 你最了解痛点在哪里，不需要猜
- 你自己就是第一个用户，可以持续验证
- 你对需求的理解深度远超"拍脑袋想出来的点子"

**示例：从自身需求出发的选题**

| 你的痛点 | 对应的 App 选题 |
|---------|----------------|
| 每天忘喝水 | 喝水提醒 App |
| 记不住各种密码 | 密码管理器 |
| 健身不知道练什么 | 健身计划生成器 |
| 读书总是半途而废 | 阅读打卡追踪器 |
| 买菜总忘带清单 | 购物清单 App |

> 💡 **提示**：拿出一张纸，写下你最近一周遇到过的 5 个"真烦"的瞬间，很可能其中就藏着一个好选题。

### 市场调研方法

光有自己的需求还不够，你还需要确认：**市场上有没有人也在找解决方案？**

#### 1. App Store 搜索分析

在 App Store 中搜索你选题相关的关键词，观察：

- 搜索结果多不多？（多 = 需求大，但竞争也大）
- 排名靠前的 App 下载量和评分如何？
- 有没有"搜索了但没找到满意的"的感觉？

#### 2. 竞品评分和评论分析

看竞品的 1-3 星评论，这是**金矿**：

- 用户在抱怨什么？
- 哪些功能缺失？
- 哪些体验很差？

> ⚠️ **警告**：不要只看好评！差评才是你超越竞品的机会。

#### 3. 社交媒体趋势

- 小红书、微博、知乎上搜索相关话题
- 看有没有人主动求推荐某类 App
- 关注热门话题中是否隐藏着需求

#### 4. 工具推荐

| 工具 | 用途 | 是否免费 |
|------|------|---------|
| App Store 搜索 | 直接看竞品和关键词热度 | ✅ 免费 |
| 七麦数据（qimai.cn） | 查看 App 下载排名、关键词热度 | 部分免费 |
| 蝉大师 | App Store 数据分析 | 部分免费 |
| Sensor Tower | 全球 App 市场数据 | 付费为主 |
| 微博/小红书/知乎 | 了解用户真实反馈 | ✅ 免费 |

### 选题评估框架

用下面这个 **5 维评估表**给每个选题打分（每项 1-5 分），帮你客观判断哪个选题值得做。

#### 5 维评估表

| 维度 | 说明 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|------|
| 需求强度 | 用户有多需要这个 App | 可有可无 | 有点需要 | 刚需，不解决不行 |
| 竞争程度 | 市场上同类 App 多不多 | 红海，巨头扎堆 | 有竞品但不完善 | 蓝海，几乎没有竞品 |
| 技术难度 | 你能不能做出来 | 超出能力范围 | 有挑战但可攻克 | 在能力范围内 |
| 变现潜力 | 能不能赚到钱 | 很难变现 | 有一定变现空间 | 变现路径清晰 |
| 个人兴趣 | 你愿不愿意长期投入 | 不太感兴趣 | 还行 | 非常感兴趣 |

#### 评分标准

- **总分 ≥ 20**：🟢 值得做，优先推进
- **总分 15-19**：🟡 可以做，但要注意短板
- **总分 < 15**：🔴 建议换一个选题

#### 示例评估

以"喝水提醒 App"为例：

| 维度 | 评分 | 理由 |
|------|------|------|
| 需求强度 | 4 | 很多人确实需要提醒喝水 |
| 竞争程度 | 2 | 已有很多喝水 App，竞争激烈 |
| 技术难度 | 5 | 通知+简单 UI，技术门槛低 |
| 变现潜力 | 2 | 免费竞品多，付费意愿低 |
| 个人兴趣 | 4 | 自己确实需要 |
| **总分** | **17** | 🟡 可以做，但需找到差异化点 |

## 竞品分析

### 竞品发现

找到竞品是分析的第一步，以下是 3 种常用方法：

#### 1. App Store 搜索

用你选题的核心关键词在 App Store 搜索，比如你的选题是"记账 App"，就搜索"记账""记账本""理财"等。

#### 2. 关键词搜索

用不同角度的关键词搜索，扩大覆盖面：

| 搜索角度 | 示例关键词 |
|---------|-----------|
| 功能词 | 记账、记账本、收支管理 |
| 场景词 | 家庭记账、学生记账、旅行记账 |
| 英文词 | expense tracker、budget planner |

#### 3. 推荐榜单

查看 App Store 的"免费榜""付费榜""分类榜"，了解同类 App 的市场表现。

> 💡 **提示**：一般选择 3-5 个核心竞品深入分析即可，不要贪多。

### 竞品功能对比

#### 功能对比表模板

| 功能 | 我的 App | 竞品 A | 竞品 B | 竞品 C |
|------|---------|--------|--------|--------|
| 核心功能 1 | ✅ | ✅ | ✅ | ❌ |
| 核心功能 2 | ✅ | ✅ | ❌ | ✅ |
| 差异功能 1 | ✅ | ❌ | ❌ | ❌ |
| ... | ... | ... | ... | ... |

#### 评分对比

| App | 评分 | 评价数量 | 主要好评 | 主要差评 |
|-----|------|---------|---------|---------|
| 竞品 A | 4.6 | 12,000 | 界面好看 | 广告太多 |
| 竞品 B | 4.2 | 3,500 | 功能全面 | 操作复杂 |
| 竞品 C | 3.8 | 800 | 免费好用 | 经常崩溃 |

#### 评论分析

重点看 1-3 星评论，提炼用户的核心不满：

```
评论示例：
"这个 App 界面太复杂了，我只是想记个账而已"  → 痛点：操作太复杂
"每次打开都有广告，太烦了"               → 痛点：广告干扰
"没有分类统计功能，看不到钱花哪了"         → 痛点：缺少统计功能
```

### 差异化定位

#### 找到竞品不足

从评论分析中提炼出竞品的不足，这些就是你的**机会**：

| 竞品不足 | 你的机会 |
|---------|---------|
| 界面复杂 | 做极简设计 |
| 广告太多 | 做纯净无广告版 |
| 缺少统计 | 加入可视化图表 |
| 没有小组件 | 支持 iOS 桌面小组件 |

#### 确定差异化方向

选择 1-2 个差异化方向，不要贪多：

> 💡 **提示**：差异化不需要"全面碾压"，只需要在某个点上做到比竞品好 10 倍。

#### 定位声明模板

用一句话说清楚你的 App 是什么、给谁用、有什么不同：

```
[App 名称] 是一款面向 [目标用户] 的 [App 类型]，
与 [主要竞品] 不同的是，它 [核心差异化点]。
```

**示例**：

```
"轻记账" 是一款面向大学生的极简记账 App，
与"随手记"不同的是，它 3 秒完成一笔记账，零学习成本。
```

## 功能清单与 MVP 定义

### 功能头脑风暴

先把所有能想到的功能都列出来，**不要设限，不要评判**。

**示例：记账 App 功能头脑风暴**

- 记录收支
- 分类管理
- 月度统计图表
- 年度报告
- 预算设置
- 多账户管理
- 数据导出
- iCloud 同步
- 桌面小组件
- 拍照记账
- 语音记账
- 共享账本
- 暗黑模式
- 提醒记账
- 标签系统
- 搜索功能
- 货币换算
- 账单扫描识别
- 订阅管理
- 投资追踪

### 功能优先级排序

#### MoSCoW 方法

把功能分成 4 个等级：

| 等级 | 含义 | 说明 |
|------|------|------|
| **M**ust have | 必须有 | 没有这个功能 App 就不能用 |
| **S**hould have | 应该有 | 很重要但不是第一版必须的 |
| **C**ould have | 可以有 | 锦上添花的功能 |
| **W**on't have | 暂不做 | 明确排除，以后再说 |

#### P0/P1/P2 标注

也可以用更简洁的 P 系列标注：

| 等级 | 含义 | 对应 MoSCoW |
|------|------|-------------|
| P0 | 核心功能，第一版必须有 | Must have |
| P1 | 重要功能，第二版加入 | Should have |
| P2 | 加分功能，后续迭代 | Could have |

#### 示例

| 功能 | 优先级 | 等级 |
|------|--------|------|
| 记录收支 | P0 | Must have |
| 分类管理 | P0 | Must have |
| 月度统计图表 | P0 | Must have |
| 预算设置 | P1 | Should have |
| 桌面小组件 | P1 | Should have |
| iCloud 同步 | P1 | Should have |
| 拍照记账 | P2 | Could have |
| 语音记账 | P2 | Could have |
| 共享账本 | P2 | Could have |
| 货币换算 | 暂不做 | Won't have |
| 投资追踪 | 暂不做 | Won't have |

### MVP（最小可行产品）定义

#### 什么是 MVP

MVP = **Minimum Viable Product**（最小可行产品）

简单说就是：**用最少的功能，验证你的想法是否可行。**

想象你要开一家餐厅，MVP 不是先把装修做到五星标准再开业，而是先摆个路边摊，看看有没有人来吃。

#### 为什么先做 MVP

| 不做 MVP | 做 MVP |
|---------|--------|
| 开发 3 个月，上线发现没人用 | 2 周上线，快速验证需求 |
| 做了一堆没人用的功能 | 只做核心功能，节省时间 |
| 发现方向错了，沉没成本大 | 方向错了，及时调整损失小 |
| 容易半途而废 | 快速获得成就感，持续迭代 |

> ⚠️ **警告**：MVP 不是"粗制滥造"，而是"精简但完整"。核心功能必须做到好用，不能因为精简就牺牲体验。

#### 如何定义 MVP 范围

**3 步法**：

1. 从功能清单中选出所有 **P0（Must have）** 功能
2. 问自己："如果只有这些功能，用户能完成核心任务吗？"
3. 如果能 → 这就是你的 MVP；如果不能 → 补充必要功能

#### 示例

**记账 App 的 MVP 范围**：

| MVP 包含 | MVP 不包含（后续迭代） |
|---------|---------------------|
| ✅ 记录收支 | ❌ 拍照记账 |
| ✅ 分类管理 | ❌ 语音记账 |
| ✅ 月度统计图表 | ❌ 共享账本 |
| ✅ 基本设置页 | ❌ 桌面小组件 |
| | ❌ iCloud 同步 |
| | ❌ 数据导出 |

> 💡 **提示**：MVP 的目标是"能用"，不是"完美"。先上线，再根据用户反馈迭代。

## App 命名与 Bundle ID 规划

### App 命名技巧

App 的名字就是你的第一张名片，好名字能让人一眼记住。

#### 好名字的特征

| 特征 | 说明 | 示例 |
|------|------|------|
| 简短好记 | 2-4 个字最佳 | 墨迹、随手记 |
| 一看就懂 | 名字能暗示功能 | 剪映、美图秀秀 |
| 容易搜索 | 包含核心关键词 | XX 记账、XX 天气 |
| 独特不撞名 | 避免和已有 App 重名 | — |

#### 命名方法

| 方法 | 说明 | 示例 |
|------|------|------|
| 功能直白法 | 直接描述 App 做什么 | 记账本、喝水提醒 |
| 隐喻联想法 | 用一个意象暗示功能 | 墨迹天气、飞书 |
| 组合词法 | 两个词组合 | 小红书、微信读书 |
| 英文缩写法 | 用英文缩写或简写 | Notion、Things |

#### 避免的问题

> ⚠️ **警告**：以下命名问题要避免！

- ❌ 名字太长（超过 6 个字）
- ❌ 含有特殊符号或数字（MyApp2024!）
- ❌ 和知名 App 名字太像（容易被拒审）
- ❌ 使用"最佳""第一"等夸大词汇（App Store 审核会拒）
- ❌ 名字和功能完全无关（用户搜不到）

#### 示例

| 选题 | 好名字 | 不好的名字 |
|------|--------|-----------|
| 记账 App | 轻记账、小账本 | 超级无敌记账大师 2024 |
| 喝水提醒 | 水滴提醒、每日水 | 饮水管理系统专业版 |
| 番茄钟 | 专注番茄、小番茄 | 时间管理效率工具 |

### Bundle ID 命名规范

Bundle ID 是你的 App 在苹果生态中的**唯一标识符**，就像身份证号一样。

#### 反域名格式

Bundle ID 使用**反域名格式**：

```
com.你的域名.App名称
```

#### 示例

| 场景 | Bundle ID |
|------|-----------|
| 有个人网站 wjq.dev | com.wjq.dev.LightNote |
| 有公司域名 mycompany.com | com.mycompany.SuperTask |
| 没有域名（用 GitHub） | com.github-wjq.LightNote |

> 💡 **提示**：如果你没有域名，可以用 `com.github-用户名.App名` 或 `com.你的英文名.App名` 作为 Bundle ID。关键是保证唯一性。

> ⚠️ **警告**：Bundle ID 一旦发布就**不能更改**！请认真规划，避免以后后悔。

### 商标查询

#### 为什么要查商标

如果你的 App 名字和别人的注册商标冲突，可能会：

- 被 App Store 审核拒绝
- 收到律师函要求改名
- 被迫下架，损失用户

#### 查询方法

| 查询渠道 | 网址 | 说明 |
|---------|------|------|
| 中国商标网 | https://sbj.cnipa.gov.cn | 查询中国注册商标 |
| USPTO | https://tmsearch.uspto.gov | 查询美国注册商标 |
| WIPO | https://www.wipo.int | 查询国际商标 |

> 💡 **提示**：至少查一下中国商标网和 App Store 是否已有同名 App。如果都查不到，基本可以放心使用。

## 用 AI 辅助做竞品分析和需求梳理

AI 是你的"免费产品经理"，善用 Prompt 可以大幅提升效率。

### Prompt 模板

#### 竞品分析 Prompt

```
我正在开发一款 [App 类型] App，目标用户是 [目标用户群体]。
请帮我分析以下内容：

1. 这个领域目前有哪些主要竞品？分别列出名称、核心功能、评分
2. 这些竞品的共同不足是什么？（从用户评论角度分析）
3. 我的 App 可以在哪些方面做出差异化？
4. 请用表格形式呈现功能对比

请用中文回答，尽量具体。
```

#### 需求梳理 Prompt

```
我正在开发一款 [App 类型] App，核心功能是 [核心功能描述]。
请帮我：

1. 列出这个 App 可能需要的所有功能（头脑风暴，不设限）
2. 用 MoSCoW 方法对这些功能进行优先级排序
3. 定义 MVP 应该包含哪些功能
4. 列出 MVP 不包含但后续可以迭代的功能

请用表格形式呈现，并说明每个功能为什么属于该优先级。
```

### 实际示例

**输入**：

```
我正在开发一款极简记账 App，目标用户是大学生和刚工作的年轻人。
请帮我分析以下内容：

1. 这个领域目前有哪些主要竞品？分别列出名称、核心功能、评分
2. 这些竞品的共同不足是什么？
3. 我的 App 可以在哪些方面做出差异化？
4. 请用表格形式呈现功能对比
```

**AI 可能的输出**：

| 竞品 | 核心功能 | 评分 | 主要不足 |
|------|---------|------|---------|
| 随手记 | 全面记账、报表、投资 | 4.5 | 功能过于复杂，新手不友好 |
| 网易有钱 | 自动记账、多账户 | 4.2 | 已停止更新 |
| 挖财 | 记账、理财、社区 | 4.3 | 广告多，界面臃肿 |
| 微记账 | 简单记账 | 4.0 | 功能太少，无统计图表 |

**差异化方向**：

- 极简操作：3 秒完成一笔记账
- 无广告：纯净体验
- 可视化图表：一目了然的消费分析
- 桌面小组件：快速记账入口

## 小结

本章我们完成了从"想法"到"产品方案"的关键一步：

| 步骤 | 关键要点 |
|------|---------|
| 选择选题 | 从自身需求出发，用 5 维评估表打分 |

| AI 辅助 | 用 Prompt 模板让 AI 帮你做分析和梳理 |
