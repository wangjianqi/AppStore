## 1. 无障碍（Accessibility）的重要性

### 1.1 为什么需要无障碍？

想象一下：你走进一家餐厅，门口只有楼梯没有坡道，坐轮椅的人根本进不去。App 也是一样——如果没有无障碍支持，视障、听障、运动障碍的用户就无法使用你的 App。

> 💡 类比：无障碍就像给建筑加坡道和电梯——不仅残障人士需要，推婴儿车的父母、搬重物的人也受益。App 的无障碍功能同样能让所有用户体验更好。

### 1.2 用户群体

| 用户群体 | 面临的困难 | 需要的无障碍支持 |
|---------|-----------|----------------|
| 视障用户 | 看不到屏幕内容 | VoiceOver、动态类型、高对比度 |
| 色盲用户 | 无法区分某些颜色 | 不依赖颜色传达信息、色盲友好配色 |
| 听障用户 | 听不到音频提示 | 视觉替代提示、字幕 |
| 运动障碍用户 | 精细触摸困难 | 大点击区域、语音控制、开关控制 |
| 认知障碍用户 | 复杂界面难以理解 | 简洁布局、清晰导航 |

### 1.3 App Store 审核要求

Apple 对无障碍有明确的审核期望：

- **必须**支持 VoiceOver：核心功能应可被 VoiceOver 用户使用
- **必须**支持动态类型：文字不应在用户放大字体后截断或重叠
- **推荐**支持高对比度模式
- **推荐**提供无障碍声明（Accessibility Statement）

> ⚠️ 虽然无障碍不是 App 被拒的绝对理由，但 Apple 越来越重视这一点。每年 WWDC 都有专门的无障碍专题，Apple 也在持续加强审核力度。

## 2. SwiftUI 无障碍基础

SwiftUI 提供了一系列 `accessibility` 修饰符，让你能为视图添加"无障碍信息"——就像给商品贴标签，告诉 VoiceOver 这个东西是什么、能做什么。

### 2.1 accessibilityLabel——"我叫什么"

`accessibilityLabel` 给视图一个文字标签，VoiceOver 会朗读这个标签。

```swift
Image(systemName: "heart.fill")
    .accessibilityLabel("收藏")
```

> 💡 图标没有文字时，VoiceOver 不知道该读什么。`accessibilityLabel` 就是给图标"配音"。

### 2.2 accessibilityHint——"我能做什么"

`accessibilityHint` 描述操作的结果，告诉用户"点击后会发生什么"。

```swift
Button(action: toggleFavorite) {
    Image(systemName: isFavorite ? "heart.fill" : "heart")
}
.accessibilityLabel(isFavorite ? "取消收藏" : "收藏")
.accessibilityHint("双击以切换收藏状态")
```

### 2.3 accessibilityValue——"我现在的值是什么"

`accessibilityValue` 用于表示当前值，比如滑块的进度、步数的数量。

```swift
Slider(value: $volume, in: 0...100)
    .accessibilityLabel("音量")
    .accessibilityValue("\(Int(volume))%")
```

### 2.4 综合示例

```swift
struct CoffeeOrderView: View {
    @State private var quantity = 1
    @State private var size = "中杯"

    var body: some View {
        VStack(spacing: 16) {
            Image("coffee")
                .accessibilityLabel("咖啡图片")

            Stepper("数量: \(quantity)", value: $quantity, in: 1...10)
                .accessibilityValue("\(quantity) 杯")
                .accessibilityHint("增减咖啡数量")

            Picker("杯型", selection: $size) {
                Text("小杯").tag("小杯")
                Text("中杯").tag("中杯")
                Text("大杯").tag("大杯")
            }
            .pickerStyle(.segmented)
            .accessibilityValue("当前选择: \(size)")
        }
        .padding()
    }
}
```

### 2.5 常用无障碍修饰符速查表

| 修饰符 | 作用 | 使用场景 |
|-------|------|---------|
| `accessibilityLabel(_:)` | 设置朗读标签 | 图标、无文字按钮 |
| `accessibilityHint(_:)` | 设置操作提示 | 需要说明点击结果的控件 |
| `accessibilityValue(_:)` | 设置当前值 | 滑块、步进器、进度条 |
| `accessibilityHidden(_:)` | 隐藏无障碍元素 | 纯装饰性元素 |
| `accessibilityAddTraits(_:)` | 添加特征标记 | 标记为按钮、标题等 |
| `accessibilityRemoveTraits(_:)` | 移除特征标记 | 移除不需要的默认特征 |
| `accessibilityElement(children:)` | 控制子元素合并 | 将多个视图合并为一个无障碍元素 |

## 3. VoiceOver 适配

VoiceOver 是 iOS 内置的屏幕阅读器，能把屏幕上的内容朗读出来。适配 VoiceOver 是无障碍最核心的工作。

> 💡 类比：VoiceOver 就像"有声导航"，替用户"看"屏幕并读出来。你的工作就是确保导航信息准确、清晰。

### 3.1 开启 VoiceOver

| 方式 | 操作 |
|------|------|
| 设置 | 设置 → 辅助功能 → VoiceOver → 打开 |
| 快捷键 | 三击侧边按钮（需先在设置中开启快捷方式） |
| Xcode | 在模拟器中打开设置 → 辅助功能 → VoiceOver |

### 3.2 分组——把相关信息合并

当多个视图在视觉上是一个整体时，VoiceOver 应该把它们作为一个元素朗读，而不是逐个朗读。

```swift
HStack {
    Image(systemName: "person.circle.fill")
        .font(.title)
    VStack(alignment: .leading) {
        Text("张三")
            .font(.headline)
        Text("iOS 开发者")
            .font(.subheadline)
    }
}
.accessibilityElement(children: .combine)
.accessibilityLabel("张三，iOS 开发者")
```

`children` 参数说明：

| 参数值 | 效果 |
|-------|------|
| `.combine` | 合并子元素为一个无障碍元素 |
| `.contain` | 将子元素包含在容器中，可逐个导航 |
| `.ignore` | 忽略所有子元素的无障碍信息 |

### 3.3 导航顺序——控制朗读顺序

默认情况下，VoiceOver 按照从左到右、从上到下的顺序朗读。你可以用 `accessibilitySortPriority` 自定义顺序（数值越大越先朗读）。

```swift
VStack {
    Text("重要通知")
        .accessibilitySortPriority(2)

    Text("次要信息")
        .accessibilitySortPriority(1)

    Text("最不重要的内容")
        .accessibilitySortPriority(0)
}
```

### 3.4 自定义动作——让操作更高效

对于有多个操作的视图，可以用自定义动作让 VoiceOver 用户通过上下滑动来选择操作，而不需要逐个导航到每个按钮。

```swift
struct MessageRow: View {
    let message: Message

    var body: some View {
        HStack {
            VStack(alignment: .leading) {
                Text(message.sender)
                Text(message.preview)
            }

            Button(action: reply) {
                Image(systemName: "arrowshape.turn.up.left")
            }
            .accessibilityLabel("回复")

            Button(action: delete) {
                Image(systemName: "trash")
            }
            .accessibilityLabel("删除")
        }
        .accessibilityElement(children: .combine)
        .accessibilityLabel("\(message.sender): \(message.preview)")
        .accessibilityActions {
            Button("回复") { reply() }
            Button("删除") { delete() }
            Button("标记未读") { markAsUnread() }
        }
    }
}
```

> 💡 VoiceOver 用户听到这条消息后，上下滑动即可在"回复""删除""标记未读"之间切换，双击执行。比逐个导航按钮高效得多！

### 3.5 隐藏装饰性元素

纯装饰性的图片和元素不应被 VoiceOver 朗读，用 `accessibilityHidden` 隐藏。

```swift
Image("decorative_pattern")
    .accessibilityHidden(true)
```

## 4. 动态类型（Dynamic Type）

### 4.1 什么是动态类型？

动态类型是 iOS 的系统级字体缩放功能。用户可以在"设置 → 显示与亮度 → 文字大小"中调整字体大小，App 应该跟随系统设置自动调整。

> 💡 类比：动态类型就像"自动变焦眼镜"——用户需要更大的字，App 就自动放大，不需要用户手动缩放。

### 4.2 使用系统字体

SwiftUI 的 `Text` 默认支持动态类型，只要你使用系统字体（不指定固定字号）：

```swift
// ✅ 支持动态类型
Text("你好世界")
    .font(.title)

// ✅ 支持动态类型
Text("正文内容")
    .font(.body)

// ❌ 不支持动态类型（固定字号）
Text("固定大小")
    .font(.system(size: 16))
```

### 4.3 文字样式与字号对照表

| 文字样式 | 默认字号（pt） | 用途 |
|---------|--------------|------|
| `.largeTitle` | 34 | 页面大标题 |
| `.title` | 28 | 区块标题 |
| `.title2` | 22 | 二级标题 |
| `.title3` | 20 | 三级标题 |
| `.headline` | 17 (粗体) | 强调文字 |
| `.body` | 17 | 正文 |
| `.callout` | 16 | 副文本 |
| `.subheadline` | 15 | 辅助说明 |
| `.footnote` | 13 | 脚注 |
| `.caption` | 12 | 标签说明 |
| `.caption2` | 11 | 次要说明 |

### 4.4 布局适配——让界面"能屈能伸"

字体放大后，布局可能被撑破。需要用灵活布局来适配：

```swift
struct AdaptiveCardView: View {
    let title: String
    let subtitle: String

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text(title)
                .font(.headline)

            Text(subtitle)
                .font(.subheadline)
                .foregroundStyle(.secondary)
        }
        .frame(maxWidth: .infinity, alignment: .leading)
        .padding()
        .background(Color(.systemBackground))
        .clipShape(RoundedRectangle(cornerRadius: 12))
        .shadow(radius: 2)
    }
}
```

布局适配的关键技巧：

| 问题 | 解决方案 |
|------|---------|
| 文字被截断 | 使用 `lineLimit(nil)` 或不限制行数 |
| 文字重叠 | 使用 `Spacer()` 和 `VStack` 而非固定偏移 |
| 固定高度不够 | 使用 `minHeight` 代替固定 `height` |
| 横向空间不足 | 使用 `VStack` 替代 `HStack`，或用 `ViewThatFits` |
| 图片比例失调 | 使用 `aspectRatio` 保持比例 |

### 4.5 限制动态类型范围

某些场景下（如标签栏图标文字），你可能需要限制字体缩放范围：

```swift
Text("首页")
    .font(.caption)
    .dynamicTypeSize(...DynamicTypeSize.xLarge)
```

```swift
Text("标题")
    .font(.title)
    .dynamicTypeSize(DynamicTypeSize.large...)
```

> ⚠️ 限制动态类型范围应谨慎使用，只在确实需要的场景下使用（如导航栏、标签栏）。大多数情况下应让用户自由调整。

## 5. 颜色与对比度

### 5.1 不要只用颜色传达信息

色盲用户无法区分某些颜色。如果只用颜色来传达信息（如"红色=错误，绿色=正确"），色盲用户就无法理解。

```swift
// ❌ 只用颜色区分
HStack {
    Circle().fill(.red)
    Text("错误")
    Circle().fill(.green)
    Text("正确")
}

// ✅ 颜色 + 图标双重提示
HStack {
    Image(systemName: "xmark.circle.fill").foregroundStyle(.red)
    Text("错误")
    Image(systemName: "checkmark.circle.fill").foregroundStyle(.green)
    Text("正确")
}
```

### 5.2 色盲友好配色

| 色盲类型 | 难以区分的颜色 | 替代方案 |
|---------|-------------|---------|
| 红色盲（Protanopia） | 红色与深绿 | 用橙色替代红色 |
| 绿色盲（Deuteranopia） | 绿色与红色 | 用蓝色替代绿色 |
| 蓝色盲（Tritanopia） | 蓝色与黄色 | 用红色替代蓝色 |

> 💡 一个简单原则：**永远不要只靠颜色传达含义**。配合图标、文字、形状等辅助信息。

### 5.3 高对比度模式

iOS 支持高对比度模式（设置 → 辅助功能 → 增强对比度）。SwiftUI 提供了 `colorSchemeContrast` 环境值来检测：

```swift
struct AdaptiveColorView: View {
    @Environment(\.colorSchemeContrast) var contrast

    var body: some View {
        Text("重要信息")
            .padding()
            .background(
                contrast == .increased
                    ? Color.black
                    : Color.blue.opacity(0.1)
            )
            .foregroundStyle(
                contrast == .increased
                    ? Color.white
                    : Color.primary
            )
    }
}
```

更推荐的做法是使用自适应颜色，让系统自动处理：

```swift
// 在 Asset Catalog 中为普通和高对比度分别设置颜色
// 命名：AccentColor（普通）和 AccentColor（High Contrast）
Text("自适应颜色")
    .foregroundStyle(Color("AccentColor"))
```

### 5.4 对比度要求

| 文本类型 | 最低对比度（WCAG AA） | 推荐对比度（WCAG AAA） |
|---------|---------------------|---------------------|
| 正文文本（< 18pt） | 4.5:1 | 7:1 |
| 大文本（≥ 18pt 粗体或 ≥ 24pt） | 3:1 | 4.5:1 |
| 非文本 UI 元素 | 3:1 | — |

> ⚠️ iOS 人机界面指南建议正文对比度至少 4.5:1。可以使用 Xcode 的 Accessibility Inspector 来检查对比度。

## 6. 无障碍测试

### 6.1 Accessibility Inspector

Xcode 内置了 Accessibility Inspector，是测试无障碍的首选工具。

**打开方式**：Xcode 菜单 → Open Developer Tool → Accessibility Inspector

#### 使用步骤

| 步骤 | 操作 |
|------|------|
| 1 | 打开 Accessibility Inspector |
| 2 | 选择目标模拟器或真机 |
| 3 | 点击"瞄准镜"图标，悬停到元素上查看无障碍信息 |
| 4 | 检查 Label、Hint、Value、Traits 是否正确 |
| 5 | 切换到"Audit"标签页，点击"Run Audit"自动检测问题 |

#### Audit 常见问题

| 问题类型 | 说明 |
|---------|------|
| Missing Accessibility Label | 元素缺少无障碍标签 |
| Low Contrast | 对比度不足 |
| Hit Area Too Small | 点击区域太小（建议至少 44×44 pt） |
| Element Not Interactive | 可交互元素未被标记为可交互 |

### 6.2 VoiceOver 测试流程

手动测试 VoiceOver 是最重要的验证方式：

```
1. 在真机或模拟器上开启 VoiceOver
2. 用单指左右滑动，逐个导航元素
3. 检查每个元素的朗读内容是否准确
4. 检查导航顺序是否合理
5. 双击执行操作，验证功能是否正常
6. 用两指下滑从顶部朗读整个页面
7. 用三指滑动切换页面
```

> 💡 建议：每周至少用 VoiceOver 完整走一遍核心流程，就像"蒙着眼睛用你的 App"一样。

### 6.3 自动化无障碍测试

可以使用 XCTest 进行自动化无障碍测试：

```swift
import XCTest

final class AccessibilityTests: XCTestCase {
    let app = XCUIApplication()

    override func setUp() {
        app.launch()
    }

    func testHomeButtonHasLabel() {
        let homeButton = app.buttons["首页"]
        XCTAssertTrue(homeButton.exists)
        XCTAssertNotNil(homeButton.label)
        XCTAssertFalse(homeButton.label.isEmpty)
    }

    func testAllButtonsHaveMinimumHitArea() {
        let buttons = app.buttons.allElementsBoundByIndex
        for button in buttons {
            let frame = button.frame
            XCTAssertGreaterThanOrEqual(
                frame.width, 44,
                "按钮 \(button.label) 宽度小于 44pt"
            )
            XCTAssertGreaterThanOrEqual(
                frame.height, 44,
                "按钮 \(button.label) 高度小于 44pt"
            )
        }
    }
}
```

## 7. 国际化（i18n）基础

### 7.1 什么是国际化？

国际化（Internationalization，简称 i18n，因为 i 和 n 之间有 18 个字母）是让 App 能适应不同语言和地区的过程。本地化（Localization，简称 l10n）则是具体翻译成某种语言的过程。

> 💡 类比：国际化就像给房子预留电线管道——不管以后装什么品牌的电器都能用。本地化就是具体装上某个品牌的电视和空调。

### 7.2 String Catalog（Xcode 15+）

String Catalog 是 Xcode 15 引入的新方式，用 `.xcstrings` 文件统一管理所有字符串。

#### 创建 String Catalog

1. File → New → File
2. 选择 "String Catalog"
3. 命名为 `Localizable.xcstrings`
4. Xcode 会自动收集代码中的所有本地化字符串

#### String Catalog 结构

```json
{
  "sourceLanguage": "en",
  "strings": {
    "Hello": {
      "localizations": {
        "en": {
          "stringUnit": {
            "state": "translated",
            "value": "Hello"
          }
        },
        "zh-Hans": {
          "stringUnit": {
            "state": "translated",
            "value": "你好"
          }
        }
      }
    }
  },
  "version": "1.0"
}
```

### 7.3 Localizable.strings（传统方式）

传统方式使用 `.strings` 文件，格式为键值对：

```
/* Localizable.strings (English) */
"welcome_message" = "Welcome";
"settings_title" = "Settings";
"logout_button" = "Log Out";
```

```
/* Localizable.strings (Chinese Simplified) */
"welcome_message" = "欢迎";
"settings_title" = "设置";
"logout_button" = "退出登录";
```

#### 添加 Localizable.strings 文件

1. File → New → File → Strings File
2. 命名为 `Localizable.strings`
3. 在 File Inspector 中点击 "Localize..."
4. 勾选需要的语言

### 7.4 String Catalog vs Localizable.strings

| 特性 | String Catalog | Localizable.strings |
|------|---------------|-------------------|
| 格式 | JSON | 键值对文本 |
| 自动发现字符串 | ✅ 是 | ❌ 否 |
| 复数/性别处理 | ✅ 内置支持 | ❌ 需手动 |
| Xcode 15+ | ✅ 推荐 | 仍可用 |
| 多语言管理 | 统一文件 | 每种语言一个文件 |
| 版本控制 | 更易合并 | 容易冲突 |

> 💡 新项目推荐使用 String Catalog，旧项目可以迁移。Xcode 提供了自动迁移功能。

## 8. SwiftUI 国际化

### 8.1 Text 自动本地化

SwiftUI 的 `Text` 视图会自动查找本地化字符串：

```swift
// SwiftUI 会自动查找 "Hello" 对应的本地化翻译
Text("Hello")

// 使用键名查找
Text("welcome_message")
```

> ⚠️ 注意：SwiftUI 的 `Text("Hello")` 会把 "Hello" 同时作为默认值和查找键。如果翻译文件中有 "Hello" 的翻译，就会显示翻译后的文本。

### 8.2 带参数的本地化字符串

```swift
// 使用字符串插值
Text("Welcome, \(userName)!")

// 在 String Catalog 中，Xcode 会自动识别参数
// 英文: "Welcome, %@!"
// 中文: "欢迎，%@！"
```

### 8.3 复数处理

不同语言的复数规则不同。String Catalog 支持复数变体：

```swift
let count = 3
Text("^[\(count) item](inflect: true)")
```

在 String Catalog 中配置复数规则：

| 语言 | 0 项 | 1 项 | 2+ 项 |
|------|------|------|-------|
| 英文 | 0 items | 1 item | 2 items |
| 中文 | 0 项 | 1 项 | 2 项 |
| 俄语 | 0 элементов | 1 элемент | 2 элемента |
| 阿拉伯语 | ٠ عناصر | ١ عنصر | ٢ عنصران |

> 💡 阿拉伯语有双数形式，俄语有复杂的复数规则。String Catalog 能帮你处理这些差异。

### 8.4 日期格式化

```swift
import SwiftUI

struct DateView: View {

    var body: some View {
        VStack {
            // 自动根据语言和地区格式化

            Text(date.formatted(
                date: .long,
                time: .short
            ))

            // 相对时间
            Text(date, style: .relative)
        }
    }
}
```

| 美国 | May 20, 2026 |

| 日本 | 2026/05/20 |

## 9. 多语言 App 实战

### 9.1 创建多语言项目

#### 第一步：添加语言

1. 选中项目 → Project → Info → Localizations
2. 点击 "+" 添加语言（如 Chinese Simplified、Japanese）
3. 勾选需要本地化的文件

#### 第二步：本地化 App 名称

创建 `InfoPlist.strings` 文件并本地化：

```
/* InfoPlist.strings (English) */
CFBundleDisplayName = "MyApp";

/* InfoPlist.strings (Chinese Simplified) */
CFBundleDisplayName = "我的应用";
```

#### 第三步：本地化图片资源

在 Asset Catalog 中：

1. 选中图片资源
2. 在 Attributes Inspector 中勾选 "Localize..."
3. 为不同语言提供不同图片

### 9.2 完整多语言示例

```swift
import SwiftUI

struct ContentView: View {
    @State private var items: [String] = []

    var body: some View {
        NavigationStack {
            List {
                Section {
                    ForEach(items, id: \.self) { item in
                        Text(item)
                    }
                } header: {
                    Text("My Items")
                }

                Section {
                    Button {
                        addItem()
                    } label: {
                        Label("Add Item", systemImage: "plus")
                    }
                }
            }
            .navigationTitle("My App")
        }
    }

    private func addItem() {
        items.append("Item \(items.count + 1)")
    }
}
```

对应的 String Catalog（`Localizable.xcstrings`）：

| 键 | 英文 | 简体中文 |
|----|------|---------|
| My Items | My Items | 我的条目 |
| Add Item | Add Item | 添加条目 |
| My App | My App | 我的应用 |
| Item %lld | Item %lld | 条目 %lld |

### 9.3 运行时切换语言

App 内切换语言（不推荐，但有时需要）：

```swift
import SwiftUI

final class LanguageManager: ObservableObject {
    @Published var language: String {
        didSet {
            UserDefaults.standard.set(language, forKey: "app_language")
        }
    }

    init() {
        self.language = UserDefaults.standard.string(forKey: "app_language") ?? Locale.current.language.languageCode?.identifier ?? "en"
    }

    var locale: Locale {
        Locale(identifier: language)
    }
}

struct LanguageSwitchView: View {
    @StateObject private var manager = LanguageManager()

    var body: some View {
        VStack(spacing: 20) {
            Picker("语言", selection: $manager.language) {
                Text("English").tag("en")
                Text("简体中文").tag("zh-Hans")
                Text("日本語").tag("ja")
            }
            .pickerStyle(.segmented)

            ContentView()
                .environment(\.locale, manager.locale)
        }
        .padding()
    }
}
```

> ⚠️ App 内切换语言是"非标准"做法。Apple 推荐跟随系统语言设置。如果必须提供此功能，务必充分测试。

### 9.4 App Store 多语言描述

在 App Store Connect 中：

1. 进入 App → App 信息
2. 在"本地化信息"部分添加语言
3. 为每种语言填写：
   - App 名称
   - 副标题
   - 描述
   - 关键词
   - 截图
   - 预览视频
   - 新功能
   - 隐私政策 URL

| 字段 | 本地化建议 |
|------|-----------|
| App 名称 | 保留品牌名，可加本地化副标题 |
| 关键词 | 每种语言用当地用户搜索习惯的词 |
| 描述 | 翻译 + 本地化调整，不只是直译 |
| 截图 | UI 截图需展示对应语言界面 |
| 隐私政策 | 提供各语言版本或使用通用英文版 |

> 💡 关键词本地化很重要！中文用户搜"记账"，英文用户搜"budget tracker"，日文用户搜"家計簿"。直译关键词会错失大量搜索流量。

## 10. 最佳实践

### 10.1 无障碍设计原则

| 原则 | 说明 | 实践方法 |
|------|------|---------|
| 可感知 | 信息可被所有用户感知 | 不只靠颜色、提供文字替代 |
| 可操作 | 界面可被所有用户操作 | 大点击区域、支持键盘导航 |
| 可理解 | 内容和操作易于理解 | 简洁文案、一致交互模式 |
| 健壮性 | 兼容各种辅助技术 | 正确使用无障碍 API |

### 10.2 国际化设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 代码与文本分离 | 不要硬编码字符串 | 用 `Text("key")` 而非 `Text("固定文字")` |
| 布局要灵活 | 不同语言长度差异大 | 德文比英文长 30%，中文可能更短 |
| 格式本地化 | 日期、数字、货币用本地格式 | 用 `Formatted` API |
| 复数和性别 | 考虑语法差异 | 用 String Catalog 的复数变体 |
| 测试伪本地化 | 用假翻译发现布局问题 | Xcode Scheme → Run → Arguments → `-AppleLanguages "(pt-BR)"` |

### 10.3 布局国际化技巧

不同语言的文本长度差异很大，布局必须灵活：

```swift
// ❌ 固定宽度，长文本会截断
Text("Settings")
    .frame(width: 80)

// ✅ 弹性宽度，自适应文本长度
Text("Settings")
    .frame(minWidth: 80)

// ✅ 使用 ViewThatFits 自动选择布局
ViewThatFits {
    HStack {
        Image(systemName: "gear")
        Text("Settings")
    }
    VStack {
        Image(systemName: "gear")
        Text("Settings")
    }
}
```

### 10.4 无障碍 + 国际化检查清单

在提交 App 前，逐项检查：

**无障碍检查清单：**

- [ ] 所有图标都有 `accessibilityLabel`
- [ ] 交互元素有 `accessibilityHint`（必要时）
- [ ] 装饰性元素已 `accessibilityHidden(true)`
- [ ] 相关信息已用 `.combine` 分组
- [ ] 导航顺序合理
- [ ] 支持动态类型，字体放大后布局正常
- [ ] 对比度符合 WCAG AA 标准
- [ ] 不只靠颜色传达信息
- [ ] 点击区域 ≥ 44×44 pt
- [ ] 用 VoiceOver 完整走通核心流程

**国际化检查清单：**

- [ ] 没有硬编码字符串
- [ ] String Catalog / Localizable.strings 配置完整
- [ ] App 名称已本地化
- [ ] 日期、数字、货币使用本地化格式
- [ ] 复数形式已处理
- [ ] 布局在不同语言下正常显示
- [ ] 截图已本地化
- [ ] App Store 描述已本地化

### 10.5 持续改进

无障碍和国际化不是"一次做完"的工作，而是持续迭代的过程：

```swift
struct AccessibilityOnboardingView: View {
    let features = [
        (icon: "eye.slash", title: "VoiceOver 支持", desc: "视障用户也能流畅使用"),
        (icon: "textformat.size", title: "动态类型", desc: "字体大小随你心意"),
        (icon: "paintpalette", title: "高对比度", desc: "清晰可辨，一目了然"),
        (icon: "globe", title: "多语言", desc: "全世界都能用你的 App"),
    ]

    var body: some View {
        VStack(spacing: 24) {
            Text("无障碍与国际化")
                .font(.largeTitle)
                .bold()

            ForEach(features, id: \.title) { feature in
                HStack(spacing: 16) {
                    Image(systemName: feature.icon)
                        .font(.title2)
                        .foregroundStyle(.blue)
                        .frame(width: 44)

                    VStack(alignment: .leading) {
                        Text(feature.title)
                            .font(.headline)
                        Text(feature.desc)
                            .font(.subheadline)
                            .foregroundStyle(.secondary)
                    }

                    Spacer()
                }
                .accessibilityElement(children: .combine)
                .accessibilityLabel("\(feature.title)，\(feature.desc)")
            }
        }
        .padding()
    }
}
```

## 小结

本章我们学习了 iOS 开发中两个让 App "面向所有人"的重要主题：

**无障碍（Accessibility）**：
- 用 `accessibilityLabel`、`accessibilityHint`、`accessibilityValue` 为视图添加无障碍信息
- 用分组、导航顺序、自定义动作优化 VoiceOver 体验
- 支持动态类型让字体自适应，确保布局不被撑破
- 注意颜色与对比度，不只靠颜色传达信息
- 用 Accessibility Inspector 和 VoiceOver 手动测试验证

**国际化（i18n）**：
- 用 String Catalog（推荐）或 Localizable.strings 管理多语言文本
- SwiftUI 的 `Text` 自动支持本地化
- 用 `Formatted` API 处理日期、数字、货币的本地化格式
- 布局要灵活，适应不同语言的文本长度差异
- App Store 描述和关键词也需要本地化

> 💡 记住：无障碍和国际化不是"锦上添花"，而是"基础建设"。就像修路时同时修坡道，比建好楼再补坡道要容易得多。从项目一开始就考虑这两点，后面会轻松很多！
