# 跨平台代码共享策略

> 🎯 **本章目标**：掌握在 iOS、watchOS、visionOS、macOS 之间共享代码的策略和方法，学会使用 Swift Package 和条件编译实现跨平台开发。

---

## Apple 平台代码共享概述

### 共享什么、不共享什么

Apple 生态中有多个平台：iOS、watchOS、visionOS、macOS、tvOS。它们共享同一套编程语言（Swift）和大量系统框架，但每个平台也有独特的 API 和交互模式。

**代码共享的核心原则：**

```text
┌──────────────────────────────────────────────────────────┐
│                    代码共享分层模型                         │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │              UI 层（不共享）                         │  │
│  │  iOS: SwiftUI/UIKit    watchOS: SwiftUI(Watch)      │  │
│  │  visionOS: SwiftUI     macOS: SwiftUI/AppKit        │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │           业务逻辑层（大部分共享）                     │  │
│  │  数据验证、业务规则、状态管理、工作流                   │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │           数据层（完全共享）                          │  │
│  │  网络请求、数据模型、持久化、缓存                      │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │           基础设施层（完全共享）                       │  │
│  │  日志、错误处理、工具类、扩展                          │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

### 各层共享程度

| 层级 | 共享程度 | 说明 |
|------|:--------:|------|
| 基础设施层 | ⭐⭐⭐⭐⭐ | 日志、工具类、扩展等，100% 共享 |
| 数据层 | ⭐⭐⭐⭐⭐ | 网络请求、数据模型、持久化等，90%+ 共享 |
| 业务逻辑层 | ⭐⭐⭐⭐ | 核心逻辑共享，平台特定逻辑分离 |
| 平台适配层 | ⭐⭐⭐ | 通过协议和封装实现部分共享 |
| UI 层 | ⭐⭐ | SwiftUI 可部分共享，但交互模式不同 |

### 各平台差异一览

| 维度 | iOS | watchOS | visionOS | macOS | tvOS |
|------|-----|---------|----------|-------|------|
| **UI 框架** | SwiftUI/UIKit | SwiftUI(Watch) | SwiftUI | SwiftUI/AppKit | SwiftUI(TV) |
| **交互方式** | 触摸 | 触摸+Digital Crown | 眼+手+语音 | 鼠标+键盘+触控板 | 遥控器 |
| **屏幕尺寸** | 多种 | 固定小屏 | 无限空间 | 多种 | 固定大屏 |
| **网络** | WiFi/蜂窝 | WiFi/蜂窝 | WiFi | WiFi/以太网 | WiFi/以太网 |
| **传感器** | 丰富 | 心率/加速度 | LiDAR/摄像头 | 基础 | 基础 |
| **后台模式** | 丰富 | 有限 | 有限 | 丰富 | 有限 |
| **最低系统** | iOS 16 | watchOS 9 | visionOS 1 | macOS 13 | tvOS 16 |

> 💡 **提示**：SwiftUI 是 Apple 跨平台 UI 开发的最佳选择。虽然各平台的 SwiftUI 组件和行为有所不同，但核心语法和声明式范式是共享的。

## Swift Package 跨平台共享

### 为什么用 Swift Package

Swift Package Manager（SPM）是 Apple 官方的依赖管理工具，也是实现跨平台代码共享的最佳方式：

| 优势 | 说明 |
|------|------|
| 原生支持 | Xcode 内置，无需额外工具 |
| 跨平台 | 一个 Package 可同时支持多个平台 |
| 模块化 | 清晰的模块边界和依赖关系 |
| 可测试 | 内置测试支持 |
| 版本管理 | 语义化版本控制 |
| 可复用 | 可在多个项目间共享 |

### 平台条件配置

在 Package.swift 中，你可以为不同平台设置不同的依赖和源文件：

```swift
let package = Package(
    name: "SharedKit",
    platforms: [
        .iOS(.v16),
        .watchOS(.v9),
        .visionOS(.v1),
        .macOS(.v13)
    ],
    targets: [
        .target(
            name: "SharedKit",
            dependencies: [],
            path: "Sources/SharedKit",
            exclude: [
                "Platform/WatchSpecific.swift"
            ],
            sources: [
                "Sources/SharedKit"
            ],
            resources: [
                .process("Resources")
            ],
            swiftSettings: [
                .define("SHARED_KIT")
            ]
        )
    ]
)
```

> 💡 **提示**：设置 `platforms` 数组时，确保最低版本号与你的项目最低部署目标一致。如果 Package 的最低版本高于项目目标，编译会报错。

## 条件编译：#if os()、#if canImport()

### #if os() 平台条件编译

`#if os()` 是最常用的条件编译指令，用于根据目标平台包含或排除代码：

```swift
import Foundation

struct PlatformLogger {
    func log(_ message: String, level: LogLevel = .info) {
        let timestamp = ISO8601DateFormatter().string(from: Date())
        let prefix = "[\(timestamp)] [\(level.rawValue)] "

        #if os(iOS)
        print("\(prefix)[iOS] \(message)")
        #elseif os(watchOS)
        print("\(prefix)[watchOS] \(message)")
        #elseif os(visionOS)
        print("\(prefix)[visionOS] \(message)")
        #elseif os(macOS)
        print("\(prefix)[macOS] \(message)")
        #elseif os(tvOS)
        print("\(prefix)[tvOS] \(message)")
        #endif
    }
}

enum LogLevel: String {
    case debug = "DEBUG"
    case info = "INFO"
    case warning = "WARN"
    case error = "ERROR"
}
```

**平台标识符：**

| 标识符 | 平台 |
|--------|------|
| `os(iOS)` | iOS（包括 iPadOS） |
| `os(watchOS)` | watchOS |
| `os(visionOS)` | visionOS |
| `os(macOS)` | macOS |
| `os(tvOS)` | tvOS |
| `os(Linux)` | Linux |
| `os(Windows)` | Windows |

### #if canImport() 框架可用性检查

`#if canImport()` 用于检查某个框架是否可用，这在跨平台开发中非常有用：

```swift
import Foundation

#if canImport(UIKit)
import UIKit
#endif

#if canImport(AppKit)
import AppKit
#endif

#if canImport(WatchKit)
import WatchKit
#endif

struct PlatformColor {
    #if canImport(UIKit)
    typealias ColorType = UIColor
    #elseif canImport(AppKit)
    typealias ColorType = NSColor
    #endif

    static var primary: ColorType {
        #if canImport(UIKit)
        return UIColor.systemBlue
        #elseif canImport(AppKit)
        return NSColor.systemBlue
        #endif
    }

    static var background: ColorType {
        #if canImport(UIKit)
        return UIColor.systemBackground
        #elseif canImport(AppKit)
        return NSColor.windowBackgroundColor
        #endif
    }
}
```

### 组合使用条件编译

```swift
import Foundation

struct DeviceInfo {
    static var platformName: String {

        return false
        #endif

        #if os(watchOS)
        return true
        #else

        return true
        #else
        return false
        #endif
    }

```

### 条件编译的最佳实践

| 实践 | 说明 | ❌ 错误做法 | ✅ 正确做法 |
|------|------|-----------|-----------|
| 最小化条件代码 | 只在必要处使用条件编译 | 整个文件都是 #if | 只包裹平台特定部分 |
| 使用协议抽象 | 用协议代替条件编译 | 每个平台写一套逻辑 | 定义协议，各平台实现 |
| 集中管理 | 将平台差异集中到适配层 | 散落在各处 | 统一在 Platform 目录 |
| 避免嵌套 | 不要嵌套条件编译 | #if 内再 #if | 扁平化条件 |
| 提供默认实现 | 确保所有平台都能编译 | 只写 iOS 代码 | 为每个平台提供实现 |

> ⚠️ **警告**：过度使用条件编译会导致代码难以维护。如果一个文件中 `#if` 超过 3 处，应该考虑用协议抽象或平台特定的文件来替代。

## 平台特定的 API 封装

### 使用协议封装平台差异

通过定义协议，将平台差异封装到各自的实现中：

```swift
import Foundation

protocol HapticFeedbackService {
    func success()
    func error()
    func warning()
    func lightImpact()
    func mediumImpact()
    func heavyImpact()
    func selection()
}
```

**iOS 实现：**

```swift
#if canImport(UIKit)
import UIKit

final class IOSHapticFeedbackService: HapticFeedbackService {
    func success() {
        let generator = UINotificationFeedbackGenerator()
        generator.notificationOccurred(.success)
    }

    func error() {
        let generator = UINotificationFeedbackGenerator()
        generator.notificationOccurred(.error)
    }

    func warning() {
        let generator = UINotificationFeedbackGenerator()
        generator.notificationOccurred(.warning)
    }

    func lightImpact() {
        let generator = UIImpactFeedbackGenerator(style: .light)
        generator.impactOccurred()
    }

    func mediumImpact() {
        let generator = UIImpactFeedbackGenerator(style: .medium)
        generator.impactOccurred()
    }

    func heavyImpact() {
        let generator = UIImpactFeedbackGenerator(style: .heavy)
        generator.impactOccurred()
    }

    func selection() {
        let generator = UISelectionFeedbackGenerator()
        generator.selectionChanged()
    }
}
#endif
```

**watchOS 实现：**

```swift
#if canImport(WatchKit)
import WatchKit

    func warning() {
        WKInterfaceDevice.current().play(.retry)

    func mediumImpact() {
        WKInterfaceDevice.current().play(.click)
    }

    func heavyImpact() {
        WKInterfaceDevice.current().play(.click)
```

### 通知封装

不同平台的通知 API 也有差异，需要封装：

```swift
import Foundation

protocol NotificationScheduling {
    func schedule(title: String, body: String, at date: Date, identifier: String) async throws
    func cancel(identifier: String)
    func cancelAll()
}

#if canImport(UserNotifications)
import UserNotifications

final class SharedNotificationScheduler: NotificationScheduling {
    private let center = UNUserNotificationCenter.current()

    func schedule(title: String, body: String, at date: Date, identifier: String) async throws {
        let content = UNMutableNotificationContent()
        content.title = title
        content.body = body
        content.sound = .default

        let triggerDate = Calendar.current.dateComponents(
            [.year, .month, .day, .hour, .minute, .second],
            from: date
        )
        let trigger = UNCalendarNotificationTrigger(dateMatching: triggerDate, repeats: false)

        let request = UNNotificationRequest(
            identifier: identifier,
            content: content,
            trigger: trigger
        )

        try await center.add(request)
    }

    func cancel(identifier: String) {
        center.removePendingNotificationRequests(withIdentifiers: [identifier])
    }

    func cancelAll() {
        center.removeAllPendingNotificationRequests()
    }
}
#endif
```

## UI 层的共享策略

| 共享程度 | 组件类型 | 示例 |

## 数据层和业务逻辑层的共享

### 网络层共享

网络请求代码是跨平台共享的最佳候选，因为所有平台都使用相同的 URLSession API：

```swift
import Foundation

public final class APIClient {
    public static let shared = APIClient()

    private let session: URLSession
    private let baseURL: String

    public init(baseURL: String = "https://api.weatherapp.com",
                session: URLSession = .shared) {
        self.baseURL = baseURL
        self.session = session
    }

    public func request<T: Decodable>(_ endpoint: Endpoint) async throws -> T {
        let urlRequest = try buildRequest(for: endpoint)
        let (data, response) = try await session.data(for: urlRequest)

        guard let httpResponse = response as? HTTPURLResponse else {
            throw APIError.invalidResponse
        }

        switch httpResponse.statusCode {
        case 200...299:
            do {
                return try JSONDecoder().decode(T.self, from: data)
            } catch {
                throw APIError.decodingFailed(error)
            }
        case 401:
            throw APIError.unauthorized
        case 429:
            throw APIError.rateLimited
        default:
            throw APIError.statusCode(httpResponse.statusCode)
        }
    }

    private func buildRequest(for endpoint: Endpoint) throws -> URLRequest {
        guard let url = URL(string: baseURL + endpoint.path) else {
            throw APIError.invalidURL
        }

        var request = URLRequest(url: url)
        request.httpMethod = endpoint.method.rawValue
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")

        if let body = endpoint.body {
            request.httpBody = try JSONEncoder().encode(body)
        }

        return request
    }
}

public enum APIError: LocalizedError {
    case invalidURL
    case invalidResponse
    case unauthorized
    case rateLimited
    case statusCode(Int)
    case decodingFailed(Error)

    public var errorDescription: String? {
        switch self {
        case .invalidURL: return "无效的 URL"
        case .invalidResponse: return "无效的响应"
        case .unauthorized: return "未授权"
        case .rateLimited: return "请求过于频繁"
        case .statusCode(let code): return "服务器错误: \(code)"
        case .decodingFailed(let error): return "数据解析失败: \(error.localizedDescription)"
        }
    }
}

public struct Endpoint {
    public let path: String
    public let method: HTTPMethod
    public let body: Encodable?
```

```swift
import Foundation

public final class WeatherCalculator {
    public static let shared = WeatherCalculator()

    public func comfortIndex(temperature: Double, humidity: Int, windSpeed: Double) -> ComfortLevel {
        let heatIndex = calculateHeatIndex(temperature: temperature, humidity: humidity)
        let windChill = calculateWindChill(temperature: temperature, windSpeed: windSpeed)

        let effectiveTemp = temperature > 27 ? heatIndex : (temperature < 10 ? windChill : temperature)

        switch effectiveTemp {
        case ..<10: return .cold
        case 10..<18: return .cool
        case 18..<26: return .comfortable
        case 26..<32: return .warm
        default: return .hot
        }
    }

    public func uvRiskLevel(_ uvIndex: Int) -> UVRiskLevel {
        switch uvIndex {
        case 0...2: return .low
        case 3...5: return .moderate
        case 6...7: return .high
        case 8...10: return .veryHigh
        default: return .extreme
        }
    }

    public func clothingRecommendation(temperature: Double, condition: WeatherCondition) -> String {
        switch (temperature, condition) {
        case (..<5, _): return "建议穿厚外套、围巾和手套"
        case (5..<15, .rainy): return "建议穿防水外套，带伞"
        case (5..<15, _): return "建议穿外套或厚毛衣"
        case (15..<22, .rainy): return "建议穿薄外套，带伞"
        case (15..<22, _): return "建议穿长袖或薄外套"
        case (22..<28, _): return "建议穿短袖"
        default: return "建议穿轻薄透气衣物，注意防晒"
        }
    }

    private func calculateHeatIndex(temperature: Double, humidity: Int) -> Double {
        let h = Double(humidity)
        let t = temperature
        let hi = -42.379 + 2.04901523 * t + 10.14333127 * h
            - 0.22475541 * t * h - 0.00683783 * t * t
            - 0.05481717 * h * h + 0.00122874 * t * t * h
            + 0.00085282 * t * h * h - 0.00000199 * t * t * h * h
        return hi
    }

    private func calculateWindChill(temperature: Double, windSpeed: Double) -> Double {
        let v = pow(windSpeed, 0.16)
        return 13.12 + 0.6215 * temperature - 11.37 * v + 0.3965 * temperature * v
    }
}

    case cold = "寒冷"
    case cool = "凉爽"
    case comfortable = "舒适"
    case warm = "温暖"
    case hot = "炎热"
```

```swift
import Foundation

public protocol DataPersisting {
    func save<T: Codable>(_ data: T, forKey key: String) throws
    func load<T: Codable>(forKey key: String, as type: T.Type) throws -> T?
    func remove(forKey key: String)
    func removeAll()

public final class UserDefaultsPersistence: DataPersisting {
    private let defaults: UserDefaults

    public init(suiteName: String? = nil) {
        self.defaults = suiteName != nil
            ? UserDefaults(suiteName: suiteName!)!
            : .standard
    }

    public func save<T: Codable>(_ data: T, forKey key: String) throws {
        let encoded = try JSONEncoder().encode(data)
        defaults.set(encoded, forKey: key)
    }

    public func load<T: Codable>(forKey key: String, as type: T.Type) throws -> T? {
        guard let data = defaults.data(forKey: key) else { return nil }
        return try JSONDecoder().decode(type, from: data)
    }

    public func remove(forKey key: String) {
        defaults.removeObject(forKey: key)
    }

    public func removeAll() {
        if let bundleID = Bundle.main.bundleIdentifier {
            defaults.removePersistentDomain(forName: bundleID)
        }
    }
}

extension UserDefaults {
    func data(forKey key: String) -> Data? {
        return object(forKey: key) as? Data
    }
```

## Universal Purchase：跨平台内购共享

### 什么是 Universal Purchase

Universal Purchase 允许用户在一个平台上购买的内购项目，在其他平台上也能使用。例如用户在 iOS 上购买了订阅，在 watchOS 和 macOS 上也能享受订阅内容。

**Universal Purchase 的要求：**

| 要求 | 说明 |
|------|------|
| 同一 App 记录 | 所有平台使用同一个 App Record |
| 共享 App ID | 所有平台使用相同的 Bundle ID 前缀 |
| 共享产品 ID | 内购产品 ID 在所有平台一致 |
| StoreKit 2 | 推荐使用 StoreKit 2 管理 |
| Xcode 配置 | 在 Xcode 中启用 Universal Purchase |

### 配置 Universal Purchase

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | 在 App Store Connect 中创建 App | 使用统一的 App Record |
| 2 | 添加多平台版本 | iOS、watchOS、macOS 等 |
| 3 | 创建共享的内购产品 | 产品 ID 在所有平台一致 |
| 4 | 在 Xcode 中配置 | 确保各平台使用正确的 Bundle ID |
| 5 | 测试购买流程 | 在各平台验证购买同步 |

### StoreKit 2 跨平台购买检查

```swift
import StoreKit

public final class SubscriptionManager {
    public static let shared = SubscriptionManager()

    public func checkSubscriptionStatus() async -> SubscriptionStatus {
        do {
            let statuses = try await Product.products(for: ["com.app.premium"])
            guard let product = statuses.first else {
                return .notSubscribed
            }

            let transaction = try await product.currentTransaction
            guard let transaction = transaction else {
                return .notSubscribed
            }

            if transaction.expirationDate ?? .distantFuture > Date() {
                return .subscribed(expiryDate: transaction.expirationDate)
            } else {
                return .expired
            }
        } catch {
            return .error(error)
        }
    }

    public func purchase(productID: String) async throws -> PurchaseResult {
        let products = try await Product.products(for: [productID])
        guard let product = products.first else {
            throw PurchaseError.productNotFound
        }

        let result = try await product.purchase()

        switch result {
        case .success(let verification):
            switch verification {
            case .verified(let transaction):
                await transaction.finish()
                return .purchased
            case .unverified:
                return .failed(PurchaseError.verificationFailed)
            }
        case .pending:
            return .pending
        case .userCancelled:
            return .cancelled
        @unknown default:
            return .failed(PurchaseError.unknown)
        }
    }
}

public enum SubscriptionStatus {
    case subscribed(expiryDate: Date?)
    case notSubscribed
    case expired
    case error(Error)
}

public enum PurchaseResult {
    case purchased
    case pending
    case cancelled
    case failed(Error)
}

public enum PurchaseError: LocalizedError {
    case productNotFound
    case verificationFailed
    case unknown

    public var errorDescription: String? {
        switch self {
        case .productNotFound: return "产品未找到"
        case .verificationFailed: return "购买验证失败"
        case .unknown: return "未知错误"
        }
    }
}
```

> 💡 **提示**：Universal Purchase 的购买记录会自动同步到用户的所有设备。你不需要自己实现跨设备同步逻辑，StoreKit 会处理。

### 测试覆盖率目标

| 模块 | 目标覆盖率 | 说明 |
|------|:----------:|------|

## 跨平台开发常见问题

### FAQ

| 问题 | 回答 |
|------|------|
| SwiftUI 代码能直接跨平台吗？ | 大部分可以，但导航和平台特定组件需要适配 |
| 条件编译会不会影响性能？ | 不会，条件编译在编译时处理，运行时无开销 |
| 一个 Package 最多支持几个平台？ | 无限制，可以同时支持所有 Apple 平台 |
| 跨平台共享代码需要修改架构吗？ | 建议采用分层架构，将共享代码和平台代码分离 |
| Core Data 能跨平台共享吗？ | 可以，但需要注意数据文件路径和容器配置 |
| SwiftData 能跨平台吗？ | 可以，SwiftData 支持 iOS 17+、watchOS 10+、macOS 14+ |
| 第三方库能跨平台使用吗？ | 取决于库本身是否支持多平台 |

### 常见错误和避免方法

| 错误 | 后果 | 避免方法 |
|------|------|----------|
| UI 和逻辑耦合 | 无法跨平台共享 | 严格分层，UI 只做展示 |
| 过度使用条件编译 | 代码难以维护 | 用协议抽象代替 |
| 不测试所有平台 | 某个平台编译失败 | CI 中构建所有平台 |
| 忽略平台差异 | 运行时崩溃 | 了解各平台限制 |
| Bundle ID 不一致 | Universal Purchase 失败 | 统一 Bundle ID 规范 |
| 不使用 App Group | 数据无法跨平台共享 | 配置 App Group |

## 本章小结

本章详细介绍了 Apple 平台间代码共享的策略和方法：

| 知识点 | 要点 |
|--------|------|
| 共享原则 | 基础设施层和数据层完全共享，UI 层不共享 |
| Swift Package | 最佳的跨平台代码共享方式 |
| 条件编译 | #if os() 和 #if canImport() 处理平台差异 |
| 协议封装 | 用协议抽象平台差异，各平台独立实现 |
| SwiftUI 跨平台 | 大部分组件可共享，导航和特定组件需适配 |
| 数据层共享 | 网络请求、数据模型、持久化完全共享 |
| Universal Purchase | 跨平台内购共享，StoreKit 2 自动同步 |
| 多平台 Target | Xcode 中配置多平台 Target 和 Scheme |
| 测试策略 | 共享代码一次测试，全平台验证 |

**核心原则：最大化共享，最小化差异。用协议封装差异，用 Package 组织共享。**

> 💡 **提示**：对于刚开始跨平台开发的独立开发者，建议先从 iOS + watchOS 两个平台开始。这两个平台的差异最大，也是最常见的组合。掌握后再扩展到 visionOS 和 macOS。
